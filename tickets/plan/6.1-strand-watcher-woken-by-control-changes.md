# The strand watcher wakes on a change to Strand or JoinedStrand

## Measured

GitHub #50, two single-machine parties sharing one strand, 60 s idle, both nodes together: 155 block reads. The inventory (this planning pass, static, reconciled against #50's numbers) attributes 48 of them to the watcher: `queryStrands` plus `queryJoinedStrands`, one read each, every 5 s, on every node. #50's own table credits the watcher with ~72 because it counted the revoked-stamp reads under it; those come from the reconcile pass and the pending-join runner (`control-reconcile-woken-by-changes-reads-once`, `pending-join-runner-woken-by-changes`).

On a single-machine party these reads stay local. On a two-machine cadre (a phone plus its always-on node) they do not: the control cohort includes the sibling, a held block read more than 10 s after it was last checked starts one background `/sync` request to the sibling (Optimystic's lazy read repair, `readRepairWindowMs` 10 s), and `JoinedStrand` is often a table nobody has written, whose every read consults the sibling. The 5 s period is shorter than the 10 s window, so the watcher alone keeps that traffic going.

## Design

- Subscribe through `control-and-strand-table-change-subscription`'s seam to `Strand` and `JoinedStrand` on the control database. On a change, run the existing diff (`queryStrands`, `queryJoinedStrands`, compare, call `onStrandAdded` / `onStrandRemoved`).
- Run once at start, as today.
- Keep a backstop poll. Default 5 minutes, configurable through the existing `strandWatchInterval` (rename it if its meaning changes to "backstop").
- Keep the existing failure ladder for a run that throws.

## Edge cases & interactions

- **Missed change at start.** A commit that lands between the first read and the subscription. Subscribe first, then run the initial diff. Verify by inspection.
- **Burst of strand rows** (an app founding several strands): the debounce collapses them into one diff. Verify by inspection; the seam's unit test covers coalescing.
- **`handleStrandAdded` is slow** (launches a strand). A change arriving meanwhile must queue one follow-up diff, not run concurrently. The seam's single-flight rule covers it.
- **A cadre larger than 16 machines,** where this machine may not be in a control block's cohort: the backstop is the only path. Note it at the backstop constant.
- **Stop.** The subscription is disposed before the control database closes.

## Tests

None new beyond `control-and-strand-table-change-subscription`'s. The existing watcher specs keep covering the diff. `message-cost-accounting`'s idle measurement shows the effect.
