# The cross-party formation connection closes when formation is done

## Measured

`message-cost-accounting` baseline, strand case, idle 60 s: failed `control-<party>/fret/ping` negotiations A.ctl→B.ctl 2 and B.ctl→A.ctl 2, plus 2 each to the relay from both control nodes and both strand nodes, plus libp2p pings on each of those connections. In the settle window: 4 failed FRET pings each way between the two control nodes. Also `/sereus/strand-addr/1.0.0` sent to the relay and refused, once at `foundStrand` and once at `addStrand`.

Why: B's control node dials A's control node for `/sereus/formation/1.0.0`. The two control nodes are on different networks (`control-<partyA>`, `control-<partyB>`), so FRET's ping on that connection always fails protocol negotiation, but FRET still treats the connected peer as a probe target. A probe target outside the ring holds FRET's stabilization interval near its 1.5 s base instead of backing off to 60 s (FRET's own NOTE at `fret-service.ts` ~3079-3085).

## Design

1. **Close the formation connection** on both sides once the formation exchange completes (success or rejection), unless the connection carries something else (check the gater: a sibling of the same party is never the counterpart here, but verify). Connections to the relay stay.
2. **strand-addr to a relay.** The refusal of an ops relay is remembered only per process (`cadre-node.ts` ~798), and the first launch in each process awaits it before the strand node starts (GitHub #49, second part). Persist the refusal with the relay's peer id in the node-local state, so a restart does not ask again; or skip asking relays that do not advertise the protocol in identify, if identify already tells us (read whether it does; prefer that, it needs no state).
3. **FRET probing off-ring and relay peers** is upstream (`fret-maintenance-probes-peers-off-its-ring`). Items 1–2 are Sereus's share.

## Edge cases & interactions

- **Formation retried** (pending-join runner): each attempt dials and closes; fine.
- **A formation whose reply is lost.** Close after the handler's write completes on the responder, and after the reply is read (or the attempt times out) on the dialer.
- **Same machine, two roles.** A machine that is both a party's control node and, for a different reason, already connected to the counterpart (e.g. both reach each other for another strand's formation in flight): close only the connection this formation opened, or leave closing to libp2p's connection manager if a connection is shared. Read how `formStrand` dials before choosing.
