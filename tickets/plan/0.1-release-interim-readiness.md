# Get the interim release to the point where the only thing left is a human saying "go"

There are users waiting. The purpose of this ticket is to remove every piece of *work* between here
and a publish, so that what remains is a decision and a command, not an investigation.

## What is already true (do not re-derive this)

- Single-node and same-process paths are green. **226 of 241 integration tests pass**; every failure
  is multi-machine.
- The multi-machine failures are one upstream defect, traced to a single line —
  `blocked/control-coordinator-answers-absent-without-asking-cohort`. **Sereus needs no code change
  for it.** It is fixed by an optimystic publish, not by anything in this repo.
- The self-coordination defect that broke lone-node reads is already fixed upstream and verified
  here (`complete/offline-node-cannot-serve-its-own-data`).
- `yarn test:dep-ranges` already guards declared floors against the version we test
  (`complete/debt-declared-dep-range-drift-gate`).

Read `tickets/.pre-existing-known.md` → "Delta 2026-08-03" for the current failure set before
writing anything about test status. Do not re-measure from scratch; do re-run the suite once to
confirm the numbers still hold at whatever HEAD you are on, and use *your* numbers in the notes.

## The shape of the decision

This is an **interim** release, so the honest framing is: ship what is solid, name what is not, and
do not let the version number imply more than we have shown.

Work out and write down a recommendation for each of these. Recommend, with reasons — do not leave
a menu:

1. **Version and dist-tag.** A prerelease under an `alpha` dist-tag does not become what
   `npm install @serfab/cadre-core` returns, which matters because multi-machine is not ready. A
   plain patch bump does the opposite. Consider that
   `blocked/report-dependency-floor-bump-to-embedding-app` tells the reporting app to *pin* to the
   new version, so a dist-tag costs them nothing.
2. **Which packages ship.** The `pub:*` scripts list six. `strand-proto` is deprecated per
   `AGENTS.md` — decide whether it ships at all.
3. **What the dependency floors say.** They currently declare `^0.18.0`. If optimystic publishes the
   coordinator fix before we cut, they should move; if it has not, they should not be bumped
   speculatively to a version nobody can install. State which case you are in.

## Release notes

Write them. They are the deliverable most likely to be skipped and most likely to be read.

They must state plainly:

- what is tested and working — single node, single machine, the control database, the surfaces in
  the passing suites
- what is **not** ready — cross-machine replication, and that it is blocked on a named upstream fix
- what an embedder should therefore not build on yet

Do not describe multi-machine as "experimental" or "under active development" if what we mean is
"known broken with a traced root cause". Somebody will build on it and lose a week. The whole value
of an interim release is that the caveats are accurate.

## What to leave for the human

Update `blocked/report-dependency-floor-bump-to-embedding-app` with the finalised version number and
whatever `0-release-verify-single-node-against-published-deps` learned about the reported freeze, so
that the drafted reply can be sent without further research. That ticket stays in `blocked/` — it
needs a human to send the message and to decide when to publish.

## Constraints

- **Do not publish, and do not run `yarn release`, `yarn pub`, `yarn bump`, or any `npm publish`.**
  Publishing is outward-facing and effectively irreversible; it is a human decision. Prepare
  everything up to that command and stop.
- Do not bump version numbers in `package.json` files either — `yarn bump` is part of the human's
  release step. Recommend the version in the ticket; do not apply it.
- Do not skip, `todo`, or loosen any test to improve the numbers in the release notes. The numbers
  are the point.
- Keep `docs/STATUS.md` current rather than writing a new summary document (`AGENTS.md`: don't
  create summary docs; update existing ones).
