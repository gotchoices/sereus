## What changed

A table nobody has written has no Optimystic collection, and Optimystic keeps no record of an absence, so every read of such a table asks the block's cohort (the machines responsible for the block) to prove it absent. That is one local lookup on a solo party, but a round trip per read on a party of several machines, and an error or a wait while they are offline. The reads that hit this were `JoinedStrand` (every strand-watcher run), `JoinRequest`/`JoinSuccess`/`JoinFailure` (the pending-join loop), `Revocation` (before nearly every membership read) and `FormationUsage`.

- **`createEmptyCollections(db, bridge, schemaNames)`** (`quereus-plugin-sereus/src/empty-collections.ts`, exported from the plugin's `index.ts`): opens every Optimystic table of the named schemas, which registers each table's main tree, index trees and unique-enforcement trees with the transaction bridge, then calls `sync()` on every registered collection that was never committed ("invented"). It throws if the schemas yield no Optimystic table (the filter is `vtabModuleName === 'optimystic'`, which the control tables get through the default vtab, not a `using` clause) or if a table's main collection did not register. Strand founding calls it with `['Strand', 'App']` (`FOUNDED_SCHEMAS` in `compose-strand.ts`).
- **`ControlDatabase.ensureOwnerKey`**, the one genesis entry point (edge node, `cadre-cli start --owner`, web e2e fixtures): when no `OwnerKey` row exists, it runs `commitEmptyControlCollections()` (the helper with `['CadreControl']`, under `withWriteLock`) and then `insertOwnerKey`. The two locked steps run one after the other, because the write lock is not re-entrant and `insertOwnerKey` takes it itself.
- **Order and fork safety** (doc comment on `ensureOwnerKey`): before genesis the party has no owner, so no other machine can have been admitted or hold a collection, and committing while alone cannot fork. The empty commits run before the insert, so a crash between them leaves no `OwnerKey` row and the next start repeats genesis, committing only what is still invented. A founder restart finds the row and commits nothing.
- **Existing parties are not migrated** (no backwards compatibility owed). Tables added by a later control schema version have the same gap; it is recorded in `backlog/feat-strand-tables-added-by-a-later-schema-get-their-collection` and in docs/architecture.md.
- **Integration harness:** `makeOwnOwner` in `harness/node-fixtures.ts` and in `harness/fixtures/strand-restart-party.mjs` now found through `ensureOwnerKey` (throwing if it returns false), so the 44 scenario files using it run production genesis. `createTestParty` in `harness/test-party.ts`, the foreign-owner-key injection in `push-wake-e2e.integration.ts` (~477) and the cadre-core unit specs that found with `insertOwnerKey` were left on `insertOwnerKey` on purpose (not the production genesis shape, or budgets pinned on that path).
- **Tests:** none added. `control-founding-consult-budget.spec.ts` lost its second test (the Revocation ledger marker test, whose "before" side assumed `Revocation` had no collection after genesis); its first test was re-pinned by `control-membership-rows-cached-until-changed` with this change in the tree. The consult figures already state the contract: after genesis the per-call membership reads and the idle reconcile consult nobody.

## Review findings

Review pass 2026-10-20, over the diffs of the four `ticket(implement): control-collections-created-at-cadre-founding` commits.

**Checked, no defect:**

- *Fork safety of `ensureOwnerKey`.* The empty commits run only when `hasOwnerKey()` saw no row. A row arriving between that read and the commits means a cohort was reachable, so the syncs are coordinated commits against it, not commits made alone; the edge node (`enrollFoundedOwner`) and `cadre-cli` (`wireServerOwnerKey`) both re-judge the key when `ensureOwnerKey` returns false. A `--owner` start on a wiped store that reaches nobody already forked `OwnerKey` before this change; it now also forks the other tables' empty collections, but each of those would have been forked by its first write made alone anyway (the self-record, for one). Same class, no new exposure; not filed.
- *Nothing else writes while the helper holds the lock.* Every public writer of `ControlDatabase` goes through `withWriteLock` (self-registration via `mutateCadrePeer`, the reconcile pass's writers, `SeedBootstrapService` via `execWrite`); the one documented bypass is `reference-app-web`'s rejected diagnostics insert, which never runs during genesis. Reads stay unlocked and stage nothing. The helper's own probe reads use `db.eval` directly, so they are not routed by `runningWriteBodies`.
- *Rows left staged by a rolled-back write.* The helper syncs a collection that was never committed and has unsynced changes. Read upstream `txn-bridge.ts` (`rollbackTransaction`, the `DirtyTree` and savepoint docs): a rollback restores a never-committed collection to its empty, readable state, so a failed earlier write (for example a self-record refused before any owner exists) cannot leave rows for the helper to commit.
- *Partial failure.* A `sync()` that throws partway leaves the earlier collections committed and the rest uncommitted, propagates out of `ensureOwnerKey` with no `OwnerKey` row, and the next start commits only what is still uncommitted. The edge node's 60 s bound logs and starts without genesis, as before.
- *Production genesis callers.* `insertOwnerKey` is called in production only from `ensureOwnerKey`; the genesis entry points are the edge node, `cadre-cli start --owner`, the reference-app-rn drone fixture and the web e2e fixtures, all through `ensureOwnerKey`.
- *`makeOwnOwner` throwing on `false`.* Equivalent to before: `insertOwnerKey` was already refused by the schema when any `OwnerKey` row exists.
- *Dependencies and anchors.* `@serfab/cadre-core` already depends on `@serfab/quereus-plugin-sereus` (no new edge, no cycle); the doc anchors `architecture.md#control-tables-are-network-backed` and `strands.md#joining-no-writes-before-the-first-sync` resolve. The log namespace change (`sereus:plugin:strand` → `sereus:plugin:empty-collections`) breaks no test or doc that filters on it.
