# Control nodes pass the membership predicate

## What it does

Optimystic picks the peers that hold and coordinate a control block (its cohort) from the peers libp2p's peer store says serve the network, and any connected peer can fill that list by opening or advertising the party's protocols. Optimystic 1.13.0 added `NodeOptions.isNetworkMember(peerId) => boolean`: synchronous, fail-closed, read on every lookup, self always a member. The control node now passes it.

- **One rule, two consumers.** `CadreNode.isControlNetworkMember(peerId)` is the body of the old `authorizeInboundControlStream`, without logging: refuse all while awaiting a claim; admit when not running / no DB, empty anchor, configured bootstrap infra, empty snapshot; otherwise admit only peers in the `authorizedControlPeers` snapshot. `authorizeInboundControlStream` calls it and logs the two denial reasons. The admission table lives on `isControlNetworkMember`'s doc comment only.
- **Wiring.** `buildControlNodeOptions` passes `isNetworkMember: (peerId) => this.isControlNetworkMember(peerId) || this.admittingDevices.has(peerId)`. Strand nodes pass nothing (their peers are cross-party).
- **No refresh change.** Optimystic keeps no verdict, so replacing the snapshot in `refreshMembershipGate` is the whole re-evaluation.

## Deviation from the plan: the redeeming device

The plan said a device redeeming an invitation is correctly refused and redemption is unaffected. That was wrong. With the predicate alone, `app-joins-cadre-by-invitation` (`B.wireOwnKeyIfOwner()` false) and `cadre-invite-row-unreplicated` (P lacked the seated row) failed, and both passed with the predicate line removed. The device used to join the member's control cohort the moment it connected, because it serves the party's protocols, and the redemption's seat and admission writes depend on that: the device must hold the rows that admit it. With the predicate it was refused, so those writes committed on the member alone.

Fix: the handler hook `catchUpDevice(peerId): Promise<void>` became `admitDevice(peerId): Promise<() => void>`. `CadreNode.admitRedeemingDevice` counts the device in `admittingDevices` (the set the control backfill gate already used for the push), pushes the control store, and returns a release; `CadreInviteHandler.seatAndRedeem` releases once the seat and the admission have settled. While counted, `isNetworkMember` admits the device; the per-stream gate never does. A failed push releases at once and the writes go ahead without the device (logged). After a successful admission the device is in the snapshot, because the admission's `CadrePeer` write refreshes it before the writer's await returns.

## For the reviewer

- **The device is counted in from before the push, not after it.** One set (`admittingDevices`) serves both the backfill gate, which must admit the device during the push, and the cohort choice. So for the push's duration, other control writes this member makes include a device that does not yet hold the base revisions, and such a write could be refused by the device and retried. Before this change the device was in the cohort from connection onward, so the window is narrower than it was, not new. Splitting the set so the cohort counts the device only after the push resolves is possible; I did not do it.
- **No control backfill on the member** (`controlBackfill.enabled === false`): the device is never counted in, so the seat and the admission commit on the member alone and reach the device later by ordinary replication. Before this change those writes had the device in the cohort without the store, which tears. Not tested.
- **Staleness now applies to cohort choice too.** A member whose row reaches this node by replication is left out of its control cohorts until the next refresh (at most one ~15 s reconcile pass), the same window its streams were already refused. Documented in "The snapshot".
- **FRET's ring still counts a stranger** that lists the party's FRET protocols (upstream Optimystic backlog `feat-fret-honours-the-network-membership-predicate`). Recorded in the doc's "What it does not cover" and in a `NOTE:` at the end of `control-stream-authz` step 5. When that ships, assert the ring excludes O there.
- **Dependency floor.** The ticket said not to bump `@optimystic/db-p2p` here. Commit `43ff6ce9` has since moved every `@optimystic/*` floor to ^1.13.0, and the v1.13.0 tag contains the predicate, so the published floor carries it.
