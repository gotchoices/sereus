# Review: phone app adds a cadre-host node by scanning its code

## What landed

**Settings → "Add an always-on node"** (`src/add-node-section.tsx`, rendered by `app/settings.tsx` only while connected) replaces the old Host Node section. Flow: **Scan code** (camera modal, `src/node-code-scanner.tsx`) or paste + **Use code** → `readNodeCode` → owner check → approval prompt (Party ID, owner fingerprint, short peer id, reach) → **Add to this cadre** → `claimHostNode` → "Node added", or an alert worded by `describeClaimFailure`; when the same code can succeed again, the section keeps it and shows **Try again** / **Discard**. Progress line, plus a second line after 20 s.

- `src/node-claim.ts` (pure, Node-testable): `readNodeCode` (three refusal branches), `nodeReach` (`isPrivateIp` from `@libp2p/utils` on the first IP/DNS component; confirmed it counts loopback, link-local and 100.64.0.0/10 as private), `ownerFingerprint`, `describeClaimFailure` (the ticket's table; refusal words keyed by `ClaimRefusedError['code']` so a new code fails typecheck; an unknown wire code falls back to the no-code wording).
- `use-cadre.ts`: `requestHostNode` → `claimHostNode(payload)` (not-started guard, ref re-entry guard, accepted-tradeoff `NOTE:` for the accept-then-killed window), plus new `isOwnerDevice()`. The cancel-and-wait machinery in `stop` is gone.
- `src/settings-controls.tsx`: `Section`, `Btn`, `LabelledInput` and shared styles moved out of `app/settings.tsx` so the section can use them (settings.tsx 617 → 511 lines).
- `expo-camera` ~16.1.11 (the SDK 53 pin) and `@libp2p/utils` ^7.4.1 added; `app.json` gains the `expo-camera` plugin, and the WebRTC plugin's camera text now matches it.
- Removed: `src/host-node-request.ts` and its spec, the old section, its stage labels and test ids, the hook spec's five host-request tests, the eslint "Import-free app modules" block, docs/testing.md's "App modules in a scenario" section and lint bullet.
- Docs: docs/reference-app-rn.md section rewritten as "Adding a Home Machine's Node (cadre-host)" (setup, firewall, run, failure table, not covered), native-rebuild note, key dependencies, package structure, and the remaining "lent/borrowed" wording. docs/cadre-host.md "Not yet" drops the phone item. docs/architecture.md row 6 links the app's flow, and the dial-limits paragraph no longer cites the forwarded-loopback case.

## Deviations from the ticket (reviewer: check these calls)

- **Owner gate.** The ticket gated on `ownerPublicKey === null`, but a running phone always has an identity-derived owner key (`getIdentityOwnerKey`), so that never fires; a member phone would claim the node with a key the cadre does not trust (the node accepts the secret, then the phone's owner-signed `CadrePeer` write is not an owner's). Instead `isOwnerDevice()` checks the key against the cadre's `OwnerKey` table, and the section runs it **when a code is read**, before the approval prompt ("Only an owner can add a node"). Not an upfront section state: ownership can arrive later by replication and Settings stays mounted, so an upfront check would go stale. `claimHostNode` itself does not re-check (its doc says callers check first).
- **`microphonePermission`** for `expo-camera` is the WebRTC plugin's "Unused…" text, not `false`. Verified with `npx expo config --type introspect`: `false` deletes `NSMicrophoneUsageDescription`, which the WebRTC plugin sets. With the text, camera = the new scan text, microphone = the "Unused" text. `recordAudioAndroid: false` is set, but `RECORD_AUDIO` stays in the Android manifest because the WebRTC plugin adds it (as before).
- **Party ID row** added to the connected Node card, because the prompt is meant to show "the same value the Node card shows" and the card did not show it.
- **"Newer cadre-host" branch** fires only for `sereus-join:<digits>.` with a version other than 1; a cut-off `sereus-join:1` (no dot) reads as damaged.
- **Permission denied:** the scanner offers "Allow camera" while Android still lets the app ask, else "Open system settings"; both point to the paste field.
- `packages/integration-tests/tsconfig.build.json`'s `rootDir` comment pointed at the deleted docs section; reworded to the reason the setting still has.
- Rebuilt `@serfab/cadre-core` (its `dist` was stale from the prereq) and `@serfab/cadre-rn` (comment-only edit) — both in this repo.

## Known gaps

- **No device run** (none available). Camera, permission prompts, modals, and a phone dialing across Wi-Fi are unverified: `blocked/rn-node-claim-by-qr-device-run`.
- **Scanner closes and the prompt opens in the same moment.** A `NOTE:` in `add-node-section.tsx` says what to change if iOS drops the second Modal.
- **The owner check is a control-database read** with no progress shown between reading a code and the prompt; it could wait behind a control write (`bug-control-read-waits-behind-an-explicit-transaction-commit`). A phone whose owner genesis timed out at start gets "Only an owner…" until genesis settles.
- **The hook's own guard errors** ('Node not started', 'A node is already being added') fall into the "Adding the node did not finish… safe to try again" wording. Both are practically unreachable from the UI (section hidden when disconnected; buttons disabled while claiming).
- `nodeReach` treats a public TCP-only address as "anywhere" though the phone dials only `/ws`; cadre-host maps TCP and WebSocket together, so a code with one has the other.
