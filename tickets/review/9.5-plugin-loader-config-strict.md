# Strict plugin-loader settings — review handoff

Maintainer decision (2026-09-28): strict, same as the cadre-cli config file. The plugin loader (Quereus `registerPlugin`, Quoomb CLI/Web) hands the plugin a `Record<string, SqlValue>`; `parseConfig` now validates every key against one table and throws once with every problem listed.

## What changed

- `src/parse-config.ts` — rewritten around `SETTINGS`, a table typed `{ [K in SettingKey]: Setting<SettingTypes[K]> }`. Each `Setting` carries `expected` (the problem-line wording), a pure `read(raw)` returning the typed value or `undefined`, and the flags `emptyIsAbsent` (string and select kinds) and `required` (`strand_id` only). One generic `readSettingInto` applies absence, required, and the problem format for every key, so readers never format errors. Kinds: `TEXT`, `COMMA_LIST`, `PORT` (integer 0–65535), `FLAG` (`true`/`false`/`1`/`0`), `oneOf<T>(Record<T, true>)` (exhaustive against the union, the cadre-cli pattern). `parseTransactor` and `STRAND_TRANSACTORS` are gone. Exports `PLUGIN_SETTING_KEYS` and `ParsedPluginConfig { options, storagePath? }`. The silent-drop NOTE is removed; the "an `IRawStorage` is not a `SqlValue`" point moved to the `storagePath` doc comment.
- `src/plugin.ts` — destructures `{ options, storagePath }`; no longer reads `config.storage_path`.
- `src/plugin-browser.ts` — throws `storage_path is Node-only; the browser entry stores in IndexedDB` when `storagePath` is set; doc comment updated.
- `package.json` `quereus.settings` — `mode` removed; `fret_profile` and `transactor` are `"type": "select"` with `options`. `transactor` lists `network` first on purpose: it has no manifest default, and Quoomb Web's `<select value="">` displays the first option when the value is unset, so the displayed option now matches what the plugin actually uses (`composeStrand`'s `'network'`). JSON cannot carry that comment.
- `README.md` — settings table: `port` range, `enable_cache` accepted values, `select` types, new `storage_path` row; one paragraph on strict checking replaces the old per-row note on `transactor`.

Sample error (from the built `dist`):

```
quereus-plugin-sereus: invalid plugin settings
  - strand_id is required
  - port must be an integer from 0 to 65535 (got "4001")
  - fret_profile must be one of edge, core (got "cor")
  - mode was removed: a lone node now coordinates for itself, and transactor selects the storage engine
  - unknown setting "transactr"; accepted settings are strand_id, bootstrap_nodes, schema, ...
```

`describeValue` handles every `SqlValue` shape: strings JSON-quoted and cut at 120 characters with the length noted, `bigint` as `5n` (so `4001n` is not mistaken for a valid port), `Uint8Array` as `a blob of N bytes`, JSON objects/arrays as `a JSON value`.

## Tests (`test/plugin.spec.ts`, `describe('parseConfig')`)

Existing tests moved to `.options.x`. Changes and additions:

- `should parse fret_profile` — the `'unknown'` → `'edge'` arm was dropped (now covered by the rejection table).
- `should handle empty bootstrap_nodes` — **removed**; it was an exact subset of the new absent-means-default test (`bootstrap_nodes: ''` → `[]`). The ticket listed only in-place edits, so flagging this deviation.
- `should read empty strings and NULL on optional keys as absent` — pins the `''`/NULL rule Quoomb Web's cleared fields depend on.
- `should reject %s = %j, naming the key` (`it.each`) — `fret_profile: 'cor'`, `port: '4001'`, `port: 70000`, `port: 1.5`, `enable_cache: 'false'`, `sapp_version: 2`.
- `should reject an unknown key, and the retired mode with a pointed message` — flipped from the old "ignore" test.
- `should report every problem in one error` — no `strand_id` plus two bad values; one message names all three.
- `should accept exactly the settings the package manifest lists` — the manifest key set equals `PLUGIN_SETTING_KEYS`; guards the drift that left `mode` in the manifest.

No tests for the entry points' `storagePath` wiring (per the ticket).

## Things for the reviewer to check

- **`''` on `port` / `enable_cache` is rejected**, per the ticket's rule that `''` is absent only for string and select keys. Quoomb Web's number input sends `Number('')` = `0` and its checkbox sends a boolean, so the UI does not produce `''` there; a hand-written config could. Decide whether that strictness is what you want.
- **Previously saved Quoomb Web configs holding `mode`** (the old manifest offered it) now fail to load with the pointed `mode was removed` line. This is the accepted cost of strict; the fix for the user is to delete the key.
- **`required` + ill-typed `strand_id`** (e.g. `strand_id: 5`) reports `strand_id must be a string (got 5)`, not "is required". Only missing/NULL/`''` gives the "required" wording the existing tests match.
- **Manifest `label` fields are still absent.** Quereus's `PluginSetting` type declares `label` as required; the manifest never had labels and Quoomb Web falls back to showing nothing. Out of scope here, noted in case the reviewer wants a backlog ticket.
- `browser-shape.spec.ts` / `browser-bundle.spec.ts` load the browser bundle with `{ strand_id }` only, so the new `storage_path` rejection is not exercised there; it was verified by inspection only.
