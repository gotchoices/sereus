# All owner signing goes through one signer

## What changed

Before this, a node signed owner writes from two sources. `SeedBootstrapService` used the private key passed to `initializeSeedBootstrap`. `CadreNode`'s own writes (strands, party keys, formation invitations, validation keys, joined-strand rows, join requests and outcomes, strand-move adoption) used the node's identity key. A node given any other owner key therefore wrote strands and joins the schema refused. Now there is one source:

- **`CadreNode.useOwnerSigner(signer)`** wires the node's one `OwnerSigner`. It refuses on a `claim` node, anchors the key as `genesis`, and builds the owner-capable seed service. `initializeSeedBootstrap(priv)` is now `useOwnerSigner(softwareOwnerSigner(priv))`. **`getOwnerSigner()`** (new, public) reads it back.
- **`SeedBootstrapServiceConfig.ownerSigner`** replaces `ownerPrivateKey` / `ownerPublicKey`. `canAuthorize()` means "has a signer", and a new `ownerSigner` getter exposes it. Every owner-signed service method takes an optional trailing `sign?: OwnerSign`. When a caller passes one, the method signs inside the caller's approval; otherwise it opens its own `approve` with its own action text. `addDrone` / `addPhoneWithRelay` put the vouch and the seed under one approval. Seeds sign the digest bytes through the signer, and `signerKey = signer.publicKey`. The no-signer error now reads `Owner signer required to authorize peers`; it used to say "Owner private key required".
- **`ControlDatabase`**: every writer's callback is the exported `ControlSign = (message) => string | Promise<string>`, and every call to it is awaited. `signGuardedRemoval`, `signJoinOutcomeInsert` and `signJoinRequestInsert` are async. `reissueRevocations` signs its rows one after another, before the lock as before. Synchronous test lambdas still type-check. The write-lock / retry `NOTE:` sits on the `ControlSign` alias.
- **One `approve` per public action**: `unpublishStrand`, `enrollValidationKey`, `removeValidationKey`, `dismissPendingJoin`, `removeMachine` (re-vouches plus removal), `claimNode` (seed, delivery, vouch), `requestJoin` (the request row only), and `adoptStrandBundle` (the whole bundle). `publishStrand` covers the insert and a closed strand's party-key mint. Its read-only paths ask for nothing, and a party-key mint on the "already published" path opens one. The other seed-service actions get their approval from the service: `authorizePeer`, `addOwner`, `removeOwner`, `createSeed`, `createCadreInvitation`, `withdrawCadreInvitation`, `addDrone`. `publishStrand`, `ensureStrandPartyKey` and `publishFormationInvite` take a trailing optional `sign` so a composing caller can share its approval. These new public parameters are an API surface change worth a look.
- **Background writers** call `approve` once per write, each with its own action text. They are: the joined-strand ledger's publish and remove, the pending-join runner's record, rewrite and remove, the drains (re-issue, re-authorize), the ledger marker, the self-row insert in `registerSelf`, the device-token insert and delete, and the launch-time party-key mint.
- **Deleted**: `signMessageWith` (in both cadre-node and strand-move), `requireOwnerSigningKey`, `ownerSigningKeyCandidate`, `enrolledOwnerSigningKey`, and strand-move's local `OwnerSigner` interface. `getSelfSigningKey` stays for the node's own address record, its device-token `Sig`, the invitation redemption, and the identity default below.
- **`isOwner()`** is true when a signer is wired and its key is a live `OwnerKey`. `planMachineRemoval`'s `selfOwnerKey` uses the same rule.
- **`wireOwnKeyIfOwner(signer?)`** chooses its candidate in this order: the `signer` argument, then the signer already wired, then a software signer over the identity key (the interim path for invitation-granted owners). It wires the candidate only when the key is a live owner. It throws if a different key is already wired.
- **`publishStrand`** writes `FounderOwnerKey = signer.publicKey`, and `isSelfFoundedRow` compares against the signer's key.
- **cadre-cli** `withConnectedNode` calls `node.wireOwnKeyIfOwner()` once the session is up, before the action. This applies to every one-shot command.
- **Docs**: in `docs/architecture.md`, the Owner Keys Status note, The owner signer (wiring, plus a new "Composing an action" paragraph), the Invitation-granted owners paragraph, the Enrollment Flow paragraph on `wireOwnKeyIfOwner`, the Implementation Status bullets and the `cadre validation-key` bullet. `types.ts` doc comments are updated too.

## Known gaps and judgement calls for the reviewer

- **`requestJoin` can make two approvals.** One is for the request row. The immediate attempt's outcome goes through the pending-join runner's own per-write approval. Folding it in would hold the approval across a formation network round trip. Similarly, `foundStrand`'s launch can mint a missing party key under a second approval, but only on the healing path.
- **`claimNode` holds one approval across the seed delivery**, which can take up to about 114 s. The ticket asked for this. A hardware backend's presence window may be shorter; that is `feat-owner-key-on-a-hardware-key`'s concern.
- **Founder detection now depends on when the signer is wired.** A watcher launch that runs before the embedder wires the signer brings up the node's own strand as a joiner; a later `foundStrand` founds the tracked instance in place. There is a `NOTE:` at `isSelfFoundedRow`. `owner-key-label-and-founder-machine` replaces the comparison.
- **Every one-shot CLI command now wires the identity key when it is an owner**, the read-only ones (`strand list`, `validation-key list`) included. That costs one `OwnerKey` read and registers a seed handler.
- **The admin server's `unpublishStrand` on a node started without `--owner`** now refuses with "the owner signer is not initialized", which the server classifies as `not_ready` (the client prints "restart with --owner"). Before, it signed with the identity key regardless of `--owner`.
- **Nodes built by `startSelfOwnerNode` now hold an owner service**, so their 1 s self-registration timer inserts their own `CadrePeer` row. Every spec that uses them passes.
- **`useOwnerSigner` is still once per node.** A second wiring hits libp2p's duplicate seed-handler error, as `initializeSeedBootstrap` did. `wireOwnKeyIfOwner(other)` refuses by name when a different key is wired. There is no replace path.
- **Background writers prompt once per write** for a prompting signer. Gating them is `backlog/feat-owner-key-on-a-hardware-key`'s.
