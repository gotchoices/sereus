# "Join a cadre" in the local UI — review

Fourth of the `cadre-host-join-a-cadre` chain. The server side (`/api/hosted-nodes`, the `hosted-nodes-changed` event, the claim route) landed in `cadre-host-hosted-nodes-join-by-qr`; this ticket is the Svelte side only. `cadre-host-join-by-invitation` (next) adds a paste field to the Join page created here.

## What landed

**State (`lib/state.svelte.ts`).** `HostedNodeView`, `HostedNodeStatus` and `ClaimDetails` mirror the server types (narrow, no secret). A `hostedNodes: { list, loaded, error }` slice with `refreshHostedNodes()`; the mutations `joinCadre()`, `removeHostedNode(id)`, `resetHostedNode(id)` throw `ApiError` to the caller and on success re-read the records, the orchestrator handles and the NAT snapshot (`refreshAfterHostedChange`); `fetchClaimDetails(id)` returns the claim payload without storing it. `refreshHostedNodes` carries a request sequence number so an older answer arriving after a newer one is dropped (the Join page's line must not step back to "waiting"). `applyEvent`: `hosted-nodes-changed` re-reads all three without looking up the event's id, so a `removed` for an id the slice never held is just a refresh; `node-state-changed` also re-reads the slice.

**Behaviour change in `refreshNodeDetail`.** A 404 from `/api/nodes/:id` is now an answer, not an error: the handle is dropped from `state.nodes` and no toast is shown. A hosted node whose spawn failed has no handle, and its page now renders from the record alone; previously such a page would sit on "Loading…" and toast every 5 s.

**Helpers (`lib/hosted-nodes.ts`).** `isWaiting`, `ownerFingerprint` (first 8 characters, `—` when absent), `claimedCadre` (the party only once `ownerKey` is set, since the claim sets both), `connectedText`, `stateLine`, `STATUS_BADGE`, `hostedLabel` (Connectivity's per-node label) and `joinNodeRows` (records joined with handles by id; a record with no handle and a handle with no record each get a row).

**`components/ClaimCode.svelte`** — shared by the Join page and the node page. While the node is `unclaimed` it fetches the claim details, retrying every second on 503 (`Starting the node…`), refreshes the slice on 409, and shows any other error with **Try again**. It renders `TokenShare` (224 px QR, textarea, copy label "Copy join details"), the scan instruction, and the warning "Works from your home network now; forward the ports below for a phone elsewhere" when the verdict is `unreachable` (live NAT entry first, the claim's own `reachability` as fallback). It re-reads the code when the node's public addresses in the NAT snapshot change, so a UPnP mapping that completes after the spawn reaches the QR; this was not in the ticket, and it is the reason the effect depends on `publicAddrs`. The payload is component state only and is dropped when the node leaves `unclaimed`.

**`routes/Join.svelte`** (`#/join`, nav "Join"). The button (`Starting a node…` while the POST spawns). One card per followed node, newest first: id link, status badge, the live state line (`aria-live`), and while waiting the `ClaimCode`, the `NodeReachabilityCard` from the live NAT snapshot, and **Cancel** (no confirm). After the claim the card shows "Open this node's page →". "Followed" is page-local: every waiting node is added as it appears and stays for the page's lifetime, so a node claimed while the page is open keeps its card and steps through claimed → connected; a reload shows only the nodes still waiting.

**`routes/NodeDetail.svelte`.** Renders from the handle, the record, or both. The first card holds the process detail (or "No process is running…"), and the handle's placeholder party is no longer shown there. A **Cadre** card: status badge, state line, Cadre ID, owner fingerprint, connected; waiting → `ClaimCode` + **Cancel** (no confirm); joined → **Reset** and **Remove**; error → error text in the state line, **Retry** and **Remove**; a handle no record names → an explanation and **Remove**. Remove, Reset and Retry each go through `ConfirmDialog` with the ticket's wording; Retry got its own wording, and a confirm the ticket did not ask for, because it deletes the failed node's data, which for a node that was once joined is its identity. Reset and Retry navigate to the fresh node's page (new id), with a toast naming both ids. An id that is neither a handle nor a record shows "There is no node … on this machine".

**`App.svelte`.** Nav entry, route, a boot-time `refreshHostedNodes()`, and `{#key}` around `NodeDetail` so moving to the fresh node after a reset starts a new page instead of carrying the old one's state.

**`routes/Nodes.svelte`.** Columns ID, Status (hosted badge plus `no process` / `stopped`), Cadre (the record's claimed party, shortened, full value in the title), Owner, Connected, Spawned. The table scrolls inside its card at narrow widths. The empty state links to the Join page, and the list shows "Loading…" until the slice has loaded.

**`routes/Home.svelte`.** The hosted-nodes tile reads "N joined, M waiting" with "Join a cadre →"; it adds "K failed; see Nodes" when K > 0, which the ticket did not ask for. The Connectivity tile is unchanged.

**`routes/Connectivity.svelte`.** Per-node label from `hostedLabel`: "hosted node for cadre `<partyId>`", "waiting to be claimed", or "hosted node" (no record, or failed).

**Docs.** docs/cadre-host.md: the Join-a-cadre intro names the UI button; a new "In the local UI" subsection under Hosted nodes (the slice and events, the Join page, reading the code, the Nodes list, the node page, Home and Connectivity); the control-plane surface line; the Status SPA line; the Status "Hosted nodes" paragraph drops "next ticket" and says no automated test covers the UI components (`debt-cadre-host-ui-component-tests`). README: the walkthrough's step 3 leads with the Join page and keeps `cadre-host join` as the shell route; Manage hosted nodes mentions Reset and Retry; "Local UI" lists five pages in the order Home, Connectivity, Nodes, Join, Settings.
