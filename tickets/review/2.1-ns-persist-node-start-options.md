# Review: NativeScript remembers the node's start options

Mirror of the landed React Native change (`rn-persist-node-start-options`) for `packages/reference-app-ns`. Every node-local record in the `sereus-peer-identity` SQLite `kv` table is filed under the party id; the party id was typed into Settings each launch, so a relaunch read empty records (sharpest case: the trusted-owner anchor written by a pasted invite). Now the start options are saved and the app resumes them at launch.

## What changed

- **`src/start-options.ts` (new)** — `PhoneNodeOptions` (moved here from `cadre-phone.ts`, re-exported from there), `SavedStartOptions { options, autoStart }`, `parseSavedStartOptions`, `serializeSavedStartOptions`. Record: `{ version: 1, partyId, bootstrapAddrs, autoStart }`. Same rules as the RN copy without relays/Noise mode: absent / not JSON / not an object / wrong version / blank party id ⇒ `undefined` + warning; malformed `bootstrapAddrs` ⇒ `[]`; non-boolean `autoStart` ⇒ `false`. No imports.
- **`node-local-slots.ts`** — `START_OPTIONS_SLOT_KEY = 'start-options'`, module comment extended.
- **`cadre-phone.ts`**
  - The identity database is now opened through `openIdentityDb()`, which caches the in-flight open *promise* (`identityDbOpening`) together with the one unprefixed `SqliteKVStore` over it (so the store's prepared statements are built once per handle, and `kvConstructions` in the spec stays one per open). A rejected open is forgotten (guarded by identity so a later open is not cleared). `closeIdentityDb()` clears the promise first, awaits it, closes the handle; a rejected open has nothing to close. The old `??=` NOTE is gone.
  - `loadSavedStartOptions()` exported; a read fault propagates.
  - Single-flight `startPhoneNode` via a cached `starting` promise; the body moved to `buildAndStartNode`. After `built.start()` succeeds: `nodeOptions = opts`, save `{ options, autoStart: true }` (best-effort, logged).
  - `stopPhoneNode` awaits an in-flight start (ignoring its rejection), saves `{ options: nodeOptions, autoStart: false }` when a start succeeded, then clears and stops as before, and closes the database in `finally`.
  - `startSolo` doc comment says it writes the record too.
  - The NOTE naming `feat-rn-persist-node-start-options` is replaced by a comment saying the records survive a relaunch because the party id does. A new NOTE in `stopPhoneNode` (adapted from RN) records the one unguarded interleaving: a start landing between stop's clear and its `finally` — unreachable today because Disconnect is shown only while connected and the launch auto-start starts only from `idle`.
- **`cadre-vm.ts`** — `savedStartOptions` observable getter (notifies `'savedStartOptions'`), `restore()`: load once; read fault ⇒ `console.warn` + `setError('Could not read the saved connection settings: …')` (shown under the Settings Node card, which binds `cadre.error`); set `savedStartOptions`; if `autoStart` and `status === 'idle'`, `this.start(saved.options)`. `getCadreVm()` calls `void vm.restore()` when it first creates the singleton; the Chat page (default page) calls `getChatVm()` at module load, which calls `getCadreVm()`, so this runs at launch.
- **`settings-view-model.ts`** — constructor prefills Party ID / Bootstrap (joined with `', '`) from `cadre.savedStartOptions`, or subscribes to `propertyChange` for `'savedStartOptions'` and prefills once when it arrives, only into still-empty fields. `onConnect` splits the bootstrap field on commas (trimmed, blanks dropped); a single address behaves as before.
- **Docs** — `docs/reference-app-ns.md` *Node-local records*: ⚠️ paragraph replaced by the start-options paragraph (written/read/overlap/reinstall); `identityDb` reference updated; *Startup Sequence* notes the launch resume; app-structure listing gains `start-options.ts`. `docs/architecture.md`: the "⚠️ NativeScript does not yet…" sentence removed and the RN sentence generalised to both phones. `packages/reference-app-ns/README.md` step 6 now says a relaunch reconnects by itself. `grep -rn "persist-node-start-options" packages docs` finds only a built `platforms/android/.../bundle.js` (gitignored build output).

## Tests

- `test/cadre-phone.spec.ts` — "reads exactly the four node-local keys during start, and writes only the start options": keys read unchanged (start does not read `start-options`), `keysWritten` now `['start-options']`.
- `test/cadre-phone.spec.ts` — new "the saved start options survive a relaunch, and Disconnect turns off the auto-start without forgetting them": start with two bootstrap addrs → `loadModule()` (fresh module state over the same fake `kv`) → `loadSavedStartOptions()` returns the same options with `autoStart: true` → start with them, stop → `autoStart: false`, options unchanged.
- `test/cadre-vm.spec.ts` — new "resumes the last session at launch only when it ended connected": saved `autoStart: true` ⇒ `getCadreVm()` starts with exactly the saved options; `autoStart: false` ⇒ nothing started, `savedStartOptions` carries the options.
- `test/stubs/fake-cadre-node.ts` — `loadSavedStartOptions` added to `phoneNodeMock()`, returning `state.savedStartOptions` (reset to `undefined`).
- Comment-only update to the "retries a failed start over the handle that start already opened" test (it named `??=` / `identityDb`).

## Not tested / by inspection only

- **Parser branches** — not duplicated; the RN copy carries the parse test and the NS parser is the same code minus two fields. A reviewer may want to diff the two parsers by eye.
- **Settings prefill** (both the immediate and the late-arrival path) and the **comma-split** in `onConnect` — no new tests, per the ticket's test list. The existing `onConnect` tests still pass (single address, blank field).
- **Connect tapped while the launch read is in flight** — `restore` sees `status !== 'idle'` and does not start; the cached open means one handle. By inspection.
- **Disconnect during the launch auto-start** — stop awaits the start, then saves `autoStart: false`. By inspection (RN has the same shape).
- **Read fault at launch** — error message path not covered by a test.
- **Save failure** — logged, node unaffected. By inspection.
- **Stop while the launch read's open is still in flight** — `closeIdentityDb` awaits the open and closes it, so no handle leaks; the launch read might then fault on a closed handle and show the read-fault message. Needs a Connect + Disconnect inside the launch read's window; judged too narrow to guard.
- No on-device run (Maestro flows are shared with RN and launch with `clearState: true`, so the new auto-start does not change what they see).
