First of the `strand-offline-mode` chain, in `@serfab/quereus-plugin-sereus`. Upstream background: Optimystic 1.20.0's Quereus plugin README, "Offline mode" (`../optimystic/packages/quereus-plugin-optimystic/README.md`, read only).

## What landed

- **`StrandConnectionOptions.offline?: StrandOfflineOptions`** (`types.ts`): upstream `OfflineConfig` less `journalLabel`. Absent → no `offline` key in the plugin register config and no `offline` on the result (checked by a throwaway script: `'offline' in result === false`, `'appSchema' in result === false` with no schema).
- **Register pass-through** (`registerStrandPlugins` + `strandOfflineConfig` in `compose-strand.ts`): the caller's options, plus the platform's default journal when none is given, plus `journalLabel: strandJournalLabel(strandId)` only when a journal exists (upstream refuses a label without one). Label = `strand-` + id with `_`→`__`, `.`→`_d`.
- **New optional platform seam `StrandPlatform.defaultOfflineJournal()`**: the browser connect answers an `IndexedDBKVStore` over the IndexedDB handle it defaulted the storage to (`sereus-strand-<id>`, default key prefix). Node supplies none → memory-only queue.
- **`SereusPluginResult.offline?: StrandOfflineController`**: a type-level `Pick` of `OfflineMode` (the 12 methods the ticket names). At runtime it is the `OfflineMode` instance itself.
- **`offlineControllerOf(db)`**: module-level `WeakMap`, set right after registration when `options.offline` is given, deleted in `shutdown` and in the failed-composition catch. Exported from the index.
- **`releaseOptimysticPlugin`** awaits `plugin.offline.dispose()` before `txnBridge.dispose()`; local shim gained `offline: OfflineMode`. Runs on both shutdown and the failed-composition path.
- **All eight `Strand` tables tagged `with tags ("optimystic.offline" = 'network')`** in `schemas/strand.qsql` and `STRAND_SCHEMA` (drift spec green). Throwaway checks confirmed: (a) every table carries the tag after a cold connect; (b) a store whose eight tables were created **without** the tag hydrates them (`tables: 8`) and the next connect applies the tag; a further reconnect still has it.
- **App-schema deferral**: `applyAppSchemaAfterQueue(db, schema, queue, released: AbortSignal)` in `compose-strand.ts` (exported from the module, not from the package index). The first apply succeeds → `{ appSchema: Promise.resolve({ state: 'applied' }) }`. Refused with `QueuedEntriesBlockSchemaChangeError` anywhere on the `cause` chain → returns `appSchemaDeferredBy` (the refusal's ids) plus a background retry: `whenDrained()`, apply, repeat while the same refusal returns. Settles `applied`+`deferred`, `failed` (other error, including a queue defect `whenDrained` rejects with), or `cancelled` (`released` aborted, or `QueueDisposedError`). Any other first-apply error is thrown, so the connect fails as before. `composeStrand` step 7 calls it with `pluginResult.offline` and spreads the result (`appSchema`, `appSchemaDeferredBy`) into its return.
- **The `NOTE:`s**: `networkCommitTimeoutMs` default at registration; the `Strand` apply is not deferred; `StrandDatabase.attachAppSchema` is not deferred (cadre-core); the retry loop runs without a pause if a refusal ever outlives a drain; shutdown does not await a deferred apply that is already running.
- **Docs**: `docs/strands.md` has a new "Offline mode" section (the option, the controller, programmatic only, release order, where queued transactions are saved and the label, the network-acknowledged `Strand` tables and their three consequences, the app-schema deferral and the alternatives rejected, `attachAppSchema`). The "Writable does not mean connected" bullet now says "outside offline mode" and has an *In offline mode* sub-paragraph (`allowSoloCommit` stays `false`, and why). The plugin README has an `offline` options row and a short "Offline mode" section linking to strands.md.

## Test added

- `packages/quereus-plugin-sereus/test/app-schema-deferral.spec.ts`: registers the Optimystic plugin directly on the `local` transactor with `offline: {}` and a closed `ICohortReachability` gate on `local:libp2p`. Applies `App` with a `Note` table, then `enter()`, inserts a row, `exit()`. Then `applyAppSchemaAfterQueue` runs with an upgrade that adds `index NoteByBody`. It checks that the first apply is deferred with exactly the queued transaction's id, that the table has no index, and that the row reads back. It then opens the gate (with a wake) and checks the outcome is `{ state: 'applied', deferred: true }` and that the index exists. It calls `exit()` before the apply because a real connect applies its schema before the app could enter the mode, so the queue it meets is the one `hydrate` restored.

## Known gaps and judgement calls for the reviewer

- **`appSchema` is optional**, present only when `options.schema` was given. The ticket said "the result carries `appSchema`"; with no schema there is nothing to report, and a replica connect (cadre-core) passes none. `strand-offline-cadre-core` reads `appSchema` / `appSchemaDeferredBy` and must handle `undefined`.
- **Shutdown during a deferred retry** is handled by an `AbortController` that `shutdown` aborts before releasing: checked after `whenDrained`, and any failure after abort maps to `cancelled`. A retry apply already in flight is not awaited (NOTE at `shutdown`). Untested; it follows from the outcome mapping.
- **The browser default journal is never `close()`d**, the same lifecycle as the defaulted `IndexedDBRawStorage` (the handle belongs to the page or worker). Upstream flushes every write a queued commit depends on before the commit resolves, so nothing promised is held only in memory. The store's idle-flush timer can still fire after shutdown on the still-open handle. No browser test exercises the default; inspection only.
- **Not tested, by the ticket's direction**: config pass-through, label escaping (injective by construction: `_` is always followed by `_` or `d`), tags, release order, `offlineControllerOf` lifecycle. A throwaway script checked the last two (deleted).
- **The controller is the live `OfflineMode` instance** typed as a `Pick`; plain-JS callers can still reach its internal methods. A wrapper object would hide them at the cost of re-binding twelve methods; not done.
- `applyAppSchemaAfterQueue` takes `queue: Pick<StrandOfflineController, 'whenDrained'>`, the narrowest thing it uses, which is why the spec can pass `plugin.offline` directly.
