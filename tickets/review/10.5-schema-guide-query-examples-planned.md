# Schema guide query examples are planned against a named schema

## What changed

`packages/quereus-plugin-sereus/test/schema-guide-examples.spec.ts` reads every fence in `docs/schema-guide.md`. The info-string grammar is now:

- `sql schema` or `sql schema <name>` — unchanged behaviour (apply, then plan an insert/update/delete per table and a select per view). The name is optional.
- `sql query <name>` — new. Fresh database, `applyAppSchema` of the named schema block (no seed, no per-table write planning), `db.setSchemaPath(['App'])`, `new Parser().parseAll(text)`, then `db.getPlan` for each statement. Never run.
- `sql script`, `sql fragment` — unchanged, take no name.

Names match `/^[a-z][a-z0-9-]*$/`. A `query` without a name, a name on `script`/`fragment`, a malformed name or a fourth word fails the "marks every fence" test; that test also fails on a schema name used twice. Lookup is by name across the whole guide, so a query may sit above its schema.

Code shape: `markerOf` became `fenceOf`, returning a discriminated union `Fence` (so `query` always carries a name at the type level); `planOrExplain(db, label, statement)` takes a label and a string or parsed statement; `planSql` is the string-quoting wrapper the schema path uses; `checkQueries` does the query path; `checkBlock` switches on the marker. The header comment lists the new form and the existing `NOTE:` now says planning proves compilation, not run-time success (an insert omitting a NOT NULL column plans cleanly).

Guide changes (block by block, as the implement ticket specified):

- Names: `chat` (Putting It All Together; gained `tags text null`, a JSON array of tag strings), `ledger` (Global Assertions), `event-clock` and `message-graph` (Ordering Events), new `org` (`employees` table added under the CTE heading).
- Now `sql query`: the Ordering `insert … with context now_iso = …` and Pattern A select; CTEs (over `employees`; materialization-hint example is two real CTEs and a real final select, no `recursive`, no `select ...;`); set operations over `chat` columns; RETURNING (insert now supplies `sent_at` and returns `NEW.slug`); table-valued functions (`cross join lateral json_each(m.tags)` and `json_tree(:payload)`, plus a sentence that a comma join fails with "m.tags isn't a column"); window functions over `ledger`.
- Deleted the "LATERAL with JSON table-valued function" lead-in and fence under Additional Coverage (it repeated the TVF example).
- Intro: new marker list, and a sentence that Sereus puts app tables in schema `App` so app code qualifies them, as `packages/reference-app-web/src/lib/chat-dml.ts` does; query examples leave them unqualified for brevity.
- Only lone constraint lines remain `sql fragment` (the "Id immutability / delete guards" block).

`docs/testing.md` → "Schema guide examples execute" describes the `query` marker, the duplicate-name rule, and what `fragment` now covers.

## Deviations from the implement ticket

- **`diff` comment corrected.** The ticket said to keep "Quereus extension: multiset difference". Quereus plans `diff` as `(A except B) union (B except A)` — a symmetric difference (`../quereus/packages/quereus/src/planner/building/select-compound.ts`, the "Expand DIFF" comment; the parser's error text says the same). The guide now says symmetric difference, and the example is "users who started a conversation or posted, but not both".
- **Digest chain runs over `ledger` rows**, not the probe's literal `select 1 … where x < 3`: `row_number() over (order by id)` numbers the entries, and a recursive CTE joins each step to the next entry, hashing `digest(previous, id, kind, amt)`. Plans and runs.

## Tests

No new test file. The existing per-block loop now also generates one `it` per `sql query` block (seven today), and the "marks every fence" test gained one assertion for duplicate schema names. Both are the contract the ticket asked for; the negative cases were checked by hand and are not kept as tests.

## Known gaps / for the reviewer

- A parse error in a query block is not wrapped with a statement position: `parseAll` parses the whole block at once, so the message is Quereus's own, with line and column relative to the fence. The test title names the block.
- The duplicate-name assertion sits after the unmarked-fence assertion in the same `it`, so when both are broken only the first is reported until it is fixed.
- Planning, not running, remains the limit for query blocks too: the RETURNING insert would still be refused at commit by `sender_is_member` without a membership row, and nothing here would notice a run-time failure. That is recorded in the spec's `NOTE:`.
- `tickets/backlog/feat-shared-causal-history-for-sapps.md` edits "Ordering Events"; it must keep the `event-clock` / `message-graph` names, which the spec now enforces.
