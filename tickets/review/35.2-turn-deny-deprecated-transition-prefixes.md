## What changed

`ops/docker/coturn/turnserver.conf`, IPv6 `denied-peer-ip` block (was lines
67-78, now 67-83): added two entries after the existing NAT64 lines —

```
denied-peer-ip=2002::-2002:ffff:ffff:ffff:ffff:ffff:ffff:ffff       # 6to4 (2002::/16, RFC 3056, deprecated)
denied-peer-ip=2001::-2001:0:ffff:ffff:ffff:ffff:ffff:ffff           # Teredo (2001:0000::/32, RFC 4380)
```

(entries themselves have no inline comment — coturn config syntax doesn't
support trailing `#` comments reliably on the same line as a directive value
in this file's existing style, so I kept the two-line block comment above the
whole IPv6 section instead, consistent with how the pre-existing
IPv4-mapped/NAT64 lines are documented.)

Updated the block comment above the IPv6 deny lines to name all four
transition mechanisms now covered (IPv4-mapped, NAT64, 6to4, Teredo) instead
of just the first two, and dropped the "every non-public IPv6 range"
overclaim language.

## Range math (hand-verified against RFC boundaries, per ticket's edge-case note)

- `2002::/16` (6to4): first 16 bits fixed = `2002`, remaining 112 bits vary.
  Range `2002::` (`2002:0000:0000:0000:0000:0000:0000:0000`) through
  `2002:ffff:ffff:ffff:ffff:ffff:ffff:ffff` — correct, matches /16 exactly.
- `2001:0000::/32` (Teredo): first 32 bits fixed = `2001:0000`, remaining 96
  bits vary. Range `2001::` (`2001:0000:0000:...:0000`) through
  `2001:0:ffff:ffff:ffff:ffff:ffff:ffff` (`2001:0000:ffff:...:ffff`) —
  correct, matches /32 exactly and does NOT extend into `2001:db8::/32`
  (documentation prefix) or other allocated `2001::` space, since those sit
  above the fixed 32-bit Teredo prefix boundary.
