# Review: extract the strict config checker into `@serfab/config-check`

## What landed

A new workspace `packages/config-check` (`@serfab/config-check`, version 1.7.0, no runtime dependencies, no `node:` imports). cadre-cli now depends on it (`workspace:^`) and keeps only its own parts.

Package layout:

- `src/checkers.ts` — `Problem`, `ValidationContext`, `Checker`, `FieldTable`, `ObjectOptions`, `isPlainObject`, `kindOf`, `describeValue` (with its `NOTE:`), the scalar checkers, `numberWhere` (now exported, for the provider's port ranges), `oneOf`, `arrayOf`, `objectOf`, `refine`; private `joinPath`, `rejectKey`, `reportMissing`. Moved verbatim from cadre-cli's `schema.ts` except:
  - `ValidationContext` takes an optional `suppliersOf(keyPath)` in its constructor (default: none). `missing()` calls it where it used to call cadre-cli's `envVarsFor` directly.
- `src/validate.ts` — `validateTree(tree, root, { configPath, provenance?, suppliersOf? })`: what `validateConfig` / `checkRoot` / `sourceOf` / `isPathPrefix` did.
- `src/env.ts` — `specifiedEnv`, `applyEnvOverrides(raw, env, overrides, onApply?)` (the override loop plus `setNestedValue` / `cloneBranch`), `EnvOverride`, `OverrideResult`, and the text parsers `parseListEnv` (with its `NOTE:`), `parseBooleanEnv`, `parseNumberEnv`. Environment maps are typed `Readonly<Record<string, string | undefined>>`.
- `src/nearest-key.ts` — moved verbatim; cadre-cli's copy deleted.

What stays in cadre-cli:

- `schema.ts` (461 → 201 lines): all field tables, `RETIRED_IDENTITY_KEYS`, `identityKeyFile`, the `strandFilter` checker, `envVarsFor`. `validateConfig(tree, provenance, configPath)` keeps its signature and calls `validateTree(..., { suppliersOf: envVarsFor })`.
- `env.ts`: `ENV_MAPPINGS` (still with `kind`), `COMMAND_ENV`, launcher and retired lists, `checkEnvNames`, `parseJsonObject`. New `ENV_OVERRIDES` maps each `kind` to its parser, in the form `applyEnvOverrides` takes. `parseEnvValue` and the local `specifiedEnv` are gone (no remaining callers).
- `loader.ts`: `applyEnvironmentOverrides(raw, env)` keeps its signature. It runs `checkEnvNames`, then `applyEnvOverrides(raw, env, ENV_OVERRIDES, logOverride)`. `logOverride` is the old debug line, still redacting `CADRE_PUSH`. cadre-cli no longer re-exports an `OverrideResult` type (nothing imported it; the return type now comes from the package).

Wiring:

- The stale-build guard `TARGETS` in cadre-cli, cadre-host and integration-tests each gained `@serfab/config-check`.
- The Dockerfile's four stages and `docker/workspace-root.package.json` now include `packages/config-check`. `.dockerignore` excludes only `node_modules`/`dist`/tsbuildinfo, so nothing to change there.
- Root `package.json`: `pub:config-check`, placed first in the `pub` chain. `knip.ts` has a workspace entry.
- Docs: AGENTS.md orientation, the `docs/architecture.md` package list and cadre-cli status line, `docs/releasing.md` (seven publishable packages, new order, the individual list now also shows `cadre-rn`, and "publish the others" in place of the stale "other four"), and two `docs/testing.md` lines: the guard exemption, and how the package stays runtime-neutral.
- Comments in `scripts/publish-package.mjs` and `scripts/release-guard.mjs` that said "six publishes" no longer give a count. The `--tag` NOTE said the last package in the chain was `cadre-host`; it now names `cadre-rn`.

## Not done / gaps for the reviewer

- **Docker image not built.** The four stages were checked only by reading them. A real `docker build -f packages/cadre-cli/docker/Dockerfile .` is the check to run if someone has the time.
- **`yarn check:published` not run.** It builds a worktree from `HEAD` and refuses a dirty tree, so it cannot see an uncommitted change. Run it after this commit lands.
- **Full root `yarn test` not run as one command.** The only suites that load changed code were run: cadre-cli, cadre-host, integration-tests' target-list spec, and the root script tests. cadre-core, quereus-plugin-sereus, cadre-rn and the reference apps do not import anything that changed.
- **Indentation is two spaces, not tabs.** The ticket said "tabs per `.editorconfig`", but the repo has no `.editorconfig`. The moved code was two-space, and cadre-provider (the package this one copies its layout from) is two-space too. Moving it verbatim kept it that way.
- **New public API beyond what cadre-cli uses:** `kindOf`, `numberWhere` and `parseListEnv` are exported for the provider follow-up (`provider-config-strict-validation`). Nothing outside the package uses `kindOf` yet.
- No test was added. This is a move with no behaviour change, and cadre-cli's unchanged specs pin the package's behaviour. The package has no suite of its own, as the ticket specifies.
- No release note in `.release-notes.pending.md`: nothing a user sees changes, apart from one more package being installed alongside cadre-cli.
