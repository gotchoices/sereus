## What was built

Maintainer decision (2026-09-27), item 2. A new protocol on the **strand** libp2p node, `/sereus/strand-peers/1.0.0`: when two strand peers connect, each sends the other the signed entries of its strand peer book and merges what comes back. Every entry is signed by the named peer's own strand transport key over the canonical JSON of `{ v: 1, strandId, peerId, addrs, issuedAt }`, and a receiver verifies it against the public key embedded in the Ed25519 peer id. The book therefore proves "this peer's own claim about where it is", never membership; the module comment in `strand-peer-book-protocol.ts` carries the four reasons the member key was not used.

- **Wire protocol, signing, verification** (`strand-peer-book-protocol.ts`, new, 432 lines): `SignedStrandPeerEntry` (a `StrandPeerEntry` without `lastSeenAt`, `sig` required) and `StrandPeerBookFrame { strandId, entries }`, the same shape as request and response. `signStrandPeerEntry`, `verifySignedStrandPeerEntry` (returns a verdict with a reason, never throws), `verifyStrandPeerBookFrame` (refuses a frame naming another strand, a non-list, or more than 16 entries; drops a failing entry individually with a debug line; drops entries naming the receiver; one entry per peer id), `assertBookFrameFits` (entry cap and the 64 KiB byte cap, at the encoder), `StrandPeerBookService` (receiver: `node.handle` with `runOnLimitedConnection`, read timeout, concurrency cap, empty frame on every error path), and `exchangeStrandPeerBook` (client: one stream on the given connection under one deadline, returns the verified entries). Framing and stream handling reuse `control-stream.ts` and `decodeLengthPrefixedFrame`, as `strand-addr-protocol.ts` does.
- **Per-strand driver** (`strand-peer-book-swap.ts`, new, 310 lines): `StrandPeerBookSwap` owns the own entry, the receiver, and the exchanges. Own entry: built from the node's own bound addresses via `dialableAddrs`, `issuedAt` strictly increasing, signed at arm time and re-signed when the address set changes (`self:peer:update`, debounced 1 s), filed in the book under the node's own peer id; the copy the node sends lives in memory. Exchange on `peer:identify` when the peer speaks the strand's block-transfer protocol and lists the swap protocol (an older node is skipped, logged), throttled to one per peer per 10 minutes, at most one in flight per peer; on every own re-sign, one exchange with every connected strand peer past the throttle; on `start`, a walk of the peers already connected. The sender's own entry is filed as seen now, a forwarded third party's as never seen (`lastSeenAt: 0`, so it ages from the signer's clock). A failed exchange is logged and waits out the throttle.
- **Shared helper** (`strand-peer-observer.ts`): `connectedIdentifiedPeers(libp2p, label)` groups open connections per peer and reads protocols and stored addresses from the peer store, skipping peers whose identify has not finished. The observer's start walk now uses it, and so does the swap. `AddrLike` is exported.
- **Wiring** (`strand-instance-manager.ts`, `cadre-node.ts`): `StartStrandConfig.strandPeerBook?: StrandPeerBookStore`; `CadreNode.launchStrand` passes its book store. The manager arms one swap per strand right after the libp2p node exists (beside the observer) and stops it in `releaseRuntime` before the enforcer, so the failure rollback and a hibernation quiesce both release it and a resume re-arms it from the retained config. The `strandPeerBookStore` field doc names the swap as the book's third writer.
- **Identity-less nodes get a cadre-held random key.** A node with neither `keyStore` nor `privateKey` used to launch its strand nodes with `privateKey: undefined`, leaving libp2p to generate a key cadre-core never saw, so the swap could not sign. `launchStrand` now generates a random Ed25519 key for that case. Same randomness as before, but held by cadre-core, retained with the launch config (the strand peer id is now stable across a hibernation resume within one process), and a delegate is now announced for it on the launch seed pass. Two tests in `cadre-node-strand-launch-key.spec.ts` that pinned the old contract were rewritten to pin this one.
- **Docs**: `docs/architecture.md` gains a "Kept fresh by the signed book swap" bullet (trigger, throttle, what travels, what is signed and by which key, why not the member key, what the book proves, receiver rules, own entry), the protocol list at the top of the doc names the new id, and the "machine count is not a party count" bullet and the cross-party bullet's closing sentences were updated. `docs/strands.md` closes the "Never refreshed while apart" limit with a swap paragraph and restates the design boundary as the remaining gap. `.release-notes.pending.md` gains a bullet and the previous bullet's "still missing" sentence points at it. `StrandPeerEntry.sig` is documented as base64url over the named payload; the `pruneAged` NOTE now states the own-entry mechanism.

## Deviations from the ticket, kept

- **Two modules, not one.** The ticket named `strand-peer-book-protocol.ts` only. The wire protocol and the per-strand driver have different dependencies (the driver needs the store, the link budget and the observer helper; the protocol needs none of them) and the driver is what a test mocks a libp2p node for, so they are split.
- **Own entry signed at arm time, not after the first relay attempts settle.** Signing happens in `start()`, before the database bring-up; the relay reservation landing fires `self:peer:update`, which re-signs and pushes. Waiting would have left the handler unregistered while the bootstrap dials landed, and a peer that dials an unregistered handler sits out its ten-minute throttle. Registering the handler itself fires `self:peer:update` (libp2p merges the protocol into the self record); the debounced refresh sees an unchanged address set and signs nothing.
- **No aging exemption for the own entry in the store.** The entry the node sends is the in-memory one, refreshed on every launch and address change, so the stored copy is a record for diagnostics and the seed's self-skip; losing it to age costs nothing. The store still cannot tell self from a peer, and need not.
- **The client opens the stream on the identified connection** (`connection.newStream`) rather than `dialProtocol(peerId)`. The connection is in hand from identify and from the connected-peer walk, and it avoids the connection manager's preference for a non-limited connection when the only one is relayed.
- **Deadlines derive from the declared link**: `circuitRequestBudgetMs(linkRoundTripMs, 1000)`, 8 s at the default, for both the client's whole exchange and the receiver's read, instead of a fixed 10 s.
- **The sender omits the recipient's own entry and the receiver drops entries naming itself**, so a node's own statement is never overwritten by a remote copy. Duplicate addresses in a received entry are collapsed before the attribution count.

## Known gaps and what is unproven

- **Third-party forwarding is proven only in-process** (two swap drivers on mock libp2p nodes over `duplexPair` streams). No live three-party scenario; `scenario-relay-only-restart-reconverges` may add one.
- **Rotation is proven with a synthetic `self:peer:update`** on a mock node: the address set changes, the event fires twice, one re-sign reaches the connected peer past the throttle. A live relay rotation is not scenario-tested.
- **Revoked peer, hibernation, open strands: inspection only.** The handler is registered through `node.handle`, so a closed strand's `authorizeInboundStream` judges it; the revocation connection gater blocks the outbound dial; `releaseRuntime` stops the swap and `resumeStrand` rebuilds from the retained config, which carries `strandPeerBook`; nothing in the protocol touches a member key.
- **`resumeStrandRuntime` announces no delegate for an identity-less node**: the random key lives only in the manager's retained launch config, so the resume seed pass passes `undefined`. Pre-existing for that shape, which no production embedder uses; noted, not fixed.
- **Every received entry persists on the persistent backend**, including an unchanged forwarded entry (the prior review's tripwire at `PersistentStrandPeerBookStore.merge`). Bounded by the ten-minute throttle per peer.
- **One connection produces two exchanges** (both sides dial at identify), as the ticket accepted.
- **The frame-size assertion is not tested.** Worst honest frame is about 38 KiB against the 64 KiB cap; the assertion throws, which fails that exchange and logs.
- **Line count**: `strand-peer-book-protocol.ts` 432, `strand-peer-book-swap.ts` 310, `strand-peer-observer.ts` 235 (`wc -l`). `cadre-node.ts` grew by about 15 lines and is tracked by `backlog/debt-cadre-node-single-file-size`.

## Tests

`packages/cadre-core/test/strand-peer-book-protocol.spec.ts` (new, 4 tests):

- **Round trip**: two swap drivers on mock libp2p nodes; A holds a signed entry for C, B holds an unsigned observation of A. After B identifies A: B holds A's signed statement (seen now) displacing the observation, and C's exactly as forwarded (never seen); A holds B's statement from the response; exactly one stream was opened; a second identify inside the throttle opens none.
- **Own-entry re-sign on `self:peer:update`**: after one exchange, A's addresses change and the event fires twice; B ends up with the new addresses under a greater `issuedAt` and a different signature; A opened exactly two streams in total (the debounced burst signed once).
- **Verification**: one frame carrying a valid entry, one with tampered addresses, one signed by the wrong key, one dated six minutes ahead; only the valid one survives.
- **Frame refusal**: a frame naming another strand rejects.

`packages/cadre-core/test/strand-peer-book.spec.ts`: two rows added to the merge-rule table: a fresher signed statement with no addresses displaces a stale reachable list; two signed statements with equal `issuedAt` take the incoming copy. (The "stale forwarded statement loses to the fresher one held" row already existed.)

`packages/cadre-core/test/cadre-node-strand-launch-key.spec.ts`: two tests rewritten for the identity-less contract (a fresh random Ed25519 key per launch; that key's peer id announced as the delegate).

Integration assertions added: `strand-formation-cross-party-seed` Subject 4 now reads the entries for others (each book also holds its own signed entry) and a new Subject 5 waits until both books hold the other side's self-signed entry and checks the joiner holds the host's exact signature. `blind-relay-phone-to-phone-e2e` waits for both self-signed entries after the mesh is classified relayed and checks every address in them is circuit-routed and bound to the peer, which is the proof that the swap ran over a limited connection.
