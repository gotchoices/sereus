# Dial preference without "owner machines" — review handoff

## What changed

**`SeedPeer`** (`types.ts`) lost `isOwner` and `publicKey` and gained `preferred: boolean`, a hint to dial that peer first. Nothing in a seed now claims anyone is an owner; the seed's `signerKey` is still the only owner-related field and is still judged against the receiver's node-local anchor.

**`projectSeedPeers(rows, minterPeerId)`** (`control-database.ts`) marks a peer preferred when it is the minter or its `CadrePeer.Profile` is `'storage'`. It reads no `OwnerKey` row. `ControlDatabase.querySeedPeers(minterPeerId)` passes it through. Callers:
- `SeedBootstrapService.mintSeed` passes its own libp2p peer id (the same id `addSelfRelayAddr` already used).
- `CadreInviteHandler` gets a new required option `peerId` (the answering member), set by `CadreNode` from `controlNode.peerId`. The reply decoder (`sanitizePeers`) reads `preferred === true` and drops everything else.

**Seed application.** `SeedBootstrapService.dialSeedOwners` → `dialPreferredPeers`; it dials `preferred` peers with addresses, skipping self, with the same per-address and per-peer limits (`dialPeerAddrs`). `CadreNode.recordSeedBootstrapPeers` retains `preferred` peers as cold-start dial targets.

**`ApplySeedResult.ownerDialsAttempted/ownerDialsFailed` → `preferredDialsAttempted/preferredDialsFailed`.** The ticket did not ask for this rename. I made it because the old names would have been wrong, and the repo has no backwards compatibility. It touches `cadre-node.ts` (`noteAppliedSeed`), the reference-app-ns fake node stub, the cold-start-retry scenario and the docs.

**Control cohort.** `selectControlCohortDials(siblings, targetDegree)`: the backbone (always dialed) is now siblings whose `profile === 'storage'`; phones and siblings with no profile yet fill up to `targetDegree` in peer id order. `cappedNonOwner` → `cappedNonBackbone`. `CohortPeerRow` gained an optional `profile` (optional so `deriveCohortMembers` callers are untouched). `CadreNode.listMembers()` is now declared as returning `CohortPeerRow[]`; it already returned whole `CadrePeerRow`s at runtime. The `getOwnerKeys()` read and its NOTE at the reconcile call site are gone.

**cadre-cli `enroll add`**: the report field `ownerAddrs` → `seedAddrs` (the `--json` output changes too), filled from preferred peers. Human output reads "Addresses in this seed:". The unreachable warning says "No machine this seed tells the new one to dial has an address…". The README and the `--json` option help text are updated, and so is the `start.ts` comment.

**Docs**: `architecture.md`: the `SeedPeer` interface; the self-registration paragraph after `PeerAddressRecord`; Unified Node Behavior step 2; Cohort auto-connect (backbone by profile); the dial-helper callers; Cold-start retry (preferred peers, the renamed result fields, self-exclusion); the `CadreInviteRedeemReply.peers` comment; Which Side Dials (the stranded-node paragraph and table row 2); seed trust ("nothing else in a seed claims anyone is an owner"); "What the replicated table is still for" (no longer a dial-hint source); receiver hardening; the budget sentence; the Implementation Status `enroll add` line. `reference-app-rn.md`: the bootstrap-peer store line. Comments in `bootstrap-peer-store*.ts`, `seed-trust-policy.ts` and two harness files (`control-trio.ts`, `node-fixtures.ts`) are reworded to match.

## Audit (no fixes needed)

I read every `ed25519PublicKeyB64FromPeerId` use and every `getOwnerKeys()` read in `packages/*/src`. No membership, admission, wake, strand-address or push decision treats a peer as privileged because its identity key is an owner key:
- Identity bindings, which stay: `resolvePeerAddrs` and `resolveDeviceToken` (the stored key is the key behind the peer id), `getSelfSigningKey`, the invite handler's `peerKey` vs connecting identity check, `peer-authorization.ts` (the usage's `peerKey` is its peer id's key), formation contact (`partyId` embeds `peerKey`), `machine-removal.ts` `describeMemberRow` (self-signature check), and `authorizePeer` filling the row's `PublicKey`.
- `getOwnerKeys()` reads that remain check a **signer's** key against the table (`enrolledOwnerSigner`, `planMachineRemoval`'s `canSign`, `wireOwnKeyIfOwner`) or invitation liveness. None of them maps a peer id to an owner.
- `membership-connection-gater.ts`, `control-protocol-guard.ts`, `strand-wake-protocol.ts`, `strand-addr-protocol.ts`, `delegate-admission.ts` and the relay files have no owner-key-by-peer-id path.
- The known exception stays as documented: `wireOwnKeyIfOwner()` falls back to a signer over the node's identity key (`identityOwnerSigner`) for invitation-granted owners. `architecture.md` → "Invitation-granted owners, until owner grants land" already names it, and `tickets/plan/2-owner-grant-separate-from-machine-invitation.md` replaces it.

## Known gaps / things to look at

- **The harness still gives the owner node the owner key as its libp2p identity.** `test-party.ts` (~113–119) carries a comment saying this is needed so the owner is "marked `isOwner` in its own seeds", which is now untrue. I left it because `harness-owner-keys-separate-from-node-identity` (implement/1.07) deletes that comment and the key derivation.
- **Profile is self-declared and unchecked** for the dial preference (it is not checked against the row's self-signature, unlike `describeMachines`). A machine misdeclaring `storage` costs extra dials only, never access. That is stated in the comments on `projectSeedPeers` and `selectControlCohortDials`.
- **Backbone out-degree is no longer bounded by a "small by design" owner set.** A `NOTE:` tripwire at `selectControlCohortDials` says to cap the backbone if a party ever runs more than a handful of always-on machines.
- **Seeds and invitation replies from before this change are not readable for dialing** (no `preferred` → nothing dialed), as the ticket accepted. Seed decoding is still a plain JSON cast; a missing `preferred` is falsy, so it reads as false.
- **Phone-only parties**: the only preferred peer is the minter, and only if the minter has a `CadrePeer` row (a solo founder before `registerSelf` contributes none). Checked by reading the code, as the ticket planned; no test.
- **`listMembers()`'s declared return type widened** to `CohortPeerRow[]` (now includes optional `profile`). Embedders that consume it compile unchanged; worth a glance if a reviewer prefers a narrower public type.
