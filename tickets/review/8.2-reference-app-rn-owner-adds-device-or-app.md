# Review: phone reference app "Add a device or app" (the owner side)

The owner app's half of joining an existing cadre. The joining half is `reference-app-rn-joins-existing-cadre` (reuses `ShareCode` and `CodeScanner` from here); the web owner half is `reference-app-web-owner-adds-device-or-app`. The user-facing behaviour is written up in docs/reference-app-rn.md → "Adding a Device or App".

## What was built

- **`src/add-device-section.tsx` → `AddDeviceSection({ showAlert, linkedRequest?, onLinkedRequestTaken? })`**, rendered by Settings while connected, directly after "Join a Cadre" (so "Add an always-on node", which the `issuer-only` warning points to, is below it).
  - Standing: `isOwnerDevice()` on mount, whenever `cadre.node` changes (a join replaces the node), and on Refresh. Member → one line only; a read failure → a line and "Try again".
  - Paste request: field, "Scan request", "Use request" → `decodeCadreJoinRequest` (refusal text shown as is) → own request refused (`request.peerId === cadre.peerId`) → owner re-check and `isMemberPeer` ("‹appName› is already in this cadre.") → approval Modal (app name with the "name is what the app calls itself" note, peer id via `shortPeerId` labelled "Code", Also an owner switch defaulting on each time) → mint `{ peerId, grantsOwner }`.
  - Copy invitation: Also an owner switch (default on), the bearer warning in the warning colour while it is on (its minutes come from cadre-core's `OWNER_INVITATION_DEFAULT_TTL_MS`), "Make invitation" → mint `{ grantsOwner }`.
  - Minted: `ShareCode` titled "Invitation for ‹appName›" / "Open invitation", "Valid until HH:MM" (weekday added when not today), reach line from a typed `Record<CadreInvitationReach, …>`, "Done".
  - Outstanding: `listCadreInvitations()` filtered to `live`, sorted by expiry descending; rows show target, owner/member, expiry, uses when total > 1; Withdraw → confirm Modal → `withdrawCadreInvitation` → refresh. A `false` result is logged, not alerted. Withdrawing the invitation currently on screen also clears it.
  - Double-tap guard: `mintingRef`, as `foundingRef` in Settings.
  - Mint failure alert: "Could not make an invitation"; when `relayStatus !== 'reserved'` the message is "This phone has no relay address, and no always-on machine of your cadre has one either." with the core error as the detail line, otherwise the core error is the message.
  - `linkedRequest` / `onLinkedRequestTaken`: optional, unused by Settings today; handled like a paste, dropped with a notice while a prompt is open or a mint runs (same rule as `AddNodeSection.linkedCode`). For `same-phone-apps-exchange-join-by-deep-link`.
- **`src/share-code.tsx` → `ShareCode({ title, text, testIDPrefix })`**: QR as one `react-native-svg` `<Path>` (runs of dark modules per row) from `qrcode/lib/core/qrcode`'s `create(text, { errorCorrectionLevel: 'L' })`, 4-module white quiet zone, drawn at min(window width − 32, 320); "Too long for a QR code; use Copy instead." when `create` throws; Copy via `expo-clipboard` showing "Copied" (or "Could not copy; select the text below instead") for 2 s; text selectable in a nested scroll box (max height 120).
- **`src/qrcode-core.d.ts`**: ambient module re-exporting `create`'s types from `@types/qrcode` for the subpath import.
- **`src/code-scanner.tsx` → `CodeScanner({ visible, accepts, hint, otherCodeHint, onScanned, onClose })`** (renamed from `node-code-scanner.tsx`; latch unchanged). Added `hint` beside the ticket's `otherCodeHint`, since the normal line also differs per caller. `AddNodeSection` passes its previous two lines verbatim. The camera-denied notice no longer names "Add an always-on node"; it now says "paste the code's text into the field instead".
- **`settings-controls.tsx`**: `Fact` and `shortPeerId` moved here from `add-node-section.tsx` (both sections use them), with their styles.
- **`cadre-phone.ts`**: `createCadreInvitation`, `listCadreInvitations`, `withdrawCadreInvitation` pass-throughs over `running()`.
- **`use-cadre.ts`**: the same three plus `isMemberPeer(peerId)` (reads `queryCadrePeers()`; false without a node); the three throw "Node not started" without a node.
- **`@serfab/cadre-core` index**: now exports `parseNullableStoredDatetimeMs` (it already existed in `control-database.ts`), to read the invite row's zone-less UTC `expiresAt`. cadre-core `dist` was rebuilt. The web owner ticket was told about it.
- **Dependencies** (`yarn expo install` for the native two): `expo-clipboard ~7.1.5`, `react-native-svg 15.11.2`, `qrcode ^1.5.4`, `@types/qrcode ^1.5.5` (dev). Docs: Package Structure, Key Dependencies, When Native Rebuild Is Needed.
- **Other tickets touched**: `reference-app-rn-joins-existing-cadre` now says to show the joining app's `shortPeerId` labelled "Code" under its request (the approval prompt asks the user to compare it), and names `CodeScanner`'s actual props. `rn-node-claim-by-qr-device-run`'s `files:` points at the renamed scanner.

## Deviations from the ticket

- **While an invitation is shown, it replaces the two inputs** (paste and open) until Done, instead of sitting between them and the list. Reason: the open flow's button is lower in the section than the paste flow's, so a result placed at either spot would land off-screen for one of them; in place of the inputs it appears where the user was looking. Consequence: "mints another" without Done is only possible through `linkedRequest`. Revert if the reviewer prefers the ticket's literal layout.
- The minted invitation's `expiresAt` comes from the returned row (parsed with the new export), not from a client-side "now + default".

## Things a reviewer might question

- `handleRequest` re-checks `isOwnerDevice()` even though the paste UI is shown only to owners; it exists for `linkedRequest`, which can arrive while the section shows the member line.
- The mint-failure relay line is chosen on `relayStatus` alone, not on which error core threw, so an owner-key error on a phone with no relay would also get the relay line. Owner-key errors should not reach this path (the section shows the member line then).
- The outstanding list includes invitations other owners minted (it reads the replicated `CadreInvite` rows), and Withdraw works on them; that matches core, but the section does not say who minted each.
- Expiry-descending is only an approximation of newest-first when targeted (24 h) and open-owner (15 min) invitations are mixed.
