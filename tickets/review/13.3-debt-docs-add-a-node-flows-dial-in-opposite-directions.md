## Deviations from the plan, with reasons

- The table has a leading `#` column. The when-to-use and relay paragraphs refer to rows by number, which a reader cannot follow without one.
- "A phone is never the dial target" was softened to "not dialed unless it holds a relay reservation", and "a seed minted by a phone carries none" gained the same qualifier: the React Native reference app can hold a reservation (relay table in the same doc), and then its `/p2p-circuit` address is dialable and rides the seed.
- The relay paragraph names row 7 as well as rows 2 and 6: the cadre-host owner node cannot hold a reservation either (same relay table; cadre-host.md → NAT and DDNS). For row 6 the wording is specifically "none lets a phone dial a container" — the requester side of row 6 can still be reached through a relay if it is, say, a `cadre-cli` node with one.

## Facts checked against code or the linked page

- `CadreNode.addDrone` → `retainDialTarget` (`packages/cadre-core/src/cadre-node.ts` ~7779, ~3635): empty address list and self are not retained.
- `SeedBootstrapService.dialSeedOwners` (`packages/cadre-core/src/seed-bootstrap.ts` ~853): owners with no addresses are skipped, so a phone-minted seed yields `ownerDialsAttempted: 0`, not a failure count — hence the "(or none attempted …)" clause.
- Row 6: `feat-provider-drone-reachable-by-phone` states the TCP-only listen address and the required non-empty `bootstrapNodes`; cadre-host.md's provision-validation paragraph says the same.
- Row 7: cadre-host.md → Trust circle → Lifecycle (invite carries host's dialable addresses; recipient dials in via `dialInvite`/`acceptPhone`).
