# Gate: declared dependency ranges must cover the linked workspace versions

Implemented and re-verified clean. No outstanding design questions.

## What it does

`scripts/check-dep-ranges.mjs`: for every root `package.json` `resolutions` entry pointing at a
`link:` sibling workspace (e.g. `@optimystic/db-core` → `link:../optimystic/packages/db-core`),
reads that sibling's real version, then checks every `packages/*/package.json`
`dependencies`/`peerDependencies`/`optionalDependencies` entry naming it against `semver.satisfies`.
Generic over whatever's in `resolutions` — covers `@optimystic/*` and `@quereus/quereus` today,
any future linked package for free.

- Reports *direction* of drift (declared range too old and excludes the linked version — the
  dangerous direction, ships an untested substrate to consumers — vs. declared range ahead of
  local dev) via `semver.gtr`/`ltr`, plus a suggested `^<linked version>` edit. Fails, doesn't
  auto-fix.
- Missing sibling checkout (e.g. bare CI clone with no `../optimystic`) → skipped with a logged
  line, not a failure.
- `DEP_RANGE_CHECK_ROOT` env var redirects the whole check at a fixture root, for tests.

## Wiring

- `yarn dep-check` = `knip && yarn check:dep-ranges` (existing gate, now also catches this drift).
- `yarn check:dep-ranges` — standalone.
- `yarn test` now chains `yarn test:dep-ranges` (`node --test scripts/check-dep-ranges.test.mjs`).
- `semver ^7.7.3` added as explicit root devDependency.
- `docs/STATUS.md` "Declared dependency range vs linked workspace" section documents the gate.

## Testing / validation for reviewer

- `yarn check:dep-ranges` — currently exits 0, "all declared ranges admit their linked workspace
  version (9 linked package(s))".
- `yarn test:dep-ranges` — 5/5 pass: 0.x-caret-excludes-newer-version (the real recurring bug
  shape), 1.0+-caret-admits-newer-minor (proves no false positive across the semver 1.0 boundary),
  inverse "declared newer than linked", absent-sibling-workspace skip, clean pass. Each runs
  against a disposable tmpdir fixture workspace via `DEP_RANGE_CHECK_ROOT`, not this repo's real
  packages.
- `yarn dep-check` — exits 0 (knip's existing unused-file/export warnings are pre-existing
  warn-tier noise per `docs/STATUS.md`, unaffected by this change, not gating).
- Manual regression check (done during implement, worth spot-re-checking if suspicious): temporarily
  lower a package's declared `@optimystic/db-core` range below the linked workspace version →
  gate fails with "too old" + correct suggested edit; revert → passes again.
- `scripts/**` is already lint-ignored (`eslint.config.mjs`) and already a knip entry point
  (`knip.ts`), so `yarn lint` needed no changes.

## Known gaps / things worth a skeptical look

- No test exercises multiple simultaneous drifted packages in one run (only ever one failing dep
  per fixture) — the accumulation/reporting loop (`failures.push` → multi-entry stderr block) is
  exercised by code reading, not a test case.
- Fixture sibling dirs are tagged with `randomUUID()` and placed one level outside `fixture.root`
  (mirroring this repo's real `../optimystic` layout) — cleanup runs in a `finally`-less `run()`
  after `spawnSync` returns; if the child process itself throws before returning, cleanup paths
  wouldn't run. Low risk (script has no code path that throws pre-return) but worth a glance.
- No test covers a `resolutions` target that *isn't* a `link:` (e.g. a normal semver resolution) —
  the `!target.startsWith('link:')` skip is straightforward but unexercised.
