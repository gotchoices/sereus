# Review: donor-aware cadre-host local UI

cadre-host runs in one of two roles (`docs/cadre-host.md` → "Two roles: donor and founder"): **donor** (default — only runs nodes for other people's cadres) or **founder** (`ownCadre.enabled` — also runs the host's own cadre, trust circle, NAT and strands). The server already left the founder routes unmounted in donor mode; the Svelte dashboard didn't know, so a default install showed three broken pages, two error toasts on every load, a Connectivity tile stuck on "Loading…", a status dot stuck at `…`, and Start/Stop buttons on donated nodes that the server answers with 501.

## What changed

**Server — one source for the role.**
- `LocalUiServerOptions` replaces the separate optional `trustCircle` / `nat` / `strands` with one optional `founder: FounderServices` (all three or none). `createLocalUiServer` mounts `/auth/*`, `/nat/*`, `/api/strands`, the settings route's `nat` hook and the boot `connectivity-changed` publish from `founder`, and passes `role: founder ? 'founder' : 'donor'` to the status route. `FounderServices` and `HostRole` are exported from the package root.
- `GET /api/status` gains required `role: 'founder' | 'donor'` and `owner: true` on the owner node's summary (so the SPA's projection of the status summary into its node list never mistakes the owner node for a donated one).
- `bin/host.ts` builds `founder` at the end of its `hostOwnsCadre(cfg)` branch; shutdown calls `founder?.nat.stop()`. The role is the running process's, not the config file's.

**SPA.**
- `deriveOverallStatus` moved to plain module `ui/src/lib/overall-status.ts` and takes the role: `null` → `loading`; founder → the old rules; donor → connectivity ignored, any stopped node or update error → `warn`, else `ok`. `state.role` is `null` until the first successful status fetch.
- `router.ts`: `FOUNDER_ROUTES` / `isFounderRoute` (trust-circle, connectivity, strands).
- `App.svelte`: founder nav items shown only when role is `founder` (hidden while unknown); founder-only routes, when the role isn't founder, don't mount the page component — "Loading…" card while unknown, and a "turned off on this machine" card with a Home link for donors.
- `Home.svelte`: founder keeps the Connectivity + Trust circle tiles; donor gets a Donation tile (donated nodes running / total, excluding the owner node, plus the `cadre-host grant issue <label>` hint); unknown role shows neither.
- `NodeDetail.svelte`: owner node + founder → Start/Restart/Stop as before; owner node + donor → muted "Your own cadre is turned off…" line, no buttons; donated node → **Terminate** behind `ConfirmDialog`, calling `DELETE /grants-admin/donations/:id`, then success toast, `refreshNodes()`, navigate to `#/nodes`. Failure → error toast in the `postAction` format, page stays.
- Docs: API table `/api/status` row, a donor-consequences bullet in "Two roles", and the SPA status bullet.

**Call-site migration.** Server tests use a new shared `src/server/__tests__/fakes.ts` (`fakeFounder(overrides)` + `SAMPLE_CONNECTIVITY`, replacing three copies of the snapshot). The integration-tests harness and bootstrap scenario (`createLocalUiServer` callers outside the package) now pass `founder`, with a new exported `emptyStrandNode()` fake for the required `StrandService`.

## Where I deviated from the plan, and why

- **Founder boot fetches run from an `$effect` on `app.role`, not a `.then` chain on the boot `refreshStatus()`.** With the chain, if the boot status fetch fails and a later one (Home's on-mount call) succeeds, a founder dashboard would never fetch the trust circle or connectivity — the Connectivity tile stays "Loading…" and the status dot stays `loading`. The effect fires once whenever the role becomes `founder`, whichever fetch resolves it; the calls are wrapped in `untrack` so only `app.role` is a dependency. Svelte skips same-value assignments, so repeated status refreshes don't re-fire it.
- **Terminate stops the poll *before* the DELETE, not after success** (restarted on failure). A poll tick landing between the server's teardown and the response would otherwise toast "node … not found". Behaviour on failure is still "page and poll as they were".
- **Owner node with role still `null` shows neither buttons nor the muted line** (the plan said "role not founder → muted line"). Otherwise a founder host briefly tells the user their own cadre is off while the status fetch is in flight.
- `OverallStatus` stays defined in `state.svelte.ts` (App and StatusDot import it from there); `overall-status.ts` imports it type-only, so the test never loads the runes module.
