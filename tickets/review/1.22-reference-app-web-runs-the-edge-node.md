# The web reference app runs the edge node — implemented

The tab now builds one `@serfab/cadre-core/edge-node` edge node over IndexedDB (`web-edge-platform.ts`, called once at module load of `cadre-web.ts`) and deletes its hand-copied lifecycle: `web-strand-move.ts`, `web-dissolve.ts` and `party-start.ts` are gone, `web-join.ts` keeps only the join request and the invitation decode, and `cadre-web.ts` keeps only the tab's own surface (diagnostics getters, chat strand, formation, cadre invitations, RBAC probe, e2e hooks, debug hook, owner-key pass-throughs). This absorbs `debt-web-app-repeats-the-phone-kit-join-sequence`.

## What changed, by module

- **`web-edge-platform.ts` (new).** `createWebEdgeNode()`: key store and node-local store from `node-local-slots.ts` over one opener of the node-local database; `storage.id = 'sereus-web'`; `rawStorage(scope) = lazyRawStorage(() => openStore(scope), durability)` where durability is `'power-loss'` when the browser honours strict transactions (what `IndexedDBRawStorage` reports), else `'process-crash'`; `destroyScope = deleteStore`; `close = closeStores`; transports WebSockets, circuit relay, WebRTC (STUN from `resolveStunServers`), WebRTC-direct; `listenAddrs` is `['/webrtc']` with relays named, else `[]`; `allowPrivateDial: true`; no `trustedOwnerSlot`, no `dataVersion`, no `configure`. Relays now go through the edge config (`network.relayAddrs`, `requireRelay: false`), so each strand node gets its own supervised reservation; the `reserveRelays` call and its NOTE are gone.
- **`node-local-slots.ts` (rewritten).** `nodeLocalKeyStore(open)`: a full `KeyStore`; slot map `cadre/identity` → `peer-private-key`, `cadre/owner` → `owner-private-key`, anything else → `keystore.<keyId>`; `list()` maps every `kv` key back and drops the node-local records; text under a slot's key throws `KeyStoreAccessError`; writes are one strict-where-supported transaction. `nodeLocalKv(open)`: `get` reads a non-string as absent, `set`/`delete` are one put/delete each, `flush` is a no-op. `kvSlot`, `partyKvKey`, `PARTY_KV_KEYS` and `ownerKeyStore` are gone.
- **`strand-storage.ts` (rewritten).** `openHandle(key)` and `openStore(key)` open on first use, cached per key, with concurrent first uses sharing one open; `closeStores()` waits for opens in flight, calls each raw storage's `close()` (applies held writes), then closes handles; `deleteStore` closes the scope's storage and handle first and stays synchronous up to the delete request when nothing is open (the existing `deleteStore` test depends on that). `openStores` and `storageProvider` are gone, and so is the "no pre-opened handle" throw.
- **`cadre-web.ts` (rewritten).** Exports `edgeNode`. `OwnerStanding = OwnerGenesisResult | 'pending'` replaces `OwnerState`; `getOwnerState()` returns `status.owner` or `pending`; `ownerKeyWired()` is `enrolled`. `getPartyId()` is `edgeNode.options?.partyId`; `getControlDbHandle()` / `getControlStorage()` read the cached scope once the node has opened it (null before). A status listener installs `__cadre` and tracks `identity-first-seen` (through `nodeLocalRecords()`) on `running`, and clears the hook, the chat strand id, the first-seen time and the formed strands on `stopped`. `__cadre.getPartyStart` returns `edgeNode.options`; `__cadre.getOwnerState` returns the standing. Owner-key calls are pass-throughs to the edge node. `addChatStrand`, `createClosedChatStrand` and `joinViaInvitation` no longer pre-open storage. The `formedStrands` accepted-tradeoff NOTE is rewritten as the ticket says.
- **`store.svelte.ts` (rewritten).** Subscribes once at module load through `edgeNode.on` (every event the old `subscribe` registered, plus a real `control:connected` and a log-only `cadre:removed`) and `edgeNode.onStatus`. `followStatus` maps `starting`/`joining`/`stopped`/`removed`/`failed` to the store's status (the `removing` status is gone) and attaches the page layer once per node on `running`; a `running` for the attached node only updates `owner` (an import or a retried move wiring the key). Actions: `start()` loads the saved start with fresh relays (ignoring `autoStart`), founds a fresh party when none is saved (`ownerKeyLabel: 'browser'`), and refuses a present-but-unusable record; `stop`, `restart` (`edgeNode.restart` with fresh relays, or `start()` when nothing runs), `joinCadre` (`decodeInvitationForThisTab` then `edgeNode.joinCadre`), `retryStrandMove` (`finishStrandMove`, returns the report, throws), `importOwnerKey`, `dissolveFormerParty` (`edgeNode.dissolveFormerParty({ discard })`). `midTransition` shows a `stopped` inside a join, dissolve or restart as `starting`, and **every action waits for the store's attach to the node the edge node ends on before resolving** (`attachSettled`): without that, the join card's follow-up dissolve ran while the chat strand was still being added and was refused as "not running" (this is how the distributed e2e failed on the first run). The removal handling (`onRemoved`, `actOnReportedRemoval`, `leaveRemovedParty`, `transitions`, `inTransition`) and its NOTEs are gone.
- **`join-cadre.svelte.ts`, `join-flow.ts`.** Types from `@serfab/cadre-core/edge-node` (`JoinCadreResult`, `StrandMoveOutcome`, `StrandMovePendingError` with `pending.strandIds`, `FormerPartyNotEmptyError`, `UnfinishedRemoval`, `EdgeJoinProgress`, `StrandsNeedOwnerJoinError`); `pendingStrandMove`, `unfinishedRemoval` and `options` read off `edgeNode`; a retried move's throw maps `StrandMoveNotOwnerError` to the `owner-key-not-wired` stall and anything else to `adoption-failed`; `describeJoinFailure` builds the owner-join sentence from `err.strandCount`; `strands(n)` moved into `join-flow.ts`.
- **`owner-keys.svelte.ts`, `diagnostics.svelte.ts`, Svelte.** List, plan and remove go through the pass-throughs; diagnostics drops `ownerError` and shows the standing; `Diagnostics.svelte` marks `failed`/`timed-out` bad; `AddDevice.svelte` keys its "could not make itself the owner" line on those; `Home.svelte` drops `removing`.

## Use cases for the reviewer

- **Boot and reload (solo).** Load → Home `running`, Owner `enrolled`, Activity log opens with a real `control:connected`. Reload keeps the peer id (identity under `peer-private-key`) and party id (saved start `start-options`).
- **Upgrade from a pre-edge-node tab.** A tab with `party-start` and no `start-options` founds a fresh party; identity and owner key carry over. By inspection only: no test covers an upgraded tab.
- **Unusable saved start.** Put text that is not a version-1 record under `kv` `start-options`: Home shows `error` with "The saved start … cannot be read", no party is founded. A `Uint8Array` under that key reads as absent and founds a party (the ticket's rule for non-string values).
- **Join, move, dissolve** (the distributed e2e): founded tab joins A as a member, B's control database is deleted, Home reads `member` after reload. Statuses during the join: `starting` → `joining` → `running`; during the dissolve `starting` throughout (the edge node's intermediate `stopped` is mapped while a store action runs).
- **Removal by an owner.** Not exercised by a test here (none existed before either). Expected: the edge node stops the node and deletes the party's storage; the store shows `stopped` briefly, then `removed` with the card; "Go back to your own cadre" runs `start()`, which reads the saved start the removal rewrote.
- **Import an owner key on a member tab.** `running` is reported again for the same node with `owner: enrolled`; the store updates `owner` without attaching (the chat strand is not added twice).
- **Restart node on Home.** `edgeNode.restart` with the current relays; the store attaches to the new node and `handleRestart`'s `ensureMessagesReady` runs with status `running`.

## Known gaps and judgment calls

- **Status flashes.** The edge node reports `stopped` on its way through a removal and, outside a store action, any other transition; the store shows it for the moment before `removed`. During store-run joins, dissolves and restarts it is shown as `starting` instead. The old `removing` status is gone.
- **Actions wait for the attach** (`attachSettled`). This restores the old contract that a store action returns with `status` at `running`; a reviewer may prefer gating the page's follow-ups on `edgeNode.status` instead. Gating on the edge node alone would let the dissolve stop the node while the chat strand is being added.
- **`failed` from the edge node** (a removal that could not be acted on, a rollback that could not restart) reaches the store as `error` through `failed('edge node', …)`; the actions then avoid a second report by checking `alreadyFailed()`.
- **Non-string `kv` values** under the saved-start key read as absent (the ticket's rule), where the old `readPartyStart` threw; a corrupt binary record now founds a fresh party.
- **README wrapping.** The README is hard-wrapped throughout; the edited sections keep that style rather than unwrapping the file.
- **Not proven:** inbound dials to the tab's strand nodes through the relay (the ticket leaves `formation-convergence.spec.ts` dialing by hand); two tabs of one origin; the `/webrtc` listen address with a relay configured (no relay in the e2e environment).
- The `strand:discovered` handler is still absent, so strands cadre-core now records in the key store are carried, not opened, after a reload (the rewritten NOTE on `formedStrands`).
