# Review: phone kit links between Sereus apps on one phone

First of three tickets replacing the twice-copy-and-paste join between two apps on one phone with one confirmation in the owner app. The two reference-app tickets (`reference-app-rn-answers-join-requests-by-link`, `reference-app-rn-asks-owner-app-by-link`) build on this. **B** is the app asking to join; **A** the owner app holding the cadre.

## What was built

**cadre-core** (`cadre-join-request.ts`): `CadreJoinRequest` gains optional `reply: { scheme, nonce }` (`CadreJoinReply`). It is encoded only when present (`canonicalJson` drops `undefined`), so a request without it encodes as before. New export `requireCadreJoinReply(reply)` refuses a scheme not matching `^[a-z][a-z0-9+.-]{0,63}$`, the named web and system schemes (`http`, `https`, …, `sms`), and a nonce not matching `^[A-Za-z0-9_-]{16,64}$`. The codec runs it in both directions. The cadre-core `dist` was rebuilt.

**cadre-rn `@serfab/cadre-rn/app-link`** (new subpath; no React Native or Expo import):
- `known-apps.ts`: `SereusApp`, `KNOWN_SEREUS_APPS` (`Sereus P2P Chat` / `sereus-chat`), and `installedSereusApps(apps, ownScheme, canOpenURL)`. It removes duplicate schemes and the app's own scheme. A rejected `canOpenURL` counts as not installed, with one warning per call naming the schemes.
- `join-response.ts`: `CADRE_JOIN_RESPONSE_PREFIX` (`sereus-join-response:1.`), `CadreJoinResponse`, `JoinRefusal`, and the encode/decode pair. The appName must be 1–64 characters once trimmed. `invitation` must start with `sereus-invite:1.`. A response carries exactly one of `invitation` and `refused`. A pasted join request is refused by name.
- `links.ts`: `parseCadreLink`, `joinRequestLink`, `joinResponseLink`, `CADRE_LINK_MAX_LENGTH` (32 768), and `CadreLinkTooLongError`. `joinResponseLink` runs `requireCadreJoinReply` again on `{ reply.scheme, response.nonce }` before it builds the link.
- `link-request-store.ts`: `LinkRequestStore` (`begin`/`current`/`cancel`/`take`), `OpenLinkRequest`, `UnsolicitedJoinResponseError`, `LINK_REQUEST_TTL_MS` (30 minutes). The nonce is 16 bytes from `globalThis.crypto.getRandomValues`, in base64url. `''` in the slot means no request is open. A malformed record reads as none and is logged. Calls run one at a time per instance.

**`PhoneNode.linkRequestSlot()`** plus `PhoneNodeNames.linkRequestKey` (default `'link-join-request'`). The slot looks the node-local database up again on each load and save, because a stop closes the handle. It waits for a stop in progress first, as `loadSavedStart` does.

**Config plugin** `appLinks` option (`true`, or `{ extraApps: [{ name, scheme }] }`):
- **Android:** the main activity gets a `VIEW`/`DEFAULT`/`BROWSABLE` intent filter for `sereus-join-request`, and the manifest gets a matching `<queries>` intent. Each is added only once.
- **iOS:** `LSApplicationQueriesSchemes` is merged with the known and extra schemes, and the prebuild fails past 50.
- **Option checks:** unknown keys and a malformed extra app fail the prebuild.
- **Known-apps copy:** the plugin's copy of the list is exported as `withCadre.KNOWN_SEREUS_APPS`.

**Docs:**
- **Kit README:** a new "App links" section (API, the open request, adding an app to the known list, what to install), the `appLinks` option under the config plugin, and table rows.
- **`docs/architecture.md`:** the request interface block now shows `reply`, and the new subsection "Between apps on one phone" covers the flow, the link formats, the response shape, the decisions, link length and security, including the accepted impostor-owner-app tradeoff with its revisit condition.

## Judgment calls and known gaps (reviewer: check these)

- **API additions beyond the ticket's listing:** `requireCadreJoinReply` and `CadreJoinReply` exported from cadre-core, and `CadreLinkTooLongError` (the ticket asked for "a named error"). There are two extra source files, `join-response.ts` and `links.ts`, so `index.ts` only re-exports, as `phone-node/index.ts` does.
- **`begin` returns the open request unchanged**, as the ticket specifies, including `ownerAppName` and `startedAtMs`. A second tap toward a different iOS owner app keeps the first app's name for B's "waiting for …" line, and does not extend the 30-minute window.
- **"Once" holds per store instance.** The calls are serialized within one `LinkRequestStore`, and the README says to create one per app. Two instances over the same slot could both take one answer if two deliveries race.
- **Response nonce form.** The response codec checks only that the nonce is a non-empty string. The form check happens in `joinResponseLink` (A's side), and B's real check is equality with its stored nonce.
- **`parseCadreLink` does no percent-decoding.** It assumes the URL reaches the app as it was opened, which is how React Native `Linking` passes it on both platforms. If a platform percent-encodes the `:` in the path, the codec would refuse the text. The device run (filed by `reference-app-rn-asks-owner-app-by-link`) will show it.
- **Is the Android `<queries>` entry needed?** Not verified on a device. `startActivity` is not filtered by package visibility; React Native's `openURL` uses `resolveActivity` only to choose a task flag. It was added because the ticket specifies it, and the README and plugin comment state only what Android's `resolveActivity` does.
- **The Android chooser lists B itself** when B also answers requests. The architecture doc says B must recognize its own request (its own peer id). Handling it is `reference-app-rn-asks-owner-app-by-link`'s job (`linkRequestCameBack`).
- **Tripwire, parked as a `NOTE:` in `PhoneNodeRuntime.linkRequestSlot`:** a restart, join or dissolve also closes the node-local handle, and there is no `stopping` promise to wait on. A slot load in that short window could fail on rn-leveldb's lock. `readSavedStart` callers outside a transition carry the same exposure.
- **The scheme pattern exists twice:** in cadre-core and in `app.plugin.cjs` (`APP_SCHEME`, for extra-app validation), because the CommonJS plugin cannot load the ESM build. No test keeps the two equal; only the known-apps list has a drift test.
- **The response link size of about 4 KB is an estimate from the invitation's shape**, as in the ticket. It was not measured.
- **Not touched:** the reference app's `app.json` (it still lists the plugin without `appLinks`; `reference-app-rn-answers-join-requests-by-link` changes it), and `docs/reference-app-rn.md`.

## Usage, for the reference-app tickets

- **B:** `new LinkRequestStore(phone.linkRequestSlot())`, then `begin`, then `encodeCadreJoinRequest({ …, reply: { scheme: ownScheme, nonce } })`, then `Linking.openURL(joinRequestLink(text, ownerApp | null))`. When the answer arrives: `parseCadreLink(url)`, then `store.take(link.text)`, then `phone.joinCadre(decodeCadreInvitation(response.invitation))`.
- **A:** `parseCadreLink(url)`, then `decodeCadreJoinRequest(link.text)`, then the user confirms, then `Linking.openURL(joinResponseLink(request.reply, { v: 1, nonce: request.reply.nonce, appName, invitation | refused }))`. Fall back to on-screen copy when it throws `CadreLinkTooLongError`.
- **iOS list:** pass `(url) => Linking.canOpenURL(url)`, not `Linking.canOpenURL` unbound: React Native's implementation uses `this`.
