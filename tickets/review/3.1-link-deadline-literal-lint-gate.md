# Lint gate: deadline constants in cadre-core are derived or say why not

## What landed

`no-restricted-syntax` in `packages/cadre-core/src/**/*.{ts,tsx,mts,cts}` now flags a value whose name ends in `timeout`/`budget`/`deadline` + `ms` (case-insensitive regex `/(timeout|budget|deadline)_?ms$/i`, so `FOO_TIMEOUT_MS`, `timeoutMs`, `dialBudgetMs`) and whose value is a numeric literal or arithmetic over numeric literals only. Five positions are covered: a `const`/`let` initialiser, a parameter or destructuring default, a class field, an object-literal property, and the right side of `??` when the left side is such a name (`opts.timeoutMs ?? 5000`). Anything that names an identifier (`relayedDialBudgetMs()`, `ATTEMPTS * PER_ATTEMPT_MS`) passes.

A constant that stays a number carries one of two directive reasons on the line above it:

- `// eslint-disable-next-line no-restricted-syntax -- link-independent: <why>`
- `// eslint-disable-next-line no-restricted-syntax -- link-bound, not yet derived: <ticket slug>`

## Deviations from the implement ticket (review these)

- **Wider selectors than the ticket's candidates.** The ticket proposed four selectors (upper-case consts, `…TimeoutMs` parameter defaults and class fields). I made the name match case-insensitive and added object properties and `??` fallbacks. Reason: the `?? DEFAULT_X` fallback is exactly how these constants are consumed, so inlining the number there (`?? 10_000`) was the easiest way around the rule. Zero sites in the tree match the added forms today, so they cost nothing now. If a reviewer finds the object-property form too broad (for example `{ timeoutMs: 0 }` meaning "none"), drop that one selector.
- **`DEFAULT_READ_TIMEOUT_MS` in strand-peer-book-protocol.ts was converted, not classified.** The ticket's table listed it as link-independent. But `StrandPeerBookService`'s only constructor is `StrandPeerBookSwap` (`strand-peer-book-swap.ts` ~140), which always passes `readTimeoutMs: this.timeoutMs`, the same `circuitRequestBudgetMs(...)` value it passes to the exchange. That is the same situation the ticket used to justify deleting `DEFAULT_EXCHANGE_TIMEOUT_MS`, so both fallbacks are gone and `readTimeoutMs` is required. `StrandPeerBookService` and `exchangeStrandPeerBook` are public exports of `@serfab/cadre-core`; nothing outside cadre-core constructs or calls them (grepped `packages/*/src` and `packages/*/test`).
- **Classification wording.** The addr and wake read caps (`DEFAULT_ADDR_READ_TIMEOUT_MS`, `DEFAULT_WAKE_READ_TIMEOUT_MS`) are link-independent: nothing overrides them, and their doc comments say they bound a peer that opens a stream and never half-closes. `DEFAULT_SEED_READ_TIMEOUT_MS` has the same shape but stays link-bound under `debt-cadre-deadlines-sized-against-old-optimystic-bounds`, because that ticket lists it (a seed frame can be up to 1 MiB, so transfer time matters there).

## Tests

None added. The lint run is the check. The probe and the exemption check above were done by hand and not committed.

## Known gaps

- Not caught by design (stated in the config comment and testing.md): other names (`FOO_WAIT_MS`, `DEFAULT_CONTROL_COHORT_RECONCILE_MS`, which `debt-cadre-deadlines-sized-against-old-optimystic-bounds` lists), inline `setTimeout(…, 5000)` / `withDeadline(5000, …)`, and a literal behind `as`.
- A directive left behind after its site is converted is only an ESLint warning, which this gate does not fail on. The config comment says converting a site means deleting its directive. Setting `linterOptions.reportUnusedDisableDirectives: 'error'` would enforce that repo-wide; I did not do it because it changes behaviour for every other directive in the repo.
- Scope is cadre-core src only. `COHORT_READ_DEADLINE_MS` in quereus-plugin-sereus stays with its owning ticket.
