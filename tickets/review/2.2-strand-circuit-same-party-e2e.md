## What landed

No product code changed — the scenario surfaced **zero product gaps**. The relay
machinery believed complete (per-relay configured circuit listeners for strand
nodes, the search-route + explicit-drive reservation for control nodes, the
strand-addr RPC with delegate announce) worked end to end on the first run. What
landed is proof, a fixture, one measured defect filed to backlog, and docs.

**`packages/integration-tests/src/harness/dedicated-relay.ts`** — an ungated
bare-libp2p circuit-relay fixture mirroring the `ops/docker/libp2p-infra`
container (`SEREUS_ROLE=relay`): `circuitRelayServer` with
`applyDefaultLimit: false` (load-bearing — db-p2p's database protocols do not
run on "limited" connections, so a default-limit relay kills every strand data
stream) and a generous `maxReservations`, stock `identify`, loopback WebSocket
listener. Exposes `dialAddr` (with `/p2p/<peerId>`), `reservationCount()`, and
`restart()` — same key, same port, all reservations dropped (the relay-restart
fault). The module doc names the config-parity contract with the ops container
and the deliberate divergences (no TCP listener, no `ping()`, in-memory key).
`@libp2p/identify` was added to `integration-tests`' dependencies, pinned to
`4.0.10` to match cadre-core's pin (avoids a second hoisted copy of
`@libp2p/interface`).

**`packages/integration-tests/src/scenarios/strand-circuit-same-party-e2e.integration.ts`**
— one phased test, one party, two `CadreNode`s **both** with `listenAddrs: []`
and `relayAddrs: [<dedicated relay>]` (a shape no prior test covered even for
the control network — every prior relay-only node had a directly-dialable
sibling). Asserts, in order:

- both control nodes come up relay-only (every advertised addr is
  `/p2p-circuit`; `getRelayReservationState()` is `reserved`; relay holds 2
  reservations);
- the control mesh forms through the relay, and the A↔B control connection is
  classified `relayed`/`circuit-relay` by `summarizeConnectionPaths` on both
  sides (per-peer assertion — each node also holds a legitimate DIRECT ws
  connection to the relay itself);
- A founds a strand; its strand node's configured-route reservation lands
  (`getMultiaddrs()` has `/p2p-circuit`, strand peerId ≠ control peerId);
- the strand-addr RPC (asked over the relayed control connection) answers with
  A's live strand addrs, `/p2p-circuit` entry FIRST (signaling-first), none of
  them a control addr;
- B launches the same strand from the RPC-resolved seed alone — no hand-dial —
  and the A↔B strand connection is classified `relayed` on both ends;
- relay reservation count is **4** (2 control + 2 strand) — the first
  measurement of the per-strand relay-slot cost: one slot per node per network;
- an `App.Data` row written on A is read on B and vice versa, across the
  circuit (scan-reads, per the known point-lookup-on-networked-strand gap);
- **restart phase**: `relay.restart()` → both strand nodes observe the loss
  (circuit addrs withdrawn), both CONTROL nodes re-reserve on their own
  (supervisor; gated on the restarted relay reaching 2 reservations), and the
  STRAND nodes never recover — pinned by an inverted 15 s gate
  (`expect(waitUntil(...)).rejects.toThrow(/Timeout/)`) and by the count
  staying at 2.

**`tickets/backlog/bug-strand-relay-reservation-not-resupervised.md`** — the
one defect the characterization measured: nothing re-drives a strand node's
lost configured-route reservation (libp2p clears the listener on
`relay:removed` and never calls `addRelay` again; cadre-core runs no per-strand
supervisor). `repro: verified` with the scenario's numbers. Not fixed inline —
a per-strand supervisor is architectural (the control-node drive assumes the
search listener's pending-reservation id, which a configured listener doesn't
have).

**Docs** — `docs/architecture.md` ("Relay Integration"): what the scenario now
proves, the 2-control+2-strand slot cost, the relay-down-at-launch behaviour
(fail-then-retry via `StrandWatcher` backoff), and the reservation-loss
asymmetry with the backlog pointer. `docs/strands.md` (SN–SN use case): the
transport half is proven within one party; cross-party SN–SN remains open
(queued as `formation-carries-strand-addrs` / `blind-relay-phone-to-phone-e2e`).

## Honest gaps / reviewer attention

- **One flake found and fixed during implementation.** The restart phase
  originally sampled addrs immediately after `relay.restart()`; on a fast run
  the close events had not yet dispatched, every "recovery" gate passed
  vacuously, and the inverted gate failed (run 2 of 5). Fixed by gating FIRST
  on the loss being observed (strand circuit addrs withdrawn — permanent, so
  race-free) and on the restarted relay's own reservation count. 3 consecutive
  green runs since. Reviewer: scrutinize the restart phase for any remaining
  ordering assumption.
- **The inverted gate pins today's broken behaviour deliberately** — it is the
  tripwire that flags the backlog ticket obsolete if a libp2p upgrade or a
  strand-side supervisor makes reservations recover. If that trade (a test that
  fails on IMPROVEMENT) is unwanted, the alternative is deleting the gate and
  leaving the backlog ticket as the only record.
- **The full integration suite was not run** (exceeds the agent wall-clock
  budget; it also carries tracked intermittent families — see
  `tickets/.pre-existing-known.md`). Everything this ticket touched is additive
  (new harness file + export, new scenario, one new devtree dependency), and
  the targeted runs above cover the shared surfaces. No `.pre-existing-error.md`
  was written — nothing failed.
- **B launches the strand via explicit `addStrand`**, the same recipe as
  `strand-addr-seed-convergence` — the watcher-driven discovery path is not
  exercised here (it is exercised elsewhere on loopback).
- **Relay-down-at-launch is documented, not tested**: characterized from code
  (configured listener dials inside `libp2p.start()` → launch throws → watcher
  retries under backoff) and recorded in `docs/architecture.md`; standing up a
  second full topology to prove it was judged outside this ticket's budget.
- **`@libp2p/ping` is deliberately absent** from the fixture (not a workspace
  dependency; not on the reservation/hop path). If ops-container parity is ever
  tightened to include it, add the dependency then.
