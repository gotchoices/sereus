# Hosted nodes: join a cadre by QR, grants removed — implementation handoff

Third of the `cadre-host-join-a-cadre` chain. The web page is `cadre-host-join-ui` (next), the paste-an-invitation way in is `cadre-host-join-by-invitation`, the doc rewrite is `cadre-host-join-docs`. This ticket built the server, service, CLI and the proving scenario, removed the grant layer end to end, and made the minimal doc edits that keep docs/cadre-host.md and the README true.

## What landed

**cadre-core.** `node-claim-payload.ts`, exported from the package root: `encodeNodeClaimPayload({ peerId, multiaddrs, secret })` → `sereus-join:1.<base64url of canonical JSON>` and `decodeNodeClaimPayload(text)`. The decoder refuses any version but 1, a body that is not base64url JSON of the right shape, a peer id that does not parse, an **empty address list** (one rule past the ticket's list: a payload with no address names nothing a phone can dial), an address that does not parse or whose destination peer (the last `/p2p/`, past any relay hop) is not that peer id, and a secret `parseClaimSecret` refuses. The encoder applies the same rules, so a host cannot show a payload the phone refuses. Loads on React Native: only `@multiformats/multiaddr`, `@libp2p/peer-id` and `uint8arrays`.

**Orchestrator.** `createContainer(request: HostedSpawnRequest)` where `HostedSpawnRequest = OrchestratorCreateRequest & { claimSecret?: string }` (`orchestrator/types.ts`, exported from the package root). The secret reaches the child as `CADRE_CLAIM_SECRET` through `extraEnv` only. The `pinnedOwnerKeys` → `CADRE_OWNER_KEYS` wiring and the foreign-party push gating are deleted: every `storage`-profile node gets the push block when credentials are configured.

**`src/hosted/`** (the renamed `src/donation/`, git history follows the renames):

- `types.ts`: `HostedNode` exactly as the ticket's interface (`join: { kind: 'claim'; secret }`, `partyId` placeholder `unclaimed` until the claim, `profile: 'storage'`, statuses `spawning | unclaimed | joined | error`, `dockerId?`, `statusEndpoint?`, `peerId?`, `ownerKey?`, `connected?`, `respawn?`, timestamps, `error?`). `HostedNodeView` strips `join.secret`. `HostedNodeError` codes `not_found | invalid_state | invalid_request | node_unavailable | orchestrator_error | storage_error`. `HostedNodeChange = { kind: 'added' | 'claimed' | 'removed' | 'changed'; id }` with a listener type.
- `hosted-node-store.ts`: `HostedNodeStore`, `<dataDir>/hosted-nodes.json`, synchronous as before.
- `node-status.ts`: `readNodeStatus(statusEndpoint)` typed against cadre-cli's `HealthStatus` (a renamed field is a compile error here), `statusUrlFor(healthEndpoint)`, `reportsClaim(status)` and `PLACEHOLDER_PARTY`.
- `hosted-node-service.ts`: `join()` (one serialization tail), `claimDetails(id)` → `{ payload, peerId, multiaddrs, reachability }`, `remove(id)`, `reset(id)`, `respawn(id, opts)`, `reapStuckSpawning(ttl)`, `list()`, `get(id)`, `onChange(listener)`, `emit(change)` (public for the supervisor's give-up), `startWatching()` / `stopWatching()` / `pollStatuses()`. Options: `{ orchestrator, store, addresses, now? }` where `addresses` is `HostedNodeAddressSource = { publicAddressesFor, getStatus }`, which `NatService` satisfies.
- `hosted-node-watcher.ts`: `HostedNodeWatcher`, one 2-second timer (`HOSTED_NODE_CLAIM_POLL_MS`) that polls every unclaimed node each tick and each joined node every 15 seconds (`HOSTED_NODE_CONNECTED_POLL_MS`) or at once when poked; the orchestrator's state change and every spawn/respawn poke the node, and a poke stands until a poll succeeds. Polls are serialized on one promise tail and re-read the record after the round-trip.
- `hosted-node-supervisor.ts`: `HostedNodeSupervisor`, supervised statuses `unclaimed` and `joined`, backoff, give-up and `restart` unchanged; give-up publishes `changed`. `SupervisedOrchestrator` gained `listNodes()`.

**Routes** `routes/hosted-nodes.ts`, mounted by `createLocalUiServer` when `hostedNodes` is passed. They use the `/api/*` envelope (`{ ok, data }`) like `/api/nodes`, so `POST` answers `201 { ok, data: { node } }` rather than the ticket's bare `{ node }`; the CLI and the UI's `apiFetch` both unwrap it. The routes publish nothing themselves: `server/index.ts` wires the service's `onChange` to the bus as `hosted-nodes-changed` with `kind` and `nodeId`, so a change the watcher or the supervisor makes reaches the SPA the same way as one a route made. `grants-changed`, `GrantError` and `DonationError` are gone from the event types and the error handler.

**CLI.** `cadre-host join [--no-qr] [--no-wait]`, `cadre-host node list`, `cadre-host node remove <id>`, `cadre-host node reset <id> [--no-qr] [--no-wait]`; the `grant` group, `parseDuration` and `duration.ts` deleted; the payload printer, the reachability warning, the claimed line and the node list in `bin/join-output.ts`. ## Decisions a reviewer should check

- **A handle with no record** (the arm added by the `cadre-host-remove-founder-role` review): the supervisor's `start()` logs each orchestrator handle no record names (`console.error`, naming `cadre-host node remove <id>`) and leaves it running, and `HostedNodeService.remove(id)` falls back to stopping and reclaiming such a handle when no record exists. Chosen over reclaiming at startup because a lost `hosted-nodes.json` would otherwise delete a node that is serving its cadre. Not unit-tested (the log line is the only effect); the removal path is (`removes a handle no record names` in the service test).
- **`joined` is written only once `/status` reports the claimed party.** `claim` flips to `claimed` the moment the node records the claim, but the node then restarts in-process into the party, and until that finishes `partyId` is the placeholder (or empty). `reportsClaim` in `node-status.ts` requires both; the service test pins it.
- **`connected` is dropped on respawn** (not set to false) until the watcher reads the new child.
- **`updatedAt`** moves on a liveness change (the watcher writes `connected`); the stuck-`spawning` reap is the only consumer and reads it on `spawning` rows only.
- **Orphan-handle removal publishes `removed`** for an id that was never in the store; the UI's next ticket should tolerate a `removed` for an unknown id (a refresh is the natural response).
- **The secret in the scenario's log check** is the `cadre:host:*` debug namespaces captured in-process for the run, enabled so every log site executes. That is what "the host's own log output" means here; the CLI's stderr is covered by inspection only (`join-output.ts` prints the payload, the addresses, the peer id and the reachability reason).

## Known gaps

- **No UI "Join a cadre" button yet** (`cadre-host-join-ui`): the only way to join today is `cadre-host join`. The docs say so.
- **`cadre-host join` is covered by inspection only.** `cli.smoke.test.ts` spawns `--help`; nothing drives `join` against a running host. The route and service it calls are tested; the polling loop (`waitForClaimDetails`, `waitForClaim`) is not.
- **The LAN address in the payload is whatever the child reports for `0.0.0.0`.** A machine with no non-loopback interface gets `503 node_unavailable` from the claim details until it has one; the scenario would fail there on such a runner. Not seen.
- **`reference-app-rn/src/host-node-request.ts`** still describes the deleted `/grants` flow; `rn-app-joins-host-node-by-qr` (`tickets/plan/4-…`) replaces it, and `docs/reference-app-rn.md`'s "Borrowing a Node" section with it. The eslint rule keeping that module import-free stays, reworded.
- **docs/architecture.md outside the summary and the dial table** still says cadre-host implements the "donate-a-node contract" and links `cadre-host.md#node-donation` (about lines 787 and 1235), an anchor this ticket removed; the provider section's `/grants` sentences are stale the same way. All of that is `cadre-host-join-docs`, by the ticket. docs/testing.md's old bullet cited `tickets/blocked/always-on-nodes-host-strands-of-apps-they-do-not-run.md`, which no longer exists; the sentence was dropped rather than carry a dead reference.
- **The watcher's 2-second timer runs while nothing is unclaimed** (a cache read per tick, no I/O). Noted in the watcher's class comment rather than optimized.
- **Two `join` calls at once** are serialized on one tail rather than run in parallel; each still gets its own id, secret and ports (tested). The ticket allowed either.
- **The `respawn` → `abandonRespawn` on `error`** keeps the old code's skipped reclaim (and its `NOTE:` about leaked ports if a second `respawn` caller ever appears).
