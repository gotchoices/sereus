## What was built

gotchoices/sereus#18, maintainer decision item 1. The in-memory `crossPartyStrandAddrs` map in `CadreNode` is gone. In its place is a **strand peer book**: a node-local, never-replicated store, one per node, keyed by strand id then by strand transport peer id, holding `{ peerId, addrs, issuedAt, sig?, lastSeenAt }` per peer. It is read on every launch, hibernation resume and periodic address refresh, so a restarted machine dials the peers it was talking to before anything else.

- **Store** (`strand-peer-book.ts`): `StrandPeerBookStore { partyId; entries(strandId); merge(strandId, entry); forget(strandId, peerId?) }` with three backends mirroring `bootstrap-peer-store.ts`: `MemoryStrandPeerBookStore`, `PersistentStrandPeerBookStore.open(slot, partyId, options?)` over `node-local-snapshot.ts` (`drop-entry`, envelope `{ version, partyId, strands: { [strandId]: { [peerId]: entry } } }`), and Node-only `FileStrandPeerBookStore` behind the new subpath `@serfab/cadre-core/strand-peer-book-file` (file `strand-peers.<party>.json`). The merge rule lives in one exported pure function, `mergeStrandPeerEntry`: signed never yields to unsigned; two signed, greater `issuedAt` wins; two unsigned, greater `lastSeenAt` wins; ties go to the incoming entry; `lastSeenAt` is always the max of both. `sanitizeStrandPeerEntry` drops an unparsable peer id (logged, merge resolves without throwing) and keeps only addresses that attribute to the peer under `groupAddrsByPeerId`'s rule, signaling-first, capped at `MAX_STRAND_ADDRS`. Per strand: aged entries pruned (14 days from `max(issuedAt, lastSeenAt)`, `STRAND_PEER_MAX_AGE_MS`) at load, on every merge and on every `entries()` read; past `MAX_STRAND_PEERS` (16) the stalest is evicted. A persistent store's `entries()` filters aged entries on read; they are physically dropped from the slot on the next merge.
- **Writers.** `CadreNode.recordFormationStrandPeers` (replaces `recordCrossPartyStrandAddrs`) groups a formation result's `strandAddrs` per peer and merges each as `{ issuedAt: 0, lastSeenAt: now }`, then clears the strand's refresh throttle as before. A re-formation now **replaces** the same peer's list instead of unioning onto it. `StrandPeerObserver` (`strand-peer-observer.ts`) is the second writer: one per running strand, armed in `StrandInstanceManager.buildStrandRuntime` right after the libp2p node exists (before the database bring-up, unlike the backfill, because the bootstrap dials land during that bring-up), released in `releaseRuntime`. On `peer:identify` where `speaksBlockTransfer` holds it reports `listenAddrs` plus the connection's `remoteAddr` when relayed, each bound with `withTrailingPeerId`, through `StartStrandConfig.onStrandPeerIdentified(strandId, { peerId, addrs })`; `CadreNode.observeStrandPeer` merges it unsigned. Throttled to one report per peer per 10 minutes unless the address set changed. `start()` also walks already-connected peers via the peer store. Nothing else writes; the sibling RPC answers stay out of the book.
- **Readers.** `resolveCohortSeed` = `unionAddrs(siblingAnswers, strandPeerBookAddrs(strandId, delegatePeerId))`, freshest peer first, self skipped; `resumeStrandRuntime` goes through it. `refreshOneStrandPeerAddrs` takes its contact addresses from the book (self skipped by the running node's id). `getStrandPeerBookStore()` beside `getBootstrapPeerStore()`.
- **Forget.** `unpublishStrand`, `forgetJoinedStrand` and self-revocation (`forgetRevokedJoin`) call `forget(strandId)`; `stopStrand` keeps the book. All book writes are fire-and-log like `retainDialTarget`: visible synchronously, the promise tracks durability.
- **Config.** `CadreNodeConfig.strandPeers?: { store? }`, party-mismatch fails closed at `start()`, memory default, kept across `stop()`→`start()`, not cleared by `cleanup()`.
- **Embedders.** `cadre-cli start` opens `FileStrandPeerBookStore` in `nodeStateDir`; React Native, web and NativeScript apps open `PersistentStrandPeerBookStore` over the same slot kind as their bootstrap peers under a new `strand-peers.<party>` key (RN `strandPeersKvKey`, web `STRAND_PEERS_KV_KEY`, NS `strandPeersSlotKey`). cadre-host needed no code: its children run `cadre-cli start`, which now opens the store in the workdir; two comments there were updated. The NativeScript app was not in the ticket's file list but wires the bootstrap store, so it got the same treatment.
- **Docs.** `docs/architecture.md` Strand-Address Resolution bullet rewritten; the "replication cluster size" bullet and the node-local-store bullet updated; `docs/strands.md` gains "How a restarted machine re-finds its strand's peers" and closes the in-memory limit; `types.ts` config doc; `node-local-snapshot.ts` module comment; `.release-notes.pending.md` bullet.

## Deviations from the ticket, stated plainly

- **No `network.controlCohort.strandPeerMaxAgeMs`.** An injected store has already loaded and pruned by the time the node sees its config, so a node-level knob could only reach the in-memory default. The age lives on the store instead: `StrandPeerBookOptions.maxAgeMs` (and `now`, for tests) on every backend's constructor or `open`. Reviewer may disagree; the alternative is a setter on the store the node calls at adoption.
- **Own-entry aging exemption is not implemented.** Nothing writes an own entry yet. The store cannot tell self from a peer, so the exemption needs the swap ticket to name it (a per-strand own peer id handed to the store, or re-stamping `lastSeenAt` on every swap). A `NOTE:` at `pruneAged` in `strand-peer-book.ts` says so.
- **Observer armed before the database, not "beside the backfill".** Reason is in the comment at the arming site; the release order in `releaseRuntime` puts it right after the backfill.
- **No unit test for the observer** (per the ticket). The throttle and `dialableAddrs` (relay-hop inclusion, wrong-peer drop, cap) are therefore pinned only by the integration scenario's book assertion, which sees one connection and one address set. The reviewer may want one `dialableAddrs` table test; I judged it below the bar the ticket set.

## What the reviewer should look at

- **Restart is not proven here.** The ticket's headline case (both relay-only parties restart, re-mesh from the book alone) is `4-scenario-relay-only-restart-reconverges`. At unit level the restart shape is the pre-populated-book seed test. Also unverified: that on a relayed restart the book dial goes out before the first-sync probe. The seed reaches libp2p as `bootstrapNodes` and is merged into the address book before `startStrand` returns, same as before, but nothing measures the ordering.
- **Tie semantics in the merge rule.** Ties go to the incoming entry in both the signed and unsigned cases. For unsigned that is harmless; for signed it means a re-received identical statement replaces its twin. Fine today; check it against the swap ticket's expectations.
- **Aging and `entries()` on the persistent store** filter on read and drop on the next write, so a slot can hold an aged entry indefinitely if nothing ever merges again. Bounded by the 16-peer cap; stated in the store docs.
- **Concurrency.** Merges from several strands' identify handlers land through `NodeLocalSnapshot`'s write chain, which serialises persists in-process; the spec's concurrent-merge case covers three strands. Two processes on one slot remain unserialised, as for every node-local store (documented on `NodeLocalSnapshot`).
- **`forgetRevokedJoin` also forgets the book for this party's own strands** (it was documented as a no-op for those). Self-revocation on a strand means this party was removed, so forgetting its peers is correct either way, but the doc comment above it still describes only the join record.
- **Behaviour change:** a re-formation replaces a peer's address list rather than unioning onto it. The old union kept stale addresses as fallback; the new rule trusts the responder's current disclosure. The test names the reasoning.
- Formation-time merges are fire-and-log; a persist failure no longer surfaces from `formStrand` (the old map could not fail). Consistent with `retainDialTarget`.
