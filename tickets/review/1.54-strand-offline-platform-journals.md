Fourth of the `strand-offline-mode` chain. `strand-offline-cadre-core` added `CadreNodeConfig.strandOffline` (`journal`, `initialMode`); this ticket supplies it from the edge node (what `@serfab/cadre-rn/phone-node` and the web reference app run) and implements the journal on the phone and in the browser.

## What landed

- **Platform seam.** `EdgeNodeStorage.offlineJournal?(scope): Promise<IKVStore>` (`platform.ts`), with JSDoc for the same-instance-per-scope rule, close and destroy. Optional: a platform without it gets no offline mode.
- **Config.** `EdgeNodeConfigInputs.offlineJournal?`; `buildConfig` passes `platform.storage.offlineJournal?.bind(platform.storage)`, and `buildEdgeNodeConfig` adds `strandOffline: { journal, initialMode: strandOfflineMode ?? 'online' }` only when it is present.
- **Kit default.** `EdgeNodeOptions.strandOfflineMode?: 'online' | 'offline'`, serialized in the saved start and parsed back (anything other than the two values parses as absent, i.e. `'online'`; an older record without the field parses as absent).
- **Phone** (`LevelDBEdgeStorage`): cached `LevelDBKVStore` per scope over the scope's existing handle. `close()` closes node-local store, then journals, then databases. `destroyScope` now closes that scope's journal and its database handle (try/finally) before `destroyDB`.
- **Browser** (`strand-storage.ts`): `openJournal(key)` over the shared `openHandle` handle, cached per key; `closeStores()` and `deleteStore()` close it (logged on failure) before the handle closes. `web-edge-platform.ts` wires `offlineJournal: (scope) => openJournal(scope)`.
- **NativeScript** untouched (backlog `feat-strand-offline-mode-nativescript`).
- **Docs.** `docs/strands.md` → new "On the edge node" subsection under "On a cadre node"; `docs/reference-app-rn.md` → "Offline queue (each strand's LevelDB)" under Node-Local Persistence, and the start-options record now lists the field; `docs/architecture.md` edge-node platform paragraph names the seam.

## Deviations from the ticket — please judge

- **Key prefix is the store's default (`'optimystic:txn:'`), not `''`.** The ticket said to check for another KV store over a strand handle before choosing `''`. Nothing in a cadre node builds one (strand nodes pass db-p2p no `kvStore`; see the `NOTE:` in `peer-join-backfill.ts`). But `quereus-plugin-sereus/src/connect-browser.ts` (`connectToStrandBrowser`) journals into the same-named IndexedDB database `sereus-strand-<id>` with `new IndexedDBKVStore(db)`, the default prefix. Using the same prefix means one strand database holds its queue under one set of keys whichever code opened it. The phone uses the default too, for one rule across platforms. The prefix is a persistence contract; nothing has shipped with either value yet.
- **`strandOfflineMode` also carries through a join and a removal.** `edge-join.ts` copies it from the left party's options into the joined start (as `relayAddrs`/`noiseCryptoMode` are), and `startAfterRemoval` keeps it (as it keeps `noiseCryptoMode`). Without that, an app that set it once would silently fall back to `'online'` after joining another cadre and then being restarted in the background. `JoinCadreOptions` got no new field; `formerPartyRead` (the dissolve's read-only start of the former party) does not carry it, so strands there start `'online'` — their journals are still configured and restored.

## Edge cases checked by inspection

- **Stop order:** `EdgeNode.shutDown` awaits `stopping.stop()` (which stops strands) before `platform.storage.close()` in its `finally`, so a journal is never closed under a live queue on a normal stop. If `stop()` throws, storage still closes — a strand still up then would fail its next commit with the store's error; that was already true of raw storage.
- **Two strands:** two scopes, two maps entries, two stores.
- **Failed IndexedDB open:** `openJournal` rejects via `openHandle`; per `strand-offline-cadre-core` the build fails.
- **Old saved start:** no `strandOfflineMode` → absent → `'online'`.
- **Dissolve:** `finishRemoving` keeps strand scopes, so journals stay.
- **Browser race (pre-existing shape):** an `openJournal` whose `openHandle` resolves after `closeStores` cleared the maps would cache a journal over a closed handle; `openStore` has the same shape today. Not addressed.
