# The NativeScript lazy storage proxy now forwards `listBlockIds`

`packages/reference-app-ns/src/ns-storage.ts` wraps the SQLite-backed storage (`SqliteRawStorage` from `@optimystic/db-p2p-storage-ns`) in a proxy class, `LazyNsRawStorage`, because the database open is asynchronous and cadre-core wants a storage object synchronously. The storage interface `IRawStorage` has optional methods that callers detect by checking whether the method exists. The proxy forwarded only one of the three that `SqliteRawStorage` has, so `listBlockIds` read as "not supported" on the phone and two consumers did nothing:

- `PeerJoinBackfill.runCatchUp` (`packages/cadre-core/src/peer-join-backfill.ts`, around line 585) returned early with "raw storage does not implement listBlockIds(); backfill is inert", so a phone that founded a strand alone never pushed its blocks to a peer that joined later.
- The startup seed of the tracked block set in `../optimystic/packages/db-p2p/src/libp2p-node-base.ts` (around line 1742) was skipped, so blocks already on disk after a restart were untracked by the spread-on-churn monitor until touched again.

## What changed (one file: `ns-storage.ts`)

- Added `async *listBlockIds()` to `LazyNsRawStorage`, in the same form as `listRevisions` (await the cached open, then `yield*` from the real storage).
- Widened the class's `implements` clause to `IRawStorage, Required<Pick<IRawStorage, OptionalMethodForwarded>>`, where `OptionalMethodForwarded = 'getApproximateBytesUsed' | 'listBlockIds'`. Removing either method from the proxy is now a compile error. This does not catch a new optional method added upstream; a person still has to notice that.
- Added an accepted-tradeoff `NOTE:` to the class comment for `getStoreIdentity`, which stays omitted: it is synchronous and must return a string fixed at construction, and the real identity exists only after the asynchronous open. `withReadCache` falls back to identifying the store by object. Revisit conditions are in the comment.

## Known gaps for the reviewer

- Not run on a device. The claim that both consumers are active on the phone is read from code (neither is gated on `profile: 'transaction'`). Confirmation would be `DEBUG=sereus:*` on the phone no longer showing the "backfill is inert" line when a second device connects.
- I did not confirm by experiment that deleting `listBlockIds` fails the type check; that follows from `Required<Pick<...>>` but was not exercised.
- Behaviour change to be aware of: backfill and the startup seed now run on the phone, and each does a full scan of block ids in the strand's SQLite database (at peer join and at startup). Cost on a large phone database was not measured.
