# Hosted nodes announce their public addresses — review handoff

Second of three (`cadre-host-nat-per-node-mappings` → this → `cadre-host-node-reachability`). The design is documented in `docs/cadre-host.md` → "Public addresses reach the node" (new subsection under "NAT and DDNS") and "Respawn" → "An address restart is not a crash".

## What was built

- **Orchestrator.** `HostProcessConfig.announceAddrs(containerId, ports)` is a synchronous hook asked once per spawn inside `launchChild` (`announceAddrsFor`). A non-empty result goes to the child as `CADRE_APPEND_ANNOUNCE_ADDRS`, placed after the scrubbed parent env and `extraEnv` so neither can override it. A throw is logged and the node starts with no public addresses. The list is stored on `Handle.announcedAddrs`, persisted in `state.json` (`PersistedHandle.announcedAddrs`, missing in an older file → `[]`) and exposed on `ManagedNodeInfo.announcedAddrs`, so it shows in `/api/nodes`. The old child-env `NOTE:` saying announce vars cannot reach a child was replaced.
- **Stale-address detection.** New `nat/address-watch.ts` (`AddressWatch`, `NAT_ADDRESS_RESTART_MIN_INTERVAL_MS` = 10 min). `NatService.publish()` now ends every pass and every settings write (it replaced the six `notifyIfChanged()` call sites). It fires the change listeners, then compares each running node's `announcedAddrs` with `publicAddressesFor(node.id, node.ports)` as sets. `NatService.onNodeAddressesStale(listener)` registers the restart callback. Listeners are called fire-and-forget; their failures are logged. A node's rate-limit entry is forgotten once the node leaves the list (terminated).
- **Restart path.** `DonationSupervisor.restart(id)` runs on the supervisor's serialization tail (a `serialize()` helper now shared with `reconcile()`). It re-reads the record and does nothing unless the record is `awaiting_seed`/`seeded`, has a `dockerId` and spawn inputs, and the node is running. It then stops the node and calls `DonationService.respawn(id, { countAttempt: false })`. With `countAttempt: false`, `respawn` leaves `respawn.attempts`/`lastAttemptAt` **and `updatedAt`** alone, and a failed uncounted restart persists only the new child's handles, if any. `hasSpawnInputs()` was extracted so the supervisor and `respawn` share one predicate.
- **Wiring (`bin/host.ts`).** The announce hook reads `NatService` through a late-bound holder (`addresses.source`), because NatService is built after the orchestrator. The stale listener sends a donated node to `donationSupervisor.restart(id)`. It sends the owner node to `restartOwnerNode()` **only when `hostOwnsCadre(cfg)`**: on a donor-only host, a leftover owner child re-attached from a founder run is being stopped during startup, and an address restart racing that stop would spawn it again.
- **Hostname guard (beyond the ticket's text, needed for its "a NAT problem never stops a node" rule).** The plan assumed the DDNS hostname was already validated; only non-empty was checked. A pasted URL or a comma would have become an announce entry that kills every child at boot: cadre-core validates announce entries, and cadre-cli splits the variable on commas. Now `NatStore.validate` refuses a hostname that is not RFC 1123 (`isDnsHostname` in `address-resolver.ts`), and `buildPublicAddresses` ignores one already in a hand-edited `nat.json`, falling back to the IP.

## Use cases for the reviewer to check

- First spawn with UPnP working and the router granting the same port: no restart. Router grants another port: exactly one restart, and the node then announces the granted port.
- Set or clear a manual forward (`PUT /nat/nodes/:id/forward`), toggle UPnP, or set or clear the DDNS hostname: each running node whose public set changed restarts once, then not again within 10 minutes. The difference is acted on at the first pass after the window.
- External IP change with a DDNS hostname configured: no restart. Without one: every node with a public address restarts.
- Host restart: re-attached handles keep the `announcedAddrs` they were spawned with, so an IP that changed while the host was down produces a restart after `NatService.start()`.
- A donated node in `error`/`terminated`, or not running: `restart` does nothing. A restart whose respawn throws leaves the node down; the exit event's reconcile pass takes over as a counted crash.

## Known gaps and judgement calls

- **DuckDNS bare subdomain (not fixed; likely needs a `bug-` ticket).** The DuckDNS provider accepts `--hostname foo` and updates `foo.duckdns.org` (`ddns/duckdns.ts` strips or accepts the suffix). `buildPublicAddresses` uses the stored hostname as-is, so the node now announces `/dns4/foo/tcp/...`, which does not resolve. This predates this ticket, but this ticket is what makes it reach the nodes. Candidate fix: store the provider's fully qualified name at `putDdns`, or have `NatStore` require a dot.
- **Owner-node restart is not serialized** against `POST /api/nodes/owner/restart` or the startup `ensureOwnerNode`. Concurrent calls rely on `refuseRespawnOverLiveChild`, so the loser fails and is logged. A failed owner restart leaves the owner node down, and nothing re-spawns it: a `NOTE:` at the listener in `bin/host.ts` records this.
- **Restarts that are correct but costly, by design.** A mapping that fails drops that address and restarts the node; the renewal that restores it restarts the node again (rate-limited). A gateway that does not answer discovery at host start does the same to every node that announced a predicted UPnP address.
- **`nat-service.ts` size `NOTE:`** said the next capability should first move the mapping table out. I put the new capability in `address-watch.ts` instead and left the move, updating the NOTE (about 890 lines now). Reviewer may judge whether the move is now due.
- **`publish()` runs the comparison after every pass,** not only when the snapshot changed. That is a superset of the plan ("after every onChange and on the 1-minute timer"), and it is what lets a deferred difference fire after the window. Cost: one `listNodes()` plus one `publicAddressesFor` per node per pass.
