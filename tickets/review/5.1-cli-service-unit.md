# `cadre service` (PR #42, kjeib)

External PR, stacked on PR #36, merged locally as `Merge PR #42: cadre-cli `cadre service` prints a unit that runs a cadre init node at boot`. The merge conflicted in `packages/cadre-cli/src/index.ts` only (PR #37 renamed the `code.ts` exports); resolved by keeping both export lines.

## What landed

- `renderService(spec)`: systemd user unit (`WantedBy=default.target`), system unit (`User=`, `After/Wants=network-online.target`), or launchd plist (`org.sereus.<name>`, `RunAtLoad`, `KeepAlive`, logs in the node folder). All paths absolute; no environment needed since the claim secret is in `claim.secretFile`.
- `installSteps(kind, name, invocation)`: the install/start/follow commands, linger only for user units. Windows is refused with a pointer to NSSM.
- Options `--name`, `-c`, `--system`, `--health-port`, `--metrics-port`.

## Follow-up made at merge time

- `fix(cadre-cli): private temp dir for `cadre code --open`; POSIX log paths in launchd plists`: the launchd log paths used `path.join`, so `service.spec.ts` failed on Windows (backslashes); they now use `path.posix.join`.

## Review focus

- **systemd escaping.** `systemdQuote` handles whitespace, quotes and backslashes, but not `%` (systemd specifiers) or `$` (variable expansion in `ExecStart`). A node folder containing either renders a unit that runs the wrong command. Escape (`%%`, `$$`) or refuse.
- **`--name`** is unvalidated and is interpolated into unit file names and printed shell commands; restrict to a unit-name-safe charset.
- **Hardening.** The unit has no sandboxing (`NoNewPrivileges=`, `ProtectSystem=` and so on). The shipped `contrib/cadre-node.service` has some; decide what is safe for a user-owned folder.
- **Duplication with `contrib/cadre-node.service`**: two unit templates now; the README should say when to use which.
- Not field-tested with systemd yet (per the PR).
