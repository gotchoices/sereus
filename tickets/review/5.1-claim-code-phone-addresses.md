# Claim codes carry only phone-usable addresses (PR #37, kjeib)

External PR, stacked on PR #36, merged locally as `Merge PR #37: claim codes carry only addresses a phone can use, and the admin can choose`. Read its commit (`feat: claim codes carry only addresses a phone can use, and the admin can choose`) first.

## What landed

- **cadre-core `selectNodeClaimAddresses(reported, peerId, { lan, includeTcp })`** beside the claim-payload codec (RN-safe, no Node imports): drops loopback, unspecified, unparsable and (unless `includeTcp`) plain TCP; public names first, raw public IPs only when there is no name; private addresses narrowed by `lan` (string keeps that IP, `null` drops all, absent keeps all); relay last; appends `/p2p/<peerId>` where no `/p2p/` component exists.
- **`@serfab/cadre-core/primary-lan-address`** (Node-only subpath): `primaryLanAddress()` by a UDP connect that sends nothing.
- **cadre-host**: `claim-details.ts` uses the rule over the NAT layer's public addresses plus the node's own; `host.config.json` `claimAddresses` (`lan`: `auto` | `none` | IP; `addrs`: exact list), read on every claim request; `PUT /api/settings` whitelists and validates it; a Settings card in the UI.
- **cadre-cli `cadre code`**: `claimAddressesFor` with `--lan <ip>`, `--no-lan`, `--addr <multiaddr>` (repeatable), `--all`.

## Review focus

- **Destination check on exact or relay addresses.** Both `selectNodeClaimAddresses` and the `addrs`/`--addr` paths skip the `/p2p/<peerId>` suffix whenever the address already holds any `/p2p/` component. A relay address without its destination (`.../p2p/<relay>/p2p-circuit`) therefore stays unsuffixed, and `encodeNodeClaimPayload` refuses it with an error that does not point at the setting. Libp2p's own reported addresses carry the destination, so this reaches only operator-typed addresses; decide whether to suffix when the last `/p2p/` precedes a `/p2p-circuit`, or validate `addrs` against that at save time.
- **Exact addresses naming another peer.** `addrs` entries that end in some other peer's `/p2p/` are accepted by the settings validator and only rejected later by the codec. Admin-only input, but the error surfaces on the Join page, not in Settings.
- **DRY**: the private-range test (`isPrivateIp`) now exists in cadre-core while cadre-host's `nat/address-resolver.ts` has `isPublicIpv4`; check whether one should use the other.
- **Interaction with PR #41** (`cadre-host-network-mode`): on a VPS, `gateway.lanAddress` is null, so `lan: auto` falls back to `primaryLanAddress()`, which is the public IP. That is harmless (public IPs are not filtered by `lan`), but PR #41's description suggests public mode should default to `lan: none`; decide.
- **Error swallowing**: `primaryLanAddress` has empty `catch` blocks (with comments); acceptable as a probe, confirm.
- **Docs**: `docs/cadre-host.md` Join-by-QR step 2 and the settings whitelist were updated; check `docs/architecture.md` for any statement that claim codes carry every address.
