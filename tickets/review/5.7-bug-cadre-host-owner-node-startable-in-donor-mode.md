# Refuse owner start/restart on a donor-only host — review handoff

## What changed

- `registerNodesRoutes` (`src/server/routes/nodes.ts`) now takes `role: HostRole`. In the owner branch of start and restart, `role === 'donor'` answers `409 { code: 'own_cadre_disabled' }` (helper `ownCadreDisabled`) before the saved-config check, so a donor gets the same answer whether or not a founder run left a saved `OwnerSpawnConfig`. Stop is unchanged (allowed in both roles). Header comment updated.
- `createLocalUiServer` (`src/server/index.ts`) computes `role` once and passes it to both the status and nodes routes.
- `deriveOverallStatus` (`ui/src/lib/overall-status.ts`) skips `n.owner` nodes for the donor role, so a leftover stopped owner node no longer holds the dashboard at "Attention". The node stays listed in `/api/nodes` and `/api/status`.
- `docs/cadre-host.md`: API table row gains the 409; the "Honest gaps" bullet no longer claims donor mode "no-ops gracefully".

## Tests added

- `nodes-route.test.ts` → "start and restart answer 409 own_cadre_disabled on a donor-only host that kept a saved owner config": the bug reproduction; also asserts `ensureOwnerNode`/`restartOwnerNode` were never called. Existing calls pass `role: 'founder'`.
- `overall-status.test.ts` → "ignores a donor owner node left stopped by an earlier founder run": donor with a running donated node and a stopped owner node is `'ok'`.
