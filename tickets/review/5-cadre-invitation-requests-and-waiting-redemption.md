# Join requests, labelled invitations, and a redemption that waits — review handoff

The platform-neutral half of the app-to-app join, all in `@serfab/cadre-core`. The phone kit's party switch (`app-joins-existing-cadre-by-invitation`, in `implement/`) and the screens (`reference-apps-join-existing-cadre`, in `plan/`) build on it. The doc home is `docs/architecture.md` → "Enrollment Flow: Invitation Redeemed at Any Member" and its new subsection "Handing an invitation from app to app".

## What was built

- **Join request** (`cadre-join-request.ts`, exported from the root): `encodeCadreJoinRequest` / `decodeCadreJoinRequest`, text `sereus-join-request:1.<base64url canonical JSON of { appName, peerId, v }>`. Shaped like `node-claim-payload.ts`: the encoder refuses what the decoder would; the decoder trims and refuses by name an invitation pasted here, a missing/other prefix, a body of another shape, a peer id that does not parse or is not Ed25519 (`PeerId.type`), and an `appName` empty or over 64 characters. Imports only `@libp2p/peer-id`, `uint8arrays` and `canonical-json.ts`.
- **Invitation prefix**: `encodeCadreInvitation` emits `sereus-invite:1.` + base64url JSON; `decodeCadreInvitation` requires it and refuses a join request by name. No backwards compatibility. `CADRE_INVITATION_PREFIX` is declared in `cadre-join-request.ts` beside the request's prefix (so the light codec can name an invitation without importing the protocol module, which imports it back) and exported from the package root.
- **Address cap**: `selectCadreInvitationMembers` (`invitation-bootstrap.ts`): own addresses first (≤ 4), then siblings at ≤ 2 each in the existing order, whole list cut to `CADRE_INVITATION_MAX_ADDRS` = 6. `selectInvitationSiblingAddrs` gained a `perSibling` parameter (default 4, so open strand invitations are unchanged). The old QR `NOTE:` now says the cadre cap answers it; an accepted-tradeoff `NOTE:` at the cap records that a sibling's reachable address can be cut.
- **`reach`** on `CreateCadreInvitationResult` (`'anywhere' | 'local-network' | 'issuer-only'`, type in `types.ts`), computed by `cadreInvitationReach(members, issuerPeerId)` over the addresses whose last `/p2p/` is not the minting node. The classifier is `node-claim-payload.ts`'s, now exported as `classifyDialAddress` (adds a `'loopback'` kind; the claim selector still drops loopback, behaviour unchanged).
- **Waiting redemption**: `redeemCadreInvitation(invitation, { waitForMember?, signal?, onProgress? })`. The request is still signed once in `CadreNode.redeemCadreInvitation`; the passes are `redeemInPasses` in `cadre-invite-protocol.ts` (exported). Pacing 5 s doubling to 60 s, cut short at the invitation's expiry; local expiry check before each pass (only when waiting) throws `CadreInviteRejectedError('invite-spent', …)`; `signal` is threaded into `redeemAtMembers` (`RedeemAtMembersOptions.signal`, relayed by hand into each address's deadline, no `AbortSignal.any`) and both the pause and the in-flight attempt throw the signal's reason; `onProgress` exceptions are logged; a stopped libp2p node ends the wait; a bundle with no addresses throws at once instead of waiting. `parseNullableStoredDatetimeMs` is now exported from `control-database.ts` for the expiry check.
- **`CadreNode.wireOwnKeyIfOwner()`**: returns false and changes nothing unless the identity key is a live `OwnerKey` row; otherwise wires it via `initializeSeedBootstrap` (skipped if already wired) and returns true. Never inserts an `OwnerKey` row.
- **NOTE above the self-anchor in `initializeSeedBootstrap`** rewritten: joined machines reach it only through `wireOwnKeyIfOwner`; three callers still wire unconditionally on every start (cadre-rn `runOwnerGenesis`, the web reference app's start in `cadre-web.ts`, `cadre start --owner`); a non-owner cannot mint (the `CadreInvite` insert needs a live owner issuer); and self-publish of an existing `CadrePeer` row needs only the identity key (`registerSelf`'s update path) — confirmed by reading `publishSelfRecord`.
- **`asError`** in `cadre-invite-protocol.ts` now keeps an `ErrorEvent`'s `message`: a refused WebSocket dial showed as `[object ErrorEvent]` in the outcomes `onProgress` now hands to UIs.
- **Harness**: `redeemWithRetry` replaced by `redeemWaitingForMember` (uses `waitForMember` plus an abort budget; returns `passes`; logs each waiting pass). `startPinningMember` takes `key` and `listenAddrs` so a member can restart as itself. `sameListenAddr` moved from `pending-join-survives-restart` into `node-fixtures.ts`.
- **CLI**: still one pass; the retry `NOTE:` in `start-invitation.ts` now points at `waitForMember` + `signal`. `cadre enroll invite --json` now includes `reach` (the human output does not show it).
- **Docs**: `docs/architecture.md` — prefix, the cap with the measured sizes, the new "Handing an invitation from app to app" subsection (two flows, join request shape, `reach` table, the pass rules), `wireOwnKeyIfOwner` replacing the `initializeSeedBootstrap(ownKey)` advice, the add-a-node table row, the helper example and the implementation-status line. cadre-cli README's address sentence updated.

## Known gaps and things to look at hard

- **Upgrade effect on cadre-host records.** cadre-host keeps the encoded invitation in `hosted-nodes.json`. A record written by an older host no longer decodes: a node still `joining` fails start-up on Retry ("does not decode as a cadre invitation"), and a joined node's issuer display falls back to none (already handled and logged in `issuerOf`, whose comment I corrected). Accepted under "no backwards compat yet"; the ticket's premise that nothing stores encoded invitations was not quite true.
- **Pass loop has no unit test** (by the ticket's decision: it would mock `redeemAtMembers`, a module this repo owns). Covered by the scenario: multi-pass with one signed request, `no-member-answered`, acceptance on a later pass. Covered **only by reading the code**: abort during a pause or a dial, local expiry ending a wait, `member-not-ready` classification, `onProgress` exceptions swallowed, stopped node ending a wait, the pause being cut short at expiry.
- **Clock skew**: the local expiry check uses the device's clock and runs only when waiting; a device clock running ahead ends a wait early with `invite-spent`. One pass still leaves expiry to the member.
- **`wireOwnKeyIfOwner` right after a redemption** returned true immediately in every scenario run (B's local `OwnerKey` read already sees the row the redemption wrote with B in M's write cohort). If the phone kit finds it false right after an owner grant on a real network, it should retry rather than conclude "member".
- **Tripwire `NOTE:`s added**: `wireOwnKeyIfOwner` cannot replace a listener-only seed service (libp2p takes one seed handler; nothing that joins by invitation enables one today). `redeemInPasses`: a node stopped during a pause is noticed when the pause ends, so the timer can keep a Node process alive up to 60 s after stop.
- **`reach` for always-on minters**: excludes the minting machine by design, so cadre-cli/cadre-host minting alone read `issuer-only`. The CLI does not print it; `--json` includes it.
- **Possibly stale CLI README sentence** (not changed, outside this ticket): `packages/cadre-cli/README.md` "Join by invitation" still says a member that has not received the row "refuses the connection, and the device moves on"; since `cadre-invitations-redeemable-by-any-member`, a member seats the row from the bundle. Worth a look.
- `createCadreInvitation` reads `this.controlNode!.peerId` for `reach`; reachable only on a started node because `insertCadreInvite` has already succeeded on that line's path.
