# Review: approval hook wired into the invite-redemption path

## What was built

An invitation row (`FormationInvite`) may carry a `ValidationUrl` — the address of an
outside service that says yes/no to each redemption. Before this ticket nothing ever
called that service, and the database column that records the approval
(`FormationUsage.UsageStampId`, plus the approving key + signature) was never populated —
so redeeming a `ValidationUrl`-bearing invite always failed. Now the redemption path
contacts the service, verifies its signed answer locally, checks the signing key is
enrolled, and writes the answer alongside the consent row in the same insert.

Also landed alongside: the real disclosure text the joiner sent is now recorded in
`FormationUsage.Disclosure`, where an empty string was written before.

### Where the pieces live

- `formation-approval.ts` — the HTTP client + signature verifier (built by the prereq
  ticket `feat-formation-approval-client`). This ticket only added the `'unenrolled'`
  failure category.
- `control-formation-recorder.ts` — `ControlFormationUsageRecorder.obtainApproval()`:
  mints the nonce (`UsageStampId`), calls the approver, verifies the signature over the
  exact request, rejects a non-enrolled key, and hands nonce + key + signature back to
  both write paths (`recordUsage` for strand-bound invites, `provisionAndRecord` for
  unbound). Placed here on purpose: the recorder is the one place where the nonce that
  gets **signed** and the nonce that gets **inserted** are trivially the same value.
- `control-database.ts` — `mintUsageStampId()`.
- `strand-formation-manager.ts` — serializes the disclosure once, enforces an 8 KiB cap
  before touching the database or the network, and maps a thrown `FormationApprovalError`
  onto a distinct per-category rejection reason.
- `strand-solicitation.ts` — `recordUsage` / `provisionAndRecord` take object params
  (`{ token, peerId, strandId | sAppId, disclosure }`); `ResolvedHostStrand` carries
  `validationUrl: string | null`. **No back-compat shims** — positional forms are gone.

### Rejection reasons a joiner can now see

| failure | reason string |
| --- | --- |
| `refused` | `Formation approval refused` |
| `unavailable` | `Formation approval unavailable, retry` |
| `malformed` | `Formation approval invalid` |
| `unenrolled` | `Formation approval key is not enrolled` |
| `misconfigured` | `Formation approval misconfigured` |

Distinct on purpose — folding any of these into the generic `Formation conflict, retry`
would tell an operator to retry what retrying can never fix.

### Gaps a reviewer should probe

- **The approver is always a fake.** No test exercises `createHttpFormationApprover()`
  against a real HTTP server — timeout behaviour, non-2xx handling, and malformed-JSON
  handling are inherited from `feat-formation-approval-client`'s own tests, not re-checked
  here end to end.
- **Integration suites are compile/type-check only.** `strand-formation-e2e.integration.ts`
  and `multi-party-workflows.integration.ts` were updated for the new object-shaped
  recorder signature and they typecheck, but the suites were not executed — they spin up
  real networking and routinely exceed the 10-minute agent idle budget. Someone should run
  them out-of-band before trusting the end-to-end path.
- **Concurrency is reasoned about, not tested.** Two redemptions of one single-use unbound
  invite racing on the `(Token, UseNumber)` primary key is handled by the catch-all, but
  there is no test that actually forces the race.
- **Only two recorder implementors outside cadre-core** were swept (the two integration
  mocks, both updated). The workspace build + typecheck are the backstop for anything
  missed; nothing else surfaced.

## Behaviour changes worth a second opinion

- **Disclosure column now carries real text.** Every redemption writes
  `JSON.stringify(disclosure)` into `FormationUsage.Disclosure` where `''` was written
  before. Pre-existing rows keep `''`. Nothing in the codebase reads the column today —
  it is a record for humans and for the approval digest. This is attacker-influenced text
  landing in a replicated table; the 8 KiB cap is the only bound, and nothing parses it.
- **The HTTP approver is ON by default** in `ControlFormationUsageRecorder`. The
  constructor comment explains why: this recorder is built by the reference apps and the
  integration harness, not by `CadreNode`, so an opt-in approver would leave every real
  deployment unable to redeem a `ValidationUrl` invite. Tests inject a fake. Worth
  confirming you agree with the default rather than opt-in.
- **Type deviation from the plan.** `obtainApproval` takes
  `Omit<FormationApprovalRequest, 'usageStampId' | 'validationUrl'> & { validationUrl: string | null }`.
  The plan specified a narrower `Omit` that only removed `usageStampId`, but that collapses
  `string & (string | null)` back to `string` and loses the nullable case the function
  branches on.
- **No second pre-write `isTokenUsed` check** was added, deliberately — it cannot close
  the race, and the primary-key-collision path must stay a clean rejection.

## Review findings (from implement)

- **Tripwire — spent approvals.** Parked as a `NOTE:` comment in the catch-all of
  `strand-formation-manager.ts` `provisionAsResponder`: if a write fails after an approval
  is obtained, that approval is spent (its nonce was never inserted, and the `unique`
  `UsageStampId` column bars re-presenting it), so a retry needs a **fresh** approval — for
  a manual review queue that means a second human review. No usage row is written on any of
  those paths, so the invite itself is not consumed. Fine today; becomes real work only if
  someone builds a human review queue where double-prompting is costly. Not filed as a
  ticket.
- The 8 KiB disclosure cap is documented at `MAX_DISCLOSURE_BYTES` in
  `strand-formation-manager.ts`; the number is a judgement call, not derived from a schema
  limit.
- `strand-formation-protocol.ts:39-55` comments were present-tensed (they previously
  referred to this ticket and the prereq ticket by slug as future work).
