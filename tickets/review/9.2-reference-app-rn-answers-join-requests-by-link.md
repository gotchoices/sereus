# Phone reference app answers a join request opened as a link (owner side) — review handoff

The owner app's half of the same-phone join. **A** is this app, holding the cadre; **B** is the app asking to join. The joining side (`reference-app-rn-asks-owner-app-by-link`) is next and builds on this.

## What was built

- **Routing** (`app/+native-intent.tsx`): the node-code case is unchanged; otherwise the kit's `parseCadreLink` turns a `join-request` link into `/settings?joinRequest=<encoded text>` and a `join-response` link into `/settings?joinResponse=…`. Nothing on the joining side reads `joinResponse` yet; that is the next ticket's. The path is never logged.
- **Holding** (`app/settings.tsx` → `useLinkedJoinRequest`): reads and clears the parameter, decodes it (a decode failure is the "Cannot use this request" alert, no answer), then reads `identityPeerId()` and refuses the app's own request with the existing alert text (`OWN_REQUEST_LINE`, now in `src/join-link.ts`). If the identity cannot be read, it logs and holds the request; the section's own check against the running node's peer id catches it later.
- **No cadre** (same hook, second effect): while `asking` is true, a held request is answered `no-cadre` when it carries a reply, else the alert "This app has no cadre yet". The hook is called after `asking` is computed, because it reads it.
- **Waiting**: otherwise the request is held until the node is connected and passed to `AddDeviceSection` through `linkedRequest` / `onLinkedRequestTaken` (now typed as a decoded `CadreJoinRequest`, not text). The Node card shows "A join request from ‹app› is waiting…" (two wordings, connecting or not, as for node codes). The hint is shown wherever the node-code hint was, and now also on the "Switching cadre…" card, for both hints.
- **Section** (`src/add-device-section.tsx`):
  - `handleRequestText` decodes pasted and scanned text. `handleRequest(request, viaLink)` does the checks. `answerTo` is the request only when `viaLink` is true and it has a reply, so a request with a reply that was pasted never makes A open another app.
  - The not-owner and already-member outcomes go through a local `refuse`: an alert for a pasted request, an answer for an answerable one. The cadre-read failure is still an alert and sends no answer.
  - **Deny cooldown**: `deniedAtRef` holds `performance.now()` at the last Deny. For 30 s (`DENY_COOLDOWN_MS`) an answerable request is answered `denied` before any I/O. The seam for `app-recommends-another-app-and-enrolls-it` is just before that check: one `if (answerTo && …) return;` fits there.
  - **Prompt**: `RequestPrompt` takes `PendingRequest` (`{ request, answerTo }`). With `answerTo` set it shows the link wording (title, "It calls itself…", Code with "Check it matches…", the grant line, the switch without its usual line underneath) and **Allow** / **Deny**. Otherwise it shows the old wording with **Add** / **Cancel**. The system back button calls Deny, so B is not left waiting; for a pasted request that is plain Cancel.
  - **Allow**: `mint` now returns the `MintedInvitation` instead of showing it. A pasted request shows it as before. For an answerable one, `answerJoinRequest` is called: if it opens, the notice reads "Sent an invitation to ‹app›."; if not, the ShareCode view shows with a warning-coloured note, "Could not open ‹app›; copy this invitation into it." (`MintedInvitation.note`).
  - `linkNotice` now renders above both the minted view and the inputs, with test id `joinRequestLinkNotice`.
- **`src/join-link.ts`**: `answerJoinRequest(request, answer)` builds the link with `joinResponseLink` (appName = `ownAppName()`, `expo.name` cut to 64, now shared with `joinRequestText` in `cadre-phone.ts`) and opens it with `Linking.openURL`. It returns whether the link opened and never throws. Its failure log removes the response body wherever the error message repeats it, because React Native's `openURL` rejection includes the URL. Also: `isAnswerable` (a type guard) and `AnswerableJoinRequest`.
- **`app.json`**: the kit plugin entry is now `["@serfab/cadre-rn", { "appLinks": true }]`. `npx expo config --type introspect` shows the `sereus-join-request` intent filter and `<queries>` entry and the iOS `LSApplicationQueriesSchemes`. A native rebuild is needed for this to take effect, and the docs say so.
- **Test ids**: Allow and Deny reuse `approveJoinRequestBtn` / `cancelJoinRequestBtn`, with the comment updated. New ids: `waitingJoinRequest` (the Node card hint) and `joinRequestLinkNotice`.
- **Docs**: in `docs/reference-app-rn.md` → "Adding a Device or App", a new "Opened from another app on this phone" paragraph and bullets. The system-camera section gets a bullet on the `sereus-join-request` scheme. "When Native Rebuild Is Needed" names `appLinks`. `docs/architecture.md` → "Between apps on one phone" gets one sentence naming A's side in the reference app.

## Things for the reviewer to look at

- **Two requests arriving while A is not connected:** the second replaces the first in the Settings hook, and the first never gets an answer (B's Cancel recovers). The same happens in the section if a second request arrives while the first is still in its owner/member check, before the prompt opens. The ticket only covers dropping a request while a prompt is open or a mint runs. Decide whether this needs a guard; it is a narrow window.
- **A failed mint for an answerable request** shows the "Could not make an invitation" alert in A and sends B nothing (the kit has no refusal code for it). B's waiting line and Cancel cover it. The ticket does not say what to do here.
- **The prompt fades out with the old wording.** When `pending` becomes null the modal fades while rendering empty content in the pasted wording, as the existing prompt already did with an empty name. This is cosmetic.
- **Hint on "Switching cadre…"**: the node-code hint now shows there too (the join-request hint needed that branch). This is a small behaviour change outside the ticket's text.
- **For the joining-side ticket:** the interim own-request alert to replace with `linkRequestCameBack()` is in `app/settings.tsx` → `useLinkedJoinRequest` → `hold` (the `isOwnRequest` branch). `joinResponse` is already routed to Settings.
