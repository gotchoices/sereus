# Joiner-signed formation records — strand-layer test sweep (review)

The joiner-consent mechanism (the joining peer signs its own `FormationUsage` row;
the responder and the schema's `PeerConsented` CHECK verify that signature over
`(Token, UsageStampId, PeerKey, Disclosure)` before accepting the join) landed in
`debt-formation-consent-core`. The test-suite catch-up came in two parts:

- **Part 1 — database layer** (`debt-formation-consent-tests-db`, committed `e94e943`):
  schema-level tests for the `PeerConsented` CHECK; already reviewed and archived as
  `complete/12.1-debt-formation-consent-tests-db`.
- **Part 2 — strand/protocol layer + harness** (this ticket): everything below. Work
  spans commits `f8f5539`, `7c384c6`, `10339d0` plus the final uncommitted edits in
  this run's tree (harness fix + one stale assertion).

## What the sweep covers

- `test/formation-consent-helper.ts`: new `TestContactJoiner` + `mintContactJoiner()`
  (real libp2p ed25519 peer-id) + `mintContactConsent(joiner, token, disclosure)` signing
  over `canonicalJson(disclosure)` — shared consent-minting for the strand-layer specs.
- `strand-formation-consent.spec.ts`: all 17 contact-frame sites now carry a genuinely
  signed consent; disclosure assertions compare canonical JSON of the real disclosure.
  NEW negative tests: **(n)** invalid-consent rejection matrix — tampered signature,
  wrong partyId, garbage peerKey each yield `approved: false` with `'Invalid joiner
  consent'`, leave the invite unburned, and a subsequent valid attempt redeems;
  **(o)** nonce reuse yields `'Formation conflict, retry'` and a fresh nonce succeeds.
- `strand-formation-protocol.spec.ts`: contact fixture is a real signed joiner; NEW
  `FormationListener joiner-consent pre-check` describe proving rejection happens BEFORE
  token validation (token-check counter stays 0) and discloses no responder identity.
- `formation-approval.spec.ts`, `peer-authorization.spec.ts`,
  `validation-key-enrollment.spec.ts`, `strand-solicitation.spec.ts`: `peerId` →
  `peerKey` renames, real consent minting where rows hit real verification, vouch/consent
  signatures bound to the same nonce and disclosure bytes.
- Harness `test-network.ts` `joinStrand` (fixed this run): mints a throwaway ed25519
  identity inline and signs a real consent digest, because it writes through the REAL
  `ControlDatabase.recordFormationUsage` where the `PeerConsented` CHECK verifies the
  signature — fixture strings cannot pass there.
- Integration scenarios (`strand-formation-e2e`, `multi-party-workflows`): the three
  `recordFormationComplete` call sites pass fixture consent strings and the mock usage
  recorders track `peerKey` — the recorders are mocks, nothing verifies, so fixtures are
  deliberate there (grep-verified no other consumer reads those entries).

## Settled design decisions (hold — do not re-open in review)

- A consent-check rejection is an ordinary `approved: false` (`'Invalid joiner
  consent'`), never an abort; `FormationAbortedError` / settle-grace paths unchanged.
- Joiner nonce reuse surfaces as `'Formation conflict, retry'` with the invite unspent.
- The listener consent pre-check runs for ALL responder configs; it is pure crypto — no
  nonce is burned at the protocol layer, so protocol-spec tests reusing one contact
  object stay valid.
- A `ValidationUrl` invite needs BOTH the approver's vouch and the joiner's consent
  signatures over the same nonce and the same canonical disclosure bytes.
