# A reconnecting machine waits for its sibling to identify before writing as connected

## What was wrong

`CadreNode` treated "a control connection is open" as "my writes reach the cohort". Optimystic admits a peer into a control block's cohort only once the peer's identify has filled its peer-store protocol list with the control network's `repo` or `cluster` protocol, and only if the control node's `isNetworkMember` accepts it. Between `connection:open` and that identify (tens of milliseconds to about a second) every control write commits on a cohort of one. A restarted owner's first-growth drain re-touched its own `CadrePeer` row in that gap; at an equal revision number with the sibling's copy, that was a fork no consult or peer-join push sees, and the owner never listed machines admitted while it was down (`cadre-invite-any-member` with the follow-on edits failed 3 of 4).

## What changed

- **One predicate, `CadreNode.hasReachableControlSibling()` (public).** True when some peer in `identifiedControlPeers` passes `isControlCohortMember` (the stream gate's member rule plus devices being admitted — the same function now wired as Optimystic's `isNetworkMember`). A peer enters `identifiedControlPeers` on its first `peer:identify` of a connected period whose protocols name the control database (`servesControlDatabase`: `/optimystic/control-<party>/repo/1.0.0` or `/cluster/1.0.0`, Optimystic's own `servesThisNetwork` test). It leaves when its last connection closes. Membership is applied at read time, so a sibling that identified before it was authorized (connect-then-authorize) or that is later revoked is judged by the current snapshot.
- **Growth edge** (`updateControlSiblingReachability`): false→true drains the write-while-alone queue; true→false re-arms. Evaluated on identify, on connection close, and at the end of every membership refresh (`refreshAuthorizedControlPeers`). Not on `admittingDevices` changes, deliberately (comment says why).
- **Sibling-open reactions** (view drops, the 11 s reload, the reconcile trigger) moved from `connection:open` to the identify that first counts the peer; identify-push repeats do nothing. The close reaction still runs on every `connection:close`. The `connection:open` listener is gone.
- **Peers identified before the listeners were wired** (`noteIdentifiedControlPeers`, from the peer store at wire time) are counted and update the edge, but get no open reaction, matching what a pre-wiring connection got before.
- `committedAlone()`, `publishFirstSelfRecord`'s guard and the revoked-row reap gate (plus the joined-strand sync behind it) all read the predicate.
- `getControlConnectionCount()` stays the raw count (admin `controlConnections`); admin `alone` now reads `!hasReachableControlSibling()`.
- NOTE added at `armMembershipViewReload` for deferred consults (tripwire from the ticket). The two NOTEs that pointed at the replaced fix ticket now point at `implement/invited-machine-skips-its-first-publish`.
- Docs: "Writes made while alone" rewritten around the predicate with a "Why identify, not a connection" paragraph; "After a sibling connects" fires on identify, with a "When a consult is deferred" paragraph replacing the old fix-ticket pointer; other mentions of "no control connection" / "0→≥1 edge" updated in architecture.md, strands.md and doc comments.
- Noted on `backlog/bug-seed-connection-counted-as-a-control-connection` that this change removes its suspected path (a placeholder node serves another party's protocols); only its confirmation step remains.

## For the reviewer — known gaps and judgment calls

- **Formation costs more streams.** The drain's re-issues now actually reach the cohort, which is their purpose, but the ticket's "cost must not rise" line was written about reconnects. Decide whether the invite delta needs a second look.
- **Reconnect within one process is slightly conservative.** libp2p's in-memory peer store keeps a sibling's protocols after it disconnects, so Optimystic counts a returning sibling at `connection:open`, while cadre waits for the new identify. A write in that gap is queued and re-issued (an idempotent re-touch). Not measured.
- **`noteIdentifiedControlPeers` has no unit test.** It covers connections that identified during `start()` before the listeners were wired; before this change such a connection fired nothing until another connection opened, so this is new behaviour (the edge now updates) with no open reaction.
- **Connect-then-authorize has no dedicated test.** The refresh hook is one line; the invitation and claim scenarios exercise that join order end to end but none asserts the drain fires there.
- **Admitting devices don't trigger the edge.** `hasReachableControlSibling` counts them (as Optimystic does), so a write during an admission is not queued, but the drain waits for the device's row to land and refresh membership. Comment at `updateControlSiblingReachability`.
- **Upstream defence in depth stays open**, for a human to raise with Optimystic: equal revision numbers are treated as equal content by consults and catch-up pushes, and a commit takes the solo path while a connected serving peer has not identified yet.
