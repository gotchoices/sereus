## What landed

The npm-distributed installer experience for cadre-host. After
`npm install -g @serfab/cadre-host`, a user runs `cadre-host install` and
ends up with:

- A populated data dir (default per platform; honors XDG / `LocalAppData`).
- A fresh Ed25519 node identity persisted to `identity.key` (mode 0600 on
  POSIX).
- `host.config.json` capturing the chosen UI/libp2p ports and toggle state.
- `nat.json` seeded with the chosen libp2p port + UPnP toggle (so
  `NatService.start()` picks them up on first boot).
- A registered system service that survives reboot:
  - Linux: `~/.config/systemd/user/cadre-host.service` + `loginctl enable-linger`.
  - macOS: `~/Library/LaunchAgents/com.serfab.cadre-host.plist`.
  - Windows: NSSM-managed `CadreHost` service (requires `nssm.exe` on PATH).
- A best-effort browser tab on `http://127.0.0.1:<uiPort>/`.

The wizard is plain readline (no extra TUI dep). It prompts for data dir,
UI port, libp2p port, UPnP toggle, and a "configure DDNS now?" yes/no
(which is currently a placeholder — the flow's NAT-side wiring lands when
the management server is live).

The full surface lives at `packages/cadre-host/src/installer/`. The CLI
commands `install`, `uninstall`, and `status` now have real
implementations in `packages/cadre-host/src/bin/host.ts`.

## What `cadre-host start` does — and doesn't — today

`start` loads `host.config.json`, validates the identity file exists,
prints a banner, and waits on SIGTERM/SIGINT. **It does not yet stand up
the management API HTTP listener** (`/auth/*`, `/nat/*`). That wiring
belongs to `6.5.1-cadre-host-local-ui-server`, which is explicitly the
home for `createLocalUiServer({...})` (see the prereq ticket header at
`tickets/implement/6.5.1-cadre-host-local-ui-server.md:3`).

Practical consequence: the wizard's enrollment-invite step (which POSTs
to `http://127.0.0.1:<uiPort>/auth/invites` after the service registers)
silently degrades — the catch in `fetchEnrollmentInvite` swallows the
connection refused and returns no QR. The wizard still completes
successfully; the user just won't see a QR code on first install. Once
`6.5.1` lands and `start` is updated to call `createLocalUiServer`, the
QR will appear without further wizard changes.

Two `TODO(...)` markers in `src/bin/host.ts` flag the two follow-up
wires (`6.4.2-cadre-host-update-flow` for the update check,
`cadre-host-local-ui-server` for the listener).

## Validation — what to test

### Golden path (per platform)

1. `cmd /c "node packages\cadre-host\dist\bin\host.js install --non-interactive --data-dir <tmp>"` — should create
   `host.config.json`, `identity.key`, `nat.json`, `logs/` in `<tmp>` and
   register a service unit.
2. `cadre-host status` — should report `installed: yes` and (after the
   service actually starts) `running: yes`. Note: on Linux you must
   `systemctl --user daemon-reload` if the unit file isn't picked up.
3. `cadre-host uninstall` — should stop + deregister; `<tmp>` is preserved.
4. `cadre-host uninstall --remove-data --yes --data-dir <tmp>` — should
   remove `<tmp>` too.

The wizard interactive flow (no `--non-interactive`) is exercised
manually since stdin TTY emulation in unit tests is fragile. Drive it
with `node packages/cadre-host/dist/bin/host.js install` and confirm
each prompt accepts blank-for-default + accepts overrides.

### Edge cases worth poking

- **Re-running install on a populated data dir.** Identity must NOT be
  regenerated (the `installer.smoke.test.ts` covers this, but worth
  confirming end-to-end). nat.json gets re-seeded with the latest
  libp2p-port choice; this is intentional.
- **`--system`.** Should exit 1 with a clear "system-wide install is not
  yet supported" message. The CLI shouldn't even call into the
  service-host on this path.
- **`--no-browser` + `--non-interactive` + `--no-invite`.** Fully
  unattended install — useful for CI / Ansible.
- **Missing `nssm.exe` on Windows.** Should produce a clear error
  pointing at <https://nssm.cc/download>. Tested by the NSSM impl's
  `requireNssmAvailable()` probe.
- **Wizard input.** `wizard.test.ts` covers default acceptance, override
  acceptance, invalid port input, and invalid yes/no input. Interactive
  Ctrl-C is *not* covered; readline's default behavior (SIGINT → exit)
  applies.

### Use cases for the broader system

- **First-run install creates a working node identity.** Even before the
  management server lands, the identity file is the source of truth for
  the host's libp2p peer ID. `loadIdentity(identityPath)` round-trips,
  per the unit test.
- **Idempotency.** Running `install` twice on the same data dir must not
  rotate the identity (and therefore not change the host's advertised
  peer ID). Verified by the smoke test.
- **Uninstall preserves the trust circle by default.** Critical: if the
  user uninstalls + reinstalls cadre-host, their enrolled members must
  not need to re-enroll. The `--remove-data` flag is opt-in.

## Known gaps / things to look at

1. **No real service-host smoke in CI.** `systemctl --user enable`,
   `launchctl bootstrap`, and `nssm install` are not exercised by any
   CI runner. Documented in `packages/cadre-host/service/README.md`. A
   real release needs at least one manual smoke per platform.
2. **`start` is a sleep-on-SIGTERM stub.** Real management-server wiring
   lives in `6.5.1-cadre-host-local-ui-server`. The wizard's
   enrollment-invite step degrades silently as described above.
3. **The wizard's "configure DDNS now? [y/N]" prompt is a no-op.** The
   answer is captured into `WizardAnswers.configureDdns` but not yet
   acted on — DDNS configuration today still requires
   `cadre-host nat ddns set duckdns --hostname <h> --token <t>` against
   the running management API. Acceptable for v1; could be tightened in
   a follow-up.
4. **Browser auto-open suppressed in CI / non-TTY.** `installer/index.ts`
   gates the call on `process.stdout.isTTY && !nonInteractive`. The
   wizard's `--no-browser` flag is also honored.
5. **The systemd unit doesn't set `ProtectSystem` / `ProtectHome`.**
   Those flags are documented in the template comment as belonging to
   system units — a per-user unit can't drop those privileges since the
   user already owns the data dir. Revisit when `--system` lands.
6. **NSSM is not bundled.** v1 expects `nssm.exe` on PATH. The
   standalone-binary distribution (`tickets/backlog/cadre-host-standalone-binary.md`)
   will ship it.
7. **`identity.ts` writes the protobuf form** (not raw bytes) — this is
   intentional (libp2p's `privateKeyFromProtobuf` consumes it directly)
   but worth a second-pair-of-eyes check vs. what `start` will need to
   load it back.
8. **No platform-installed-on record.** Manual verification recorded
   here: implemented + smoke-built on Windows 11 (PowerShell 5.1, Node
   24.2.0, yarn 4.12.0). The systemd / launchd code paths are
   untested at runtime — render-only via the template tests.
