# Remove the founder role from cadre-host — review handoff

Second of the `cadre-host-join-a-cadre` chain. Pure deletion: the grant and donation layers are untouched (they go in `cadre-host-hosted-nodes-join-by-qr`).

## What changed

- **Orchestrator.** `ensureOwnerNode`, `restartOwnerNode`, `stopOwnerNode`, `getOwnerAdminEndpoint`, `hasOwnerConfig`, `isOwnerNode`, `findOwnerHandle`, `buildOwnerChildConfig`, `OwnerSpawnConfig`, `OwnerAdminEndpoint`, `OWNER_CONTAINER_ID`, `ownerConfig` in `state.json`, `Handle.owner` / `ManagedNodeInfo.owner` / `PersistedHandle.owner`, and `NodePorts.admin` are gone. `childPortBindings` and `refuseRespawnOverLiveChild` lost their owner/override arguments; `reclaimWorkdir` lost its `owner` exception. `NODE_PORT_KEYS` is now `health, metrics, p2p, ws` — a fresh node takes four consecutive ports; a re-spawn still keeps whatever ports its handle held (`reusedNodePorts`).
- **Owner client, strands, role.** `src/owner/`, `src/strands/`, `routes/strands.ts`, `FounderServices`, the `founder` server option, `HostRole`, `role` on `/api/status`, the `strands-changed` event and `StrandError` in the error handler are deleted, with their exports. `POST /api/nodes/:id/{start,stop,restart}` are removed; `/api/nodes` is list/detail/logs only.
- **bin/host.ts.** No founder stack, no owner reap, no identity-file check; every stale-address restart goes to `DonationSupervisor.restart`. Push CLI messages no longer mention an owner node.
- **Installer/config.** `host.config.json` is version 3 without `identityPath`, `libp2pPort`, `ownCadre`; `hostOwnsCadre` and `paths.identityPath` are gone; the installer no longer writes `<dataDir>/identity.key`; the wizard asks data dir, UI port, UPnP, DDNS. `install` lost `--own-cadre` and `--libp2p-port`. The settings write-whitelist's structural keys follow. `installer/identity.ts` stays (per-node identities) with a corrected header.
- **UI.** Strands page, `strand-removal`, `typed-confirm` (and `ConfirmDialog`'s `requireText` gate, which only Strands used), the strands slice, `role`, `FOUNDER_ROUTES`, the founder gate, owner lifecycle buttons, and the owner exception in `overall-status` are gone. Home always shows the Donation tile (without counts — the Nodes tile has them). The UI's `HostConfigFile` mirror is now version 3 (it read `1` before, already wrong).
- **Docs.** The sections the ticket listed, plus everything else in `docs/cadre-host.md` that described the owner node: the ports count (four), the per-node identity and env-scrub paragraphs (kept, moved from "Node admin channel" into a new "Per-node identity and configuration" section), the release-signing table's identity column, push wording, Security posture point 2, the architecture sketch, Status. "Node donation (the primary role)" is now "Node donation"; its two inbound links in `docs/architecture.md` and the README's were updated. `docs/testing.md`'s cross-process scenario list and the architecture.md integration-tests summary drop `cadre-host-owner-node`.

## Not in the ticket's list, done because the build or truth needed it

- **Two scenarios used the owner node as the requester's authority:** `cadre-host-node-donation` and `provider-seed-accepted` spawned their phone stand-in through `HostProcessOrchestrator.ensureOwnerNode` + `OwnerNodeClient`. New harness module `integration-tests/src/harness/owner-cli-node.ts` (`startOwnerCliNode`) spawns a `cadre-cli start --owner --admin-port` child directly and speaks `identity` / `multiaddrs` / `add-drone` over its admin channel; both scenarios use it. It listens on loopback TCP only (the owner node listened on `0.0.0.0` TCP + WS). cadre-cli's `admin-client.ts` NOTE ("two thin clients of one contract") now names this harness client instead of `OwnerNodeClient`. `cadre-host-node-donation` is replaced by the QR scenario in the next ticket; `provider-seed-accepted` keeps the helper.
- `orchestrator-push.test.ts` drove the owner node; it now drives `createContainer` (a storage node with no pinned keys — the only spawn that carries push). `orchestrator-node-identity.test.ts` lost the owner-identity case and its range is now four ports.
- `cadre-host-orchestrator-lifecycle`: the owner stop→SSE case became "a stop through the orchestrator reaches `GET /api/nodes/:id` and emits `node-state-changed`" on a created node, so the real orchestrator→bus→SSE seam keeps an integration check. The 501 cases for the removed verbs are gone.
- `DonationSupervisor` read `info.owner`; that guard and its test ("ignores owner-node exits") are gone.
- `scripts/smoke-cadre-host.mjs` was already stale beyond `founder` (`NatService` took `cadreNode`, `nat` sat inside `founder`); fixed to the current API. Booted to `[smoke] ready`.
- Comments: cadre-provider `port-allocator.ts` (owner `libp2pPort` override case), cadre-cli `start --owner` help (cited cadre-host `ownCadre`), `nat-service.ts` (`createStrandHandlers` reference).
- Backlog `feat-cadre-host-and-provider-nodes-carry-strand-reactivity`: its owner-node arm removed (the code it named is gone).
- Stale `dist/owner`, `dist/strands`, `dist/server/routes/strands.*` deleted by hand (tsc never prunes). `dist/auth` was already stale before this ticket and is left alone.

## Things for the reviewer to weigh

- **Every existing install is refused, not just founder ones.** A donor-only v2 `host.config.json` fails the version check too, so an upgrade means wiping the data dir, donation records included. That is the ticket's "no migration", stated plainly.
- **An orphan owner child.** A founder-era host whose owner child is still running (children are detached and survive the host) leaves that process running after the data dir is wiped; nothing reaps it. By inspection only.
- **Push now reaches no node in production.** Every spawn is a donation with pinned owner keys, and the orchestrator withholds push from those. Unchanged code; the docs and README now say so. `cadre-host-hosted-nodes-join-by-qr` revisits the rule.
- **A re-attached handle's old `admin` port** is no longer reserved, so the allocator may hand it to another node. Only the owner node ever bound it, so for donated nodes it was an idle reservation. By inspection.
