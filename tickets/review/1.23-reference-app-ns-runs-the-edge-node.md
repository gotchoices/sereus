# The NativeScript reference app runs the edge node — review

## What changed

The app builds one `@serfab/cadre-core/edge-node` edge node over SQLite and deletes its own lifecycle copy (`start-options.ts`, `ns-storage.ts`, `node-local-slots.ts`, and the start/stop/identity code in `cadre-phone.ts`).

- **`src/ns-edge-platform.ts` (new)** — `nsEdgePlatform()` / `createNsEdgeNode()`:
  - **Key store** over the `sereus-peer-identity` database's `kv` table, `b_val` column. `cadre/identity` → `peer-private-key` (the row `loadOrCreateNSPeerKey` wrote, so the peer id survives the upgrade); every other slot → `keystore.<keyId>`. Each write is followed by `syncSqliteDb`. A row whose `b_val` is not bytes → `KeyStoreAccessError`. `list()` is one key-range query on `keystore.` plus a point lookup of `peer-private-key`. SQL is lowercase.
  - **Node-local store**: `SqliteKVStore(db, '')` over the same database, behind a wrapper that opens it on first use and after `close`.
  - **Raw storage**: `lazyRawStorage(..., 'power-loss')` per call, over one cached open per database name (`sereus-<scope>`), a rejected open forgotten (`SharedOpen`).
  - **`destroyScope`**: closes that scope's block store and handle, then `deleteDatabase(nsDbPath(name))` from `@nativescript-community/sqlite` (3.5.9 exports it on Android and iOS).
  - **`close`**: flushes and closes the identity database, then each scope's `SqliteRawStorage.close()` (flush, sync, disarm timers) and its handle. Failures are logged, never rethrown. New: strand and control databases are now closed by every stop.
  - `id: 'sereus-ns'`, default transports and listen addresses, `configure` keeps `requireSignedSchemas: false`.
- **`src/cadre-phone.ts`** exports `edge` plus the helpers over `edge.node` (`Phone node not started` when null). The old comment about guarding a non-running node is gone.
- **`src/solo-smoke.ts`** now owns `startSolo`: `edge.start({ partyId, bootstrapAddrs: [], relayAddrs: [] })`, so it now founds with owner genesis.
- **`src/cadre-vm.ts`**:
  - Status, peer id and strands follow `edge.onStatus`: `running` → connected; `starting`/`joining` → connecting; `stopped` → idle; `removed` → idle with "An owner removed this phone from cadre …"; `failed` → error.
  - Every state but `running` drops the strand map.
  - Strand and commit-held handlers are registered once through `edge.on`.
  - `start`, `stop` and `restore` go through the edge node.
  - `joinCadre(encoded, relayAddrs)` decodes, then calls `edge.joinCadre(invitation, { relayAddrs })`. It no longer has a "Node not started" guard, since the edge node can join from stopped.
  - On each `running`, `savedStartOptions` becomes `edge.options`.
- **Settings**:
  - New Relays field (`relayAddr`, `input-relay-addr` in `test-ids.ts` and the XML, with a hint), sent as `relayAddrs` on Connect and on Join.
  - The form now follows `savedStartOptions` permanently. The launch read fills only empty fields. A report that comes while connected replaces all three fields, so after a join the hidden form names the joined party (otherwise Disconnect then Connect would leave it).
  - The Join hint now says the phone moves to that cadre.
- **`src/join-failure.ts`** gains the `StrandsNeedOwnerJoinError` sentence. RN's twin comment was corrected: the NS twin now has that refusal, and lacks only the cancelled-join alert.

## Tests

- `test/ns-edge-platform.spec.ts` (new, 4 tests). Real SQL on Node's `node:sqlite`, wrapped by the package's own `wrapNSPluginDb`. Only `openOptimysticNSDb` and the plugin's `deleteDatabase` are mocked.
  - **Identity survives the upgrade**: an identity written by the real `loadOrCreateNSPeerKey` comes back from `createNsEdgeNode().identityPeerId()` as the same peer id.
  - **Saved start survives the upgrade**: a `start-options` record in the old format (`{version:1, partyId, bootstrapAddrs, autoStart}`, raw SQL into `s_val`) reads back through `loadSavedStart` as `{ partyId, bootstrapAddrs, relayAddrs: [] }` with `autoStart: true`.
  - **Refusal**: a slot whose row holds text is refused with `KeyStoreAccessError`, not read as empty.
  - **Row layout**: each slot's row name (`keystore.cadre/owner`, `keystore.cadre/joined-strand/…`, `peer-private-key`) sits beside a node-local record; `list()` returns the three slots and not the node-local key.
- `test/cadre-vm.spec.ts`, trimmed and adapted:
  - New: a `removed` report shows idle with the reason and the strands dropped.
  - New: `stop` drops the strand list.
  - Join hands the decoded bundle and relays to `edge.joinCadre`.
  - Removed: "refuses join before started", "ignores a non-running node", and "ignores events after the node stopped". None of these states can happen with the edge node.
- `test/settings-view-model.spec.ts`:
  - New: a join leaves the form naming the joined party and relays.
  - Connect passes relays through, trimmed.
  - Disconnect calls `stop`.
- `test/stubs/fake-cadre-node.ts` now fakes the edge node (`FakeEdgeNode implements Pick<EdgeNode, …>`): status reports, subscriptions re-applied on each run, and a join that comes up in the invitation's party. `chat-vm.spec.ts` is unchanged and passes.
- **Deleted**:
  - `test/cadre-phone.spec.ts`: everything it pinned now lives in cadre-core's suite or the new spec. The helper forwards are glue and stay untested.
  - `test/ns-storage.spec.ts`: its cases were ported to cadre-core by the prereq ticket.
  - `test/node-local-slots.spec.ts`: the edge node's `node-local.ts` key functions replace that file entirely.

## Known gaps and judgment calls for the reviewer

- **Genesis on a seeded phone.** Typing another cadre's party id and bootstrap address into Settings is a founded start. If that party's owner rows have not arrived when genesis runs, the phone is seated as a second founding owner. This is the same behaviour RN has, and it is documented in `docs/reference-app-ns.md` → Owner key. Joining by invitation is the safe path.
- **The join UI is still shown only while connected**, so a fresh phone has to Connect (founding a party and running genesis) before it can paste an invitation. The edge node can join from stopped; exposing the join while disconnected is UI parity work, which belongs with the Maestro drift ticket.
- **The "Joined cadre" modal still words standing from `result.grantsOwner`.** `2.4-machine-invitation-grants-no-ownership` already carries the arm to switch it to `status.owner`.
- **Checked by reading only, not by a test:**
  - `close()`, including waiting for opens in flight through `SharedOpen.take`.
  - `destroyScope`, including that the edge node's removal and dissolve paths reach it.
  - The failed-start cleanup.
- A key-store or node-local call already holding the identity handle when `close()` runs would hit a closed handle. The edge node serializes its transitions, so the only exposure is a read outside them (`pendingStrandMove`). This is the same posture as the web app.
- The NOTE on iOS `deleteDatabase` leaving `-wal`/`-shm` side files is a tripwire (only matters after a failed close). The two upstream NOTEs carried over from `ns-storage.ts` sit on `openScopeDb`: the schema-failure handle leak, and `listBlockIds` reading every id.
- `cadre-phone.ts` still exports `applySeed`, `decodeSeed`, `getConnectionPaths` and `addStrand`. They have no callers (the VM uses only `dialPeer`); they are kept as they were.
- **Docs:**
  - The rewritten sections of `docs/reference-app-ns.md` (Storage, Node-local records and identity, Joining another cadre, Owner key, Start options, the unit-suite paragraphs) use one line per paragraph, while the rest of that file is hard-wrapped.
  - The `#node-local-records` anchor is now `#node-local-records-and-identity`. The Startup Sequence link was repointed to `#start-options`.
  - `docs/architecture.md` changes: the NativeScript anchor and start-option paragraphs, the relay table row (now "yes, when its relay is up"), and "Who runs it".
- The deletions were made with `git rm`, so they are already staged.
