# Review: single-use, action-scoped authority tokens for CadrePeer

Filed from the review of `membership-cadrepeer-voucher-persist`: storing the authority
voucher (`VouchSig`) on a replicated row made it a lift-and-replay token, because ONE
signature over `digest(peerId)` authorized insert AND delete AND reauthorize. This ticket
makes each action a distinct, single-use token.

## What was built

- **`StampId text not null unique`** on `CadrePeer` (mirrors `AuthorityKey`/`Strand`/
  `FormationInvite`). Generated per (re)insert via the existing `generateStampId`.
- **Action-scoped digests** (`peer-authorization.ts`): the voucher signs
  `cadrePeerVoucherDigest(peerId, stampId)` = `digest([peerId, stampId])`; delete signs
  `cadrePeerRemoveDigest(peerId, stampId)` = `digest([peerId, stampId, 'remove'])` — a
  DIFFERENT payload the stored voucher can never satisfy. `peerAuthorizationDigest(peerId)`
  is unchanged and still used by `DeviceToken` + the offline `enroll register` verify.
- **Split constraints:** `AuthorizedInsert check on insert` verifies `digest(new.PeerId,
  new.StampId)` + binds the stored voucher == context pair; `AuthorizedDelete check on
  delete` verifies the distinct `digest(old.PeerId, old.StampId, 'remove')`;
  `AuthorizedUpdate` self-branch makes `StampId` + voucher immutable, authority branch
  re-vouches over `digest(new.PeerId, new.StampId)`. Both schema copies edited identically.
- **Write paths:** `insertCadrePeerRow` mints a StampId + signs the voucher digest;
  `removePeer` reads the row's live StampId (returns early if absent) and signs the remove
  digest; `reauthorizePeer` reads the StampId, re-signs the voucher digest and re-sets the
  voucher columns. A single `signDigest` helper is now the one place the authority key is
  applied.
- **Read:** `queryCadrePeers` returns `stampId`; `queryCadrePeerStampId` added for the
  delete/reauthorize paths and ticket 4's read-time re-verification.

## Known gaps / what the reviewer must scrutinize

- **Residual, by design:** a self-appointed-authority *outsider* can still author a valid
  `remove` (its key is in the replicated, pollutable `AuthorityKey` table). This ticket
  closes *stored-voucher replay by a non-authority reader* and adds single-use nonces; it
  does NOT close outsider-authored actions — that's the node-local anchor / connection gate
  (tickets 4/6). Do not treat this as unfinished here.
- **reauthorize determinism.** `reauthorizePeer` keeps the StampId and re-derives the same
  voucher signature (ed25519 is deterministic) while bumping `UpdatedAt`; it also re-sets
  `VouchAuthority`/`VouchSig` explicitly so the authority branch passes even if a different
  authority re-touches. Confirm the re-set is harmless when it's the same authority (it is —
  same bytes).
- **DeviceToken deferred.** `DeviceToken` still signs `digest(peerId)` and shares
  `signPeerAuthorization`; it does NOT store the sig, so no stored-sig replay, but it lacks
  single-use nonces. Filed as `tickets/backlog/bug-devicetoken-authority-antireplay`.
- **Ticket 4 dependency:** the read-time predicate must re-verify `VouchSig` over
  `cadrePeerVoucherDigest(peerId, stampId)` using the now-surfaced `stampId` (ticket 4
  prereqs this one).
