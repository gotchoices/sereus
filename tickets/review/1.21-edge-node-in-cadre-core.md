# The edge node in cadre-core — implemented

GitHub #45. `@serfab/cadre-core/edge-node` now holds the bring-up the phone kit had: `createEdgeNode(platform)` over a cadre-core `KeyStore` and an `EdgeNodeStorage`. `@serfab/cadre-rn/phone-node`'s `createPhoneNode` is that over `SecureStoreKeyStore` and a LevelDB adapter, with every name it exported before re-exported as an alias, so `reference-app-rn`, `lifecycle/`, `app-link/` and `provider/` compile untouched (the reference app typechecks against the rebuilt kit). The web and NativeScript tickets (`reference-app-web-runs-the-edge-node`, `reference-app-ns-runs-the-edge-node`) adopt it next.

## Deviations from the ticket, for the reviewer

- **`lazyRawStorage` takes `durability` as a second argument.** `IRawStorage.durability` is a readonly property read synchronously, before any open, and the NativeScript proxy hard-coded `'power-loss'`; a generic proxy cannot learn it from a storage it has not opened, so the platform states it (`'power-loss'` for SQLite and IndexedDB). The two optional methods it forwards, `getApproximateBytesUsed` and `listBlockIds`, delegate when the opened storage has them and otherwise answer 0 / nothing, which is what their callers do with a missing method; `getStoreIdentity`, `readCached` and `close` are omitted (the accepted-tradeoff NOTE on `getStoreIdentity` moved with it). `UnclassifiedOptionalMember` still fails the build when `IRawStorage` gains an optional member nobody classified.
- **`unfinishedRemoval` when the marker itself cannot be read.** `finishRemovalAtStart` then reports an error with no party; the runtime keeps the previous report rather than clearing it or inventing a party (`noteRemovalAtStart`). A start that finds no marker, or finishes it, clears it; so do a dissolve and a removal that run `finishMarkedRemoval`.
- **`EdgeNodeConfigInputs.listenAddrs` is optional** (default `[]`), so `config.spec.ts` moved with its assertions and its helper unchanged.
- **`StrandMoveRecords` and `joinMoveRecord` stay unexported.** The new `finishStrandMove` test writes the move record by hand through `SecureStoreKeyStore` (`{ v: 1, targetPartyId, bundle, moved: [], refused: [] }` under the slot `node.spec.ts` already pins as a persistence contract), rather than widening the public surface for a test.

## Known gaps and notes for the reviewer

- **`@libp2p/websockets` and `@libp2p/circuit-relay-v2` are now unused by cadre-rn's own source** (the default transports moved to cadre-core). They are still in `packages/cadre-rn/package.json` `dependencies`: removing them changes `yarn.lock`, which needs `yarn install`, left to a human while other runs share the tree. `knip` (`yarn dep-check`, not a gate) will report them.
- **Stale `dist` files.** `tsc` does not clean `dist`; the kit's `dist/phone-node/{config,dissolve,options,strand-move,strands}.*` from the old layout were deleted by hand in this checkout. A checkout that builds without `yarn clean` keeps them, and `files` publishes `dist`; the release flow should clean first (check `scripts/release-*`).
- `node-local.spec.ts` in cadre-rn still exercises `kvStoreSlot` through the re-export; cadre-core has no spec of its own for it (one behaviour, already covered there).
- The web app's `web-join.ts` still documents the previous `finishStrandMove` as "the better of the two"; the ticket for it deletes that file.
- Tripwire kept at its site: `lazy-raw-storage.ts`'s NOTE on retried opens having no backoff; `edge-node.ts`'s NOTEs (file size, the node-local read window during a restart, the removed-party start) moved with the code.
