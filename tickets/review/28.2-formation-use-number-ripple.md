# Summary

Swept every remaining reader of the dropped `FormationUsage.UseNumber` column (removed by
`formation-unique-token-redesign`, which made `UsageStampId` the row key). None of this broke
`yarn build`/`yarn lint` before the fix — every reference lived inside a SQL string or a
`row.X as number` cast — so it would only have surfaced as a runtime SQL error or a column of
`undefined` in the diagnostics UI.

## Changes

- `packages/reference-app-web/src/lib/cadre-web.ts`: `FormationUsageRow.useNumber: number` →
  `usageStampId: string`; diagnostics query now selects `UsageStampId` instead of `UseNumber`
  and maps it as a string.
- `packages/reference-app-web/src/Diagnostics.svelte`: keyed-each key changed from
  `use.token + ':' + use.useNumber` to `use.usageStampId` (now unique on its own — it's the
  primary key). Rendered line shows `{use.usageStampId.slice(0, 12)}…` instead of the removed
  sequence number. `data-testid`/`data-count` attributes untouched.
- `packages/reference-app-web/e2e/fixtures/formation-responder.ts`: `readFormationUsage()`
  handle type + implementation switched to `usageStampId: string`, query selects
  `UsageStampId`.
- `packages/reference-app-web/e2e/distributed/formation-convergence.spec.ts`: no code change —
  confirmed (grep) it only reads lengths/tokens from the responder handle, never the renamed
  field.
- `packages/integration-tests/src/scenarios/strand-formation-e2e.integration.ts`: comment-only
  fix — the note about multi-use tokens now says "select by the `UsageStampId`" instead of the
  removed `UseNumber`. The function's actual query already selected `UsageStampId`; no
  functional change here.
