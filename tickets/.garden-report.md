### The night's finding: sereus cannot build or run at all

Baseline `yarn build` was red before any ticket work, and the cause is outside this repo:

```
node -e "import('@serfab/cadre-core')"
  → The requested module 'p2p-fret' does not provide an export named 'readAllBounded'
```

`../Fret` commit `f5f2eb6` (2026-08-18, "ticket(implement): rpc-framing-src") replaced its exported
`readAllBounded` with a `sendFramed` / `readFramed` pair. `../optimystic/packages/db-p2p` still
imports the removed name at 16 sites across 7 files. Both repos are linked into this one through
root `resolutions`, so the break lands here whole: `cadre-core` fails at ES-module link time, which
takes every suite that touches it with it.

Note that `tsc` passes — the type-check never descends into `db-p2p`'s internals, so only the
esbuild browser bundle and actual module loading catch it. A green `yarn typecheck` means nothing
about this class of drift.

This is not a rename. The old reader consumed a stream to EOF; the new one reads exactly one
length-prefixed frame and pairs with a matching writer. Porting changes what goes over the wire for
`db-p2p`'s cohort-topic and reactivity protocols, so it is a design call, not a mechanical swap.

### Resolution (same night)

`../optimystic` ran its own chase through all three stages and landed the fix:

| commit | stage |
| --- | --- |
| `0ea9639` | fix — research; chose "adopt FRET's framing" over the two alternatives |
| `42b1d2e` | implement — ported both ends of every affected protocol |
| `235539e` | review — fixed findings inline, filed one backlog ticket, recorded one tripwire |

The fix stage retired the wire-compatibility objection this report's blocker ticket raised, with
evidence rather than assertion: `f5f2eb6` also converted FRET's *own* routing protocols
(`maybeAct`, `ping`, `neighbors`, `leave`), and `db-p2p` pins `p2p-fret` to `portal:../Fret` — so a
build today already cannot talk to published v0.24.0 at the routing layer, and cohort-topic depends
on that routing to find peers at all. Preserving cohort-topic's old framing would have bought
interop only with peers it can no longer reach. Separately, `db-p2p`'s other protocol family
(`protocol-client.ts`, `cluster/`, `repo/`, `sync/`, `dispute/`) already uses `it-length-prefixed`,
the same varint format, so the port makes cohort-topic consistent rather than divergent.

Its review stage also caught a latent defect the framing change created: `host.ts` typed all five
protocol handlers as `Uint8Array | undefined` with a "must always reply" doc comment, so a later
edit returning `undefined` would compile and hand its dialer a truncation error. Split into
`makeRequestHandler` / `makeOneWayHandler` over one shared lifecycle, putting the invariant in the
type. Upstream validation: build clean, eslint clean, 1817 unit tests passing, 30 integration.

### The review stage earned its place this run

Two findings the implementers had missed, both fixed at the invariant rather than the instance:

- **`cleanup()` was not the complete teardown.** `stop()` privately held the relay-supervisor stop
  and the `_running = false` reset. Harmless while nothing after `_running = true` could throw —
  and `control-db-bring-up-runs-before-first-connection` made something throw there. A node whose
  relay was down would reject `start()` and then report `isRunning === true` over a torn-down
  libp2p (an embedder's retry early-returns "already running" and does nothing), while a
  reservation retry loop kept dialing that stopped node on an unref'd timer nothing would clear.
  Reachable by any operator whose `CADRE_RELAY_ADDRS` relay is down. `cleanup()` now owns the whole
  teardown, so any future throw after `_running = true` is safe by construction. Note this also
  makes `bug-relay-drive-not-cancellable`'s second arm true — that arm asserted `stop()`/`cleanup()`
  already stopped the supervisor, which was wrong when written.
- **`control:connected` emitted with no closing edge** when `start()` then rejected. The implement
  handoff named this as an accepted cost; the review disagreed and fixed it.

unlocked read), and the inference that the stall sits above optimystic (drawn from a missing debug
line in a trace we cannot reproduce from their tree).
