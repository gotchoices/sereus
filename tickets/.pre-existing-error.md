Following its confirm protocol, the debug run alone logged `Committed 35 empty control collections in` 8898, 9021, 10437, 11764, 11771 and 13236 ms. The record measured 891–1188 ms for the same step alone (32 collections then). So the genesis step is near the 15 s bound even alone, which the protocol says is the genesis cost, to go with `control-collections-created-at-cadre-founding` or an upstream batching request rather than a bigger spec bound.

The machine was heavily loaded during both runs: CPU at 97%, with 59 `node` processes running that this ticket did not start. That load may account for all of the slowdown; re-measure on an idle machine before concluding the step itself regressed.
