no `src/` runtime code. I verified the failures are independent of the diff two ways:

1. **Runtime dep versions are unchanged** by the diff: `libp2p` (3.1.3), `@optimystic/db-p2p`
   and `@optimystic/db-core` (`0.0.0-use.local` workspace portals), `@libp2p/tcp` (11.0.10),
   `@chainsafe/libp2p-noise` (17.0.0) all resolve identically before/after in `yarn.lock`.
2. **Reproduced at the parent commit.** I checked out `6a5806e~1`'s `yarn.lock` + all
   `package.json`, ran `yarn install`, and re-ran `yarn workspace @serfab/integration-tests run test`:
   **identical 12 failed | 74 passed (86)**. The failures exist before this ticket landed.

The shape (real-network libp2p convergence timeouts) is consistent with environment/infra
sensitivity (no local relay/bootstrap, CPU/IO timing), not a code regression.
