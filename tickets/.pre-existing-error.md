# The second long test in `joiner-first-commit-over-slow-relay` fails its relay reservation

Found while running the integration suite for `optimystic-1-30-integration-harness` (implement stage, 2026-11-26).

## Command

From the repo root:

```
yarn workspace @serfab/integration-tests exec vitest run src/scenarios/joiner-first-commit-over-slow-relay.integration.ts
```

## The failure

`packages/integration-tests/src/scenarios/joiner-first-commit-over-slow-relay.integration.ts` — the pair

- "a joiner's first transaction over a relayed link > delivers the rows of a commit made alone once the joiner restarts over its kept storage"
- "…once the joiner restarts over its kept storage, still on the slow link"

Whichever of the two runs **second** fails after about 19 s with:

```
→ network.relayAddrs reservation failed (status: retrying): relay reservation on
  /ip4/127.0.0.1/tcp/55207/ws/p2p/12D3KooWMP5vtnpy1D1LTQqE3bbooGYhDUmvz97uFiD2jhvDAbeY failed:
  The operation was aborted due to timeout
  — relays: /ip4/127.0.0.1/tcp/55207/ws/p2p/12D3KooWMP5vtnpy1D1LTQqE3bbooGYhDUmvz97uFiD2jhvDAbeY
```

The failure is raised out of node start, before any part of the scenario body runs.

## Why this looks like a pre-existing, order-dependent flake rather than this ticket's change

Measured in two runs of the same file, same working tree:

| Run | Order | Result |
| --- | --- | --- |
| whole file | 70%-busy-event-loop arm (441 s) → kept-storage (loopback) → kept-storage (slow link) | loopback FAILED at 19 s; slow link PASSED at 429 s |
| `-t "delivers the rows of a commit made alone once the joiner restarts over its kept storage"` | kept-storage (loopback) → kept-storage (slow link) | loopback PASSED at 348 s; slow link FAILED at 19 s |

So each variant has both passed and failed, and the one that fails is always the one starting right after a test that ran for six to seven minutes in the same worker process. Neither variant fails when it is the first long test in its process. The failing call is a libp2p circuit-relay reservation, which this ticket's diff does not touch — its one line in this file is `home.storage.provider` → `home.storage.open`, on the node-storage seam, and the other five tests in the file pass over that same line.

The honest caveat: this cannot be confirmed by running the file at HEAD. `@serfab/integration-tests` does not build or run at HEAD — ticket `optimystic-1-30-cadre-core-node-storage` changed `CadreNodeConfig.storage` and left this package with 13 typecheck errors that this ticket is the one to fix — so there is no pre-change run to compare against. The evidence above is from the post-change tree only.
