# Pre-existing error: reference-app-web browser bundle breaks on `node:crypto` (cadre-core push-notifier)

## Command(s) run

From repo root:

- `yarn workspace @serfab/reference-app-web typecheck` → **PASSES** (`tsc --noEmit`, clean).
- `yarn workspace @serfab/reference-app-web build` → **FAILS** at the `vite build` step
  (the `tsc --noEmit` half passes; the rollup/vite bundling half fails).

The same break blocks the Playwright e2e suite, because `playwright.config.ts`'s
`webServer.command` is `yarn build && yarn preview` — the build must succeed before
the preview server (and thus any e2e spec) can start. So
`yarn workspace @serfab/reference-app-web test:e2e -g "solo"` could not be run either.

## Failure output (excerpt)

```
../cadre-core/dist/push-notifier-fcm.js (16:9): "sign" is not exported by
"__vite-browser-external", imported by "../cadre-core/dist/push-notifier-fcm.js".
file: C:/projects/sereus/packages/cadre-core/dist/push-notifier-fcm.js:16:9
16: import { sign } from 'node:crypto';
✗ Build failed
```

(`push-notifier-apns.js` triggers the same class of warning for `node:crypto` /
`node:http2`; `push-notifier-fcm.js` is the one that hard-fails the build because it
imports a *named* export, `sign`, that the browser-external shim does not provide.)

## Why this is pre-existing (not caused by this ticket)

- This ticket (`formation-convergence-e2e-app-hooks`) touches only the chat-strand
  DML/hook surface: `packages/reference-app-web/src/lib/{cadre-web.ts,
  messages.svelte.ts,chat-dml.ts}`. None of these import push-notifier, `node:crypto`,
  or anything in that chain. The `tsc --noEmit` typecheck of those changes passes.
- The failing module is a **cadre-core** artifact. `push-notifier-fcm.ts` was added by
  the recent `cadre-push-notifier` ticket (commit `66d736d`) with a top-level
  `import { sign } from 'node:crypto'`. The import chain into the browser bundle is
  `cadre-node.ts` → `push-notifier.js` → `push-notifier-fcm.js` → `node:crypto`, and
  `reference-app-web` bundles `CadreNode`, so the node-only crypto is pulled into the
  browser build.
- `packages/reference-app-web/vite.config.ts` (lines 14-15) **deliberately** does not
  alias `node:crypto`: "anything reaching for them in a browser bundle is a real bug we
  want surfaced, not papered over." So this is exactly the surfaced-bug case that config
  intends — a cadre-core regression, not a missing alias.

## Likely fix (for triage — out of scope here)

In cadre-core, keep `node:crypto` (and `node:http2`) out of the browser-reachable
module graph: make the FCM/APNS push notifiers node-only (e.g. a runtime dynamic
`import('node:crypto')` guarded for the node environment, or split the push-notifier
factory so the `node:crypto`-using code is not statically imported by `cadre-node.ts`).
Push delivery is a server/host concern; the browser edge node never sends pushes.

## Work-arounds applied in this ticket

None. I did not alias `node:crypto` in the web app's vite config (doing so would
contradict that config's stated intent and mask the cadre-core bug), and I did not
modify cadre-core (out of scope for this ticket). I validated this ticket's changes via
`tsc --noEmit` (typecheck, green) + `eslint` on the three changed files (green) instead
of the full `vite build` / e2e, both of which are blocked by this pre-existing break.
