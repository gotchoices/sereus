## Why this is pre-existing, not mine

The scenario's node A is `profile: 'storage', enableRelay: true`
(`control-cohort-cold-start-retry.integration.ts:53`). On a node that RUNS the
circuit-relay server, the membership connection gate no longer expresses
"positively an outsider" as a connection deny — it returns `'admit-for-relay'`,
admits the connection, and drops it only at the 5 s not-reserving deadline
(`membership-connection-gater.ts` → "The relay-reservation seam"). B meanwhile
re-dials from its retained seed addresses on a 2 s reconcile cadence
(`reconcileMs: 2_000`, line 62), so a poll never observes zero connections. The
scenario's step-3 premise — that a relay-enabled owner refuses an unvouched
peer's connection outright — stopped being true when that seam landed
(`8180ebf` / `6c87c5b`, `control-sibling-relay-reservation-denied`), which is
before this ticket.

Measured, not only inferred: the failure reproduces unchanged with this ticket's
own change neutralized (the bring-up quiet period forced off in
`createMembershipConnectionGater`), and this ticket's other change — the
`network.relayAddrs` listen-address route — cannot reach a scenario where neither
node sets `relayAddrs`.

The scenario's own REGRESSION assertion (step 5: B re-dials A from its retained
seed addresses) is never reached, so the cold-start-redial behaviour it exists to
guard is currently unproven either way.
