# Pre-existing test failure: three scenarios compare a `Strand` row without `FounderPeerId`

## Commands

From the repo root:

```
yarn workspace @serfab/integration-tests exec vitest run harness-topology
yarn workspace @serfab/integration-tests exec vitest run strand-late-cadre-join
yarn workspace @serfab/integration-tests exec vitest run strand-unpublish-sibling-convergence
```

(Seen in batch runs; logs `tickets/.logs/harness-owner-keys.batch3.log`, `.batch8.log`, `.batch9.log`.)

## Failing tests

All three fail on the same kind of line: a `Strand` row read back from a control database, compared with `toEqual` against an object of four keys.

- `packages/integration-tests/src/scenarios/harness-topology.integration.ts:354` → "Topology builder harness > controlMesh 'star' plus the strand knobs the mesh cases never drive: mesh 'none', publish, closed founder"
- `packages/integration-tests/src/scenarios/strand-late-cadre-join.integration.ts:360` (`joinDiscoveredStrand`) → "Late cadre join: the strand follows the newcomer > delivers a pre-existing strand — blocks and all — to a machine enrolled after the writes" and "… > loses no row written while the newcomer is still catching up"
- `packages/integration-tests/src/scenarios/strand-unpublish-sibling-convergence.integration.ts:144` → "Two-node strand-unpublish sibling convergence > stops the sibling instance once its watcher observes the removal, exactly once, and rediscovers a re-publish"

```
    "FounderOwnerKey": "Hin0YMNUQH8tUnHBiOyLQuN6MB-cvd8bx3m1R5ve4yU",
```

## Why it is pre-existing

`ControlDatabase.queryStrands()` and the discovered-strand rows have carried a fifth column, `FounderPeerId`, since `owner-key-label-and-founder-machine` (commit `d37f7dd7`, `STRAND_COLUMNS` in `packages/cadre-core/src/control-database.ts`), so each of these exact comparisons fails on every run at HEAD. None of the failing lines is in the diff of `harness-owner-keys-separate-from-node-identity` (that ticket changed only the owner-genesis line of `strand-late-cadre-join`, and none of the other two files), and the owner key each row carries (`FounderOwnerKey`) matched.
