# Pre-existing failure: claim past two silent addresses times out its live address under full-suite load

**Command** (repo root): `yarn workspace @serfab/cadre-core test` (full suite, 162 files in parallel).

**Failing test:** `packages/cadre-core/test/cadre-node-dial-past-dead-addresses.spec.ts` → "CadreNode — claiming a node whose first addresses never answer" → "reaches the node past two silent addresses and the claim is accepted".

**Error excerpt:**

```
PeerUnreachableError: Could not reach 12D3KooW…: Seed delivery dial of 12D3KooW… failed for all 3 candidate addresses:
  /ip4/127.0.0.1/tcp/53176/ws/p2p/12D3KooW… — … timed out after 500ms;
  /ip4/127.0.0.1/tcp/53177/ws/p2p/12D3KooW… — … timed out after 500ms;
  /ip4/127.0.0.1/tcp/53180/ws/p2p/12D3KooW… — … timed out after 500ms
```

The third address is the live node's own WebSocket listener, and it also timed out on the spec's `PER_ADDRESS_MS = 500` per-address deadline (spec line 33).

**Rate observed:** failed in 1 of 2 full-suite runs on 2026-10-11; passed in isolation (`npx vitest run test/cadre-node-dial-past-dead-addresses.spec.ts`, all 3 tests) and on the second full run.

**Why it is pre-existing / not from the ticket that surfaced it** (`relay-only-strand-launch-waits-out-relay-drive`): that ticket changes the `transports` option only for nodes with configured relays (`network.relayAddrs`, or relays on a strand node); this spec configures no relays, so its nodes get exactly the `network.transports` they got before. The failure is a real WebSocket dial on loopback missing a 500 ms deadline while 162 spec files run in parallel, which reads as a load-sensitive deadline in the spec rather than a code change.
