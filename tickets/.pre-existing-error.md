# Pre-existing failure: RN Metro bundle cannot resolve `path`

## Command

```
cd packages/reference-app-rn
npx expo export --platform android --output-dir .bundle-check
# (equivalent to the package's `yarn test:bundle`, whose `expo export` step is the bundle compile)
```

## Failure (before workaround)

```
Android Bundling failed 22963ms packages\reference-app-rn\index.js (3578 modules)
Error: Unable to resolve module path from C:\projects\sereus\packages\cadre-core\dist\strand-instance-manager.js:
  path could not be found within the project or in these directories: ...
  > 28 | const path = require('path');
```

## Why this is pre-existing (not caused by this ticket)

- The failing module is `@serfab/cadre-core`'s `strand-instance-manager.ts` →
  `getStrandStoragePath(basePath, strandId)`, which is **outside this ticket's
  diff** (this ticket touches `cadre-node.ts`, a new `strand-member-key.ts`, and
  the reference-app files — never `strand-instance-manager.ts`).
- `getStrandStoragePath` is **explicitly `@deprecated` and self-documents as
  "not available in React Native"**: it `require('path')`s and throws at runtime
  on RN before reaching it. But Metro bundles statically, so the bare
  `require('path')` must still *resolve* at bundle time — and
  `packages/reference-app-rn/metro.config.js` maps `os`/`crypto`/`stream`/
  `buffer`/`net`/`tls` (and their `node:` forms) but **not `path`**. Both the
  static `require('path')` and the missing metro mapping predate this ticket.
- It fails for any RN bundle that imports `@serfab/cadre-core` (the whole index
  re-exports `getStrandStoragePath`), independent of this ticket's changes. The
  prior `reference-app-rn-discovered-strand-join` ticket validated via
  build/typecheck/lint and did not run `test:bundle`, so this latent break went
  unflagged.

## Workaround applied (to complete this ticket's bundle validation)

- `packages/reference-app-rn/metro.config.js`: added `path` and `node:path` →
  `polyfills/empty.js` (the same empty-stub treatment as `net`/`tls`, documented
  inline as "imported by transitive deps but never called at runtime"). This is
  safe because `getStrandStoragePath` throws on RN before ever calling
  `path.join`. With it, `npx expo export --platform android` succeeds (3581
  modules, exit 0), confirming this ticket's new code bundles.

## Suggested real fix (for the triage pass)

Prefer fixing the root cause in cadre-core rather than relying on the app-level
stub: make `getStrandStoragePath` not *statically* reference the `path` module
(e.g. build the path with plain string joins, or drop the deprecated helper),
so RN bundles never need a `path` shim at all. If the metro stub is kept,
consider a minimal real `path` shim (POSIX `join`) instead of the empty stub in
case a transitive dep ever calls `path.*` at RN runtime.
