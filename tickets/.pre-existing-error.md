## Pre-existing test failure: strand-membership-invite.spec.ts

**Test command:**
```
cd packages/cadre-core && npx vitest run test/strand-membership-invite.spec.ts
```

**Result:** 21 failed | 4 passed (25).

**Error excerpt:**
```
Error: Unsupported output encoding: utf8
 ❯ resolveOutputEncoder ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:129:9
 ❯ digest ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:324:56
 ❯ signStrandPayload src/strand-membership-writer.ts:50:21
 ❯ issueInvite src/strand-membership-writer.ts:298:30
```

**Root cause:** API drift. `quereus-plugin-crypto`'s `digest` is now a 3-arg function
`digest(fields, algorithm = 'sha256', encoding = 'base64url')`, but `cadre-core` still
calls it with 4 args — e.g. `strand-membership-writer.ts:50`
`digest(payload, 'sha256', 'utf8', 'bytes')`. The 3rd positional arg `'utf8'` is now
interpreted as the output encoding, which `resolveOutputEncoder` rejects. This matches
the pre-existing build errors (`TS2554: Expected 1-3 arguments, but got 4`) at
`strand-membership-writer.ts:50,71`, `control-database.ts:25,72`, `device-token.ts:38`,
`peer-authorization.ts:17`, `peer-record.ts:56`, `seed-bootstrap.ts:430,643`.

**Why pre-existing:** This ticket made comment-only changes to `strand-membership-writer.ts`
(lines 356-357) and to the spec; it never touched any `digest()` call site. The `digest`
signature change lives in the `optimystic` workspace, outside this ticket's diff. A prior
triage run (commit ba2beaf) documented an earlier manifestation of the same broken file
(`MissingServiceError: libp2p not set`) and removed this file; the failure now surfaces as
the `digest` encoding error before the libp2p path is reached. Re-flagging so the runner
re-triages against the current signature.

**Work-around:** None applied — the failing tests never exercise the datetime comment
corrections this ticket makes, so no work-around was needed to complete the ticket.
