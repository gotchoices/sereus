`Test Files 1 failed | 53 passed (54)` / `Tests 1 failed | 443 passed | 6 skipped (450)`. The run reports the case at 15135 ms. `result.status === null` with empty `stderr` is `spawnSync` hitting its own `timeout: 15000` (line 929), not the helper failing.

## Why it is pre-existing

The budget is marginal by construction, and the failing step is one this ticket's diff does not touch. The helper the test spawns imports the built `packages/cadre-host/dist/orchestrator/host-process-orchestrator.js`, whose import graph reaches cadre-core and `@optimystic/db-p2p`. A **cold** import of that one module on an otherwise idle machine measures 8.2 s:

```
$ node -e "import('file:///C:/Projects/sereus/packages/cadre-host/dist/orchestrator/host-process-orchestrator.js')"
real 0m8.199s
```

The whole case — that import, plus spawning the grandchild, plus the helper exiting — has 15 s. Under the 54-file parallel suite (389 s of import time in total) the import alone exceeds it.

Reproduction pattern, which is what a load-sensitive budget looks like:

- the single case alone (`-t "grandchild stays alive"`): **passes**, 9.98 s of test time;
- the whole file alone (`vitest run src/__tests__/orchestrator.test.ts`): **passes** (38 passed, 1 unrelated pre-existing skip);
- the full `@serfab/cadre-host` suite: **fails**, twice out of two runs.

This ticket's change to that file is the field rename only — `makeRequest`'s `opts.profile?: 'storage' | 'transaction'` became `opts.nodeClass?: NodeClass`, and three `profile: 'transaction'` literals became `nodeClass: 'device'`. It adds nothing to the helper's import graph and changes no timing. The failing case's own request literal (line 913) is one of those renames; everything it exercises afterwards is process detachment and stdio.

## Not in `.pre-existing-known.md`

No entry there matches this test, so it is reported here rather than noted as already-tracked. Nothing was skipped, disabled, or loosened to get a green run; the rest of the ticket's validation (full `yarn build`, `yarn lint`, `yarn typecheck`, cadre-core 2654 tests, cadre-cli 295 tests, cadre-provider, the reference apps) passed.

A fix probably belongs on the test's side: raise the `spawnSync` timeout to something above the measured cold-import cost with headroom, or have the helper report readiness so the case waits on a signal rather than a fixed budget.
