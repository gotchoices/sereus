## Pre-existing test failure

**Command run:**
```
yarn workspace @serfab/cadre-core test 2>&1 | tee /tmp/cadre-core-test.log
```

**Failing test suites (representative):**
- `test/authority-key.spec.ts` — 8/8 failed
- `test/cadre-node-seed-trust.spec.ts` — multiple failed
- `test/control-formation-invite.spec.ts` — 16 skipped (beforeAll crashes)
- `test/peer-record.spec.ts`, `test/peer-record-resolution.spec.ts`, `test/peer-authorization.spec.ts`, `test/publish-strand.spec.ts`, `test/publish-formation-invite.spec.ts`, `test/control-database-genesis.spec.ts`, and more — all fail or skip

**Root error (same in all cases):**
```
Error: Unsupported output encoding: utf8
 ❯ resolveOutputEncoder ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:129:9
 ❯ digest ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:324:56
```

Triggered whenever code calls `digest(..., 'sha256', 'utf8', 'bytes')` — the
`'bytes'` output encoding is not recognized by the current `quereus-plugin-crypto`
build.  In `control-formation-invite.spec.ts` specifically it crashes inside
`generateStampId` → `insertAuthorityKey` → `ensureAuthorityKey` in `beforeAll`,
which causes all 16 tests to be skipped.

**Why pre-existing:** The failure is in `packages/quereus-plugin-crypto` (under
`../optimystic/`), a package not touched by this ticket.  The `control-schema-drift`
spec (which does not use crypto) passes cleanly, confirming the schema edits are
correct.  All affected test suites fail on `main` at the same SHA before any
changes from this ticket.

**Workaround:** None applied — the drift guard (`control-schema-drift.spec.ts`)
runs clean and is the only cadre-core spec that can execute under the current
crypto build.
