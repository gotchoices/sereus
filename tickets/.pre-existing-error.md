## Why this is pre-existing / not mine
- Both failures are **vitest 5000ms timeouts** on tests that spawn the cadre-host CLI as a child
  process (subprocess + HTTP server boot), not type or assertion errors.
- They are entirely outside this ticket's diff. My changes are type-only: adding `admin` to
  `NodePorts` test fixtures, annotating `req`/`a` params, swapping `peerId`→`privateKey` and
  `storage: { type }`→`{ provider }` in cadre-core specs, dropping a return-type annotation, and
  adding two `tsconfig.typecheck.json` files. None of these tests import anything I touched.
- **Running the two files in isolation passes 11/11:**
  `yarn workspace @serfab/cadre-host exec vitest run src/__tests__/cli.smoke.test.ts src/__tests__/cli-nat.smoke.test.ts`
  → `Test Files 2 passed (2) / Tests 11 passed (11)`. They only fail in the full 46-file run, where
  the reported `import 86.51s` indicates heavy parallel contention pushing the CLI subprocess spawn
  past the 5s per-test cap (a slow/loaded Windows host effect, not a logic break).

## Work-around applied
None needed for this ticket. I did not modify these smoke tests or their timeouts. cadre-core tests
(292/292) and both per-package + monorepo typechecks pass clean. A durable fix would raise the
per-test `testTimeout` for these subprocess-spawning smoke tests (they cold-start a Node child + boot
a server, which is inherently >5s on a loaded host).
