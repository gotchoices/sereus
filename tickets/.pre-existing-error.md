## Why this is pre-existing

`packages/cadre-core/test/peer-addr-book.spec.ts` imports four packages that
`packages/cadre-core/package.json` declares nowhere, so they resolve only by hoisting.
The spec and its imports came in with the completed `merge-verified-peer-addrs-into-control-peerstore` /
`merge-strand-peer-addrs-into-strand-peerstore` work; this review ticket
(`harness-topology-builder`) touches only `packages/integration-tests/src/harness/**` and
one integration scenario, and declares no dependencies at all.

Same class as the two dep-check entries already in `tickets/.pre-existing-known.md`
(2026-07-30 `@libp2p/peer-id` in reference-app-web, 2026-08-03 `@serfab/cadre-cli` in
integration-tests): the fix there was declaring the packages in the workspace manifest —
here as `devDependencies` of `packages/cadre-core`, at ranges matching the versions the
other workspaces already declare, and `yarn check:dep-ranges` must pass afterwards.
Not fixed inside this ticket because it edits another package's manifest and picks
version ranges, which is a decision outside this ticket's diff.

`yarn lint`, `yarn typecheck` and the integration suites this ticket ran are all green.
