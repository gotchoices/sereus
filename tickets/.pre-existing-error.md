## Why it is pre-existing / not this ticket's

- This ticket's phase changed **test files only** (`packages/cadre-core/test/*`) plus ticket
  markdown. Nothing it touched is on the block-transfer or schema-load path.
- The membership gate — the subsystem this ticket covers — was ruled out directly. Re-run
  under `DEBUG='sereus:cadre:*'` there is **not one**
  `authorizeInboundControlStream: DENYING` line, and the automatic write-driven refresh
  fires correctly and promptly (`refreshAuthorizedControlPeers(peer-insert): 1 authorized
  peer(s)` then `… 2 authorized peer(s)`). A stale gate snapshot is the failure mode this
  scenario's own comments warn about, and it is demonstrably not what is happening.
- The failure is inside `@optimystic/*` (block retrieval / collection sync), a sibling
  checkout consumed as built `dist`. Its version floor was moved `^0.17.0 → ^0.18.0`
  repo-wide in the same commit as this ticket's implement phase (unrelated churn from
  `2fe64b4`, the v0.18.0 re-measurement); the last green verification of this scenario
  recorded in `.pre-existing-known.md` is 2026-07-29, against 0.17.
