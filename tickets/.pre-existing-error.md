The statement under test is an UNSIGNED counter bump with no `with context` clause:

```sql
update CadreControl.Revocation set ReissuedAt = 1 where StampId = ?
```

The test expects the `AuthorizedReissue` CHECK to reject it. Quereus instead fails
earlier, at plan time, because the constraint body references `context.OwnerKey` while
the statement omits the `with context` clause entirely — so `context.OwnerKey` never
resolves to anything. Same failure mode already documented in
`control-database.ts:reapRevokedRow` ("Quereus cannot resolve `context.OwnerKey` at plan
time when the clause is absent while a constraint references `context.*`"), where the fix
was to pass the clause present-and-null. The likely resolution here is the same shape:
either the test issues `with context OwnerKey = null, Signature = null`, or the engine is
expected to treat an absent clause as all-null and that regressed upstream.
