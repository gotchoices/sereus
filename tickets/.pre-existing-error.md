## Why pre-existing

It fails identically with this repo's HEAD dependencies (libp2p 3.1.3 / `@libp2p/interface` 3.1.0, lockfile restored from HEAD and reinstalled): same two tests, same 141147 / 133164 / 120461 ms settle times. So it is not caused by `typecheck-fails-on-libp2p-interface-3-1-against-linked-optimystic-3-3`'s dependency move.

Likely cause (static, not traced): the linked `../optimystic` at `249a26b8` includes `7da08dc2` (`the-rpc-dial-deadline-cannot-be-set-per-node`, landed 2026-10-01 01:20), which derives the RPC dial deadline as 11 link round trips and the transaction budget as 4 dial deadlines (44 round trips, `packages/db-p2p/src/rpc-deadline.ts`). At sereus's declared 3.5 s round trip (`DECLARED_LINK_ROUND_TRIP_MS`, `packages/cadre-core/src/link-budget.ts:205`) that is about 154 s, which the measured settle times fit. `tickets/blocked/adopt-optimystic-address-dial-timeout.md` already has a TODO to "check that the derived transaction timeout still fits inside sereus's write and cohort budgets"; this failure is that check failing in the linked workspace. Deciding whether sereus should pass explicit `rpcDeadlines` or the test cap should follow the derived budget is that ticket's question.
