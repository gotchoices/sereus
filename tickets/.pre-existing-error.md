## Command

yarn workspace @serfab/integration-tests test strand-formation-e2e -t "replicate data"

(package: `packages/integration-tests`)

## Failing test

`src/scenarios/strand-formation-e2e.integration.ts > E2E Strand Formation > Phase 2: Strand instance lifecycle > should form strand, start instances, and replicate data`

Error excerpt:

```
× should form strand, start instances, and replicate data 15241ms
   → Timeout waiting for data replicates from Alice to Bob after 15000ms
```

## Why this is pre-existing (not caused by this ticket)

I ran this test only as a diagnostic while implementing
`1-integration-tests-rbac-signed-write-coverage`. It fails at HEAD on `master`
**before** my edits, and lives in a file/subsystem my diff does not touch
(`strand-formation-e2e.integration.ts`, plus the strand cohort/mode-selection path).

Root cause: a two-`CadreNode` strand formed in these tests has no `CadrePeer` rows in
its control DB (control-sync is not yet wired), so `selectStrandMode` infers
`bootstrap` (local transactor) instead of `networked`. In bootstrap mode each node has
an independent local DB and writes never replicate, so the cross-node replication wait
times out. This is the exact gap owned by the **already-filed** ticket
`2-integration-tests-real-control-sync-and-scenario-honesty` (and the related
`formationinvite-fix-curve-and-wire-consent`).

## Work-around used to complete my ticket

My new scenario (`rbac-signed-write.integration.ts`) does **not** hard-assert cross-node
replication for the same reason. It asserts the sApp RBAC accept/reject behavior locally
on the writer (which is the deliverable and is mode-independent) and treats cross-node
replication as a logged best-effort observation. No production code was changed to
side-step the failure.
