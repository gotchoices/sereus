# Pre-existing failures found while reviewing `joining-machine-writes-before-first-sync-fork-tables` (2026-09-16)

Every failure below reproduces against the linked `../optimystic` at commit `6302f2e8` (the `same-named-tables-in-two-schemas-share-storage` fix, rebuilt and consistent per the optimystic session); `../quereus` is clean at `ff1c619c6`. The optimystic session (`optimystic-4e`) has taken the first group as its own highest-priority fix: its change keys the schema catalog by schema and table and restores each table into the schema it was declared in on restart, which is the shape of every failure here. None of these tests touch the first-sync gate, and `discovered-strands-late-subscriber` was green for the implementer on 2026-09-16 before that rebuild.

## 2. Store written by the local transactor reads back empty through the network transactor (1 test, cadre-core)

- `test/strand-transactor-handover.spec.ts` — "reads and appends, through the network transactor, a store the local transactor wrote": `expected Set{} to deeply equal Set{ 'gen1-a', 'gen1-b', 'gen1-c' }`.

Why pre-existing: the optimystic rebuild states that data written under the old collection location (`tree://default/<table>`) is not read by the new keying (`tree://default/<schema>/<table>`) and that a re-declared table starts empty; this test writes with one transactor and reads with another over the same raw store, which is exactly that path. The gate ticket does not touch transactors.
