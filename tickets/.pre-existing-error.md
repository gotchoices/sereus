# Pre-existing failure: linked `@optimystic/quereus-plugin-crypto` `digest()` API drift

## Commands run (from `packages/cadre-core`)

```
yarn build      # tsc -p tsconfig.build.json
yarn typecheck  # tsc -p tsconfig.typecheck.json --noEmit   (includes test/)
yarn test       # vitest run
```

## Symptom

`yarn build` / `yarn typecheck` fail with the same error across many files:

```
src/control-database.ts(25,55):       error TS2554: Expected 1-3 arguments, but got 4.
src/device-token.ts(38,43):           error TS2554: Expected 1-3 arguments, but got 4.
src/peer-authorization.ts(17,43):     error TS2554: Expected 1-3 arguments, but got 4.
src/peer-record.ts(56,43):            error TS2554: Expected 1-3 arguments, but got 4.
src/seed-bootstrap.ts(430,59):        error TS2554: Expected 1-3 arguments, but got 4.
src/seed-bootstrap.ts(643,61):        error TS2554: Expected 1-3 arguments, but got 4.
src/strand-membership-writer.ts(50,55): error TS2554: Expected 1-3 arguments, but got 4.
src/strand-membership-writer.ts(71,59): error TS2554: Expected 1-3 arguments, but got 4.
... (also test/seed-bootstrap.spec.ts: 134, 172, 199, 471, 930)
```

`yarn test` (full cadre-core suite): **112 failed | 393 passed | 41 skipped (546)**, across 17
spec files. Every failure is the same root cause:

```
Error: Unsupported output encoding: utf8
 ❯ resolveOutputEncoder ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:129:9
 ❯ digest                ../../../optimystic/packages/quereus-plugin-crypto/src/crypto.ts:324:56
 ❯ generateStampId       src/control-database.ts:25:22   (digest(peerId,'sha256','utf8','bytes'))
```

Breakdown of the 112: 94 direct `Unsupported output encoding: utf8`, 1 assertion that received
that error instead of its expected throw, and 2 `bootAuthorityNode` helpers
(`device-token-registry.spec.ts`, `peer-record-resolution.spec.ts`) whose node is `undefined`
because `node.start()` → `insertAuthorityKey` → `digest(...,'utf8',...)` threw during setup.

## Why it is pre-existing (not from this ticket)

This ticket (`control-protocol-stream-read-timeouts`) only touches the control-network stream
readers: `control-stream.ts` (new), `strand-wake-protocol.ts`, `seed-bootstrap.ts` (handler +
config only), `strand-formation-protocol.ts`, and three test files. **None of these call
`digest`.**

The failing call sites are in files this ticket never edits — `control-database.ts`,
`device-token.ts`, `peer-authorization.ts`, `peer-record.ts`, `strand-membership-writer.ts` — and
in `seed-bootstrap.ts` the two erroring lines (430, 643) are the *pre-existing* `createSeed` /
`validateSeedSignature` `digest(seedJson,'sha256','utf8','base64url')` calls, unchanged by this
ticket.

Root cause is a **workspace-link drift**: the root `package.json` `resolutions` links
`@optimystic/quereus-plugin-crypto` to `../optimystic/packages/quereus-plugin-crypto`. That sibling
workspace's `digest` has changed shape — its `.d.ts` now declares
`digest(fields: readonly DigestField[], algorithm?, encoding?)` (1-3 args) and its runtime rejects
`'utf8'` as an output encoding — while all of Sereus still calls the old 4-arg form
`digest(data, algorithm, inputEncoding, outputEncoding)`. So the whole Sereus monorepo, not just
cadre-core, is affected wherever it hashes.

## Work-around applied for this ticket

None needed and none applied. The new code is type-clean and lint-clean:

- `yarn typecheck` reports **zero** errors other than the `digest` 4-arg drift (verified by
  filtering them out — 0 remaining).
- `yarn lint` (eslint) passes on every touched file.
- vitest uses esbuild (no type-check), so it runs regardless of the `tsc` break. The protocol
  specs this ticket adds/affects all pass:
  - `strand-wake-protocol.spec.ts` — fully green (incl. new read-timeout / concurrency-cap /
    dialWake-abort tests).
  - `strand-formation-protocol.spec.ts` — fully green (after the shared-primitive refactor).
  - `seed-bootstrap.spec.ts` — the **new** `handleSeedStream` read-timeout + concurrency-cap tests
    pass; the 16 failures in that file are all the pre-existing crypto-dependent ones above.

A fix likely belongs in `../optimystic` (restore/adapt the `digest` signature + `utf8` support) or
a coordinated migration of every Sereus `digest(...,'utf8',...)` call to the new crypto API. Either
is well outside this ticket's stream-timeout scope.
