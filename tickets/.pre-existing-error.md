## Why this is pre-existing

**Measured, not inferred.** The working copy of `packages/cadre-core/src/cadre-node.ts` was
temporarily replaced with its `HEAD` content (and the new `src/peer-addr-book.ts` removed), the
two specs re-run, and then the ticket's files restored. At `HEAD`, with none of the ticket's
changes present, both tests fail with the **identical** counts — 1983 and 1979 — and identical
per-method fingerprints. So the regression is already on `master`.

Corroborating: both specs are solo-node scenarios (no `authorizePeer`, no siblings), and the
ticket's change only adds work *after* `runReconcileControlCohort`'s `siblings.length === 0`
early return, so it cannot add a storage operation in either scenario.

The shared per-method fingerprint across the two specs (`listPendingTransactions 270/6`,
`listRevisions 264/3`, `getMaterializedBlock 264/3`, `getPendingTransaction 121/6`, identical
save counts) points at one change below cadre-core — the `resolutions`-linked `../optimystic` /
`../quereus` workspaces — rather than at anything in this repo's control code. The budgets were
last re-measured 2026-08-12 / 2026-08-13; the jump is ~+29% on both.

Related but **not** the same record: `tickets/blocked/optimystic-block-read-amplification-on-control-start.md`
(which the assertion message names) is about the standing amplification the budget was set
*around*; this is a fresh step over that budget, and neither spec is listed in
`tickets/.pre-existing-known.md`.
