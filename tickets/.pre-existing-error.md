# Pre-existing test failures (not caused by `cadre-digest-variadic-libs`)

## Command

```
yarn workspace @serfab/cadre-core test
```

Result: **2 failed | 554 passed | 1 skipped (557)**. The two failures are both
self-described "KNOWN GAP" time-bomb tests that assert an optimystic/quereus
**platform** limitation still exists; they fail the moment the platform starts
enforcing it. The linked `../../../quereus` (+ optimystic) workspace has evidently
closed both gaps, so the gap-pinning assertions now fail.

## Failing tests

1. `test/strand-membership-invite.spec.ts > consumeInvite > KNOWN GAP: a double consume currently overwrites instead of rejecting (PK uniqueness not enforced)`

   ```
   AssertionError: promise rejected "ConstraintError: UNIQUE constraint failed… " instead of resolving
   Caused by: ConstraintError: UNIQUE constraint failed: ConsumedInvite.InviteKey
   ```

   The test asserts the second `consumeInvite` RESOLVES (overwrites) because the
   platform does not enforce primary-key uniqueness on insert. The platform now
   enforces it, so the second insert is rejected. The test comment says verbatim it
   will "fail loudly the moment the platform starts enforcing PK uniqueness on
   insert" — filed as backlog `optimystic-insert-pk-uniqueness-not-enforced`.

2. `test/strand-membership-peer-rotation.spec.ts > removeAuthority > KNOWN GAP: a non-authority removal currently SUCCEEDS (deferred CHECK not enforced on delete)`

   ```
   AssertionError: promise rejected "QuereusError: CHECK constraint failed: Au… " instead of resolving
   Caused by: QuereusError: CHECK constraint failed: Authorized
   ```

   The test asserts a non-authority's `removeAuthority` RESOLVES because the
   optimystic bootstrap transactor evaluates deferred CHECKs only on insert, not on
   delete. The platform now evaluates the deferred `Authority.Authorized` CHECK on
   delete, which correctly rejects the non-authority's invalid signature. The test
   comment says verbatim it will "fail loudly the moment the platform starts
   enforcing delete-side constraints" — filed as backlog
   `optimystic-deferred-check-not-enforced-on-delete`.

## Why these are pre-existing (not caused by this ticket)

This ticket only changed `verify(digest(...))` expressions (4-arg/3-arg → variadic)
and the TS bytes their signers produce. It did NOT touch PK declarations or any
`check on ... delete` clause.

- Failure 1 is a PK-uniqueness rejection that involves **no digest/verify at all**
  (`ConsumedInvite.InviteKey text primary key`, unchanged by this ticket), so it is
  definitively independent of the digest migration.
- Failure 2 is the deferred `Authority.Authorized` CHECK now *running* on delete.
  Whether that CHECK runs on delete is a platform decision (the `check on insert,
  update, delete` clause is unchanged here); the non-authority signature is invalid
  under both the old and new digest forms, so the result (reject) is the same
  regardless of this migration.
- The platform lives in the resolutions-linked `../../../quereus` / optimystic
  checkout, whose state is independent of this ticket; these gap-pinning tests were
  already failing against that checkout at HEAD before these edits.

Every happy-path signed strand operation in those same two spec files passes
(24/25 and 13/14) against the migrated schema, as do the drift guards
(`control-schema-drift`, `strand-schema-drift`), the new
`digest-variadic-parity.spec.ts`, and `control-authorization-binding.spec.ts` — so
the digest TS↔SQL byte-parity this ticket migrated is intact.

## Work-around applied

None. The two tests were left untouched. Per their own comments the correct fix is
to flip the assertions to `rejects.toThrow()` + unchanged row counts (the platform
gaps are now closed); that belongs to the platform-gap-closure follow-ups, not this
digest-migration ticket.
