What did change underneath the suite: the stale-build guard required rebuilding `@optimystic/db-p2p` from `../optimystic` (per the ticket's working note), and that build picked up the 2026-09-14 optimystic commits `a7686808` / `d9acf8ed` (`debt-libp2p-interface-version-drift-guard`), which touch `packages/db-p2p/src/storage/block-latch.ts` and `libp2p-node-base.ts`; `db-core`'s dist had already been rebuilt at 22:16 the same day by the optimystic runner. The counts halved across every phase (cold start 169 → 45, solo launch 168 → 78, warm restart within budget), consistent with an upstream amplification improvement, not a sereus regression. Confirming step for the triage agent: run the two specs on `master` at `8280a46` with the same freshly built optimystic packages; if they fail there too, re-measure and tighten both budgets (the specs' own instructions) rather than widening the floor.
