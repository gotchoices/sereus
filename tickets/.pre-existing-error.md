## Why this is pre-existing

Measured A/B on 2026-07-29, 10 runs per arm, same test file both arms, only
`packages/cadre-core/src/cadre-node.ts` swapped (`yarn workspace @serfab/cadre-core build`
between arms):

| `cadre-node.ts` | passes | failure shapes |
| --- | --- | --- |
| baseline `548236e` (before the control-stream-authz chain) | 7/10 | 2× replication timeout, 1× `stale revision` / stream reset |
| current `HEAD` | 8/10 | 2× `PartialCommitError` (`stale revision` / stream reset) |

The baseline arm has no per-stream control-DB gate at all and fails at the same
rate with the same underlying errors, so the race is not caused by that work. The
failing runs contain **zero** `authorizeInboundControlStream: DENYING` lines under
`DEBUG='sereus:cadre:*'`. The stack bottoms out in
`../optimystic/packages/db-p2p/src/repo/cluster-coordinator.ts` — outside this
repo's diff.

Not covered by anything in `tickets/.pre-existing-known.md`. The older tracker
`control-db-convergence-optimystic-p2p` is finished and archived in
`tickets/complete/0-control-db-convergence-optimystic-p2p.md`; it fixed the
*replication* root cause, not this residual 3-node commit race.

No test was skipped, disabled, or loosened.
