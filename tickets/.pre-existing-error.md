## Why it is pre-existing

**The module it cannot resolve was already in the bundle graph before this ticket's changes.** `p2p-fret` is imported by `../optimystic/packages/db-p2p/.../cluster/rebalance-monitor.js`, which `@optimystic/db-p2p`'s index re-exports (`index.ts:38`). That index was already imported at runtime by `@optimystic/db-p2p-storage-rn`'s `leveldb-storage.ts` and `leveldb-kv-store.ts` — the modules the kit's `LevelDBEdgeStorage` imported **before** this ticket — and by `@serfab/cadre-core`'s `cadre-node.ts` (`createLibp2pNode`), which every path through `createPhoneNode` reaches. This ticket changed which symbols `packages/cadre-rn/src/phone-node/leveldb-storage.ts` imports from the same two packages; it did not add `@optimystic/db-p2p` or `rebalance-monitor` to the graph.

**The cause is a path spelling, not code.** The junction `C:\Projects\optimystic\packages\db-p2p\node_modules\p2p-fret` stores the target `C:\Projects\Fret\packages\fret` (capital F). `packages/reference-app-rn/metro.config.js` passes `linkedRoots` built with `path.resolve(__dirname, '../../../fret')`, which is the string `C:\Projects\fret` — and `fs.realpathSync.native('C:/Projects/fret')` confirms the on-disk spelling is lowercase. The directory is the same one on this case-insensitive volume, but the two strings differ, so Metro does not see the symlink's target as inside a watched root and reports the module as unresolvable. That is the same class as `tickets/complete/linked-sibling-loaded-under-two-path-spellings.md`, here in Metro's watch-folder matching rather than Node's module cache; `metro.config.js`'s own comment predicts this exact message when a portaled sibling's root is not covered.

**Nothing in this ticket's diff touches Metro config, the sibling links, or `p2p-fret`.**
