GitHub #51 (kjeib, Sereus Health), with a proposed patch in the issue body (`gh issue view 51`). Hermes on bare React Native has neither `TextDecoder` nor `structuredClone`, so `polyfills/hermes.js` installs both. Measured by the reporter on a Galaxy S7 (debug build, solo strand, one log entry of 1 row plus 3 child rows): 7.1–7.7 s per write. A CPU profile attributes 6.6 s of `TextDecoder.decode` and 3.2 s of `structuredClone` over two writes, out of 21.8 s of busy JS time. Optimystic decodes every block it reads from storage (`raw-store-codec` `decodeJson`), and db-core clones each block it reads or updates.

## Causes

- **`TextDecoder.decode`** appends one character at a time (`str += String.fromCharCode(b)`), which Hermes runs slowly on multi-KB JSON. It also mis-decodes invalid input because it never checks continuation bytes: a truncated `F0 9F 98` decodes as a full emoji, `E2 41` swallows the `A`, `C0 80` becomes NUL, and a lone `FF` becomes two surrogates. The WHATWG decoder (and Node's) returns U+FFFD in each case.
- **`structuredClone`** sends every call to `@ungap/structured-clone`, which serializes to an intermediate record list and deserializes it. That is several times slower than a direct copy for the plain JSON-shaped data db-core clones.

## Required behaviour

- **Decode** matches the WHATWG UTF-8 decoder with replacement (`fatal` false): one U+FFFD per maximal invalid subpart; overlong forms, surrogate code points and values above U+10FFFF are invalid; a truncated sequence at the end gives one U+FFFD; a leading BOM is stripped. Output is built in chunks (code units into a fixed `Uint16Array`, flushed with `String.fromCharCode.apply`), with a fast path for a leading ASCII run. The constructor, the UTF-8-only `RangeError`, and the `encoding`/`fatal`/`ignoreBOM` fields stay as they are.
- **Clone** copies directly, following the structured-clone algorithm, for: primitives, plain objects (prototype `Object.prototype` or `null`; own enumerable string keys; result is a plain object), arrays (holes preserved), the standard typed arrays, `ArrayBuffer`, `DataView`, `Date`, `RegExp`, `Map` and `Set`. Shared references and cycles are preserved, including several views over one buffer. Any other value anywhere in the graph (class instances, `Error`, boxed primitives, typed-array subclasses such as `Buffer`, functions, symbols), or a call that passes an `options` argument, sends the **whole** original value to `@ungap/structured-clone`, as today.
- Both blocks stay guarded by `typeof globalThis.X` checks, so an engine that has the native API keeps it.

The reporter's patch implements all of this and reports these results: 200,024 decode inputs matching Node's native `TextDecoder` (edge cases plus 200k random byte strings biased to UTF-8 boundary bytes), 23 clone cases matching native `structuredClone`, the same vectors passing on the Hermes CLI, and S7 write times of 1385–1622 ms. Use it as the starting point, but review it as you would any code, against the rules in AGENTS.md (tabs, comment density, no swallowed exceptions; the clone's internal `UNSUPPORTED` sentinel is control flow by exception, so judge whether a returned sentinel reads better). Credit the reporter in the release notes.

## Edge cases & interactions

- **Surrogate pair straddling a flush.** The code-unit buffer is `CHUNK + 1` long so a pair written at position `CHUNK - 1` fits. Verify with a test vector longer than 4096 code units made of 4-byte sequences.
- **Shared module-level buffer.** `decode` is synchronous and never re-entered, so one `Uint16Array` per module is safe. Verify by inspection.
- **`String.fromCharCode.apply` argument limit.** At most 4096 arguments per call, well inside Hermes's limit. Verify by inspection.
- **Fallback mid-graph.** An unsupported value found deep in the graph must abandon the partial copy and clone the original whole through ungap, so no half-copied result escapes. Verify with one test.
- **Typed-array subclass** (`Buffer` under Node in the spec): goes to the fallback, not the fast path. Verify with one test.
- **`polyfills/audit.js` / `markPolyfilled`.** The audit list and `boot-check` must still report both as polyfilled. The existing spec covers this.

## Tests

The existing harness in `hermes-polyfills.spec.ts` runs `hermes.js` with the native globals removed. Add one conformance test per polyfill there, comparing against Node's native implementation:

- Decode: a fixed edge-case table (BOM, overlong, surrogates, above U+10FFFF, each truncation, the four cases above) plus a seeded random batch (a few thousand byte strings biased to boundary bytes, fixed seed so failures reproduce) and the straddling-flush vector. Expected output: identical to `new TextDecoder().decode`.
- Clone: shared references, a cycle, two views over one buffer, `Map`/`Set` with object keys, a sparse array, a nested class instance (whole-value fallback) and a `Buffer`. Expected: deep-equal to native `structuredClone` and the same identity relations.

Keep the batch small enough that the spec stays fast (well under a second).
