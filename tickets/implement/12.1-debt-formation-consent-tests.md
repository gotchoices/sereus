## Edge cases to hold (settled design — do not re-open)

- Nonce reuse by the joiner → second insert fails `unique` → surfaces as
  'Formation conflict, retry' with the invite unspent, not a dropped frame.
- ValidationUrl invite needs BOTH signatures, over the same nonce + same
  canonical disclosure bytes.
- `redeemInvitation` runs its two inserts with deferred CHECKs; `PeerConsented`
  has no subquery so it is NOT deferred — confirm it evaluates correctly inside
  that transaction.
- Concurrent redemptions of one multi-use invite: loser's consent signature
  must stay re-presentable under a new use number (free-nonce property) — do
  not bar it.
- `FormationAbortedError` / settle-grace paths unchanged; a consent-check
  rejection is an ordinary `approved: false`, never an abort.
- Listener consent pre-check runs for ALL responder configs (including
  provisioner-only / no-recorder fallbacks) — their tests must send well-formed
  contacts even though those branches write no `FormationUsage` row.
