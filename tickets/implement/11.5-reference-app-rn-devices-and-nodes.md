# Phone reference app: "Devices and nodes"

Core API (from `cadre-node-removes-a-machine`): `CadreNode.listMachines()`, `planMachineRemoval(peerId)`, `removeMachine(peerId, { revouch })`, `listCadreInvitations()`, `withdrawCadreInvitation(key)`. Kit (from `phone-kit-forgets-a-cadre-that-removed-it`): `PhoneNodeStatus` `{ state: 'removed'; partyId; removal; formerPartyId? }`.

## Section

New `src/machines-section.tsx`, shown in Settings while connected, below "Add a device or app" (same `Section` / `controlStyles` components as `add-device-section.tsx`).

- **List.** One row per `CadreMachine`:
  - Title: kind from `profile` — "App" (`'transaction'`), "Always-on node" (`'storage'`), "Machine" (null: not published yet) — plus "(this device)" for `isSelf`.
  - Facts: "Owner" when `isOwner`; "Last seen" from `lastPublishedAt` (relative time; "never" when null; note in the doc that a running machine re-stamps every 7.5 minutes, so "last seen 3 minutes ago" means running); key fingerprint (`ownerFingerprint(publicKey)` from `node-claim.ts`, else `shortPeerId(peerId)`); "Not trusted here" when `!trusted` (a row vouched by a removed owner and not re-vouched).
  - Owner-only entries (`!isMember`): "Owner key, no machine joined".
- **Pending.** Live invitations targeted at a device (`listCadreInvitations()` → `live && peerId`), as rows "Invited, not joined yet" with **Withdraw**. Open invitations stay in "Add a device or app" (which already lists and withdraws them); do not list them twice.
- **Remove.** Each row except this device has **Remove** (owner devices only; a non-owner sees the list with no actions and one line saying only an owner can remove machines). Tapping it reads `planMachineRemoval` and shows a confirmation modal:
  - What will happen: the machine is removed; "its owner key is removed too" when `removesOwnerKey`; the invitations it could use again are withdrawn (count).
  - **Dependents** (when `removesOwnerKey`): "Devices and owners this machine added" with a switch per entry, on by default, label "Keep". Kept entries go in `revouch`. Explain in one sentence: a device it added stops being trusted unless you keep it here; switch off anything you do not recognise.
  - `ownDependency`: "This device was added by the machine you are removing. After removing it, ask another owner to add this device again."
  - What removal does not do: "It keeps whatever it already copied, including the cadre's shared data. Removing it stops it syncing with this cadre's machines." (The strand gap, `decide-removed-machine-strand-access`, is a library limit; the copy should not overpromise: say "this cadre's machines", not "everything".)
  - Refusals by name: `'self'` → no Remove button on this device's row; a line under it: "To remove this device, use another owner device." `'not-an-owner'` → no buttons. `'last-owner'` → the modal says it cannot be removed because it is the only owner.
  - Confirm runs `removeMachine`; on success, refresh the list; on error, an alert with the message (`removeMachine` throws named errors).
- **Refresh.** On mount, on node change, after every action, and with a Refresh button (as "Add a device or app" does). No polling.

## Removed screen

When the kit's status is `removed` (`use-cadre.ts` follows `onStatus`), Settings replaces the connected view with a card: "This device was removed from cadre `<partyId>` by an owner (`<fingerprint of removal.signerKey>`). Its copy of that cadre has been deleted from this phone." Buttons: **Go back to your own cadre** when `formerPartyId` is set (starts the saved start through the kit), and **Join a cadre** (the existing join section). The hook's state goes to `idle` with an informational message, not an error.

## Use-case wording to document (docs/reference-app-rn.md, new "Devices and Nodes" section after "Adding a Device or App")

- Uninstalled app or stolen phone: Remove it from another owner device.
- Dead always-on node / replacing a host: Remove the old node here, then add the new one with "Add an always-on node" (QR claim). docs/cadre-host.md → "A host lost for good" links here.
- Leaving the cadre from an owner device: another owner removes it; this device cannot sign its own removal.

## Edge cases & interactions

- **List read while the node is stopping or switching party** (`cadre.node` changes): discard results for a node that is no longer current (the pattern the add-device section uses for its standing read). By inspection.
- **Removing a machine that another owner removed meanwhile**: `removeMachine` returns all-false; show "Already removed" and refresh. By inspection.
- **Double tap on Confirm**: guard with a ref as `add-device-section.tsx` does (`mintingRef`). By inspection.
- **A dependent that is itself an owner with its own dependents**: re-vouching it restores its chain; nothing further to show. By inspection.
- **This phone removed while the Settings modal is open**: the status change unmounts the connected view; the modal must close with it. By inspection.
- **Owner-only entry for a key with no machine**: Remove runs the same call; the plan has no `CadrePeer` part. By inspection.

## Tests

None new: the section is UI over core calls that carry their own tests, and its one piece of logic (mapping a plan to modal text) is display wording. If a pure helper grows branching beyond wording (for example choosing which refusal text to show from several fields), one table-driven test for it in the app's existing test folder is acceptable.
