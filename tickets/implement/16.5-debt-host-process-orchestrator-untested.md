# One shared handle-lifecycle contract, run against both the real and the fake orchestrator

## Background

`HostProcessOrchestrator` (`packages/cadre-host/src/orchestrator/host-process-orchestrator.ts`) starts a node as a child process and keeps a record of it, called a *handle*, keyed by a per-spawn id called `dockerId`. `FakeOrchestrator` (`packages/cadre-host/src/donation/__tests__/fake-orchestrator.ts`) is the hand-written stand-in the donated-node unit tests use instead; it starts no processes.

The real class is already tested against a stub child script in `packages/cadre-host/src/__tests__/orchestrator.test.ts`. The fake has its own tests in `fake-orchestrator.test.ts`, each labelled with the real method it "mirrors". Two gaps remain:

- The rule that stopping or removing a `dockerId` the orchestrator does not know is an error (`requireHandle`, which throws `Container not found: <dockerId>`) is asserted for the fake only. The real suite has a single incidental check (`getStats` after a remove).
- The two suites assert overlapping rules in separate code, so nothing fails if the fake and the real class come to disagree.

## Design (settled)

**A shared contract function.** Add `packages/cadre-host/src/__tests__/orchestrator-handle-contract.ts` (not a `.test.ts` file, so vitest does not collect it on its own — same arrangement as `orchestrator-teardown.ts` beside it). It exports one function that registers a `describe` block of cases written once against a small harness interface. `orchestrator.test.ts` calls it with a harness over the real class; `fake-orchestrator.test.ts` calls it with a harness over the fake. A rule one of them stops obeying then fails in that file's run.

```ts
/** What the contract needs from either orchestrator. */
type ContractOrchestrator = Pick<
  HostProcessOrchestrator,
  'createContainer' | 'stopContainer' | 'removeContainer' | 'resolveDockerId'
>;

export interface HandleContractHarness {
  /** A fresh orchestrator. Teardown is the calling file's own afterEach. */
  make(): ContractOrchestrator;
  request(containerId: string): OrchestratorCreateRequest;
  /** Resolve once the spawn named by `dockerId` can be stopped. Real: wait for `isRunning`. Fake: nothing to wait for. */
  started(orch: ContractOrchestrator, dockerId: string): Promise<void>;
  /** Make the next `createContainer` for `containerId` throw. Only called after that container has been spawned once and stopped. */
  failNextCreate(orch: ContractOrchestrator, containerId: string): void;
}

export function describeHandleContract(label: string, harness: HandleContractHarness): void;
```

If `Pick<HostProcessOrchestrator, …>` does not accept `FakeOrchestrator` structurally, type against the existing `DonationOrchestrator` interface in `packages/cadre-host/src/donation/donation-service.ts` instead (both already satisfy it). `resolveDockerId` is optional there, so wrap the pick in `Required<…>`; do not widen with `any`.

**Every re-spawn in the contract stops the first child first.** The real class refuses to start a container whose previous child is still alive (`refuseRespawnOverLiveChild`); the fake does not model that refusal. Writing the contract as create → stop → create keeps both on the path they share. The fake's un-modelled refusal is out of scope (no donation caller re-spawns over a live child).

**The cases** (one `it` each; exact error text `Container not found: <dockerId>` in every rejection):

- A never-issued `dockerId` is rejected by both `stopContainer` and `removeContainer`.
- After `removeContainer(id)` succeeds, a second `stopContainer(id)` and a second `removeContainer(id)` are both rejected.
- After a successful re-spawn of the same container, the first spawn's `dockerId` is rejected by `stopContainer`, `resolveDockerId(containerId)` returns the second spawn's id, and the second spawn can still be stopped.
- Re-spawning one container leaves a different container's `dockerId` stoppable and resolvable.
- After a failed re-spawn, `resolveDockerId(containerId)` still returns the first spawn's id and `removeContainer` of that id succeeds.

**Real harness** (in `orchestrator.test.ts`, reusing its `makeOrchestrator`, `makeRequest`, `waitFor` and file-level `afterEach`, which already tears down through `removeAllNodes`): `failNextCreate` is the existing `sabotageWorkdir` helper — replacing `<rootDir>/<containerId>/storage` with a plain file so the launch throws. That helper is currently local to the `failed launch` describe block; hoist it to file scope rather than copying it.

**Fake harness** (in `fake-orchestrator.test.ts`): `make` is `new FakeOrchestrator()`, `started` resolves immediately, `failNextCreate` sets `failCreate = true`.

**Existing cases.** In `fake-orchestrator.test.ts`, delete `drops only the re-spawned container, leaving another container untouched` — the contract covers it completely. Keep the rest: they also assert the fake's own recording arrays (`stopped`, `removed`) and hooks (`onStop`, `onCreate`, `onSpawned`), which have no real counterpart. In `orchestrator.test.ts`, delete nothing: the overlapping real cases also assert ports, on-disk state and working-directory deletion.

**Comments.** Update the header comments of `fake-orchestrator.ts` (the paragraph saying its contract is pinned by the sibling test file) and `fake-orchestrator.test.ts` to say the rules shared with the real class live in `orchestrator-handle-contract.ts` and run against both.

## Questions from the original ticket, and how they were settled

- **Does any case need a real `cadre-cli` child, and where would a slower suite live?** No new suite. The handle rules are bookkeeping inside the manager and do not depend on what the child does beyond writing its startup token. Behaviour that needs a real `cadre-cli` child is already covered in `packages/integration-tests` (`cadre-host-node-donation.integration.ts`, `cadre-host-owner-node.integration.ts`; see `docs/testing.md`).
- **Parallel safety.** The stub child binds no ports; the port range is allocator bookkeeping only, and each test uses its own temporary root directory. The new cases run inside `orchestrator.test.ts`, so they add no new file-level concurrency.
- **Explicit fake-versus-real cross-check.** Yes — this ticket.

## Not in the contract, deliberately

- `getStats` / `getLogs` on an unknown id: the real class throws, the fake returns empty values. Recorded as a `NOTE:` at the fake's `getStats`; no donation code calls either.
- `reclaimWorkdir` return value for an already-deleted directory: differs, recorded as a comment on the fake's `reclaimWorkdir`.
- `removeContainer` on a still-running child: the real class stops it first, the fake only deletes. Recorded as a `NOTE:` in the fake's `removeContainer`. The contract's remove cases therefore stop before removing, or remove a child whose prior state does not matter to the assertion.

## Edge cases & interactions

- **Windows teardown is asynchronous.** A real re-spawn immediately after `stopContainer` must not be refused as "previous child still alive". `stopContainer` already waits for the process to exit before returning; if a contract case is flaky here, fix the wait in the harness's `started`/stop sequence, not by adding sleeps to the contract. Verified by running the real suite on Windows.
- **`failNextCreate` on the real class needs the working directory to exist**, which is why the interface restricts it to a container already spawned once. Verified by the failed-re-spawn case itself.
- **The failed-re-spawn case leaves a sabotaged `storage` file behind.** `removeContainer` deletes the whole working directory, so the case cleans up after itself; confirm teardown (`removeAllNodes`) reports no surviving process. Verified by the test run.
- **A contract case must not assert anything only one side can satisfy** (ports, files on disk, the fake's `stopped` array). Verified by inspection: the contract file imports neither `node:fs` nor `FakeOrchestrator`.
- **A never-issued `dockerId` on the real class**: `requireHandle` is a map lookup, so any string works; it does not need to decode as `<pid>:<token>`. Verified by the first case.
- **No process leak when a contract case fails midway.** The real harness's orchestrators are created through `makeOrchestrator`, so the existing `afterEach` removes them. Verified by inspection.
