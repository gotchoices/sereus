# Empty environment variables no longer override configured values

## Root cause (confirmed)

`applyEnvironmentOverrides` in `packages/cadre-cli/src/config/loader.ts` treated any *defined*
env var as an override, including an empty string (`FOO=`). Docker Compose's `${VAR:-}` syntax
sets the var to an empty string rather than leaving it unset, so every optional var in
`packages/cadre-cli/docker/docker-compose.yml` (e.g. `CADRE_ENABLE_RELAY=${CADRE_ENABLE_RELAY:-}`)
was reintroducing an empty-string override on every container start — `false` for booleans, `[]`
for lists — even though the operator never set anything.

`packages/cadre-cli/docker/entrypoint.sh` was already correct: it only writes a key into the
generated `cadre.yaml` when the corresponding var is non-empty (`[ -n "$VAR" ]` guards throughout).
The bug was solely in the CLI's env-override pass, which runs *after* the file is loaded and
reintroduced the value the entrypoint had correctly omitted.

## Fix

`packages/cadre-cli/src/config/loader.ts`: the override loop now skips a variable when it is
`undefined` **or** empty/whitespace-only (`value.trim() === ''`), before any per-variable parsing
runs. This applies uniformly to every entry in `ENV_MAPPINGS` (`packages/cadre-cli/src/config/types.ts`)
— scalars, the `_NODES`/`_ADDRS` lists, the `_ENABLED`/`_RELAY` booleans, `CADRE_STRAND_FILTER`,
and `CADRE_PUSH` — since the rule now lives in the loop rather than in each parser branch.

Two parser helpers had their own empty-string special-casing (`parsePushEnv` returned `undefined`
for `''`, `parseStrandFilterEnv` returned `'all'` for `''`); both are now unreachable dead code
given the loop-level skip, so they were removed along with the doc comments describing that old
behavior. Net behavior is unchanged for those two — the loop skip already produces "config file
value stands, or `undefined`/`all` fallback applies downstream" — but now the *file's own value*
is respected instead of being silently clobbered, which is the actual bug fix for cases where a
config file **does** set `strandFilter`/`push` explicitly and Compose independently passes an
empty override.

## Scope check: cadre-host / cadre-provider child-process env

Reviewed `packages/cadre-host/src/orchestrator/host-process-orchestrator.ts` (spawns the CLI as a
child process). It builds the child's env explicitly (`CADRE_STARTUP_TOKEN`, `CADRE_HEALTH_PORT`,
`CADRE_LISTEN_ADDRS`, `CADRE_SEED_TOKEN`, `CADRE_NODE_STATE_DIR`, conditionally `CADRE_OWNER_KEYS`)
rather than blanket-passing every optional var with an empty-string default — it does not exhibit
this bug. The separate, broader question of *ambient* env vars leaking from the host process into
the spawned child (e.g. if the host itself inherited `CADRE_ENABLE_RELAY=""` from its own launcher)
is what `tickets/plan/22-debt-host-child-env-inheritance.md` already tracks; not duplicated here.
