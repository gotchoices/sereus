# Strict plugin-loader settings

Maintainer decision (2026-09-28): **strict**, same as the cadre-cli config file (`cli-config-strict-validation`, complete). A misspelled or ill-typed plugin setting is an error, never a silent default.

## Where things stand

The plugin loader (Quereus `registerPlugin`, `@quereus/plugin-loader`, Quoomb CLI/Web) calls the plugin's default export with a `Record<string, SqlValue>` settings map. Both entry points, `src/plugin.ts` (Node) and `src/plugin-browser.ts` (browser), pass that map to `parseConfig` in `src/parse-config.ts`. Today `parseConfig` reads eight keys with `typeof`-or-default coercion and drops every other key. `transactor` is the one exception: its closed value set is validated, and anything outside it throws. The Node entry reads a ninth key, `storage_path`, itself, outside `parseConfig`. The browser entry ignores `storage_path` without saying so.

What that swallows today: `fret_profile = 'cor'` becomes `'edge'`, `port = '4001'` becomes `0`, `enable_cache = 'false'` stays enabled, `sapp_version = 2` becomes `'1.0.0'`, and `mode` / `transactr` are dropped.

The package manifest (`package.json` → `quereus.settings`) still declares the retired `mode` key. That matters because Quoomb CLI's `.plugin config key=value` already rejects any key the manifest does not list, and Quoomb Web renders its settings form from the manifest. So the manifest is a second allowlist, it has already drifted from the parser, and it still offers `mode` in the UI.

## Design

### One settings table owns every key

`parse-config.ts` holds a single table covering every key the plugin accepts, including the Node-only `storage_path`. For each key it records how to read and check the value. The allowlist is the table's key set, and it is exported (e.g. `PLUGIN_SETTING_KEYS`) so the manifest test below can compare against it. Nothing outside this file reads the raw map any more.

`parseConfig` changes its return type so the platform-only value travels with the typed options instead of being re-read from the raw map:

```ts
export interface ParsedPluginConfig {
	options: StrandConnectionOptions;
	/** Node-only: resolved to a FileRawStorage by `plugin.ts`. */
	storagePath?: string;
}
export function parseConfig(config: Record<string, SqlValue>): ParsedPluginConfig;
```

`StrandConnectionOptions` cannot hold the path itself (its `storage` field is an `IRawStorage`, not a path). The existing NOTE in `parse-config.ts` explains this; keep its point and move it to the new field. This is a breaking change to an exported function, which is acceptable here: AGENTS.md says "no backwards compat yet", and the only callers are the two entry points and `test/plugin.spec.ts`.

### Per-key rules

"Absent" means the key is missing, `null` (SQL NULL), or, for optional string and enum keys, `''`. The empty string has to count as absent because Quoomb Web's text inputs send `''` when a field is cleared, and the manifest's own default for `bootstrap_nodes` is `''`. This matches what `transactor` already does. Absent optional keys take their defaults exactly as today.

| key | accepted when supplied | default when absent |
| --- | --- | --- |
| `strand_id` | non-empty string (required) | error: `strand_id is required` (keep the wording; tests match it) |
| `bootstrap_nodes` | string, comma-separated; empty entries are filtered out as today | `[]` |
| `schema` | string | undefined |
| `sapp_id` | string | `'unknown'` |
| `sapp_version` | string | `'1.0.0'` |
| `port` | number, integer, 0–65535 | `0` |
| `enable_cache` | `true`, `false`, `1`, `0` (0/1 because SQL has no boolean type; existing tests pin them) | `true` |
| `fret_profile` | `'edge'` or `'core'` | `'edge'` |
| `transactor` | `'local'`, `'network'`, `'test'` | left unset (`composeStrand` applies `'network'`) |
| `storage_path` | string | undefined |

Any other key is an **unknown setting** error that names the key and lists the accepted keys. With ten keys, the list is enough, so there is no nearest-match suggestion. The retired `mode` gets a specific message saying it was removed, that a lone node now coordinates for itself, and that `transactor` selects the storage engine. That is one extra branch; it is not a general retired-keys mechanism.

A `bigint`, a `Uint8Array`, or a string where a number belongs is ill-typed. Do not coerce `'4001'` to `4001` and do not accept `'false'`. Strict means the value must already have the declared type, and Quoomb CLI's `.plugin config` already converts `number` and `boolean` settings to their types before storing them.

### Error shape

Collect every problem in the map, then throw one `Error` whose message starts `quereus-plugin-sereus: invalid plugin settings` and puts one problem per line. Each line names the key, what was accepted (the value set, or the type and range), and what was received, formatted with `JSON.stringify` as `parseTransactor` does today. A string value is cut to about 120 characters (with its length noted) before it is echoed. `schema` holds whole DDL, so a wrong-typed or misplaced value could otherwise flood the message. The cadre-cli review added the same cut to its `describeValue`. Reporting every problem at once matches cadre-cli. `parseTransactor` folds into the table and its own throw goes away. Keep the `transactor must be one of local, network, test` wording inside the problem line, because existing tests match `/transactor must be one of/`.

### Entry points

- `plugin.ts`: `const { options, storagePath } = parseConfig(config)`, and if `storagePath` is set, construct `FileRawStorage` as today. It no longer touches `config.storage_path`.
- `plugin-browser.ts`: if `storagePath` is set (non-empty), throw `storage_path is Node-only; the browser entry stores in IndexedDB`. Today it silently ignores the path, which is the same failure this ticket removes. Update the doc comment that currently says the browser entry "ignores it".

### Manifest

In `package.json` → `quereus.settings`, remove `mode`. Change `fret_profile` and `transactor` to `"type": "select"` with `"options"` listing their values (Quereus's `PluginSetting` supports `select` + `options`, and Quoomb Web renders it as a dropdown). Leave the defaults as they are.

## Edge cases & interactions

- **Empty string on optional keys** (the Quoomb Web cleared-field case, and the manifest default for `bootstrap_nodes`): treated as absent. Verified by the "absent means default" test below.
- **`null`**: absent for every optional key. For `strand_id`, it is the required-key error. Verified by inspection.
- **`port` edge values**: `0` is valid (ephemeral port) and `65535` is valid. `-1`, `65536`, `4001.5`, `NaN` and `Infinity` are rejected. `Number.isInteger` handles the last three. Verified by one test arm.
- **`enable_cache` numbers other than 0/1** (for example `2`): rejected. Today `2` means enabled. Verified by inspection.
- **Several problems at once**: one error that lists them all, including when `strand_id` is missing alongside other problems. Do not return early on the required-key check. Verified by one test.
- **`storage_path` on the browser entry**: rejected when non-empty, accepted when `''`/`null`. Verified by inspection. `browser-shape.spec.ts` loads the browser bundle with `{ strand_id }` only, so it is unaffected.
- **Node entry with `storage_path` of the wrong type** (for example a number): today it is silently ignored and the plugin falls back to in-memory storage. It is now rejected by the table like any other key. Covered by the table, so no separate test.
- **Hosts adding their own keys to the map**: now a load failure. This is the accepted cost of the strict decision. No in-repo host passes the sereus plugin a settings map other than tests (grepped `packages/*/src` for `strand_id`), and Quoomb CLI already refuses keys outside the manifest. State this in the README.
- **Manifest drift**: the manifest and the table must list the same keys, or Quoomb Web will offer a setting the plugin rejects (today's `mode`), or will hide one the plugin accepts. Verified by one test (below).
- **Programmatic API** (`connectToStrand(db, options)`): untouched. It takes typed `StrandConnectionOptions`, and TypeScript already checks that path.

## Tests (in `test/plugin.spec.ts`, `describe('parseConfig')`)

Keep each test to one behaviour. Existing tests change only as follows:

- All existing tests: `parseConfig(...).x` becomes `parseConfig(...).options.x`.
- `should parse fret_profile`: its `'unknown'` → `'edge'` arm becomes a rejection. Merge it into the rejection test below rather than keeping a separate case.
- `should ignore a key it does not know, including the retired mode`: **flip** it to `should reject an unknown key, and the retired mode with a pointed message`. `{ strand_id: 'abc', transactr: 'local' }` throws, naming `transactr`. `{ strand_id: 'abc', mode: 'bootstrap' }` throws, naming `mode` and pointing at `transactor`.

New tests (each pins a branch of the spec above):

- **ill-typed and out-of-set values are rejected, naming the key**: `fret_profile: 'cor'`, `port: '4001'`, `port: 70000`, `port: 1.5`, `enable_cache: 'false'`, `sapp_version: 2` each throw a message containing the key name. Write it as a table-driven `it.each` or one `it` with several `expect`s.
- **absent means default**: `{ strand_id: 'abc', schema: '', sapp_id: null, fret_profile: '', bootstrap_nodes: '' }` parses to the defaults. This pins the empty-string and null rule the Quoomb Web form depends on.
- **every problem reported at once**: `{ fret_profile: 'cor', port: 'x' }`, with no `strand_id`, throws one error whose message mentions `strand_id`, `fret_profile` and `port`.
- **manifest agrees with the parser**: read `package.json` (via `readFileSync` on a path resolved from `import.meta.url`), and check that the `quereus.settings[].key` set equals `PLUGIN_SETTING_KEYS`. This is the class-level guard for the `mode` drift that is already present.

Do not add tests for the entry points' use of `storagePath` (that is wiring) or for each string key individually.
