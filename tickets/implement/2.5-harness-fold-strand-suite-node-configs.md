# Fold the last two private node-config builders onto the shared helper

Second half of the plan ticket `harness-one-node-config-builder` (split 2026-09-08). The
prerequisite ticket carries every harness-side change and the four cheap scenario folds; this
ticket carries the two remaining files, which are separated only because their test runs are long
enough to want their own agent run — `strand-formation-e2e` is 20 tests across 1741 lines and
`strand-membership-closed-strand-e2e` is 9 tests across 1811 lines.

Read the prerequisite ticket for the full rationale. In short: the suite has one shared helper,
`controlNodeConfig` (`packages/integration-tests/src/harness/node-fixtures.ts:131`), and the
private copies of it have already caused one real defect that had to be fixed in four places —
each copy forwarded the caller's relay flag on truthiness, so an explicit `enableRelay: false` was
silently dropped and a storage-profile node kept relaying.

## What is left to fold

files — it should not have, but confirm rather than trust.

| `strand-membership-closed-strand-e2e.integration.ts` | `createTestNodeConfig`, `:190` | 2 — `:510`, `:513` |

Plus the last two copies of the formation mocks, which the prerequisite ticket hoists into
`harness/formation-mocks.ts`: `createMockProvisioner` at `strand-formation-e2e.integration.ts:45`
and at `strand-membership-closed-strand-e2e.integration.ts:177`, and `createMockUsageRecorder` at
`strand-formation-e2e.integration.ts:55`.

Both files' builders are strict subsets of `controlNodeConfig` and share its defaults
(`profile` defaults to `'transaction'`, `strandFilter: 'all'`, `hibernation: false`,
`listenAddrs: ['/ip4/127.0.0.1/tcp/0/ws']`), so unlike `multi-party-workflows` in the sibling
ticket there is no default-flipping trap here. The conversion is positional-to-object:
`createTestNodeConfig(partyId, opts)` becomes `controlNodeConfig({ partyId, ...opts })`.

The closed-strand copy additionally takes a per-node `RawStorageCapture` positionally
(`:190-192`) and uses `capture.provider` as the node's storage provider. `ControlNodeOpts` grew
`storageProvider` under `scenario-strand-follows-a-late-joining-cadre-node`
(`node-fixtures.ts:88`), forwarded verbatim as `storage.provider`, so that becomes
`controlNodeConfig({ partyId, storageProvider: capture.provider, ... })` with nothing left over.
`control-offline-read-after-restart.integration.ts:55` is the worked example of exactly this
shape already in the tree.

## Edge cases & interactions

- **One capture per node.** The closed-strand fixture deliberately gives the founder and the
  joiner separate `captureRawStorage()` captures (`:500-501`, consumed at `:510` and `:513`) so
  each node's blocks are observed independently. Do not collapse them, and do not let the two
  nodes end up sharing one provider — that would make the block-coverage assertions read one
  node's storage twice and pass for the wrong reason.
- **`storageProvider` and `storageOpDelayMs` are mutually exclusive** — `controlNodeConfig` throws
  when given both (`node-fixtures.ts:132-134`). Neither file uses the delay today; keep it that
  way.
- **Positional-to-object conversion is where a silent behavior change hides.** A dropped or
  renamed option produces a node that boots fine and behaves differently. There are nine call
  sites across two files; convert one file at a time and run that file before starting the other.
- **`strand-formation-e2e:829` is the odd call site** — `createTestNodeConfig(`solo-${partyId}`)`
  with no options at all, the only single-node case in the file. It must still come out as a
  transaction-profile node with the default listener and relay left unset, i.e. defaulted by
  `CadreNode` rather than forced off.
- **`createMockUsageRecorder`'s callers mutate `knownTokens` directly** (see
  `strand-formation-e2e:310` and the cases around it), so the hoisted version must keep the
  `FormationUsageRecorder & { knownTokens; usedTokens }` intersection return type. If it does not,
  that is a bug in the prerequisite ticket's hoist — fix it there rather than reintroducing a
  local copy.
- **Every provisioner call site passes an explicit prefix**, so the differing per-file defaults
  (`'test'` here, `'closed'` there) are dead and carry nothing forward.
- **Dead imports are a lint failure, not a nit.** `yarn lint` is fully enforced at `error`. After
  the fold, `MemoryRawStorage`, `wsTransports`, `CadreNodeConfig` and `StrandProvisioner` may all
  be unused — drop them.

## Validation

Build first; `test/global-setup.ts` fails the run outright when a cadre package's `dist` predates
its `src`. Run tests in the foreground with no redirection so the runner's idle timer keeps
getting output.

```
yarn workspace @serfab/cadre-core build
yarn workspace @serfab/integration-tests typecheck
yarn lint
yarn workspace @serfab/integration-tests test src/scenarios/strand-formation-e2e.integration.ts
yarn workspace @serfab/integration-tests test src/scenarios/strand-membership-closed-strand-e2e.integration.ts
```

Run the two files in separate commands, not one — each is long, and a combined run makes it harder
to attribute a failure. Budget: recorded durations in `tickets/.logs/` put a three-test scenario
file at roughly 100-115 s including ~10-30 s of transform and import overhead, so 20 tests and 9
tests are each several minutes. Files run one at a time regardless
(`fileParallelism: false`, `vitest.config.ts:29-30`).

Both suites pass at HEAD, so any failure here is a regression from this change, not a discovery.
If one is already red before your edits, follow the pre-existing-failure procedure — do not skip
or loosen it.
