## Scope

This ticket lands the "install and forget" experience for **the npm-distributed cadre-host**. The standalone single-executable installer (node-sea / .msi / .pkg / .deb / .rpm) is out of scope and tracked separately in `backlog/cadre-host-standalone-binary.md`.

The deliverable is: a user with Node ≥ 20 already installed can run

```
npm install -g @serfab/cadre-host
cadre-host install
```

…and end up with a long-lived service that survives reboot, a populated data dir, a freshly-minted node identity, and a browser tab open on the local UI showing an enrollment QR.

## Design decisions (pinned from plan)

- **Distribution v1: npm only.** Standalone single-exe deferred (see backlog ticket). The CLI is invoked via the npm-installed `cadre-host` binstub. Service-host unit files reference `node` + the absolute path to the installed `dist/bin/host.js`.
- **Install scope v1: per-user.** systemd `--user` unit + `loginctl enable-linger`, launchd `LaunchAgent`, NSSM running as the current user. An explicit `--system` flag is recognized but produces a "system-wide install is a follow-up; see docs" error for v1. (Document this clearly; the security work for running as a dedicated `cadre-host` system user is non-trivial.)
- **Service name:** `cadre-host` on Linux/macOS, `CadreHost` on Windows (matches NSSM convention; mirrors `CadreProvider`).
- **Default data dir** (per platform; XDG/standard conventions):
  - Linux: `${XDG_DATA_HOME:-$HOME/.local/share}/cadre-host`
  - macOS: `$HOME/Library/Application Support/CadreHost`
  - Windows: `%LocalAppData%\CadreHost`
- **Default UI port:** 8765 (same as the existing management-API default).
- **Default libp2p port:** 4001.
- **Identity:** generated at install time via the same primitive cadre-cli uses (Ed25519 via `@libp2p/crypto`); persisted into the data dir under `identity.key` (file mode 600 on POSIX).
- **Service-host unit template parity with cadre-provider:** the units mirror `packages/cadre-provider/service/` so a maintainer can diff them. Both packages share `Restart=on-failure` / `RestartPreventExitStatus=0` (systemd), `KeepAlive.SuccessfulExit=false` + `Crashed=true` (launchd), `AppExit 0 Exit` + `AppExit Default Restart` (NSSM).

### `Installer` surface

```ts
export interface InstallOptions {
  /** If true, all prompts use defaults; --config <path> overrides individual values. */
  nonInteractive: boolean;
  /** Optional path to a JSON config providing wizard answers. */
  configFile?: string;
  /** Override the default data dir. */
  dataDir?: string;
  /** Override the default UI port. */
  uiPort?: number;
  /** Override the default libp2p port. */
  libp2pPort?: number;
  /** Disable UPnP probing on first run. */
  noUpnp?: boolean;
  /** Open browser at end (default true; suppressed by --no-browser or non-TTY). */
  openBrowser?: boolean;
  /** Skip the enrollment-invite step (no QR printed). */
  noInvite?: boolean;
  /** System-wide install — v1 emits a not-yet-supported error. */
  system?: boolean;
}

export interface InstallResult {
  /** Where the wizard wrote the config and data. */
  dataDir: string;
  /** Resolved UI URL (e.g. http://127.0.0.1:8765). */
  uiUrl: string;
  /** Service-host name registered (cadre-host / CadreHost). */
  serviceName: string;
  /** Generated enrollment invite, unless --no-invite. */
  enrollmentInvite?: {
    encodedInvite: string;
    expiresAt: string;
  };
}

export interface UninstallOptions {
  /** Also remove the data dir (default false — preserve trust circle + identity). */
  removeData: boolean;
  /** Skip the confirmation prompt (for scripts). */
  yes: boolean;
}

export class Installer {
  constructor(opts: { platform?: NodeJS.Platform });
  install(opts: InstallOptions): Promise<InstallResult>;
  uninstall(opts: UninstallOptions): Promise<void>;
  status(): Promise<{ installed: boolean; running: boolean; pid?: number }>;
}
```

### Config schema (`<dataDir>/host.config.json`)

```ts
interface HostConfigFile {
  version: 1;
  uiPort: number;             // Localhost-only management UI + API listener
  libp2pPort: number;         // External cadre libp2p port (NAT will map to this)
  dataDir: string;            // Self-reference (handy for service-host unit ExecStart)
  identityPath: string;       // <dataDir>/identity.key
  upnpEnabled: boolean;
  installedAt: string;        // ISO timestamp
  installerVersion: string;   // Package version that wrote this file
}
```

Subsystems (trust-circle, NAT, orchestrator) own their own files under `<dataDir>/`. This file is the wizard's output, **not** an umbrella config — the subsystems are not driven by it. They each read their own files (e.g. `trust-circle.json`, `nat-settings.json`, `orchestrator/state.json`).

### Service-host unit templates

systemd template (`service/cadre-host.service.tmpl`):

```
[Unit]
Description=Sereus Cadre Host
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=@NODE_PATH@ @HOST_JS@ start --no-tui --data-dir @DATA_DIR@
Restart=on-failure
RestartPreventExitStatus=0
RestartSec=5s
Environment=NODE_ENV=production
NoNewPrivileges=true
# User units don't get ProtectSystem/ProtectHome (those are for system units);
# revisit when --system lands.

[Install]
WantedBy=default.target
```

launchd template (`service/com.serfab.cadre-host.plist.tmpl`):

- `Label = com.serfab.cadre-host`
- `ProgramArguments = [NODE_PATH, HOST_JS, "start", "--no-tui", "--data-dir", DATA_DIR]`
- `RunAtLoad = true`
- `KeepAlive.SuccessfulExit = false`, `KeepAlive.Crashed = true`
- `StandardOutPath` / `StandardErrorPath` → `<dataDir>/logs/{out,err}.log`
- `EnvironmentVariables.NODE_ENV = production`

NSSM (`service/install-service.ps1`):

- Resolve `$NodePath` (Get-Command node), `$HostJs` (relative to script), `$DataDir` (from `-DataDir` param).
- `nssm install CadreHost $NodePath $HostJs start --no-tui --data-dir $DataDir`
- `nssm set CadreHost AppExit 0 Exit`
- `nssm set CadreHost AppExit Default Restart`
- `nssm set CadreHost AppRestartDelay 5000`
- `nssm set CadreHost AppThrottle 10000`
- `nssm set CadreHost AppStdout $DataDir\logs\out.log`
- `nssm set CadreHost AppStderr $DataDir\logs\err.log`
- `nssm set CadreHost AppRotateFiles 1`
- `nssm set CadreHost Start SERVICE_AUTO_START`
- Quoting via array-passed args to `Start-Process` to handle `C:\Program Files\nodejs\node.exe` (per the review-stage minor finding on `5-provider-one-shot-shutdown`).

Bundle nothing. The wizard checks for `nssm.exe` on PATH and links the user to `https://nssm.cc/download` if missing (matches cadre-provider's pattern for v1; the standalone-binary ticket will bundle NSSM).

### `start` integration

The `start` subcommand (currently a stub) reads `--data-dir <path>` and the optional `--no-tui` flag. For this ticket, `start` becomes a thin shim that:

1. Loads `host.config.json` from `--data-dir` (env override `CADRE_HOST_DATA_DIR`, finally falls back to the platform default — same resolution `cadre-host install` uses).
2. Loads the identity from `identityPath`.
3. Bootstraps the orchestrator (already implemented), NAT layer (already), trust-circle service (already), and the management-API HTTP listener.
4. Does **not** include the update-check call (that lands in the sibling ticket `6.4.2-cadre-host-update-flow`). Leave a one-line stub: `// TODO(cadre-host-update-flow): kick off checkForUpdate() before serve().`

The local UI itself ships in `6.5-cadre-host-local-ui`. For *this* ticket, the listener only needs to serve the existing `/auth/*` and `/nat/*` endpoints (from sibling tickets). The wizard opens `http://127.0.0.1:<uiPort>/` which will 404 today; that's expected — the UI ticket fills it in.


`--yes --remove-data` for scripted teardown.

### Browser-open

Implemented inline (no `open` npm dep — adds 60 KB and a dependency tree for one line). Use:

- darwin: `spawn('open', [url])`
- linux: `spawn('xdg-open', [url])`
- win32: `spawn('rundll32', ['url.dll,FileProtocolHandler', url])`

If spawn fails (no DE, no xdg-utils, headless), log the URL and continue. Never fail the install on browser-open failure.

### Enrollment invite

After the service is up, the wizard calls the management API at `http://127.0.0.1:<uiPort>/auth/invites` (same as `cadre-host invite`) with label `Install — first device` and TTL `24h`. The response includes an `encodedInvite` string. Render as both:

- ASCII QR code (use `qrcode-terminal` — small, no deps).
- The raw token, so the user can copy/paste if QR doesn't render.

If `--no-invite` is passed, or the user is `--non-interactive`, skip this step.

### Tests

- `wizard.test.ts` — drive `Wizard.run()` with a scripted readline iterable; assert it returns the expected `InstallOptions` for default and override input streams.
- `config.test.ts` — `writeHostConfig(...)` then `readHostConfig(...)` round-trips; reject older `version` values with a clear error.
- `identity.test.ts` — `generateIdentity()` writes a file with mode `0o600` (on POSIX); `loadIdentity()` returns the same `peerId` after a round-trip.
- `paths.test.ts` — XDG variables override defaults on Linux; macOS / Windows defaults match the design above.
- `service-host.test.ts` — render-only tests for each platform that produce the expected unit-file text given the same input. **No `systemctl`/`launchctl`/`nssm.exe` is invoked.** Cross-platform CI doesn't have those daemons available.
- `installer.smoke.test.ts` — drives `Installer.install({ nonInteractive: true, dataDir: tmpdir, openBrowser: false, noInvite: true })` against a fake `ServiceHost` injected via the constructor, then `uninstall(...)`. Confirms the config file and identity end up on disk and the service-host's `install`/`uninstall` were called with the right args.

Cross-platform CI gap to call out in the implement ticket: real service-host registration (`systemctl --user enable`, `launchctl bootstrap`, `nssm install`) is not exercised in CI. Document this in `service/README.md`; manual verification on each platform is required before tagging a release.
