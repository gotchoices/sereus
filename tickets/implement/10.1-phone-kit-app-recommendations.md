# Phone kit: one app recommends another

First of three tickets for "app A links to app B; the user allows B to join before leaving A; B joins A's cadre on first launch". `reference-app-rn-recommends-an-app` (A's side in the reference app) and `reference-app-rn-joins-the-app-that-recommended-it` (B's side) build on this one. **A** is the owner app that recommends; **B** the recommended app. Everything here builds on the same-phone links (`@serfab/cadre-rn/app-link`, docs/architecture.md → "Between apps on one phone").

## The design, and why there is no open invitation

The plan ticket proposed that A mint an **open** owner invitation when the user approves and hand it to B later (through Android's Play Install Referrer, or on iOS when B asks). That invitation would be a bearer credential for an hour, and the Play referrer is a parameter of the store URL, which Google's servers receive and store. Both are avoidable: every way B can reach A on one phone already ends with B opening A with a join request that carries B's peer id and a reply scheme. So A mints nothing at approval time.

- **A records a pre-approval**, not an invitation: "the app at scheme `S` may join party `P`, owner or not, until `T`". When a join request opened as a link arrives whose `reply.scheme` is `S`, A skips its Allow / Deny prompt and mints the ordinary **targeted** invitation for the request's peer id with the approved grant, and answers by link as it does today. The pre-approval is used up by that answer.
- **The referrer and the "opened by" link carry only A's scheme**, which is not a secret. B uses it only to name A in its first-launch question and to open A directly instead of through Android's chooser.
- **What this gives up.** A must be able to mint when B asks (its node connected, as for any link request today), and B always makes one round trip to A. B cannot redeem without visiting A, which on iOS was already the case.

**Rejected:** the ticket's open invitation (bearer credential in the referrer, which Google receives, and in A's storage for an hour); a handoff id in the referrer that B exchanges with A (needs the same round trip to A as a plain join request, and adds a second secret to track).

## Pre-approval store

`src/app-link/recommendation-store.ts`, exported from `@serfab/cadre-rn/app-link`, shaped like `LinkRequestStore` (`link-request-store.ts`): calls serialized per instance through one promise chain, a slot read fault propagates, a malformed record reads as none with one `console.warn`.

```typescript
/** How long a pre-approval waits for the recommended app's request: enough to install it from the store and open it. */
export const RECOMMENDATION_TTL_MS = 60 * 60_000;

/** The user allowed the app at `scheme` to join `partyId` before it asked. */
export interface AppRecommendation {
	scheme: string;      // the recommended app's own URL scheme: what its request's reply.scheme must be
	appName: string;     // the name A showed the user, from A's known-apps list, never from a request
	partyId: string;     // the party A was in when the user allowed it
	grantsOwner: boolean;
	approvedAtMs: number;
}

export class AppRecommendationStore {
	constructor(slot: DurableSlot, now?: () => number);
	/** Record a pre-approval, replacing any for the same scheme. */
	approve(entry: Omit<AppRecommendation, 'approvedAtMs'>): Promise<AppRecommendation>;
	/** The live pre-approvals for `partyId`, newest first, for A's list. */
	live(partyId: string): Promise<AppRecommendation[]>;
	/** Drop the pre-approval for `scheme`, if any. */
	withdraw(scheme: string): Promise<void>;
	/** The live pre-approval for `scheme` in `partyId`, removed as it is returned; null when there is none. */
	take(scheme: string, partyId: string): Promise<AppRecommendation | null>;
}
```

- **One slot, a JSON list**, at most one entry per scheme. Each write drops expired entries and entries for other parties. The list is bounded by the known apps an owner can recommend, so no cap is needed.
- **`take` removes on match.** That makes the pre-approval single-use even if two requests race. If A then cannot mint, the pre-approval is gone and A shows its usual "Could not make an invitation" alert; the user recommends again. This is simpler than restoring the entry, and it fails safe.
- **Party-bound.** An entry for another party is never returned. A that joins another cadre between the approval and the request must not admit B into the new cadre on a consent the user gave for the old one.
- **Slot.** `PhoneNode.recommendationSlot()` over a new `PhoneNodeNames.recommendationsKey` (`'recommended-apps'`), a copy of `linkRequestSlot` (`phone-node/node.ts`: waits for a stop in progress, re-resolves the node-local handle on every load and save). One per install, not party-scoped; the entries carry the party.

## Recommend links

`src/app-link/recommend-links.ts`, exported from the index.

- **`RECOMMENDED_BY_REFERRER_PREFIX = 'sereus-recommended-by:1.'`.** `recommendedByReferrer(ownScheme)` returns that prefix followed by the scheme. `recommendedBySchemeFromReferrer(referrer)` returns the scheme when the trimmed referrer is exactly that prefix plus a non-empty remainder, and null otherwise. Play returns `utm_source=google-play&utm_medium=organic` for an install that no link of ours started, and that reads as null. Matching only the exact token means no query-string parser is needed.
- **`storePageLink(app, platform, ownScheme): string | null`.** `platform` is `'android' | 'ios'` and the app passes `Platform.OS` in, so this file still imports no React Native. Android returns `https://play.google.com/store/apps/details?id=<androidPackage>&referrer=<encodeURIComponent(recommendedByReferrer(ownScheme))>`. iOS returns `https://apps.apple.com/app/id<iosAppStoreId>`, with nothing about A in it, because iOS has no install referrer. The result is null when the app has no store id for that platform.
- **`recommendedByLink(app, ownScheme)`** returns `<app.scheme>://cadre-recommended-by/<ownScheme>`. A opens it when B is already installed, so B learns who recommended it in the same way the referrer would tell it.
- **`parseCadreLink`** (`links.ts`) gains `{ kind: 'recommended-by'; text: <scheme> }` for `<any scheme>://cadre-recommended-by/<scheme>`. It gets its own path constant next to `REQUEST_PATH` and `RESPONSE_PATH`, and the `SCHEME_LINK` alternation is extended.
- **The scheme in either hint is not trusted.** Anyone can build a Play link with any referrer, and any app can open B with any link. B resolves the scheme against its own known-apps list (the kit's list plus its extras) by exact equality, and drops a scheme that is not on it. It also shows the name from its own list, never anything from the link. This is B's side (`reference-app-rn-joins-the-app-that-recommended-it`); the kit README states the rule.

## Known apps gain store ids

- `SereusApp` gains `androidPackage?: string` (Play application id) and `iosAppStoreId?: string` (the numeric App Store id). Today's `KNOWN_SEREUS_APPS` entry, the reference app, has neither; it is not in either store.
- **Config plugin** (`app.plugin.cjs`):
  - `requireSereusApp` accepts the two optional fields. It refuses an `androidPackage` that is not a dotted Java package name (`^[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z][A-Za-z0-9_]*)+$`) and an `iosAppStoreId` that is not 1–12 digits, naming the field, as it does today for `scheme`. The plugin's `KNOWN_SEREUS_APPS` copy carries the same fields; the existing drift test keeps the two lists equal.
  - **Android `<queries>`** gains one VIEW-intent entry per known and extra scheme (`<intent><action android:name="android.intent.action.VIEW"/><data android:scheme="…"/></intent>`). Without it, `Linking.canOpenURL('<scheme>://')` returns false on Android 11 and later, and A cannot tell that B is installed. The entries are idempotent, like `addJoinRequestQuery`, and are added only when `appLinks` is set.

- **Security bullet.** During the hour, any app that sends a request with reply scheme `S` is admitted without a prompt. The answer still goes to `S`, so this is the existing accepted impostor-owner-app tradeoff seen from the other side: an installed app that registers a Sereus scheme. Name that, and keep its revisit condition (web domains, App Links / universal links). The mitigations are the single use, the expiry, the notice A shows, and the targeted invitation then being listed and withdrawable in A.

## Edge cases & interactions

- **Expired entry:** `take` and `live` treat it as absent, and the next write prunes it. Verified by the store test.
- **Clock set backwards:** the entry lives longer than an hour. This is the same accepted case as `LinkRequestStore`; it needs no handling, and is checked by inspection.
- **Re-approving the same app** replaces the entry, so the grant and expiry follow the latest choice. Verified by the store test.
- **Two apps pending:** there is one entry per scheme, and a `take` for one leaves the other in place. Verified by the store test.
- **Party switch:** an entry for party P is not returned for party Q. Verified by the store test.
- **Concurrent `take`s on one instance:** the serialized turns let only one of them return the entry. Checked by inspection, since it is the same chain as `LinkRequestStore`, which its tests already pin.
- **Malformed slot text** (not JSON, a non-array, or an entry with a wrong field type) reads as an empty list and is logged. The next write replaces it. Verified by the store test, in one case.
- **A referrer with extra characters, or `utm_…` text:** reads as null. Verified by a short table.
- **A `cadre-recommended-by` link with an empty remainder:** `parseCadreLink` returns null, as it does for an empty response path. Add it as a row in the existing `parseCadreLink` table.
- **Node codes, invitations, requests and responses** still classify as before. The existing table covers them; re-run it.
- **The plugin run twice** (prebuild after prebuild) adds no duplicate `<queries>` entries. Checked by inspection against `addJoinRequestQuery`'s guard.
- **iOS `LSApplicationQueriesSchemes` cap of 50:** unchanged, because the queried schemes are the same list.

## Tests

- **New** `test/app-link/recommendation-store.spec.ts`, over an in-memory `DurableSlot` and an injected clock. It pins the store's security contract, which branches: `take` returns a live match once and then null; it returns null after `RECOMMENDATION_TTL_MS`, for another party and for another scheme; re-approval replaces the entry; two schemes are independent; a malformed record reads as none.
- **In `app-link.spec.ts`:** add rows to the `parseCadreLink` table for the new link and its empty form, and a short table for `recommendedBySchemeFromReferrer` (the exact token, the organic `utm` text, the empty string, the prefix with nothing after it).
- **No test** for `storePageLink` or `recommendedByLink` (string assembly), for the slot wiring, or for the plugin's new `<queries>` entries. The known-list drift test already covers the copied fields.
