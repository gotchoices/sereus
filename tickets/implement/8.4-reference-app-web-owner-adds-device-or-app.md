# Browser reference app: "Add a device or app" (the owner side)

Split from the plan ticket `reference-apps-join-existing-cadre`. Same flows and wording as the phone app's owner side (`reference-app-rn-owner-adds-device-or-app`; read its "Screen" section for the exact strings, which this ticket reuses). The tab's joining side is `reference-app-web-joins-existing-cadre`, which adds its section to the page built here.

cadre-core calls on the running node (`getCadreNode()` in `cadre-web.ts`): `decodeCadreJoinRequest`, `createCadreInvitation({ peerId?, grantsOwner })` → `{ encoded, reach, invitation }`, `listCadreInvitations()`, `withdrawCadreInvitation(key)`.

## Page

A new route `#/cadre`, nav label **Cadre** (test id `nav-cadre`), component `src/Cadre.svelte`. Home is already 441 lines and holds the strand-formation panel; cadre membership gets its own page. The page's first card is **Add a device or app**; the join ticket adds **Join my existing cadre** above it.

- **Owner check.** The tab founds its own party and runs owner genesis today, so it is an owner unless genesis failed (`getOwnerState().state === 'error'`) or, after the join ticket, it joined as a member. Read it the same way as the phone app: `getControlDatabase().getOwnerKeys()` contains this tab's owner key (`ed25519KeyPairFromLibp2p` of the identity, already derived in `runOwnerGenesis`; keep the public key in a module variable). Not an owner: the one-line member message only.
- **Paste request**: textarea (placeholder `sereus-join-request:1.…`), "Use request", `decodeCadreJoinRequest` (errors shown inline), the self and already-a-machine checks (`queryCadrePeers()`), then an inline approval panel (not a modal): app name with the "check the code" note, short peer id, **Also an owner** checkbox (default on) with its line, Add / Cancel. No camera scanning in the browser; paste only.
- **Copy invitation**: **Also an owner** checkbox (default on), the bearer warning while it is on, "Make invitation".
- **The minted invitation**: QR (below), the text with the existing `Copyable` component, the expiry as a local time, the reach line (same table as the phone ticket), "Done".
- **Outstanding invitations**: `listCadreInvitations()` filtered to `live`; per row target, owner/member, expiry, uses; Withdraw with a `confirm()`; refresh on mount, after mint, after withdraw, and a Refresh button.
- **Reading `expiresAt`**: the row's `invite.expiresAt` is the stored UTC datetime text without a zone; cadre-core exports `parseNullableStoredDatetimeMs` to turn it into epoch ms (the phone app's `add-device-section.tsx` uses it for the minted invitation and each row).

## QR

`src/lib/QrCode.svelte` renders `await QRCode.toString(text, { type: 'svg', errorCorrectionLevel: 'L', margin: 2 })` from the `qrcode` package with `{@html}`. The SVG is generated by the library from our own invitation text (path data only), so injecting it is safe; say so in a one-line comment. Level L for the same reason as on the phone (texts up to about 2,000 characters). When `toString` rejects (too long), show "Too long for a QR code; use copy instead."

Add `qrcode` and `@types/qrcode` (dev) to `packages/reference-app-web` with yarn. Check the production build still passes `test/build-targets.spec.ts`.

## `cadre-web.ts`

Pass-throughs `createCadreInvitation(options)`, `listCadreInvitations()`, `withdrawCadreInvitation(key)`, `isMemberPeer(peerId)`, `isOwner()`, each throwing "CadreNode not started" with no node, like `addChatStrand`. Add the first three to the `__cadre` debug hook only if an e2e needs them (none in this ticket).

## Edge cases & interactions

- A tab with no relay configured has no address (`listenAddrs: []`), and a solo party has no other member: `createCadreInvitation` throws "neither this machine nor any other machine of the party has an address a device could dial". Show "Could not make an invitation" with that detail and, when `getRelayState().status !== 'reserved'`, "This tab has no relay address (set one in the runtime manifest), and no always-on machine of your cadre has one either." By inspection.
- A tab with a relay but no other member: `reach` is `issuer-only` (judged on other machines only); the warning says the new app can join only while this tab stays open. This is the common case for the web app and is correct. By inspection.
- Two same-origin tabs: both open the same node-local database (existing NOTE in `node-local-slots.ts`); minting from either is fine, each writes its own control row. Nothing new. By inspection.
- Withdraw returning `false`: refresh silently. By inspection.
- The tab restarting (Restart on Home) while the page shows a minted invitation: the invitation stays valid; the list reloads from the new node on the next refresh. By inspection.
