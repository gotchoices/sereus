# Phone kit: links between Sereus apps on one phone

First of three tickets that replace the twice-copy-and-paste join between two apps on one phone with one confirmation in the owner app. This one is the shared kit and the request field in cadre-core; `reference-app-rn-answers-join-requests-by-link` (the owner app's side) and `reference-app-rn-asks-owner-app-by-link` (the joining app's side) use it.

Terms used below: **B** is the app that wants to join; **A** is the owner app that holds the cadre. The **join request** and the **invitation** are the existing texts from `docs/architecture.md` → "Handing an invitation from app to app".

## Decisions (settled in planning)

**Links in both directions, on both platforms; no Android activity result.** B opens A with a request link; A answers by opening B's own URL scheme with a response link.
- Why not an activity result on Android: receiving a custom intent action and answering with `setResult` needs a native module, and the kit ships none today (JavaScript, a Metro helper and a config plugin). A result promise is also lost when Android kills B while A is open, which the ticket requires B to survive; a response link reaches a cold-started B like any other link.
- What that gives up: A cannot learn B's calling package (it is reported only to an activity started for a result). The confirmation never relied on it, so nothing is lost for security.

**Android discovery: the request text is the link.** The join request is already a URI (`sereus-join-request:1.<base64url>`). Every Sereus app that opts in registers the `sereus-join-request` scheme, so opening the request shows Android's app chooser with every installed owner app. Bonus: pointing the Android system camera at a request QR code (the paste flow's) opens the chooser too; A then answers on screen as for a pasted request, because that request carries no reply.

**iOS discovery: known schemes plus `canOpenURL`.** iOS has no chooser, and which app opens a scheme that two apps register is undefined, so B opens a specific app at that app's own scheme: `<scheme>://cadre-join-request/<request text>`. B lists the known Sereus apps that `canOpenURL` reports installed, minus itself. Each queried scheme must be in `LSApplicationQueriesSchemes` (iOS allows 50).
- Rejected: per-app universal links. They need a web domain per app with an `apple-app-site-association` file, and B would still need a list of domains; no Sereus app has one today. They are the upgrade path (see Security).
- **How a new Sereus app gets on the list:** add `{ name, scheme }` to `KNOWN_SEREUS_APPS` in this kit (a pull request here and a kit release). Until then an app passes it as an extra (plugin option and runtime argument, below).

**The reply is a custom scheme, never a web URL.** The request carries `reply: { scheme, nonce }`. A builds the answer link itself as `<scheme>://cadre-join-response/<response text>`; it never opens a URL the request supplied. That keeps an invitation (which names the cadre's machine addresses) from being sent to a web server by a request that names `https`.

**B accepts only an answer to a request it has open.** B persists `{ nonce, ownerAppName, startedAtMs }` before opening A, and takes a response only when its nonce matches, once. The record lives in the kit's app-private node-local LevelDB, beside the saved start, so a cold start can take the answer.

## cadre-core: the request's `reply`

`CadreJoinRequest` (`packages/cadre-core/src/cadre-join-request.ts`) gains an optional field:

```typescript
interface CadreJoinRequest {
	v: 1;
	peerId: string;
	appName: string;
	/** Present only on a request opened as a link: where and how the owner app answers. */
	reply?: { scheme: string; nonce: string };
}
```

- Encoded in the same canonical JSON, and only when present, so a request without it encodes exactly as today.
- Both directions refuse (naming the problem): a scheme not matching `^[a-z][a-z0-9+.-]{0,63}$`; a scheme in a named list of web and system schemes (`http`, `https`, `ws`, `wss`, `ftp`, `file`, `content`, `data`, `blob`, `javascript`, `about`, `intent`, `mailto`, `tel`, `sms`); a nonce not matching `^[A-Za-z0-9_-]{16,64}$`.
- The web reference app decodes requests too; it never opens a reply and needs no change.
- Update the request's interface block in `docs/architecture.md` → "The join request".

## cadre-rn: `@serfab/cadre-rn/app-link`

New subpath export (`package.json` `exports`, `dist/app-link/index.js`). No React Native or Expo import: the app passes `Linking.canOpenURL` in, so the module runs under vitest.

```typescript
/** A Sereus app another can open at its own URL scheme. */
export interface SereusApp { name: string; scheme: string }
/** The Sereus apps the kit knows; one entry per published app. */
export const KNOWN_SEREUS_APPS: readonly SereusApp[];   // [{ name: 'Sereus P2P Chat', scheme: 'sereus-chat' }]

export const CADRE_JOIN_RESPONSE_PREFIX = 'sereus-join-response:1.';
export type JoinRefusal = 'denied' | 'no-cadre' | 'not-owner' | 'already-member';
export type CadreJoinResponse =
	| { v: 1; nonce: string; appName: string; invitation: string }   // an encoded `sereus-invite:1.` text
	| { v: 1; nonce: string; appName: string; refused: JoinRefusal };
export function encodeCadreJoinResponse(response: CadreJoinResponse): string;
export function decodeCadreJoinResponse(text: string): CadreJoinResponse;

export type CadreLink = { kind: 'join-request'; text: string } | { kind: 'join-response'; text: string };
/** What an incoming URL is, or null for anything else (a node code included). */
export function parseCadreLink(url: string): CadreLink | null;

/** Android (`ownerApp` null): the request text itself. iOS: `<ownerApp.scheme>://cadre-join-request/<text>`. */
export function joinRequestLink(requestText: string, ownerApp: SereusApp | null): string;
/** `<replyScheme>://cadre-join-response/<text>`; throws above CADRE_LINK_MAX_LENGTH. */
export function joinResponseLink(reply: { scheme: string }, response: CadreJoinResponse): string;
export const CADRE_LINK_MAX_LENGTH: number;   // 32_768

/** The apps in `apps` that `canOpenURL('<scheme>://')` reports installed, minus `ownScheme`. For iOS. */
export function installedSereusApps(apps: readonly SereusApp[], ownScheme: string, canOpenURL: (url: string) => Promise<boolean>): Promise<SereusApp[]>;

export interface OpenLinkRequest { nonce: string; ownerAppName: string | null; startedAtMs: number }
export class UnsolicitedJoinResponseError extends Error {}
export class LinkRequestStore {
	constructor(slot: DurableSlot, now?: () => number);
	/** Open a request, or return the open one unchanged (same nonce) so an answer to an earlier tap still lands. */
	begin(ownerAppName: string | null): Promise<OpenLinkRequest>;
	/** The open request, or null when none is open or it is older than LINK_REQUEST_TTL_MS. */
	current(): Promise<OpenLinkRequest | null>;
	cancel(): Promise<void>;
	/** The decoded response when its nonce is the open request's, clearing the request; else throws UnsolicitedJoinResponseError. */
	take(responseText: string): Promise<CadreJoinResponse>;
}
export const LINK_REQUEST_TTL_MS: number;   // 30 minutes
```

Notes for each piece:

- **Response codec:** canonical JSON behind the prefix, like the request (cadre-core exports `canonicalJson`). `appName` is A's own name, unverified, 1–64 characters, used only in B's messages. `invitation` must start with `CADRE_INVITATION_PREFIX`; B's join decodes it fully. Exactly one of `invitation` and `refused`.
- **`parseCadreLink`:** recognizes only the forms this module builds: a URL starting with `CADRE_JOIN_REQUEST_PREFIX` (Android), and `<scheme>://cadre-join-request/<text>` / `<scheme>://cadre-join-response/<text>` (any scheme, so the second-install variant works). Return the text without decoding it; decoding and refusing is the caller's step.
- **Nonce:** 16 random bytes from `globalThis.crypto.getRandomValues` (the kit's polyfills provide it), base64url.
- **Store:** an empty slot text means no open request (`KvStoreApi` has no delete, so `cancel` and `take` write `''`). A malformed record reads as none and is logged. `take` decodes before it compares the nonce, so a malformed response throws the codec's error and leaves the request open.
- **Link length:** an invitation names at most six machine addresses (`CADRE_INVITATION_MAX_ADDRS`). By reading the `CadreInvitation` shape, a response link is estimated at about 4 KB; this was not measured. Android carries URIs of that size in an intent, and iOS URLs work at that size too. The 32 KB limit is a guard against invitation growth: past it, `joinResponseLink` throws and the owner app falls back to showing the invitation for copy.

**`PhoneNode.linkRequestSlot(): DurableSlot`.** This is a public accessor over a new `PhoneNodeNames.linkRequestKey`, default `'link-join-request'` (dot-free and one per app, like `savedStartKey`). It works with no node running, as the saved-start read does. The app builds `new LinkRequestStore(phone.linkRequestSlot())`.

## Config plugin: `appLinks` option

`["@serfab/cadre-rn", { "appLinks": { "extraApps": [{ "name": "…", "scheme": "…" }] } }]`, or `"appLinks": true`. Without the option, the plugin does what it does today.

- **Android:** add to the main activity a `VIEW` intent filter (`DEFAULT`, `BROWSABLE`) for the scheme `sereus-join-request`. Add a manifest `<queries>` entry for the same intent, so the opening app's `resolveActivity` sees other handlers on Android 11 and later.
- **iOS:** add the schemes of `KNOWN_SEREUS_APPS` plus `extraApps` to `LSApplicationQueriesSchemes`, keeping entries already there. Refuse at prebuild when the total passes 50.
- **Each app's own scheme:** registered by Expo from `expo.scheme`, as today. Every Sereus app needs a scheme of its own; the README says so.
- **The known-apps list exists twice.** The plugin is CommonJS and cannot load the kit's ESM build, so it carries its own copy, exported as a property of the plugin function. The spec below keeps the two copies equal.

## Security (goes in the architecture subsection)

- A link is a request, never a grant: the confirmation in A authorizes. A opens a reply only for a request that arrived as a link, never for a pasted one.
- An invitation that reaches the wrong app is useless, because it is targeted at B's peer id. A hijacked reply scheme therefore leaks the cadre's machine addresses, as any invitation does, not access.
- B takes only an answer carrying the nonce of its open request, once, within 30 minutes. An unsolicited link cannot inject an invitation.
- **Accepted residual risk:** an installed app that registers `sereus-join-request` (Android) or a known app's scheme (iOS) can answer B with an invitation to a cadre of its own, and B would join it and move its chats there. Pasting from the wrong app carries the same risk, and custom schemes give no way to verify the answering app. Record this in the doc as an accepted tradeoff. **Revisit when** Sereus apps have web domains: Android App Links and iOS universal links bind a link to the app's signing identity.

## Edge cases & interactions

- A request without `reply` encodes byte-for-byte as before. Verified by the existing round-trip test still passing unchanged.
- A `reply` naming `https` or with a short nonce is refused both when encoding and when decoding. Verified by a test row.
- `begin` while a request is open returns the same nonce, so the answer to the first tap is still accepted after a second tap. Verified by test.
- `take` with a matching nonce succeeds once. A second take of the same text, a different nonce, an expired request and no open request each throw `UnsolicitedJoinResponseError`. Verified by test: this is the security contract.
- A malformed response text throws the codec's error and leaves the request open. Verified by inspection.
- A slot read that throws (a LevelDB fault) propagates from `current` and `take`. It is not read as "no request", which would drop a valid answer silently. Verified by inspection, following the `DurableSlot` contract.
- `parseCadreLink` returns null for `sereus-join:1.…` (a node code), for `sereus-invite:1.…`, and for an unrelated path, so the app's existing link routing is untouched. Verified by a test table.
- iOS `canOpenURL` rejecting for a scheme missing from `LSApplicationQueriesSchemes`: treat it as not installed and log it once. Verified by inspection.
- `joinResponseLink` above the limit throws a named error. Verified by inspection.
