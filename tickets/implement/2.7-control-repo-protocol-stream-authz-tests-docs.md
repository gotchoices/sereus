## Run-4 findings — upstream contracts VERIFIED (no re-reading needed)

- `inbound-authorization.ts`: deny aborts the stream with
  `UnauthorizedInboundStreamError` BEFORE any frame decode; the remote
  observes only a stream reset (no error frame, deliberately). A SYNC
  predicate short-circuits with no timer. `RepoService.handleIncomingStream`
  runs `authorization.deny` first (service.ts ~287) — before redirect logic,
  decode, everything.
- `ProtocolClient.processMessage` uses ONLY
  `peerNetwork.connect(peerId, protocol, { signal })` — so the scenario's
  `IPeerNetwork` stub is literally
  `{ connect: (peerId, protocol, opts) => libp2pNode.dialProtocol(peerId, protocol, opts) }`
  (cast via `unknown` as needed). The dialing node must have the target in
  its peerstore — a prior `dial(multiaddr)` guarantees that.
- `MessageOptions` = `{ expiration?, signal?, dialTimeoutMs? }`. RepoClient
  drives the whole call off `expiration` (default now+30s) via an
  AbortController whose reason is `Error('RepoClient timeout')`. For the
  deny test pass `{ expiration: Date.now() + 10_000 }` so the rejection
  surfaces fast; the error may be the timeout or a stream-reset error —
  assert `rejects.toThrow()` generically.
- `IBlock` = `{ header: { id, type, collectionId } }` — a synthetic block is
  trivial, e.g. `{ header: { id: 'B1', type: 'TST', collectionId: 'C1' } }`.
  `PendRequest` = `{ transforms, actionId, rev?, policy: 'c' }`;
  `CommitRequest` = `{ blockIds, tailId, actionId, rev }`. `GetBlockResults`
  = `Record<BlockId, { block?, state }>` — absent block ⇒
  `result['B2']?.block` undefined.
- Redirect robustness (resolves run-2's "UNVERIFIED CAVEAT" about cluster
  consensus): `responsibilityK` defaults to 1, so A MAY answer any op with a
  REDIRECT if it deems itself not responsible for the synthetic block key;
  `RepoClient` chases it (max 2 hops). The assertions survive this: the deny
  test is unaffected (gate fires before redirect logic), and for the probe,
  B2 absent wherever the get lands still proves "not written anywhere",
  while B1 present after M's pend+commit proves the probe sees real writes.
  If M's raw pend/commit itself proves flaky under cluster consensus, fall
  back per run-2: positive control = M's `get` returning a decoded response
  + an owner-written row converging to M (as control-db-two-node-convergence
  does).
- Gate topology note for the scenario: only A gates (M and O have no anchor
  → their `admitControlPeerUnconditionally` admits everyone), so cluster
  chatter among M/O and outbound dials from A are all unimpeded; the only
  enforced edge is inbound-to-A, which is exactly what the scenario asserts.
- Integration runner: `yarn workspace @serfab/integration-tests test` runs

  `cd packages/integration-tests && yarn vitest run src/scenarios/<file>`

## Integration-scenario design (from run 2, still the plan)

New file `packages/integration-tests/src/scenarios/control-stream-authz.integration.ts`:
three `CadreNode`s on one party — A (owner, `profile: 'storage'`,
`enableRelay`), M (member: A calls `authorizePeer(M.peerId)` BEFORE M dials,
so A's snapshot holds M — refresh fires inside `authorizePeer` itself, so it
is immediate), O (outsider). `A.createInvite(...)` opens the enrollment
window; O dials and HOLDS an admitted connection (assert via the
`waitForConnection` shape from membership-connection-gater.integration.ts).
Then drive the repo protocol raw with
`RepoClient.create(A.peerId!, peerNetworkStub, '/optimystic/control-<partyId>')`
(client appends `/repo/1.0.0`):
- Positive control (M): pend `{ transforms: { inserts: { B1: block } },
  actionId, policy: 'c' }` then commit `{ blockIds: ['B1'], tailId: 'B1',
  actionId, rev: 1 }`.
- Denial (O): same-shape pend for B2 → `await expect(...).rejects.toThrow()`.
- DB-not-written probe: M's `get({ blockIds: ['B2'] })` → block absent;
  `get({ blockIds: ['B1'] })` → block present (probe control). Service serves
  get with `skipClusterFetch: true` (local read).
- Assert O's connection to A is STILL open after the denied stream (the
  point: connection admitted, stream refused).
- Do NOT make O its own owner / write via O's own control DB (same party id
  ⇒ forked collection history — messy and beside the point).
