Fourth of the `strand-offline-mode` chain. `strand-offline-cadre-core` added `CadreNodeConfig.strandOffline` (`journal: (scope) => IKVStore | Promise<IKVStore>`, `initialMode`). This ticket supplies it from the edge node (the code `@serfab/cadre-rn` and the web reference app both run), and implements the journal for the phone and the browser.

## Decisions

**A platform seam.** `EdgeNodeStorage.offlineJournal?(scope: string): Promise<IKVStore>`: the scope's journal, the same instance for the same scope until `close()`. Optional, because a platform without it gets no offline mode. When the platform has it, the edge node passes `strandOffline: { journal: scope => storage.offlineJournal!(scope), initialMode }` in the config `edge-node/config.ts` builds. It is async because the browser opens IndexedDB asynchronously (the raw-storage side uses `lazyRawStorage` for the same reason).

**The journal lives in the strand's own database.** Upstream's journal keys all start with `optimystic-offline/`, which is in db-p2p's `NODE_KV_NAMESPACES`, and both platform KV stores tag their keys apart from block storage. So a store over the scope's existing database handle cannot collide with blocks, and the queue sits beside the blocks it refers to. One store per strand also means one strand per store, which makes the label (derived from the strand id in `strand-offline-composition`) a second guard rather than the only one.

- **Phone** (`LevelDBEdgeStorage`): `offlineJournal(scope)` returns a cached `LevelDBKVStore(this.database(storagePrefix + scope), '')`. Use one instance per handle: its write group serves unflushed writes from memory, so a second store over the same handle would not see them (the existing comment on `nodeLocalStore` says the same). `close()` closes the journal stores, which flushes them, before closing the databases, as it does the node-local store. `destroyScope(scope)` closes that scope's journal store and handle first; rn-leveldb's `destroyDB` throws on an open database.
- **Browser** (`webEdgeStorage`): `offlineJournal(scope)` opens the scope's database through `strand-storage.ts` (the same handle `openStore(scope)` uses; share it rather than opening a second connection) and returns a cached `IndexedDBKVStore(handle, '')`. `closeStores()` and `deleteStore(scope)` close it as they close the raw storage.
- **NativeScript**: not in this release. `ns-edge-platform.ts` gets no `offlineJournal`, so offline mode is unavailable there (`setStrandOfflineMode` throws `StrandOfflineUnavailableError`). Parked as backlog `feat-strand-offline-mode-nativescript`.
- **Node** embedders of cadre-core set `strandOffline.journal` themselves (for example `FileKVStore` from `@optimystic/db-p2p-storage-fs` in the strand's directory). The always-on programs do not.

Before choosing `''` as the prefix, check whether anything else already builds a `LevelDBKVStore` or `IndexedDBKVStore` over a strand scope's handle, such as a node `kvStore` that db-p2p derives. If something does, reuse that instance instead of building a second one.

**The kit's default.** `EdgeNodeOptions.strandOfflineMode?: 'online' | 'offline'` (default `'online'`), passed through as `strandOffline.initialMode`, and saved in `SavedStart` with the other start options so a background restart keeps it (as in `2-rn-persist-node-start-options`). An app that wants every strand offline-acknowledged sets it once. Per-strand changes still go through `CadreNode.setStrandOfflineMode` and last for the process. Recommended in the doc: an app that turns the mode on should leave it on, because exiting with transactions still queued makes every later commit wait behind them.

## Edge cases & interactions

- **Two strands on one device:** two scopes, two databases, two stores. Inspection.
- **Storage closed while a strand is still up** (the edge node's stop order): the strand databases close before `storage.close()` in the edge node's stop. Read the stop sequence and confirm, because a journal closed under a live queue fails the next commit with the store's error. Inspection.
- **A failed IndexedDB open** inside `offlineJournal`: the promise rejects and the strand build fails (`strand-offline-cadre-core`: a journal that throws fails the build, like a storage provider). Inspection.
- **Saved start from an older build** without the new field: it parses as `'online'`. Inspection of `parseSavedStart`.
- **Dissolve / party removal:** `finishRemoving` keeps strand scopes (its `NOTE:`), and with them the journals. Nothing to change. Inspection.

## Tests

None. Each piece is a constructor call over a handle that already exists, plus option plumbing. The phone and browser paths run in their apps (`strand-offline-reference-apps`), and the cadre-core path runs in the real-network scenario of `strand-offline-mode` with a Node journal.
