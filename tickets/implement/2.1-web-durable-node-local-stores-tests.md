### The fake handle

`kvSlot(handle, key)` (`packages/reference-app-web/src/lib/node-local-slots.ts:36`)
only ever calls `handle.get('kv', key)` and `handle.put('kv', text, key)` at
runtime. The real handle type, `OptimysticWebDBHandle` from
`@optimystic/db-p2p-storage-web`, is `IDBPDatabase<OptimysticWebDB>` where the
`kv` store is `{ key: string; value: string | Uint8Array }`
(`node_modules/@optimystic/db-p2p-storage-web/src/db.ts` lines ~48-51). A
map-backed double covers both methods; cast at the test boundary rather than
widening any production signature:

```ts
class FakeKvHandle {
	readonly store = new Map<string, string | Uint8Array>();
	getError: Error | null = null;

	async get(_storeName: 'kv', key: string): Promise<string | Uint8Array | undefined> {
		if (this.getError) throw this.getError;
		return this.store.get(key);
	}

	async put(_storeName: 'kv', value: string | Uint8Array, key: string): Promise<string> {
		this.store.set(key, value);
		return key;
	}
}

function fakeHandle(): { fake: FakeKvHandle; handle: OptimysticWebDBHandle } {
	const fake = new FakeKvHandle();
	return { fake, handle: fake as unknown as OptimysticWebDBHandle };
}
```

### `kvSlot` unit tests

- round-trip: `kvSlot(handle, 'k').save('hello world')`, then a **fresh**
  `kvSlot(handle, 'k')` (new closure, same backing map) `.load()`s the same
  text back — proves the slot itself holds no state, only the backing map
  does.
- a non-string value already under the key (e.g. `fake.store.set('k', new
  Uint8Array([1,2,3]))`) makes `.load()` resolve `undefined`, not throw (the
  `typeof raw === 'string'` guard at `node-local-slots.ts:40`).
- `fake.getError = new Error('IndexedDB blocked')` makes `.load()` **reject**
  with that error — proves the failure propagates rather than being swallowed
  (this is the property `startCadre`'s "must fail loudly" comment at
  `cadre-web.ts:313-315` depends on).
- a never-written key loads `undefined`.

### `PersistentTrustedOwnerStore` / `PersistentBootstrapPeerStore` integration tests

Import `PersistentTrustedOwnerStore`, `PersistentBootstrapPeerStore` from
`@serfab/cadre-core` (both already exported — see
`packages/cadre-core/src/index.ts` lines 40, 58), and `TRUSTED_OWNERS_KV_KEY`
/ `BOOTSTRAP_PEERS_KV_KEY` from `../src/lib/node-local-slots`.

For `PersistentTrustedOwnerStore` (`packages/cadre-core/src/trusted-owner-store.ts`):
- `.open(kvSlot(handle, TRUSTED_OWNERS_KV_KEY), 'party-1')`, `.trust('owner-key-b64',
  'genesis')`, then open a **second** instance over the same `handle` +
  key/partyId ⇒ `.has('owner-key-b64')` is `true` and `.all()` contains it.
- open with partyId `'party-a'`, trust a key, then open with partyId
  `'party-b'` over the SAME backing map/key ⇒ the second store is empty, no
  throw (the `NodeLocalSnapshot.open` foreign-partyId-cold-starts-empty
  policy, `packages/cadre-core/src/node-local-snapshot.ts` lines ~113-118,
  247).
- `fake.store.set(TRUSTED_OWNERS_KV_KEY, '{not valid json')` then `.open(...)`
  ⇒ empty store, no throw (`node-local-snapshot.ts` lines ~202-208, the
  `JSON.parse` catch).

For `PersistentBootstrapPeerStore` (`packages/cadre-core/src/bootstrap-peer-store.ts`):
same three shapes (`record`/`all` instead of `trust`/`has`/`all`), PLUS one
`BootstrapPeerStore`-specific case: a structurally junk entry (e.g. an
unparseable peer id, or an entry with `addrs: []`) is **dropped**, not
whole-record-discarded — assert a well-formed sibling entry survives
alongside the dropped one (the `unusableEntry: 'drop-entry'` policy,
`bootstrap-peer-store.ts` lines ~106-134, contrasted with the trusted-owner
store's `'discard-all'`).

**Needs a syntactically valid peer id string** for `record(peerId, addrs)` —
`acceptEntry` calls `peerIdFromString(peerId)` (`bootstrap-peer-store.ts` line
~128) and a malformed one is treated as junk. Grep
`packages/cadre-core/test/cadre-node-bootstrap-peers.spec.ts` (a hit for
`12D3Koo` was found via repo-wide grep this session but the file itself was
not yet read) for an existing valid-peer-id fixture to reuse rather than
hand-rolling one — cadre-core's own bootstrap-peer-store tests almost
certainly already have one.
