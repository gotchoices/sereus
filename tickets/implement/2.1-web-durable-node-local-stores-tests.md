## What already landed (do not redo)

`packages/reference-app-web/src/lib/node-local-slots.ts` (new file) exports
`kvSlot(handle, key): DurableSlot` — a `DurableSlot` (from `@serfab/cadre-core`)
backed by one key of the control IndexedDB database's `kv` object store (the
same store `cadre-web.ts` already uses for `party-id` / `identity-first-seen`).
It also exports the two `kv` keys used: `TRUSTED_OWNERS_KV_KEY` (`'trusted-owners'`)
and `BOOTSTRAP_PEERS_KV_KEY` (`'bootstrap-peers'`).

`packages/reference-app-web/src/lib/cadre-web.ts`'s `startCadre()` now, right
after resolving `partyId` and before constructing `CadreNodeConfig`:

```ts
trustedOwnerStore = await PersistentTrustedOwnerStore.open(
	kvSlot(controlHandle, TRUSTED_OWNERS_KV_KEY),
	partyId,
);
bootstrapPeerStore = await PersistentBootstrapPeerStore.open(
	kvSlot(controlHandle, BOOTSTRAP_PEERS_KV_KEY),
	partyId,
);
```

and passes `trustedOwners: { store: trustedOwnerStore }` /
`bootstrapPeers: { store: bootstrapPeerStore }` into the `CadreNodeConfig`.
Both module-scope store variables are nulled in `stopCadre()` alongside the
other module state (`partyId`, `controlStorage`, etc.) — the slot closures
capture the control IndexedDB handle, which `closeStores()` closes on stop.

Two new getters, `getTrustedOwnerStore()` / `getBootstrapPeerStore()`, expose
the module-scope store references (mirrors the existing `getControlStorage()`
getter pattern in the same file) — available if diagnostics ever want to
surface anchor/peer counts, not currently used by any UI.

An IndexedDB read failure during either `.open()` call is NOT caught — it
propagates out of `startCadre()` and fails startup loudly, deliberately unlike
the fail-soft `runOwnerGenesis()` / `reserveRelay()` calls later in the same
function. The two-tabs-last-writer-wins caveat is recorded as a `NOTE:` in
`kvSlot`'s doc comment in `node-local-slots.ts`, and the "no migration, cold-start
once" rationale is a comment at the `startCadre()` call site — both already
written, no further action needed.

## What's missing: test infrastructure + the tests themselves

`packages/reference-app-web` has **no vitest setup at all** today — only
Playwright specs under `e2e/`. `packages/reference-app-rn/vitest.config.ts` is
the pattern to mirror (read it first): a `defineConfig` with a `node`-environment
project targeting `test/**/*.spec.ts`. This package needs only the `node`
project — `node-local-slots.ts` has no DOM/React dependency, so a plain node
environment with a hand-built fake `OptimysticWebDBHandle`-shaped object
(implementing just `get`/`put`, cast at the test boundary — `kvSlot` only calls
those two methods at runtime) is enough; no real IndexedDB needed.
