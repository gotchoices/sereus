# Browser reference app: owner grants

Mirror `reference-app-rn-owner-grants` on the Cadre page's Owner keys card (`OwnerKeys.svelte`, state in `lib/owner-keys.svelte.ts`), with "this tab" for "this device" and Download for Share, as `reference-app-web-owner-keys` did for owner keys. Copy the phone's words from `owner-keys.ts` (the existing `NOTE:` in `owner-keys.svelte.ts` explains the copies).

## The card

- **Add an owner key** and **Make a backup** (owner): the phone's two grant kinds. The backup's view adds **Download** (`sereus-owner-grant-‹name›.txt`, the same Blob-URL handling as the key export). "Make a backup key" (the exported fresh key) goes.
- **Outstanding grants** with **Withdraw** (owner).
- **Redeem an owner grant** (any member tab): paste only; seats the tab's owner slot key (created when empty) and wires it through the store as `importOwnerKey` does, so the other cards re-read.
- **Removal confirmation** lists the grants the key issued.

## Joining

Since `reference-app-web-runs-the-edge-node` the tab joins through the shared edge node (`cadre-web.ts`'s `joinCadre` → `edge.joinCadre`), which takes an owner grant since `machine-invitation-grants-no-ownership`: it joins as a machine and an owner with the tab's owner slot key, moves the strands signed with it, and redeems locally when already running in the grant's party. What is left here is the tab's side: `decodeInvitationForThisTab` (`web-join.ts`) recognizes owner-grant text too and returns either credential, `cadre-web.ts`'s `joinCadre` passes it through, and the Join card's field and `join-flow.ts` lines take either text (the `StrandsNeedOwnerJoinError` sentence says to join with an owner grant from the owner tab's Owner keys). The card's redeem uses the edge node's `redeemOwnerGrant` (`reference-app-rn-owner-grants`).

## Removing the old backup key

With both apps minting backup grants, `addBackupOwnerKey` (`owner-key-flows.ts`) has no caller. Remove it, its export from `cadre-core`'s index, the edge node's pass-through (`EdgeNode.addBackupOwnerKey` in `edge-node.ts`), the phone app's pass-through in `cadre-phone.ts` if `reference-app-rn-owner-grants` left it, the tab's in `cadre-web.ts`, the README lines in `cadre-rn/README.md`, and its tests (`owner-key-flows.spec.ts`, the backup case in cadre-rn's `phone-node/node.spec.ts`); then update the `owner-key-flows.ts` paragraph in `docs/architecture.md` (Owner Keys → "Exporting and importing an owner key": "A backup key is made on …" becomes the backup grant, pointing to the owner-grant section). Run a search for `addBackupOwnerKey` and `BackupOwnerKey` across `packages/` and `docs/` before handing off.

## Edge cases & interactions

The phone ticket's list applies with "tab" for "device". In addition:

- **Download of a backup grant**: nothing goes to `localStorage` or IndexedDB; the Blob URL is revoked as the key export's is. Inspection.
- **A tab replaced (node restarted) while a backup is on screen**: forgotten as the key export is (`forgetIfReplaced`). Inspection.
- **The join with an owner grant rolls back** after the grant was redeemed but the machine admission failed: handled in the edge node (`machine-invitation-grants-no-ownership`); the tab only shows the failure. Inspection.
- **Text that is neither a machine invitation nor an owner grant**: the Join card shows today's decode error. Inspection.

## Tests

- `e2e/solo/owner-keys.spec.ts`: replace the backup-key path with the backup grant: make one, see its warning, QR, text and downloaded file, see it listed under outstanding grants, withdraw it, see the list empty. That pins the user-visible backup path, as the current test does.
- No web unit test for the copied helpers (the existing precedent, recorded in that `NOTE:`).
- If a distributed web e2e already joins a tab by invitation with conversations to move (`e2e/distributed/join-cadre.spec.ts`), switch that tab to an owner grant; do not add a second.
