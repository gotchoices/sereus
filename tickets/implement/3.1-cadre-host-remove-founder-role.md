# Remove the founder role from cadre-host

Second of the `cadre-host-join-a-cadre` chain. Independent of `claim-carries-the-party-id`; `cadre-host-hosted-nodes-join-by-qr` needs both. This ticket deletes; it adds nothing. The grant layer and the donation layer stay as they are here and go in the next ticket.

## Why

Settled with the project owner: owner signing stays on devices people hold (phones, hardware keys), never on a server. cadre-host therefore never holds an owner key and never founds a cadre. A cadre always starts on a phone, and the host joins it. The founder role, where the host spawned an owner node carrying the install's identity key and ran genesis for a party named by `installId`, contradicts that and goes. The backlog ticket `feat-owner-keys-only-on-user-devices` carries the same principle for cadre-cli's `--owner`; cadre-cli is out of scope here and keeps `--owner` (its other users: cadre-cli's own tests, `published-smoke-scenario.mjs`, the reference-app-web notes).

## What goes

Every managed node then holds four ports (health, metrics, TCP, WebSocket); `reclaimWorkdir`'s owner exception goes with it. `childListenAddrs` and the per-node identity (`orchestrator/node-identity.ts`, which imports `installer/identity.ts`) stay.

Strand management asked the owner node, which no longer exists; a hosted node is not an owner and cannot sign a strand removal. ## Edge cases & interactions

- `state.json` from a founder run (an `owner` handle, an `ownerConfig` field): not supported, no branch for it; the version-3 config refusal is the loud failure a founder-era data dir meets first. By inspection.
- A node from an older `state.json` with an `admin` port: `port-allocator.ts` already skips missing keys; an extra key is ignored by the type and never reserved. By inspection.
- `NatService.onNodeAddressesStale` for a node the donation store does not know (none should exist after this ticket): `DonationSupervisor.restart` re-reads the record and leaves an unknown id alone. By inspection.
- Push credentials: unchanged in this ticket. The orchestrator still withholds the push block from a node started with pinned owner keys; `cadre-host-hosted-nodes-join-by-qr` removes pinned keys and revisits that rule.
- The UI's `overall-status` no longer excuses a stopped owner node; with no owner node there is nothing to excuse. The existing test's donor case becomes the only case.
- The `cli-reference.test.ts` guard: every removed command and flag leaves the README reference, and no README heading is left without a command.

## Tests

No new tests. Every change here is a deletion or the removal of a branch; the surviving tests are adjusted, not extended. `cadre-host-bootstrap`, `cadre-host-orchestrator-lifecycle`, `cadre-host-sse-events`, `cadre-host-origin-guard` and `cadre-host-update-notify` must still pass.
