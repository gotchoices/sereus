# The NativeScript lazy storage proxy does not expose `listBlockIds`

`packages/reference-app-ns/src/ns-storage.ts` wraps the real SQLite-backed storage (`SqliteRawStorage` from `@optimystic/db-p2p-storage-ns`) in a proxy class, `LazyNsRawStorage`, because the database open is asynchronous and cadre-core wants a storage object synchronously.

The storage interface (`IRawStorage` in `../optimystic/packages/db-p2p/src/storage/i-raw-storage.ts`) has optional methods that callers detect by checking whether the method exists. `SqliteRawStorage` always has three of them (`sqlite-storage.ts` lines 235-238 re-declare them as always present): `getApproximateBytesUsed`, `listBlockIds` and `getStoreIdentity`. The proxy forwards only `getApproximateBytesUsed` (`ns-storage.ts` line 161). Because the proxy is what cadre-core sees, the other two read as "not supported" on this app.

## Research: both consumers run on the phone

The source ticket left open whether the consumers of `listBlockIds` are active under the phone's `profile: 'transaction'` (`packages/reference-app-ns/src/cadre-phone.ts` line 252). Read from the code, not run on a device: neither consumer is gated on the profile, so both are affected.

- **Peer-join block catch-up (cadre-core).** `PeerJoinBackfill` is created for every stored strand in `packages/cadre-core/src/strand-instance-manager.ts` (line 1016, condition is only `strandStorage && config.backfill?.enabled !== false`) and for the control network in `packages/cadre-core/src/cadre-node.ts` `startControlBackfill` (line 1683, condition is only `controlBackfill?.enabled !== false`). `cadre-phone.ts` sets neither flag. `runCatchUp` in `peer-join-backfill.ts` line 585 returns early with "raw storage does not implement listBlockIds(); backfill is inert" when the method is absent. The strand comment at line 1000 states the purpose: a device that founded a strand alone pushes its blocks to a peer that joins later. On the phone that push never happens; the joiner gets blocks only through read repair as it reads them.
- **Startup seed of the tracked block set (optimystic).** `../optimystic/packages/db-p2p/src/libp2p-node-base.ts` line 1742 seeds the set only when `typeof rawStorage.listBlockIds === 'function'` and a spread-on-churn or rebalance monitor is wired. Spread-on-churn defaults to enabled (line 1368) and cadre-core's node options do not turn it off by profile (the profile only changes `fretProfile` and `arachnode.enableRingZulu`). So after a phone restart, blocks already on disk are untracked by that monitor until touched again.

The wrappers between the proxy and these consumers (`CachedRawStorage`, `KvRawStorage`) copy `listBlockIds` through only when the inner object has it, so adding it to the proxy is sufficient; no other site needs to change.

What would confirm it on a device: `DEBUG=sereus:*` on the phone showing the "backfill is inert" line when a second device connects, and that line disappearing after the fix.

## Change

Add to `LazyNsRawStorage`, in the same form as `listRevisions` / `listPendingTransactions`:

```ts
async *listBlockIds(): AsyncIterable<BlockId> {
	const storage = await this.storage();
	yield* storage.listBlockIds();
}
```

`SqliteRawStorage.listBlockIds` is declared non-optional, so no `?.` or `!` is needed.

So that a later optional method dropped from the proxy is a compile error instead of a silent loss, consider widening the class's `implements` clause to also require the two optional methods it promises, for example `implements IRawStorage, Required<Pick<IRawStorage, 'listBlockIds' | 'getApproximateBytesUsed'>>`. This only guards the named methods; a new optional method added upstream still has to be noticed by a person.

`getStoreIdentity` stays omitted. It is synchronous and its contract (`i-raw-storage.ts` lines 44-69) says the string is fixed at construction and that two storages over different locations must never return equal strings; the real identity (`sqlite-handle:...`) exists only after the asynchronous open. The interface says a backend that cannot honour the contract must omit the method. The consequence of omission is that `withReadCache` (`../optimystic/packages/db-p2p/src/storage/with-read-cache.ts` line 165) falls back to identifying the store by object, which is the documented fallback. Record this as an accepted-tradeoff `NOTE:` in the `LazyNsRawStorage` class comment: what is omitted, why (no open handle at construction), and the revisit condition (two proxy objects over one database being seen to get separate read caches, or the interface allowing a lazily-resolved identity).

## Tests

`packages/reference-app-ns/test/ns-storage.spec.ts` states that one-line delegating methods are not tested individually because the interface types enforce them, and it already covers the lazy-open-then-stream shape once with `listRevisions`. `listBlockIds` has the same shape, so no new test is needed; the type check covers the delegation. If the `implements` clause is widened, that is the guard against regression.
