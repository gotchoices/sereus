# One per-stream guard for every protocol on the control node

## Why

The maintainer decided (2026-10-07, plan ticket `cadre-invite-redeemable-before-the-row-replicates`, option B) that an enrolled member will admit an unknown device's connection and rely on per-stream checks. The connection change itself is the next ticket (`stranger-connections-admitted-provisionally`). This ticket comes first and builds what that change relies on. The condition attached to the decision: the per-stream checks must be enforced by one cross-cutting layer, so a later protocol handler cannot open a hole by forgetting a check.

Today only some protocols check membership per stream, each in its own way:

- the four Optimystic control-database protocols, through Optimystic's `authorizeInboundStream` hook (`CadreNode.authorizeInboundControlStream`, the in-memory snapshot of authorized peers);
- wake and strand-addr, each calling `isAuthorizedMember` inside its handler;
- nothing at all on the five FRET protocols. FRET is the peer-discovery ring Optimystic runs on the control network. A stranger can read a member's neighbour snapshot there, which lists other members' peer ids. It can also announce a snapshot that is merged into the routing table. Strangers reach these today in the windows where the connection gate admits them (open invitations, relay-only admission on storage nodes).

`STRANGER_OPEN_PROTOCOLS` in `membership-connection-gater.ts` is declared but never enforced. The blocked ticket `decide-public-read-only-strand-access` notes it as dead code.

## The classes

```ts
/** What a peer must be to open a stream on a control-node protocol. */
export type ControlProtocolClass =
	/** Any peer. The handler makes its own trust decision in-protocol (seed, formation, cadre-invite). */
	| 'stranger-open'
	/** libp2p plumbing that a stranger's connection needs or that carries no party data. */
	| 'transport'
	/** Authorized members by the voucher-anchored live read (`isAuthorizedMember`). For Sereus application protocols. */
	| 'members'
	/** Authorized members by the in-memory snapshot (`authorizeInboundControlStream`). For anything a control-database read itself depends on. */
	| 'members-snapshot';
```

Why two member classes. FRET and the database protocols serve the reads a live membership check would make. A live read from inside their gate would deadlock into mutual denial, which is why `authorizeInboundControlStream` uses the snapshot today. Wake and strand-addr have no such dependency. They keep the stricter live read they use now, so moving the check does not change who they admit. That matters most for strand-addr's delegate grant, which hands out connection and relay admission. The live read also has no window during `start()` where the node is not yet `_running`, whereas the shared unconditional admissions in `admitControlPeerUnconditionally` do.

Why `transport` is open. Identify, ping, hole punching and AutoNAT run on every connection, including the redeeming device's own. Refusing identify would make the device's identify-on-open treat the member as off-network. What they expose is listen and observed addresses, the protocol list (whose prefix names the party id, which the invitation bundle already carries) and the public key. AutoNAT v1 is understood to dial back only addresses on the requester's own observed IP. That is from memory, not checked: confirm it against the installed `@libp2p/autonat` before writing it down. State this reasoning in the table's doc comment.

## The seam: `control-protocol-guard.ts`

One module owns the class table and the enforcement:

- `controlProtocolClasses(partyId): ReadonlyMap<string, ControlProtocolClass>` is the single declaration. Exact protocol ids, built from `controlNetworkName(partyId)` for the `<P>` ones. `STRANGER_OPEN_PROTOCOLS` is derived from it, or deleted in favour of it. Update `index.ts` exports to match.
- `installControlProtocolGuard(node, { partyId, isMemberLive, isMemberSnapshot })` is called in `CadreNode.start()` immediately after `createControlNode()` returns. That point is inside the bring-up quiet period, so no connection exists yet and no stream can arrive before the guard is in place.
- **Mechanism: intercept the registrar's handler lookup, not each registration.** libp2p dispatches every inbound stream through `components.registrar.getHandler(protocol)` (`libp2p/dist/src/connection.js`, `onIncomingStream`). The guard replaces `getHandler` on the control node's registrar instance with one that returns the registered record with its handler wrapped for the protocol's class. Options are preserved. Cache the wrapper per original handler in a `WeakMap`, so repeated lookups don't allocate. A handler registered at any time, by Sereus, Optimystic, FRET or libp2p, is therefore guarded at dispatch with no sweep and no race.
  - `components.registrar` is not on libp2p's public `Libp2p` type. The test fault injector in `control-write-degraded-cohort-member.integration.ts` already reaches it. Narrow it with a type guard. If the shape is absent (a libp2p upgrade), throw from `start()`, naming the guard. Failing to start is the right outcome: a control node without the guard must not run.
  - Rejected: libp2p's own stream middleware (`libp2p.use`). In the installed libp2p 3.3.11, `onIncomingStream` pushes the handler closure onto the very array `registrar.getMiddleware` returns. Every inbound stream therefore appends another handler call to the stored chain, and outbound streams then run those handlers too. Established by reading the source, not by running it. Don't adopt `use()` while that holds.
  - Rejected: a typed `guard.handle(protocol, class, handler)` registration API on its own. It cannot reach the handlers Optimystic, FRET and libp2p register, and those were the gap.
- **Wrapping per class:**
  - `stranger-open` and `transport`: the original handler, unwrapped.
  - `members-snapshot`: synchronous `isMemberSnapshot(remotePeer, protocol)`, which is `authorizeInboundControlStream`. Deny means `stream.abort(...)` before the handler runs, so nothing is decoded.
  - `members`: `await isMemberLive(remotePeer)` under a deadline. Use a link-derived budget or an existing constant; the lint rule forbids a bare millisecond literal. A false result, a throw or a timeout all deny (fail closed), are logged with peer, protocol and reason, and abort the stream.
  - **A protocol missing from the table is guarded as `members-snapshot` and logged once per protocol at warning level** (`log.error` or the module's equivalent). This is the fail-closed answer to "a later handler forgot to declare": the protocol works for members and refuses strangers until someone classes it. The completeness test below turns that warning into a CI failure.
- Denial is a stream reset with a distinct error, like Optimystic's `UnauthorizedInboundStreamError`. Nothing goes on the wire. Telling a stranger "you are not a member" would confirm membership state to it.

Keep Optimystic's `authorizeInboundStream` wired as it is. The four database protocols are then checked by the guard and again by Optimystic, both with the same predicate (one `Set` lookup). This is not a second policy: removing a working, supported upstream check to reach a count of one would only reduce defence. Say so in one sentence where `authorizeInboundStream` is wired.

## Handlers lose their own membership checks

- `StrandWakeService` and `StrandAddrService` drop the `isMember` option and the checks in `processWakeRequest` and the strand-addr request path. The guard runs the same predicate before their handlers do. Strand-addr's delegate grant stays after the guard: a stream that reaches the handler is from an authorized member.
- Remove strand-addr's `refused` status (`StrandAddrStatus`, `STRAND_ADDR_STATUSES`) and the `refused` `StrandAddrOutcome`. A refused asker now sees a reset, which reads as `unreachable`. Remove wake's "Sender is not a cadre member" reply the same way. No backwards compatibility is kept (AGENTS.md).

## Edge cases & interactions

- **Unclaimed node** (`isAwaitingClaim`). The snapshot class refuses everything there, FRET included; the live class refuses because the member list is empty. The claim seed rides `/sereus/seed/1.0.0` (stranger-open). Verify by inspection that the guard adds no admission ahead of `authorizeInboundControlStream`'s claim check.
- **Cold start, before the snapshot is materialized** (empty snapshot, empty anchor, `!_running`). The snapshot class admits everyone, exactly as the database protocols do today. Unchanged behaviour, so not a new hole. Verify by inspection.
- **Delegate peers.** Refused on every members-only protocol: the snapshot and the live read both exclude them. Covered by the existing `control-stream-authz` delegate test.
- **Configured bootstrap/relay infrastructure.** The snapshot class admits it (shared unconditional admissions); the live class refuses it, as wake and strand-addr do today.
- **A member whose row has not replicated here yet** now gets FRET resets from this node. Today that same peer is already refused at the connection on relay-disabled nodes and dropped after the relay-only deadline on relay-enabled ones, so FRET to it already fails. Watch for ring or cohort regressions: run `control-cohort-auto-convergence`, `control-cohort-three-node-isolation`, `control-cohort-cold-start-retry` and `cadre-invite-any-member`.
- **Wake and strand-addr callers.** A refused caller now sees a rejection or reset instead of `accepted:false` or `refused`. Check `pushWake`'s callers (push fan-out) and `collectStrandAddrs`' consumers (the `outcome === 'answered' || 'empty'` predicate in `cadre-node.ts`). Confirm a reset is handled the way the refusal was: retried on the same schedule, and not mistaken for a malformed reply that ends the attempt.
- **Concurrency caps.** Wake's and strand-addr's handlers keep their concurrency caps. A denied stream never reaches them, so a stranger can no longer use up those slots.
- **Handler replaced at runtime** (`initializeStrandSolicitation` swaps the formation handler; `enableSeedListener` registers later). Covered by interception at lookup. The completeness test exercises the late-registered seed listener.
- **libp2p re-reads `getHandler` for stream limits** (`findIncomingStreamLimit`, `findOutgoingStreamLimit`). The wrapper must return the original `options` object unchanged, so limits stay the same.

## Tests

- **Completeness (new, cadre-core spec).** Start a real `CadreNode` with every conditional protocol on: storage profile so the relay server runs, plus `enableSeedListener()`. Assert every id in the control node's `getProtocols()` has an explicit entry in `controlProtocolClasses(partyId)`. This test fails when a new handler, or an Optimystic, FRET or libp2p upgrade, adds a protocol nobody classed. `cadre-node-seed-trust.spec.ts` shows how to start a node and read `getProtocols()`.
- **Fail closed on a broken predicate (unit, small).** A live-class predicate that throws, and one that never settles, both abort the stream without calling the handler. This is the branching contract; one test table.
- **Stranger probe (extend `control-stream-authz.integration.ts`).** Use the scenario's existing invitation-admitted outsider. Enumerate the member's live `getProtocols()`, keep the ones `controlProtocolClasses` marks `members` or `members-snapshot`, and on each open a stream, write a frame and expect a reset with zero response bytes. A members-only protocol added later is then probed automatically. Then check nothing was written:
  - no repo write landed (the existing pend check);
  - no delegate grant exists for the outsider's announced peer id (`hasDelegateAdmission`);
  - the member's FRET routing table and neighbour snapshot do not contain the outsider after an announce;
  - no strand began waking.
- Update the wake and strand-addr unit tests that pinned the in-handler refusal: delete them; the guard owns it now.
