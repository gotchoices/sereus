## Scope

The browser-facing SPA the server (from `6.5.1`) hosts. Five pages covering the four things a self-host user actually does:

1. **Home / Status** — green/yellow/red dot, node summary, trust-circle size, connectivity at a glance, update banner.
2. **Trust Circle** — list members, invite a friend (modal → QR + token), revoke / re-label.
3. **Connectivity** — port-forward status, DDNS, "Test reachability" button, manual fix instructions.
4. **Nodes** — per-node detail, resource usage, log tail, start/stop/restart.
5. **Settings** — update preference, DDNS config, data-dir display, uninstall instructions.

Bundle size budget: **< 1 MB JS+CSS gzipped**, ideally well under. Svelte 5 + Vite + zero CDN assets at runtime.

## Design decisions (pinned from plan)

- **Framework: Svelte 5 + Vite + TypeScript.** Matches `packages/reference-app-web` (Svelte 5, Vite 6) so monorepo contributors don't context-switch. Runes mode (`$state`, `$derived`, `$effect`) for the reactive status. No SSR — the SPA is mounted by a single `index.html` from `@fastify/static`.
- **Routing.** Tiny hash-router (one ~50-line helper, no external dep). Five routes is too few to pull in `svelte-routing`/`tinro`. Hash routes (`#/`, `#/trust-circle`, `#/connectivity`, `#/nodes`, `#/nodes/:id`, `#/settings`) avoid having to configure SPA fallback rewrites in Fastify.
- **State.** A single `$state`-backed `AppState` module (`src/lib/state.ts`) holds: `status`, `nodes`, `trustCircle`, `connectivity`, `update`. Pages read from it directly. The EventSource subscription mutates the state in place; HTTP responses (GETs on page-enter and on action results) also update it. No store library; runes are enough.
- **Network.** Tiny `apiFetch(path, init)` wrapper in `src/lib/api.ts`. Same-origin (`fetch(path, ...)`), parses `{ ok: false, error }` into a typed `ApiError`. Toast on error (a 5-line component, not a library).
- **EventSource.** One global subscription opened by `App.svelte` on mount, closed on unmount (no unmount in production — the app is one tab). Reconnect on `error` event with a 2 s backoff capped at 30 s.
- **No CDN.** All fonts/icons/assets in the bundle. Use system font stack and inline SVG for the few icons we need (status dot, copy, QR, refresh, gear).
- **No dark-mode toggle.** Honour `prefers-color-scheme` via CSS custom properties only. Cheap, looks polished, zero settings.
- **QR rendering.** Use `qrcode` (npm, ~13 KB minified). The installer ticket pulls in `qrcode-terminal` for ASCII; the SPA needs a real PNG/SVG render. Same package family; small. Render to inline SVG (no canvas / no Image data URL plumbing). Reject pulling in heavier libs.
- **Accessibility (v1).** Semantic HTML, keyboard navigation through the nav and forms, ARIA labels on icon-only buttons, contrast ≥ 4.5:1 by default. Not WCAG-audited.
- **Build wiring.** Vite builds to `<package>/dist/ui/`. `yarn workspace @serfab/cadre-host build` runs `tsc -p tsconfig.build.json && vite build --config ui/vite.config.ts`. The output is consumed by `@fastify/static` (mount added in `6.5.1`). `dist/ui/` is `.gitignore`d but added to the npm `files` glob in `package.json` so it ships in the published tarball.
- **No tray icon in v1.** Defer to v2 — see `tickets/backlog/cadre-host-tray-icon.md`.

### State shape

```ts
interface AppState {
  status: 'loading' | 'ok' | 'warn' | 'error';
  service: { name: string; version: string; uptimeSeconds: number } | null;
  nodes: Array<{ id: string; partyId: string; profile: 'storage' | 'transaction'; status: ContainerStatus; stats?: { cpu: number; rssBytes: number } }>;
  trustCircle: {
    members: Array<{ peerId: string; label: string; addedAt: string; lastSeenAt?: string; self?: boolean }>;
    pending: Array<{ token: string; label: string; createdAt: string; expiresAt?: string }>;
  };
  connectivity: NatStatusSnapshot | null;
  update: { available?: { version: string; releaseNotesUrl?: string }; lastChecked?: string; applyInProgress?: boolean; lastError?: { code: string; message: string } } | null;
  toasts: Array<{ id: string; kind: 'info' | 'error'; text: string; expiresAt: number }>;
}
```

### Page behaviours (use cases the plan calls out)

- **Home** displays `/api/status` summary; banner row at the top if `update.available` is set, with "View" → routes to Settings → Updates section. Connectivity card links into the Connectivity page when `directReachability !== 'reachable'`.
- **TrustCircle**: list + "Invite a friend" button → opens `InviteModal` (label input, optional TTL select), POSTs `/auth/invites`, shows the returned token + QR for copy/share. Per-member context menu: Revoke (confirm) → DELETE `/auth/members/:peerId`. Re-label is out of scope for v1 (the existing `TrustCircleService` has no rename method; flag as a future enhancement in the handoff but don't add to v1).
- **Connectivity** mirrors `cadre-host nat status` data; "Test reachability" → POST `/nat/test`; if `directReachability === 'unreachable'`, show a side panel with the generic manual-port-forward instructions and a "Find your router admin" link to a vendor-list section in `docs/cadre-host.md`. DDNS section: provider picker (from GET `/nat/ddns/providers`), hostname + token fields, "Save" → PUT `/nat/ddns`; "External hostname" toggle if user wants no DDNS but a static IP.
- **Nodes**: list + per-node detail. Detail shows recent stats (poll `/api/nodes/:id` every 5 s while on the page — orchestrator stats aren't pushed yet), log tail (`<LogTail>` fetches initial `/api/nodes/:id/logs?lines=200` then renders all `node-state-changed` events for that id into a refresh hint, with a manual "Refresh logs" button). Stop is gated behind `ConfirmDialog`.
- **Settings**: `updates.autoApply` toggle (PUT `/api/settings`), DDNS provider link (cross-page to Connectivity), data dir as read-only text with a "Copy path" button, uninstall instructions as plain markdown text (link to the README section).

### Bundle target

Rough estimate (gzipped):
- Svelte 5 runtime: ~12 KB
- App code: ~25 KB
- `qrcode` SVG-only: ~9 KB
- CSS: ~4 KB
- Total: ~50 KB. Well under the 1 MB budget.

If a future page needs charts (it doesn't for v1), revisit. No charting lib pulled in.

## Tests

In-package (Vitest, jsdom environment):
- `api.test.ts` — `apiFetch` strips the wrapper on `{ ok: true, data: ... }`, throws `ApiError` with code/message on `{ ok: false, error: ... }`, throws `ApiError('network', ...)` on fetch failure.
- `router.test.ts` — `parseHash('#/nodes/abc')` → `{ route: 'nodes', params: { id: 'abc' } }`; `navigate('#/settings')` updates `location.hash`.
- `events.test.ts` — fake EventSource that throws → backoff goes `2s, 4s, 8s, 16s, 30s, 30s`; reconnects use the new endpoint after manual disconnect.

Component tests are out of scope (overhead doesn't pay off at this size); call this out in the handoff and rely on the manual smoke pass instead.

Smoke (manual, recorded in the handoff):
- `yarn workspace @serfab/cadre-host build && yarn workspace @serfab/cadre-host start --data-dir tmpdata`, open `http://127.0.0.1:8765/`, click through all five pages with the dev console open. Confirm: green status dot when subsystems are healthy, invite modal generates a QR, "Test reachability" updates the connectivity card, Settings toggle round-trips.
- Lighthouse pass (Chrome DevTools) for accessibility + performance scores; record both in the handoff. Targets: a11y ≥ 90, performance ≥ 95 (it's a local-only static SPA — anything less means a regression in the build).
