# Android: a node code scanned by the system camera opens the app

## What and why

The code cadre-host shows is `sereus-join:1.<base64url>`, which is a URI with the scheme `sereus-join`. When an Android app registers that scheme, the system camera (or Google Lens) offers to open the scanned text in it; when several Sereus apps register it, Android shows a chooser listing all of them. That chooser is the same discovery idea as the shared intent action in `same-phone-apps-exchange-join-by-deep-link`: every Sereus app registers one shared name and the user picks.

It is a convenience over the in-app scanner built by `rn-app-joins-host-node-by-qr`, which stays the main path. **iOS is left out on purpose:** when two iOS apps register the same custom scheme, which one opens is undefined, so a code could open a Sereus app whose cadre the user did not mean. iOS users scan inside the app.

## What to build

- **Register the scheme on Android only.** `app.json` → `expo.android.intentFilters`: one filter with `action: "VIEW"`, categories `BROWSABLE` and `DEFAULT`, `data: [{ scheme: "sereus-join" }]`. Do not add `sereus-join` to `expo.scheme` (that would register it on iOS too). A scheme-only filter matches opaque URIs like `sereus-join:1.abc`, as `mailto:` filters do.
- **Route the link to the approval prompt.** `app/+native-intent.tsx` exports `redirectSystemPath({ path, initial })` (expo-router's hook for rewriting incoming links): a `path` that starts with `sereus-join:` becomes `/settings?nodeCode=<encodeURIComponent(path)>`; every other path is returned unchanged. Settings passes the `nodeCode` search parameter (`useLocalSearchParams`) to the add-node section, which runs it through `readNodeCode` exactly like a pasted code and opens the approval prompt. A link never claims without the user's approval.
- **Clear the parameter once read** (`router.setParams({ nodeCode: undefined })`), so returning to Settings does not prompt again and the secret does not linger in navigation state.
- **The node is not running yet** (a cold start from the link, while the app's auto-start is still connecting): keep the code and show the approval prompt once the node is connected; if the app does not auto-start (no saved start, or `autoStart` false), the section shows the code is waiting and asks the user to Connect first.

## Edge cases & interactions

- **The link arrives while a claim is already running, or a prompt is already open:** ignore the new code with a short note; one claim at a time. By inspection.
- **Another app on the phone registers `sereus-join`:** Android's chooser lists it; the approval prompt in this app names the cadre, so a code opened in the wrong Sereus app is declined there. By inspection.
- **A malformed link** (`sereus-join:` followed by junk): `readNodeCode`'s failure message, same as a bad paste. Covered by `node-claim.spec.ts` already.
- **The secret in the link:** never log `path` or the parameter. By inspection.
- **Warm start** (the app is open in the background when the link arrives): `redirectSystemPath` runs with `initial: false`; the same route applies. Device run.

## Tests

None new: the routing is a prefix check and a parameter, and the decoding it feeds is already pinned by `node-claim.spec.ts`. Whether the system camera actually offers the app is a device question.
