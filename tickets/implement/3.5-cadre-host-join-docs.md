# cadre-host docs rewrite

Last of the `cadre-host-join-a-cadre` chain. The four implement tickets before it each made the minimal edits that kept the docs true; this one restructures. Docs describe the system as it is now: name a ticket slug where a past design is the reason for a present constraint, and do not retell the donation or founder history.

## docs/cadre-host.md

Target shape, in this order:

- **Intro and Who it's for.** A self-hosted manager that runs always-on nodes for cadres that live on people's phones: your own first, a friend's if they scan a code you show them. No grants, no trust circle, no own cadre.
- **Package boundary.** Unchanged table minus the Auth row's invitation wording (admission is by claim or invitation at the cadre's members, not by anything the host holds).
- **Deployment model.** Management plane only; the host holds no owner key and never founds a cadre (the constraint from `feat-owner-keys-only-on-user-devices`, stated as a rule); one kind of node, the hosted node; the control-plane separation paragraph reduced to that one case; the updated diagram (the manager, N hosted nodes, phones dialing them).
- **Join a cadre.** The QR claim flow end to end (start, the payload and its `sereus-join:` encoding, scan, the claim naming the party, the live states, respawn keeping the secret and ports, remove, reset, replacing a dead host by removing the old node in the owner app and joining a new one); "Join by invitation" (when it works, the first-node case, retry); the "already claimed by someone else" case.
- **Hosted nodes.** The record and its statuses, the supervisor (respawn rules, the restart on new addresses, the stuck-`spawning` reap), the ending-wins rule for the operations that remain, per-node identity and node-local stores in the workdir, four ports per node, the push block on every storage node.
- **Security posture.** Two points as now, the second reworded: devices join a cadre by proving a claim secret or an owner-signed invitation at the cadre's members; the host never authenticates anyone itself.
- **NAT and DDNS.** As now, with "donated" and "owner node" wording gone and the `libp2pPort` sentence removed; "Reachability from outside" becomes part of "Join a cadre" (the QR still works at home; outside needs a mapping or a forward; CGNAT needs a relay, not yet wired).
- **Push credentials.** Unchanged mechanism; the injection section says every storage-profile hosted node gets the block, and that the credentials are the operator's app credentials, so configure them only when the hosted nodes serve cadres of that app's users.
- **Updates, Release signing.** Unchanged, except the two-keys table loses the per-install identity row (the host no longer has one) and gains the per-node identity instead.
- **Local UI server.** The API table (status without role, nodes without lifecycle verbs, `/api/hosted-nodes` and its sub-routes, `/nat/*`, `/update/*`), the SSE table, the settings whitelist with the version-3 structural keys, "Honest gaps" reduced to what is true.
- **Architecture sketch and Status.** Updated.

Use `yarn unwrap:md docs/cadre-host.md` if any hard-wrapped lines remain.
