# cadre-cli: owner grants

`machine-invitation-grants-no-ownership` removed `cadre enroll invite --owner`. This ticket gives the CLI the owner-grant side, on the same patterns as machine invitations (`cadre enroll invite`, `cadre start --invitation`; README → "Join by invitation").

## Issuing (owner node, admin channel)

- `POST /admin/owner-grants` body `{ label?, expiresInMs?: number | null, uses? }` → `{ grant, encoded, warnings }`; `GET /admin/owner-grants` lists them with liveness and redemptions; `DELETE /admin/owner-grants/<key>` withdraws one. Validation as the invite endpoints validate theirs; `expiresInMs: null` is a backup (no expiry) and must be given explicitly.
- `cadre enroll owner-grant [--label <text>] [--ttl <duration>|never] [--uses <n>] [--json]`: only the encoded grant on stdout; stderr names the party, the label, the expiry, the member addresses, and always the warning that whoever holds it can become an owner of the cadre until it is used, expires or is withdrawn (`DELETE /admin/owner-grants/<key>`). Default 15 minutes, one use.

## Redeeming (any server)

`cadre start --owner-grant <text>` (or `@<file>`, if the CLI already accepts that for `--invitation`; otherwise the same forms `--invitation` takes):

- Uses the owner key file (`owner.keyFile`), created when missing as `--owner` creates it, and refused when it is the identity file (the existing rule).
- On a node that is already a member of the grant's party: redeems locally and wires the key.
- On a node that is not: joins the cadre as a machine and an owner (`joinWithOwnerGrant`), then wires the key.
- After it, the node runs as `--owner` does. A later start with the flag still in its service file is answered "already an owner" with no use spent; the README says to change the flag to `--owner`.
- Refused together with `--seed` or `--invitation` (a grant alone joins), and with `--owner` on a fresh party (that founds a party rather than joining one).
- A failed redemption is reported on the console and in `/status` and the node keeps running, as a failed `--invitation` is (`redeemStartupInvitation`, `describeRedemptionFailure`; reuse them for the grant's errors).

## Edge cases & interactions

- **Owner key file already holds a key that is an owner of this cadre**: "already an owner", nothing spent. Inspection.
- **Owner key file holds a key that owns another cadre**: it becomes an owner of this one too (one key, several cadres). Inspection; say it in the README.
- **The grant is for another party than the config names**: refused at start, before the node dials anything, as a wrong-party invitation is. Inspection.
- **Alone on the local path**: refused `alone`, reported as retryable in `/status`. Inspection.
- **A backup grant minted on a server and printed by an operator**: stdout carries only the grant; the warning goes to stderr. Inspection.
