# Hosted nodes announce their public addresses

Second of three (`cadre-host-nat-per-node-mappings` → this → `cadre-host-node-reachability`). After the first ticket, `NatService.publicAddressesFor(nodeId, ports)` returns a node's public TCP and `/ws` addresses synchronously from cached state, predicting an identity mapping for a port that is not mapped yet. This ticket gets those addresses into each child and keeps them current.

## How a node learns its public addresses

cadre-cli already has the setting: `network.appendAnnounceAddrs`, env `CADRE_APPEND_ANNOUNCE_ADDRS` (comma-separated list, `packages/cadre-cli/src/config/env.ts`), which cadre-core validates at start (`announce-addrs.ts`) and libp2p adds to the node's advertised addresses beside its listen addresses. No cadre-cli change is needed. Use the **append** form, not `announceAddrs`: `announceAddrs` replaces the advertised set and would drop the LAN addresses a phone at home dials. Strand nodes inside the child do not inherit either field (`cadre-core/src/strand-network-config.ts`), which is correct: the announced ports are the control node's.

With no pushed invite addresses (the first ticket removed the push), cadre-core's `collectSelfAddrs` publishes `libp2p getMultiaddrs()` in the node's own `CadrePeer` row and its invitations, and that list includes appended announce addresses. So the cadre's stored addresses for the node carry the public ones once the node announces them.

### Orchestrator hook

- `HostProcessConfig` gains `announceAddrs?: (containerId: string, ports: NodePorts) => string[]`. **Synchronous on purpose:** `createContainer` and `ensureOwnerNode` allocate ports inside a window that must contain no `await` (see the comment above `dropStaleHandle` in `createContainer`), and the addresses depend on the ports.
- `launchChild` calls it once ports are known and sets `CADRE_APPEND_ANNOUNCE_ADDRS` in the child's env (omitted when the list is empty; cadre-core treats empty as unset). It sits with the fixed per-child vars, after `scrubbedParentEnv()` and `extraEnv`, so neither can override it. A throw from the hook is logged and treated as no addresses — a NAT problem must never stop a node from starting.
- The list is recorded on the `Handle` as `announcedAddrs: string[]`, persisted in `state.json` (`PersistedHandle`), and exposed on `ManagedNodeInfo`. A handle from an older `state.json` without the field reads as `[]`.
- Replace the child-env `NOTE:` in `launchChild` that says announce vars cannot reach a child.
- `bin/host.ts` builds the orchestrator before `NatService`, so wire the hook through a late-bound reference: `announceAddrs: (id, ports) => nat?.publicAddressesFor(id, ports) ?? []`. The first ticket already starts `NatService` before any spawn, so the first spawns see a discovered gateway.

### Keeping addresses current: restart, not live update

A node's announced addresses change when its mapping lands on a port other than the predicted one, when a mapping fails or is restored, when a manual forward is set or cleared, when UPnP is toggled, when the DDNS hostname is set or cleared, or when the external IP changes while no DDNS hostname is configured.

**Decision: restart the node with the new addresses.** A live update was rejected: libp2p can add public address mappings at runtime, but reaching a child needs a management channel on every hosted node (today only the owner node has one, and `cadre-host-join-a-cadre` removes it), a new cadre-core API and a new cadre-cli route. A restart reuses the existing respawn machinery, keeps the peer id and ports (docs/cadre-host.md → "A respawned node keeps its addresses"), and costs a few seconds of downtime. Residential external IPs change rarely, and **with a DDNS hostname configured an IP change changes no announced address**, so no restart happens; the docs should recommend DDNS for that reason.

Mechanism:

- `NatService` compares, for each running node, `node.announcedAddrs` with `publicAddressesFor(node.id, node.ports)` as sets (order-insensitive). It checks after every change that fires its `onChange` and on its 1-minute reconcile timer.
- On a difference it calls a restart callback registered via `NatService.onNodeAddressesStale(listener: (nodeId: string) => void | Promise<void>)`.
- **Rate limit:** at most one address restart per node per `NAT_ADDRESS_RESTART_MIN_INTERVAL_MS` (10 min). A difference found inside that window waits for a reconcile pass after it ends; it is not dropped. This bounds a flapping router to one restart per node per 10 minutes.
- `bin/host.ts` wires the listener: the owner node → `orchestrator.restartOwnerNode()`; any other node → `donationSupervisor.restart(id)` (the container id is the donation id).

### `DonationSupervisor.restart(id)`

- Runs on the supervisor's serialization tail, so it never overlaps a reconcile pass, a respawn of the same record, or a give-up.
- Inside it: re-read the record; do nothing unless it is `awaiting_seed`/`seeded` with a `dockerId` and the node is running. Then stop the child and respawn it through `DonationService`, which already handles a loan that ends mid-spawn ("An ending that lands mid-operation wins").
- **Does not count toward the give-up budget.** `DonationService.respawn` persists an incremented attempt counter today; give it an option (or a sibling method) that leaves `respawn.attempts`/`lastAttemptAt` alone for a deliberate restart. A restart that throws is logged; the next reconcile pass finds the node down and the normal crash path takes over, with its counting.
- The stop raises an exit event, which queues a normal reconcile pass. That pass runs after `restart` on the tail and finds the node running, so it does nothing.

`cadre-host-join-a-cadre` renames the donation layer; it keeps this method under the new name.

## Edge cases & interactions

- First spawn of a node with UPnP working: the predicted identity mapping matches the router's answer, so no restart follows. The router assigns another port: exactly one restart, after which the announced set matches. **Test** at the `NatService` level with the fake mapper and a fake node source: stale listener fires once for the reassigned node and not for the identity-mapped one.
- Rate limit: a second difference within 10 minutes does not fire; it fires on the first reconcile pass after the window. **Test** with an injected clock (same test file).
- Order-insensitive comparison: same addresses in another order is not a difference. Covered by the test above by inspection of the comparison helper; no separate test.
- Host restart: re-attached handles carry the `announcedAddrs` they were spawned with (persisted), so an IP that changed while the host was down produces a restart after `NatService.start()`. By inspection.
- `restart(id)` racing a terminate, a give-up, or a crash respawn: serialized on the tail and re-reads the record. **Test** in the supervisor's unit tests: a restart leaves `respawn.attempts` unchanged and respawns the node.
- `restart(id)` for a record that is `error`/`terminated`, or a node that is not running: no-op. By inspection.
- The announce hook throws or returns malformed entries: a throw is logged and the child starts with no public addresses; a malformed entry would fail cadre-core's validation and the child would die at boot, so `buildPublicAddresses` only builds from validated parts (integer ports, a hostname from settings, a public IPv4). By inspection.
- The owner node (until `cadre-host-join-a-cadre` removes it) gets the same announce addresses; its restart goes through `restartOwnerNode`.
- An unclaimed or `awaiting_seed` node restarted for addresses keeps its record status; `respawn` rotates the host-side seed token, which the host presents itself. By inspection.
