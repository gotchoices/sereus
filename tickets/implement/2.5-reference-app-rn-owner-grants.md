# Phone reference app: owner grants

After `machine-invitation-grants-no-ownership`, "Add a device or app" admits machines only. This ticket gives the phone app the owner-grant side the project owner decided: **"Add an owner key" and "Make a backup" mint owner grants**, and a device that should be an owner redeems one.

## The edge node

The phone kit's node is the shared edge node (`createPhoneNode` returns `createEdgeNode(...)`, `PhoneNode = EdgeNode`), so the calls go on the edge node (`packages/cadre-core/src/edge-node/edge-node.ts`) and the browser and NativeScript apps get them too: pass-throughs `createOwnerGrant`, `listOwnerGrants`, `withdrawOwnerGrant` to the running node, and a `redeemOwnerGrant(text)` that seats the owner slot's key (created when the slot is empty) on the running node and wires it, in the edge node's transition queue like `importOwnerKey`. `joinCadre` already takes an owner grant (`machine-invitation-grants-no-ownership`). `cadre-rn/README.md`: the phone-node section lists the new calls.

## Settings → Owner keys

Keep the section's existing parts (list, export this device's key, import, remove) and change or add:

- **Add an owner key** (owner): a Name field, then a single-use grant valid 15 minutes, shown as a QR code and text (`share-code.tsx`) with the line that whoever redeems it first becomes an owner of this cadre. For another device or another app of the user's.
- **Make a backup** replaces "Make a backup key": a Name (default "Backup") and a grant with no expiry, shown once as QR and text for printing or saving, under a plain warning: whoever holds it can become an owner of this cadre until it is used or withdrawn; keep it like a key. It also says that it works only while one of the cadre's machines can be reached at an address it carries. The kit's `addBackupOwnerKey` stops being called here; "Export this device's key" stays as the way to keep a copy of a key that works with no network.
- **Outstanding grants** (owner): each live grant with its name, when it expires ("never" for a backup) and uses left, and **Withdraw**. A withdrawn or spent grant drops off the list.
- **Redeem an owner grant** (any member device): paste or scan a grant; the device becomes an owner with its owner slot's key. Outcomes: became an owner; already an owner; refused, with the member's reason in words (spent, withdrawn, not reachable, wrong cadre).
- **Removing an owner key** that issued live grants: the confirmation lists them ("Backup 'Paper' stops working"), from `planOwnerKeyRemoval`'s `grants`.

## Join my existing cadre

The join field also takes an owner grant (decoded by its prefix; the codecs refuse each other by name). An owner grant joins the app as a machine and an owner, which is how an app with conversations brings them along. `join-failure.ts`'s `StrandsNeedOwnerJoinError` text (set in `machine-invitation-grants-no-ownership`) points at this: ask the owner app for an owner grant under Owner keys → Add an owner key, and paste it here. The join progress line for an owner-grant join says it is setting the app up as an owner.

## Words

Write every user-facing string in plain words; no "grant" without saying what it does the first time on a screen ("an owner grant: a code that makes the device that uses it an owner"). Keep the words in `owner-keys.ts` as the web app will copy them (`reference-app-web-owner-grants`).

## Edge cases & interactions

- **A device whose owner slot already holds a key** (it founded its own cadre before joining this one) redeems a grant: the slot's key becomes an owner of this cadre too; nothing is created. Inspection.
- **Redeeming on a device that is already an owner** of this cadre: answered "already an owner", no use spent. Inspection.
- **Redeeming while offline**: refused `alone` or unreachable; the app says to connect and try again. Inspection.
- **The backup shown once**: leaving the screen loses it, as the backup key export does today (`OwnerKeysSection`'s `NOTE:`). Inspection.
- **A grant pasted into the owner-key import field, or a key export into the grant field**: refused by name. Inspection (codec tested in cadre-core).
- **A member device** (not an owner) sees no Add/Make backup/Outstanding parts, only Redeem and Import. Inspection.
