# The NativeScript reference app runs the edge node

After `edge-node-in-cadre-core`, `@serfab/cadre-core/edge-node`'s `createEdgeNode(platform)` is the bring-up the NativeScript app re-implements in `cadre-phone.ts`, `start-options.ts` and `node-local-slots.ts`. What that copy lacks (GitHub #45, verified at 70b2dc1d): no owner genesis; dials out through relays but reserves none, so it cannot be reached through one; no cleanup after a failed start (~265-266, NOTE ~328-333); a start during a stop unhandled (NOTE ~310-314). This ticket gives the app one edge node over a SQLite platform.

## The platform (`ns-edge-platform.ts`, new)

All over the one SQLite database `sereus-peer-identity` (`nsDbPath`), as now:

- **`keyStore`**: a cadre-core `KeyStore` over that database's `kv` table, `b_val` column (the column `loadOrCreateNSPeerKey` uses; `SqliteKVStore` uses only `s_val`). Slot → key: `cadre/identity` → `peer-private-key`, the row phones hold today, so the peer id survives the upgrade (libp2p protobuf bytes, the format `loadOrCreateIdentityKey` reads); every other slot → `keystore.<keyId>`. Writes are followed by `syncSqliteDb(db)`, as the identity write is now. A row whose `b_val` is not bytes → `KeyStoreAccessError`. `list()` by key range, not a full scan.
- **Plaintext, as the identity already is.** The owner key and the strand-move records now land in the same plaintext SQLite as the identity. `docs/reference-app-ns.md` already says whoever adds NativeScript secure storage moves the identity and anchor together; the owner key joins that list. The plan accepted this ("no secure store in browsers, and NativeScript, for now").
- **`storage.nodeLocal()`**: `SqliteKVStore(db, '')` (empty prefix, the literal keys used today), opening the database on first use and after `close`; `flush` is `SqliteKVStore.flush`. The default anchor key `trusted-owners.<partyId>` and the edge node's `bootstrap-peers.`, `enrolled-machines.`, `strand-network.` keys are the ones this app writes today.
- **`storage.rawStorage(scope)`**: `lazyRawStorage(() => open('sereus-' + scope))` from cadre-core, with today's per-name open cache (`ns-storage.ts`'s `openByDbName`) kept in the adapter so `close()` can close each handle and `destroyScope` can close one before deleting it. Delete `makeLazyNsStorage` and `test/ns-storage.spec.ts`: the edge-node ticket ports its cases to cadre-core.
- **`storage.destroyScope(scope)`**: close that scope's cached handle, then delete the database file at `nsDbPath('sereus-' + scope)` (find the deletion call `@nativescript-community/sqlite` 3.x offers, or remove the file through `@nativescript/core`'s `File`). Absent → resolves.
- **`storage.close()`**: flush and close the node-local store, close the identity database and every raw-storage handle. Today a stop closes only the identity database. Closing strand databases on stop is new, so a later start reopens them.
- **`storage.id`**: `'sereus-ns'`.
- `transports`: default (WebSockets, circuit relay). `listenAddrs`: default `[]`. `configure: (c) => ({ ...c, requireSignedSchemas: false })`, today's demo opt-out with its comment.

## The saved start

The edge node's record under `start-options` replaces `start-options.ts`. The record this app writes today (`{ version: 1, partyId, bootstrapAddrs, autoStart }`) parses under the kit's reader (missing `relayAddrs` → `[]`, missing `origin` → founded), so an installed phone keeps its party and its auto-start. One test pins that: a record in today's exact format, read through the edge node's `loadSavedStart`, gives the same party, bootstrap list and `autoStart`.

## The app

- `cadre-phone.ts` becomes the edge node's home: `createEdgeNode(nsPlatform)` once, and the helpers (`applySeed`, `decodeSeed`, `dialPeer`, `getConnectionPaths`, `addStrand`) over `edge.node`, which is null unless running. The comment block on helpers guarding `!node` while a failed start leaves a non-running node goes: `edge.node` is never a non-running node.
- `cadre-vm.ts`: start, stop and restore through `edge.start`, `edge.stop`, `edge.loadSavedStart`; status from `edge.onStatus`; the strand and commit-held handlers registered once through `edge.on`, so they survive every rebuilt node. Delete `bindEvents`/unbind per node.
- **Joining** goes through `edge.joinCadre(invitation, { relayAddrs })`, not `node.redeemCadreInvitation` on the running node. The edge node starts the invitation's party with `origin: 'joined'`, so it never runs owner genesis there. Redeeming on a node the user started by typing the invitation's party id would first have run genesis on a party whose control rows had not arrived, seating the phone as a second founder. `join-failure.ts` gains a sentence for `StrandsNeedOwnerJoinError`, the refusal a member-only invitation earns when the founded party holds strands (RN's `join-failure.ts` has one to copy). Moving strands and dissolving the left party need no NativeScript UI in this ticket; the edge node does the move on its own when the invitation grants owner.
- **Settings gains a Relays field** beside Bootstrap (comma-separated, same `splitAddrs`, prefilled from the saved start, test id `input-relay-addr` added to `test-ids.ts`). Its value is the start's `relayAddrs`, so the phone reserves on the relays and both its control and strand nodes get a `/p2p-circuit` address.
- `startSolo` (`solo-smoke.ts`) starts `{ partyId, bootstrapAddrs: [], relayAddrs: [] }`; it now founds with owner genesis like any founded start.

## Edge cases & interactions

- **Owner genesis on a seeded phone.** A phone started with the drone's party id and bootstrap address now runs genesis at start, as the React Native app has done since the kit got genesis. The Maestro flows the two apps share (`reference-app-rn/maestro/flows`) already run against that behavior on RN. Check that the NS-specific steps (seed paste after Connect) still read the same; device runs are not agent-runnable, so leave them for a human and say so.
- **Overlapping launch auto-start and Connect tap**, Disconnect during a start, Connect during a stop: queued by the edge node. Covered by the kit's `node.spec.ts`; delete the `cadre-phone.spec.ts` cases that tested this module's own copy of that logic.
- **A failed start** closes the identity database and every opened scope (`storage.close()`); the next Connect opens fresh. Covered by the kit's suite; the adapter's `close()` is checked by inspection.
- **Strand databases closed on stop** (new): a chat screen holding a strand instance across Disconnect must not read through a closed handle. The VM drops its strand map on `stopped`.
- **Identity across the upgrade**: one test that the key store reads an identity row written by `loadOrCreateNSPeerKey`'s format (`b_val` protobuf under `peer-private-key`) as `cadre/identity`. This and the saved-start test above replace the persistence pins in `cadre-phone.spec.ts`. Keep `node-local-slots.spec.ts`'s key-string pins if `node-local-slots.ts` survives; delete the file and its spec if the edge node's key functions replace it entirely.
- **Bundle**: `yarn workspace @serfab/reference-app-ns test:bundle` must resolve `@serfab/cadre-core/edge-node` under the app's webpack config.
