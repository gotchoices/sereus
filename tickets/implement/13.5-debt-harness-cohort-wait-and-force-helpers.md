# Harness helpers: observe, wait for, and force a multi-machine control cohort

Split out of `debt-harness-control-cohort-observable-and-forced` (deleted; this ticket and
`debt-harness-party-multi-machine-control-write` replace it). This ticket builds the
helpers only. The scenario that uses them to actually write into a three-machine cohort is
the follow-on ticket.

## Vocabulary (used throughout)

- **Control cohort** — the set of peers a control-database write is offered to. Derived by
  `Libp2pKeyPeerNetwork.findCluster(key)`; the write commits when a super-majority of that
  set approves. A one-member cohort commits on the writer's own vote (`allowClusterDownsize`
  defaults to true), which is why a passing write proves nothing about cohort size.
- **Party** — `createTestParty` output: one owner node plus zero or more **drones**. Drones
  dial only the owner, never each other.
- **Harness node** (`TestCadreNode`) — a bare libp2p node from `createLibp2pNode`, wrapped in
  a small record. Distinct from `CadreNode` (the `cadre-core` class), which wraps its own
  libp2p node behind `getControlNode()`.

## Background you need before touching code

Read the file header of `packages/integration-tests/src/harness/forced-cluster.ts` first. It
explains why the existing helpers patch `Libp2pKeyPeerNetwork.prototype` rather than node
instances: every node has **two** `Libp2pKeyPeerNetwork` instances over the same libp2p node
(the node-attached one at `node.keyNetwork`, and a second one the Quereus optimystic
collection factory creates and caches with the `NetworkTransactor`). An instance patch covers
only the first, and the transactor's coordinator assignment goes through the second.

Two facts measured by the prereq ticket `debt-harness-record-fret-ring-convergence-finding`
(now in `complete/`), which this design rests on:

- The owner's peer ring **does** reach every party member, within about five seconds of
  `createTestParty` resolving. Single-member cohorts in the harness are a start-up race, not
  a permanent gap. So *waiting* is the primary tool.
- Because drones dial only the owner, a **drone**-coordinated write tops out at a two-member
  cohort forever. Only owner-coordinated writes can reach three. A wait can never fix that;
  forcing can.

One more fact that makes the probe key below sound: `CONTROL_REPLICATION_BREADTH` is 16 and
`findCluster` returns the ring's closest-`k` peers, so in any party smaller than 16 nodes it
returns **every peer FRET has classified as serving this network**, whatever key you pass.
See the `NOTE:` at `packages/quereus-plugin-sereus/src/cluster-size.ts:44-49`, which states
the same bound from the other direction.

## What to build

### 1. New file `packages/integration-tests/src/harness/control-cohort.ts`

Kept separate from `wait-utils.ts` on purpose: `wait-utils.ts` is deliberately generic (its
only import is `debug`), and these helpers need libp2p and optimystic types. Export the new
module from `harness/index.ts`.

Give the file a header that states, for a future reader who has none of the above context:
what a control cohort is, that the ring converges in ~5 s so waiting is the default tool,
that forcing is a **stopgap** for determinism and for the drone-coordinated case a wait can
never satisfy, and why the probe key is representative.

```ts
/** The key every probe uses. See the file header for why the choice does not matter. */
export const CONTROL_COHORT_PROBE_KEY: Uint8Array;

export interface ControlCohortOptions extends WaitOptions {
  /** Whose view to observe. Default: `party.ownerNode`. */
  node?: TestCadreNode;
}

/** One-shot read of the cohort `node` would currently offer a control write to. */
export function readControlCohort(
  party: TestParty, node?: TestCadreNode
): Promise<string[]>;

/** Poll until that cohort holds at least `minPeers` members. Resolves to the member ids. */
export function waitForControlCohort(
  party: TestParty, minPeers: number, options?: ControlCohortOptions
): Promise<string[]>;

export interface ControlCohortObserverHandle {
  /** Restore the real prototype `findCluster`. Idempotent. */
  restore(): void;
  /** Total `findCluster` calls seen since observing began (all instances, all nodes). */
  callCount(): number;
  /** Cohort size returned by each observed call, in call order. */
  cohortSizes(): number[];
}

/**
 * Record — without substituting — every cohort the real `findCluster` returns.
 * The anti-vacuity instrument for wait-based tests, where `forceFullCohort`'s
 * counters do not apply because nothing is forced.
 */
export function observeControlCohorts(): ControlCohortObserverHandle;
```

Implementation notes:

- **Resolving the key network.** `createLibp2pNode` attaches the node-attached instance as
  `keyNetwork` (see `libp2p-node-base.ts:1301` in the sibling `../optimystic` workspace). It
  is not on the public `Libp2p` interface, so read it through a narrow structural cast —
  `(node.libp2p as unknown as { keyNetwork?: Libp2pKeyPeerNetwork }).keyNetwork` — and throw
  a named error if it is absent rather than returning a fake empty cohort. No `any`.
- **`findCluster` is not cached** (only `findCoordinator` is), so polling it is live. Do not
  add a cache-busting key rotation.
- **Argument validation, before any polling.** `minPeers < 1` and `minPeers > 1 +
  party.droneNodes.length` both throw immediately, naming the party, the requested count and
  the party's node count. A request the party can never satisfy must not burn a timeout.
- **Timeout message.** Track the last observed cohort in a closure and, on timeout, throw
  naming: the party name, the observing node's peer id, the last observed size, the required
  size, and the elapsed budget. Set the original timeout error as `cause`. `waitUntil`'s
  generic message is not enough — the observed size is the whole point.
- Defaults: `timeoutMs` 15000 (≈3× the measured ~5 s convergence), `intervalMs` 250.
- `observeControlCohorts` wraps whatever `findCluster` is currently installed and delegates
  to it, recording `Object.keys(result).length`. It must restore the method it captured, so
  observers and forcers nest last-in-first-out like `pinCoordinator` already does.

### 2. Widen `forceFullCohort` and `pinCoordinator` to accept harness nodes

Both currently take `readonly CadreNode[]` and reach through `node.getControlNode()`. A
harness party holds `TestCadreNode`s, so neither is usable from a party today.

Widen rather than adding siblings — two near-identical forcing helpers is the shape that
drifts. Add one shared resolver in `forced-cluster.ts`:

```ts
/** Anything these helpers can read a live control libp2p node out of. */
export type CohortNodeSource = CadreNode | TestCadreNode | Libp2p;

/** Resolve to the started control libp2p node, or throw naming `who` and the shape seen. */
function resolveControlLibp2p(node: CohortNodeSource, who: string): Libp2p;
```

Discriminate in this order, with `in` checks (no `any`, no `instanceof` against `CadreNode` —
that would pull a class import where a structural one suffices):

1. `'getControlNode' in node` → `CadreNode`; call it, throw if it returns null.
2. `'libp2p' in node` → `TestCadreNode`; use `node.libp2p`.
3. otherwise treat as `Libp2p` — verify it exposes `peerId` and `getMultiaddrs`, and throw a
   named error if not.

`CadreNode` exposes no public `libp2p` property and `TestCadreNode` has no `getControlNode`,
so the order is unambiguous today; say so in a comment so a future field addition on either
type is a conscious change.

**Keep everything else identical.** `ForcedCohortHandle` and `PinnedCoordinatorHandle` keep
their exact shape (`restore` / `callCount` / `cohortSizes`), so
`control-write-degraded-cohort-member.integration.ts` compiles and behaves unchanged. Keep
both existing loud checks: no multiaddrs → throw (an addressless forced entry surfaces
downstream as a dial failure indistinguishable from an injected degradation), and no public
key → throw.

## Edge cases & interactions

- **`minPeers: 1` on a `droneCount: 0` party** — must succeed on the first poll, not
  deadlock. `findCluster` always includes self, so this falls out naturally; add a case that
  proves it rather than assuming it.
- **`minPeers` above the party's node count** — immediate, clear throw, never a timeout.
- **`minPeers: 0` or negative** — throw; a helper whose contract is "at least N members" has
  no meaning at zero and silently passing would make a caller's assertion vacuous.
- **Restore ordering across all three prototype patches.** `pinCoordinator` wraps whatever
  `findCluster` is installed, and `observeControlCohorts` now does too. Rule: restore in
  reverse order of application. A test that tears down out of order leaves a patched
  prototype behind for the rest of the file. State the rule in both file headers.
- **Observing a forced cohort** records the forced sizes, so an anti-vacuity assertion built
  on `observeControlCohorts` while a force is active proves nothing about the real network.
  Document that; do not try to detect it at runtime.
- **Prototype patches are process-wide within a vitest worker**, including any
  strand-network `Libp2pKeyPeerNetwork`. Restate the existing caveat for the observer.
- **Both key-network instances.** The observer must be a prototype patch for the same reason
  the forcer is — an instance patch on `node.keyNetwork` misses the transactor's instance and
  under-counts.
- **Missing `keyNetwork` attachment** — if the structural cast finds nothing, throw naming the
  node. Returning an empty cohort would make `waitForControlCohort` hang to its timeout with a
  misleading message.
- **A `waitForControlCohort` that throws inside `beforeAll`** leaves the party's nodes running.
  Any scenario using it must still call `shutdownTestParty` (which calls `releasePorts`) on the
  failure path. The helper itself starts and stops nothing; note this in its doc comment so
  callers wire teardown correctly.
- **Existing call site unchanged** — `control-write-degraded-cohort-member.integration.ts`
  passes `CadreNode`s and must need no edit at all. If it needs one, the widening is wrong.

## Tests

No new scenario file here — the multi-machine write scenario is the follow-on ticket. Cover
the helpers' own contract with a fast harness-level scenario (a party or two, no writes):

- `waitForControlCohort(party, 1)` on a `droneCount: 0` party resolves promptly with exactly
  the owner's peer id.
- `waitForControlCohort(party, 3)` on a `droneCount: 2` party resolves, and the returned ids
  are the owner's plus both drones'. Expected to take up to ~5 s; give the test real headroom.
- `waitForControlCohort(party, 4)` on a `droneCount: 2` party throws **immediately** (assert
  the elapsed time is far below the timeout) and the message names both counts.
- `waitForControlCohort(party, 3, { timeoutMs: 1 })` on a fresh `droneCount: 2` party throws a
  message containing the party name and the observed size. (If this proves flaky because the
  ring occasionally warms inside 1 ms, assert on the message shape from a party that cannot
  satisfy the wait in time by another means — do not weaken the assertion to `/timeout/`.)
- `observeControlCohorts()` records a non-zero `callCount()` after a `readControlCohort` call,
  and `restore()` is idempotent (call it twice; the second is a no-op and the real method is
  back).
- `forceFullCohort([party.ownerNode, ...party.droneNodes])` on a harness party returns a
  handle whose `cohortSizes()` are all 3 after a `readControlCohort`, then restores cleanly.

Every one of these is cheap (no control writes), so the file should run in well under a
minute.
