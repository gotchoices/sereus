# Finish authorizing writes to `CadreControl.Revocation`

Continuation of `bug-control-revocation-unauthenticated-writes` — that run hit its token
budget after landing the schema rule and the production/test signing changes, and was
replaced by this ticket. **Nothing below has been run yet**: no test suite, no lint, no
typecheck. Treat every "already written" item as written-but-unverified.

## Background (why the rule exists)

`CadreControl.Revocation` is the append-only table that retires the one-time authorization
nonce (`StampId`) of a removed `OwnerKey` / `CadrePeer` / `ValidationKey` / `Strand` row, so
a never-expiring add-approval signature cannot resurrect a removed row.

At HEAD before this change it had **no `with context` clause and no `verify(...)`** — any
writer reaching the control database could append rows. Confirmed consequences (reproduced
in the fix stage against a real `CadreNode`, empty bootstrap, `transaction` profile):

- **Unbounded junk.** 25 bare inserts were accepted and permanent; they replicate
  party-wide and `CadreNode.listAuthorizedMembers` re-reads the whole set per inbound gate
  request.
- **Eviction / pre-block.** A tombstone written while the target `CadrePeer` row is not
  locally visible lands unauthenticated; the owner's own later admission of that exact row
  is then refused by `NotRevoked`, permanently, and every node drops the peer from the
  authorized-membership set.
- The only pre-existing barrier was `RowIsGone` (refuses tombstoning a *live, locally
  visible* row).

## What is already written (unverified)

### Schema — both copies

`schemas/control.qsql` and `CONTROL_SCHEMA` in `packages/cadre-core/src/control-schema.ts`
(hand-maintained twins, compared byte-for-byte by `control-schema-drift.spec.ts`) both gained,
on `Revocation`:

```sql
        constraint Authorized check on insert (
            exists (select 1 from OwnerKey A where A.Key = context.OwnerKey and verify(digest('CadreControl.Revocation', 'remove', new.TableName, new.StampId), context.Signature, A.Key, 'ed25519'))
        )
    ) with context (OwnerKey text, Signature text);
```

plus a comment block covering: the digest binds the whole row; the domain tag keeps it
disjoint from the `'CadreControl.CadrePeer'` `'remove'` digest signed in the same
transaction; it reads live `OwnerKey` (matching the sibling tables) and why that is
deliberate; `RowIsGone` / `Immutable` are unchanged. The table's leading `NOTE:` about
unbounded growth now says growth is owner-gated.

`control-schema-drift.spec.ts` was run after this edit and **passes** — the one thing here
that has been verified.

### TypeScript

- `control-authorization.ts` — `RevocableTable` moved here from `control-database.ts` (so
  `peer-authorization.ts` can type against it without importing the runtime); the
  `CONTROL_TABLES` doc paragraph about `Revocation` rewritten (it used to claim no
  signature is ever minted for the table).
- `control-database.ts` — re-exports `RevocableTable` from its new home;
  `deleteGuardedRow` now signs `buildAuthorizationMessage('CadreControl.Revocation',
  'remove', [table, stampId])` and passes it as context on the tombstone insert.
- `peer-authorization.ts` — new `revocationDigest(tableName: RevocableTable, stampId)`.
- `seed-bootstrap.ts:removePeer` — signs `revocationDigest('CadrePeer', stampId)` via the
  existing `signDigest` and passes context on the tombstone insert.

Both signing encodings (raw bytes via `buildAuthorizationMessage`, base64url digest string
via `signDigest`) were verified in the fix stage to satisfy this SQL `verify`.

## Which constraint reports each rejection

Measured in the fix stage against this exact rule. Write assertions against these names via
`expectConstraintFailure` in `test/control-constraint-helpers.ts`.

| Attempt | Reports |
|---|---|
| tombstone with no context (`OwnerKey`/`Signature` null) | `Authorized` |
| tombstone signed by a non-owner | `Authorized` |
| owner-signed tombstone over a *different* stamp | `Authorized` |
| owner's `CadrePeer` `'remove'` signature replayed as the tombstone | `Authorized` |
| owner-signed tombstone of a still-live row | `RowIsGone` |
| delete of an existing tombstone | `Immutable` |

Do **not** widen an accepted-name list to get a suite green — re-shape the write instead
(see the note in `control-constraint-helpers.ts`).
