# "Join a cadre" in the local UI

Fourth of the `cadre-host-join-a-cadre` chain. The server side (`/api/hosted-nodes`, the `hosted-nodes-changed` event, the claim payload) landed in `cadre-host-hosted-nodes-join-by-qr`; this ticket is the Svelte side only. `cadre-host-join-by-invitation` adds a paste field to the page this ticket creates.

## What to build

- **State.** A `hostedNodes` slice in `state.svelte.ts` mirroring `HostedNodeView` (`id`, `partyId`, `status`, `peerId?`, `ownerKey?`, `connected?`, `error?`, timestamps; never the secret), with `refreshHostedNodes()`, `joinCadre()` (POST), `removeHostedNode(id)`, `resetHostedNode(id)` and `fetchClaimDetails(id)`. The claim response (`payload`, `peerId`, `multiaddrs`, `reachability`) is held in page-local state only, never in the global slice and never in browser storage. `applyEvent` refreshes the slice on `hosted-nodes-changed` and on `node-state-changed`.
- **Join page** (`#/join`, nav entry "Join"). One button, "Join a cadre", which calls `joinCadre()` and then shows, for the new node: the QR and copyable payload (`TokenShare`, copy label "Copy join details"), a one-line instruction ("Scan this with the Sereus app on the phone that owns the cadre, or paste the text into it"), the `NodeReachabilityCard` for the node with a warning line when the verdict is `unreachable` ("Works from your home network now; forward the ports below for a phone elsewhere"), the live state line, and Cancel (removes the node) while it is unclaimed. The state line reads "Waiting for a phone to claim this node" → "Claimed by owner `<first 8 chars>` into cadre `<partyId>`" → "Connected to the cadre" once `connected`. After the claim the QR is replaced by a link to the node's page. Reloading the page while a node is unclaimed shows it again (the page lists every unclaimed node, each with its QR fetched on demand), so a closed tab loses nothing.
- **Nodes list.** Each row shows the hosted-node status, the party (the record's, not the orchestrator handle's placeholder), the owner fingerprint and connected state, joined by id with the orchestrator list from `/api/nodes`.
- **Node detail.** A "Cadre" card: status, party, owner fingerprint, connected. For an unclaimed node: the QR and Cancel. For a joined node: Remove (confirm dialog: "stops this node and deletes its data on this machine; the cadre keeps the node's row until its owner removes it there") and Reset (confirm dialog: "use this if someone you did not intend claimed the node; the node is stopped, its data deleted, and a fresh node with a new code starts"). An `error` node: the error text, Remove, and Retry (which is a reset).
- **Home tile.** "Hosted nodes: N joined, M waiting" with "Join a cadre →"; the Connectivity tile unchanged.
- **Connectivity page.** The per-node label becomes "hosted node for cadre `<partyId>`" or "waiting to be claimed", from the hosted-nodes slice.
- **Pure helpers** in `lib/hosted-nodes.ts`: `stateLine(node)`, `ownerFingerprint(key)` (first 8 characters), and the join of hosted records with orchestrator handles.

## Edge cases & interactions

- The claim endpoint answers 503 while the child is starting: the page retries every second and shows "Starting the node…" until the QR appears. By inspection.
- The node is claimed while the Join page is open: the `hosted-nodes-changed` event drives the state line without a reload. By inspection; the scenario in the previous ticket observes the event.
- Two unclaimed nodes at once: both listed with their own QR. By inspection.
- The copy button copies the whole payload, which includes the secret; that is the point, and nothing else on the page carries it. By inspection.
- `node-state-changed` for a respawn: the list refreshes; the Cadre card does not flicker to "unknown" because the record is unchanged. By inspection.
- A `hosted-nodes-changed` event with `kind: 'removed'` for an id the slice never held: `DELETE /api/hosted-nodes/:id` also removes an orchestrator handle that no record names (a lost `hosted-nodes.json`), and the service publishes `removed` for it. The slice tolerates the unknown id and refreshes rather than throwing. By inspection.
- Narrow screens: the QR is 224 px as the grant QR was; the payload textarea wraps. Check at 390 px as the reachability ticket did.
