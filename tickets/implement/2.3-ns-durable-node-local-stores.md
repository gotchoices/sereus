# Durable trusted-owner anchor + bootstrap peers on NativeScript

`startPhoneNode` (`reference-app-ns/src/cadre-phone.ts`) injects neither
`trustedOwners.store` nor `bootstrapPeers.store`, so both node-local records are
in-memory only and die with the app process — the same gap the web and React Native
tickets close, on the third target.

## Where they go

Both records go in the **`sereus-peer-identity` SQLite database**, via `SqliteKVStore`
from `@optimystic/db-p2p-storage-ns`, opened with the existing `openOptimysticNSDb`
helper.

The placement rationale is fate-sharing with the identity, exactly as on web: this app's
Ed25519 identity is already a BLOB in that database's `kv` table (see
`loadOrCreatePhoneKey`). There is no more tamper-resistant option to choose between here
— unlike React Native, this app deliberately does **not** use Keychain/Keystore (the
module comment calls secure storage "a future hardening step"), so the anchor cannot be
placed anywhere stronger than the identity it qualifies. Putting them in one database
means they are wiped together and the device cold-starts as a genuinely fresh node that
trusts no one until re-invited. Do **not** introduce a second database for the anchor: a
split lifetime is strictly worse than a shared one and buys no protection here.

Because the anchor is only as protected as the identity on this target, add a short
`NOTE:` at the wiring site pointing at that gap, so whoever does the NS secure-storage
hardening moves both together.

Slot keys in `SqliteKVStore`: `trusted-owners.<partyId>` and `bootstrap-peers.<partyId>`.
`SqliteKVStore` is the shared `IKVStore` shape (`get`/`set`/`delete`/`list`), so the
`DurableSlot` adapter is four lines: `get` ⇒ text or `undefined`, a rejection propagates
(unreadable), `set` ⇒ `save`.

## Edge cases & interactions

- **Database handle lifetime.** `loadOrCreatePhoneKey` currently opens `sereus-peer-identity`
  and closes it in a `finally`. The stores need a handle for the node's life: open once in
  `startPhoneNode`, close in `stopPhoneNode`, and keep `startPhoneNode`'s idempotent
  early-return (`if (node?.isRunning) return node`) from opening a second one. NS SQLite
  serialises access through `connection-mutex`, but two handles to one file is still
  something to avoid.
- **Unreadable database.** A `get` rejection must propagate and fail `startPhoneNode`, not
  degrade to an empty anchor — the shared loader's "present but unreadable ⇒ throw" policy.
- **Corrupt / foreign-party snapshot.** Cold start (empty), never a crash.
- **`startSolo`.** Goes through `startPhoneNode`, so both stores are wired on the solo path
  too; the founder's own key re-anchors each start via the genesis path. Confirm
  `solo-smoke.ts` still passes.
- **No migration.** An existing install has no persisted record and cold-starts once.
  State that at the wiring site.
- **Persist failure.** In-memory record stands, the caller's promise rejects, the next
  successful write re-lands the full snapshot.
