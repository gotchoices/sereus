# Let a publish choose its npm dist-tag, and refuse to publish a prerelease without one

## Why

npm gives every published version a *dist-tag*. The tag `latest` is special: it is what
`npm install <pkg>` resolves to and what a `^`-range picks up. Any other tag (`alpha`, `next`, …)
means "you can have this, but you have to ask for it by name".

`scripts/publish-package.js` runs a bare `yarn npm publish --access public`, which always writes
`latest`. So today there is no way to publish a version that does *not* become the default install.

The next release needs exactly that. Cross-machine replication is known-broken with a traced
upstream root cause, so `0.10.0-alpha.0` must not be what a new installer gets by default — see
`docs/releasing.md` → "The interim release" and `blocked/cut-the-interim-release`. Without this
change the release has to be published by hand, package by package, from six directories, with the
`--tag` flag typed correctly each time. That is a bad thing to hand a person at the one moment where
a mistake is irreversible: a version wrongly tagged `latest` cannot be untagged back into
non-existence — the best you can do is re-point `latest` at the older release, after every installer
in that window has already taken the new one.

The second half of this ticket is the guard, and it is the more valuable half. `bumpp` will happily
produce `0.10.0-alpha.0`, and `yarn pub` will happily publish it as `latest`. Nothing today notices
the contradiction.

## Design

### Where the tag comes from

`publish-package` resolves its tag from, in order of precedence:

1. `--tag <name>` on its own argv
2. the `SEREUS_DIST_TAG` environment variable
3. nothing — in which case npm's own default (`latest`) applies

Both forms are needed, and neither alone is enough:

- `yarn pub:cadre-core --tag alpha` works, because yarn appends script arguments to the end of the
  command.
- `yarn pub --tag alpha` **does not** work, and must not appear to. `pub` is a chain of six `&&`-ed
  commands, so appended arguments reach only the last one — `cadre-host` would be tagged `alpha` and
  the five before it `latest`. The environment variable is the form that works for the whole chain:
  `SEREUS_DIST_TAG=alpha yarn pub`.

Do not try to make `yarn pub --tag alpha` work by rewriting the chain; the env var is the honest
mechanism and the doc should say so plainly.

### The guard

Refuse to publish when the version in the package being published carries a semver prerelease
component (`semver.prerelease(version) !== null`) and the resolved tag is `latest` or absent. Fail
before `yarn npm publish` runs — ideally before `yarn clean && yarn build`, so a refusal costs
seconds rather than a full rebuild.

The error must name the version it read, and give the two ways forward:

```
@serfab/cadre-core@0.10.0-alpha.0 is a prerelease, but no dist-tag was given, so it
would be published as `latest` — the version `npm install @serfab/cadre-core` returns.
  Publish it under a tag:  SEREUS_DIST_TAG=alpha yarn pub
  Or, if `latest` really is intended:  SEREUS_DIST_TAG=latest yarn pub
```

`SEREUS_DIST_TAG=latest` is the deliberate escape hatch — an explicit `latest` is a decision, an
absent tag is an oversight, and the guard exists to tell them apart. Model it on the existing
`CADRE_HOST_ALLOW_PLACEHOLDER_KEY` escape in the same file.

`semver` is already a root devDependency (used by `scripts/check-dep-ranges.mjs`).

The inverse case — a *stable* version published under a non-`latest` tag — is legitimate (that is
how a fix gets to a `next` channel) and must not be refused.

### Module format

`scripts/publish-package.js` is the only script in `scripts/` still written as CommonJS; every other
one is `.mjs`, and the repo standard is ES modules (`AGENTS.md`). Testing the two decisions above
means exporting them, and a CJS file cannot be imported by the `.mjs` test convention every other
gate script follows. **Rename it to `scripts/publish-package.mjs`** and convert it.

The rename is already anticipated in one place: `scripts/lib/published-smoke-support.mjs:50` matches
`/publish-package\.(?:js|mjs)\s+(\S+)/`, so the smoke gate's publishable-set derivation survives it.
Other references that must move with it: the six `pub:*` scripts in the root `package.json`, the
usage string inside the file, `docs/cadre-host.md:430`, `docs/releasing.md`, and the fixture in
`scripts/smoke-published-install.test.mjs:66` (which spells `publish-package.js` — leave at least
one fixture on the old spelling, or add one, so that regex stays pinned in both directions).

### Tests

Follow the convention the smoke ticket's review established: pure decisions live where they can be
imported, and get a `scripts/<name>.test.mjs` of `node --test` cases wired into root `yarn test` as
`test:publish-package`. Keep the parts that shell out (`yarn clean`, `yarn build`,
`yarn npm publish`) out of the tested surface — export `resolveDistTag(argv, env)` and the
prerelease check as plain functions and test those.

Key cases, with expected outcomes:

- `--tag alpha` wins over `SEREUS_DIST_TAG=next` → `alpha`.
- `SEREUS_DIST_TAG=alpha` alone → `alpha`.
- Neither → no tag (and the published command carries no `--tag`, rather than an explicit
  `--tag latest`; publishing the first-ever version of a package with an explicit tag behaves
  differently from letting npm default).
- `--tag` as the final argument with no value → a loud error, not a silently absent tag. Same for
  `--tag ""`.
- An unrecognised flag → refused. (`smoke-published-install.mjs` already refuses unknown flags for
  this exact reason; match it.)
- Prerelease version + no tag → refused; + `--tag alpha` → allowed; + `SEREUS_DIST_TAG=latest` →
  allowed.
- Stable version + `--tag next` → allowed.
- Stable version + no tag → allowed (this is the ordinary path and must not regress).
- A version string semver cannot parse → a clear error naming the file it came from, not a silent
  pass.

## Edge cases & interactions

- **Partial-failure publish.** `yarn pub` is six sequential publishes. If the fourth fails, the
  first three are already on npm under the resolved tag and cannot be recalled. The guard must
  therefore fire *per package, before that package's build*, so a bad tag stops the chain at the
  first package rather than after five. Do not hoist the check into a one-time preflight that
  reads only the root manifest.
- **`SEREUS_DIST_TAG` leaking across a session.** An exported variable left in a shell would silently
  tag a later, unrelated release. The script should echo the tag it resolved (`Publishing cadre-core
  under dist-tag: alpha`) or, when there is none, say `under dist-tag: latest (npm default)` — so the
  operator sees it every time rather than only when they set it.
- **Interaction with the `cadre-host` release-key guard.** `assertReleaseKeyEmbedded` currently runs
  *after* `yarn build`. Two refusal paths in one script: keep them independent and make sure the
  prerelease guard's earlier position does not reorder or skip the key guard. A `cadre-host` publish
  with a placeholder key **and** an untagged prerelease should refuse for whichever reason it hits
  first, and still refuse for the other once that is fixed.
- **The smoke gate's publishable set.** `publishableWorkspaces` parses the `pub:*` script bodies. A
  `pub:*` body that grows a `--tag` argument must still parse to the same package name — the existing
  regex takes the first non-flag token after the script path, so `node scripts/publish-package.mjs
  cadre-core --tag alpha` is fine but `node scripts/publish-package.mjs --tag alpha cadre-core` is
  not. Pick the former ordering in any `pub:*` body, and add a fixture case pinning it.
- **knip.** `knip.ts` treats `scripts/*.mjs` as entry points and ignores that tree, so the rename
  needs no knip change — but `yarn dep-check` must be run to confirm, since the old `.js` entry may
  be reached by a different rule.
- **Cross-platform.** The script runs `execSync` with a string command; the argument is a tag name
  that now comes from user input. Reject anything that is not a plausible npm tag
  (`/^[a-z0-9][a-z0-9._-]*$/i`, and refuse a tag that is a bare semver version — npm itself rejects
  those) rather than interpolating it into a shell string unchecked.
- **Windows.** `docs/releasing.md`'s manual fallback uses `cd packages/<name> && …`; the env-var form
  is `SEREUS_DIST_TAG=alpha yarn pub` in POSIX shells and `$env:SEREUS_DIST_TAG='alpha'; yarn pub` in
  PowerShell. Document both — this repo's primary shell is PowerShell.
