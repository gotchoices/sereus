# The Strands screen

## Why

`feat-cadre-host-strand-api` puts `GET /api/strands` and `DELETE /api/strands/:id` on the
manager's local server. This ticket is the page an owner actually uses. Until it lands, leaving
a shared network means opening a terminal and running `cadre strand remove`.

## The screen

Nav item **Strands**, sixth in the top bar after Settings, hash route `#/strands`.

```
Strands
Shared networks this party takes part in. Leaving one takes your whole party out of it.
The other parties in that network are unaffected and keep running it.

┌──────────────────────────────────────────────────────────────┐
│  ● family-photos                        [Open]   running     │  [ Leave ]
│  ○ ledger-2024                          [Closed] not running │  [ Leave ]
└──────────────────────────────────────────────────────────────┘
```

Per row: the strand id in a monospace, selectable, wrapping element; an Open/Closed badge; the
run state (`running` plus the raw status when running, `not running` otherwise); a `Leave`
button.

Empty list: *"This party doesn't take part in any shared networks yet."*

**"Leave", not "Remove".** The removal deletes this party's row, and an owner reading "Remove"
next to a network name will hear "delete this network for everyone." The button, the dialog
title, and the toast all say leave.

## The confirmation

Two strengths, chosen by the strand's type.

**Open strand** — the existing `ConfirmDialog`, same as removing a trust-circle member:

> **Leave this shared network?**
> Every cadre node in your party will stop taking part in `<id>`. The other parties in that
> network are unaffected — this only removes yours. You can re-join later by publishing the
> strand again.
> `[ Cancel ]  [ Leave ]`

**Closed strand** — the same dialog with a **type-the-id-to-confirm** field:

> **Leave this closed network?**
> This is irreversible. `<id>` is a closed network, and your party's membership key for it is
> stored only in the row you are about to delete. Once it is gone your party can never admit
> another member to that network, and re-publishing the strand would create a *different* key
> that its existing members will not accept.
> Every cadre node in your party will stop taking part in it. The other parties in that network
> are unaffected.
> **Type `<id>` to confirm:** `[__________]`
> `[ Cancel ]  [ Leave ]` ← disabled until the typed text matches

The command line gates this behind an explicit `--yes` flag. A click-through checkbox is not the
same weight: the point of the flag is that the operator has to *do something extra and specific*.
Typing the id is the web equivalent (paste is fine — the goal is deliberateness, not recall).
The trade-off is real friction on a long id; it is bought deliberately, because the thing being
destroyed cannot be recreated.

## The durability warning

`GET /api/strands` returns `controlConnections`. It is advisory — right at read time, possibly
stale by the click — and both places it is used must read as advisory.

**Before**, when `controlConnections === 0`, an extra line in either dialog:

> ⚠ This machine currently has no connection to your other cadre nodes. If you leave now, they
> may keep running this network until they sync.

**After**, when the response comes back with `alone: true`, an inline banner on the page (not a
toast — a toast disappears in 6 seconds and this is the one message an owner may need to act on):

> You left `<id>` while this machine had no connection to your other cadre nodes. The removal is
> recorded here, but your other nodes may keep running it until they reconnect and sync.
> `[ Dismiss ]`

Otherwise a normal success toast: *"Left <id>"*.

## Wiring

- `lib/router.ts` — `'strands'` added to `RouteName`, a `case 'strands'` in `parseHash`, and a
  `hrefFor` arm.
- `App.svelte` — `NAV` entry, and a branch rendering `<Strands />`.
- `lib/state.svelte.ts` — a `StrandSummary` mirror type, a `strands: { list, controlConnections }`
  slice, `refreshStrands()`, and a `'strands-changed'` case in `applyEvent` that calls it.
- `lib/events.ts` — **already done** by the `feat-cadre-host-strand-api` review pass.
  `'strands-changed'` is in `EVENT_TYPES`, so the `EventSource` listener is registered and the
  event reaches `applyEvent`. (Without that entry the SSE event is dropped silently — a named SSE
  event only arrives for a name the client called `addEventListener` on. Nothing to add here; the
  note exists so the omission isn't re-introduced.)
- `lib/strand-confirm.ts` — the two pure predicates, so the rule is testable and out of the
  template:
  ```ts
  export function requiresTypedConfirmation(type: 'o' | 'c'): boolean;
  export function typedConfirmationMatches(expected: string, typed: string): boolean;
  ```
- `components/ConfirmDialog.svelte` — optional `requireText?: string` and
  `requireTextLabel?: string`. When `requireText` is set, render a labelled text input and keep
  the confirm button disabled until `typedConfirmationMatches`. Existing callers (two in
  `TrustCircle.svelte`) pass neither and must be unaffected.

**Do not add `refreshStrands()` to `App.svelte`'s global `onMount`.** Fetch on the page's own
`onMount`, the way `TrustCircle.svelte` does. On a donor-only install `/api/strands` 404s, and a
boot-time call would add a new error toast to every donor dashboard before the user has visited
anything.

## Known gap, deliberately not fixed here

On a donor-only install (`ownCadre.enabled` false — the default) the Strands nav item is visible
and the page 404s into an error toast on open. That is exactly what Trust Circle and Connectivity
already do; hiding founder-only pages is one problem with one fix, tracked in
`tickets/backlog/feat-cadre-host-donor-aware-ui` (an arm for Strands has been added to it).
Follow the existing pattern here — do **not** invent a second, page-local gating mechanism.

## Edge cases & interactions

- **Strand removed by another device while the dialog is open** → the response comes back
  `published: false`. Show *"`<id>` was already removed"* as an info toast, refresh the list, and
  do not show the alone-banner.
- **A 428 reaching the client.** Should not happen — the page confirms before sending — but if
  the flag is ever dropped, render the server's message rather than a generic "Leave failed".
- **Typed confirmation**: exact match after trimming both sides; paste allowed; the input must
  reset when the dialog closes and reopens (do not carry a stale match into the next strand);
  Enter submits only when the button is enabled; Escape still cancels.
- **Confirm button must be disabled while the request is in flight** — `ConfirmDialog`'s existing
  `pending` state already does this; make sure the new input path does not bypass it.
- **Long / opaque ids** must wrap rather than widen the layout, in both the row and the dialog.
  The mobile breakpoint (`max-width: 640px`) already applies to the page shell.
- **A strand that is published but not running** (filtered out, or a failed launch) still appears
  and is still leavable — that is the point of listing from the control database.
- **Empty and loading states** are distinct: an unfetched list is not "no strands".
- **Accessibility**: the confirm input needs a real `<label>`; the dialog already sets
  `aria-modal` and `aria-labelledby`. The Leave button needs an `aria-label` naming the strand,
  like `TrustCircle.svelte`'s Remove button does.
- **Two tabs open**: the `strands-changed` SSE event refreshes the other tab's list. The removing
  tab refreshes explicitly too — do not rely on the event for its own feedback.

## Test coverage, honestly

This package has **no Svelte component test harness** — `vitest.config.ts` runs in the `node`
environment and `ui/__tests__/` holds only plain-module tests (`api`, `events`, `router`). Do not
stand one up inside this ticket. What that leaves:

- `ui/__tests__/router.test.ts` — `#/strands` parses to `{ name: 'strands' }`, `hrefFor('strands')`
  round-trips, an unknown hash still falls back to home.
- `ui/__tests__/strand-confirm.test.ts` — `requiresTypedConfirmation('c')` true / `('o')` false;
  `typedConfirmationMatches` on exact, surrounding-whitespace, case-differing (must **not**
  match), empty, and substring inputs.
- The template itself — the dialog copy, the disabled-until-typed behaviour, the alone-banner —
  is covered only by the manual pass below. Say so plainly in the handoff; do not describe the
  screen as tested.
