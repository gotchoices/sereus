# `/api/strands` on the cadre-host management server

## Why

`feat-strand-admin-channel` puts `GET /admin/strands` and `DELETE /admin/strands/:id` on the
owner node's loopback channel. This ticket is the manager-side half: the client method, the
service that owns the error vocabulary, the HTTP routes the SPA will call, and the wiring.

No UI in this ticket — that is `feat-cadre-host-strand-removal-screen`.

## Shape

### `OwnerNodeClient` (`src/owner/owner-node-client.ts`)

Two methods alongside the existing ones, same `request()` helper:

```ts
listStrands(): Promise<{ strands: StrandSummary[]; controlConnections: number }>
removeStrand(strandId: string, opts: { confirm: boolean }): Promise<StrandRemovalResult>
```

`removeStrand` appends `?confirm=1` **only** when `opts.confirm` is true. It must never default
to true and never retry a rejected call with it added.

### `src/strands/` — a new subsystem folder

Mirrors the shape of `src/auth/` and `src/nat/` so `error-handler.ts`'s imports stay uniform.
There is **no host-local state** here (unlike the trust circle, which owns labels and pending
invites in `trust-circle.json`) — this layer exists for validation, error translation, and a
stable vocabulary, and should stay small.

`types.ts`:

```ts
export interface StrandSummary {
  id: string;
  type: 'o' | 'c';
  running: boolean;
  status: string | null;
}

export interface StrandListSnapshot {
  strands: StrandSummary[];
  /** Open control-network connections on the owner node; 0 ⇒ writes commit local-only. */
  controlConnections: number;
}

export interface StrandRemovalResult {
  strandId: string;
  published: boolean;
  type: 'o' | 'c' | null;
  removed: boolean;
  /** The node had no control connections at the write — the delete may not have travelled. */
  alone: boolean;
}

export type StrandErrorCode =
  | 'invalid_id'
  | 'confirmation_required'
  | 'node_unavailable'
  | 'internal';

export class StrandError extends Error {
  readonly code: StrandErrorCode;
  /* ...same shape as TrustCircleError */
}

export interface StrandHandlers {
  listStrands(): Promise<StrandListSnapshot>;
  removeStrand(strandId: string, opts: { confirm: boolean }): Promise<StrandRemovalResult>;
}
```

`strand-service.ts` — `StrandService` over a narrow `CadreNodeLike` declared in this module
(`{ listStrands, removeStrand }`), the third such trimmed interface `OwnerNodeClient` satisfies.
It validates the id and translates `OwnerNodeUnavailableError` by its `nodeCode`:

| `nodeCode` | becomes |
|---|---|
| `confirmation_required` | `StrandError('confirmation_required')`, message passed through |
| `bad_request` | `StrandError('invalid_id')`, message passed through |
| `not_ready`, `not_authorized`, absent (transport failure) | `StrandError('node_unavailable')` |
| anything else | `StrandError('internal')`, message passed through |

`OwnerNodeUnavailableError` is thrown for *every* non-ok admin response, so its name undersells
what it carries. Read `nodeCode` first and fall back to `node_unavailable` only when nothing
better fits — a 428 surfacing as "your node is down" would be actively misleading.

`index.ts` re-exports the above plus `createStrandHandlers(service): StrandHandlers`.

### `src/server/routes/strands.ts`

```
GET    /api/strands            → { ok: true, data: StrandListSnapshot }
DELETE /api/strands/:id?confirm=1 → { ok: true, data: StrandRemovalResult }
```

`/api/*` because this is a UI-only surface with no CLI contract to preserve — the `/auth/*`
mount exists only because the CLI already targeted those URLs. Envelope form follows the other
`/api/*` routes (`routes/nodes.ts`), not the bare-object form of `/auth/*`.

After a removal where `removed === true`, publish `{ type: 'strands-changed', kind: 'removed' }`
on the bus so other open tabs refresh. Do **not** publish when `published` was false — nothing
changed.

### Wiring

- `events/types.ts` — add `{ type: 'strands-changed'; kind: 'removed' }` to `LocalUiEvent`.
- `error-handler.ts` — a `STRAND_STATUS` map (`invalid_id` 400, `confirmation_required` 428,
  `node_unavailable` 503, `internal` 500), a `StrandError` branch in `classify`, and the code
  block added to the file's header comment.
- `server/index.ts` — an optional `strands?: StrandService` option, mounted next to the
  trust-circle mount and gated the same way. Founder-role only: in donor-only mode there is no
  owner node, so `/api/strands` stays unmounted and falls through to the static 404 handler.
- `bin/host.ts` — construct the service in the founder branch (near line 364, where
  `OwnerNodeClient` and `TrustCircleService` are built) and pass it to `createLocalUiServer`.
- `src/index.ts` — export `StrandService`, `StrandError`, `createStrandHandlers`, and the types.

## Design notes

**The confirmation rule is stated twice on purpose.** The node enforces it
(`feat-strand-admin-channel`) and the SPA asks for it (`feat-cadre-host-strand-removal-screen`);
this middle layer only forwards the flag. Do not add a third copy of "closed strands need
confirmation" here — the manager does not read the row and must not guess. It forwards what the
caller sent and surfaces the node's 428 when the node refuses.

**Not sharing `planRemove` with the CLI.** `packages/cadre-cli/src/commands/strands.ts` exports
`planRemove`/`applyRemove`, but they are not re-exported from cadre-cli's package entry, they
bundle CLI-flavoured prose (`✓`/`⚠` lines, `--yes` wording) into their return value, and
importing that module would pull `commander` into the manager process. cadre-host depends on
cadre-cli only to resolve its **bin path**, never its source, and that boundary is worth more
than deduplicating one `type === 'c'` predicate. The predicate now lives in exactly one
executable place — the node — which is the only place it can be enforced anyway.

**Strand ids containing `/`.** Not addressable through a path parameter. Reject them at the
service layer with `invalid_id` rather than inventing an encoding that only half works.

> **Corrected during the review of `feat-strand-admin-channel` (2026-08-03).** The admin channel
> does *not* have this limitation: `URL.pathname` leaves `%2F` encoded, so a percent-encoded id
> survives the segment split and `DELETE /admin/strands/ns%2Fstrand` removes `ns/strand`
> (covered by a test). Only a *literal* slash is refused there. So this layer may still refuse
> such ids if its own routing cannot carry them — but the refusal message must not claim the
> node cannot address them, and `cadre strand remove` is the fallback to name only if the
> manager genuinely cannot. Whichever way it goes, `OwnerNodeClient` must `encodeURIComponent`
> the id it puts in the admin URL, or an id with a `/`, `?` or `#` corrupts the request.

## Edge cases & interactions

- **Donor-only install** (`ownCadre.enabled` false): no `strands` option → `/api/strands` 404s
  through the static not-found handler. Assert it, alongside the existing `/auth/*` 404 assertion.
- **Blank / whitespace-only id** → `invalid_id` (400) with no call to the node.
- **Id containing `/`** → `invalid_id` (400), no node call.
- **Owner node down or mid-respawn** → transport error → `node_unavailable` (503), never a bare
  500. The endpoint getter (`() => orchestrator.getOwnerAdminEndpoint()`) returns undefined
  between respawns and `resolveEndpoint` already throws `OwnerNodeUnavailableError` for that.
- **428 must not be swallowed.** A `confirmation_required` from the node has to reach the client
  as 428 with the node's message, not as a generic failure — the screen renders a different
  dialog on it.
- **Absent strand** → 200 with `published: false`, `removed: false`, and **no** bus event.
- **Two managers removing the same strand at once** → both get 200; the loser's `removed: true`
  reflects the issued write, not an observed change. Same non-atomic window as the CLI; do not
  add a claim the layer cannot support.
- **`controlConnections` is a snapshot**, not a subscription — it is right at read time and may
  be stale by the time the user clicks. The screen ticket treats it as advisory.
- **Query param forwarding**: `confirm` is the only one; anything else on the request is ignored,
  not proxied.
