# Per-node reachability in the CLI and UI

Last of three (`cadre-host-nat-per-node-mappings` → `cadre-host-nodes-announce-public-addresses` → this). The service, routes and status model exist after the first ticket: `GET /nat/status` returns `nodes: NodeReachability[]` (verdict `mapped` / `manual` / `unreachable`, a plain-language `reason`, a `PortRoute` for `tcp` and `ws`, `publicAddrs`) plus `gateway.lanAddress`, and `PUT /nat/nodes/:nodeId/forward { tcp?, ws? }` (`null` clears) stores a manual forward. After the second ticket a changed forward restarts the node so it announces the new addresses (rate-limited to one restart per node per 10 minutes). `cadre-host-join-a-cadre` depends on this ticket and shows the same verdict next to its QR code.

## What to build

### CLI (`bin/host.ts`)

- `cadre-host nat status`: after the host-level lines (UPnP on/off, gateway found + LAN address, external IP, CGNAT, DDNS), one block per node: node id, verdict, and for each of TCP and WebSocket the internal port, the external port and its source, then the public addresses. For an `unreachable` node print the `reason` and the exact forward to make: "On your router, forward TCP port <internal> to <lanAddress>:<internal> (and WebSocket port …), then run `cadre-host nat forward <nodeId> --tcp <external> --ws <external>`." `--json` stays raw.
- New `cadre-host nat forward <nodeId> [--tcp <port>] [--ws <port>] [--clear-tcp] [--clear-ws] [--clear]` → `PUT /nat/nodes/:nodeId/forward`. Print the node's block from the returned snapshot. Note in the output that the node restarts to pick up the new address (it may wait up to 10 minutes if it was restarted for an address change recently).
- Error output for `404 unknown_node` names the node id and suggests `cadre-host nat status` to list ids.

### UI

- **Connectivity page**: keep the host-level panel (UPnP toggle, test button, DDNS form, CGNAT notice). Remove the single external-port field. Add a per-node table: node (id, and the grant label for a donated node where the page already has it), verdict badge, TCP and WebSocket rows showing internal → external port and source, public addresses (copyable). An `unreachable` row shows its `reason` in plain words and the forward to make, using `gateway.lanAddress`. Each row has an inline "I forwarded these ports" form (external TCP, external WebSocket, Save, Clear) calling the forward route.
- **Node detail page**: the same reachability block for that node, with the form.
- **Home**: the connectivity tile shows "N of M nodes reachable from outside" and links to Connectivity; it says plainly when none can be reached. Visible in every role.
- The page follows `connectivity-changed` and `node-state-changed` events, so a mapping that completes after a spawn, or a restart for new addresses, shows without reload.
- Keep `overall-status.ts` consistent: an unreachable node is a warning, not an error (the node still works on the LAN).

### Docs

- docs/cadre-host.md: under "NAT and DDNS", a "Manual port forwarding" subsection (which ports, forwarded to which LAN address, how to tell cadre-host, that the node restarts, that respawn keeps ports so a forward stays valid); the `/nat/nodes/:nodeId/forward` row in the API table; the per-node `connectivity-changed` behaviour in the SSE table if it changed.
- `packages/cadre-host/README.md`: the `nat` command reference (`nat status` output, `nat forward`), and the Connectivity page description.

## Edge cases & interactions

- A node with no `ws` port (handle from an older build): the WebSocket row reads "not available" and the form omits that field. By inspection.
- Gateway not found: the table still lists every node; the instructions use the LAN address from status, and when `lanAddress` is null they say "this machine's LAN address" rather than printing `null`. By inspection.
- CGNAT detected: unreachable rows say a router forward will not help and point to a relay (not available yet: `backlog/feat-cadre-host-children-reserve-on-a-relay`); the manual form stays available, since the CGNAT check can misfire. By inspection.
- Entering an external port outside 1–65535 or a non-integer: rejected in the form before sending; the route's `400` is shown if it gets through. By inspection.
- A node terminated while its row is open: the next status refresh drops the row; a save racing it gets `404` and shows a toast. By inspection.
- No new tests: UI component tests are tracked by `backlog/debt-cadre-host-ui-component-tests`; the CLI formatting is glue over the route.
