# sereus: `.gitignore` is missing the yarn-berry PnP artifacts

## Summary

After running `yarn install` in a fresh checkout of `gotchoices/sereus`, `git status` shows two yarn-generated files as untracked, indefinitely:

```
$ git status
…
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .pnp.cjs
        .pnp.loader.mjs
```

These are generated by every `yarn install` (because the repo uses Yarn Berry's default PnP linker via `packageManager: yarn@4.12.0` and no `.yarnrc.yml` override) and shouldn't be either tracked or visible in `git status`.

## Environment

| | |
| --- | --- |
| Repo | `gotchoices/sereus` |
| Commit | `66728c0521a95c5fdceb44d79f0bd346b6f4f966` (current `master`) |
| Yarn | `4.12.0` |

## Reproduction

```bash
git clone https://github.com/gotchoices/sereus.git
cd sereus
corepack enable
yarn install
git status
```

`.pnp.cjs` and `.pnp.loader.mjs` appear as untracked.

## Current `.gitignore` excerpt

```
.yarnrc.yml
.yarn
```

It covers `.yarn/` (cache directory) and `.yarnrc.yml` but not the two PnP files yarn writes at the repo root.

## Suggested fix

Add to `.gitignore`:

```
.pnp.*
```

That catches the current `.pnp.cjs` + `.pnp.loader.mjs` plus any future PnP-named variants without listing them individually.

Alternative (if the project ever wants to opt into Yarn Berry's "zero-installs" model): commit the PnP files instead of ignoring them, and document that choice. But the current state — neither tracked nor ignored — is the worst of both worlds.

## Impact

Low. This doesn't break any build, just pollutes `git status` output indefinitely and risks an accidental `git add .` committing PnP files into the repo. The user-side workaround (adding to `.git/info/exclude` locally) shouldn't be necessary.

## Sibling repos

The same fix likely belongs in `gotchoices/quereus` and `gotchoices/optimystic`, which use the same Yarn Berry setup. I haven't reproduced there but `git status` after `yarn install` in either would tell quickly.
