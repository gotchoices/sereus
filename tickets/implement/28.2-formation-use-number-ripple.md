# Sweep the readers of the dropped `FormationUsage.UseNumber` column

`formation-unique-token-redesign` drops `FormationUsage.UseNumber` and makes `UsageStampId` the
row key. Nothing here breaks the TypeScript build — every remaining reference is inside a SQL
string or a value typed from a `row.X as number` cast — so `yarn lint` and `yarn build` will not
catch these. They fail at runtime, or silently render a column of `undefined`.

## What to change

`packages/reference-app-web/src/lib/cadre-web.ts`

- `FormationUsageRow` (~line 135): `useNumber: number` → `usageStampId: string`.
- The diagnostics query (~line 696): `select Token, UseNumber, StrandId` →
  `select Token, UsageStampId, StrandId`, and map `usageStampId: row.UsageStampId as string`.

`packages/reference-app-web/src/Diagnostics.svelte` (~lines 199-202)

- Keyed-each key `use.token + ':' + use.useNumber` → `use.usageStampId` (it is unique on its own
  now — it is the primary key).
- The rendered line `· use #{use.useNumber} → strand {…}` shows a sequence number that no longer
  exists. Render a short prefix of the stamp instead (the full value is a long base64url nonce
  and would wreck the layout) — e.g. `· {use.usageStampId.slice(0, 12)}… → strand {…}`.
  `data-testid`/`data-count` attributes stay as they are.

`packages/reference-app-web/e2e/fixtures/formation-responder.ts` (~lines 104, 325-333)

- The `readFormationUsage()` handle type and its implementation: `useNumber: number` →
  `usageStampId: string`, query `select Token, UsageStampId, StrandId`.
- `packages/reference-app-web/e2e/distributed/formation-convergence.spec.ts` calls this at
  ~lines 137/198/224/242 but only reads lengths/tokens today — confirm with a grep that no
  assertion touches the renamed field, and leave it alone if none does.

`packages/integration-tests/src/scenarios/strand-formation-e2e.integration.ts` (~line 215)

- Comment only: "If a case ever reads back a multi-use token, select the `UseNumber` it means
  rather than trusting scan order" → select by `UsageStampId`. The scenario's query already
  selects `UsageStampId` and no code changes.

## Edge cases & interactions

- **Nothing else reads the column.** Before finishing, run
  `grep -rn "UseNumber\|useNumber" packages docs schemas --include=*.ts --include=*.svelte --include=*.qsql --include=*.md`
  (excluding `node_modules` and the `reference-app-*` build output directories, which contain
  stale bundled copies and are not source) and expect zero hits. A stale build artifact under
  `packages/reference-app-ns/platforms/**` or `packages/reference-app-rn/android/**` is not a
  source file — do not edit those.
- **The diagnostics panel is asserted by `data-testid`, not by its text.** Changing the rendered
  string is safe, but re-check `packages/reference-app-web/e2e` for any assertion matching on
  `use #` before changing it.
- **Two rows can now share a token in the diagnostics list.** That was already true (a multi-use
  invite), but the old `token:useNumber` each-key hid it. `usageStampId` alone is unique; do not
  compose a key out of token + index.
