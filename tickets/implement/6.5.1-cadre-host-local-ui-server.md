## Scope

Stand up the long-lived management server that `cadre-host start` (added in `6.4.1-cadre-host-installer`) launches:

1. Fastify bound to `127.0.0.1:<uiPort>` only.
2. Strict origin guard (defeat DNS-rebind from another origin).
3. The three existing handler factories (`createTrustCircleHandlers`, `createNatHandlers`, `UpdateService` routes from `6.4.2`) wired in at their existing mount points.
4. New `/api/*` routes covering the gaps the local UI needs: overall status, per-node detail (stats + log tail + start/stop/restart), and host-level settings.
5. A Server-Sent Events bus at `GET /api/events` that lets the SPA reflect state changes without polling.
6. Static-asset mount at `/` that serves the SPA bundle produced by `6.5.2-cadre-host-local-ui-spa` (this ticket lands a stub that returns the install URL if the bundle isn't present yet, so the server is testable in isolation).

The Svelte SPA ships in the sibling ticket. The two land separately so the server can be tested with `curl` / `vitest` and the SPA can develop against a recorded fixture if needed.

## Design decisions (pinned from plan)

- **API path scheme.** Keep the existing `/auth/*` (trust-circle) and `/nat/*` (NAT/DDNS) mounts — they are the public contract today (cadre-host CLI talks to them, see `packages/cadre-host/src/bin/host.ts`). `6.4.2` adds `/update`, `/update/apply`, `/update/settings`. New UI-only routes go under `/api/*`. The SPA consumes both; the CLI doesn't break.
- **Origin defense.** Fastify `onRequest` hook that rejects unless `Host` is `127.0.0.1:<port>` or `localhost:<port>` (case-insensitive, optional `:port` for default ports). Also asserts `Origin`, when present, matches one of those origins. Bad origin → 403 `{ ok: false, error: { code: 'forbidden_origin', message } }`. The listener never binds to `0.0.0.0`; this is belt-and-braces against a browser hitting the loopback port from a malicious page.
- **Reactive updates: Server-Sent Events.** `GET /api/events` returns `text/event-stream`. Event types: `node-state-changed`, `trust-circle-changed`, `connectivity-changed`, `update-available`. Internal `EventBus` (tiny EventEmitter wrapper) is the publisher; trust-circle / NAT / orchestrator / update service all push through it. Re-publishes from outside helpers (e.g. `TrustCircleService.issueInvite` was completed) happen via lightweight bus calls from the route handlers — we don't retrofit observability into the libraries themselves. Heartbeat comment every 15 s keeps the connection alive through corporate proxies.
- **Error shape.** New `/api/*` routes return `{ ok: false, error: { code, message } }` on failure (matches cadre-provider — see `packages/cadre-provider/src/server/routes.ts:40`). A single Fastify `setErrorHandler` maps `TrustCircleError` / `NatError` instances by `.code` → HTTP status (per the integration contract recorded in `tickets/complete/6.2-cadre-host-trust-circle.md` and `tickets/complete/6.3-cadre-host-nat.md`), unknown errors → 500 with `code: 'internal'`. Status mapping:
  - trust-circle: `invalid_label|invalid_token|invalid_peer_id` → 400, `unknown_token|unknown_member|already_redeemed` → 404 (404 for already_redeemed so the CLI's idempotent revoke works), `storage_error` → 500.
  - NAT: `invalid_config|ddns_provider_unknown|ddns_credentials_missing` → 400, `secrets_unavailable|storage_error` → 500.
- **Static-asset mount.** `@fastify/static` rooted at `<package>/dist/ui` (gitignored — produced by 6.5.2's Vite build). If the directory is missing (e.g. running from source before the SPA build), the root handler returns a placeholder HTML pointing at the docs. Implementer note: `@fastify/static` registers the SPA fallback route — `index.html` for any unknown GET that accepts `text/html`. API paths take precedence because Fastify matches in registration order; mount `@fastify/static` last.
- **Port-collision fallback.** Try the configured port. On `EADDRINUSE`, try `port+1` through `port+9`. Persist the chosen port to `host.config.json` (extends the `6.4.1` config writer with a `lastBoundUiPort` field — but the *configured* `uiPort` doesn't change; this is just a memo so subsequent boots try the previously-working port first). On total failure, exit non-zero with a clear message including which ports were tried.
- **No login, no roles.** Same-machine access is auth. The README and `docs/cadre-host.md` re-state the threat model: any local process can fully control cadre-host; harden the host OS, not this listener.
- **Browser auto-open is the installer's job, not the server's.** This ticket only adds a `cadre-host ui` CLI subcommand that prints the URL and opens it (reusing `installer/browser.ts` from 6.4.1).

### `createLocalUiServer` surface

```ts
export interface LocalUiServerOptions {
  /** Configured UI port. May be re-bound if occupied; the chosen port is in start()'s return value. */
  uiPort: number;
  /** Resolved data dir (passed by `cadre-host start` from host.config.json). */
  dataDir: string;
  /** Wired dependencies — all owned by `start`, not by this server. */
  orchestrator: HostProcessOrchestrator;
  trustCircle: TrustCircleService;
  nat: NatService;
  update?: UpdateService;          // optional — 6.4.2 lands this; allow null while still iterating.
  /** Settings writer (writes to host.config.json; passed in for testability). */
  settingsStore: HostSettingsStore;
  /** Bus instance — caller may share with subsystems so they can publish too. */
  events?: EventBus;
}

export interface LocalUiServer {
  app: FastifyInstance;
  events: EventBus;
  /** Resolves with the actually-bound port. */
  start(): Promise<{ port: number; url: string }>;
  stop(): Promise<void>;
}
```

`HostSettingsStore` is a tiny new helper that reads/writes the `host.config.json` file landed by `6.4.1-cadre-host-installer`. Lives in `src/server/settings-store.ts` to keep the installer file untouched; both modules read the same v1/v2 schema. Whitelist for PUT: `uiPort` (rejected — must be edited at install time), `libp2pPort` (rejected — restart required), `upnpEnabled` (accepted, propagated via `NatService.putSettings`), `updates.autoApply` (accepted, propagated via `UpdateService` if present). Anything else → 400 `invalid_setting`.

### `EventBus`

```ts
export type LocalUiEvent =
  | { type: 'node-state-changed'; nodeId: string; status: ContainerStatus }
  | { type: 'trust-circle-changed'; kind: 'invited' | 'redeemed' | 'revoked' }
  | { type: 'connectivity-changed'; portMode: PortForwardMode; directReachability: DirectReachability }
  | { type: 'update-available'; version: string; releaseNotesUrl?: string };

export class EventBus {
  publish(event: LocalUiEvent): void;
  subscribe(listener: (event: LocalUiEvent) => void): () => void; // returns unsubscribe
}
```

Publishers:

- **Orchestrator** — `HostProcessOrchestrator` already emits state transitions internally; add a thin adapter in `routes/nodes.ts` that polls or subscribes (depending on what the orchestrator surface exposes — verify against `packages/cadre-host/src/orchestrator/host-process-orchestrator.ts`; add an `on('state', cb)` hook if not present and propagate to the bus). If adding listeners requires changing the orchestrator, do it minimally — single new `on/off` pair, no event-emitter base class.
- **Trust-circle** — published from the route wrappers (POST invite → publish `invited`, DELETE invite → `revoked`, etc.). No changes to `TrustCircleService`.
- **NAT** — `NatService` already snapshots state; publish `connectivity-changed` from the `/nat/settings` and `/nat/test` route wrappers, plus a one-shot publish from `start()` after the initial NAT bring-up.
- **Update** — `UpdateService` exposes `getState()`; publish `update-available` from the route wrappers when the apply state transitions and from a thin observer in `start()` (compares previous state on a 60 s tick — cheap, avoids touching the service surface).

The bus is in-memory only. Multiple SPA tabs each get their own `EventSource` subscription; the route holds the subscription open and writes back on `publish`.

### SSE route

```
GET /api/events
Accept: text/event-stream

retry: 5000
: heartbeat
event: node-state-changed
data: {"nodeId":"abc","status":"running"}

event: trust-circle-changed
data: {"kind":"invited"}
```

Heartbeat comment `: heartbeat\n\n` every 15 s. Closes cleanly on client disconnect (`request.raw.on('close', cleanup)`). Origin guard runs before this handler.

### `/api/status` shape

```ts
interface StatusResponse {
  service: { name: 'cadre-host'; version: string; uptimeSeconds: number };
  nodes: Array<{ id: string; partyId: string; status: ContainerStatus; profile: 'storage' | 'transaction' }>;
  trustCircle: { members: number; pending: number };
  connectivity: NatStatusSnapshot;    // re-export from @serfab/cadre-host/nat
  update?: { available?: string; lastChecked?: string };
}
```

All fields populated from in-memory subsystem state — no disk reads on each call. Should respond in < 5 ms.

### `/api/nodes/:id/logs` shape

Tails `<dataDir>/orchestrator/<id>/node.log`. Default `lines=200`, max `lines=2000`. If the file is missing (e.g. node was never started), return `{ ok: true, data: { lines: [] } }`. Read backwards with a small buffered tail (no external deps; ~30 lines of code).

### CLI `cadre-host ui`

New subcommand in `src/bin/host.ts`:
```
$ cadre-host ui
http://127.0.0.1:8765
(Opening in your default browser...)
```
- Reads the resolved port from `host.config.json` (same resolution as `cadre-host install`).
- Calls `openInBrowser(url)` from `src/installer/browser.ts` (added by `6.4.1`).
- Doesn't require the cadre-host service to be running — just prints + opens. If the server isn't up, the browser will fail to connect; that's fine and obvious.

### Integration with `cadre-host start`

`6.4.1`'s `start` bootstraps the orchestrator / trust-circle / NAT, mounts `/auth/*` and `/nat/*`, then leaves a `TODO(cadre-host-local-ui)` marker. This ticket fills that in:

```ts
const settingsStore = new HostSettingsStore({ dataDir });
const server = createLocalUiServer({
  uiPort: config.uiPort,
  dataDir,
  orchestrator,
  trustCircle: trustCircleService,
  nat: natService,
  update: updateService,        // may be undefined if 6.4.2 lands after this
  settingsStore,
});
const { port, url } = await server.start();
console.log(`cadre-host local UI: ${url}`);
```

Shutdown wiring: `process.on('SIGINT', () => server.stop().then(() => process.exit(0)))`. Mirror the pattern from `cadre-provider/src/server/server.ts:122` (drain timeout 5 s, idempotent, exit code 0 on clean drain).

## Tests

- `origin-guard.test.ts` — accepts `127.0.0.1:8765`, `localhost:8765`; rejects `evil.example.com`, missing-Host, port-mismatch. Origin header (when present) double-checked.
- `error-handler.test.ts` — throw `TrustCircleError('unknown_token', ...)` from a fake route → 404; `NatError('secrets_unavailable', ...)` → 500; unknown `Error` → 500 with `code: 'internal'`; payload shape exactly `{ ok: false, error: { code, message } }`.
- `sse-route.test.ts` — subscribe via real EventSource (use `eventsource` npm in devDependencies, or a tiny custom client over `undici`), publish three events, assert each arrives in order; close client → server unsubscribes (assert internal listener count drops).
- `status-route.test.ts` — populate fakes for all subsystems, assert response shape and that nothing throws when `update` is absent.
- `nodes-route.test.ts` — start/stop/restart each call the orchestrator and publish a bus event; logs route returns the right number of lines from a tmpdir log file; unknown nodeId → 404.
- `settings-route.test.ts` — PUT a whitelisted key → propagated to subsystem; PUT a forbidden key (`uiPort`) → 400 `invalid_setting`; the v1/v2 host.config.json migration runs once on first read.
- `server.smoke.test.ts` — boot the server in-process with fake subsystems, exercise an end-to-end flow: GET `/api/status`, POST `/auth/invites` (existing handler), GET `/auth/trust-circle` reflects the new invite, SSE subscriber sees `trust-circle-changed`. Bind to port 0 (let the OS pick) to avoid CI collisions, then read the chosen port from the start() result.

## SSE plugin decision

`@fastify/sse-v2` adds 30 KB and one dep; hand-rolled SSE is ~40 lines (set Content-Type, write event frames, heartbeat interval, unregister on close). **Recommendation: hand-roll.** Matches the project's "no extra deps for one place" pattern (cf. 6.4.2's hand-rolled canonical JSON and 6.4.1's hand-rolled browser-open). Less surface to maintain; the SSE wire format is trivial.
