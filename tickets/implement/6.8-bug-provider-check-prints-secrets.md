## Status: the fix has already landed

Commit 2bef08fa (ticket `provider-config-strict-validation`) added `redactConfigSecrets` in `packages/cadre-provider/src/config/loader.ts`. It replaces `billing.stripeSecretKey`, `billing.stripeWebhookSecret` and every push `fcm.privateKey` / `apns.privateKey` (through `redactPushConfig` in `config/validate.ts`) with `[redacted]`. Both callers use it: the debug dump in `loadConfig`, and the `check` command in `src/bin/provider.ts`. That meets the ticket's requirement that one function covers both outputs.

Confirmed during fix by running the built CLI, `node packages/cadre-provider/dist/bin/provider.js check -c <file>`, on a config that set all four secrets (with `auth.mode: api-key`). The output showed `[redacted]` for each of the four, and a grep of the output for the planted secret values found nothing.

## Remaining gap

`src/config/__tests__/push-validate.test.ts` tests `redactPushConfig` only. Nothing tests the Stripe arm of `redactConfigSecrets`. A refactor could drop it without any test failing, and `check` would leak the Stripe keys again.
