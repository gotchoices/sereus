## The gap (original spec — still authoritative)

An invitation may carry a `ValidationUrl`. The control database enforces it: when
`FormationInvite.ValidationUrl` is non-null, `FormationUsage.Authorized` requires a signature
from an enrolled `ValidationKey` over
`formationVouchMessage({ token, usageStampId, strandId, peerId, disclosure })`. No production
code path supplies one, so redeeming such an invitation fails with
`CHECK constraint failed: Authorized`. The invitation is unusable, and the party that configured
it has locked its own network rather than gated it.

`feat-formation-approval-client` built the client surface; the recorder now calls it (landed
this run). The approval fetch lives INSIDE `ControlFormationUsageRecorder` (settled: the
recorder is the only place where "the nonce we signed" and "the nonce we insert" are trivially
the same value). The manager's remaining job is (a) serialize the disclosure once and pass it
down, and (b) translate approval failures into rejection reasons — Phase 3 above.

## Edge cases & interactions (unchanged from original spec)

- **Approval refused / hook unreachable** — clean `approved: false` with the mapped reason, no
  `FormationUsage` row, invite still redeemable afterwards. Assert the use count is unchanged.
- **Non-enrolled key** — must produce `'Formation approval key is not enrolled'`, NOT
  `'Formation conflict, retry'`; that mis-mapping is the opaque failure this ticket removes.
- **Approval signed over different fields** — caught by the local verify, mapped to
  `'Formation approval invalid'`, no write attempted.
- **Nonce mismatch between sign and insert** — assert directly (read `UsageStampId` back and
  compare to the value the fake approver saw).
- **Invite with no `ValidationUrl`** — approver not called at all; redemption unchanged except
  `Disclosure` now carries the real text.
- **Concurrent redemption of a single-use `ValidationUrl` invite** — the loser's approval is
  spent; acceptable now; the `NOTE:` at the retry mapping covers it (no new ticket).
- **Bound invite whose host strand is `missing`** — unchanged: reject before any hook call.
- **Disclosure over the cap** — rejected before the hook call and before any database read.
- **Hook latency vs. session budgets** — the approval fetch (10 s) sits inside the responder
  provisioning budget (12 s); the 6 s slow-approver test confirms.
- **`Disclosure` is attacker-influenced text in a replicated table** — the 8 KiB cap is the
  bound. Nothing parses the column; do not add parsing.
- **`isTokenUsed` raced by the hook window** — do NOT add a second pre-write `isTokenUsed`
  check; it cannot close the race. The PK-collision path must stay a clean rejection.
