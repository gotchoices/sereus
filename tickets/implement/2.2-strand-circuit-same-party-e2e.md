## Why

No strand (per-app shared network) has ever been carried over a circuit relay: every
strand mesh in the suite forms over direct loopback WebSocket addresses, and the only
`/p2p-circuit` strand test (`packages/cadre-core/test/strand-transport-relay.spec.ts`)
uses bare libp2p nodes with fabricated protocols — not one byte of strand data crosses
the circuit, and nothing proves a peer can *learn* a strand node's relayed address.
Meanwhile the machinery is believed complete: strand nodes inherit per-relay
`<relay>/p2p-circuit` configured listeners (`relay-addrs.ts:23-27` — libp2p reserves
from inside `listen()`), the strand-addr RPC (`/sereus/strand-addr/1.0.0`) returns
live strand multiaddrs signaling-first, and its client dials over limited (relayed)
connections. This ticket is the proof, plus whatever product fixes fall out.

Same-party only — both nodes belong to one party, so the control mesh and the
strand-addr RPC (which is membership-gated) work as designed. Cross-party is
`formation-carries-strand-addrs` / `blind-relay-phone-to-phone-e2e`.

## Build

**1. Harness dedicated-relay fixture** (new file under
`packages/integration-tests/src/harness/`, e.g. `dedicated-relay.ts`): a bare
`createLibp2p` node mirroring the ops relay container
(`ops/docker/libp2p-infra/src/main.ts`): `circuitRelayServer` with
`reservations: { applyDefaultLimit: false, maxReservations: <generous> }`, stock
`identify` + `ping`, WebSocket listener on loopback. `applyDefaultLimit: false` is
load-bearing: db-p2p's database protocols do not set `runOnLimitedConnection`, so a
relay that applies libp2p's default 128 KiB / 2 min limit kills every strand data
stream. Expose the relay's dial addr and its live reservation count (for assertions).
Note in the fixture doc that it must stay config-parity with the ops container.

**2. Scenario** (new file, modeled on
`strand-addr-seed-convergence.integration.ts` which already proves RPC-only seeding
without hand-dials): one party, two `CadreNode`s A and B, **both** relay-only —
`listenAddrs: []`, `relayAddrs: [<dedicated relay>]` — so *neither* end is directly
dialable (a shape no existing test covers even on the control network). The dedicated
relay is ungated and speaks no strand-addr protocol, so no delegate-admission grant is
needed (`cadre-node.ts` folds the per-relay announce failure to a no-op). Then:

- control mesh forms over the relay (both control nodes reserve via the search route);
- A founds a strand, B discovers/launches it, seed resolved via the strand-addr RPC —
  **no hand-dial anywhere**;
- assert each strand node's `getMultiaddrs()` contains a `/p2p-circuit` address
  (i.e. the strand node's configured-route reservation actually landed);
- assert the strand-network connection between A and B is classified `relayed` by
  `summarizeConnectionPaths` (`packages/cadre-core/src/diagnostics/connection-path.ts`)
  — so a direct fallback cannot pass for relayed success;
- write rows on A, read on B (and reverse) over the circuit;
- record the relay's reservation count (expect 4: two control + two strand) — this is
  the first measurement of the per-strand relay-slot cost the plan ticket asked for.

## Edge cases & interactions

- **Both ends unreachable on the control network** — previously unproven; if the
  control half fails, that is in-scope fallout.
- **Strand launch when the relay is down**: the configured circuit listener dials from
  inside `libp2p.start()`, so the strand launch fails and `StrandWatcher` retries with
  backoff. Characterize and document; do not redesign here.
- **Reservation loss** (relay restarts while the strand runs): characterize whether
  libp2p's configured-route listener re-reserves on its own. Strand nodes have no
  supervisor equivalent to the control node's `superviseRelayReservation`
  (`relay-reservation.ts`). If recovery is broken, file a backlog ticket with the
  measurement — only fix inline if trivially small.
- The strand-addr RPC answer must be dialable *by the asker*: both sides sit on the
  same relay here, so the circuit addr works; assert the returned addrs actually
  include the `/p2p-circuit` entry first (signaling-first ordering).
- Test timing: circuit setup is slower than loopback; use the harness's existing
  `waitUntil` patterns, no bare sleeps.
