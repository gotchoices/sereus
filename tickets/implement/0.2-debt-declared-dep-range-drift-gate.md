# Gate: declared dependency ranges must cover the linked workspace versions

## Status: implemented and verified during the fix-stage pass — this ticket is a final-check handoff

The fix-stage research for this ticket produced a complete, working, tested implementation
directly (the fix was concrete and small enough that writing it was the fastest way to validate
the hypothesis). Nothing here is designed-but-unbuilt; the TODOs below are verification, not
construction.

## What was built

- **`scripts/check-dep-ranges.mjs`** — the gate script. For every entry in root `package.json`'s
  `resolutions` whose target is a `link:` path (e.g. `link:../optimystic/packages/db-core`), it
  reads that linked sibling workspace's own `package.json` to get its real version. It then walks
  every `packages/*/package.json` and checks each `dependencies` / `peerDependencies` /
  `optionalDependencies` entry that names one of those linked packages, using `semver.satisfies`
  to confirm the declared range admits the linked version.
  - Generic over whatever is in `resolutions` — not hardcoded to `@optimystic/*` — so it also
    covers `@quereus/quereus` and any future linked package for free.
  - Uses `semver.gtr` / `semver.ltr` to report *which direction* a mismatch drifted: declared range
    too old (excludes a newer linked version — the direction that ships an untested substrate to
    consumers) vs. declared range newer than the linked workspace (local dev behind what's
    promised). Both cases exist in this repo's history (`^0.16.3` excluding a linked `0.17.0` is
    exactly what recurred twice — see `docs/STATUS.md` "Declared dependency range vs linked
    workspace").
  - Prints an exact suggested edit (`^<linked version>`) per failure; does not auto-fix.
  - If a linked sibling workspace directory doesn't exist (e.g. a clean CI clone with no
    `../optimystic` checkout), that resolutions entry is skipped with a logged `skip: ...` line
    rather than failing the gate.
  - Supports `DEP_RANGE_CHECK_ROOT` env override so tests can point it at a throwaway fixture
    workspace instead of this repo.
- **`scripts/check-dep-ranges.test.mjs`** — 5 cases using Node's built-in test runner
  (`node --test`) against disposable fixture workspaces (`os.tmpdir()`, cleaned up after each
  run): the 0.x-caret-excludes-newer-version direction, the 1.0+-caret-admits-newer-minor
  direction (proving no false positive across the semver 1.0 boundary), the inverse "declared
  newer than linked" direction, the absent-sibling-workspace skip, and a clean pass.
- **Wiring** (`package.json`):
  - `"dep-check": "knip && yarn check:dep-ranges"` — the check now runs as part of the existing
    dependency gate, not a script someone has to remember to invoke.
  - `"check:dep-ranges": "node scripts/check-dep-ranges.mjs"` — standalone invocation.
  - `"test": "yarn workspaces foreach -A run test && yarn test:dep-ranges"` and
    `"test:dep-ranges": "node --test scripts/check-dep-ranges.test.mjs"` — the gate's own tests run
    under the standard `yarn test` entry point too.
  - Added `semver` (`^7.7.3`, matching the range already used transitively elsewhere in
    `yarn.lock`) as an explicit root `devDependency` rather than relying on it being hoisted.
- **`docs/STATUS.md`** — the existing "Declared dependency range vs linked workspace" section now
  documents the gate and its test coverage, so the drift narrative and the fix for it live in the
  same place.
