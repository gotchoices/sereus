# Subscription state and termination for non-payment

Third ticket of the `provider-client-and-sign-up` chain. The app side that shows these fields is `reference-app-rn-rents-a-provider-node`.

## What exists

`CustomerBilling` (`types.ts`) has `planId`, `balanceCents`, `paymentMethodId`, `currentPeriodStart`, `currentPeriodEnd`. `BillingService` meters usage, enforces `maxContainers` in `canCreateContainer`, and offers `BillingHooks` (`processPayment`, `getPaymentMethod`, `sendInvoice`) for the operator's payment processor. Nothing records a subscription's standing, and nothing ever stops a container except the customer's `DELETE`.

## Types

```ts
export type SubscriptionStatus = 'active' | 'past-due' | 'lapsed';

export interface Subscription {
  status: SubscriptionStatus;
  /** When the current period renews; null once lapsed. */
  renewsAt: Date | null;
  /** past-due only: when the grace period ends and the customer's nodes are stopped. */
  lapsesAt: Date | null;
}

// CustomerBilling gains:
subscription: Subscription;

// Container gains:
/** Why a stopped container was stopped; absent while it runs. */
stopReason?: 'customer' | 'non-payment';
```

`initializeCustomer` writes `{ status: 'active', renewsAt: currentPeriodEnd, lapsesAt: null }`.

## Service

- `BillingService.updateSubscription(customerId, patch: Partial<Subscription>)`: the one write the operator's payment webhook calls (Stripe `invoice.paid` → `active` with the next `renewsAt`; `invoice.payment_failed` → `past-due` with `lapsesAt` at the end of the operator's grace period; `customer.subscription.deleted` → `lapseSubscription`). It only writes fields; no payment logic lives in the provider.
- `BillingService.lapseSubscription(customerId)`: marks `lapsed` (`renewsAt` and `lapsesAt` null) and terminates every quota-consuming container of that customer through `ContainerService.terminateContainer(id, { reason: 'non-payment' })`, one at a time, logging and continuing on a failure. `BillingServiceOptions` gains `containerService`; `createProviderServer` wires it (ContainerService does not depend on BillingService, so there is no cycle).
- `terminateContainer(id, options?: { reason?: 'customer' | 'non-payment' })` stamps `stopReason` on the `stopped` write; the `DELETE` route passes `customer`. The reap sweep's `stopping` path keeps whatever reason the record already has.
- The billing tick (the usage-collection interval) also runs `lapseOverdue()`: every `past-due` record with `lapsesAt <= now` is lapsed. `BillingServiceOptions` gains `now?: () => Date`, as `ContainerService` has.
- `canCreateContainer` refuses a `lapsed` customer with "Subscription lapsed". `past-due` still creates (the grace period is the operator's call).
- `GET /billing/status` returns the record with `subscription`; `GET /containers/:id` and the list carry `stopReason` through `redactContainer` unchanged (it is not a secret).

## Edge cases & interactions

- A lapse while a container is `enrolling` or `creating`: `terminateContainer` moves it to `stopping` and the enrolment waiter bails on the status change, as it does for a concurrent `DELETE`. By inspection of `waitForEnrollment`.
- A lapse while a terminate is already failing (`error` record): the record is not quota-consuming, so it is skipped; a container that is still up with an `error` record is the existing accepted trade at `terminateContainer`'s catch. No change.
- `updateSubscription` to `active` after a lapse does not restart stopped containers: the volume is gone with the container (`removeContainer`), so a renewed customer rents again. The README says so.
- Two ticks racing on one customer: `lapseSubscription` re-reads the record and returns when it is already `lapsed`. By inspection, with a comment.
- A customer with no billing record (billing disabled, or a static admin key) has no subscription; `canCreateContainer` already allows them and `GET /billing/status` answers `billing: undefined` as today.

## Tests

- `billing-quota-statuses.test.ts` (extend): a `lapsed` customer cannot create; `past-due` can.
- New `billing-lapse.test.ts`: `lapseSubscription` stops the customer's running containers with `stopReason: 'non-payment'` and leaves another customer's running; a `past-due` record whose `lapsesAt` is before the injected `now` is lapsed by `lapseOverdue()`, one whose `lapsesAt` is later is not.
