# React Native reference app: owner keys

The kit calls exist after `phone-and-web-kits-hold-a-separate-owner-key` (`listOwnerKeys`, `addBackupOwnerKey`, `exportOwnerKey`, `importOwnerKey`, `planOwnerKeyRemoval`, `removeOwner`). This ticket is the Settings UI and the wording changes, in `docs/reference-app-rn.md` first and then in code.

## Settings → Owner keys (new section, below Devices and nodes)

- **List** (`listOwnerKeys`): one row per live owner key — its label (or "Unnamed key"), the 8-character fingerprint the app already shows elsewhere (`node-claim.ts` `ownerFingerprint`), "This device" when `heldHere`, and "Not trusted here" when it is not in this phone's anchor.
- **Make a backup key** (owner only): asks for a name (default "Backup"), offers "Protect with a passphrase" (on by default; two entry fields), then `addBackupOwnerKey` and shows the export once — as a QR code (`share-code.tsx`) and as text with Copy / Share. Above it, plainly: "Anyone who has this can control your cadre. Keep it somewhere safe and offline. This phone does not keep a copy." A Done button closes it; it is not shown again.
- **Export this device's key** (when this device holds one): same screen and warning, `exportOwnerKey`.
- **Import an owner key**: paste or scan (`code-scanner.tsx`), passphrase if locked, `importOwnerKey`. Outcomes: wired (this device is now an owner); stored but not an owner of this cadre ("This key is not an owner of this cadre. An owner can add it."); refused because the device already holds a different key; wrong passphrase. The scanner and paste field must refuse an invitation or join request here by name, and the invitation fields must refuse an owner key (the decoders do this; show their message).
- **Remove** (owner only, not on this device's own key — "A device cannot remove its own owner key; use another owner key"): `planOwnerKeyRemoval`, then a confirmation listing what the key added with one **Keep** switch each (on by default; the switches `removeMachine`'s prompt used to carry), the `last-owner` refusal as "It cannot be removed: it is the only owner key of this cadre.", then `removeOwner(key, { revouch })`.
- Member view: the list with one line saying only an owner can add or remove keys (`owner-standing.ts` `standingLine`).

## Changed wording

Already done by `machine-removal-leaves-owner-keys`, which changed the cadre-core API under the app: the machine list's "Owner" and "Owner key, no machine joined" facts, the removal prompt's "its owner key is removed too" line, its keep-switches, its `ownDependency` line and its `last-owner` refusal are gone, in code and in `docs/reference-app-rn.md` → Devices and Nodes. The switch helpers (`dependentsOf`, `revouchFor` in `machines.ts`) and `test/machines.spec.ts` were deleted with them: they merged a dependent peer row with the owner key behind its peer id, which assumed owner keys derived from machine identities. The owner-key removal prompt needs one switch per dependent row (a device by peer id, an owner key by key and label), written fresh. What remains below: the lost-device line and button, and the `self` wording.

- **Devices and nodes** (`machines-section.tsx`, `machines.ts`): drop "Owner" from a machine's facts and the "Owner key, no machine joined" rows (owner keys are listed in their own section). The "To remove this device, use another owner device" line stays (removing your own machine is refused as `self`), with the reason restated.
- **Machine removal prompt** (`machine-removal.tsx`): drop "its owner key is removed too" and the keep-switches. Add: "If this was a lost or stolen phone that held an owner key, remove that key too in Owner keys; otherwise whoever has the phone can still act as an owner." with a button that scrolls to or opens Owner keys.
- **Approval prompts that name the device's owner key** (`add-node-section.tsx` ~182–186 "Owner fingerprint", node claim, provider rental at `docs/reference-app-rn.md` ~792 and ~841): name the cadre (full party id, as today) and "owner key ‹label› (‹fingerprint›)", from the wired signer's key and its row's label, instead of "this device's owner fingerprint".

## Edge cases & interactions

- The section reads on appear, after each add/import/remove here, after a join replaces the node, and on Refresh; a read that finishes after the node was replaced is dropped (same rule as Devices and nodes). By inspection.
- Backup creation refused `alone` (no connection while the cadre has other machines): show "Connect to your cadre first; a new owner key made now would not reach your other machines." By inspection.
- The export screen must not be captured in the app switcher snapshot if the platform allows (`FLAG_SECURE` on Android / blur on iOS): decide by what Expo exposes; if nothing, note it in the docs as a known exposure. By inspection.
- Passphrase mismatch on entry, empty passphrase with the toggle on: blocked in the form. By inspection.
- A Maestro flow for the backup path (make a backup key with a passphrase, see it listed, remove it) if the existing flows' helpers make it cheap; otherwise list it as not covered in the handoff. Unit tests only for pure helpers in `owner-keys.ts` (labels, row facts) if they hold branching logic.
