# Web reference app: "Devices and nodes" and acting on removal

The browser counterpart of `reference-app-rn-devices-and-nodes` (read it for the section's content and wording; this ticket states only what differs) plus the browser counterpart of `phone-kit-forgets-a-cadre-that-removed-it`, since the web app has no kit: `store.svelte.ts` and `web-join.ts` own the node's lifetime, `party-start.ts` the saved start, `web-dissolve.ts` the party's storage removal.

## Section

- `src/Machines.svelte` on the Cadre page (`Cadre.svelte`), after `AddDevice`, with its state and actions in `lib/machines.svelte.ts` (the `add-device.svelte.ts` pattern).
- Same list, pending invitations, Remove confirmation with the dependents' "Keep" switches, refusals and wording as the phone ticket. Fingerprint and short-id helpers from `lib/cadre-format.ts` (add a fingerprint helper there if it has none, matching `ownerFingerprint` in the phone app's `node-claim.ts`).

## Acting on removal

- In `store.svelte.ts`, where the node's events are recorded (`node.on('strand:revoked', …)` ~line 143), subscribe to `cadre:removed`, and check `removedFromCadre()` once after start.
- On removal, through the store's existing transition (the one `web-join.ts` uses to stop and start nodes, so nothing interleaves): stop the node; delete the removed party's storage with `removeParty(handle, partyId)` (`web-dissolve.ts`, marker first, no holdings check, called directly because the party being removed is the running one — `web-dissolve.ts`'s doc says a removal never names the running party; widen that sentence to say the removal of a cadre that removed this tab does, after the node stopped); and set the saved start (`party-start.ts`): the former party with auto-start off when `formerPartyId` is set (`withoutFormerParty` semantics), otherwise none.
- `finishRemovalAtStart` deletes a marker naming the party that is starting "with a warning, not acted on". That stays right: by the time a start happens, the marker names a party the tab is no longer running.
- Store status: a new `removed` state carrying `{ partyId, signerKey, formerPartyId? }`; the Cadre page shows the removed card (phone ticket's wording, "this browser" for "this phone") with **Go back to your own cadre** and the join section.

## Edge cases & interactions

- Same as the phone ticket's list and modal cases.
- **Two tabs on the same party** (same IndexedDB): the web app already refuses a second running node per storage, or not — check how `party-start.ts` / `store.svelte.ts` handle two tabs; if a second tab can run the same party, the removal in one tab deletes storage under the other. If the app has no guard today, note it in the README's "Out of scope" and do not add one here.
- **Removal during a join** (`joining`): as in the phone kit ticket; the transition queue orders them. By inspection.
- **Removed while the tab was closed**: never reported after restart (the core rule); `NOTE:` at the subscription, as in the kit.
