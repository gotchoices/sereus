## Phase 1 — shared helper `test/formation-consent-helper.ts` (new file)

Write exactly this shape (verified against the APIs above):

```ts
import { generatePrivateKey, sign } from '@optimystic/quereus-plugin-crypto';
import { generateStampId, formationConsentMessage } from '../src/control-database.js';
import { ed25519PublicKeyFromPrivate } from '../src/ed25519-key.js';

/** A throwaway joining peer: base64url ed25519 seed + its public key. */
export interface TestJoiner {
  privateKey: string;
  peerKey: string;
}

export function mintJoiner(): TestJoiner {
  const privateKey = generatePrivateKey('ed25519', 'base64url') as string;
  return { privateKey, peerKey: ed25519PublicKeyFromPrivate(privateKey) };
}

/** Spreadable into redeemInvitation / recordFormationUsage / recordUsage calls. */
export interface JoinerConsent {
  peerKey: string;
  usageStampId: string;
  peerSignature: string;
}

/** Sign the 'consent' digest over the EXACT token/nonce/disclosure the insert will carry. */
export function signJoinerConsent(
  joiner: TestJoiner,
  fields: { token: string; usageStampId: string; disclosure?: string },
): string {
  return sign(
    formationConsentMessage({
      token: fields.token,
      usageStampId: fields.usageStampId,
      peerKey: joiner.peerKey,
      disclosure: fields.disclosure ?? '',
    }),
    joiner.privateKey, 'ed25519', 'bytes', 'base64url', 'base64url',
  ) as string;
}

/** Fresh joiner + fresh nonce + consent signature, in one spreadable object. */
export function mintConsent(token: string, disclosure = '', joiner: TestJoiner = mintJoiner()): JoinerConsent {
  const usageStampId = generateStampId(joiner.peerKey);
  return {
    peerKey: joiner.peerKey,
    usageStampId,
    peerSignature: signJoinerConsent(joiner, { token, usageStampId, disclosure }),
  };
}
```

The signature MUST cover the same `token` and `disclosure` strings the insert
carries — every call site below matches them by construction.

### `Redemption` interface (~728) + `vouch` (~744) + `sibling` (~757) — THE HARD PART

`expectConstraintFailure` (test/control-constraint-helpers.ts) is a
single-rejector assertion: the write must be arranged so exactly ONE constraint
can fail. The consent digest covers `(Token, UsageStampId, PeerKey,
Disclosure)`; the vouch digest covers those plus `StrandId`. So any case that
varies a consent-covered field while expecting `'Authorized'` must RE-SIGN the
joiner's consent, or `PeerConsented` fires instead and the assertion goes
flaky/red.

Rework:

```ts
interface Redemption {
  token: string;
  strandId: string;
  usageStampId: string;
  peerKey: string;
  disclosure: string;
  /** Joiner's consent signature over (token, usageStampId, peerKey, disclosure). */
  peerSignature: string;
  /** Joiner's seed, kept so cases varying a consent-digest field can re-sign. */
  peerPrivateKey: string;
}

/** Recompute peerSignature from the redemption's OWN current fields. */
const reconsent = (r: Redemption): Redemption => ({
  ...r,
  peerSignature: signJoinerConsent({ privateKey: r.peerPrivateKey, peerKey: r.peerKey }, r),
});

const sibling = (redemption: Redemption, tag: string): Redemption => {
  const joiner = mintJoiner();
  return reconsent({
    ...redemption,
    usageStampId: generateStampId(`vouch-${tag}-` + rand()),
    peerKey: joiner.peerKey,
    peerPrivateKey: joiner.privateKey,
  });
};
```

`validatingInvite` mints a joiner and returns a fully-consented `Redemption`
(peerKey/peerPrivateKey/peerSignature populated). `vouch` is unchanged in body
— `Redemption` now structurally satisfies `FormationVouchFields` (it has
`peerKey`); extra fields are ignored. Spreading a `Redemption` into
`recordFormationUsage` passes the extra `peerPrivateKey`, which the
destructuring callee ignores — acceptable, TS-clean.

Per-case map in the `Authorized` / replay blocks (comments mentioning "PeerId"
→ "PeerKey" as you go):

- **fresh-nonce case** (~1069): attempted insert =
  `reconsent({ ...approved, usageStampId: generateStampId(…) })` — joiner
  re-consents to the fresh nonce; the STALE approval is the single rejector.
- **peer-swap case** (~1106): fresh joiner, SAME nonce:
  `reconsent({ ...approved, peerKey: j.peerKey, peerPrivateKey: j.privateKey })`.
- **tampered-disclosure case** (~1187): `reconsent({ ...approved, disclosure:
  approved.disclosure + ' — and one more thing' })` — joiner agreed to the new
  text, approver didn't.
- **cross-strand case** (~1132): NO re-sign — `strandId` is deliberately not in
  the consent digest, original consent stays valid.
- **cross-token vouch swap** (~1161): NO re-sign — insert fields unchanged,
  only the vouch is minted over the other token.
- **verbatim** (~1051) and **race** (~1208) cases: unchanged consents; `sibling`
  handles joiner B.
