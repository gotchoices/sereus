# Joiner-consent: end-to-end re-verification + documentation

Split out of `debt-formation-consent-tests-docs` when that run hit its token budget during
investigation, before writing code. Nothing was implemented; everything below is measured,
not guessed. Sibling ticket `debt-formation-consent-signature-matrix` owns the schema-level
negative-case matrix. The two touch disjoint files and can land in either order.

## Background

`debt-formation-consent-core` made the joining peer sign its own
`CadreControl.FormationUsage` row: the row stores `PeerKey` (the joiner's base64url ed25519
public key) and `PeerSig` (its signature over a digest of token, redemption nonce, peer key
and disclosure text). The signature is stored rather than passed transiently, so any later
reader can re-check it. Nothing proves that end-to-end yet, and the docs still describe the
old design.

## Part 1 — end-to-end assertion

Add a case to `Phase 4: Responder consent enforcement (real recorder)` in
`packages/integration-tests/src/scenarios/strand-formation-e2e.integration.ts` (starts
around line 740). That block is the right home: it is the only one wired to a real
`ControlFormationUsageRecorder` over a real libp2p network, and it already has
`responderService(party)`, `ownerSigner(party)` and `invitationFor(token, sAppId, party)`
helpers plus two working cases to copy the shape from.

After a genuine `bobService.formStrand(...)` against alice's responder, assert:

- the stored `PeerSig` re-verifies via `verifyFormationConsent` (exported from
  `@serfab/cadre-core`) against the stored `PeerKey`, using the row's own `Token`,
  `UsageStampId` and `Disclosure` read back out of alice's control database; and
- the stored `PeerKey` is the key behind the joiner's returned `memberKey` — an Ed25519
  libp2p peer id is the identity multihash of exactly those key bytes.
  `ed25519PublicKeyB64FromPeerId` is exported from `@serfab/cadre-core` and does that
  extraction.

Measured facts so the disclosure bytes line up:

- The joiner signs over `canonicalJson({ ...disclosure, partyId: memberKey })` —
  `strand-solicitation.ts:317-334`, where `memberKey` is
  `peerIdFromPrivateKey(privateKey).toString()` and the peer key is
  `ed25519KeyPairFromLibp2p(privateKey).publicKeyB64`.
- The responder writes `canonicalJson(contact.disclosure)` to `FormationUsage.Disclosure`
  — `strand-formation-manager.ts:298`. So reading the column back gives exactly the bytes
  that were signed; do not re-serialize it.

Note the known constraint carried forward from the two prior tickets: the integration
scenarios run a real network and their wall clock is past what an agent run can hold, so
they are build- and type-checked only inside the ticket and need a human or CI run
out-of-band. Say so in the handoff rather than claiming a green run.

## Part 2 — documentation

`docs/api.md`, approval-hook wire contract. Two corrections, not one:

- The POST body field named `peerId` (around lines 88-90, and the example hook at line
  167) is now `peerKey`, and the value is the joiner's Ed25519 public key rather than a
  libp2p peer id — the peer id is derivable from it.
- The text at lines 66-67, 76 and 147 says the REDEEMING node mints the single-use
  redemption nonce and reasons from that ("only that node can guarantee the nonce that was
  signed is the nonce that gets inserted"). That is now false: the JOINER mints it
  (`strand-solicitation.ts:317`) and signs its own consent over it before the contact
  message is sent, and the responder inserts that same value. Rewrite the surrounding
  argument, do not just swap the noun.

`docs/strands.md` and `docs/architecture.md`: grep both for wording that describes
formation as the joiner contributing no signature, or as approval resting solely on the
inviting party's owner/approver keys, and update it to describe the stored, re-checkable
consent signature. (Not yet located — the budget ran out before these two files were
read. `docs/cadre-consistency.md`, `docs/cadre-host.md` and `docs/STATUS.md` were checked
during `debt-formation-consent-tests-db` and carry no claim this change falsifies.)
