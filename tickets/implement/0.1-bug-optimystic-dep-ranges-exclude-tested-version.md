# Declared `@optimystic/*` and `@quereus/quereus` ranges bumped to match tested versions

## What was done

All 22 `@optimystic/*` dependency ranges across the workspace raised `^0.16.3` → `^0.17.0`, matching
the version actually linked via `resolutions` in root `package.json` (`link:../optimystic/packages/*`,
confirmed at `0.17.0` on disk).

Files touched: `packages/cadre-cli`, `packages/cadre-core`, `packages/integration-tests`,
`packages/quereus-plugin-sereus`, `packages/reference-app-ns`, `packages/reference-app-rn`,
`packages/reference-app-web`. (`packages/cadre-host` and `packages/cadre-provider`, named in the
originating ticket's `files:` header, carry no direct `@optimystic/*` dependency — nothing to change
there.)

Also bumped `@quereus/quereus` floor `^4.4.0` → `^4.5.0` in the same 6 packages that declare it
(`cadre-core`, `integration-tests`, `quereus-plugin-sereus`, `reference-app-ns`, `reference-app-rn`,
`reference-app-web`), matching the linked `../quereus/packages/quereus` version on disk (`4.5.0`).
Decision: even though `^4.4.0` already *admits* 4.5.0 (caret crosses minors above 1.0, so this one
wasn't broken like the optimystic ranges), the floor should still track what's actually tested —
same principle as the rest of this ticket, applied consistently rather than left as an exception.

`yarn install` run to refresh `yarn.lock` (36 lines changed — resolution metadata catching up to the
new ranges; the `link:` resolutions meant no new code was actually fetched, so this is bookkeeping,
not a dependency swap).
