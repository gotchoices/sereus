## Build order trap — read before running anything

```
yarn workspace @serfab/quereus-plugin-sereus build
```

`cadre-core` loads the embedded strand schema from that package's `dist/`, and the root
test wiring does not build first. On an unbuilt tree a `cadre-core` run silently uses the
OLD schema and reports a meaningless green, or fails with `Table not found:
Strand.CancelledInvite`. Filed as `backlog/debt-embedded-schema-stale-dist-false-green`.
The build IS current as of this handoff, but re-run it — it takes under a second and a
stale `dist/` produces a false green.

## Expect real failures, not a green rubber-stamp

`cancelInvite` / `listOutstandingInvites` / `scanInviteKeys` have been typechecked but
NEVER executed. Budget at least one runtime fix in the source, not only in the tests.
Specific things worth suspecting first if something fails:

- `db.exec` of an insert with **one** column and a `with context` clause —
  `insert into Strand.CancelledInvite (InviteKey) with context ... values (?)` is a shape
  nothing else in the writer uses (every sibling insert has ≥2 columns).
- `CancelledInvite`'s context is `(ManagerKey text, ManagerSignature text)` —
  **non-null**, unlike `Invite`'s and `Member`'s. A path that passes null there fails
  differently than the sibling tables do.
- The `/Immutable/` test updates `InviteKey`, which is the whole primary key. The
  `Revocation` `Immutable` test does the same to `StampId` and passes, so this should
  too — but it is the one assertion whose mechanism is borrowed rather than observed.
- The exclusive-expiry positive control uses `base - 86_400_000` (a whole day earlier)
  rather than `base - 1`, deliberately: the canonical datetime form may carry fractional
  seconds, and a 1 ms delta would test string formatting rather than ordering.

A test that fails while contradicting one of the doc blocks in
`strand-membership-writer.ts` or `schemas/strand.qsql` has found either a bug in the
source or a wrong comment — decide which and fix that, rather than bending the test to
match observed behavior.

## Known gaps in the tests as written (be honest about these; do not paper over)

- The `/NotCancelled/` rejection and the rollback assertions live in ONE test rather than
  two, matching the existing spec's own convention (see the wrong-key and expired
  atomicity tests it mirrors). If a reviewer wants them split, that is a style call.
- No test covers `cancelInvite` on an OPEN strand. `OnlyClosed` would fire there, but so
  would `Authorized` (an open strand has no founding Manager), so the rejection could not
  be cleanly name-pinned — deliberately skipped rather than asserted vaguely.
- `listOutstandingInvites`'s documented "in storage order" guarantee is only exercised
  incidentally (the multi-row assertions index by key rather than by position), so
  ordering is effectively untested.
