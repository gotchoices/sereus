# Lint gate: deadline constants in cadre-core are derived or say why not

## Why

`link-budget.ts` says it "is the only place a new dial's budget should be written", and nothing enforces it. The three sender deadlines converted by `wake-addr-seed-deadlines-count-round-trips` were the second batch of sites that did not follow the rule, and planning that ticket found more (`debt-formation-and-relay-admission-deadlines-ignore-the-declared-link`). A name-based check on "DIAL" would have missed all of them: they are called `DEFAULT_WAKE_TIMEOUT_MS`, `DEFAULT_ADDR_TIMEOUT_MS` and `DEFAULT_SEED_DELIVER_TIMEOUT_MS`. So the check covers every deadline-named constant and makes the author classify it, rather than trying to recognise dials.

## The rule

In `packages/cadre-core/src/**`, `no-restricted-syntax` flags:

- a `const` whose name ends in `TIMEOUT_MS`, `BUDGET_MS` or `DEADLINE_MS` and whose initialiser is a numeric literal or arithmetic over numeric literals only (`10_000`, `10 * 60 * 1000`). A derived initialiser (`relayedDialBudgetMs()`, `ATTEMPTS * OTHER_CONST`) passes.
- a parameter default or class-field initialiser whose name ends in `TimeoutMs`, `BudgetMs` or `DeadlineMs` and whose value is a numeric literal. There are none in the tree today (searched 2026-09-29); this keeps the rule from being sidestepped by moving the number.

Candidate selectors (verify against the tree; esquery supports `:has`/`:not`):

```js
const LINK_DEADLINE_GUARD = [
	{ selector: "VariableDeclarator[id.name=/(TIMEOUT|BUDGET|DEADLINE)_MS$/][init.type='Literal']", message: LINK_DEADLINE_MESSAGE },
	{ selector: "VariableDeclarator[id.name=/(TIMEOUT|BUDGET|DEADLINE)_MS$/] > BinaryExpression.init:not(:has(Identifier))", message: LINK_DEADLINE_MESSAGE },
	{ selector: "AssignmentPattern[left.name=/(Timeout|Budget|Deadline)Ms$/][right.type='Literal']", message: LINK_DEADLINE_MESSAGE },
	{ selector: "PropertyDefinition[key.name=/(Timeout|Budget|Deadline)Ms$/][value.type='Literal']", message: LINK_DEADLINE_MESSAGE },
];
```

Message, in substance: "A deadline written as milliseconds. If it bounds an exchange with another machine, derive it from link-budget.ts: count the round trips, as that module's doc describes. If it does not, keep the number and disable this line with the reason: `// eslint-disable-next-line no-restricted-syntax -- link-independent: <why>`."

Two disable-reason forms, so the classified set stays greppable:

- `-- link-independent: <why>`: the deadline does not wait on the machine-to-machine link (a local operation, an HTTP call, a cap whose expiry has its own fallback).
- `-- link-bound, not yet derived: <ticket slug>`: it does wait on the link and an open ticket owns converting it.

Flat-config mechanics: an entry that sets `no-restricted-syntax` replaces the options of earlier entries for the files it matches (the header comment at `eslint.config.mjs` ~31 explains). So add one entry for `packages/cadre-core/src/**/*.{ts,tsx,mts,cts}`, after the `PHONE_RUNTIME_SCOPE` entry, carrying `CADRE_PEER_WRITE_GUARD`, `PHONE_RUNTIME_GUARD` and `LINK_DEADLINE_GUARD`. The `control-database.ts` exemption entry must add `LINK_DEADLINE_GUARD` to its list, or that file silently loses the new rule.

Scope is cadre-core only. `quereus-plugin-sereus/src/cluster-size.ts`'s `COHORT_READ_DEADLINE_MS` is owned by `debt-cadre-deadlines-sized-against-old-optimystic-bounds`. Record the scope choice in the config comment; widening the scope later is a one-glob change.

## Edge cases & interactions

- **Exemption entries.** Any later `eslint.config.mjs` entry that sets `no-restricted-syntax` for files under `packages/cadre-core/src` replaces the options, so the new selectors must be in it. Today that is only `control-database.ts`. Verify by temporarily adding `const X_TIMEOUT_MS = 1;` to `control-database.ts` and seeing `yarn lint` fail, then remove it.
- **Test files.** `packages/cadre-core/test/**` is out of scope: tests pass chosen durations on purpose. The glob must not reach them.
- **Derived-but-arithmetic constants.** `DEFAULT_CONTROL_COHORT_DIAL_TIMEOUT_MS = CONTROL_COHORT_DIAL_ADDRESS_ATTEMPTS * DEFAULT_CONTROL_COHORT_PER_ADDRESS_DIAL_TIMEOUT_MS` must pass (it contains identifiers). `link-budget.ts`'s own `DECLARED_LINK_ROUND_TRIP_MS` and `PUSH_TRANSFER_ALLOWANCE_MS` do not end in the flagged suffixes; confirm, and if one is flagged, classify it rather than rename it.
- **Stale disables.** When a `link-bound, not yet derived` site is later converted, its disable directive becomes unused. ESLint reports unused directives as a warning by default, which this repo's all-`error` gate does not fail on. Leave that as is and say in the config comment that converting a site means deleting its directive.
- **What this does not catch.** A deadline under a name without those suffixes (`FOO_WAIT_MS`), or an inline `setTimeout(..., 5000)`. Say so in the config comment; it is a guard against the idiom this codebase uses, not a proof.
