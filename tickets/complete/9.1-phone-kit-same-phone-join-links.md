# Phone kit: links between Sereus apps on one phone

First of three tickets replacing the twice-copy-and-paste join between two apps on one phone with one confirmation in the owner app. `reference-app-rn-answers-join-requests-by-link` (owner side) and `reference-app-rn-asks-owner-app-by-link` (asking side) build on it. **B** is the app asking to join; **A** the owner app holding the cadre.

## What landed

Implemented in `ticket(implement): phone-kit-same-phone-join-links`.

- **cadre-core:** `CadreJoinRequest.reply?: { scheme, nonce }` (`CadreJoinReply`), encoded only when present, and `requireCadreJoinReply`, which refuses a scheme outside `^[a-z][a-z0-9+.-]{0,63}$` or in the named web/system list, and a nonce outside `^[A-Za-z0-9_-]{16,64}$`. Both codec directions run it.
- **`@serfab/cadre-rn/app-link`** (no React Native or Expo import): `KNOWN_SEREUS_APPS` and `installedSereusApps` (`known-apps.ts`); the `sereus-join-response:1.` codec with exactly one of `invitation`/`refused` (`join-response.ts`); `parseCadreLink`, `joinRequestLink`, `joinResponseLink`, `CADRE_LINK_MAX_LENGTH`, `CadreLinkTooLongError` (`links.ts`); `LinkRequestStore` with the take-once, matching-nonce, 30-minute contract and `UnsolicitedJoinResponseError` (`link-request-store.ts`).
- **`PhoneNode.linkRequestSlot()`** over `PhoneNodeNames.linkRequestKey` (`link-join-request`) in the node-local database; waits for a stop in progress.
- **Config plugin `appLinks`:** Android `VIEW` intent filter and `<queries>` entry for `sereus-join-request`; iOS `LSApplicationQueriesSchemes` merge capped at 50; strict option checking; the plugin's known-apps copy exported for a drift test.
- **Docs:** kit README "App links" section and the `appLinks` plugin option; `docs/architecture.md` → "Between apps on one phone" (flow, link formats, decisions, link length, security, and the accepted impostor-owner-app tradeoff with its revisit condition).

## Usage, for the reference-app tickets

- **B:** `new LinkRequestStore(phone.linkRequestSlot())` (one per app), `begin`, `encodeCadreJoinRequest({ …, reply: { scheme: ownScheme, nonce } })`, `Linking.openURL(joinRequestLink(text, ownerApp | null))`. On the answer: `parseCadreLink(url)`, `store.take(link.text)`, `phone.joinCadre(decodeCadreInvitation(response.invitation))`.
- **A:** `parseCadreLink(url)`, `decodeCadreJoinRequest(link.text)`, the user confirms, `Linking.openURL(joinResponseLink(request.reply, { v: 1, nonce: request.reply.nonce, appName, invitation | refused }))`; on `CadreLinkTooLongError`, show the invitation for copying.
- **iOS list:** pass `(url) => Linking.canOpenURL(url)`, not the unbound method (React Native's implementation uses `this`).

## Review findings

Read the implement diff first, then the handoff, then the code paths and the suite.

**Checked:**
- **The request's `reply`:** `canonicalJson` drops `undefined` keys (`canonical-json.ts`), so a request without `reply` encodes as before; the existing round-trip test passes unchanged. A JSON `reply: null` is refused by `replyShape`, not ignored.
- **Response codec:** both directions share `requireCadreJoinResponse`; both or neither of `invitation`/`refused` is refused, as is an unknown refusal reason; a pasted request is refused by name.
- **`LinkRequestStore`:** `take` decodes before reading the slot (a malformed answer leaves the request open), refuses no-open / wrong-nonce / expired / second take, and clears only on a match. Slot read faults propagate. Calls are serialized per instance, and a failed call does not wedge the queue (`turn` swallows the rejection; the caller still sees it). A malformed record reads as none and is logged.
- **`linkRequestSlot`:** re-resolves the node-local handle on every load and save, so it survives a stop closing the database, and waits for `stopping` as `loadSavedStart` does. With a node running it shares the node's handle, so there is no second lock in steady state.
- **`parseCadreLink`:** recognizes only the forms the module builds; node codes, invitations, other paths and an empty response path are null (test table).
- **`joinResponseLink`:** re-checks scheme and nonce before building, so A never opens a web or system scheme.
- **Config plugin:** option parsing refuses unknown keys and malformed extras; the Android additions are idempotent; the iOS merge keeps existing entries and checks their type. On the handoff's question whether `<queries>` is needed: it is also what lets B's Android `canOpenURL` on a `sereus-join-request:` link see the owner apps, so it is kept.
- **Type safety and hygiene:** no `any`; the largest new source file is 129 lines; comments give reasons rather than narrate.
- **Tests:** the new cases are the ones the ticket specified, and each pins a contract with real branching (reply refusal both ways, the store's security contract, the link classification table, the known-list drift). None restates the implementation or verifies a mock. Nothing cut, nothing added.
- **Docs:** read the kit README, `docs/architecture.md` and the reference-app docs. `docs/reference-app-rn.md`'s storage notes do not list `link-join-request` yet; the reference app does not use it until `reference-app-rn-asks-owner-app-by-link`, which owns that change.

**Found and fixed in this pass:**
- **README misplacement (minor):** the new `appLinks` subsection was inserted between the cleartext section's text and its "a bare React Native app adds the attribute by hand" XML snippet, so the cleartext snippet sat under the `appLinks` heading. Moved it back above that heading (`packages/cadre-rn/README.md`).

**Tripwires parked (no ticket):**
- **Scheme pattern kept twice** (cadre-core's `CADRE_JOIN_REPLY_SCHEME`, the plugin's `APP_SCHEME`) with no test keeping them equal: `NOTE:` added at both sites. Drift would only change which `extraApps` the prebuild accepts; A re-checks every reply at run time.
- **Node-local lock during a restart, join or dissolve:** the implementer's `NOTE:` in `PhoneNodeRuntime.linkRequestSlot` stands; left as is.

**Considered, no action:**
- **"Once" holds per store instance:** documented in the README ("One per app"); two instances over one slot is misuse, not a path either planned app takes.
- **`begin` keeps the first `ownerAppName` and start time on a second tap:** the ticket specifies returning the open request unchanged; the cost is a stale "waiting for …" name on iOS if the user switches owner apps within 30 minutes.
- **A clock set backwards** keeps a request open past 30 minutes; contrived, and the nonce check still holds.
- **No percent-decoding in `parseCadreLink`, and the unmeasured ~4 KB link size:** both need a device; that run belongs to `reference-app-rn-asks-owner-app-by-link`.
- **The Android chooser lists B itself:** handled by `reference-app-rn-asks-owner-app-by-link` (B recognizes its own peer id).
- **The response codec repeats the request codec's prefix, base64url and JSON steps:** two short codecs with different fields and error texts in different packages; a shared helper would save a few lines at the cost of coupling.
