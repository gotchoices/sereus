# The NativeScript lazy storage proxy forwards `listBlockIds`

`packages/reference-app-ns/src/ns-storage.ts` wraps the SQLite-backed storage (`SqliteRawStorage` from `@optimystic/db-p2p-storage-ns`) in a proxy class, `LazyNsRawStorage`, because the database open is asynchronous and cadre-core wants a storage object synchronously. The storage interface `IRawStorage` has optional members that callers detect by checking whether the member exists. The proxy did not forward `listBlockIds`, so it read as "not supported" on the phone and two consumers did nothing: the push of existing blocks to a peer that joins later (`PeerJoinBackfill.runCatchUp` in `packages/cadre-core/src/peer-join-backfill.ts`), and the startup seed of the tracked block set in `../optimystic/packages/db-p2p/src/libp2p-node-base.ts`.

## What shipped

- `LazyNsRawStorage.listBlockIds()` awaits the cached open and streams from the real storage, in the same form as `listRevisions`.
- The class's `implements` clause requires the optional methods it forwards (`getApproximateBytesUsed`, `listBlockIds`), so removing one is a compile error.
- Every optional member of `IRawStorage` must appear in one of two lists in the file, forwarded or deliberately omitted. A member added upstream that is in neither list fails the type check (`UnclassifiedOptionalMember`). Added in review.
- Two members are deliberately omitted, each with its reason in the file: `getStoreIdentity` (an accepted-tradeoff `NOTE:` on the class, with revisit conditions) and `readCached` (a marker for a storage with a read cache beneath it, which this one does not have).

## Review findings

Read the `ticket(implement): debt-ns-storage-proxy-omits-block-listing` diff before the handoff.

**Checked**

- The forwarding method: signature matches `IRawStorage.listBlockIds` and `SqliteRawStorage.listBlockIds`; the open is deferred until iteration starts, the same behaviour `ns-storage.spec.ts` already pins for `listRevisions`. A failed open rejects on the first `next()`, which `runCatchUp` and the startup seed already handle as any storage error. No resource to clean up: the underlying method reads all rows before yielding, so an abandoned iteration holds no cursor.
- The handoff's untested claim that deleting `listBlockIds` fails the type check: confirmed by experiment (renamed the method, `typecheck` reported TS2420 "Property 'listBlockIds' is missing", then restored it).
- The handoff's statement that the guard "does not catch a new optional method added upstream": treated as a finding, see below.
- Consumers: both `runCatchUp` and the startup seed detect the method by presence and neither is gated on the node profile, read from code. The comment in `peer-join-backfill.ts` describing the "no `listBlockIds`" case remains accurate for backends that lack it.
- Docs: `docs/reference-app-ns.md` and `packages/reference-app-ns/README.md` describe the proxy as delegating each call after a cached open and do not enumerate methods. Still accurate; no change.
- Tests: none added by the implementer, none added here. The delegation is one line whose shape is already covered by the `listRevisions` test, and the omission class is now enforced by the type check.

**Found and fixed in this pass (minor)**

- The guard covered only removal of an already-forwarded method. The original defect was the other direction: an optional member that was never forwarded. Added a type-level exhaustiveness check over the optional keys of `IRawStorage`. On first compile it reported `readCached`, an optional member neither the fix nor the implement stage had accounted for. It is correctly absent from the proxy, and is now listed as omitted with the reason.
- Updated the class comment, which said the upstream-addition case could not be caught.

**Tripwire**

- Backfill and the startup seed now run on the phone, and `SqliteRawStorage.listBlockIds` reads every block id into memory before yielding. Cost on a large phone database is unmeasured. Parked as a `NOTE:` on `LazyNsRawStorage.listBlockIds`.

**Major findings**

- None. The change is one delegating method plus type guards; nothing in it reaches beyond this file.

**Not verified**

- Not run on a device. Confirmation would be `DEBUG=sereus:*` on the phone no longer logging "backfill is inert" when a second device connects.
