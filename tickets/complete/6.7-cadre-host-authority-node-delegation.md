## What landed

The manager (cadre-host) no longer holds an in-process `CadreNode` or `ControlDatabase`. It spawns
the admin's **authority node** as a managed child and delegates over the node's loopback admin
channel (the 6.6 contract):

- **Orchestrator** — `NodePorts` gained an `admin` port (allocated per child, persisted, re-reserved
  on `init()`). New authority lifecycle: `ensureAuthorityNode`/`restartAuthorityNode`/
  `stopAuthorityNode`/`getAuthorityAdminEndpoint`/`isAuthorityNode`/`hasAuthorityConfig`. The
  authority node is `cadre-cli start --authority --admin-port <p> --identity-protobuf <path>`,
  partyId = installId, on `cfg.libp2pPort`, reusing `CADRE_STARTUP_TOKEN` as the admin bearer.
  `createContainer` + authority spawn share a private `launchChild()`. **Authority restart preserves
  the workdir** (control-DB storage).
- **`AuthorityNodeClient`** (`src/authority/`) — HTTP client of the admin contract implementing both
  `CadreNodeLike` shapes + `pushInviteAddresses`. Transport/non-2xx → `AuthorityNodeUnavailableError`
  (carries the node error `code`). Accepts a static endpoint or a getter (host passes a getter so a
  restart's fresh token is picked up). `encodeInvite` mirrors cadre-core locally.
- **Trust-circle** — `CadreNodeLike` dropped `getControlDatabase()`, added `listMembers()`/
  `isMember()`. Authority-op failures → `TrustCircleError('node_unavailable')` (→ 503); `list()`
  degrades to the local labels file when the node is down.
- **NAT** — `getPeerId()`/`getMultiaddrs()` are async; `getInviteAddresses()` maps node-down →
  `NatError('node_unavailable')`. New `onAddressesChanged` hook fires from `start`/`putSettings`/
  `testReachability`; `cadre-host start` wires it to `pushInviteAddresses`.
- **Routes / errors** — `/api/nodes/:id/{start,restart}` real for the authority node; unknown id →
  404; known non-authority id → 501. `node_unavailable` → 503 in `error-handler.ts`.
- **`bin/host.ts`** — `ensureAuthorityNode` after `init()`; builds `AuthorityNodeClient`; wires
  trust-circle + NAT + invite-address push; stops the authority node on graceful shutdown. Deleted
  `missingCadreNodeStub` / `missingNatNodeStub`.

## Review findings

Adversarial pass over the implement diff (`6c54862`). Read the full diff of every touched source
file and the files it interacts with (`port-allocator.ts`, `address-resolver.ts`, `cadre-node.ts`,
the route/error-handler, all updated tests) before the handoff summary.

**Checked & clean:**

- **Spawn / lifecycle mechanics** — `launchChild` DRY refactor is faithful (shared by
  `createContainer` and `ensureAuthorityNode`); ports released on sync spawn failure and on
  remove/restart via the new `releasePorts`. Authority restart preserves the workdir (verified by
  test + by reading the code: no `rmSync` in `ensureAuthorityNode`'s stale-handle drop). `init()`
  re-attach guards the legacy-handle missing-`admin` case; `PortAllocator.markUsed`/`release` handle
  the out-of-range `libp2pPort` as harmless no-ops. Idempotency, admin-port persistence, init
  re-attach, and the end-to-end client round-trip against a fake CLI are all covered.
- **Type safety** — no `any` leaks; `AuthorityNodeUnavailableError` carries an optional `nodeCode`;
  `isMember`'s `toDomainError` returns `never` so the `Promise<boolean>` signature holds. `tsc`
  (build:server) is green; package has no separate lint script — the build is the type gate.
- **Error mapping** — `node_unavailable` → 503 added for both trust-circle and NAT; `list()`
  correctly degrades **only** on `AuthorityNodeUnavailableError` (re-throws anything else, so a real
  bug isn't masked as a degrade).
- **Resource cleanup** — graceful shutdown stops the authority node; orchestrator test afterEach
  stops + removes all children. Log fd closed on every spawn path.
- **Docs** — `docs/cadre-host.md` (topology diagram, honest-gaps, architecture sketch) and
  `docs/architecture.md` rewritten to match the landed reality (no stale "realignment pending" /
  "stubbed" language remains — confirmed by reading both files end-to-end).

**Minor — fixed in this pass:**

- **NAT could mint malformed invite addresses from an empty peerId.**
  `AuthorityNodeClient.getPeerId()` returns `data.peerId ?? ''`, so a node that is *up* but whose
  libp2p peer ID isn't established yet yields `''`. `buildInviteAddresses` would then produce
  `…/p2p/` suffixes with an empty peer id and (via `onAddressesChanged`) **push them to the node**.
  Added a guard in `NatService.getInviteAddresses`: an empty peerId now throws
  `NatError('node_unavailable')` (treated as not-ready), so `fireAddressesChanged` skips the push and
  the `/nat` route returns 503 until the node is ready. Added a regression test
  (`nat-service.test.ts` — "throws node_unavailable when the node reports an empty peer ID").

**Major — filed as new tickets:**

- **`fix/redeem-invite-token-loss-on-transient-node-unavailable`** — `redeemInvite` durably consumes
  the one-time pending row *before* delegating `acceptPhone`. Now that `acceptPhone` round-trips over
  the admin channel, a *transient* `node_unavailable` permanently burns the token even though nothing
  was authorized on the node. Recoverable failure indistinguishable from success; was effectively
  impossible with the old in-process node. Needs reordering that preserves the double-redeem race
  protection.
- **`backlog/cadre-host-real-authority-node-integration-test`** — no test spawns the *real* cadre-cli
  authority node from the orchestrator and drives `AuthorityNodeClient` against the real admin
  contract (current tests use a fake CLI / stub HTTP server). Cross-package integration test to close
  the loop.

**Known items reviewed — accepted, no action:**

- **Quereus `CadrePeer` delete bug** — pre-existing upstream (reproduces with this ticket reverted),
  already tracked by `fix/quereus-cadrepeer-delete-no-row-context`; the remove-cycle integration
  assertion is `it.skip`'d with that reference. Correctly out of this ticket's scope.
- **Every non-2xx → `AuthorityNodeUnavailableError` (503)** — per the 6.7 spec; a genuine
  `400 bad_request` from the node also surfaces as 503. Acceptable for v1; finer client-error mapping
  is a future refinement, not a regression.
- **`removeContainer` wipes the authority workdir while `authorityConfig` persists** (re-founds an
  empty control DB on next ensure). Confirmed **not reachable via the HTTP API** — there is no
  node-remove/delete route; only stop/start/restart/logs are exposed. Internal-only footgun; the
  wipe-on-remove is the intended `removeContainer` semantics. Left as-is (guarding it would break the
  orchestrator test's cleanup and add complexity for an unreachable path).
- **Initial invite-address push is best-effort** (node not yet accepting at `start()`); retried on
  the next NAT event — by design, and the new empty-peerId guard makes the not-ready window cleaner.
- **Per-child admin port allocated even for non-authority nodes that never bind it** — minor reserved
  waste, explicitly per the ticket ("allocated for every child").
- **Authority node profile defaults to `storage`, no `bootstrapNodes`** (founds the network), no
  quota — the intended household-node shape per the docs.
