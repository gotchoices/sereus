# Complete: cadre-core takes one storage value per scope, and an allotment

Second of five tickets adopting Optimystic 1.30.0. Implemented in `ticket(implement): optimystic-1-30-cadre-core-node-storage`, reviewed and amended in this pass.

## What landed

**The config seam.** `StorageConfig.provider: IRawStorage | ((scope) => IRawStorage)` and `quotaBytes` are gone. In their place `open(scope: string): Promise<NodeStorage>` and `allotmentBytes?: number`. The `RawStorageProvider` type is deleted, and the deprecated Node-only `getStrandStoragePath` with it. There is no single-instance form any more: one value shared by every scope would put one party's control database in another's store.

**One shared helper puts the read cache on.** `node-storage-cache.ts` returns `{ storage: { ...opened, blocks: cached }, lease }` over upstream's `withReadCache`, and releases a lease without throwing. Both seams that open a scope — `CadreNode` for the control database, `StrandInstanceManager` for each strand — go through it, so neither can drift on the shape it hands a node or on who releases what.

**`CadreNode`.** `resolveControlStorage`, `controlBackfillStorage` and `buildControlNodeOptions` are `async`. The in-flight open is memoized alongside the resolved value, so two concurrent first uses open once (LevelDB refuses a second open over one handle). `cleanup()` releases the lease and drops the field, which is what lets a `stop()`/`start()` cycle re-open against a live cache.

**`StrandInstanceManager`.** Storage is opened for every role, a client included — a client serves no blocks but keeps its own blob records, blob pieces, owed-blob ledger and clock high-water mark — so `backfillArms` now reads the role flag rather than the presence of a store. The asynchronous open put an `await` between `startStrand`'s `instances.has` check and its `instances.set`, so a `launches` memo was added: the first call registers its promise synchronously and a second joins it, which is the answer the tracked-instance early return already gives.

**A full cohort is never retried.** `reportsCohortOutOfSpace(links)` in `control-retry.ts`, checked in `matchesRetriableFailure` before any claim — a veto rather than an omission, because `isUncommittedTransactorAggregate` claims a promise-phase aggregate on the phase alone and would otherwise re-admit an out-of-space refusal carried inside one.

**The edge-node seam.** `EdgeNodeStorage.rawStorage` became `nodeStorage(scope): Promise<NodeStorage>`; `allotmentBytes` is new, and `DEFAULT_DEVICE_STORAGE_ALLOTMENT_BYTES` (2 GiB) is what the kits declare where the backend reports no free space. `edge-node/lazy-raw-storage.ts` is deleted, and so is `quereus-plugin-sereus/src/cached-storage.ts`.

**Docs.** `docs/cadre/node.md` was within 75 words of its 6,000-word budget, so `## Storage` stays there — keeping `#storage` resolvable for its inbound links and tickets 3/4/5' anchors — and the rest moved to the new `docs/cadre/node-storage.md`: scope keys, when a scope is opened, who closes it, the read cache, the five openers, the allotment, and three accepted tradeoffs.

## Measured figures

Every figure stayed inside its existing ceiling.

- **`scripts/lib/published-smoke-scenario.mjs` built `storage: { provider }` over one shared store** — the single-instance form this change made unwritable, in two of its four cases. - **`docs/cadre/node.md`'s limits still documented the single-store provider form** as supported-but-unexercised, a configuration a caller can no longer write. Bullet removed. Its backlog ticket (`debt-shared-store-provider-never-exercised-end-to-end`) is moot for the same reason; I deleted it and then **restored** it, because ticket 5 explicitly owns deleting it and carries the reasoning to record. - **`storage-scope.ts`'s module header** opened "A provider is a factory cadre-core invokes once per scope" two lines after its own first line had been updated to `storage.open`. Reworded.
- **The handoff's known gap #1: `control-database-solo-warm-start.spec.ts`'s stated property #1 was stale.** Reworded to what the suite really gives — the same directory and real bytes written through a filesystem backend and its write-ahead log, so a hydrate path that only works against an in-memory store still fails there — and to say plainly which half it lost and why (`fileNodeStorage` keeps one set of stores per directory, counted by holder, and the helper never closes one). No behaviour change: restructuring a reproduction case to recover the cold handle is filed, not done here.
- **The new `launches` memo reported a dropped founder bootstrap where nothing was dropped.** `warnIfFounderRequestDropped` compared against `launchConfigs`, which a launch does not write until after it has opened the scope — so a second `addStrand` with `founder: true` joining a *founder* launch in flight logged "DROPS the founder request" every time, and the message said "already running" on a path where it is not. No missed warnings before or after — only the spurious one is gone. No new test: it is a log line with no branch worth pinning, and `publish-strand.spec.ts` already drives the concurrent-launch path the memo exists for.
- **`node-storage-cache.ts`'s "do not reorder" comment claimed more than upstream gives.** On an identity hit `withReadCache` fronts the FIRST caller's block store and drops the one passed in, so `blocks` and `pieces` in the value cadre-core builds can already be different objects. Benign — the node's storage account measures by location and every shipped opener hands one set of stores per location — but the comment read as an object-identity guarantee. Reworded to say location.

### Tripwires recorded, not filed

- **`startControlBackfill`'s new `await` can interleave with a `stop()` begun from the `control:connected` handler.** `_running` is already true when `start()` reaches it, and `stop()`'s own comment acknowledges embedders that stop from an event handler. Harmless today only because `buildControlNodeOptions` has already opened the control scope, so the resolver returns the held value within a microtask — far less than `cleanup()` needs to reach its lease release, which is its last step. If this ever becomes the first reader of the control scope, the open can land after cleanup released: a second lease nothing releases, and a second open LevelDB refuses outright. `NOTE:` at the await in `cadre-node.ts`, naming the guard to add.
