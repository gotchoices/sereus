# "Join a cadre" in the local UI — complete

Fourth of the `cadre-host-join-a-cadre` chain; the Svelte side of the hosted-node routes that landed in `cadre-host-hosted-nodes-join-by-qr`. `cadre-host-join-by-invitation` (next) adds a paste field to the Join page created here.

## What landed

Landed in `ticket(implement): cadre-host-join-ui`, with two small fixes from review (below).

- **State** (`lib/state.svelte.ts`): a `hostedNodes` slice (`list`, `loaded`, `error`) mirroring the server's `HostedNodeView` without the secret; `refreshHostedNodes()` drops an older answer that lands after a newer one; `joinCadre`, `removeHostedNode`, `resetHostedNode` re-read the records, the orchestrator handles and the NAT snapshot; `fetchClaimDetails` returns the payload without storing it. `hosted-nodes-changed` and `node-state-changed` events re-read the slice. A 404 from `/api/nodes/:id` now drops the handle quietly, so a hosted node with no process renders from its record.
- **Helpers** (`lib/hosted-nodes.ts`): `isWaiting`, `ownerFingerprint`, `claimedCadre`, `connectedText`, `stateLine`, `STATUS_BADGE`, `hostedLabel`, `joinNodeRows`.
- **`components/ClaimCode.svelte`**: reads the code while the node is `unclaimed`, retries 503s every second, re-reads when the node's public addresses change, shows the unreachable warning; the payload lives only in the component.
- **Join page** (`#/join`): the button, one card per waiting node (followed through claimed → connected for the page's lifetime), with code, reachability card and Cancel.
- **Node page**: a Cadre card with status line, cadre, owner, connected; Cancel while waiting; Reset + Remove when joined; Retry + Remove when failed; Remove for a handle with no record; each destructive action behind `ConfirmDialog`. `App.svelte` keys the page by id so a reset's navigation starts a fresh page.
- **Nodes list**, **Home tile** ("N joined, M waiting", plus failed), **Connectivity labels**, router entry, nav, and docs (docs/cadre-host.md "In the local UI", README walkthrough and Local UI pages).

## Review findings

Read the full implement diff first, then the server routes and service it calls (`src/server/routes/hosted-nodes.ts`, `src/hosted/hosted-node-service.ts`, `src/hosted/node-status.ts`), and the CLI's claim polling in `src/bin/host.ts`.

**Fixed in this pass (minor):**
- **The code reader retried a 503 forever.** `claimDetails` answers 503 not only while the child starts but also whenever the node reports no address a phone could dial (e.g. a host with no LAN address), and that lasts as long as the node waits. The page showed "Starting the node…" indefinitely with no reason. `ClaimCode.svelte` now treats 503 as "starting" for 60 s (matching the CLI's `CLAIM_DETAILS_WAIT_MS`), then shows the server's message with **Try again**, which restarts the clock. docs/cadre-host.md "Reading the code" says so.
- **The Nodes page read a failed hosted-nodes fetch as "No nodes yet"** — exactly what the slice's `loaded`/`error` fields exist to prevent; only a toast told the user otherwise. `Nodes.svelte` now shows the error line (as the Join page does), shows "No nodes yet" only once the slice has loaded, and "Loading…" only while neither has happened.

**Checked, no change:**
- *Correctness of the live line*: `refreshHostedNodes`' sequence numbers drop a stale success; a stale error after a newer success is also dropped. A stale success could still clear a newer error — harmless, as the next refresh restores whichever is true.
- *Secret handling*: the payload is only in `ClaimCode`'s local state and `TokenShare`'s props, cleared when the node leaves `unclaimed`; nothing writes it to the global slice or browser storage.
- *Effect dependencies in `ClaimCode`*: the effect reads only primitives (`id`, `unclaimed`, `publicAddrs`, `attempt`), so a slice refresh that hands a new `node` object does not refetch; cleanup cancels the retry timer and ignores late answers.
- *Remove of a handle with no record*: the server's `remove` falls through to `removeOrphanHandle` and emits `removed`; the UI's refresh ignores the id. Matches the ticket's edge case.
- *Reset / Retry navigation*: `join()` resolves after the spawn, so the fresh node's handle exists when the keyed page mounts; `destroyed` guards navigation from an unmounted page.
- *Scope additions the implementer flagged* (public-address re-read, Home "failed" clause, Retry confirm, record-only node page, quiet 404): each is small, has a stated reason, and serves the ticket's description. Kept.
- *Event fan-out*: each `hosted-nodes-changed` re-reads three loopback endpoints, and a mutation does so twice (its own refresh plus the event). In-memory reads on the server; not worth a tripwire.
- *DRY*: the "find this node's NAT entry" one-liner appears in `ClaimCode`, `Join` and `NodeDetail`; a lookup this small is not worth a shared helper.
- *Type safety*: mirrored types match the server (`HostedNodeStatus`, `ClaimDetails`, the event names); `STATUS_BADGE` is a `Record` over the status union and `stateLine`'s switch is exhaustive.
- *Docs*: docs/cadre-host.md and the README reflect the new pages and actions; no stale "no Join page yet" text remains.
- *Tests*: only `router.test.ts` gained assertions for `#/join`, which pin real routing. No new tests: the two fixes are template branches and a timeout in a component, which the project has no component-test harness for (`debt-cadre-host-ui-component-tests`, already in backlog).
