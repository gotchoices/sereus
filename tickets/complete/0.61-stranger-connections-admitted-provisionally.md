# Enrolled members admit strangers' connections provisionally

An enrolled member's control-network connection gate no longer refuses a peer it cannot place. Members, delegates, configured infrastructure, and any peer arriving while a stranger window is open (un-enrolled node, outstanding formation invitation, live cadre invitation) are admitted outright. Every other peer is admitted **provisionally**: its connection carries a deadline of `relayedRequestBudgetMs` at the node's own declared link (28.5 s at the default). At the deadline the gate asks `admitInboundControlConnection` again. It keeps the connection if the answer is now `'admit'`, or if the question throws or times out (fail-open). It closes the connection, bounded graceful close then abort, if the answer is still `'admit-provisionally'`. An admitted relay reservation disarms the deadline. The only remaining connection deny is the bring-up quiet period. The per-stream protocol guard is the fail-closed layer that refuses strangers every members-only protocol. Implemented in `ticket(implement): stranger-connections-admitted-provisionally`; the handoff below is the implementer's, kept for the record.

# Implement-stage handoff (as written)

## What changed

Maintainer decision 2026-10-07 (plan `cadre-invite-redeemable-before-the-row-replicates`, option B): the control node's connection gate no longer refuses a peer it cannot place.

- **Verdict.** `InboundConnectionVerdict` is now `'admit' | 'admit-provisionally'`. `admitInboundControlConnection` keeps checks 1–6 as "admit outright"; its fall-through returns `'admit-provisionally'` on every node, relay server or not. The relay-server branch and the `'deny'` verdict are gone. The bring-up quiet period still denies both directions (gater-level, unchanged).
- **Provisional deadline with re-check.** `PendingReserveDeadlines` became `ProvisionalAdmissions`. At expiry it re-asks the policy (through the same `decideWithinDeadline` bound as the admission itself):
  - `'admit'` → connection kept, nothing re-armed;
  - `'admit-provisionally'` → bounded close, abort only as the escalation (unchanged close path);
  - throw or timeout → kept and logged (fail-open).
  - A connection whose `maConn.status` is no longer `'open'` at expiry is skipped without asking.
  - An admitted reservation still disarms all of a peer's deadlines, including one whose re-check is already in flight (the entry stays in the per-peer set until the answer returns, and `release` reports whether a disarm took it).
- **Deadline length.** `relayedRequestBudgetMs` of the node's own declared link (28.5 s at the default), passed from `createControlNode`. Constants renamed: `PROVISIONAL_ADMISSION_DEADLINE_MS`, `PROVISIONAL_ADMISSION_CLOSE_TIMEOUT_MS` (index.ts exports updated). The accepted-tradeoff `NOTE` sits on `PROVISIONAL_ADMISSION_DEADLINE_MS` with the revisit condition "stranger connections show up as load on a member".
- **link-budget.ts.** `relayAdmissionReserveDeadlineMs` removed (and its spec assertion). `RELAY_RESERVE_REQUEST_ROUND_TRIPS` is **kept**: `RELAY_RESERVATION_ROUND_TRIPS` is built from it. Its doc no longer mentions the old deadline.
- **Option-A text removed.**
  - `cadre-node.ts`: check 6's NOTE, the relay-disabled transient-deny NOTE, and the `createCadreInvitation` paragraph.
  - `docs/architecture.md`: the Enrollment Flow paragraph and diagram step 2.
  - `cadre-invite-any-member.integration.ts` header (the wait for M to hold the row is left in place, as asked).
- **Docs rewritten.** The gater module doc, and in `docs/architecture.md`:

## Edge cases, checked by reading the code only

- **Device mid-redemption at expiry.** After the seat, check 6 admits, because the seated row is live. After the redemption commits, check 4 admits, because `listAuthorizedMembers` verifies invitation-admitted rows through `verifyInvitationAdmission`. Before the seat, the device's own per-address budget (same length) has run out too. The scenario that exercises this for real is `implement/cadre-invite-redeemed-at-a-member-without-the-row`.
- **Expiry racing node stop.** `admitControlPeerUnconditionally` returns true when not running, so the re-check answers `'admit'` and teardown closes the connection. The timers are unref'd.
- **Several provisional connections per peer.** Each expires and re-asks on its own; a reservation admission disarms them all.
