# The web reference app runs the edge node — complete

Landed in `ticket(implement): reference-app-web-runs-the-edge-node`. The tab builds one `@serfab/cadre-core/edge-node` edge node over IndexedDB (`web-edge-platform.ts`: the key store and node-local store of `node-local-slots.ts` over the node-local database, `lazyRawStorage` over `strand-storage.ts`'s per-scope databases opened on first use, WebSocket, circuit-relay and WebRTC transports, `/webrtc` as the listen address when a relay is named) and deletes its hand-copied lifecycle (`party-start.ts`, `web-dissolve.ts`, `web-strand-move.ts`, most of `web-join.ts`). The store follows the edge node's status and attaches the page layer to each node it reports running; every store action waits for that attach before resolving. Relays go through the edge config, so the control node and each strand node hold their own supervised reservation. This absorbs `debt-web-app-repeats-the-phone-kit-join-sequence`.

The platform against the `EdgeNodeStorage` contract: `rawStorage` returns a fresh proxy per call over one cached handle and one `IndexedDBRawStorage` per scope, so a scope asked for again after a stop reopens; `close` applies each storage's held writes before closing handles and waits for opens in flight; `destroyScope` closes the scope's storage and handle before the delete request and still throws `StoreDeleteBlockedError` synchronously enough for the existing test. The key store's slot-to-key map and its refusal of text under a slot's key. The store's status following: `followStatus` for each edge-node state, `attach` against a node replaced mid-attach, `attachSettled` against a second `running` report during the wait, `midTransition` against a join cancelled with nothing to go back to, `start` from `removed` and from `error`, `restart` with nothing running. The removal path by inspection only (`forgetRemovedParty` stops, rewrites the saved start, deletes the control database, reports `removed`; the store shows `stopped` for a moment, then the card).
