# Grants page in the cadre-host dashboard

## What was built

A **grant token** is the secret the host owner gives a friend so the friend's phone can ask this machine for donated nodes, up to the grant's `maxNodes`. The dashboard now manages them through the existing loopback admin surface `/grants-admin`, alongside the `cadre-host grant` CLI.

**Server**
- `GET /grants-admin` returns `GrantListing[]`: each grant plus `liveNodes` (same rule as the quota, via the new `isLiveDonationStatus` in `donation-store.ts`) and `donations` (`{ id, status }` of every donation not yet `terminated`, `error` included — the set a revoke tears down). `createGrantAdminHandlers` reads `donations.list()` once and groups by token (`groupByGrant` / `toListing` in `grant-service.ts`). With no donation service wired, every grant lists `liveNodes: 0, donations: []`.
- New SSE event `grants-changed` (`kind: 'issued' | 'revoked' | 'terminated'`), published by the three `/grants-admin` mutations after success only. `GrantsAdminRoutesOptions.events` is required; `server/index.ts` passes the bus.
- CLI `grant list` prints `live=<n> max=<n>`.

**UI**
- Route `#/grants`, nav item "Grants" after Nodes, shown in both roles (not a founder route).
- `state.svelte.ts`: `grants` slice `{ list, loaded, error }`, `refreshGrants()` (called from the page's `onMount`, not at boot). `grants-changed` → refresh grants; `node-state-changed` → refresh grants once the slice has loaded (covers grantee borrows/releases and supervisor respawns, which don't publish `grants-changed`). `NOTE:` tripwire there for the supervisor give-up case.
- `lib/grants.ts`: `grantState` (revoked checked before expiry, like `GrantService.validate`), `sortGrants` (active → expired → revoked, newest first), `DONATION_STATUS_LABEL`, `donationHasNode` (only `awaiting_seed`/`seeded` link to `#/nodes/<id>`).
- `Grants.svelte`: list with label, state badge, `live / max nodes`, issued, expiry, donations (linked where a node exists), **Show token** (active only) and **Revoke** (any non-revoked). Revoke uses `ConfirmDialog` with the real teardown count and a "Keep its N donated node(s) running" checkbox (reset each open) → `?keepNodes=true`; the success toast uses the server's `terminated.length`.
- `GrantIssueModal.svelte`: issue form (label ≤200, max nodes ≥1 or blank for server default, lifetime 30d/90d/1y/No expiry, default No expiry) → token view; or show mode for an existing grant. Tokens live only in component state; nothing touches browser storage.
- `TokenShare.svelte` (QR + textarea + Copy) extracted from `InviteModal.svelte`, used by both. `ConfirmDialog.svelte` gained an optional `children` snippet.
- Home's Donation tile now links "Manage grants →".

## Changes beyond the ticket's list (please scrutinise)

Found while browser-checking; each blocked or visibly broke the new page's flows:

- **Node detail page crashed for every running node** (pre-existing since the local UI landed). The SPA's `NodeStats` mirror said `{ cpu, rssBytes }`; the server sends cadre-provider's `OrchestratorStats` `{ cpuPercent, memoryBytes, … }`, so `stats.cpu.toFixed` threw and the page sat on "Loading node…". Fixed the mirror in `state.svelte.ts` and the two reads in `NodeDetail.svelte`. Every donation link on the Grants page lands there.
- **`refreshNodeDetail` only replaced existing entries** in `state.nodes`, so a node spawned after the last list fetch (the normal case when following a Grants-page link) never rendered. Now an upsert.
- **Header health went to "Attention" after a revoke/terminate via `/grants-admin`**: the terminated node's last `node-state-changed` left it listed as `stopped`. `grants-changed` with kind `revoked`/`terminated` now also calls `refreshNodes()` (covers the CLI too; NodeDetail's own Terminate already did this).
- **`formatRelativeTime` renders any future moment as "just now"**, so expiries would all read wrong. Added `formatRelativeDeadline` ("in 29d" / "3d ago") in `format.ts`, and switched Trust Circle's pending-invite expiry (same bug) to it — a one-line change outside the ticket's list.
- `ui/vite.config.ts` dev proxy gained `/grants-admin` (the Vite dev server could not reach it otherwise).
- README "Local UI" section was stale from before the donor-aware UI (claimed founder pages still show on donor installs, no donor grants view, Stop errors on donated nodes); rewritten to current behaviour while adding the Grants bullet.

## Known gaps / judgement calls for the reviewer

- **Give-up tripwire**: the supervisor writes `error` after the crash event fired, so an open page counts that node live until the next refresh. `NOTE:` at the `node-state-changed` handler in `state.svelte.ts`.
- **Grant state is computed at list-change time**, not on a timer: a grant that expires while the page is open keeps its Active badge (and Show token) until the next refresh. Commented at `grants` in `Grants.svelte`.
- **"expires in 29d" right after issuing a 30-day grant**: `formatSpan` floors, consistent with the past-tense formatter. Cosmetic.
- **Revoke error toast** goes through `reportError`, whose message for an unknown token includes the token text (from the server's `not_found` message). Only reachable if `grants.json` was hand-edited.
- `GrantIssueModal` duplicates the backdrop/dialog CSS from `InviteModal` and `ConfirmDialog` (a third copy of an existing pattern; no shared modal shell exists yet).
- `docs/cadre-host.md`'s "Status" section still describes the donation service as in progress; untouched here.
