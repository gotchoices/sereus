# `publish-package` gained a dist-tag and a prerelease guard

## What shipped

`scripts/publish-package.js` → `scripts/publish-package.mjs` (ES module; it was the last CommonJS
file under `scripts/`). Same entry point, now optionally `--tag <dist-tag>`.

- **`resolveDistTag(argv, env)`** — `--tag <name>` on argv > `SEREUS_DIST_TAG` env var > nothing
  (npm's own `latest` default; no `--tag` flag is passed at all in that case). Validates tag shape
  (`/^[a-z0-9][a-z0-9._-]*$/i`) and rejects a tag that is itself a valid semver version. Throws on an
  unrecognised `--` flag, on a stray bare word, on `--tag` with no value, and on `--tag ""`.
- **`assertDistTagForPrerelease(name, version, tag)`** — refuses when the version has a semver
  prerelease component and no tag was given. `SEREUS_DIST_TAG=latest` is the deliberate escape hatch:
  an explicit `latest` is a decision, an absent tag is an oversight. Runs *before*
  `yarn clean && yarn build`, so a refusal costs seconds and fires per-package inside the six-publish
  `yarn pub` chain.
- **`publishCommand(tag)`** — omits `--tag` entirely when there is none, rather than an explicit
  `--tag latest`.
- **`readManifest(packageDir)`** — throws a clear error naming the manifest path when `version` is
  not valid semver.
- The `cadre-host` release-key placeholder guard is unchanged and still runs after `yarn build`,
  independent of the new prerelease guard.
- `main()`'s invocation is guarded on `process.argv[1]` vs `import.meta.url`, so the test file can
  import the pure functions without triggering a real build-and-publish.

Root `package.json`: six `pub:*` scripts point at `.mjs`; new `test:publish-package`, wired into
`yarn test`. `scripts/smoke-published-install.test.mjs` pins
`published-smoke-support.mjs`'s `/publish-package\.(?:js|mjs)\s+(\S+)/` against both spellings.
`docs/releasing.md` prerelease section and interim-release runbook step 6 now carry real working
commands; `docs/cadre-host.md` and a `release-key.ts` doc comment updated to `.mjs`.

## Why both `--tag` and `SEREUS_DIST_TAG` exist

`yarn pub` is six `&&`-ed publishes. Trailing args land on the *last* command only, so
`yarn pub --tag alpha` would tag `cadre-host` and silently leave the other five at `latest`. An
environment variable is visible to every command in the chain, so `SEREUS_DIST_TAG=alpha yarn pub`
tags all six. `--tag` is for a single package's own script (`yarn pub:cadre-core --tag alpha`),
where there is no chain to lose the flag partway through. Do not "fix" `yarn pub --tag` to work.

## Review findings

### Verified

- **Read the implement diff first**, before the handoff summary. Guard ordering in `main()` matches
  what the ticket asked: `readManifest` → `resolveDistTag` → `assertDistTagForPrerelease` →
  chdir/clean/build → cadre-host key guard → publish. Prerelease guard is before the build and does
  not reorder or subsume the existing key guard.
- **Yarn trailing-arg forwarding actually works** — the docs' `yarn pub:cadre-core --tag alpha` form
  rests on it. Probed with a harmless script (`yarn lint --bogus-flag-xyz` → eslint's own
  "Invalid option" error), confirming Yarn 4.12 forwards trailing args to the script body.
- **`main()` aborts before any build on the failure paths**, exercised by hand (none reach
  `yarn clean`): `--tag 1.2.3` (version-shaped tag), `no-such-pkg` (ENOENT naming the manifest path),
  and the newly-added stray-positional case. All exit 1 with a readable message.
- **Shell-injection surface**: `publishCommand` interpolates the tag into an `execSync` string, but
  every path to it runs `assertPlausibleTag` first, whose regex admits only
  `[a-z0-9][a-z0-9._-]*`. No metacharacter survives.
- **Docs**: read every file the change touches plus `docs/cadre-host.md` § publishing and the
  interim-release runbook. All four `scripts/publish-package.js` references in tracked source/docs
  are updated. `docs/releasing.md` gives POSIX *and* PowerShell env-var forms — correct, since
  PowerShell is this repo's primary shell and `VAR=x cmd` is a parse error there.
- **Lint + tests**: `yarn lint` (exit 0), `yarn test:publish-package` (20 pass), 
  `yarn test:published-smoke-support` (23 pass), `yarn test:dep-ranges` (9 pass),
  `yarn test:vitest-typecheck-coverage` (16 pass), `yarn test:test-file-typecheck-coverage`
  (30 pass), `yarn dep-check` (knip clean of new findings; `check-dep-ranges` green — the `.js`→`.mjs`
  rename needed no `knip.ts` change since `scripts/**` is ignored there).

### Fixed in this pass (minor)

- **Stray positional arguments were silently ignored.** `resolveDistTag`'s loop `continue`d on any
  arg not starting with `--`, so `yarn pub:cadre-core alpha` — a forgotten `--tag`, the single most
  likely typo for this exact feature — resolved to no tag and published to `latest` without a word
  of complaint. Now throws `unexpected argument "alpha" — expected: --tag <name>`; unknown `--`
  flags keep their distinct `unknown flag` wording.
- **Four test gaps closed** in `scripts/publish-package.test.mjs` (16 → 20 cases): the stray
  positional above; `--tag --keep` treated as a missing value (behavior the implementer shipped
  beyond spec and flagged as untested); a malformed `SEREUS_DIST_TAG` refused; an empty
  `SEREUS_DIST_TAG` treated as unset.

### Tripwires (conditional — parked, not ticketed)

- `yarn pub --tag alpha` tags only the last of the six packages. Today that mis-invocation fails
  loudly on package one whenever it matters (a prerelease with no tag trips the guard), and when it
  doesn't matter the versions are stable and `latest` was the right answer anyway — so it is not a
  live defect. It becomes one if the `pub` chain stops being a flat `&&` list of per-package scripts.
  Parked as a `NOTE:` comment on `resolveDistTag`'s doc block in `scripts/publish-package.mjs`.
