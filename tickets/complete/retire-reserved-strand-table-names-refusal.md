# Retire the reserved strand table-name refusal

A strand database holds two engine schemas: `Strand` (built-in membership tables) and `App` (the sApp's tables). Sereus used to refuse an sApp table named like a `Strand` table (`ReservedTableNameError`, in `composeStrand` and `CadreNode.foundStrand`) because optimystic stored both `Member` tables in one collection. Optimystic now stores an unlocated table at `tree://default/<schema>/<Table>` (`table-identity.ts` in `quereus-plugin-optimystic`) and keys its catalog record by schema and name, so the refusal was removed along with its module, exports, tests and doc references. `docs/strands.md` now has a "Same-Named Tables in `Strand` and `App`" section in place of "Reserved Table Names".

Guard test: `plugin.spec.ts` → "an sApp table named like a strand table" inserts into both `Strand.Member` and `App.Member` over one `MemoryRawStorage`, checks each holds only its own row, then reopens and checks the hydrated table count and rows again. The implementer confirmed by hand that forcing a shared explicit location makes it fail with a null-id phantom row.
