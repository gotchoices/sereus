# The joiner hands its join to the launch

## What landed

- **`JoinedStrandSession.rememberForeign` asks the machine-local joined-strand store first.** An identical record (same `Type` and `MemberPrivateKey`) returns before the party's control database is read (`queryStrand` + `queryJoinedStrand`). Otherwise the old order runs. A failed early store read is logged and treated as unknown; the store is asked again only when the party does not name the strand, where a second failure throws to `rememberForeignStrand`, which warns as before.
- **Party-key handoff.** `CadreNode.formedPartyKeys` (in memory, by strand id) holds the key `adoptFormationMembershipInvite` got from `ensureStrandPartyKey`. `resolveStrandPartyKey` takes it (and deletes it) after the explicit key and before the `StrandPartyKey` row. `detachStrand` and `cleanup` drop entries.
- **Accepted-tradeoff `NOTE:` at `rememberFormedStrand`** on why the party-wide `JoinedStrand` row is still published by the connected reconcile pass, with its revisit condition.

Measured by the implementer (two-party strand case of `message-cost-accounting`): B's control-database reads in the `addStrand` phase went from 6 calls / 12 block ids to 3 / 6; `formStrand` and first-insert phases unchanged.

## Review findings

Read the `ticket(implement): joiner-hands-its-join-to-the-launch` diff, the original implement ticket, and the surrounding code (`ensureStrandPartyKey`, `startOrFoundStrand`, `claimTrackedStrand`, `forgetJoinedStrand`, `stopStrand`, `handleStrandRemoved`, `detachStrand`, `cleanup`, `rememberForeignStrand`).

- **Equivalence of the reordered `rememberForeign` (checked by reading, every case).** Identical record: returned before as well (on whichever branch); now returns without the control read. Old code could also throw out of `namedByParty` here; the new code returns quietly, which is the better outcome. Differing record: `namedByParty`, then rewrite keeping the old `joinedAt` — same as before. No record (`find` gives `undefined`, distinct from the `null` failure marker): `namedByParty`, then record, no second store read — same. Early read fails: party names it → quiet return (the case the original ticket asked for); party does not → re-read, throws, `rememberForeignStrand` warns — same as before. `pendingRemovals.delete` still first; `onLocalChange` still only after a write. No defect.
- **Party-key handoff (checked).** Explicit key still wins. Entry is consumed by the first launch that resolves a closed strand's key, whoever triggers it (app `addStrand` or the watcher); the value equals the row either way. An entry left by a formation that failed after the key was seated, or by a re-formation against a strand already running (`claimTrackedStrand` does not resolve a joiner's key), holds the same value as the row. Open strands never set or read it. No defect.
- **Fixed inline: entries survived `stop()`/`start()`.** `cleanup()` is documented as the one teardown and clears the sibling per-strand maps (`sAppConfigs`, `discoveredStrands`, …); `formedPartyKeys` was not cleared, so a restarted instance could use a key a sibling machine rotated while it was down. Added `this.formedPartyKeys.clear()` there.
- **Tripwire parked: direct row deletion.** No `CadreNode` path removes a `StrandPartyKey` row, but `getControlDatabase()` is public, so an embedder calling `deleteStrandPartyKey` between a join and its launch would get the deleted key. Recorded as a `NOTE:` on the `formedPartyKeys` declaration (revisit when a node-level rotation is added).
- **Docs.** `detachStrand`'s doc listed its unconditional deletes; added `formedPartyKeys`. Clarified the comment in `rememberForeign`'s catch. `docs/strands.md` → "What a joiner's node remembers" already explains the publication gate the new `NOTE:` refers to and describes no read order, and `docs/architecture.md`'s formation sections are responder-side or founder-side, so no doc file needed a change.
- **Tests.** None added or cut: the change keeps behaviour and saves reads; there is no branching contract a unit test would pin that the reading above did not settle, and the implementer added none.
- **Type safety / errors / resource cleanup.** No `any`; the early-read failure is logged, not swallowed silently; map entries are bounded by strand count and now cleared on teardown.
