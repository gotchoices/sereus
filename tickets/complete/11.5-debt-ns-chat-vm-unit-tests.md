# Unit tests for `ChatViewModel` on `reference-app-ns`

## What landed

The work landed in `ticket(implement): debt-ns-chat-vm-unit-tests`. There is no source change: `src/chat-vm.ts` and `src/chat-operations.ts` are untouched.

- `test/stubs/nativescript-core.ts` also re-exports the real `ObservableArray`. It loads because Vite transforms `@nativescript/core` itself. The fallback config for the case where Node's directory-import error comes back is documented at the stub.
- `test/stubs/fake-cadre-node.ts`: `fakeStrand(status, { strandId, database })` wraps a Quereus `Database` as `{ getDatabase }`.
- `test/chat-vm.spec.ts` has 13 tests. `chat-operations.ts` runs unmocked against `new Database()` with the app's real chat schema. `ScriptedDatabase` sits between the strand and that database. It classifies each statement by the table it touches and lets a test hold a statement, refuse it, or apply it and then throw. Only `setInterval`/`clearInterval` are faked. The test groups cover the poll's one-read-per-strand guard, participant registration (in-flight guard, retry, waiting for a joiner's database, late attach), the send rule, and the retry key's lifetime.
- `vitest.config.ts` and `docs/reference-app-ns.md` describe the chat suite.

## Review findings

Checked: the implement diff; `chat-vm.ts` and `chat-operations.ts` against every test (each test's path traced through `refresh`/`attach`/`register`/`send`/`settlePendingDraft`); the `vi.waitFor` fake-timer claim (confirmed in vitest 4.1.8 `dist/chunks/test.*.js`: it calls `vi.advanceTimersByTime(interval)` per check while fake timers are on); the schema-apply claim against `applyAppSchema` in `quereus-plugin-sereus/src/compose-strand.ts` (same `declare schema App { … }` / `apply schema App;`, minus the ignored-item check, which does not matter for this fixed schema); teardown; docs.

- **Minor, fixed: an unrecognised query shape failed the test on a count that did not name the cause.** `classify()` threw inside the decorator. For a participant insert, the throw went to `register()`'s `console.warn`, and one test silences that. The failure then read "expected +0 to be 2" with nothing pointing at the SQL. `classify` now returns `undefined`, `admit` records the SQL in `ScriptedDatabase.unrecognised` before refusing it, and `afterEach` asserts the list is empty after cleanup. Verified by temporarily breaking the participant-insert pattern: the run now also reports `statements the scripted database could not classify` and lists the two `insert or ignore into App.Participant …` statements. The file was then restored.
- **Tripwire, parked as a `NOTE:` on `ScriptedDatabase.idle()`:** `idle()` assumes `chat-vm.ts` starts follow-up statements on microtasks. If it ever waits on a timer between two statements, `idle()` can resolve early.
- **Minor, fixed: stale docs.** `packages/reference-app-ns/README.md` described the unit suite as "node-local slots + the `cadre-phone` lifecycle". It now also names the cadre, settings and chat view models. The "Bundle smoke" section of `docs/reference-app-ns.md` said the unit suite "touches two modules", which was already stale after the settings suites. It now says "loads a few modules".
- **Checked, no change: held statements released in `afterEach`.** They finish on a stopped view model over their own `Database`, so nothing crosses into the next test. The run shows no stray output and no unhandled rejections (verbose run of the chat spec). The in-memory databases are not closed; each is small and per-test, so this is not worth teardown code.
- **Checked, no change: fake clock drift.** Each `vi.waitFor` check advances the fake clock 50 ms. A spurious poll would need about 1,200 checks within one test at `POLL_MS = 60_000`, and the slowest test runs about 300 ms.
- **Checked, no change: the referenced bug ticket.** The spec comment cites `bug-ns-chat-shows-previous-strand-messages-after-switch`. The ticket exists (filed at plan time, now in `fix/`). The handoff's "(backlog)" was stale, but the comment gives only the slug.
- **Test value:** all 13 tests pin distinct behaviour with real branching. The two key-retirement tests look alike but cover different cases: edited text, and the same text cleared and retyped (the case the `draft` setter's comment is about). None was cut. No test was added.
- **Type safety and hygiene:** the two `as unknown as` casts are each at a single documented site. The spec is about 480 lines, and the section helpers are small. No major findings, so no tickets were filed.
