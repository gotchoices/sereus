# A wake that lands during a quiesce waits for it and rebuilds

## The defect

`StrandInstanceManager.quiesceStrand` releases a strand's runtime over several awaited steps and only clears its database and libp2p node near the end. A wake during that time (`wakeStrand`, a push-wake, activity on an `idle` strand) saw the handles still attached, took `handleStrandWake`'s "already live" branch and resolved; the quiesce then finished and the strand slept. Activity on an `active` strand during a check-in window's quiesce did not wake it at all.

## What shipped (`ticket(implement): strand-wake-during-quiesce-is-told-the-strand-is-up`)

- **One ordering mechanism in `StrandInstanceManager`.** `transitions` records the latest resume or quiesce requested per strand. Each new request waits for the one before it (its failure is logged and left to its own caller), then for any `startStrand` build, then runs; a request of the same kind as the latest joins it. A resume requested during a quiesce rebuilds after it; a quiesce requested during a rebuild releases the finished runtime; a resume requested after that quiesce builds again rather than joining the earlier resume. `quiesceStrand` writes `hibernating` as its last step (also for a tracked strand with no runtime left). `isQuiescing(strandId)` reports a pending quiesce.
- **Callers.** `handleStrandHibernate`, `runWakeWindow` and `rehibernateAfterFailedResume` no longer write the status the quiesce writes (the last one still writes it when the quiesce throws). `handleStrandWake`, `runServiceWake`, `wakeHostStrandForFormation` and `foundExistingStrand` treat a quiescing strand as not live and wake/rebuild it.
- **Timers (`HibernationManager`).** New required callback `isQuiescing`; `recordActivity` wakes a quiescing strand. The timer-driven hibernate's check-in chain start goes to a wake or probe that holds the strand, and starts only on a strand still `hibernating`. `endProbe` hands its chain to a wake that began during the probe's window. `timerHibernates` stops a force-hibernate that joins a timer-driven quiesce from getting a check-in chain afterwards (adjacent pre-existing defect, with a reproduction test).
- **Docs.** `docs/architecture.md` → Strand Hibernation: the ordering bullet, the `hibernating` bullet, mechanisms 1, 2 and 4.

## Review findings

Read the implement diff first, then the surrounding wake/hibernate/check-in/probe paths in `cadre-node.ts`, `hibernation-manager.ts` and `strand-instance-manager.ts`, the three spec files and the architecture doc.

**Checked, correct as shipped:**

- Ordering in `resumeStrand` / `quiesceStrand`: no `await` between reading `transitions` and `holdTransition`, so two callers cannot both start; `holdTransition` releases only its own entry, and its `then(release, release)` leaves no unhandled rejection; `settleTransition` never rejects. Sequences checked by hand: Q→R, R→Q→R, Q→R→Q→Q (the last Q joins), a failed R followed by its re-hibernate quiesce.
- Status writes: every quiesce path marks `hibernating` before any resume queued behind it writes `starting`. `rehibernateAfterFailedResume` writing only on a throwing quiesce is right: an unconditional write could land after a queued resume's `starting`.
- Activity: nothing in the quiesce path itself records activity (the only `recordActivity` callers are `handleStrandWritable`, `recordStrandActivity` and `wakeHostStrandForFormation`), so a quiesce cannot wake itself through the new `recordActivity` arm.
- Timer paths: a wake started by activity during a timer-driven quiesce receives the check-in chain and, on settling live, gets only the idle countdown. Verified by reading `startCheckInChain`, `handCheckInChainToHolder` and `settleWake`.
- `HibernationCallbacks` gained a required member; the only implementer is `CadreNode` (grep over `packages/`), and AGENTS.md says no backwards compatibility yet.
- Tests the implementer added: each pins a specific ordering or reproduces a defect; the `fakeManager` consolidation in `cadre-node.spec.ts` removes five hand-written fakes. None cut.
- Docs: the touched architecture bullets match the code. The "(… or quiescing)" refusal case is gone from both the doc and the error message.

**Found and fixed in this pass:**

- **A force-hibernate during a wake's rebuild left an idle countdown armed on the quiesced strand** (major; reachable when the mobile app backgrounds while a foreground wake is rebuilding). The quiesce is now correctly queued behind the rebuild, so the wake settles `active` while the quiesce is still pending, and `settleWake` → `rearmIdleIfLive` armed the idle timer. That timer later wrote `idle` over the quiesced strand, and the hibernate timer then started a check-in chain on a strand the runner means to keep down. Fix: `rearmIdleIfLive` arms nothing while `isQuiescing`, the one site every settle path goes through. Reproduction: `hibernation-manager.spec.ts` → `a force-hibernate during a wake's rebuild leaves no idle countdown when the wake settles`. It failed before the fix (`onIdle` called) and passes after.
- **A wake window that saw activity wrote a live status over a strand force-hibernated during the window** (pre-existing, same area). `runWakeWindow` wrote `liveStrandStatus(instance)`, which is `syncing` for an instance with no database. The strand then read `syncing` with no runtime, and `recordActivity` does not wake a `syncing` strand. Fix: the live-status write and the `strand:waking` emit happen only while a runtime is still attached. A force-hibernate's `hibernating` stands, and a wake queued behind it writes its own status. Reproduction: `cadre-node.spec.ts` → `a strand force-hibernated during a window that saw activity stays hibernating`. It failed before the fix (`syncing`) and passes after.
- `docs/architecture.md`: the ordering bullet now states both behaviours.

**Considered, no action:**

- The implementer's own known gaps need no ticket now:
  - `stopStrand` is outside the ordering. This is pre-existing: a resume queued behind a stop fails "not tracked", and a quiesce queued behind one no-ops.
  - `attachSApp` does not wait for a pending quiesce, so its documented throw remains.
