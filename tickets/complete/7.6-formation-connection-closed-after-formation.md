# The joiner closes the formation connection it opened

## What landed

`strand-formation-protocol.ts`, initiator side only:

- `openFormationStream` no longer calls `dialProtocol`. `dialFormationChannel` reads the ids of the node's open connections, then `node.dial(addrs, { signal })`, then `connection.newStream(protocolId, { signal })`, and returns `{ stream, connection }`. A connection whose id was not in that snapshot was opened by this dial.
- `formationConnectionUsers` (module-level `WeakMap<Connection, number>`) holds each connection a formation dial opened, with the number of formation exchanges using it. `useFormationConnection` adds one; a connection that was already held is entered only if another formation dial already entered it. `releaseFormationConnection` subtracts one; at zero it drops the entry and closes the connection gracefully (libp2p's own 1 s close timeout), and on a failed close it logs and aborts, as libp2p's `hangUp` does. Never throws.
- Release points: `exchangeContact`'s `finally` (answered, refused, failed validation, await-response timeout), the `newStream` failure path inside `dialFormationChannel` (including a dial that resolves after the deadline: `signal.throwIfAborted()` runs before `newStream`), and `abandonLateChannel` (a channel that resolves after the dial deadline: stream aborted, connection released). Each use is released exactly once.
- `withTimeout` checked: it does not cancel the inner work, but every inner step is bounded on its own (the dial by `withDeadline`, the read by the await-response budget, which is clamped under the session), so `exchangeContact`'s `finally` always runs, shortly after the session deadline at worst. No outer-path close was needed.
- Doc: one paragraph in `docs/architecture.md` → Strand Formation; doc comments on the new functions.

### Deviations from the plan

- **Count instead of the plan's "no other open formation stream on the connection" check.** After a timed-out exchange, its own half-closed stream is still listed in `connection.streams`, and a concurrent exchange whose stream is still negotiating may not be listed yet, so the stream check could leave the connection open or close it under a live exchange. The count is exact for formation's own uses. Same rule otherwise: a connection that was not opened by formation is never closed.
- **Part 2 (skip a relay whose identify lists no strand-addr) was implemented, measured, and reverted.** The control node's identify is namespaced (`/optimystic/control-<party>/id/1.0.0`), a dedicated relay serves only `/ipfs/id/1.0.0`, so the control node never identifies it, and its peer-store record holds only what this node negotiated with it (`hop`, `/ipfs/ping`). The plan's rule (non-empty list without strand-addr) would also match a same-party relay in the moment before its identify lands, which needs the grant; a rule gated on identify having run never matches a dedicated relay and only matches a same-party relay before its strand-addr handler registers, the one relay that must be asked. Measured with it in place: still 2 refused asks at `foundStrand` and 2 at `addStrand`. Both of each pair log in the same millisecond, so they come from two concurrent passes (callers not traced). Filed as `backlog/debt-dedicated-relay-asked-for-strand-addr-at-each-start` with the directions found. `cadre-node.ts`, `delegate-admission.ts` and the "Delegate announce" bullet are unchanged from HEAD.
- `node.dial` gives the formation dial libp2p's user-dial priority (75) in the dial queue; `dialProtocol` used the default (50).

## Measurement (strand case, `MESSAGE_COST_MEASURE=1 MESSAGE_COST_CASE=strand`)

Before (earlier run the same day, before this change): `formStrand` 1 failed FRET ping A.ctl→B.ctl; settle 2 failed `control-<party>/fret/ping` A.ctl→B.ctl and 3 B.ctl→A.ctl; idle 0 failed FRET pings between the control nodes and 2 `/ipfs/ping` each way.

After: `formStrand` none; settle 3 failed each way, plus a new relayed dial (`B.ctl->relay hop` 1, `relay->A.ctl stop` 1); idle 0 failed FRET pings and 2 `/ipfs/ping` each way between the control nodes.

The connection does close: with `DEBUG=optimystic:fret:service:fret`, both control nodes log `peer:disconnect` about 100 ms after the formation contact. About 4.2 s later one control node's FRET reconnects to the other (`peer:connect`, then negotiate strikes 1, 2, 3), and that connection stays up through the idle minute. This matches FRET's `probeMembership`, which redials a peer that is not connected before pinging it; not traced to the call. So the plan's expected result (no FRET pings or libp2p pings between the control nodes) is **not met**, and the remaining traffic is FRET's. Recorded as evidence on `blocked/fret-maintenance-probes-peers-off-its-ring`, whose "Sereus's side meanwhile" had assumed this close would remove that peer. A Sereus-side way to stop the redial (for example dropping the inviter's control node from the joiner's peer store after formation) was not tried; it would work around FRET by editing shared libp2p state.

The strand-addr asks to the dedicated relay are unchanged (2 at `foundStrand`, 2 at `addStrand`); see the backlog ticket above.

## Review findings

Read the implement diff (`ticket(implement): formation-connection-closed-after-formation`) first, then libp2p 3.3.11's `Connection.close` and `@libp2p/utils` 7.4.1's `AbstractStream.close`.

- **Release exactly once: checked, holds.** `withDeadline` aborts its signal only from its timer, and `pending`'s first `.then` (which checks `signal.aborted`) is registered before the `await` continuation, so a channel either reaches `exchangeContact` (released in its `finally`) or is passed to `abandonLateChannel`, never both and never neither. A dial that resolves after the abort is released by `throwIfAborted` in `dialFormationChannel`; a `newStream` that resolves after it is released by `abandonLateChannel`. A late rejection after release is swallowed by `withTimeout`'s settled promise. No change.
- **`exchangeContact`'s `finally` always runs: checked.** Dial is bounded by `withDeadline`, the read by the await-response `withTimeout`, so neither waits on the session timeout. `await stream.close()` (no signal) can wait only on its write queue reaching idle, which for a contact frame far under yamux's initial window does not block; not a tripwire, because a contact that size is not a reachable state. `connection.close()` uses libp2p's 1 s close timeout, and the abort-on-failure path matches libp2p's `hangUp`. No change.
- **Count versus stream check (the deviation from the plan): agreed.** A half-closed stream remains in `connection.streams` after a timed-out exchange, so the count is the right representation. No change.
- **Joined dial counted as formation's:** the `NOTE:` on `dialFormationChannel` is an adequate tripwire; nothing else dials an inviter's control node first today. No change.
- **FRET redial result (the reviewer question):** stays with `blocked/fret-maintenance-probes-peers-off-its-ring`. By the measurement above the change is about neutral on cost until FRET is fixed: settle goes from 5 to 6 failed FRET pings, plus one relayed connection, and idle does not change. Once FRET stops probing peers it labels foreign (that ticket's item 1), the closed connection is not reopened, and the 2 `/ipfs/ping` each way at idle go away too, which leaving it open would not achieve. Keep it. Dropping the inviter from the joiner's peer store as a workaround was declined (it edits libp2p state that other services read). Fixed inline: the blocked ticket's "Sereus's side meanwhile" first paragraph still said this change removes the off-ring peer, which the measurement under it contradicts; reworded.
