## What landed

No product code changed. The relay machinery believed complete — per-relay
configured circuit listeners for strand nodes, the search-route + explicit-drive
reservation for control nodes, the strand-addr RPC with delegate announce —
worked end to end on the first run. What landed is proof, a fixture, one
measured defect filed to backlog, and docs.

**`packages/integration-tests/src/harness/dedicated-relay.ts`** — an ungated
bare-libp2p circuit-relay fixture mirroring the `ops/docker/libp2p-infra`
container (`SEREUS_ROLE=relay`): `circuitRelayServer` with
`applyDefaultLimit: false` (load-bearing — db-p2p's database protocols do not
run on "limited" connections, so a default-limit relay kills every strand data
stream) and a raised `maxReservations`, stock `identify`, loopback WebSocket
listener. Exposes `dialAddr` (with `/p2p/<peerId>`), `reservationCount()`, and
`restart()` — same key, same port, all reservations dropped. The module doc
names the config-parity contract with the ops container and the deliberate
divergences (no TCP listener, no `ping()`, in-memory key). `@libp2p/identify`
added to `integration-tests`' dependencies, pinned to `4.0.10` to match
cadre-core's pin.

**`packages/integration-tests/src/scenarios/strand-circuit-same-party-e2e.integration.ts`**
— one phased test, one party, two `CadreNode`s **both** with `listenAddrs: []`
and `relayAddrs: [<dedicated relay>]` (a shape no prior test covered even for
the control network). Asserts, in order: both control nodes come up relay-only;
the control mesh forms through the relay and classifies `relayed`/`circuit-relay`
per `summarizeConnectionPaths` on both sides; A founds a strand and its
configured-route reservation lands; the strand-addr RPC over the relayed control
connection answers with A's live strand addrs, `/p2p-circuit` first; B launches
the same strand from the RPC-resolved seed alone; the A↔B strand connection
classifies `relayed` on both ends; the relay holds **4** reservations (2 control
+ 2 strand — the first measurement of the per-strand relay-slot cost); App rows
written on A read on B and vice versa across the circuit; and, after
`relay.restart()`, both control nodes re-reserve on their own while the strand
nodes never do (pinned by an inverted 15 s gate plus direct assertions).

**`tickets/backlog/bug-strand-relay-reservation-not-resupervised.md`** — the one
defect the characterization measured: nothing re-drives a strand node's lost
configured-route reservation. `repro: verified`.

**Docs** — `docs/architecture.md` (Relay Integration), `docs/strands.md` (SN–SN
use case), `docs/testing.md` (topology coverage map).

## Review findings

### Read first, summary second

The implement diff was read in full before the handoff summary — the fixture,
the scenario, both doc blocks, and the backlog ticket. The backlog ticket's
static claims were then re-derived independently from
`node_modules/@libp2p/circuit-relay-v2/dist/src/transport/reservation-store.js`
and from `packages/cadre-core/src/relay-reservation.ts`, rather than taken on
trust.

### Verified independently (no defect)

- **Ops-container config parity is real.** `ops/docker/libp2p-infra/src/main.ts`
  confirms `applyDefaultLimit` defaults to `false` (`RELAY_APPLY_DEFAULT_LIMIT`)
  and `maxReservations` to 500 (`RELAY_MAX_RESERVATIONS`), that role `relay`
  adds no DHT, and that `identify()` + `ping()` are the service set — so the
  fixture's documented divergences are complete and correct.
- **The backlog ticket's mechanism is exactly right.** In circuit-relay-v2 v4,
  `#removeReservation` re-queues a pending reservation id **only** when the
  removed reservation's `type` was `'discovered'`, and `addRelay(…, 'discovered')`
  throws `HadEnoughRelaysError` when `pendingReservations` is empty. A
  configured-only node therefore has nothing to re-drive and no way for the
  existing drive to re-drive it. The control node recovers for the mirror-image
  reason: its reservation is `'discovered'`, so the id comes back.
- **The `StrandWatcher` claim in `docs/architecture.md` holds.** A failed launch
  leaves nothing tracked and is retried under `pollInterval * 2^(failures-1)`
  capped at `MAX_RETRY_BACKOFF_MS`, never abandoned (`strand-watcher.ts:144-192`).
- **Repo conventions followed**: single-`it` phased scenario (same as
  `strand-addr-seed-convergence`), `Promise.allSettled` teardown (5 sibling
  scenarios), `console.log` in scenarios (73 existing uses), exact dependency
  pin matching cadre-core.

### Minor — fixed in this pass

- **`docs/testing.md` topology coverage map was stale — the doc the change most
  needed and did not touch.** It still listed "**Uncovered**: relayed strand
  plane / per-strand NAT reachability" and pointed the relayed-control-plane
  line at that uncovered class, both of which this scenario closes. Added a
  covered line for the new scenario (with the slot-cost and restart-asymmetry
  measurements) and narrowed the uncovered line to the genuinely still-open
  cross-party shape, naming the two queued tickets. Both referenced slugs
  (`formation-carries-strand-addrs`, `blind-relay-phone-to-phone-e2e`) were
  confirmed present on the board.
- **Silent truncation in `dedicated-relay.ts`'s address derivation.**
  `dialAddr.slice(0, dialAddr.indexOf('/p2p/'))` returns a string one character
  short when `/p2p/` is absent (`indexOf` → `-1`), which would have handed
  `restart()` a malformed listen addr with no error. Now strips the exact
  `/p2p/<peerId>` suffix and throws with the observed addrs if the shape does
  not match.
- **`restart()` did not verify it re-bound the same address.** A restart that
  silently landed on a different port would look *identical* to the fault the
  scenario characterizes — nobody re-reserves — so the fixture's central
  measurement could have been produced by its own bug. `restart()` now throws if
  the rebuilt node does not advertise `dialAddr`.
- **Type-lazy service access.** `(node.services as { relay: CircuitRelayService }).relay`
  replaced by a declared `RelayServices` map and `createLibp2p<RelayServices>`,
  so `node.services.relay` type-checks without a cast (AGENTS.md: "not type
  lazy").
- **Comment contradicted its own constant.** `DEFAULT_MAX_RESERVATIONS = 100`
  was documented as "mirroring the ops container's raised default (500)".
  Reworded to say what it actually does: same posture, sized down, clearing
  libp2p's default of 15.
- **Stale-snapshot race in the strand-addr assertion.** The seed's addrs were
  compared against `aStrandAddrs`, snapshotted before the RPC; A gaining an addr
  in between would have failed the test on a timing accident. Now sampled live
  at assertion time.
- **The inverted gate could pass for the wrong reason.** `waitUntil` swallows a
  throwing condition, so "the wait timed out" alone does not prove the
  behaviour. Added a direct `expect(strandRecovered()).toBe(false)` alongside
  the existing relay-side `reservationCount() === 2`.
- **Unverified claim presented as measured.** The relay-down-at-launch paragraph
  in `docs/architecture.md` sat between two measured claims and read as one.
  Marked explicitly as read off the code, not measured (the claim itself was
  then verified — see above).

### Major — none filed, and why

No finding rose to a new ticket. The one product defect this work exposes was
already filed by the implement stage
(`backlog/bug-strand-relay-reservation-not-resupervised`), correctly rooted at
one site with `repro: verified`; re-filing an arm of it would be duplication.
Everything else was a fixture or documentation defect fixable in this pass. The
site-claim grep over `tickets/{backlog,fix,plan,implement,review}` for the
touched paths returned only that ticket.

One improvement was made **to** that ticket rather than as a new one: its
"shape of a fix" section named two candidate approaches; the reservation-store
read above shows a third and cheaper one — drive with
`addRelay(peerId, 'configured')`, which has no pending-id precondition — so the
three shapes are now listed in rising cost, with the precondition spelled out.

### Tripwires — one, parked in code

- The restart phase's 15 s inverted gate is a **window**, not a proof of
  "never". If a future libp2p re-reserves a configured route on a cadence slower
  than that window, the gate starts passing vacuously. Parked as a `NOTE:` at
  the gate itself in
  `strand-circuit-same-party-e2e.integration.ts`, naming the widen-it-then
  action and the backlog ticket to re-read.

### Considered and left alone

- **No unit spec for `dedicated-relay.ts`.** Sibling harness modules with specs
  (`block-store-probe`, `control-node-config`) are pure functions; this fixture
  is a real libp2p node whose only meaningful assertions are the ones the
  scenario already makes end to end. A spec would restate the scenario at higher
  cost.
- **`DedicatedRelay.node` and `.peerId` are unused by the current scenario.**
  Left as deliberate fixture surface — `node` is the escape hatch for a future
  scenario needing the raw relay, and `peerId` is now the basis of the suffix
  strip rather than dead weight.
- **Indentation is spaces, while several sibling harness files use tabs.** The
  harness directory is already split roughly half and half (10 files each way)
  and nothing machine-enforces it, so normalizing one new file would be noise.
- **The `it.skip`/loosen-assertions escape hatch was not needed** — no test
  failed, so no `tickets/.pre-existing-error.md` was written.
