# Phone reference app: "Devices and nodes" and the removed card

## What landed

Built in `ticket(implement): reference-app-rn-devices-and-nodes`; documented in `docs/reference-app-rn.md` → "Devices and Nodes" and "When this app is removed".

- **Settings → Devices and nodes** (`src/machines-section.tsx`, words in `src/machines.ts`): one row per machine `CadreNode.listMachines` reports (kind from the published profile, "(this device)", Owner, Last seen, Key fingerprint, "Not trusted here", owner keys with no machine), plus live invitations targeted at a peer that has not joined ("Invited, not joined yet", with Withdraw). Add a device or app now lists open invitations only, so each invitation appears once, and tells Devices and nodes to re-read after a mint or withdraw.
- **Remove** (owner devices, not on this device's own row): reads `planMachineRemoval`, shows what happens, one Keep switch per dependent (a device added as an owner is one switch covering its peer row and its owner key: `dependentsOf` / `revouchFor`), the own-dependency line, and what removal does not do. A refused plan shows the reason and only Close; a machine already gone shows "Already removed". Plan reads and removals run one at a time; a read finishing after the node changed is dropped.
- **The removed card** (Settings, Node section): `use-cadre.ts` follows the kit's status; on `removed` it drops the node, clears the join flow and strand selection, sets `removedFrom`, and re-reads the saved start. Buttons: Go back to your own cadre (when the app founded one), Join a cadre, OK.
- **Cold-start fix**: the hook clears the runner's cold-start options as soon as the node emits `cadre:removed`, so a foreground return before the kit finishes deleting storage cannot rebuild the removed party.
- `WithdrawPrompt` is shared from `settings-controls.tsx`; `docs/cadre-host.md` links the new section; the blocked device-run ticket `rn-device-run-join-existing-cadre` gained a row for this screen and the card.

## Review findings

Read the implement diff first, then the cadre-core types and plan logic (`packages/cadre-core/src/types.ts` `CadreMachine` / `MachineRemovalPlan`, `machine-removal.ts`), the kit's removal path (`packages/cadre-rn/src/phone-node/node.ts` `forgetRemovedParty`, `leaveRemovedStart`, `switchParty`; `options.ts` `startAfterRemoval`), `use-join-flow.ts`, and `push-wake-native.ts`.

**Correctness — checked, no defect found.**
- The `onPhoneNodeStatus` effect calls `follow(getPhoneNodeStatus())` again whenever it re-subscribes, which would bring back a dismissed card if `forgetRemovedParty` changed identity. It doesn't: `showNode` and `dismissJoinFlow` (through `setJoinFlow`) are `useCallback`s with stable deps, so the effect runs once per mount.
- The kit reports `removed` only after rewriting the saved start, so `returnToOwnCadre` reading the saved start gets the former party (matches `startAfterRemoval`). Join a cadre from the `removed` state: the kit's `switchParty` reads the saved start when nothing runs, so the founded party is carried as `formerPartyId`, as from a normal stop.
- A removal while another party runs (a join finished first): the kit deletes only the removed party's storage and reports no `removed`. The hook had already unsubscribed from the old node when the join dropped it, so `optsRef` keeps the new party's options. Correct.
- `remove` reads `kept` from the render that confirmed, which is current. The confirm can only open when not busy, so `exclusive` never drops a confirm. The section unmounts with the connected view on any node change, so the prompt cannot act on a different party.
- The Connect-form effect in Settings now applies a null saved start once `savedStartRead` is `read`. It can only fire while the form is hidden (launch read, join, removal), so it never overwrites an edit.
- `dependentsOf` for an owner-only entry (`isMember: false`) finds its machine by key and gets its own switch. `MachineRow` keys are unique because `describeMachines` de-duplicates peer ids.
- Push-token rotation after a removal registers against `getPhoneNode()`, which is null, so it defers like during a join. No new leak.
- "Last seen" wording: the heartbeat is `DEFAULT_PEER_RECORD_HEARTBEAT_MS` (7.5 minutes, `cadre-node.ts`), matching the doc.

**Error handling — one tripwire.** If the kit fails to act on a removal (its saved-start write throws), it reports `failed` after stopping the node. The hook follows only `removed`, so the screen would show a stopped node as connected. This needs a storage failure, so it is conditional. Parked as a `NOTE:` at the status-follow effect in `src/use-cadre.ts`. If `returnToOwnCadre`'s `start` fails, `start` sets status `error` and shows `cadre.error` at the bottom of Settings, and the card stays with its buttons enabled again. Acceptable.

**DRY — fixed.** The diff added a third identical `errorMessage` helper (already in `add-device-section.tsx` and `recommend-app-section.tsx`). Moved it into `settings-controls.tsx` as one export and imported it in all three sections.

**Docs — fixed one gap.** The handoff named a gap the doc did not state: the removed card is screen state and is gone after a restart. Added that sentence under "When this app is removed" in `docs/reference-app-rn.md`. The other touched docs (`cadre-host.md` link, the file list, Outstanding invitations now open-only, "listed under Devices and nodes" in the Allow and recommendation paragraphs, and the removed "Not covered here" bullet) match the code.

**Tests — kept both, added none.** `machines.spec.ts` pins the one branching helper, where a defect would re-vouch half a device. The `use-cadre` test reproduces the cold-start bug and was confirmed to fail without the fix. Neither restates the implementation. No new test, since the review found no defect that needed one.

**Judgement calls in the handoff — accepted as they stand.** These are stated in the doc or at a `NOTE:` site:
- The OK button.
- Buttons follow `isOwnerDevice` while the plan judges the enrolled key; a mismatch shows the refusal with Close.
- Targeted invitations for machines already in the cadre are listed nowhere: a `NOTE:` at `pendingDeviceInvitations`.
- Two modals at once follow the AddNodeSection pattern.
- "Last seen" is relative to the last read.

**Type safety, resource cleanup, performance — nothing found.** The new code has no `any`. Every subscription returns its unsubscribe (`node.on/off`, `onPhoneNodeStatus`). The list is read on demand only, and nothing polls.
