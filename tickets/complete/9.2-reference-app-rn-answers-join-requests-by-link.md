# Phone reference app answers a join request opened as a link (owner side)

The owner app's half of the same-phone join. **A** is this app, holding the cadre; **B** is the app asking to join. The joining side is `reference-app-rn-asks-owner-app-by-link`.

## What was built

- `app/+native-intent.tsx` routes the kit's `parseCadreLink` results: a `join-request` link to `/settings?joinRequest=…`, a `join-response` link to `/settings?joinResponse=…` (read by the joining-side ticket). The node-code case is unchanged; no path is logged.
- `app/settings.tsx` → `useLinkedJoinRequest` reads and clears the parameter, decodes it (a decode failure is an alert, no answer), refuses this app's own request with the own-request alert, answers `no-cadre` while the first-launch condition `asking` holds (alert when there is no reply), and otherwise holds the request until the node is connected, with a waiting hint on the Node card. It then passes the decoded request to `AddDeviceSection`.
- `src/add-device-section.tsx`: a request that arrived as a link and carries a reply is answered instead of alerted (`not-owner`, `already-member`); the prompt uses the link wording with Allow / Deny (system back = Deny); Allow mints and opens B with the invitation, falling back to the ShareCode view with a note when B cannot be opened; Deny answers `denied` and starts a 30-second cooldown during which answerable requests are denied without a prompt. A pasted request with a reply is never answered by link.
- `src/join-link.ts`: `answerJoinRequest` builds the answer with `joinResponseLink` (app name from `ownAppName()`, shared with `joinRequestText` in `cadre-phone.ts`), opens it, returns whether it opened, never throws, and strips the response body from the logged error.
- `app.json`: kit plugin with `appLinks: true` (native rebuild needed).
- Docs: `docs/reference-app-rn.md` → "Adding a Device or App" ("Opened from another app on this phone"), the system-camera section, "When Native Rebuild Is Needed"; `docs/architecture.md` → "Between apps on one phone".

Validation: typecheck, lint, the package's 155 tests and the Android bundle (`test:bundle`) all pass. **Not run on a device**: link delivery, the Android chooser, cold start with a link, and whether `redirectSystemPath` receives the full URL for the iOS `<scheme>://cadre-join-request/…` form. The joining-side ticket files the device-run ticket.

## Review findings

Read the diff of `ticket(implement): reference-app-rn-answers-join-requests-by-link` before the handoff, then the kit's `app-link` source (`links.ts`, `join-response.ts`) it calls.

**Checked, no defect found:**
- Behaviour against the implement ticket's spec, point by point: routing, holding and clearing the parameter, own-request and no-cadre settled at Settings level, the waiting hint's two wordings, answer-instead-of-alert, link prompt wording, Allow / Deny, cooldown, one-at-a-time, request without a reply, `app.json`.
- Security: only a request from `linkedRequest` (`viaLink`) is ever answered by link, so a pasted request with a reply never makes A open another app. The answer URL is built by the kit from `reply.scheme`, which `joinResponseLink` re-validates; `answerJoinRequest` catches both its throws (bad scheme, `CadreLinkTooLongError`) and the `openURL` rejection. The logged error drops the response body after `CADRE_JOIN_RESPONSE_PREFIX`; the route path is never logged.
- Launch read still `reading`: `asking` is false, so the request waits and is answered `no-cadre` once the read says there is no cadre. Launch read `failed`: held with the disconnected hint. Mid-join (`joinFlow` set): held, hint on the "Joining…/Switching cadre…" card.
- `+native-intent.tsx` now imports `@serfab/cadre-rn/app-link` (and so `@serfab/cadre-core`) at link time; the polyfills are the entry's first imports (`index.js`), and `src/node-claim.ts` already pulled `@serfab/cadre-core` into this file, so load order is unchanged.

- Type safety: `AnswerableJoinRequest` via the `isAnswerable` guard; no `any`. Error handling: every `void` call ends in a function that catches and logs. Comments say why, not what.
- File size: `add-device-section.tsx` is 557 lines and `settings.tsx` 640 (`wc -l`); both were already large and this change adds about 70 and 85. No split filed: no section of either has an obvious seam the change created.
