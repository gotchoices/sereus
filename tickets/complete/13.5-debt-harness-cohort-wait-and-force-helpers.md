# Complete: control-cohort observe/wait helpers, and widened forcing helpers

Harness helpers only. The scenario that drives a real three-machine control write with
them is the follow-on `debt-harness-party-multi-machine-control-write` (in `implement/`).

## Vocabulary

- **Control cohort** — the peers a control-database write is offered to, derived by
  `Libp2pKeyPeerNetwork.findCluster(key)`. The write commits on a super-majority; a
  **one-member** cohort commits on the writer's own vote, so a passing write proves
  nothing about how many machines took part.
- **Party** — `createTestParty` output: one owner node plus zero or more **drones**.
  Drones dial only the owner, never each other.
- **Harness node** (`TestCadreNode`) — a bare libp2p node in a party, distinct from
  `CadreNode`, the `cadre-core` class whose libp2p node sits behind `getControlNode()`.

## What shipped

### `harness/control-cohort.ts` (new in implement)

Exported from `harness/index.js`; deliberately not in `wait-utils.ts`, whose only import
is `debug`.

- `CONTROL_COHORT_PROBE_KEY` — one fixed probe key. Sound because `findCluster` returns
  the ring's closest-k serving peers with k = `CONTROL_REPLICATION_BREADTH` (16), so in a
  party under 16 nodes it returns every peer FRET classifies as serving this network,
  whatever key is asked.
- `readControlCohort(party, node?)` — one-shot read, owner by default.
- `waitForControlCohort(party, minPeers, options?)` — polls to `minPeers`, resolves to the
  member peer ids. Defaults `timeoutMs` 15000, `intervalMs` 250; `options.node` picks
  whose view to observe.
- `observeControlCohorts()` — wraps (does not substitute) the installed `findCluster` and
  records call count + per-call cohort size. The anti-vacuity instrument for wait-based
  tests.

### `harness/key-network-patch.ts` (new in review)

`patchKeyNetwork(who, method, build)` — the one place any helper installs over
`Libp2pKeyPeerNetwork.prototype.findCluster` / `findCoordinator`. Its `restore()` checks
that this patch is still the top of the stack and throws naming the reverse-order rule
otherwise, instead of reinstating a stale method. The throw does **not** latch, so a
`finally` that unwinds the later patch can then restore normally. `forceFullCohort`,
`pinCoordinator` and `observeControlCohorts` all go through it.

### `harness/forced-cluster.ts` (widened in implement, hardened in review)

`forceFullCohort` and `pinCoordinator` take `readonly CohortNodeSource[]`, where
`CohortNodeSource = CadreNode | TestCadreNode | Libp2p`, resolved by one shared
`resolveControlLibp2p`. Discrimination is `in`-based: `getControlNode` → `CadreNode`;
`libp2p` → `TestCadreNode`; otherwise a structural `Libp2p` check. Unambiguous today
because `CadreNode`'s control node is the private `controlNode` and `TestCadreNode` has no
`getControlNode` — stated in a comment so adding either field to the other type is a
conscious change. Both handle contracts and both loud checks (no multiaddrs, no public
key) are unchanged.

## Review findings

Read the implement diff (`b40037d`) first, then the sources it touched and the ones it
should have. Verified against upstream rather than taken on trust: `keyNetwork` really is
attached to the node (`../optimystic/.../libp2p-node-base.ts:1301`); the harness really
passes `clusterSize: CONTROL_REPLICATION_BREADTH` = 16 (`test-party.ts:52`,
`quereus-plugin-sereus/src/cluster-size.ts`); `findCluster` really is uncached and really
does return closest-k serving peers plus self, while only `findCoordinator` caches
(`../optimystic/.../libp2p-key-network.ts:383,556`). All three header claims hold.

### Fixed in this pass (minor)

- **A persistently failing `findCluster` was reported as a network that never converged.**
  `waitUntil` swallows a throwing condition as "not yet" and reports only a generic
  timeout, so `waitForControlCohort` would say "saw a cohort of 0" when the real story was
  an exception on every poll. The poll body now catches, keeps the last error, and the
  timeout message carries it. (The `cause` stays the caught timeout — the
  `preserve-caught-error` lint rule is right about that — so the underlying failure is
  reported in the message text.)
- **Out-of-order restore was documented but unenforced**, and silently left a patched
  prototype installed for the rest of the suite. Now `key-network-patch.ts` throws naming
  the rule. Both header comments were repointed at it. The only real caller,
  `control-write-degraded-cohort-member.integration.ts`, already tears down in the correct
  order (`pinned` then `forced`), so the guard does not change its behaviour.
- **`forceFullCohort` silently deduplicated a node listed twice**, forcing a cohort
  *smaller* than the caller listed while `cohortSizes()` reported the smaller number —
  precisely the vacuous-consensus shape the helper exists to prevent. Now a named throw.
- **The probe was spelled out at two call sites**; extracted to one `probeCohort`.
- **Measurement drift in the comments.** `control-cohort.ts` and `test-party.ts` both
  asserted "~5 s ring convergence"; the three-node wait resolves in 791 ms (re-measured
  this pass). Both now say "a few seconds — sub-second for a three-node party, ~5 s worst
  observed", and the 15 s default is described as a generous multiple rather than "≈3×".

### Coverage added (the implementer's own listed gaps)

The scenario went 7 → **12 tests, 11.8 s**. New cases, all green:

- a bare started `Libp2p` as a cohort source — the third `resolveControlLibp2p` branch,
  previously unexercised;
- an unrecognised shape — the throw naming the keys it saw;
- the same node listed twice — the new duplicate throw;
- a node with no attached `keyNetwork` — both `readControlCohort` and
  `waitForControlCohort` blame the wiring immediately rather than polling to timeout;
- force → observe → **restore the forcer first** — proves the guard throws, that the throw
  does not latch, and that both patches really come off afterwards.

Kept from the implement pass, and re-confirmed as the better test: the timeout-message case
runs against a *drone's* view with a 2 s budget rather than the ticket's original 1 ms
budget on a fresh party. A drone's cohort caps at 2 permanently (drones never dial each
other), so the timeout is a property of the topology, not a race with ring warm-up. It
loses nothing the original covered and additionally exercises `options.node`.

### Tripwire recorded

- `waitForControlCohort` rejects `minPeers` above the party's own node count. Correct
  today because `findCluster` admits only peers serving `control-<partyId>`, so the cohort
  cannot exceed the party — but it would reject a legitimate wait if a scenario ever put a
  node into a party's control network without listing it in `TestParty`. Parked as a
  `NOTE:` at the check itself in `control-cohort.ts`.

### Checked and deliberately left alone

- **Docs.** `docs/STATUS.md` and `docs/architecture.md` describe *scenarios and
  subsystems*, not harness modules; the one existing mention of `forced-cluster.ts`
  (STATUS ~line 713) is still accurate. Both harness files carry authoritative headers, so
  no doc edit was warranted. The one doc claim that may become wrong — STATUS marking
  `control-write-degraded-cohort-member` `[x]` at ~185 s — depends on the unrun scenario
  above and is called out in that ticket rather than pre-emptively edited.
- **Header prose duplicated between `control-cohort.ts` and `forced-cluster.ts`** (the
  process-wide prototype-patch caveat, the restore rule). Both files are entry points a
  reader may open first, so the repetition is deliberate rather than a DRY violation.
- **`observeControlCohorts` counts a throwing call in `callCount()` but adds no
  `cohortSizes()` entry**, so the arrays can differ in length. Documented on the handle;
  still no test, because provoking it means installing a throwing patch from the test file
  and reaching past the helpers' own API for a case no caller relies on.
- **`CONTROL_COHORT_PROBE_KEY` is an exported mutable `Uint8Array`.** `Object.freeze`
  cannot protect a typed array's elements, the module never mutates it, and the doc says
  to treat it as immutable. Not worth an accessor.
