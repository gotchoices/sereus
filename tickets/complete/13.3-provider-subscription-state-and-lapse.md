# Subscription state and termination for non-payment

Third ticket of the `provider-client-and-sign-up` chain. The app side that reads these fields is `reference-app-rn-rents-a-provider-node`; the client that parses them is `cadre-core-provider-client-and-rent-node`.

## What landed

- **Types**: `SubscriptionStatus` (`active | past-due | lapsed`), `Subscription { status, renewsAt, lapsesAt }` (required on `CustomerBilling`), `StopReason` (`customer | non-payment`), `Container.stopReason?`. All exported.
- **BillingService**: `initializeCustomer` starts `active` with `renewsAt` at the period end. `updateSubscription(customerId, patch)` is the operator webhook's write; it refuses `lapsed` (type and runtime) and clears `lapsesAt` unless the result is `past-due`. `lapseSubscription` marks `lapsed` with both dates null and terminates the customer's `pending`/`creating`/`enrolling`/`running` containers with `reason: 'non-payment'`. `lapseOverdue` runs on the billing tick after usage collection and lapses each `past-due` record whose `lapsesAt` has passed, re-testing the stored record first. `canCreateContainer` refuses a lapsed customer. New options `containerService` (required) and `now`. An in-process set keeps concurrent lapses of one customer from double-terminating.
- **ContainerService**: `terminateContainer(id, { reason })` writes `stopReason` with `stopping` and keeps an existing one; the `DELETE` route passes `customer`. A new `advance(id, from, to, patch)` writes only when the record is still in `from`, used for pending→creating, creating→enrolling and enrolling→running, so a provision that finishes late never revives a record a terminate stopped (a race the original ticket had assumed covered).
- **Store**: `listCustomerBilling()` on the interface and both stores; FileStore revives the subscription dates as `Date`s.
- **Docs**: README → "Subscription state and termination for non-payment" (fields, Stripe webhook mapping, lapse behaviour, renewal does not restore nodes); `docs/architecture.md` → Provider Flow sentence linking to it.

Commit: `ticket(implement): provider-subscription-state-and-lapse`, plus this review's edits.

## Review findings

**Fixed in this pass (minor):**
- `canCreateContainer` checked the lapse after the plan lookup, so a lapsed customer whose `planId` is not a known plan was allowed to create. Moved the lapse check ahead of the plan lookup (`billing-service.ts`).
- `updateSubscription` merged with an object spread, so a patch carrying an explicit `undefined` (allowed by the type without `exactOptionalPropertyTypes`, and easy from a JavaScript webhook) wrote `status: undefined` or `renewsAt: undefined` onto the record. Extracted `mergeSubscription`, which keeps a field the patch leaves `undefined` and applies the `lapsesAt` rule. No new test: the function is three field assignments.

**Tripwires parked (`NOTE:`):**
- A lapsed record patched to `past-due` (a processor reporting a failed payment after cancellation) gets a fresh grace period and can create again until the tick re-lapses it — `NOTE:` on `updateSubscription`.
- A create that passed `canCreateContainer` just before the lapse mark and saved its record after the stop listed containers survives the lapse — folded into the existing `NOTE:` on `lapseSubscription`, which already names the remedy (tick stops live containers of lapsed customers) for the provider-dies-mid-lapse case.
- The provision's catch writes `error` over a record a terminate stopped while the orchestrator's create was failing (record keeps `stopReason`) — `NOTE:` at the catch in `provisionContainer`.

**Implementer's deviations, weighed:**
- Skipping `stopping` in the lapse: agreed. A `stopping` record is already owned by a terminate or the reap, which writes `stopped` keeping the reason it has; a second concurrent stop risks an `error` write.
- FileStore data written before `subscription` existed fails to load: accepted under AGENTS.md "No backwards compat yet"; no `customer-billing.json` exists in the repo.
- `ProviderStore.listCustomerBilling` is a new required method: the repo has only MemoryStore and FileStore; noted in the handoff for operators.
- Late-advance race fix (`advance`): checked against the reap sweep — a reap that terminalizes a stuck `creating` record now also makes the late provision reclaim instead of reviving it, which is an improvement. `enrollIfHealthy` returning true after the record moved only makes the waiter and reap stop polling; correct.
- The `lapsing` set returns immediately for a second concurrent caller, so a webhook's `lapseSubscription` can resolve while the tick's lapse is still stopping containers. Acceptable: the record is already `lapsed` and the stops are in progress.
