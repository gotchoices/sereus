# The edge node in cadre-core — complete

GitHub #45. `@serfab/cadre-core/edge-node` holds the bring-up the phone kit had: `createEdgeNode(platform)` over a cadre-core `KeyStore` and an `EdgeNodeStorage` (one raw block store per storage scope, a node-local key-value store, `destroyScope`, `close`, an optional per-party `trustedOwnerSlot`). `@serfab/cadre-rn/phone-node`'s `createPhoneNode` is that over `SecureStoreKeyStore` and a LevelDB adapter (`leveldb-storage.ts`), with every name it exported before re-exported as an alias, so `reference-app-rn`, `lifecycle/`, `app-link/` and `provider/` compile untouched. The web and NativeScript tickets (`reference-app-web-runs-the-edge-node`, `reference-app-ns-runs-the-edge-node`) adopt it next. Landed in `ticket(implement): edge-node-in-cadre-core`; the review pass is below.

## What moved and what changed

## Review findings

Read first: the implement-stage diff (`ticket(implement): edge-node-in-cadre-core`), including a direct diff of the old `phone-node/node.ts` against `edge-node.ts` and `edge-join.ts`, then every new and moved file in full, then the handoff summary.

**Checked.**

- Behaviour parity of the move: the transition queue, `trackStart`/`trackStop`, the join's switch and rollback, the strand-move record lifecycle, the dissolve's refusals and removal order, the removal watcher, `shutDown`'s ordering (node references cleared before the stores close) and the saved-start rules are the old code with the storage calls routed through `EdgeNodeStorage`. The LevelDB adapter reproduces the old handle map, the one `LevelDBKVStore` per open node-local database, and the close order (node-local store flushed and closed first, then every database, failures logged and not rethrown), which is what `EdgeNodeStorage.close` promises the runtime.
- Persistence contracts: node-local keys (`start-options`, `dissolving-party`, `link-join-request`, `recommended-apps`, `<record>.<partyId>`), the LevelDB names, the anchor's secure-store slot key, and the move-record slot id (`uint8arrays` base64url of the UTF-8 bytes, identical to `secureStoreKeySegment`) are unchanged; the existing cadre-rn specs pin them and still pass through the adapters.
- The one real behaviour change, `finishStrandMove` re-asking a joined party for the owner row: reasoned through `wireJoinedOwnerKey` with `granted: false` (one pass, returns at once when the key is not listed; the 60 s timer is cleared) and `reportEnrolled` (a no-op when already enrolled); the new cadre-rn test covers the refusal before the row arrives and the adoption after.
- `unfinishedRemoval` bookkeeping: a marker that finishes or is absent clears it, a marker that cannot be read keeps the previous report, a removal or dissolve that finishes a marker clears it, and a failing `finishMarkedRemoval` inside `removeLocalParty` leaves it standing.
- Dependencies: cadre-core already declares `@libp2p/websockets`, `@libp2p/circuit-relay-v2` and `uint8arrays`, so the subpath's imports are declared, not hoisting luck. The root `index.ts` does not import the subpath, so cadre-host and the CLI never load it.
- Docs: `docs/architecture.md` (the new section, the join and dissolve sections, the recreate-control-store step, the secure-backend paragraph), `docs/cadre-consistency.md`'s deadline row, `docs/reference-app-rn.md` (its `PhoneNode.*` and `buildPhoneNodeConfig` names are the kit's aliases, still exported) and the cadre-rn README. Stale path references were searched for across docs, READMEs, sources and tests.
- Release hygiene: `scripts/publish-package.mjs` runs `yarn clean` before `yarn build`, so the stale `dist/phone-node/*` files from the old layout cannot reach a published tarball; the handoff's concern about them is confined to local checkouts.
- Lint and tests: `yarn lint` (exit 0), `yarn workspace @serfab/cadre-core test` (181 files, 2502 passed, 1 pre-existing skip), `build` and `typecheck`; `yarn workspace @serfab/cadre-rn typecheck`, `test` (15 files, 169 passed) and `build`; `yarn workspace @serfab/reference-app-rn typecheck`; the three check scripts (test-file typecheck coverage, vitest typecheck coverage, stale-build-guard wiring). Logs under `tickets/.logs/edge-node-in-cadre-core.review.*.log`.

**Found and fixed in this pass (minor).**

- `lazy-raw-storage.ts` always installs `listBlockIds` and `getApproximateBytesUsed`, answering as an empty store when the opened storage lacks them. Upstream `IRawStorage` asks backends to omit rather than stub these, so feature detection sees the true capability; cadre-core's peer-join backfill goes inert without `listBlockIds` and would run an empty scan against the stub. The handoff's claim that a stub is "what callers do with a missing method" was not quite right, but every storage a platform opens behind the proxy (IndexedDB, SQLite) has both methods, and the old NativeScript proxy forwarded them the same way. Recorded as a `NOTE:` tripwire on the class, with the remedy if a platform ever lacks them (declare the capability beside `durability`).
- `packages/cadre-rn/src/phone-node/index.ts` did not re-export the new `UnfinishedRemoval` type beside the other aliases; added.
- `packages/cadre-rn/README.md` said only `/phone-node` and `/lifecycle` need the optional cadre-core peer; `/node-local` now imports its record keys and `kvStoreSlot` from `@serfab/cadre-core/edge-node` at runtime, so the sentence names it too.
- `packages/reference-app-rn/test/solo-founding.spec.ts` pointed at `cadre-rn/test/phone-node/config.spec.ts`, which moved to `cadre-core/test/edge-node/config.spec.ts`; repointed.

**Tests.** The implementer's two new tests both pay for themselves: the cadre-rn `finishStrandMove` case is the only new branching in the move, and `lazy-raw-storage.spec.ts` pins the proxy's three real behaviours (one shared open, a rejected open retried, lazy iteration) over a fake storage with no module mocking. The moved specs (`config`, `options`, `strands`) kept their assertions. No test was cut and none added: every other change is a move whose contracts the existing cadre-rn specs already pin through the adapters.

**Major findings.** None. The move keeps the runtime's invariants and introduces no new representation that could hold a bad state; nothing met the filing bar.

**Tripwires (conditional concerns), recorded at their sites.**

- `lazy-raw-storage.ts`: the stubbed optional methods (above), and the existing NOTE that retried opens have no backoff.
- `edge-node.ts`: the existing NOTEs moved with the code — file size (about 1000 lines, with the next module to split named), the node-local read window during a restart, join or dissolve, the removed-party start, and a stop during a join restarting the left party first.
- `config.ts`: `DEFAULT_OWNER_KEY_LABEL` is still `'phone'` now that it lives in cadre-core; a browser or NativeScript app that founds a party without naming `ownerKeyLabel` gets an `OwnerKey` row labelled "phone". Not changed here because it is a user-visible default the adopting tickets should set per app (`EdgeNodeOptions.ownerKeyLabel`); no code site needed a note beyond this line.

**Considered and declined.** `nodeLocalRemovableSlot` in `edge-node.ts` and `deleteSavedStart` both do delete-then-flush; folding them into `node-local.ts` would make it import `RemovableSlot` from `platform.ts`, which already imports `node-local.ts`'s types. Two short sites are cheaper than the cycle. `JoinRuntime` exposing eleven runtime methods as public members of a class the module never exports is documented at the site and acceptable for a view used by one module.

**Left for a human, not filed.**

- `@libp2p/circuit-relay-v2` is no longer imported by any cadre-rn source or test (the default transports moved to cadre-core) and could leave `packages/cadre-rn/package.json`. `@libp2p/websockets` is still read by path in `test/polyfills/hermes-polyfills.spec.ts`, so it stays. Removing the first changes `yarn.lock` and needs `yarn install`, which this pass did not run while other runs share the tree. `knip` (`yarn dep-check`, not a gate) reports it.
- Not run: `reference-app-rn`'s `test:bundle` (an Expo export) and any device run; `reference-app-web` and `reference-app-ns` were not re-run (their sources are untouched except comment paths repointed at the new files).
