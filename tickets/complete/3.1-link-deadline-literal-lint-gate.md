# Lint gate: deadline constants in cadre-core are derived or say why not

## What landed

`no-restricted-syntax` in `packages/cadre-core/src/**` flags a value whose name ends in `timeout`/`budget`/`deadline` + `ms` (any case: `FOO_TIMEOUT_MS`, `timeoutMs`, `dialBudgetMs`) when its value is a numeric literal or arithmetic over numeric literals only. Covered positions: `const`/`let` initialiser, parameter or destructuring default, class field, object-literal property, assignment (`this.timeoutMs = 5000`), and the right side of `??` or `||` whose left side is such a name, including through optional chaining (`opts?.timeoutMs ?? 5000`). A value that names any identifier passes.

A constant that stays a number carries one of two directive reasons on the line above it:

- `// eslint-disable-next-line no-restricted-syntax -- link-independent: <why>`
- `// eslint-disable-next-line no-restricted-syntax -- link-bound, not yet derived: <ticket slug>`

`grep -rn "link-bound, not yet derived" packages/cadre-core/src` lists the 9 unconverted sites. A directive that no longer disables anything now fails `yarn lint` repo-wide, so that list cannot go stale.

`StrandPeerBookService` and `exchangeStrandPeerBook` lost their fixed 10 s fallbacks; the only caller (`StrandPeerBookSwap`) always passed the link-derived `circuitRequestBudgetMs(...)` value to both.

## Review findings

Read the diff of `ticket(implement): link-deadline-literal-lint-gate` before the handoff, then probed the selectors by piping source into `yarn eslint --stdin --stdin-filename packages/cadre-core/src/link-budget.ts` (no file written to the tree).

**Fixed in this pass**

- **The `??` arm missed the codebase's own fallback idiom.** The selector matched `timeoutMs ?? 5000` and `opts.timeoutMs ?? 5000` but not `opts?.timeoutMs ?? 5000`, because optional chaining parses as a `ChainExpression` wrapping the member access. That is the form every fallback in cadre-core uses (`formation-approval.ts:546`, `relay-reservation.ts:427`, `strand-peer-book-swap.ts:133`), so inlining a number into any of them passed lint. Verified by the probe before the fix. Added the `left.expression.property.name` arm (`NAMED_LINK_DEADLINE_LEFT` in `eslint.config.mjs`).
- **Equivalent evasions not covered:** `opts.timeoutMs || 5000` and a constructor assignment `this.readTimeoutMs = 5000` behind an uninitialised field both passed. Added `||` to the logical arm and an `AssignmentExpression` arm with the same left-side matching. Zero sites in the tree match the added forms; `yarn lint` stays at exit 0.
- **A stale directive was only a warning.** The implementer declined `reportUnusedDisableDirectives: 'error'` because it applies repo-wide. Measured: `yarn eslint . --report-unused-disable-directives-severity error` reports zero unused directives today, and the repo's stated policy (AGENTS.md, testing.md) is an all-`error` gate with no warnings. Set it on the globals config entry with a comment saying why; confirmed a stale `link-bound` directive now fails. Updated the config comment and testing.md to match.
- Probe results after the fix: flagged `opts?.timeoutMs ?? 5000`, `opts.timeoutMs ?? 5000`, `opts?.timeoutMs || 5000`, `this.readTimeoutMs = 5000`, `timeoutMs = 5000`, `timeoutMs ?? 2 * 1000`, `(5 as number) * 1000`; passed `opts?.timeoutMs ?? DEFAULT_X_MS`, `opts?.other ?? 5000`, `o.timeoutMs = DEFAULT_X_MS`, `-1`, `5000 as const`, `options['timeoutMs'] ?? 5000`.

**Checked, no change**

- Classification: every `link-bound` directive names a ticket that exists (in `backlog/`) and lists that constant (grepped each constant against the board). `DEFAULT_PROVISION_TIMEOUT_MS` appears in both deadline tickets; the directive names the one that owns the whole number, as the handoff said.
- Peer-book change: `StrandPeerBookSwap` is the only constructor/caller (grepped `packages/*/src` and `packages/*/test`); both options were already always supplied. The public exports now require them, which is fine under "no backwards compat yet".
- Link-independent reasons: read the addr/wake receiver read caps and `RELAY_ADMISSION_CLOSE_TIMEOUT_MS` (expiry falls back to abort). The addr/wake read caps do wait for one link delay after the stream opens, but 10 s is several times the 1.5 s one-way ceiling, and their purpose is to cap a peer that opens a stream and never sends. The classification holds.
- Docs: architecture.md Relay Integration and link-budget.ts doc paragraph are accurate after the fixes (neither lists covered positions). testing.md updated for the new positions and the unused-directive setting.
- Scope: `packages/cadre-host/src/update/manifest.ts:48` has `opts.readTimeoutMs ?? 10_000`, outside the cadre-core scope and an HTTP manifest fetch; not a link deadline.

**Not caught, by design (documented in the config comment and testing.md; no ticket):** other names (`…_WAIT_MS`), inline `setTimeout(…, 5000)`, a literal behind `as`, string-keyed properties, and a renamed destructuring default (`{ timeoutMs: t = 5000 }`).

**Tripwires:** none new. The existing `NOTE:` in `eslint.config.mjs` on name-based coverage stays as the one place that says what the guard does not prove.
