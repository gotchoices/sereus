## What was built

Maintainer decision (2026-09-27), item 2. A new protocol on the **strand** libp2p node, `/sereus/strand-peers/1.0.0`: when two strand peers connect, each sends the other the signed entries of its strand peer book and merges what comes back. Every entry is signed by the named peer's own strand transport key over the canonical JSON of `{ v: 1, strandId, peerId, addrs, issuedAt }`, and a receiver verifies it against the public key embedded in the Ed25519 peer id. The book therefore proves "this peer's own claim about where it is", never membership; the module comment in `strand-peer-book-protocol.ts` carries the four reasons the member key was not used.

- **Wire protocol, signing, verification** (`strand-peer-book-protocol.ts`, new): `SignedStrandPeerEntry` (a `StrandPeerEntry` without `lastSeenAt`, `sig` required) and `StrandPeerBookFrame { strandId, entries }`, the same shape as request and response. `signStrandPeerEntry`, `verifySignedStrandPeerEntry` (returns a verdict with a reason, never throws), `verifyStrandPeerBookFrame` (refuses a frame naming another strand, a non-list, or more than 16 entries; drops a failing entry individually with a debug line; drops entries naming the receiver; one entry per peer id), `trimBookFrameToFit` (drops entries from the stale end until the frame fits the 16-entry and 64 KiB caps), `assertBookFrameFits` (the invariant check at the encoder), `StrandPeerBookService` (receiver: `node.handle` with `runOnLimitedConnection`, read timeout, concurrency cap, empty frame on every error path), and `exchangeStrandPeerBook` (client: one stream on the given connection under one deadline, returns the verified entries). Framing and stream handling reuse `control-stream.ts` and `decodeLengthPrefixedFrame`, as `strand-addr-protocol.ts` does.
- **Per-strand driver** (`strand-peer-book-swap.ts`, new): `StrandPeerBookSwap` owns the own entry, the receiver, and the exchanges. Own entry: built from the node's own bound addresses via `dialableAddrs`, `issuedAt` strictly greater than every statement this node is known to have made (in memory, or the copy its own book kept from a previous run), signed at arm time and re-signed when the address set changes (`self:peer:update`, debounced 1 s), filed in the book under the node's own peer id; the copy the node sends lives in memory. Exchange on `peer:identify` when the peer speaks the strand's block-transfer protocol and lists the swap protocol (an older node is skipped, logged), throttled to one per peer per 10 minutes, at most one in flight per peer; on every own re-sign, one exchange with every connected strand peer past the throttle, and a peer whose exchange is in flight at that moment gets one more once it settles; on `start`, a walk of the peers already connected. The sender's own entry is filed as seen now, a forwarded third party's as never seen (`lastSeenAt: 0`, so it ages from the signer's clock). A failed exchange is logged and waits out the throttle.
- **Store** (`strand-peer-book.ts`): a signed entry is stored with its addresses in the signer's order, since the signature covers that order and the stored copy is what gets forwarded; an unsigned entry is still reordered signaling-first.
- **Shared helper** (`strand-peer-observer.ts`): `connectedIdentifiedPeers(libp2p, label)` groups open connections per peer and reads protocols and stored addresses from the peer store, skipping peers whose identify has not finished. The observer's start walk and the swap both use it. `AddrLike` is exported.
- **Wiring** (`strand-instance-manager.ts`, `cadre-node.ts`): `StartStrandConfig.strandPeerBook?: StrandPeerBookStore`; `CadreNode.launchStrand` passes its book store. The manager arms one swap per strand right after the libp2p node exists (beside the observer) and stops it in `releaseRuntime` before the enforcer, so the failure rollback and a hibernation quiesce both release it and a resume re-arms it from the retained config.
- **Identity-less nodes get a cadre-held random key.** A node with neither `keyStore` nor `privateKey` used to launch its strand nodes with `privateKey: undefined`, leaving libp2p to generate a key cadre-core never saw, so the swap could not sign. `launchStrand` now generates a random Ed25519 key for that case, retained with the launch config, and announces a delegate for it on the launch seed pass. Two tests in `cadre-node-strand-launch-key.spec.ts` pin this contract.
- **Docs**: `docs/architecture.md` gains a "Kept fresh by the signed book swap" bullet (trigger, throttle, what travels, what is signed and by which key, why not the member key, what the book proves, receiver rules, own entry, the signed-order rule, the trim), the protocol list at the top names the new id, and two neighbouring bullets were updated. `docs/strands.md` closes the "Never refreshed while apart" limit with a swap paragraph and restates the design boundary as the remaining gap. `.release-notes.pending.md` gains a bullet.

## Deviations from the ticket, kept

- **Two modules, not one.** The wire protocol and the per-strand driver have different dependencies and the driver is what a test mocks a libp2p node for.
- **Own entry signed at arm time, not after the first relay attempts settle.** Waiting would have left the handler unregistered while the bootstrap dials landed, and a peer that dials an unregistered handler sits out its ten-minute throttle. The relay reservation landing fires `self:peer:update`, which re-signs and pushes.
- **No aging exemption for the own entry in the store.** The entry the node sends is the in-memory one; the stored copy is a record for diagnostics, the seed's self-skip, and (since review) the `issuedAt` floor after a restart.
- **The client opens the stream on the identified connection** (`connection.newStream`) rather than `dialProtocol(peerId)`, avoiding the connection manager's preference for a non-limited connection when the only one is relayed.
- **Deadlines derive from the declared link**: `circuitRequestBudgetMs(linkRoundTripMs, 1000)`, 8 s at the default, for both the client's whole exchange and the receiver's read.

## Known gaps and what is unproven

- **Third-party forwarding is proven only in-process** (two swap drivers on mock libp2p nodes over `duplexPair` streams). `scenario-relay-only-restart-reconverges` may add a live one.
- **Rotation and the resend are proven with a synthetic `self:peer:update`** on a mock node. A live relay rotation is not scenario-tested.
- **Revoked peer, hibernation, open strands: inspection only.**
- **`resumeStrandRuntime` announces no delegate for an identity-less node.** Pre-existing for that shape, which no production embedder uses.
- **Every received entry persists on the persistent backend**, including an unchanged forwarded entry (the prior review's tripwire at `PersistentStrandPeerBookStore.merge`). Bounded by the ten-minute client throttle per peer, and only by that: see the backlog ticket below.
- **One connection produces two exchanges** (both sides dial at identify), as the ticket accepted.

## Review findings

Read the implement-stage diff (`6620a2fb`) file by file before the handoff summary, then the two new modules whole, the store, the observer, `control-stream.ts`, `strand-addr-protocol.ts` (the pattern being followed), `peer-record.ts` and `peer-addr-book.ts` (address ordering and attribution), the formation protocol's address sanitiser, the runtime arm order in `strand-instance-manager.ts`, and the sibling implement ticket `scenario-relay-only-restart-reconverges` for what it expects of this one. Checked the happy path, the forward path, the rotation path, the receiver's error paths, the caps, the clock rules, the lifecycle (arm, rollback, hibernate, resume, stop), the docs against the code, and the tests as code under review.

**Fixed inline (four).**

- **The store reordered a signed entry's addresses, which broke its signature when forwarded.** `sanitizeStrandPeerEntry` applied `orderSignalingFirst` to every entry; a signed entry whose signer listed a direct address before a circuit one was stored circuit-first, and the forwarded copy failed verification at the next peer with a debug line and nothing else. Reproduced with a probe before fixing (the signer's `dialableAddrs` happens to order signaling-first today, so no production writer hit it; the coupling was one refactor away from silently disabling third-party forwarding). Signed entries now keep the signer's order; unsigned entries are still reordered. Pinned at the store (`strand-peer-book.spec.ts`, one test) and at the forward (the round-trip test's third party now signs direct-first and the receiver must hold that order).
- **The own entry's `issuedAt` restarted from the clock.** Strictly increasing only within one process, so a restart on a clock behind the previous run's stamp (NTP correction, VM restore) would have every peer keep the old statement, and nothing re-signs until an address change. The floor now also reads the stored own entry, which is exactly the copy the store keeps. Pinned in the round-trip test (a stored previous-run entry stamped 50 s ahead; the new statement is issued later than it).
- **A re-sign push was dropped when an exchange with that peer was already in flight.** `exchangeWith` returned on `inFlight` regardless of `bypassThrottle`, and the in-flight frame carried the old entry. Routine at launch: the identify exchange with a bootstrap peer is on the wire when the relay reservation lands a second later. The peer whose exchange is in flight is now marked and gets one more exchange once it settles. Pinned with a stalled dial in `strand-peer-book-protocol.spec.ts` (one test). The existing rotation test's dial count relied on the old drop (it identified before the own entry was signed, so its first frame carried nothing); it now signs first, as the other tests do.
- **An oversized frame failed the exchange instead of degrading.** The comment claimed the 64 KiB cap could not be reached by an honest frame, but nothing bounds a multiaddr's length (`sanitizeStrandAddrs` caps count, not bytes), and sixteen peers with sixteen long DNS addresses each would exceed it, after which neither side ever swaps. `frameFor` now trims forwarded entries from the stale end to fit (`trimBookFrameToFit`), and `assertBookFrameFits` stays as the invariant check. Not separately tested: the trim is a loop over the encoder with no branching of its own.

**Filed (one).** `backlog/debt-strand-peer-book-remote-write-bounds`: a connected peer can, with one verified frame of sixteen self-signed throwaway entries stamped a few minutes ahead, evict every peer this node has actually met from its book, and the receiver bounds streams in flight but not frames per peer per unit time, so the persist each frame costs is unbounded too. Static reading, not reproduced live. On a closed strand only a member can send; on an open strand anyone connected. Proposed invariants in the ticket: met peers outrank forwarded ones at eviction, and the receiver mirrors the client's throttle with the same re-sign exemption. Filed rather than fixed because both touch a store rule the maintainer settled last ticket ("nothing here is trust-bearing") and deserve a decision on which mitigation. `NOTE:` at `evictPastCap` and at `StrandPeerBookService.handleStream` point to it.

**Tripwires recorded.** The two `NOTE:`s above. The pre-existing NOTE in `strand-instance-manager.ts` about a third `peer:identify` listener per strand stands.

**Considered and left alone.** `readBookFrame` is a fourth copy of the read-to-end plus decode plus parse shape (`strand-addr`, `strand-wake`, seed); the split exists to keep `control-stream.ts` free of `seed-bootstrap.ts`, and folding four copies is a refactor across three settled modules, not this ticket's. The own entry includes loopback and private listen addresses, the same as the formation path's `getStrandMultiaddrs`; consistent, not a finding. The receiver does not gate on the asker speaking block transfer; on an open strand any node can announce the protocol, so the gate would filter only the relay and buy nothing against the case in the filed ticket. The index exports the protocol internals (`signedStrandPeerEntryPayload`, `assertBookFrameFits`); matches the observer's export style. The identity-less random key uses `@libp2p/crypto`, already a cadre-core dependency and cross-platform.

**Tests cut: none.** The implementer's four protocol tests each pin a distinct contract (round trip and forward, rotation, per-entry verification, frame refusal); the two merge-table rows are cheap and name real rules; the two rewritten launch-key tests pin the new identity-less contract.
