description: Error messages built from a caught value now describe values that are not Errors (such as a phone's WebSocket failure event) instead of printing "[object Object]", through one shared helper, and a lint rule stops the old pattern from coming back.
architecture: docs/testing.md
files: packages/cadre-core/src/describe-thrown.ts, packages/cadre-core/test/describe-thrown.spec.ts, packages/cadre-core/src/index.ts, eslint.config.mjs, docs/testing.md ("Lint coverage" → "Thrown-value guard", "Phone-runtime API guard"), packages/cadre-core/src/push-notifier-shared.ts (NOTE), packages/cadre-provider/src/server/invitation-validation.ts (NOTE), packages/reference-app-rn/app/*.tsx, packages/reference-app-ns/app/settings/settings-view-model.ts, plus the call-site files of `ticket(implement): describe-thrown-values-in-error-messages`

## What landed

gotchoices/sereus#54: on a phone (Hermes), `relayStatus().error` read `"[object Object]"` because a React Native WebSocket failure rejects with an event object, and every site that turned a caught value into text used `err instanceof Error ? err.message : String(err)`.

- **`describeThrown(value: unknown): string`** in `packages/cadre-core/src/describe-thrown.ts`, exported from cadre-core's root entry. It imports nothing, so it is safe in every runtime.
  - An `Error` gives its `message`, unchanged. `cause` and `AggregateError.errors` are not walked.
  - A non-null object gives its non-empty string `type`, `message` and `reason` joined with `: `, plus `code` (a string or a number) as ` (code X)`. Otherwise it gives its JSON, and `String()` when the JSON is `{}` or cannot be made. Object descriptions are cut to 500 characters.
  - A primitive gives its `String()` text.
- **`toError(value: unknown): Error`** in the same file, used only inside cadre-core: an `Error` is returned as it is, and anything else becomes `new Error(describeThrown(value), { cause: value })`. It replaces `edge-node/strand-move.ts`'s `toError` and `member-redemption.ts`'s `asError`, which was a partial copy of `describeThrown`, and the inline `x instanceof Error ? x : new Error(String(x))` wraps in `cadre-node.ts` (2), `control-stream.ts`, `peer-dial.ts`, `strand-addr-protocol.ts`, `strand-formation-protocol.ts` and `strand-offline.ts`.
- **Call sites.** Every `x instanceof Error ? x.message : String(x)` in `packages/*/src` and `packages/*/app` of the packages that depend on cadre-core now calls `describeThrown`. So do the phone apps' bare `String(err)` alert texts in `reference-app-rn/app/settings.tsx`, `reference-app-rn/src/add-node-section.tsx` and `reference-app-ns/app/settings/settings-view-model.ts`, and cadre-cli's `admin-client.ts` non-Error fallback. The local copies of the pattern are removed (listed in the implement commit).
- **Lint rule** `THROWN_DESCRIPTION_GUARD` in `eslint.config.mjs` (`no-restricted-syntax`, `error`). It has two selectors: a conditional whose test is `… instanceof Error` and whose other arm is `String(…)`, and the same conditional whose other arm is `new Error(String(…))`. It applies to `packages/*/src/**` (`.ts` and `.svelte`) and `packages/*/app/**`. It ignores cadre-provider, config-check and quereus-plugin-sereus, which do not depend on cadre-core by design. `cadre-host/ui` is outside the globs because that browser bundle must not load cadre-core's root entry. The phone-runtime guard's scope now includes `packages/*/app/**` too, through the shared `FIRST_PARTY_APP_ROUTES` glob.
- Not changed, by design: cadre-provider's 6 sites (there is a `NOTE:` on `reasonOf` in `server/invitation-validation.ts`) and the 3 sites in `cadre-host/ui/src`.

## Review findings

Checked: I read the implement diff line by line. All call-site rewrites are a straight swap of the idiom. The local helpers that were removed did nothing but the idiom. The three variant sites keep their Error arm. Then I ran a repo-wide grep for every remaining `String(err|error…)`, ran the lint rule on stdin snippets in each scope, and ran the commands under Validation.

- **Missed scope (fixed).** reference-app-rn's expo-router `app/` directory had 2 sites of the exact idiom, which neither the rewrite nor the lint glob reached (`app/index.tsx` send failure, `app/settings.tsx` join-request decode). This code runs on the phone, which is where the bug was reported. Both are fixed. `packages/*/app/**` is now in the rule's scope, and in the phone-runtime guard's scope, which had the same gap. Probes show both guards fire in `reference-app-rn/app` and `reference-app-ns/app`.
- **Same bug class, other shape (fixed).** cadre-core had 7 `x instanceof Error ? x : new Error(String(x))` wraps plus a `toError` copy. Wrapping a non-Error that way makes `Error('[object Object]')`. `peer-dial.ts`'s per-address dial failures are the clearest case: a phone's WebSocket dial failure lost its text there. These now go through the new shared `toError`, and a second selector flags the shape. `member-redemption.ts`'s `asError` was a hand-written partial `describeThrown`, so it was replaced as well. The one visible change: an `ErrorEvent`'s text is now `error: <message>` where it used to be just `<message>`. No spec matched the old text.
- **Bare `String(err)` in phone alerts (fixed).** 9 alert sites in the two phone apps passed a caught value straight to `String()`. That is the same `[object Object]` failure on Hermes. The lint rule cannot see them because it matches the conditional only, so they were fixed by hand. The remaining bare `String(error)` uses are in integration-test harness and scenario diagnostics, which run on Node. They stay under the rule's existing `NOTE:` ("catches the idiom, not every way to lose the text"). I filed no ticket: a rule that tracks catch-clause parameters needs a custom ESLint rule with scope analysis, and nothing on a phone still uses the bare form.
- **Push-notifier secrecy (tripwire).** `errText` was documented as secret-free. `describeThrown` would turn a thrown non-Error object into JSON, but every thrower on that path throws an `Error` today. I kept the replacement and parked the condition as a `NOTE:` in `packages/cadre-core/src/push-notifier-shared.ts`.
- **Tests.** I kept the implementer's spec: each case pins one branch of the helper. I added one `toError` case, which checks that a non-Error is wrapped with its description and keeps the value as `cause`. That is the contract the dial-failure fix depends on. No call-site tests, because the lint rule enforces the pattern at the sites.
- **Docs.** I updated `docs/testing.md` → "Lint coverage" (thrown-value guard: the new selector, `toError`, `app/` scope; phone-runtime guard: `app/` scope). No other doc names the removed helpers (grep for `errText`, `errorMessage(`, `errMessage`, `toError` in `docs/` and the READMEs).
- **Accepted as is (no action):** the output format (`type: message: reason (code X)`); a null-prototype object with no fields still makes `String()` throw, as every old site did (contrived); the scripted import placement is unsorted, which is cosmetic and not linted; `bounded` can split a surrogate pair at character 500 (cosmetic); the 3 `cadre-host/ui` sites stay, per the bundle constraint the eslint comment records.
- Type safety, resource cleanup, performance: nothing found. The helper is pure and allocation-light, and runs only on failure paths.
