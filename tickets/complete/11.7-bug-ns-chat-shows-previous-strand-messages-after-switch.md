# NS chat view model applied the previous strand's results after a switch

## What changed

`ChatViewModel` (`packages/reference-app-ns/src/chat-vm.ts`) follows two rules, mirroring the RN hook `packages/reference-app-rn/src/use-chat.ts`:

- **Results belong to the strand instance they were read from.** `refresh()` drops a read (result or error) that settles after the view model re-attached elsewhere; a stale error is logged with `console.warn`. `loading` is cleared only for the attached strand; `readsInFlight` is always cleared.
- **The list belongs to the strand id it shows.** `attach()` calls the new `clearConversation()` when the strand id changes (including to or from none): empties the list, zeroes the participant count, clears the poll error, re-enters loading. A reconnect that replaces the instance of the same strand keeps the list.
- **`send()`** still settles the draft whichever strand is attached, but appends the row and clears the poll error only if the strand it wrote to is still attached. The RN hook's `send` got the same guard.

Tests (`packages/reference-app-ns/test/chat-vm.spec.ts`): the existing re-attach test now asserts that the late read of the old strand is dropped, and a new test asserts the list clears at once when re-attaching to no strand. Both were confirmed failing before the fix (in the fix stage and again in implement).
