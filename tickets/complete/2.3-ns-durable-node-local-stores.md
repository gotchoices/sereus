# Durable trusted-owner anchor + bootstrap peers on NativeScript — complete

Third and last of the three per-platform durable-node-local-store tickets (web,
React Native, NativeScript). The cross-platform machinery
(`node-local-snapshot.ts`, `trusted-owner-store.ts`, `bootstrap-peer-store.ts`
in `@serfab/cadre-core`) was already in place; this ticket supplied the
NativeScript `DurableSlot` backend and wired both stores into the node config.

## What shipped

- **`packages/reference-app-ns/src/node-local-slots.ts`** (new): the two slot
  keys (`trusted-owners.<partyId>` / `bootstrap-peers.<partyId>`), a local
  `KvStoreApi` shape (so a test can fake the KV store without SQLite), and
  `kvSlot(kv, key)` — a direct `DurableSlot` pass-through.
- **`packages/reference-app-ns/src/cadre-phone.ts`**: the `sereus-peer-identity`
  SQLite handle is now opened once (`identityDb`) and reused for the identity
  load and for a `SqliteKVStore(db, '')` (empty prefix, so stored keys equal the
  literal strings above) backing both stores; `PersistentTrustedOwnerStore` and
  `PersistentBootstrapPeerStore` are passed in `CadreNodeConfig`;
  `stopPhoneNode` clears the module `node` reference before stopping and closes
  the handle in a `finally`.
- **Docs** (this review): `docs/reference-app-ns.md` gained a "Node-local
  records" section; `docs/architecture.md`'s per-platform paragraph no longer
  claims NativeScript is ephemeral, and now records that the NS anchor is
  durable but unreachable (see findings).

## Review findings

Reviewed the implement diff (`07050d1`) first, then the handoff, then the
surrounding code: `SqliteKVStore` / `openOptimysticNSDb` / `loadOrCreateNSPeerKey`
in `@optimystic/db-p2p-storage-ns`, cadre-core's snapshot machinery and its
`trust()` call sites, the NS view model and Settings screen, and the RN/web
siblings for parity.

### Verified, no action

- **Key namespace.** The empty `SqliteKVStore` prefix shares the `kv` table with
  the identity BLOB (`peer-private-key`) and nothing else in that database;
  no collision. The `kv` table is created by `openOptimysticNSDb`'s schema pass,
  which the identity path already relies on, so the store's prepared statements
  cannot hit a missing table.
- **Slot contract.** `kvSlot` satisfies `DurableSlot`'s load-bearing rule —
  absent key ⇒ `undefined` (cold start), read fault ⇒ throw (never a silent
  empty, which the next snapshot write would make permanent).
- **Party scoping.** Both stores are constructed with `opts.partyId`, and
  `CadreNode` fails closed if an injected store's party does not match the
  node's — a foreign party's anchor or dial targets cannot leak in.
- **Handle lifecycle.** `stopPhoneNode` releases the native handle even when
  `node.stop()` throws, and clears both module references before the close, so a
  failed stop cannot leave a live reference to a node whose database is gone.
- **Write-after-close.** cadre-core's genesis anchor persist is
  fire-and-forget (`void … .catch(log)`), so a persist racing a stop would log
  rather than crash; it is also unreachable on this app (nothing anchors — see
  below). No change made.
- **Type safety / hygiene.** No `any`; the new file is 54 lines and each function
  is a one-liner; comments explain the non-obvious choices (empty prefix,
  fate-sharing, no migration) rather than restating the code.

### Fixed in this pass (minor)

- **Stale docs.** `docs/architecture.md` still called NativeScript "the last
  ephemeral platform", and `docs/reference-app-ns.md`'s Storage section said
  nothing about the two new records. Both updated; the party-id caveat that was
  written as RN-only now covers both phone apps, since neither persists its
  party id.
- **Misleading comment.** The `??=` comment implied the `node?.isRunning`
  early-return prevents a second open. It prevents a *sequential* second open,
  not an overlapping one. Reworded, with the tripwire below attached.
- **Module header** now mentions the node-local records so a reader lands on
  `node-local-slots.ts`.

### Filed as new tickets (major)

- **`backlog/feat-ns-invite-trust-pinning`** — the durable anchor is wired but
  **nothing in this app ever writes it**: no owner private key is configured (so
  no genesis self-anchor) and there is no invite-paste field (so no pinned owner
  keys), while the default `anchoredTrustPolicy` trusts only anchored keys. Net
  effect: Apply Seed always fails on the NS app and it can only run solo.
  Pre-existing — the in-memory anchor was equally empty — so not a regression
  from this ticket, but it is what the handoff's third "known gap" was pointing
  at, and it is a real functional parity gap against React Native. The
  bootstrap-peer record does fill in, via `applySeed`.
- **`backlog/debt-ns-unit-test-harness`** — the package has no unit-test runner
  at all (`typecheck` / `test:bundle` / device-only `test:e2e`), so the
  `SqliteKVStore` + `kvSlot` composition and the shared-handle lifecycle are
  unverified outside a device. The handoff flagged this and deliberately left the
  call to review; a runner plus round-trip coverage is worth more than a
  one-off test, hence a ticket rather than an inline addition.

### Tripwires (recorded, not ticketed)

- **Overlapping starts would leak a native SQLite handle** — `??=` is not a
  re-entrancy guard, so two concurrent `startPhoneNode` calls would each open a
  handle and the loser's would never be closed. Unreachable today: the Connect
  button is disabled while connecting (`cadre.notConnecting`) and `startSolo` is
  only called programmatically. Parked as a `NOTE:` at the `??=` site in
  `cadre-phone.ts`, with the fix if it ever becomes reachable (cache the
  in-flight open promise, not the handle).

### Not run

- **`test:e2e`** needs a real device/emulator — not agent-runnable, and not
  implied to have passed. `solo-smoke.ts` likewise only runs under the
  NativeScript runtime.
