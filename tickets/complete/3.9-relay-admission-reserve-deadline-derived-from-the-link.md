# Relay admission's reserve deadline derived from the declared link

## What landed

- `link-budget.ts`: `RELAY_RESERVE_REQUEST_ROUND_TRIPS = 1` and `relayAdmissionReserveDeadlineMs(link?) = 1 × link round trip + ADMISSION_DECISION_TIMEOUT_MS` (3 500 + 2 000 = 5 500 ms at the default declaration). The module's "What still fails" list drops the "one cadre deadline still typed as milliseconds" bullet and adds relay admission to the "machine that declares a faster link than its peers" bullet.
- `membership-connection-gater.ts`: `RELAY_ADMISSION_RESERVE_DEADLINE_MS` is now the derived default; its lint suppression is gone.
- `cadre-node.ts`: the control node's gater gets the deadline derived from the relay's own `network.linkRoundTripMs`.
- `docs/architecture.md`: derived-deadline list entry added, known-limit bullet removed, control-gate bullet states the derivation.
- One `expect` in `link-budget.spec.ts` pinning the formula alongside the other budgets.

## Review findings

- **Diff read first** (`ticket(implement): relay-admission-reserve-deadline-derived-from-the-link`). The gater arms the timer in `denyInboundEncryptedConnection` after `admitInbound` resolves, and disarms it in `denyInboundRelayReservation` only after that decision settles, under the same `decisionTimeoutMs`. So the deadline has to cover the client's RESERVE arriving plus one full decision, which is what the formula counts. The one-round-trip count is an upper bound: if libp2p negotiated the hop stream lazily, RESERVE would arrive with the stream open, earlier than counted. The worst case has 500 ms of margin, from the 3 500 ms default rounding up the supported 3 000 ms round trip. The arithmetic is still `static`, not measured.
- **Wiring:** `CadreNode` passes `ADMISSION_DECISION_TIMEOUT_MS` explicitly only to reach the fourth positional parameter; that equals the default, so there is no behaviour change. Considered and not changed: the reserve deadline adds the constant `ADMISSION_DECISION_TIMEOUT_MS`, not the gater's `decisionTimeoutMs` parameter. Only tests pass a different decision timeout, and they pass their own reserve deadline too, so no production path can diverge. No tripwire filed.
- **Exports:** the new function and round-trip constant are not re-exported from `index.ts`. That matches how the barrel treats other link-budget helpers, which it exports only in part (for example `cohortReadDeadlineMs` and `commitBudgetMs` are not exported). `RELAY_ADMISSION_RESERVE_DEADLINE_MS` is still exported. No change.
- **Docs and comments (minor, fixed):** two references still said 5 s. `control-cohort-cold-start-retry.integration.ts` said "5 s not-reserving deadline … for those five seconds" and now states the derived 5.5 s at the default link. The backlog ticket `debt-relay-reservation-decision-repeatable-cost` said "~5 s … aborts it" and now says "~5.5 s (at the default declared link) … closes it". The deadline has closed the connection rather than aborting it since the WebSocket leak fix. I read every other hit for the deadline across docs, sources and the open board; they either give no figure ("a few seconds") or were updated by the implementer.
- **Tests:** the added `expect` follows the existing test's pattern of pinning each operation's round-trip count, so I kept it. I added no test: the gater's arm/disarm/close logic already has coverage in `membership-connection-gater.spec.ts` (doubles) and `relay-admission-deadline.spec.ts` (real WebSocket), and those take the deadline as a parameter.
- **Faster-link mismatch:** a relay that declares a faster link than its client closes that client's connection before the client's request arrives. This is documented in `link-budget.ts`'s "What still fails" list under the existing "declare the same link on every machine" guidance. No new ticket.
- **Resource cleanup / error handling:** no change in this diff. Timers stay unref'd, and the close/abort escalation is untouched.
- **Validation:** `yarn lint` exit 0; `yarn workspace @serfab/cadre-core typecheck` exit 0; `yarn workspace @serfab/integration-tests typecheck` exit 0; `vitest run link-budget membership-connection-gater relay-admission-deadline` 61 passed. The `relay-only-control-addr` integration scenario was not run. By inspection, its 10 s drop wait still leaves 4.5 s of margin over the 5.5 s deadline.
