# Android system camera opens node codes in the app

## What landed (`ticket(implement): rn-app-opens-node-codes-from-the-system-camera`)

- `app.json` → `expo.android.intentFilters`: a `VIEW` filter (`BROWSABLE`, `DEFAULT`) for scheme `sereus-join`. `expo.scheme` stays `sereus-chat`, so iOS does not register `sereus-join`.
- `app/+native-intent.tsx`: `redirectSystemPath` rewrites a path starting with `NODE_CODE_SCHEME` to `/settings?nodeCode=<encoded>`; other paths pass through. Nothing is logged (the code holds the node's claim secret).
- `app/settings.tsx`: `useLinkedNodeCode()` copies the `nodeCode` parameter into screen state and clears the parameter. While disconnected, the Node card says a code is waiting (worded for connecting vs. not).
- `src/add-node-section.tsx`: a linked code goes through the same `handleCode` as a pasted one (read → owner check → approval prompt); it is dropped with an inline note while a prompt is open or a claim runs.
- Docs: `docs/reference-app-rn.md` gains "Opening a code from the system camera (Android only)" and a native-rebuild note; the device-run ticket gains cold- and warm-start rows.

## Review findings

- **Link delivery to the rewrite hook (the implementer's main open question):** checked statically against the installed expo-router 5.1 (`build/getLinkingConfig.js`, `build/link/linking.js`). Both the initial URL and later `url` events reach `redirectSystemPath` as the raw URL string; the only transforms before it are `applyRedirects` (no redirects configured, returns the URL unchanged) and the Expo Go parser (a no-op outside Expo Go). So `sereus-join:1.…` arrives intact and the prefix check works. Only whether the camera app offers the link at all remains device-only, and the blocked device-run ticket covers it.
- **Correctness / edge cases:** read the effect in `AddNodeSection` and `useLinkedNodeCode`. The same code opened twice works (the parameter goes undefined → code, so the effect re-fires). A code arriving while the scanner is open closes it first. A code arriving while disconnected is shown on the Node card and handed over when the section mounts on connect. No defects found.
- **Owner-check window** (a second linked code during the `isOwnerDevice` await is not counted as busy): agreed with the implementer that it is too narrow to guard. The later prompt wins and nothing claims without approval. No change.
- **No Discard for a waiting code:** declined. The code lives only in memory, Connect then Cancel discards it, and an app restart clears it. A button would add UI for a rare state. No change.
- **Stale link notice:** the "ignored" note stays after the current claim finishes, until the next linked code. It still describes what happened, so it is cosmetic. No change.
- **Docs:** read `docs/reference-app-rn.md` (new subsection, "Not covered here", native rebuild) and `docs/architecture.md` row 6. Both are accurate. `tickets/plan/same-phone-apps-exchange-join-by-deep-link` already says to extend `+native-intent.tsx` rather than add a second hook. No edits needed.
- **Tests:** none added, none cut. Routing is a prefix check plus a parameter, and decoding is covered by `test/node-claim.spec.ts`. The remaining risk is native behaviour, which a unit test cannot reach.
- **Tripwires / new tickets:** none.
- **Validation:** `yarn workspace @serfab/reference-app-rn typecheck` clean; `yarn workspace @serfab/reference-app-rn test` 18 files / 151 tests pass; `yarn lint` clean. Nothing has run on a device; that work is in the blocked ticket `rn-node-claim-by-qr-device-run`.
