# Phone reference app: owner grants

## What was built

**Edge node (cadre-core, so the browser and NativeScript apps get it too).** `EdgeNode` gains `createOwnerGrant(options?)`, `listOwnerGrants()`, `withdrawOwnerGrant(key)` (pass-throughs on the running node, in the transition queue) and `redeemOwnerGrant(text)`, whose sequence is a new module `edge-node/owner-grant.ts` (`redeemOwnerGrantText` over a two-call view of the runtime, `OwnerGrantRuntime`, as the join is over `JoinRuntime`):

1. decode with `decodeOwnerGrant` (refuses an owner key, an invitation, a join request by name);
2. a grant for another party → `OwnerGrantRejectedError('party-mismatch')`, before any key is made;
3. the owner slot's key (created when empty, `ownerSlotSigner`); if it is already a live owner, wire it and answer `{ alreadyOwner: true, wired: true }` without signing or writing. This comes first because `CadreNode.redeemOwnerGrant`'s local path refuses `alone` before it checks whether the key is already an owner;
4. otherwise `CadreNode.redeemOwnerGrant(bundle, signer)` then `wireJoinedOwner(node, true)`; `wired` reports whether the row arrived within the owner-step bound. The class reports `status.owner: 'enrolled'` when wired.

`RedeemedOwnerGrant` and `JoinCredential` are exported from `@serfab/cadre-core/edge-node` and re-exported from `@serfab/cadre-rn/phone-node`. Kit README: new "Owner grants" section and table row.

**Phone app, Settings → Owner keys** (`owner-keys-section.tsx` holds state; the grant parts are a new `owner-grant-views.tsx`; words in `owner-keys.ts`):

- **Add an owner key** (owner): Name, then a grant with the default 15 minutes / one use, shown once (warning, "Valid until …, once", where to redeem, reach line, QR, Copy, Share, text).
- **Make a backup** (owner) replaces "Make a backup key": Name default "Backup", `expiresInMs: null`, shown once under the bearer warning and the "works only while a machine can be reached … Export this device's key is the no-network copy" line. The app no longer calls `addBackupOwnerKey`; its pass-throughs in `cadre-phone.ts` and `use-cadre.ts` are removed (the kit's and core's stay for `reference-app-web-owner-grants` to remove).
- **Outstanding owner grants** (owner): live grants only (`liveGrants`, backups first), name, expiry ("Never expires"), uses left, **Withdraw** behind a confirmation.
- **Redeem an owner grant** (every device): paste or scan (a scan redeems at once); outcome alert from `redemptionAlert` (now an owner / already an owner, grant not used / accepted, row not here yet); refusals worded by `describeOwnerGrantFailure` (grant-spent, party-mismatch, issuer-unknown, unreachable, alone, reply invalid).
- **Removal confirmation** lists the plan's `grants` (`grantRemovalLines`: `Backup "Paper" stops working.`), and the grant list re-reads after a removal.
- `describeOwnerKeyFailure` now tries the grant words first. The old `ADD_REFUSAL_LINE` is gone: nothing on these screens calls `addOwner` any more, and a redemption's `alone` is worded by the grant function.

**Join my existing cadre** takes an owner grant: `use-join-flow.ts` decodes by prefix (`decodeJoinCredential`), skips the "response for another app" check for a grant, and `cadre-phone.ts`'s `joinCadreByInvitation` became `joinCadre(credential)`. The joining step carries `asOwner` ("Joining your cadre, and setting this app up as an owner…"); the admitted line already said so. A hint above the field says where a grant comes from (two wordings: first launch, and an app with chats). The scanner accepts either text. `StrandsNeedOwnerJoinError`'s sentence now says Owner keys → Add an owner key, then paste it here. Join failures delegate grant errors to `describeOwnerGrantFailure`.

**Maestro fixture** (not run here): `start.mjs` now also mints an owner grant (`ownerGrant`, an hour); `_setup.yaml`'s env var is renamed `JOIN_CODE`; the phone app's `run-e2e.mjs` passes the grant, so flows 1–3 should get past Create strand; reference-app-ns's `run-e2e.mjs` passes the machine invitation (its join field takes no grant yet, `feat-reference-app-ns-owner-grant-join`).

**Docs**: `docs/reference-app-rn.md` (Owner Keys rewritten: adding, backup, outstanding, redeeming, exporting, importing, removing, uses; joining section: owner-grant paragraph, step line, failure lines, `joinCadre`; package list; owner-key storage line; Phase 2 fixture paragraph), `docs/architecture.md` (Owner grants → "On an edge node" paragraph and the proof line; the Recovery bullet), `docs/reference-app-ns.md` (step 5's env var), the kit README, the app README's e2e line, `tickets/blocked/decide-owner-recovery.md` ("What exists now" rewritten: backup grant = option B, exported key = option A without a second device; open questions kept), and `tickets/blocked/rn-device-run-join-existing-cadre.md` (the owner rows now use a grant).

## Known gaps and judgement calls for the reviewer

Not a ticket: it needs a member device with an empty slot to fail a redemption and then import a different key.
- **Redeem is offered on owner devices too**; there it can only answer "already an owner". Kept, since the ticket says "any member device" and hiding it would need the standing read to settle first.
- **Outstanding owner grants is read on member devices too** (hidden there). One cheap read; kept rather than gating on a standing that may still be `checking`.
- **The edge node's owner-key section grew** (four pass-throughs plus a four-line method); the existing size `NOTE:` in `edge-node.ts` was updated (about 1050 lines, measured with `wc -l`), and the redemption's logic went to `owner-grant.ts` per that note.

## Review findings

Reviewed the diff of `ticket(implement): reference-app-rn-owner-grants` before the handoff, then read the core calls it relies on (`CadreNode.redeemOwnerGrant` and its local path, `wireOwnKeyIfOwner`, `wireJoinedOwnerKey`, `redeemOwnerGrantInPasses`, the edge node's `ownerSlotSigner` and `reportEnrolled`).

**Correctness — checked, nothing to fix.**
- The already-owner check before the redemption is sound: `wireOwnKeyIfOwner(signer)` throws only when a different key is wired, and the edge node wires only the owner slot's key (founding, joined start, import), so the slot key and the wired key never differ.
- An owner device whose own key was removed redeems with the same slot key: the check answers false, the local path re-seats the key, and `wireJoinedOwner` asks the already-wired signer, which is an owner again. Correct.
- The protocol-path redemption runs inside the edge node's transition queue, but `redeemOwnerGrant` passes no `waitForMember`, which defaults to false (one pass), so the queue is not held for an unbounded wait.
- `party-mismatch` and the decoder's refusals happen before `ownerSlotSigner`, so no key is made for them (the cadre-rn spec pins the first).
- `decodeJoinCredential` tests the trimmed prefix and hands the untrimmed text to decoders that trim themselves. `'invite' in credential` narrows correctly: `OwnerGrantBundle` has no `invite` field.
- `describeOwnerGrantFailure` maps `OwnerKeyAddRefusedError` to the redemption's "connect" line. Checked that no other call on these screens throws that error: a removal's `alone` is `OwnerKeyRemovalRefusedError`, still worded by `REMOVAL_REFUSAL_LINE`, and the docs quote that line correctly.

**Error handling and resource cleanup — no findings.** Every handler in the section logs and alerts. Grant text is never logged (only the grant's key and the key fingerprint). Reads that finish after the node is replaced are dropped, as the section's other reads are.

**Type safety — no findings.** `GRANT_REJECTION_LINE` is keyed by `OwnerGrantRejectedError['code']`, so a new code fails typecheck. No `any`.

**DRY / modularity / size.**
- `labelProblem` now serves both forms, and the redemption logic sits in `owner-grant.ts` as the edge node's size `NOTE:` asks. `edge-node.ts` is 1056 lines (`wc -l`), and its `NOTE:` says about 1050.
- `owner-keys-section.tsx` is 604 lines (523 before) and `use-cadre.ts` is 1030 (994 before). The growth is pass-throughs and state, with the views moved out to `owner-grant-views.tsx`. No split is warranted for this ticket.
- The kit README still lists `addBackupOwnerKey`. `reference-app-web-owner-grants` (implement/) removes it from core, the kit and the docs, and its text already says so.
