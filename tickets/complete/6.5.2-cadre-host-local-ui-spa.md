## Outcome

`yarn workspace @serfab/cadre-host build` produces both the server (`tsc`) and the SPA bundle (`vite build`) into `dist/`. The SPA lands in `dist/ui/` and is consumed by the static mount from `6.5.1`. Bundle: **0.45 kB index.html + 14.32 kB CSS + 106.97 kB JS = ≈ 43 KB gzipped** (39.31 kB JS + 3.27 kB CSS + 0.29 kB HTML), 194 modules transformed, no warnings, well under the 1 MB budget the plan pinned.

Five pages all wired through:

- **Home** — overall status dot, service/version/uptime, connectivity card with conditional "Resolve →" link, trust-circle count, nodes running/total, update-available banner.
- **Trust Circle** — members list (self-flagged), pending invites, "Invite a friend" modal that POSTs `/auth/invites` and renders the returned token + QR (inline SVG via `qrcode`).
- **Connectivity** — `NatStatusSnapshot` snapshot, "Test reachability" → `POST /nat/test`, port-forwarding form → `PUT /nat/settings`, DDNS form → `PUT /nat/ddns` populated from `GET /nat/providers`. CGNAT and manual-fix copy when reachability isn't `reachable`.
- **Nodes / NodeDetail** — empty-state notes that v1 doesn't auto-spawn nodes; detail page polls `/api/nodes/:id` every 5 s, log tail pulls `/api/nodes/:id/logs?lines=200`, start/restart/stop with confirm dialog on stop.
- **Settings** — `autoApply` toggle, manifest URL override, "Apply now" when an update is available, read-only install metadata with copy-to-clipboard buttons, uninstall pointer.

Realtime: `App.svelte` opens a single `EventSource` on mount (subscribed once) that dispatches the four event types (`node-state-changed`, `trust-circle-changed`, `connectivity-changed`, `update-available`) into `applyEvent`, which either patches `appState` in place or kicks off the relevant refresh helper. Reconnect uses a hand-rolled `[2s, 4s, 8s, 16s, 30s, 30s…]` backoff with a single toast on the first failure (suppressed once the connection re-opens).

Validation: 281 passed + 3 skipped across 40 test files (server suite + the three new UI test files for `api.ts`, `router.ts`, `events.ts`). Smoke wiring re-verified after the inline cleanup below.

## Review findings

### Architecture / consistency
- **Runes file split (router/state) diverges from the plan but is correct.** Svelte 5 forbids runes outside `.svelte`/`.svelte.ts`. The implementer split the reactive store into `router.svelte.ts` / `state.svelte.ts` and kept the pure parsers in `router.ts` so they remain testable without the Svelte compiler. Clean and justified.
- **Mixed-envelope `apiFetch` is the right call.** Half the existing routes return bare bodies (`/api/status`, `/nat/*`, `/auth/trust-circle`, `/update`); newer ones use `{ ok, data, error }`. The wrapper unwraps the envelope when present and throws `ApiError` on `{ ok: false }` regardless of HTTP status. Verified against `routes/nat.ts`, `routes/settings.ts`, `events/sse-route.ts`, `routes/trust-circle.ts`.
- **Settings PUT shape matches the server validator** (`{ updates: { autoApply, manifestUrl? } }` — server's `validatePatch` in `src/server/routes/settings.ts` lines 82–115 confirms).
- **SSE event names match end-to-end** (`src/server/events/types.ts` ↔ `ui/src/lib/events.ts` `EVENT_TYPES`). Heartbeats use the SSE comment prefix and so don't trigger named listeners, matching the comment in `applyEvent`.

### Dead code / DRY
- **Three unused icon components shipped** — `GearIcon.svelte`, `QrIcon.svelte`, `StatusIcon.svelte` had no importers anywhere in `ui/`. **Fixed inline (deleted)**. Vite tree-shaking meant the JS bundle hash didn't change after deletion, confirming they weren't in the build.
- **`state.svelte.ts:212–223` summary→full hydration shim is awkward but bounded.** `refreshStatus` projects the thin `/api/status` node summary into the full shape only when `state.nodes.length === 0` — a one-shot bootstrap. Subsequent `refreshNodes()` fills in real data. No bug, but flag in case future work surfaces ghost values (empty `workdir`, `spawnedAt`, ports `0/0/0`) for the brief window between the two calls.

### Error handling / resource cleanup
- `subscribeEvents` close path verified: `closed` flag short-circuits both `onerror` and `onopen`; outstanding `timer` is cleared; `EventSource.close()` is wrapped in try/catch.
- `NodeDetail` interval is cleared in `onDestroy`; `LogTail` `$effect` triggers a fresh fetch when `nodeId` changes.
- `App.svelte`'s `onMount` cleanup closes the SSE handle and stops the hash router on unmount.
- Modals (`InviteModal`, `ConfirmDialog`) handle Escape; backdrops cancel. **No focus trap and no auto-focus** on the dialog — flagged below as accessibility v1.

### Functional gaps (kept as known, not fixed)
- **`Settings.svelte` can't clear an existing `manifestUrl` override.** `saveUpdates` only sends `manifestUrl` when truthy (`if (manifestUrl.trim())`), so the server keeps the prior override. Once a user has saved a URL, clearing the input + saving silently leaves the override in place. Server accepts empty strings (`typeof !== 'string'` guard only) so a one-line SPA change would suffice — left for a follow-up since the plan didn't require it.
- **`Connectivity.svelte` doesn't reset `fieldValues` when the provider changes.** Switching providers leaves credentials entered for provider A in the form state for provider B. Low risk (the credentials never leave the modal until save), but worth tightening.
- **`Settings.svelte` and `Connectivity.svelte` `$effect`s overwrite the form on every state refresh.** If `refreshSettings()` or `refreshConnectivity()` runs while the user is mid-edit (e.g. an SSE event triggers a refresh), their unsaved input is clobbered. Acceptable for v1 but a UX trap worth a follow-up.
- **`NodeDetail` doesn't refetch immediately when the route id changes** — only the 5 s poll picks up the new id. Mounting via `onMount` runs once; subsequent id changes wait for the next tick. Could be `$effect` rather than `onMount`. Minor.

### Tests
- `ui/__tests__/api.test.ts` (8) covers envelope-on-2xx, envelope-on-non-2xx, bare body, `ok:false` on a 200, network failure → `ApiError('network')`, `apiPost` headers, `apiDelete` shape.
- `ui/__tests__/router.test.ts` (9) covers `parseHash` for all routes (incl. URL-encoded ids and unknown fallback), `hrefFor` round-trips, `navigate` setting/normalising the hash.
- `ui/__tests__/events.test.ts` (4) drives a fake `EventSource` through error → backoff schedule → clamp-at-last → reset-on-open → no-retry-after-close. Good coverage for the reconnect state machine.
- **No component or e2e tests** — explicitly out of scope per the plan and re-flagged by the implementer. Routes/components rely on smoke verification.

### Documentation
- **`docs/cadre-host.md` was out of date.** Lines 242 + 282 still said the SPA was "forthcoming." **Fixed inline** — placeholder note now describes the build pipeline + the placeholder-when-missing fallback, and the package-status section adds a `6.5.2` bullet describing the SPA.
- `README.md` already has a thorough "Local UI" + "Building the SPA" section from the implement step.
- `static.ts` placeholder HTML (in `6.5.1`) already points contributors at `yarn workspace @serfab/cadre-host build` and `build:ui`. No change needed; matches the implementer's claim.
- `docs/architecture.md` line 830's blanket "local UI implementations forthcoming" is now mostly false (orchestrator, trust-circle, NAT, installer, and local UI are all real), but that's a broader doc-refresh task that goes beyond this ticket.

### Security
- Same-origin only; no CSRF (consistent with the "same-machine access is the auth boundary" model documented in `README.md`). SSE-driven trust-circle/nat refreshes don't bypass that — they re-hit the same origin.
- `apiFetch` doesn't include credentials; not needed for same-origin loopback.
- `QrCode.svelte` uses `{@html svg}` to inject the SVG returned by the `qrcode` npm module. Acceptable because the SVG is library-generated from the invite token (not from arbitrary HTML); the only input is `result.encodedInvite` which is base64-ish and never reaches the SVG as markup.

### Build / packaging
- Server build (`tsc -p tsconfig.build.json`) clean.
- SPA build (`vite build --config ui/vite.config.ts`) → 194 modules, no warnings, sourcemap emitted.
- `package.json` `files` covers `dist/`, so `dist/ui/` ships in the npm tarball.
- `vitest.config.ts` `include` picks up both `src/**/__tests__` and `ui/__tests__`. Node + jsdom environments coexist via `@vitest-environment jsdom` pragma on the UI test files — no extra config needed.

## Deliberately not done in this review pass

- **Live browser smoke / Lighthouse capture.** The agent harness can't keep a foreground server alive across tool calls and background processes die at end-of-turn. The implementer flagged this; the human should run the documented smoke (`cadre-host start --data-dir /tmp/cadre-ui-test` then `http://127.0.0.1:8765/`) and capture a Lighthouse score before considering the feature shipped end-to-end. Static analysis says ≥ 95 perf / ≥ 90 a11y is plausible given the bundle size, semantic HTML, and absence of third-party fonts — but that's an inference, not a measurement.
- **Follow-up tickets not filed.** The functional gaps above (manifest-URL clear, provider switch, form-overwrite race, NodeDetail re-fetch on id change) are small UX papercuts inside the SPA. They can collect into a single `cadre-host-local-ui-spa-polish` ticket if/when they start biting.
