# Retired the "zero approvals from a healthy trio" failure and corrected what the code says about it

`Failed to get super-majority: 0/3 approvals (needed 3, 0 rejections)` from a healthy or delayed cohort member — nobody voting at all, including the two healthy machines — was fixed upstream on 2026-08-12 (`member-must-answer-a-lost-conflict-race`, optimystic `c7e3506d`) and has not recurred in the roughly 39 runs recorded in `tickets/.pre-existing-known.md` between 2026-08-21 and 2026-09-17. Everything changed is documentation, comments, one added unit test, and one ledger entry moved. No runtime behavior changed.

## What landed

**Scenario comments** (`control-write-degraded-cohort-member.integration.ts`): the "KNOWN INTERMITTENT" header block now states the class as fixed and historical and lists the fingerprints the file can still show with the ticket owning each; the stream-reset injector's doc comment keeps the historical lesson (inject at the batch seam, not the cluster promise seam) as history; the healthy, delayed and silent-member cases' comments no longer cite the closed class as live. The `\d+/3` assertion in the silent-member case was deliberately left as-is — two observations of `2/3` are not enough to pin a literal, and the comment explains why.

**Classifier comments** (`control-write-retry.ts`): the module header and `SUPER_MAJORITY_SHORTFALL_UNANSWERED`'s doc comment no longer claim a decisive rejection is never retried by this classifier, which was false for a rejection raised while the cohort is still collecting promises — it arrives wrapped in the transactor's `Some peers did not complete: …[block:…]` aggregate, and `isUncommittedTransactorAggregate` claims that wrapper on its own whatever the cause inside says. An accepted-tradeoff `NOTE:` at `isUncommittedTransactorAggregate` records what is retried, why it is kept (nothing has committed at that phase, and the only rejection ever seen there is the transient `pending conflict`), and the revisit condition (upstream `a-contended-pend-refusal-is-permanent-on-a-small-cohort`).

**A test pinning that tradeoff** (`control-write-retry.spec.ts`): `PROMISE_PHASE_REJECTION_IN_PEND_AGGREGATE`, a verbatim captured message, asserted retriable — so the tradeoff is an explicit claim rather than an implicit consequence of matcher composition.

**`docs/architecture.md`**: the control-write retry passage now records the abandoned-pend limit as fixed and closed with its evidence; notes that the anticipated follow-on change did *not* happen as predicted (the losing member gained a `conflict` vote kind, not a `reject` vote, so the classifier's zero-rejections guard needed no change); and describes the narrower limit that took its place, pointing at `blocked/control-write-refused-when-a-rival-write-holds-the-block`.

**`tickets/.pre-existing-known.md`**: the `0/3 approvals` entry moved out of "Open" into "Resolved in place" with its original analysis kept verbatim, and the 2026-09-17 Delta's "that ticket is now in `implement/`" clause was updated.

**Minor — fixed in this pass.**

- *The module header stated a rule the classifier does not implement.* The implement pass rewrote "a write somebody actually REJECTED is never retried" into "REJECTED **after something committed** is never retried". That is a different false claim: the classifier never tests whether anything committed, and a bare rejection is declined at every phase, including the promise phase, simply because no matcher claims a rejection message. What actually gets retried is the *wrapper*, not the rejection. Both `control-write-retry.ts`'s header and the same sentence in `docs/architecture.md` (which additionally mis-attributed the non-zero-rejection guard to "the commit phase", when that guard is phase-agnostic) now state the real rule.
- *A stale ticket citation the handoff claimed it had swept.* The handoff says it grepped `packages/` and `docs/` for `scenario-coverage` and found nothing stale. `packages/cadre-core/test/control-formation-seat-budget.spec.ts:482` still cited `control-write-retry-scenario-coverage`, a ticket long since landed and swept out of `complete/` (one record in `tickets/.pruned-tickets.jsonl`). Replaced with the path of the scenario file that actually produces the two retriable messages.
- *The known-failures list was left describing the class as live.* The handoff deferred this, gating it on the Phase 2 run series. The closure does not depend on that series — it rests on 39 recorded runs — and the ledger's own Delta already recorded it, so the stale Open entry was the only thing left. Moved to "Resolved in place" with its analysis intact; the Delta's pointer to `implement/` corrected.
- *A dangling "neither" in the new fingerprint table.* The second row read "`pending conflict` with neither, clearing by itself" with no antecedent in this copy of the table. Spelled out as "with NO preceding stream reset and NO `cancelError`".
- *The new test's provenance pointed at a file that deletes itself.* `tickets/.logs/` is pruned on age and run count, so citing `control-write-hears-zero.gate-r1.log` as the record of a message would rot. The comment now says the literal in the spec *is* the surviving copy.

**Verified, not taken on faith.** Every citation the implement pass added was checked against the thing it cites: optimystic `c7e3506d` is `ticket(review): member-must-answer-a-lost-conflict-race`; `../optimystic/tickets/fix/2-a-contended-pend-refusal-is-permanent-on-a-small-cohort.md` exists (the doc's reference to it carried the sequence prefix, which can change — rewritten to slug plus folder); `control-write-refused-when-a-rival-write-holds-the-block`, `control-write-retry-does-not-absorb-a-transient-stream-reset` and `control-peer-row-refresh-invisible-to-third-node` are all on the board; and `PROMISE_PHASE_REJECTION_IN_PEND_AGGREGATE` matches the captured log byte-for-byte.
