Fourth of the `strand-offline-mode` chain. `strand-offline-cadre-core` added `CadreNodeConfig.strandOffline` (`journal`, `initialMode`); this ticket supplies it from the edge node (what `@serfab/cadre-rn/phone-node` and the web reference app run) and implements the journal on the phone and in the browser. Implementation landed in `ticket(implement): strand-offline-platform-journals`.

## What landed

- **Platform seam.** `EdgeNodeStorage.offlineJournal?(scope): Promise<IKVStore>` (`platform.ts`): same instance per scope until `close`, which flushes and closes it; `destroyScope` closes it too. Absent: no offline mode on that platform.
- **Config.** `buildConfig` passes `platform.storage.offlineJournal?.bind(...)`; `buildEdgeNodeConfig` adds `strandOffline: { journal, initialMode: strandOfflineMode ?? 'online' }` only when a journal exists.
- **Kit default.** `EdgeNodeOptions.strandOfflineMode` (`'online' | 'offline'`), saved in the start record and parsed back (anything else parses as absent). Carried through a join (from the party left) and back to the founded party by `startAfterRemoval`, as `noiseCryptoMode` is.
- **Phone** (`LevelDBEdgeStorage`): one `LevelDBKVStore` per strand scope over the scope's existing rn-leveldb handle, default key prefix. `close()` closes the node-local store, then journals, then databases. `destroyScope` closes the scope's journal and handle before `destroyDB`.
- **Browser** (`strand-storage.ts`): `openJournal(key)`, one `IndexedDBKVStore` per key over the shared handle, closed by `closeStores` and `deleteStore` before the handle.
- **NativeScript** untouched (backlog `feat-strand-offline-mode-nativescript`).

## Review findings

Read the implement diff first, then the sibling store classes it builds on (`LevelDBKVStore`, `IndexedDBKVStore` in `../optimystic`, read only) and cadre-core's `strandOffline` consumer (`strand-offline.ts`, `strand-database.ts`, `strand-instance-manager.ts`).

**Correctness — checked, no defect found.**
- Scope agreement: cadre-core calls `journal(strandId)` and `storage.provider(strandId)` with the same key (`strand-instance-manager.ts` `offlineDatabaseConfig` / `resolveStrandStorage`), so the journal lands in the same database as the strand's blocks on both platforms.
- Key separation: `LevelDBKVStore` tags key-value keys with `TAG_KV`, apart from block keys; `IndexedDBKVStore` uses the `kv` object store. The journal's own namespace is `optimystic-offline/` (`db-p2p` `OFFLINE_JOURNAL_KEY_PREFIX`). Doc claims match.
- Lifetime: cadre-core's `StrandOfflineConfig.journal` contract says nothing in cadre-core or Optimystic closes the store and every rebuild asks again, which is exactly what the per-scope cache plus close-on-storage-close implements. Both store classes' `close()` only flushes and disarms the idle timer; the host closes the handle after, which both platforms do in that order.
- Browser durability: the journal is built without options, so it resolves strict durability from `supportsStrictDurability()`, the same answer the raw storage's proxy states. Consistent.
- `connectToStrandBrowser` really does use `new IndexedDBKVStore(db)` (default prefix) over `sereus-strand-<id>`; the implementer's prefix claim holds.
- `destroyScope` is only ever called on a control scope (`dissolve.ts` `finishRemoving`), so its journal arm is never exercised today; the handle-close arm turns what would have been a `destroyDB` throw into a close, and the platform contract still requires callers to have no handle open. Kept as written.
- The old saved-start record and the malformed-value fallback are pinned by the existing `options.spec.ts` round-trip and malformed-field cases, which the implementer extended; no new test needed.

**Implementer's open questions — decided.**
- Default key prefix (`'optimystic:txn:'`) rather than `''`: **kept**. It matches the only other code that journals into the same IndexedDB database, nothing has shipped with either value, and one rule across both platforms is simpler.
- Carrying `strandOfflineMode` through join and removal: **kept**. Dropping it would silently revert an app to online after a background restart in the joined cadre, which is the failure the saved field exists to prevent.

**Fixed inline.**
- DRY: `LevelDBEdgeStorage.close()` had three copies of a try/catch/warn block; extracted a module-level `closeLogged(what, closable)`. The web `closeStorage`/`closeJournal` pair were the same function twice; merged into one `closeLogged`.
- Docs: the strands.md bullet about a Node embedder supplying `FileKVStore` sat under "On the edge node" though it is about non-edge embedders; moved to "On a cadre node". `packages/reference-app-web/README.md` (which documents `strand-storage.ts` and lists each database's contents) did not mention the journal; added it to the chat strand's database entry and the storage bridge section.

**Tripwire parked.**
- Browser `openJournal` (like the pre-existing `openStore`) can cache a store over a closed handle if a call races `closeStores`; unreachable while the edge node stops strands before closing storage. `NOTE:` at `openJournal` in `strand-storage.ts`.

**Tests.** No tests added or cut. The phone and browser journal paths are a constructor over an existing handle plus cache/close bookkeeping; they are exercised end to end by `strand-offline-reference-apps` and the real-network scenario of `strand-offline-mode`. The `buildEdgeNodeConfig` branch is a presence check with nothing to pin beyond what the type enforces.

File size: `leveldb-storage.ts` shrank; `strand-storage.ts` is ~200 lines.
