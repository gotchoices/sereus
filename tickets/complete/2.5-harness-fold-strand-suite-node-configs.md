# Complete: last two private node-config builders folded onto `controlNodeConfig`

Second and final half of `harness-one-node-config-builder`. The prerequisite landed the harness
side (`controlNodeConfig` in `harness/node-fixtures.ts`, `createMockProvisioner` /
`createMockUsageRecorder` hoisted into `harness/formation-mocks.ts`, both re-exported from
`harness/index.ts`, plus `test/control-node-config.spec.ts` as the builder's unit guard) and four
cheap scenario folds. This ticket folded the two long-running files held back for their own run.

Implement diff: 27 insertions, 105 deletions across two scenario files, no production code.
Review pass added three small changes (below), still test-only.

## What landed

### `strand-membership-closed-strand-e2e.integration.ts` (1811 → 1787 lines)

Local `createTestNodeConfig` and `createMockProvisioner` deleted. Both bring-up sites converted
positional-to-object, with each node's `captureRawStorage()` capture riding across as
`storageProvider`. The founder gets `founderCapture`, the joiner `joinerCapture` — the
one-capture-per-node rule the deleted helper's doc comment carried survives in
`bringUpClosedStrand`'s own body comment, and the fourth test's distinctness assertion
(`expect(founderStore).not.toBe(joinerStore)` plus the per-scope `capture.scopes()` checks) is
the guard that they were not collapsed.

The harness `createMockProvisioner` takes a REQUIRED prefix, so the fold passes `label` rather
than inheriting the old file-local `'closed'` default — each bring-up now names itself in the
strand ids it mints. Nothing asserts on the literal strand id, so this is an improvement in
failure legibility, not a behaviour change.

### `strand-formation-e2e.integration.ts` (1744 → 1687 lines)

Local `createTestNodeConfig`, `createMockProvisioner` and `createMockUsageRecorder` deleted; all
three replacements imported from the harness. All eight call sites converted, including the
single-node Phase-3 case, which came out as `controlNodeConfig({ partyId })` — transaction
profile, default loopback WS listener, `enableRelay` left unset so `CadreNode` derives it, which
is exactly what the old zero-option call produced.

The file-header size note was refreshed: 1687 lines, now the SECOND-largest file in
`src/scenarios/` behind `strand-membership-closed-strand-e2e` at 1787. Re-measured this pass with
`wc -l`; both figures still hold.

### Fixed in this pass

- **`wsTransports`'s doc comment was stale.** It claimed to be "shared by every e2e/integration
  scenario"; this fold removed the last scenario that called it, leaving `controlNodeConfig` as
  its only consumer. Comment rewritten to say what it now is and why it stays exported. (`knip`
  scores unused exports as `warn`, not a gate failure, so nothing was red — but the comment
  actively misled.)
- **The builder's unit spec never asserted `network.transports`.** With the last direct
  `wsTransports()` call gone from the scenarios, `controlNodeConfig` is the single place
  transports come from, and a regression dropping them yields a node that starts and then fails
  every dial as an unexplained timeout. Added a case to `test/control-node-config.spec.ts`
  asserting the default config carries the full transport list and that every entry is a
  transport factory. 11 tests pass.
- **`cadre-host-trust-circle.integration.ts` — kept hand-written, now says so.** The handoff
  correctly declined to fold this one: it is a deliberately minimal node with no `network`,
  `storage`, `strandFilter` or `hibernation` block, never put on the wire, and routing it through
  `controlNodeConfig` would ADD WebSocket transports, a loopback listener, a memory store,
  `strandFilter: 'all'` and `hibernation: false` — a behaviour change, not a deduplication. I
  agree, and left the config alone. What I did add is a `NOTE:` at the site recording that
  decision and its reason, so the next dedup pass does not re-discover and "fix" it. While there,
  its six-line owner-genesis block folded onto the existing `makeOwnOwner` helper (behaviour
  identical — that helper's body is what the site inlined); its three tests pass.
