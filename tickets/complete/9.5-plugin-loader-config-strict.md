# Strict plugin-loader settings

Maintainer decision (2026-09-28): strict, same as the cadre-cli config file. The plugin loader (Quereus `registerPlugin`, Quoomb CLI/Web) hands the plugin a `Record<string, SqlValue>`; `parseConfig` validates every key against one table (`SETTINGS` in `src/parse-config.ts`) and throws one error listing every problem: missing `strand_id`, ill-typed or out-of-set values, unknown keys, and the retired `mode` (with its own message). It returns `{ options, storagePath? }`; the Node entry turns `storagePath` into a `FileRawStorage`, the browser entry rejects it. The package manifest's `quereus.settings` lists exactly the accepted keys (a test pins the equality), with `fret_profile` and `transactor` as `select` settings.

Implementation landed in `ticket(implement): plugin-loader-config-strict`.

## Review findings

Read the implement diff first, then checked the hosts that produce the config: Quereus `registerPlugin` and plugin-loader's `toPluginSqlConfig` (pass-through, no defaults merged), Quoomb CLI `.plugin config` (coerces number/boolean by manifest type, refuses unlisted keys), and Quoomb Web `PluginsModal` (text inputs send `''` when cleared, number input sends `Number(...)`, select shows the first option when unset). No other repo code passes plugin settings: `cadre-core` uses `connectToStrand` directly and its `control-database.ts` `enable_cache` belongs to the optimystic plugin.

- **Correctness / edge cases** — checked absence (missing/NULL/`''` on string and select kinds), `required`, ill-typed `strand_id`, port bounds and non-integers, bigint display, blob/JSON display, long-string truncation, multiple problems in one error, and `Object.hasOwn` for unknown-key detection (not fooled by `constructor` etc.). No defect found.
- **Fixed: manifest had no `label` on any setting.** Quereus's `PluginSetting.label` is required, and Quoomb Web renders `{setting.label}` as each field's only caption, so the settings form showed ten uncaptioned inputs. Added a `label` to every setting and a `help` to `bootstrap_nodes`, `port`, `transactor`, `storage_path` in `package.json`. No test added (it is data, and the existing manifest-keys test covers drift of the key set).
- **Tripwire: env-interpolated numbers.** plugin-loader's `${VAR}` interpolation in `quoomb.config.json` always yields a string, so `port`/`enable_cache` cannot come from an env var under strict typing. Consistent with the maintainer's decision and the pinned `port: '4001'` rejection; parked as a `NOTE:` above `PORT` in `parse-config.ts`, and one README sentence tells users.
- **Handoff questions** — `''` rejected on `port`/`enable_cache`: kept; no Quoomb UI path produces it and the error names the key. Saved Quoomb configs holding `mode` failing to load: the accepted cost of strict, with a pointed message. `strand_id: 5` reporting "must be a string" rather than "is required": correct wording for the case.
- **Considered, left as is** — the browser entry's `storage_path` rejection is thrown after `parseConfig`, so it is not batched with other problems in the same error; a config with both a typo and `storage_path` needs two attempts. Folding it in would need a platform parameter on the shared parser for one key; not worth it. Each unknown key's problem line repeats the accepted-key list; cosmetic.
- **Tests** — the removed `should handle empty bootstrap_nodes` was a strict subset of the new absent-means-default test; removal agreed. The `it.each` rejection table, one-error aggregation test, and manifest-keys equality test each pin a distinct piece of the contract; none cut. The older `should reject an unrecognised transactor` test overlaps the table in kind but covers the transactor key the table lacks; kept. No new tests.
- **Docs** — README settings table and strict-checking paragraph match the code; the plugin-loader example and quoomb.config.json example use only accepted keys. `docs/architecture.md`'s `bootstrap_nodes` mention is still accurate. Nothing else in `docs/` references the plugin settings.
- **Source hygiene / type safety / resources** — `parse-config.ts` is ~190 lines of small functions; the mapped-type table forces every key to have a reader of the right type, and `oneOf<T>(Record<T, true>)` fails to compile if a union member is added or dropped. No resources are acquired before validation, so a throw leaks nothing.
- **Validation** — `yarn workspace @serfab/quereus-plugin-sereus typecheck` clean; `yarn workspace @serfab/quereus-plugin-sereus test` 10 files, 124 passed, 1 todo; `yarn lint` exit 0.
