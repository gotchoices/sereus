# File names built from ids no longer depend on letter case

`encodeFileSafeComponent` (`packages/cadre-core/src/fs-atomic.ts`) turns an id into a file name. It percent-encoded but kept letter case, so on NTFS / APFS two ids differing only in case shared one file. Its two users are `FileKeyStore` (slot `<dir>/<encoded key id>.key`; the realistic victim was `cadre/joined-strand/<base64url party id>/<strand id>`) and `FileDurableSlot` (`<dir>/<name>.<encoded party id>.json`, behind the trusted-owner, bootstrap-peer, enrolled-machine and strand-peer-book file stores).

## What landed (`ticket(implement): file-store-names-collide-on-case-insensitive-filesystems`)

- **Encoder:** also escapes `A`–`Z` as `%41`–`%5A`, passing existing `%XX` escapes through so their uppercase hex is not re-escaped. Output is `[a-z0-9_-]` plus `%XX` with uppercase hex; ids with no capital letters encode exactly as before (node identity slot `cadre%2Fidentity.key` unchanged).
- **`decodeKeyId`:** skips (with a log line) any `.key` file whose name is not the canonical encoding of what it decodes to, so `list()` never names an id that `get()` reports absent (e.g. an old-format joined-strand file).
- **Docs / release note:** `docs/architecture.md` FileKeyStore bullet names the encoding and why; `.release-notes.pending.md` says joined-strand records and per-party files for party ids with capitals start fresh after upgrade and old files can be deleted.
- **Tests** (`packages/cadre-core/test/key-store.spec.ts`): two case-only-differing rows in the contract round-trip test (the real reproduction on Windows/macOS); a platform-independent encoder pin (no literal uppercase, round-trips, `cadre/identity` unchanged); a `list()` test for the non-canonical-name skip.

## Review findings

Checked:
- **Encoder correctness.** Read the regex against `encodeURIComponent`'s output: `%` only ever starts an escape, so the alternation matches every escape before its hex digits could be seen as capitals. Injectivity ignoring case holds because literal letters are always lowercase and hex digits always uppercase, so two outputs equal ignoring case are equal outright; non-ASCII (where NTFS case tables go beyond ASCII) is always escaped. No defect.
- **`decodeKeyId` canonical check.** Re-encoding and comparing is the minimal way to keep `list()` and `get()` agreeing; it also rejects lowercase-hex escapes a foreign tool might write. No defect.
- **Other callers / file-name consumers.** Grepped every use of `encodeFileSafeComponent` (only the two stores) and every test or helper that builds these file names by hand (`bootstrap-peer-store.spec.ts`, `strand-peer-book.spec.ts`, `enrolled-machine-store.spec.ts` seed files as `<name>.${PARTY}.json`). All use the lowercase `party-alpha`, so their seeded files still land at the name the store reads — they are not passing vacuously. Integration helpers find files by prefix (per the handoff); not re-run.
- **Docs.** `docs/architecture.md` bullet is accurate. `docs/cadre-host.md` and `packages/cadre-cli/README.md` write `trusted-owners.<partyId>.json` informally; accurate for the lowercase ids those hosts use, left as is.
- **Tests.** The three new tests each pin something a Linux run would not otherwise catch (the contract rows only bite on case-insensitive filesystems, hence the encoder pin); kept all three, none cut.
- **Hygiene / error handling / types.** Nothing eaten silently (skips are logged); no `any`; file sizes unchanged in any meaningful way.

Found and done:
- **Tripwire (conditional):** a pre-upgrade file such as `trusted-owners.Alice.json` has, ignoring case, the new name of the lowercase id `alice`, so on Windows/macOS a lookup for `alice` opens it. Per-party records reject it via the envelope party-id check (`node-local-snapshot.ts`, `enrolled-machine-store.ts`) and cold-start; `FileKeyStore` would need two parties in one key directory whose ids fold to the same lowercase string. The handoff raised this and left it undocumented in code; parked as a `NOTE:` in `encodeFileSafeComponent` (`packages/cadre-core/src/fs-atomic.ts`) with the revisit condition (rename or remove old-format files at store open if it is ever seen in practice).
- Major findings: none — no ticket filed.
- Accepted-tradeoff notes at the sites: none present.
