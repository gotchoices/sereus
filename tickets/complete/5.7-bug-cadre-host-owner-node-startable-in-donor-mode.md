# Refuse owner start/restart on a donor-only host

## What landed

- `registerNodesRoutes` (`packages/cadre-host/src/server/routes/nodes.ts`) takes `role: HostRole`; in the donor role, owner start/restart answer `409 { code: 'own_cadre_disabled' }` before the saved-config check. Stop stays allowed in both roles.
- `createLocalUiServer` computes `role` once and passes it to the status and nodes routes.
- `deriveOverallStatus` (UI) ignores the owner node for a donor, so a leftover stopped owner node no longer holds the dashboard at "Attention". The node stays listed.
- `docs/cadre-host.md`: API table, "Honest gaps", and (in review) the donor-role consequences list describe the 409 and the health-summary exclusion.

Implementation commit: `ticket(implement): bug-cadre-host-owner-node-startable-in-donor-mode`.

## Review findings

- **Correctness of the guard:** checked. The role check sits before `hasOwnerConfig()`, so a donor gets 409 whether or not a founder run left a saved config. The route is the only caller of `ensureOwnerNode`/`restartOwnerNode` outside the founder branch of `bin/host.ts`, so one guard covers the class. `role` is a required option, so any future caller of `registerNodesRoutes` must decide it (type-enforced); the only callers are `server/index.ts` and the route test.
- **Error message (minor, fixed):** the 409 message told users to "start with --own-cadre", but `--own-cadre` is an `install` option only (`bin/host.ts` line ~102), not a `start` flag. Reworded to "Set ownCadre.enabled in host.config.json and restart cadre-host" — matching the docs, which say the flag is install-time/structural and not settable through `/api/settings` (`ownCadre` is in `FORBIDDEN_KEYS`).
- **Docs (minor, fixed):** the anchor section "Two roles: donor and founder" described the UI hiding owner lifecycle buttons but not the API refusal or health-summary exclusion; added one sentence there. The API table and "Honest gaps" bullet were already updated by the implementer and are accurate.
- **UI:** `NodeDetail.svelte` already hides owner Start/Restart for donors, so the 409 is only reachable via direct API calls; the UI does not surface `own_cadre_disabled` and does not need to. `deriveOverallStatus` exclusion reads correctly (`owner` is mirrored from the server list in `state.svelte.ts`).
- **Layering:** `nodes.ts` imports the `HostRole` type from `routes/status.ts`; a type-only import between sibling route modules, already the exported home of that type. Left as is.
- **Tests:** both added tests meet the bar — the route test is the bug reproduction (also asserts the orchestrator was never asked to spawn), the UI test pins the new branch of the status derivation. No tests cut; none added.
- **Resource cleanup / error handling / performance:** nothing new — the change adds no resources, and the helper returns a plain reply. No findings.
