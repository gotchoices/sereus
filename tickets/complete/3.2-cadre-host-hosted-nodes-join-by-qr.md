# Hosted nodes: join a cadre by QR, grants removed — complete

Third of the `cadre-host-join-a-cadre` chain. Implemented in `ticket(implement): cadre-host-hosted-nodes-join-by-qr`; reviewed and finished here. The web page is `cadre-host-join-ui` (next), the paste-an-invitation way in is `cadre-host-join-by-invitation`, the doc rewrite is `cadre-host-join-docs`.

## What landed

**cadre-core.** `node-claim-payload.ts`, exported from the package root: `encodeNodeClaimPayload({ peerId, multiaddrs, secret })` produces `sereus-join:1.<base64url of canonical JSON>` and `decodeNodeClaimPayload(text)` reads it back. Both directions refuse any version but 1, a body that is not base64url JSON of the right shape, a peer id that does not parse, an empty address list, an address that does not parse or whose destination peer (the last `/p2p/`, past any relay hop) is not that peer id, and a secret `parseClaimSecret` refuses. Loads on React Native: only `@multiformats/multiaddr`, `@libp2p/peer-id` and `uint8arrays`.

**Orchestrator.** `createContainer(request: HostedSpawnRequest)` where `HostedSpawnRequest = OrchestratorCreateRequest & { claimSecret?: string }`. The secret reaches the child as `CADRE_CLAIM_SECRET` through `extraEnv` only, never as an argument, never in `state.json`. The `pinnedOwnerKeys` wiring and the foreign-party push gating are gone: every `storage`-profile node gets the push block when credentials are configured.

**`src/hosted/`** (the renamed `src/donation/`): `types.ts` (`HostedNode` with `join: { kind: 'claim'; secret }`, placeholder party `unclaimed`, statuses `spawning | unclaimed | joined | error`, `HostedNodeView` with the secret stripped, `HostedNodeError`, `HostedNodeChange`), `hosted-node-store.ts` (`<dataDir>/hosted-nodes.json`, synchronous by design), `node-status.ts` (the child's `/status` typed against cadre-cli's `HealthStatus`, `reportsClaim`), `hosted-node-service.ts` (`join`, `claimDetails`, `remove`, `reset`, `respawn`, `reapStuckSpawning`, `list`, `get`, `onChange`, the watcher's start/stop), `hosted-node-watcher.ts` (one 2-second timer polling every unclaimed node each tick and each joined node every 15 seconds or at once when poked), `hosted-node-supervisor.ts` (respawn with backoff and give-up; a handle no record names is logged at startup and left running).

**Routes** `routes/hosted-nodes.ts` mounted by `createLocalUiServer` when `hostedNodes` is passed, using the `/api/*` envelope. The service's `onChange` is wired to the bus as `hosted-nodes-changed` with `kind` and `nodeId`; `grants-changed`, `GrantError` and `DonationError` are gone.

**CLI.** `cadre-host join [--no-qr] [--no-wait]`, `cadre-host node list`, `cadre-host node remove <id>`, `cadre-host node reset <id> [--no-qr] [--no-wait]`; the `grant` group and `duration.ts` deleted. The payload text goes to stdout alone, everything else to stderr (`bin/join-output.ts`).

**UI.** Grants page, modal, `lib/grants.ts`, nav entry, route and Home tile deleted; `NodeDetail`'s Terminate is **Remove** calling `DELETE /api/hosted-nodes/:id`; the Nodes empty state points at `cadre-host join`; `hosted-nodes-changed` re-reads the node list (added in review, below).

**Harness and scenario.** `createTestCadreHost` wires the store, service (watcher started) and supervisor (started), takes a `portRange`, and stops the watcher and supervisor before the server. `cadre-host-join-by-qr.integration.ts` replaces the two donation scenarios: 201 and `unclaimed`; the payload decodes and names a non-loopback `/ws` address; a phone-shaped claimant claims it and the record goes `joined` with its party and owner key over SSE and `GET`, then `connected`; the child is killed and respawned on the same ports as the same peer with the claimant reconnecting; 409 on the joined node's claim; `DELETE` removes record, child and workdir; the secret never appears on the SSE stream or in the host's debug log.

**Docs, minimal.** docs/cadre-host.md, packages/cadre-host/README.md, docs/testing.md and the cadre-host summary and dial table of docs/architecture.md. The rest of docs/architecture.md (lines near 706, 787 and 1235 still describe `/grants`, the "donate-a-node contract" and link the removed `cadre-host.md#node-donation` anchor) and docs/reference-app-rn.md's "Borrowing a Node" section are carried by `cadre-host-join-docs` and `rn-app-joins-host-node-by-qr`, both on the board and both naming those sites.

**Checked and found sound.** The re-read-after-await rule holds at every site a record is written across a wait (`joinLocked`, `respawn`, `remove`, the watcher's `pollOne`, the supervisor's refill and give-up, the reap); the secret leaves the host only through `claimDetails` and is absent from the view, the events, the orchestrator's `state.json` and the `cadre:host:*` log; the supervisor and watcher serialize their passes on one tail each; the harness stops both before the server; the error-handler maps every `HostedNodeErrorCode`; the fake orchestrator mirrors the real drop/restore/refuse handle rules the service depends on; the follow-up tickets `cadre-host-join-ui`, `cadre-host-join-by-invitation` and `cadre-host-join-docs` exist in `implement/` with the deferred work named.

**Minor, fixed in this pass.**

- `isDialableFromLan` let the unspecified addresses `0.0.0.0` and `::` into the payload. libp2p expands a `0.0.0.0` listen into interface addresses, so it is not reached today, but a raw one names nothing a phone can dial; filtered alongside loopback.
- `readNodeStatus` let a non-JSON `/status` body escape as a plain `Error`, which `claimDetails` would answer as a 500 instead of the 503 every other startup condition gets; wrapped as `node_unavailable`.
- The watcher's `lastPolledAt` and `due` maps kept entries for removed nodes forever; `pollOnce` now drops entries for ids no longer on record.
- The README said the SPA re-fetches when a hosted node is added, claimed or removed, but `applyEvent` ignored `hosted-nodes-changed`; it now re-reads `/api/nodes` on that event (a join adds a handle, a removal drops one). The hosted-node slice itself stays with `cadre-host-join-ui`.
- Stale donation-era wording the ticket missed: `orchestrator/node-identity.ts` and `orchestrator/port-allocator.ts` ("donated node", "loan", "lent node"), cadre-cli's `admin-server.ts` add-drone comment ("donor host"), and `orchestrator-node-identity.test.ts`, whose requests still passed `pinnedOwnerKeys` (a field cadre-host no longer reads) under `donated-*` / `foreign-P` names. Reworded; the test's requests drop the field.
