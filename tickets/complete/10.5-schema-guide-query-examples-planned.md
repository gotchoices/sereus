# Schema guide query examples are planned against a named schema

## What landed

Landed in `ticket(implement): schema-guide-query-examples-planned`.

`packages/quereus-plugin-sereus/test/schema-guide-examples.spec.ts` reads every fence in `docs/schema-guide.md`. Info-string grammar:

- `sql schema` or `sql schema <name>` — apply the body, then plan an insert/update/delete per table and a select per view.
- `sql query <name>` — fresh database, `applyAppSchema` of the named schema block, `App` alone on the search path, parse the block with `Parser.parseAll`, plan (never run) each statement.
- `sql script` — run as-is. `sql fragment` — never run; now used only for lone constraint lines.

Names match `/^[a-z][a-z0-9-]*$/`; a missing or malformed name, a name on `script`/`fragment`, or a schema name used twice fails the "marks every fence" test. A query may sit above the schema it names.

Guide changes: named schemas `chat` (gained `tags`), `ledger`, `event-clock`, `message-graph`, and a new `org` (`employees`); the Ordering, CTE, set-operation, RETURNING, table-valued-function and window-function examples are now `sql query` blocks over those schemas. `diff` is documented as a symmetric difference (what Quereus plans). The running digest is a recursive CTE over `ledger`, since Quereus has no digest window aggregate and no windowed `group_concat`. The intro explains the markers and that app code qualifies tables with `App.`. `docs/testing.md` → "Schema guide examples execute" describes the new marker and the duplicate-name rule.

## Review findings

Checked:

- **Diff read first.** Spec, guide and `docs/testing.md` changes read in full against the handoff; they match it.
- **Correctness of the harness.** `fenceOf` rejects every malformed form the handoff lists (a fourth word, a name on `script`/`fragment`, `query` without a name, uppercase names). The `Fence` union makes a nameless `query` unrepresentable, and `checkBlock`'s switch is exhaustive over the non-fragment markers. Each block gets its own database, closed in `finally`. Nothing to change.
- **Engine claims in the guide, verified in `../quereus` source (read only).** `diff` expands to `(A except B) union (B except A)` (`planner/building/select-compound.ts`), so "symmetric difference" is right. The registered window functions (`func/builtins/builtin-window-functions.ts`) include ranking, navigation, value and `count`/`sum`/`avg`/`min`/`max` aggregates but no `group_concat`, so that sentence in the guide is right.
- **Docs.** `docs/testing.md` no longer points at the retired `debt-schema-guide-query-examples-unchecked` backlog ticket. Repo-wide grep finds no remaining references to it, or to the removed `DigestAll` / `json_array_elements_text` examples. The intro's claim that app code qualifies tables with `App.` matches `packages/reference-app-web/src/lib/chat-dml.ts`.
- **Interaction with open work.** `tickets/backlog/feat-shared-causal-history-for-sapps.md` edits "Ordering Events". Renaming or dropping the `event-clock` / `message-graph` schemas would fail the query test with "query refers to no `sql schema …` block", which names the fix, so I added no note to that ticket.
- **Validation.** `yarn workspace @serfab/quereus-plugin-sereus vitest run --project unit`: 7 files, 128 tests pass (26 in the guide spec, 7 of them query blocks). The package typecheck and `yarn lint` both exit 0.

Found:

- **Minor:** none worth changing. `schemaNames` takes a `blocks` parameter with the same name as the module-level constant, and the duplicate-name assertion shares an `it` with the unmarked-fence assertion, so when both are broken only the first shows. Both are cosmetic and I left them as they are.
- **Major:** none.
- **Conditional (tripwire):** a query block can plan cleanly and still fail when run. For example, the RETURNING insert would be refused at commit by `sender_is_member` if no membership row exists. The spec's header `NOTE:` already covers this, and the implementer widened that note to include queries, so I added no new tripwire.
- **Tests:** none added or cut. The per-block loop gives one test per query block, and the duplicate-name assertion is part of the marker contract. The implementer checked the negative cases by hand and did not keep them as tests, which is right under the "tests must pay for themselves" rule.
