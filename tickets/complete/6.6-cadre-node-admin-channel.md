## What landed

The node side of the cadre-host control-plane realignment (host side is 6.7). `cadre-cli start` gains `--authority`, `--admin-port`, and `--identity-protobuf`, plus a loopback admin HTTP surface; cadre-core gains the authority-key bridge, the push-model invite-address resolver, and idempotent-genesis + membership-read helpers on `ControlDatabase`.

### cadre-core
- **`authority-key.ts` — `authorityKeyFromLibp2p(privateKey)`** (exported from `index.ts`): bridges a libp2p Ed25519 key into the base64url `{ privateKeyB64, publicKeyB64 }` consumed by `@optimystic/quereus-plugin-crypto`. Single-key path: peer-id and authority pubkey are one keypair (libp2p raw seed `[0:32]` is the noble private key; derived pubkey === `publicKey.raw`).
- **`CadreNode`** — `get partyId`, `setInviteAddresses(string[]|null)`, private `resolveInviteAddresses()` (pushed → config resolver → `getMultiaddrs()`), `listMembers()`, `isMember(peerId)`. Both `initializeSeedBootstrap` and `enableSeedListener` now wire the push-model resolver.
- **`ControlDatabase`** — `hasAuthorityKey()`, `ensureAuthorityKey(key)` (idempotent genesis), `queryCadrePeers()`.

### cadre-cli
- **`admin-server.ts`** — `AdminServer` binds `127.0.0.1:<port>`, constant-time bearer check against `CADRE_STARTUP_TOKEN`, provider-style `{ ok, data }` / `{ ok:false, error:{ code, message } }` envelope (codes→status 401/503/400/500). Implements the 8 wire-contract routes; unexpected "not initialized / not running / must be started" errors classify to `not_ready`, everything else `internal`.
- **`start.ts`** — `--authority` (genesis + seed-bootstrap init), `--admin-port` (refuses to bind without `CADRE_STARTUP_TOKEN`), `--identity-protobuf <path>`. Admin server started after authority init, closed on shutdown alongside the health server.
- **config loader** — `identity.protobufKeyFile` (+ `CADRE_IDENTITY_PROTOBUF` env, + `--identity-protobuf` flag) loads the installer's protobuf `identity.key` via `privateKeyFromProtobuf`; takes precedence over the raw/hex `keyFile`.

- **Lint: N/A** — neither `@serfab/cadre-cli` nor `@serfab/cadre-core` defines a `lint` script (aegir is a devDep but no lint wiring), so there is no lint gate for these workspaces. Nothing to run; not a gap introduced here.

**Correctness / schema:** Verified `queryCadrePeers` selects columns that exist (`PeerId`, `Multiaddr` per `schemas/control.qsql:44`). Verified the authority-key encoding bridge against the crypto plugin (the implementer's `authority-key.spec.ts` round-trips sign/verify and asserts `getPublicKey(seed) === publicKey.raw`). Verified the push-model resolver semantics: pushed `null` → libp2p fallback, pushed `[]` → explicit empty override (covered by `invite-address-push.spec.ts`). Constant-time bearer check and 127.0.0.1-only bind are correct for a same-machine trust boundary.

**Minor — fixed inline this pass:** the admin-server spec had no coverage for three reachable branches: the `internal` (500) classification of an unclassifiable error, rejection of a non-object JSON body (array), and the `MAX_BODY_BYTES` over-large-body guard. Added three tests (`error classification & body handling`) plus a `genericFailure` hook on the mock node; all green.

**Major — filed `fix/quereus-cadrepeer-delete-no-row-context`:** the `DELETE /admin/members/:peerId` route delegates to `CadreNode.removePeer` → a signed CadrePeer delete, which currently throws `QuereusError: No row context found for column PeerId` from Quereus' deferred-constraint evaluation (the `check on insert, delete` constraint references `coalesce(new.PeerId, old.PeerId)`; the `old`-row column isn't resolvable in the deferred delete context). Mock-level route tests pass, but the operation is non-functional against a real control DB. The fix lands in the linked `../quereus` workspace, so it is filed as a separate fix ticket rather than patched here.

**Notes accepted as-is (documented, not blocking):**
- `accept-phone` passes `issuedInvite` through as `CadreInvite` with only `phonePeerId`-presence validation; a malformed invite surfaces as whatever `acceptPhone` throws (classified `internal`). Acceptable for a same-machine trusted caller.
- Admin port resolution is `CADRE_ADMIN_PORT ?? --admin-port` (env wins over flag), the inverse of the usual flag-over-env convention. Harmless but mildly surprising; left as documented behavior.
- `--authority` genesis is silently skipped when an authority key already exists but isn't *this* node's key (a different founder). Correct per spec, but a misconfigured node can run `--authority` without actually being an authority and no error is raised. Acceptable for the trust-circle model.
- No end-to-end admin-channel integration test (real node + admin server + HTTP client + live control DB). Deferred deliberately: a full e2e would exercise the broken delete leg above; the mint→accept-phone→list legs are worth an integration test once the Quereus delete bug is fixed. Tracked in the fix ticket's validation section and for 6.7/integration to pick up.
- `docs/architecture.md` was listed in the original `files:` but only `docs/cadre-host.md` needed the node-admin-channel note (added); 6.7 finalizes the host-facing doc and topology reconciliation.
