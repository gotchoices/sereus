# Complete: phone reference app "Add a device or app" (the owner side)

Settings → **Add a device or app** (`src/add-device-section.tsx`), shown while connected. An owner pastes or scans another app's join request, approves it in a prompt that names the app and its shortened peer id with an **Also an owner** switch, and gets an invitation only that app can redeem; or makes an open invitation (with the 15-minute bearer warning when it grants ownership). The invitation shows through `ShareCode` (`src/share-code.tsx`: QR code drawn with `react-native-svg` from `qrcode`'s encoder, Copy via `expo-clipboard`, selectable text), with its expiry and a line per `reach`. Outstanding invitations are listed (live ones, latest expiry first) and can be withdrawn. A non-owner sees one line. `node-code-scanner.tsx` became the general `CodeScanner` (`accepts`, `hint`, `otherCodeHint`), used by both sections. `use-cadre.ts` gained `isMemberPeer`, `createCadreInvitation`, `listCadreInvitations`, `withdrawCadreInvitation`; `@serfab/cadre-core` now exports `parseNullableStoredDatetimeMs`. User-facing behaviour: docs/reference-app-rn.md → "Adding a Device or App".

Deviation kept: while an invitation is shown it replaces the two inputs until Done (so the result appears where the user was looking for either flow), rather than sitting between the inputs and the list.

## Review findings

**Checked, no change needed**
- Core contracts the section relies on: `CadreInviteStatus.live` already folds in withdrawn / expired / used up / issuer no longer an owner, so the `live` filter is the whole "outstanding" test; `queryCadrePeers()` drops revoked rows, so `isMemberPeer` does not refuse a removed device; `createCadreInvitation` picks the 15-minute default only for untargeted owner grants, which matches the warning text (taken from `OWNER_INVITATION_DEFAULT_TTL_MS`).
- `qrcode` subpath import: the package has no `exports` map and its `browser` field remaps only `lib/index.js`, so Metro resolves `qrcode/lib/core/qrcode` directly (the bundle test confirms). The encoder uses `TextEncoder`, which Hermes in RN 0.79 provides; no `Buffer` or `fs`.
- QR sizing: `SCREEN_PADDING = 32` matches Settings' `content: { padding: 16 }`; `Section` adds no horizontal padding.
- Double tap (`mintingRef`), withdraw of the on-screen invitation, `false` from withdraw (logged), copy-result timer cleanup on unmount: correct by reading.
- Rename of the scanner: no remaining references to `node-code-scanner` / `NodeCodeScanner` outside the archived handoff text.

**Found and fixed (minor)**
- A join request opened from another app (`linkedRequest`) while the owner standing was still being read, or could not be read, would set the pending request but never show the approval prompt, because the prompt renders only in the owner view. `handleRequest` now records the standing its own owner check reads (`setStanding`), so the prompt appears, and a device that has lost owner standing switches to the member line.
- The mint-failure line for a phone without a relay reservation said "no always-on machine of your cadre has one either", which the section never checks (the line is chosen on relay status, not on the error core threw, so a transient write failure would get it too). Reworded to state only what the relay status shows: "This phone has no relay address, so an invitation can be made only while an always-on machine of your cadre has one." A comment at the constant says why. The doc's description of that alert still holds.

**Considered, not changed**
