# `cadre service` (PR #42, kjeib)

External PR, stacked on PR #36, merged locally as `Merge PR #42: cadre-cli `cadre service` prints a unit that runs a cadre init node at boot`, with the follow-up `fix(cadre-cli): private temp dir for `cadre code --open`; POSIX log paths in launchd plists`.

## What landed

- `renderService(spec)`: systemd user unit (`WantedBy=default.target`), system unit (`User=`, `After/Wants=network-online.target`), or launchd plist (`org.sereus.<name>`, `RunAtLoad`, `KeepAlive`, logs in the node folder). All paths absolute; no environment needed since the claim secret is in `claim.secretFile`.
- `installSteps(kind, name, invocation)`: the install/start/follow commands, linger only for user units. Windows is refused with a pointer to NSSM.
- Options `--name`, `-c`, `--system`, `--health-port`, `--metrics-port`.
- `cadre init`'s closing hints and the README quick start mention `cadre service`; release notes carry a line.

## Review findings

Checked: the merge diff and follow-up commit, `service.ts` and its spec, the `init.ts` hint, `bin/cadre.ts` registration, `index.ts` exports, README section and quick start, `.release-notes.pending.md`, and `contrib/cadre-node.service`. Field-tested the rendered units against systemd 255 (Ubuntu in WSL): installed a system unit and a user unit whose node folder was `/opt/my 100% $node\x`, with a stub in place of `node` that records its working directory, account, argv and `NoNewPrivs`, then removed them.

Fixed in this pass:

- **Quoted `WorkingDirectory=` broke every node folder with a space in its path** (verified: systemd rejects `WorkingDirectory="/home/k/my node"` as "path is not absolute", a fatal unit error). `WorkingDirectory=` takes the rest of the line literally, so it is now written unquoted. The PR's spec asserted the broken output; that test now asserts the working form.
- **`%` and `$` in paths** (ticket focus): `%` is doubled in every systemd setting written (Description, User, WorkingDirectory, ExecStart) and `$` is doubled in ExecStart words. Verified the process receives the exact path. A control character (newline) in any value is refused, since it would let a path inject unit lines.
- **`--name` unvalidated** (ticket focus): now must match `^[A-Za-z0-9][A-Za-z0-9._-]*$` (no `@`, which would make a template unit), checked in both `renderService` and `installSteps` since both interpolate it into file names and shell commands.
- **`--health-port` / `--metrics-port` unvalidated**: arbitrary text reached ExecStart and the printed commands; now parsed as a port 1–65535 at option parse time.
- **Printed `-c` path wrong when run from elsewhere**: the steps say to run from the node folder but repeated the `-c` path relative to the original working directory. A non-default config is now printed as its absolute path, single-quoted for the shell when needed.
- **`os.userInfo()` called for every kind**: it throws for an account without a passwd entry (some containers); now only consulted for `--system`.
- **Hardening** (ticket focus): added `NoNewPrivileges=true` to both unit kinds (verified `NoNewPrivs: 1` in system and user units). Declined `ProtectSystem=`, `ProtectHome=` and `PrivateTmp=`: the node folder may be anywhere the account can write, and the field test showed `PrivateTmp=true` makes a node folder under `/tmp` fail to start (`status=200/CHDIR`); these also need namespaces a user manager may lack. The reason is a comment at the site and a sentence in the README.
- **Duplication with `contrib/cadre-node.service`** (ticket focus): the README already says when to use which; reworded to say the contrib unit is the sandboxed, dedicated-user layout and the generated one is not sandboxed.

Tests: replaced the space-quoting test with one covering space, `%`, `$` and backslash in a path; added one test for the refusals (bad names, newline in a path). No other tests added: the remaining paths are string assembly the field test covered.

Tripwires:

- `launchctl load -w` is the legacy launchctl form; `NOTE:` at the site in `installSteps` to switch to `bootstrap`/`enable` if macOS drops it.

Not done / not verified:

- The launchd plist is still not field-tested (no macOS available). Its values are XML-escaped and launchd takes `ProgramArguments` as a literal array, so no quoting issue applies.
- The `cadre service` command itself was not run on Linux (no Node in the WSL image); its rendering functions were, through the built `dist`.

Validation: `yarn lint` clean; `yarn workspace @serfab/cadre-cli typecheck` clean; cadre-cli tests 23 files, 285 passed, 1 skipped.
