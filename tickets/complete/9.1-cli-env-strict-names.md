# Strict `CADRE_*` environment variables for cadre-cli — complete

## Summary

Implemented in `ticket(implement): cli-env-strict-names`; reviewed with no code changes.

`packages/cadre-cli/src/config/env.ts` is now the one registry of every `CADRE_*` name the node process may see: config overrides (`ENV_MAPPINGS`, each `{ path, kind }` with an explicit parser kind), variables commands read themselves (`COMMAND_ENV`, read only through the typed `commandEnv`), launcher-only names (`CADRE_CONFIG`, `CADRE_CONFIG_FILE`, `CADRE_DEBUG`) and retired names (`CADRE_IDENTITY_PROTOBUF`). `checkEnvNames` runs first in `applyEnvironmentOverrides` and rejects every set, non-blank, unknown or retired `CADRE_*` name in one error with a "did you mean" suggestion; `CADRE_HOST_*` names are skipped. Booleans accept only `true`/`false`/`1`/`0`; numbers must be finite. Three new overrides: `CADRE_STORAGE_QUOTA`, `CADRE_LATENCY_HINT`, `CADRE_STRAND_WATCH_INTERVAL`. `nearestKey` moved to `config/nearest-key.ts` (shared by the config validator and the env check; avoids an import cycle between `schema.ts` and `env.ts`). README env table, `docker/env.example` and `docs/architecture.md` (seed delivery: `cadre start --seed`, not a `CADRE_SEED` variable) updated.
