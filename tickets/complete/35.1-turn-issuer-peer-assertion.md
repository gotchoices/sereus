## What landed

The **server half** of peer-bound TURN issuance in
`ops/docker/turn-credential-issuer/`. The client half (web + React Native signers
wired into `loadIceConfig`) is ticket `ice-config-peer-assertion-client` and has
**not** landed — until it does this code is dormant behind `PEER_AUTH_MODE=off`
(the default), and behaviour is byte-identical to before for every existing
deployment.

The issuer previously handed out coturn credentials to anyone who passed an
optional shared-token check and a per-IP rate limit, labelling every credential
with a fixed `CRED_ID`. It can now additionally require the caller to prove control
of a libp2p Ed25519 identity key, and label the credential with the **derived peer
id** instead — so coturn's logs attribute relayed bytes to the same peer id that
appears in relay logs.

### New module — `src/peer-assertion.ts` (345 lines)
Header parsing, the signed-message builder, verification, and the replay cache.

Wire format: five request headers on `GET /ice-servers.json` —
`X-Sereus-Peer-{Key,Aud,Ts,Nonce,Sig}` — carrying the base64url protobuf-encoded
Ed25519 public key, the audience the client signed, a unix-seconds timestamp, 32
lowercase hex chars of nonce, and a base64url signature. The signed message is five
LF-separated lines with no trailing newline:

```
sereus.turn-issuer.v1
<audience>
<peerId>
<issuedAtUnixSeconds>
<nonce>
```

The issuer **never trusts a client-supplied peer id** — it derives the id from the
presented key (`publicKey.toString()`, already the base58btc peer id) and rebuilds
the message with the derived value, so a mismatch fails the signature check.

### Reworked admission ladder — `src/main.ts`
`handleIceServers` was split into a pure, socket-free `decideIceServers` (plus
`decidePeerBound` / `admitVerifiedPeer`) returning `{status, body, headers}`, and a
thin HTTP wrapper — which is what makes the whole admission table testable.
Ordering change from the previous code: the **per-IP limit now runs before
signature verification**, so an unauthenticated flood cannot burn Ed25519
verification CPU. The shared bearer token stays first (constant-time compare).

New env knobs, all defaulted: `PEER_AUTH_MODE` (`off`|`optional`|`required`,
default `off`), `PEER_AUTH_AUDIENCE`, `PEER_AUTH_SKEW_SECONDS` (default 60, clamped
`[5, 300]`), `PEER_ALLOW_LIST`, `PEER_DENY_LIST`, `RATE_LIMIT_PER_PEER_PER_MIN`
(default 10), `REPLAY_CACHE_MAX` (default 50000).

Manifest gains `peerAuth` (`"off"` | `"none"` | `"verified"`) and, when verified,
`peerId`. Both informational; clients read only `iceServers`.

### Packaging
`@libp2p/crypto` is now a runtime dependency (plus type-only `@libp2p/interface`),
so the Dockerfile copies `node_modules` into the runtime stage. Every
"dependency-free / Node built-ins only" claim was corrected in `src/main.ts`,
`ops/docker/README.md`, and the issuer README.

### Admission table

| `PEER_AUTH_MODE` | no assertion | valid assertion | invalid assertion |
|---|---|---|---|
| `off` | token + IP limit, `peerAuth: "off"` | headers ignored | headers ignored |
| `optional` | token + IP limit, `peerAuth: "none"` | peer-labelled TURN, `peerAuth: "verified"` | 400 / 401 |
| `required` | `200` STUN-only, `peerAuth: "none"` | peer-labelled TURN, `peerAuth: "verified"` | 400 / 401 |

Plus: deny list → `403 peer_denied` (before the per-peer bucket is touched); allow
list miss → `200` STUN-only with `peerAuth: "verified"`; per-peer limit → `429` +
`Retry-After: 60`; full replay cache → `503`; the TURN gating matrix
(`shouldEmitTurn`) still overrides everything.

`required` deliberately serves a STUN-only `200` rather than `401` to an
assertion-less caller, because `loadIceConfig()` turns a non-OK response into `[]`,
which would strip STUN too.

### The pinned test vector (the cross-repo lock)
Verified against the installed `@libp2p/crypto` 5.1.13. The client ticket pins the
same values, so drift on either side fails a test rather than silently failing to
authenticate in production:

```
seed          = 32 bytes, every byte 0x01   (generateKeyPairFromSeed('Ed25519', seed))

publicKeyB64  = CAESIIqI4910CfGV_VLbLTy6XXLKZwm_HZQSG_N0iAG0D29c
audience      = https://issuer.example/ice-servers.json
issuedAt      = 1735689600
nonce         = 00112233445566778899aabbccddeeff
signatureB64  = 6jvguqhDOhK9ZahdAYb3aYnzz1dJaJBJtVCFcLCWMwCdupTUClWMJzXoS7yujjr7V3XA-htohz-VCl8GQQFcDg
```

With `CRED_TTL_SECONDS=300` the coturn username is
`1735689900:12D3KooWK99VoVxNE7XzyBwXEzW7xhK7Gpv85r9F3V3fyKSUKPH5` (63 chars) and,
with `TURN_SECRET=test-secret-do-not-use`, the credential is
`/5Zf2yVO7Zf/TsGiAGb48vQuB8I=`. Both self-tests assert the peer id survives
`mintTurnCredential`'s `[A-Za-z0-9._-]` sanitizer byte-for-byte.

## How to validate

Network-free (loopback only) and agent-runnable, from the repo root:

```bash
npm --prefix ops/docker/turn-credential-issuer install
npm --prefix ops/docker/turn-credential-issuer run selftest
node ops/test/check-turn-creds.mjs --self-test
```

Final run at review close: **38/38 pass** (issuer self-test, up from 33 —
see findings), **16/16 pass** (mirror test). The `selftest` script runs `tsc`
first, so it is also the type gate.

## Review findings

### Checked and clean — no change made

- **Cryptographic core.** Peer id derived from the presented key, never from the
  wire; message rebuilt with the derived id before verification; domain tag on line
  1; message encoding injective (audience is printable ASCII only, so no field can
  contain an LF); Ed25519-only key type; fixed 64-byte signature length check
  before the primitive sees the bytes; length caps enforced before any decode or
  log. Every one of these has a self-test case that inverts it.
- **Replay semantics.** The nonce is checked before the signature but recorded only
  after it verifies, so a forged assertion can neither burn a legitimate nonce nor
  pollute the cache. A full cache fails closed (`503`) instead of admitting an
  unrecorded nonce. The retention window (2× skew from record time) is *not*
  load-bearing, because the skew check runs first: an assertion old enough to have
  fallen out of retention is already outside `|now − issuedAt| ≤ skew`. No change.
- **Admission ordering.** Constant-time token → per-IP limit → parse → verify →
  deny → allow → per-peer limit. Deny genuinely precedes any per-peer limiter
  state, as claimed. The `shouldEmitTurn` matrix overrides every branch.
- **Resource cleanup.** Both rate-limiter maps and the replay cache are swept by one
  `unref`'d interval, cleared on `SIGTERM`/`SIGINT`; the server closes before exit.
- **Type safety.** No `any`; discriminated unions for both the parse and the verify
  outcome; `strict: true`; `tsc` gates on every `npm run selftest`.
- **Env/docs parity.** Every one of the seven new env vars appears in `readConfig`,
  `docker-compose.yml`, `env.example`, and the README, with matching defaults and
  clamps. Verified one by one.

### Fixed in this pass

- **The HTTP layer had no automated coverage at all** (the implementer flagged this
  as the top known gap; `handleRequest`, `handleIceServers`, and the `.catch` on the
  server callback were manual-smoke-only). Extracted `createIssuerServer(ctx)` from
  the body of `main()` — `main()` now calls it — and added five socket-level cases
  that boot the real handler on an ephemeral **loopback** port: routing +
  preflight + `405`/`404`/`/healthz`; the unsigned-`required` `200` with
  `Cache-Control: no-store`; a real signed request end-to-end plus its `401` replay;
  the bearer token via both the `Authorization` header and `?token=`; and a context
  whose clock throws, proving the `.catch` answers `500` and leaves the server
  serving rather than hanging the socket. 33 → 38 tests.
- **`PEER_AUTH_MODE=optional` makes both peer lists trivially bypassable, and
  nothing said so.** Under `optional` a denied node simply omits the five headers,
  takes the unsigned path, and still receives a `CRED_ID`-labelled TURN credential.
  `env.example` described `PEER_DENY_LIST` as "how you cut off one misbehaving
  node", which is only true under `required`. Added an explicit "`optional` is
  attribution, not access control" paragraph to the issuer README's admission
  section and a matching caveat on `PEER_DENY_LIST` in `env.example`.
- **Docs made stale by the change itself.** The issuer README's "Client wiring (the
  only client-side change)" section still implied an env var is all a client ever
  needs; its "Served surfaces" line described the `OPTIONS` preflight as being for
  "a future `Authorization`-header client"; and its Validate section advertised the
  self-test as "no socket", which the new cases make false. All three corrected.
- **`ops/docs/ice-servers.md` forward pointer named a slug that no longer exists** —
  `turn-relayed-path-metrics` is completed work (it is referenced as such in
  `packages/cadre-core/src/cadre-node.ts:446`); the open follow-up is
  `backlog/web-turn-relayed-path-detection`. Pre-existing line in a file this change
  edits; retargeted.

### Filed as arms on already-open tickets (site was claimed)

- **`tickets/implement/35.12-ice-config-peer-assertion-client`** — that ticket's
  client falls back to an unauthenticated retry on `401`/`403` only. `400`
  (malformed header set) and `503` (full replay cache) are equally
  assertion-path-only statuses, and `loadIceConfig` turns any of them into `[]`,
  stripping STUN as well — the exact outcome the server's `required`-mode `200`
  exists to avoid. Widened the retry list to `400`/`401`/`403`/`503` in that
  ticket's design and test list, with `429` explicitly excluded (the per-IP limit
  fires before the assertion is parsed, so an unsigned retry hits the same wall).
  Not a code change here: the client half has not been written yet.
- **`tickets/plan/37.1-debt-tooling-scripts-unlinted-and-unchecked`** — that ticket
  is rooted at the `ignores` block in `eslint.config.mjs` for `scripts/**`. The same
  block also ignores `ops/**`, so none of this ticket's 1,699 new/changed lines of
  TypeScript are linted (they *are* type-checked, by the service's own strict
  `tsconfig.json` via `npm run build` — just not from root `yarn typecheck`, because
  `ops/` sits outside the `workspaces` glob). Appended as a third arm with measured
  line counts rather than filed fresh, since it resolves at the identical site.

### Tripwires (parked, not ticketed)

- **The Docker runtime image ships devDependencies.** `COPY --from=build
  /app/node_modules` copies the whole tree, `typescript` and `@types/node`
  included, because the build stage runs a plain `npm install`. Nothing imports
  them at runtime. `NOTE:` at the site in the Dockerfile pointing at `npm prune
  --omit=dev` if image size or dependency surface ever matters — and noting
  `../libp2p-infra` has the identical shape and should be fixed with it.
- Verified the three `NOTE:` tripwires the implement stage left are accurate and
  still at their sites: log volume per rejected assertion (`decidePeerBound`),
  linear allow/deny-list scan (`admitVerifiedPeer`), and the missing lock file
  (Dockerfile).

### Considered and deliberately not actioned

- **`src/main.ts` is now 700 lines** (`wc -l`), up from ~356. Not split: the file is
  cleanly sectioned by banner comment (env parsing, minting, manifest, rate limiter,
  HTTP helpers, admission ladder, boot), every function in it is short and
  single-purpose, and the one part that needed to be independently testable — the
  admission ladder — already is, via `decideIceServers`. Recorded so the measurement
  is on the record rather than silently skipped.
- **`Number.isSafeInteger(issuedAtSec)` in `parsePeerAssertion` is unreachable.**
  `MAX_TIMESTAMP_CHARS = 12` bounds the parse at 10¹² − 1, well under 2⁵³. Left as
  defence-in-depth against a future cap change; harmless.
- **Per-process replay cache and rate limiters.** Two replicas each admit a given
  replayed assertion once. Bounded by the per-peer limit and coturn's quotas, and
  already written up in the README next to the pre-existing per-process rate-limit
  caveat. A deliberate trade against needing shared state in an ops service this
  small — not a defect.
- **The three deviations the implementer flagged for a second opinion** — the fifth
  `overloaded` outcome arm, recording the nonce after verification rather than at
  the check, and treating a CR/LF `PEER_AUTH_AUDIENCE` as a fatal boot error — all
  reviewed and all correct as built. Each has a self-test case pinning it.

### Still untested, and unchanged by this review

- **The Docker image has never been built.** No Docker in this environment. The new
  `COPY --from=build /app/node_modules` line and the runtime dependency are untested
  *in the image*. This wants a `docker build ops/docker/turn-credential-issuer` from
  a human or CI; there is nothing further an agent can do about it here.
- **The verified path has never run against a real client signer**, because the
  client half has not landed. The pinned vector is the guard against that gap
  (client and server pin the same bytes), but it is a guard, not a substitute.
