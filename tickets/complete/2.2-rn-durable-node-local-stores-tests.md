# Tests for the React Native reference app's node-local durable stores

Two records the phone keeps locally and never replicates — the **trusted-owner
anchor** (which owner keys this device believes speak for its party) and the
**cold-start bootstrap peers** (the addresses a stranded node re-dials to get
back into its party) — got durable storage in `2.2-rn-durable-node-local-stores`.
This ticket added the tests, then a review pass hardened one teardown path and
swept the docs.

## What is where

- `packages/reference-app-rn/src/node-local-slots.ts` — the phone's two
  `DurableSlot` backends. The anchor goes to the platform secure enclave
  (`expo-secure-store`, under its own `sereus.anchor.` key prefix, deliberately
  outside the key store's `sereus.ks.` namespace), because it is trust-bearing.
  The dial hints go to an app-private LevelDB database (`sereus-node-local`),
  because they grant no authority and a growing multiaddr snapshot would cross
  SecureStore's ~2048-byte value limit. Unchanged by this ticket.
- `packages/reference-app-rn/test/node-local-slots.spec.ts` — 28 tests: each slot
  (round trip, absent key, read-fails-rejects, write-fails-rejects, exact option
  forwarding, gated-slot construction refusal), the key-shape helpers as
  persistence contracts, each slot composed with the real cadre-core store it
  backs, and the anchor coexisting with `SecureStoreKeyStore` in one secure store.
- `packages/reference-app-rn/test/fake-secure-store.ts` — the one in-memory
  `expo-secure-store` double, shared with `secure-key-store.spec.ts`.

Node-local *store policy* (corrupt JSON, foreign party, discard-all vs
drop-entry, envelope versioning) stays covered once in
`packages/cadre-core/test/node-local-snapshot.spec.ts` and is not re-asserted per
platform — same boundary the web sibling `2.1-web-durable-node-local-stores-tests`
drew.

## Known limits (unchanged by this ticket)

- **Survival across an app relaunch is still not observable on device.** Both
  records are party-scoped and the app does not persist its party id — it is
  typed into Settings each launch — so a fresh id loads both slots empty every
  time. Backlog ticket `feat-rn-persist-node-start-options` closes that. The
  storage is correct; the end-to-end case is not yet demonstrable.
- **Nothing ran on a device or under the Expo e2e harness.** Coverage is
  unit-level against fakes, same as the web sibling.
- **`startPhoneNode` / `stopPhoneNode` wiring and the `sereus-node-local` LevelDB
  handle lifetime are not unit-covered** — `cadre-phone.ts` imports the native
  `expo-secure-store` and `rn-leveldb`, so it cannot load in a Node vitest graph.
  Recorded in `docs/STATUS.md`, matching how web's equivalent gap
  (`startCadre`'s wiring) is tracked rather than ticketed.

## Review findings

**Checked:** the implement diff read before the handoff summary; both production
files (`node-local-slots.ts`, the `cadre-phone.ts` and `secure-key-store.ts`
halves from the prior commit, which no separate review ticket covered); the new
spec against the web sibling spec for silent divergence; the real
`LevelDBKVStore` in `../optimystic` to confirm the `KvStoreApi` seam's
absent-key and read-fault semantics actually match what the slot's doc comment
claims; every doc mentioning these records or the phone's storage; lint,
typecheck, and the full RN suite.

**Fixed in this pass (minor):**

- `packages/reference-app-rn/src/cadre-phone.ts` — `stopPhoneNode` closed the
  node-local LevelDB handle in a `finally` but only cleared the module-level
  `node` reference *after* a successful `await node.stop()`. A throwing stop
  therefore left a reachable node whose bootstrap-peer store pointed at a
  just-closed native handle, and `startPhoneNode`'s `node?.isRunning`
  early-return would hand that node straight back. `node` is now cleared before
  the stop, for the same reason `nodeLocalDb` already was.
- Two near-identical `FakeSecureStore` doubles (one per spec) collapsed into
  `test/fake-secure-store.ts`, supporting both the per-key `throwOnGet` the key
  store spec needs and the blanket `getError`/`setError` the slot spec needs.
- Coverage gaps closed: the anchor slot beside `SecureStoreKeyStore` in one
  secure store (the spec asserted only that the two key *prefixes* differ, never
  that the key store's `__index` stays clean or that neither write clobbers the
  other — the actual reason the separate prefix exists, and the analogue of the
  web spec's "both records side by side in one database" test, which the RN spec
  had dropped); distinct party ids ⇒ distinct keys for both helpers; a slot given
  no options forwards `{}` rather than fields explicitly set to `undefined`.
- `docs/architecture.md` — the node-local persistence paragraph still carried
  "⚠️ **Still ephemeral on React Native and in the browser**, which inject no
  slot". Both platforms have shipped slots; only NativeScript is ephemeral now.
  Replaced with what each platform actually injects, plus the party-id caveat.
- `docs/reference-app-rn.md` — "Peer Identity Persistence" described the identity
  key as living in MMKV with secure storage as "a future hardening step", which
  has been wrong since `SecureStoreKeyStore` landed. Rewritten as "Node-Local
  Persistence" covering all three local records and why each sits where it does.
  The `src/` file listing (also stale, missing nine modules) was refreshed.
- `docs/STATUS.md` — Testing section recorded the web spec but not the RN one;
  added, with its scope boundary and what stays uncovered.

**Filed as a new ticket (major):**

- `tickets/backlog/debt-rn-docs-mmkv-is-gone.md` — `react-native-mmkv` is not a
  dependency of the app any more (LevelDB replaced it), yet seven doc sites
  across `docs/reference-app-rn.md` and `docs/architecture.md` still describe
  MMKV-backed storage, including native-rebuild guidance that names the wrong
  dependency. This is a staleness cluster left by an earlier storage change, not
  by this diff, and spans a diagram, two tables, and a build workflow — too broad
  to sweep inside a test-coverage review.

**Tripwires (recorded in code, not ticketed):** none added — the two conditional
concerns worth knowing were already parked at their sites by the implementer and
were verified to still read correctly: the ~2048-byte SecureStore value limit and
its "move the anchor to LevelDB rather than trimming the record" remedy
(`node-local-slots.ts`, on `secureStoreSlot`'s `save`), and the `??=` LevelDB-open
rationale for a push-wake resume that skipped `stopPhoneNode`
(`cadre-phone.ts`, in `startPhoneNode`).

**Deliberately not changed:** the hardcoded Ed25519 peer-id fixture stays a
literal rather than a `@libp2p/crypto` devDependency — the store's loader parses
every key on reload, so an invalid literal fails loudly, and the constant keeps
the test deterministic. `packages/reference-app-web/src/lib/node-local-slots.ts`
references a ticket slug with its sequence prefix (`2.1-web-…`) where the
convention is bare slugs; cosmetic, in another package's file, left alone.
