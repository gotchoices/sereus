# Donor-aware cadre-host local UI

cadre-host runs as a **donor** (default: only runs nodes for other people's cadres) or a **founder** (`ownCadre.enabled`: also runs the host's own cadre, trust circle, NAT and strands). The server already left the founder routes unmounted for donors; the Svelte dashboard now knows the role too.

## What landed (`ticket(implement): feat-cadre-host-donor-aware-ui`)

- **Server.** `LocalUiServerOptions.founder?: FounderServices` (trust circle + NAT + strands, all or none) replaces three separate optional services, so the reported role cannot disagree with what is mounted. `GET /api/status` carries `role: 'founder' | 'donor'` and `owner: true` on the owner node's summary. `bin/host.ts` builds `founder` in its own-cadre branch. `FounderServices` and `HostRole` are exported.
- **SPA.** `state.role` is `null` until the first successful status fetch. `deriveOverallStatus` (now `ui/src/lib/overall-status.ts`) ignores connectivity for donors, so the header dot no longer sticks at "loading". Founder nav items, Home tiles (Connectivity, Trust circle) and pages are shown only for founders; a donor deep link to a founder page shows a "turned off on this machine" card without mounting the page. Donors get a Donation tile. The founder-only boot fetches run from an `$effect` on `app.role`, so they happen whichever status fetch first resolves the role.
- **Node detail.** Owner node + founder → Start/Restart/Stop; owner node + donor → a muted "your own cadre is turned off" line; donated node (either role) → **Terminate** behind a confirm dialog, calling `DELETE /grants-admin/donations/:id`.
- Call sites (server tests, integration harness, bootstrap scenario) pass `founder`; server tests share `src/server/__tests__/fakes.ts`.

**Checked, nothing to change**

- Donation id vs node id: `DonationService.provision` spawns with `containerId: id`, so the node id the page holds is the donation id `DELETE /grants-admin/donations/:id` expects. "Frees one node slot" in the confirm text matches `terminate` (the record goes `terminated`, which the live-node count excludes).
- The `$effect` in `App.svelte`: it depends only on `app.role` (the refresh calls are in `untrack`), the refreshes write `trustCircle` / `connectivity`, never `role`, and Svelte skips same-value writes, so it fires once per null→founder transition and cannot loop.
- `/api/nodes/:id` returns the full `ManagedNodeInfo`, which carries `owner`, so the node-detail gating does not depend on the status-summary projection.
- No other SPA code reaches a founder route in the donor role: Settings uses `/api/settings` and `/update/*`; the `trust-circle-changed` / `connectivity-changed` / `strands-changed` events that trigger founder fetches are published only when `founder` is wired.
- Server gating: `/auth/*`, `/nat/*`, `/api/strands`, the settings `nat` hook and the boot connectivity publish all key off the single `founder` value. `createLocalUiServer` has no callers besides those migrated (grep). Shutdown uses `founder?.nat.stop()`.
- Tests: `overall-status.test.ts` (four cases, one per branch, one reproducing the stuck-loading bug) and the smoke test's role assertions pay for themselves. The `status-route.test.ts` role assertions only echo the option back; kept because they ride on existing tests at no extra cost.
