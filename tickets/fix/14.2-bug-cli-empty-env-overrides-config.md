# Empty environment variables override configured values

## What happens

`packages/cadre-cli/src/config/loader.ts` applies an environment override whenever the variable is
**defined**:

```ts
const value = process.env[envVar];
if (value === undefined) continue;
setNestedValue(result, configPath, parseEnvValue(envVar, value));
```

An empty string is defined, so `FOO=` overrides the config file with whatever `parseEnvValue('')`
produces. For the boolean vars that is `false`:

```ts
if (envVar.includes('_ENABLED') || envVar.includes('_RELAY')) {
  return value.toLowerCase() === 'true' || value === '1';   // '' -> false
}
```

## Why it matters today

The shipped Docker stack passes every optional variable through with an empty default:

```yaml
- CADRE_PROFILE=${CADRE_PROFILE:-storage}
- CADRE_ENABLE_RELAY=${CADRE_ENABLE_RELAY:-}
```

so a container that the operator never configured gets `network.enableRelay = false`. The storage
profile is supposed to default that to **true**, and `enableRelay` is what makes `db-p2p` install
the circuit-relay **server** (`circuitRelayServer(...)` in `libp2p-node-base.ts`). Net effect: the
one node profile meant to relay for other peers never does, and nothing says so — the config file
written by `entrypoint.sh` does not even contain the key, because the entrypoint correctly skips
empty values. Only the env pass, running afterwards, reintroduces it.

Notice this is the *opposite* failure from the one relay reservation had: there a set value was
ignored; here an unset value is invented.

## Expected behavior

A variable that is present but empty should mean "not specified" — the config file value (or the
profile default) stands. Deliberately setting a boolean to false should require writing `false`.

An empty *list* variable (`CADRE_LISTEN_ADDRS=`) currently resolves to `[]`, which is not harmless
either: an empty `listenAddrs` is a meaningful setting (it means "do not listen"), so the same
"empty means unspecified" rule should apply rather than handing the node an explicit empty list.

## Scope

- Every variable in `ENV_MAPPINGS` (`packages/cadre-cli/src/config/types.ts`), not only the boolean
  ones — the rule belongs in the override loop, not in each parser branch.
- Confirm the Docker path end to end: a container run with no operator variables set must come up
  with the storage profile's relay server enabled.
- Check whether `cadre-host` / `cadre-provider`, which spawn the CLI as a child process, pass
  empty-valued variables of their own (`tickets/plan/22-debt-host-child-env-inheritance.md` covers
  a related inheritance question).

## How it was found

Review of `14-cadre-relay-addrs-wiring`, while confirming that `network.enableRelay` and the newly
live `network.relayAddrs` do not interfere with each other. They do not — this is an independent,
pre-existing defect in the CLI's environment layer.
