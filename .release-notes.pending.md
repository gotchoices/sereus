# Release notes — pending

## Requires Optimystic 1.26.0 and Quereus 5.0.0

Every `@optimystic/*` range is now `^1.26.0` and every `@quereus/quereus` range `^5.0.0`. The Optimystic plugin's transaction engine id is now `quereus@5.0.0`. A machine that re-checks transactions refuses an engine id it does not know, so a deployment that re-checks must run the same Quereus version on every machine. Sereus does not configure re-checking itself.

Quereus 5.0.0's `@quereus/sync` wire change does not reach Sereus, which does not use that package.

**NativeScript:** `@optimystic/db-p2p-storage-ns` 1.26.0 requires `@nativescript-community/sqlite` `^4.1.0`, and `reference-app-ns` now declares it. On iOS, 4.x resolves a bare database name in the documents folder where 3.x used the working directory. The reference app opens its databases by full path (`nsDbPath`), so its stores stay where they were; an app that opened by bare name under 3.x should switch to a full path or move the file first.

## What changes for an app's own SQL

These come from Quereus 5.0.0 and Optimystic 1.26.0 and reach a strand app's `App` schema and queries directly. Read both projects' 5.0.0 / 1.26.0 notes for the full list.

- **A subquery that selects an outer column now reads each outer row**, in queries and in CHECKs. Such queries return different results, which were wrong before; a CHECK written that way now checks every row of a multi-row write.
- **`db.close()` stops running statements and waits for them.** Code running inside a statement, such as a `db.watch` handler, must call `void db.close()` and not await it.
- **An async `db.watch` handler no longer holds up the commit.** It can query the same database, and handlers can overlap; one that needs its events in order must queue them.
- **A `delete` on an Optimystic table now reports its row.** `on delete cascade` and `set null` now take effect, and `returning` and change events report the deleted row. Check any foreign key in an `App` schema that was declared but never seen enforced.
- **`=` and `in` on a case-insensitive, `timespan`, `boolean` or `any` column now scan with a filter**, because a seek on those could miss matching rows. Such queries may return more rows than before and read more of the table.
- **Secondary indexes serve `order by`, ranges and `in` lists** on columns whose stored bytes order as their values do (TEXT, binary collation). A `limit` over an indexed `order by` stops early.

## `full` Noise crypto mode starts on React Native (gotchoices/sereus#58)

`buildNoiseCrypto('full')` failed every node start with `x25519 keypair did not come back as DER buffers`, because `react-native-quick-crypto` 1.1.7 returns the generated key pair as `ArrayBuffer`s. The adapter now accepts either shape. `'symmetric'` remains the default; `'full'` has still not been run end to end on a phone by this project.

A phone that restarts from its saved start keeps the Noise mode it first started with, even after `noiseCrypto.defaultMode` changes in a new build. Only a start that passes `noiseCryptoMode` changes it (cadre-rn README).

## An app schema that can never apply no longer relaunches the strand forever (gotchoices/sereus#57)

When an app's new schema could never apply to the tables a strand holds, such as a `not null` column with no default added to a table with rows, a cadre node relaunched the strand on its retry ladder for the life of the process, each attempt a full start-up. Such a refusal now fails with `AppSchemaRefusedError` (exported by `@serfab/quereus-plugin-sereus` and `@serfab/cadre-core`, with `appSchemaRefusalOf(error)`), emits one `strand:error`, and stops the automatic relaunches until the app calls `addStrand` again. A storage or network fault during the apply is not typed this way and is still retried.
