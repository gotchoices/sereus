# Release notes — pending

## App schemas: `seed` items are now an error

An sApp schema containing a `seed` item now fails to connect (and `attachAppSchema` throws), naming the tables the seeds were for. Seed items never inserted rows into a strand — they were silently ignored — so no stored data changes. Remove them, and insert the rows your app needs at birth from the app when it founds the strand.

## Strand nodes keep their routing table across a restart; the strand peer book is removed

Each strand node now saves its network state (its routing table, with every peer's signed address record) and loads it again when it restarts, so a restarted machine reaches the other members of each strand without a fresh invitation. The routing table also carries a member's new address, and members a node has never met, between strand nodes. That was the strand peer book's job, so the book is removed.

Removed from `@serfab/cadre-core`: `CadreNodeConfig.strandPeers`, `CadreNode.getStrandPeerBookStore()`, the strand peer book stores (`MemoryStrandPeerBookStore`, `PersistentStrandPeerBookStore`, and `FileStrandPeerBookStore` with its subpath `@serfab/cadre-core/strand-peer-book-file`), and the `/sereus/strand-peers/1.0.0` protocol with everything exported for it (`StrandPeerBookSwap`, `StrandPeerBookService`, `StrandPeerObserver`, `dialableAddrs`, `connectedIdentifiedPeers` and their types).

Embedders: where you passed `strandPeers.store`, pass a durable store as `CadreNodeConfig.strandNetworkState.store` instead. Use `PersistentStrandNetworkStateStore.open(slot, partyId)` over any `DurableSlot`, or on Node `FileStrandNetworkStateStore.open(dir, partyId)` from `@serfab/cadre-core/strand-network-state-file`. Without one the state is held in memory and lost when the process exits. `cadre-cli start` does this itself (and so does every `cadre-host` node), writing `strand-network.<party>.json` in the node's state directory.

Old strand peer book data is no longer read and can be deleted: the `strand-peers.<party>` slot an app kept, and `strand-peers.<party>.json` in a CLI node's state directory.

The addresses an invitation hands over are now kept in memory until the strand first runs. Launch a strand in the same session that forms it, as the reference apps do; a strand formed and then first launched after a restart has no address for the other party and must be re-formed.

There is no compatibility with a node still running the `/sereus/strand-peers/1.0.0` swap: it logs that this node does not speak the protocol and skips the swap. The two still connect and replicate.

A node that restarts while every other member of a strand is offline now remembers them, so its first writes to that strand can fail for a few seconds (`Failed to get super-majority`) until it finds them unreachable. Retry the write.

The `@optimystic/*` dependency floors are now `^1.8.1`, the first release whose routing table carries address records.
