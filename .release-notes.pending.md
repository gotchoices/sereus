# Release notes — pending

## Fixes

- **A restarted machine now remembers the other parties' strand addresses and dials them first** (part of gotchoices/sereus#18). Each node keeps a per-strand **strand peer book** in its own storage: the peers a formation carried back, and every strand peer it connects to, with their last-known addresses. On every launch, hibernation resume and periodic address refresh the book seeds the strand before anything else, so two relay-only parties that both restart re-mesh with no fresh invitation. Entries age out after 14 days and are forgotten when a strand is unpublished, left, or the party is removed. Embedders inject a durable backend as `strandPeers: { store }` — `FileStrandPeerBookStore.open(dir, partyId)` from `@serfab/cadre-core/strand-peer-book-file` on Node, or `PersistentStrandPeerBookStore.open(slot, partyId)` over any `DurableSlot`; `cadre-cli start` and every reference app already do. Without one the book is in-memory and dies with the process, which is exactly the old behaviour. An entry is refreshed by the signed book swap below whenever two members connect.
- **Members of a shared workspace now tell each other where everyone is** (part of gotchoices/sereus#18). Whenever two machines on a strand connect, each sends the other its own current strand addresses, signed with its own strand transport key, plus the freshest signed entry it holds for every other member, and keeps whichever is newer by the signer's clock (`/sereus/strand-peers/1.0.0`, on the strand node). So a machine whose relay reservation or address changes re-signs and pushes its new entry to every peer it is connected to, and a machine that joined later learns the members it has never met from whoever has. Only self-signed entries travel and every receiver verifies them against the peer id, so no member can plant another member's address; the exchange runs on open and closed strands alike and passes a closed strand's revocation gate first. One exchange per peer per ten minutes, unthrottled after an address change. Nothing to configure: it rides the same `strandPeers.store` as the address book. What is still not covered: a member whose address changed while it was connected to nobody, and that nobody else holds a fresher entry for, is unreachable until it dials someone.
- **A strand joined from another party now comes back after a restart without the app keeping its own list** (part of gotchoices/sereus#18). `formStrand`, and an `addStrand` of a strand this party's control database has no row for, record the join — strand id, type and, for a closed strand, its read secret — in the node's `keyStore`, and every later start offers it again as `strand:discovered`, the way the party's own strands come back. `forgetJoinedStrand(strandId)` is the new way to leave such a strand; a party removed from the strand stops re-attaching it after its next restart. A node configured with `privateKey` and no `keyStore` only remembers joins until it stops, and warns once; pass `joinedStrands: { store: new KeyStoreJoinedStrandStore(<a durable KeyStore>, partyId) }` to keep them. The reference React Native app now also re-attaches closed strands on restart — joined ones and its own. Still missing: the addresses of the other party's machines are not kept yet, so a re-attached join starts without them until that lands.
- **The peer-join block catch-up no longer targets a relay** (gotchoices/sereus#18). It used to schedule a whole-store push to every connected peer, including a circuit relay or bootstrap node that cannot speak the strand's block-transfer protocol at all; the push always failed, and after three failures a `console.warn` named the relay as if it were a struggling strand peer. It now schedules only peers whose libp2p identify names the protocol, so a relay is never dialed and never produces that warning.
