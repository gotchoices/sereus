# Release notes — pending

## Upgrading

- **The control store migrates in place when a machine starts on a newer release** (gotchoices/sereus#46). A store written by 1.17.0 or later (control schema version 3 on) is upgraded by each machine when it starts on the new release, keeping every row. Machines still on the older release keep working, before and after a restart, and read the rows the updated machines write (a column they do not know reads as absent, and a row they update loses the values in such a column until the updated machine writes it again). `ControlStoreIncompatibleError` now carries a `reason`: `newer-release`, `before-migrations` (a store from 1.16.0 or earlier, recreated as before) or `not-migratable`.
- **A machine refused as `newer-release` should be updated, not recreated.** The store was migrated by a newer release and its rows are intact. 1.17.0's own check reports such a store as "created by a newer release" and advises recreating it; update the app or node instead.

## Breaking

- **Polling settings were renamed to backstops.** `strandFirstSync.pollIntervalMs` is now `backstopMs` (default 2 s) and `strandRevocationEnforcement.pollIntervalMs` is now `backstopMs` (default 5 min, plus `autoRefresh: false` to stop it scheduling its own re-reads); `controlCohort.reconcileMs` now defaults to 120 s. The exports `DEFAULT_STRAND_FIRST_SYNC_POLL_MS`, `DEFAULT_REVOCATION_POLL_INTERVAL_MS` and `PENDING_JOIN_POLL_MS` are replaced by `DEFAULT_STRAND_FIRST_SYNC_BACKSTOP_MS`, `DEFAULT_REVOCATION_BACKSTOP_MS` and `PENDING_JOIN_BACKSTOP_MS`.
- **Removed exports:** `strandHeaderHeld`, `appTablesReadable`, `strandFirstSyncComplete`, `RevocationRefreshScheduler`, `RevocationLedgerOpenResult` and `ControlDatabase.openRevocationLedger` (an owner no longer writes a placeholder row into the revocation list). `ControlDatabase.updateSelfPeerRecord` now takes a peer id and a signer and returns the record written.

## Fewer messages (gotchoices/sereus#50)

- **An idle machine no longer re-reads its control tables on a timer** (gotchoices/sereus#50). The strand watcher, the control reconcile pass, the pending-join runner and each closed strand's revocation check now run when a table they read changes, locally or replicated in, with a slow backstop (5 min, 2 min, 10 min and 5 min). An idle two-party strand's minute now sends no Optimystic or Sereus streams and reads no blocks, against 154 block reads and 18 `sync` streams on 2026-10-19. A removed strand member is also cut off when the membership change reaches the strand node, instead of at the next 30 s check.
- **An idle two-machine cadre sends no `sync` requests** (gotchoices/sereus#50). With Optimystic 1.17.0, idle `sync` streams went from 103 a minute to 0 in the owner-and-member case and from 134 to 0 after a device redeems a cadre invitation.
- **Membership, invitation and owner-grant rows are read from an in-memory copy that is dropped when the table changes** (gotchoices/sereus#50). The control database used to re-read these tables on almost every operation, and on a cadre of two or more machines each read could become a request to another machine; the copy is also reloaded after 15 s.
- **A new cadre creates every control table's storage at founding** (gotchoices/sereus#50). A read of a table nobody has written is then answered locally instead of asking the other machines to prove it absent, which also failed or waited while they were offline. Cadres founded before this release are not changed.
- **Founding a strand writes all its rows in one commit, and its control rows in one transaction under one owner approval** (gotchoices/sereus#50). The strand row, its membership key and an optional formation invitation are signed together (see `formationInvite` under Changed), and the new key is passed to the launch instead of read back.
- **Formation and invitation redemption read each row once** (gotchoices/sereus#50). The machine answering a strand formation reads the invitation and host strand once per answer, the machine answering a cadre invitation or owner grant reads it once instead of three times, and the joiner's launch reuses the join record and key it just wrote.
- **A machine joining by invitation writes its address record once** (gotchoices/sereus#50). It sends its signed record with its join request, the admitting member writes it, and the joiner no longer writes it again after joining or at its next boot.
- **The join catch-up sends each block to each peer once and starts on first contact** (gotchoices/sereus#50). It no longer pushes a block back to a peer that approved or already accepted that revision, and a machine on its first join waits for the push instead of fetching the same blocks one at a time; requests from the joiner while attaching went from 13 to 2. Optimystic's rebalancing is turned off on nodes where this catch-up runs, since on storage-profile nodes it re-sent the same blocks one request each.
- **A joining machine is no longer sent each block a second time, one request per block** (gotchoices/sereus#50, needs Optimystic 1.18.0). The join catch-up tells Optimystic which blocks the peer accepted (`reportBlockHeld`), so Optimystic's under-replication drain stops re-sending them a few seconds later. A strand join's settle window went from 82 to 31 Optimystic and Sereus streams, and an idle two-machine cadre's minute from 32 `block-transfer` streams to none.
- **A joining machine's first-sync check reads one row per table and re-checks when data arrives** (gotchoices/sereus#50). It remembers which tables it has confirmed and probes when a block lands in the strand's store, with a 2 s backstop, instead of re-reading every table every 500 ms.

## Fixes

- **A machine joining a strand reads every membership table before it may write.** The first-sync gate checked only the strand header and app tables, so the membership rows a joiner wrote right after joining could start a second copy of a membership table that never merges with the founder's. `DEFAULT_STRAND_FIRST_SYNC_TIMEOUT_MS` rises from 300 s to 360 s to cover the extra reads, so a strand that never becomes writable rejects `addStrand` with `StrandAwaitingFirstSyncError` a minute later.
- **A restarted machine writes as connected only once a sibling has identified as serving the cadre's control network.** Between a connection opening and that identify, a write committed on this machine alone; a restarted owner's re-touch of its own record in that window split the membership table, and the owner did not see machines admitted while it was down.
- **A membership write refused by a concurrent change to the same row is re-run.** Two writers of one `CadrePeer` row refuse each other routinely while a cadre starts, and a machine's own address record or an owner's re-broadcast of a member was lost until a later pass redid it. The machine's self-publish, the owner's re-touch and machine removal now re-read the row and decide again.
- **A machine that drops off a network and reconnects is sent the blocks it missed.** The join catch-up runs again for a peer each time it reconnects and sends only blocks whose revision moved.
- **A node claimed by QR code restarts into the phone's cadre as soon as it acknowledges the claim** (`cadre-cli`, `cadre-host`, `cadre-provider`). It used to wait first on a dial to every machine the claim named, up to 86 s per unreachable one, and the restarted node now keeps those addresses so it can dial its owner at once. The phone redials the node every second for 15 s meanwhile, so a phone that cannot be dialed reconnects without waiting for its next scheduled retry.

## Changed

- **`ControlDatabase.watchTables` and `StrandDatabase.watchTables` subscribe to changes to named tables**, local or replicated, coalesced over 50 ms with one follow-up run for any changes during a run. `ControlDatabase.watchMembershipTables` and `invalidateMembershipViews` cover the membership tables the in-memory copy holds.
- **`FoundStrandConfig.formationInvite` publishes a formation invitation in the same transaction and approval as the strand row.** Mint the invitation first, then found with it; the reference apps do this, and `FoundingRows` and `FoundingInvite` are exported.
- **`strandWatchInterval` (and `CADRE_STRAND_WATCH_INTERVAL`) is now a backstop with default 300000 ms, not a 5000 ms poll.** A config that sets 5000 still re-reads every 5 s; remove it to get the new default.
- **`seed:applied` fires once the seed is acknowledged, before the seed's peers are dialed, and carries `dialTargets`.** An embedder that restarts on it no longer waits on dials; `seedDialTargets` is exported.
- **The admin `alone` field now reads `CadreNode.hasReachableControlSibling()`** (`cadre-cli`). A connection to a relay, a bootstrap node or a sibling still identifying no longer counts; `controlConnections` stays the raw connection count.
- **`@serfab/quereus-plugin-sereus` exports `createEmptyCollections`**, which commits empty storage for every Optimystic table of the named schemas; the strand plugin's `createEmptyCollections` takes an optional `except` list of tables the caller is about to write.

## Dependencies

- Every `@optimystic/*` dependency now requires ^1.18.0, which brings p2p-fret ^1.2.1, and `@quereus/quereus` requires ^4.20.3, which the Optimystic Quereus plugin now requires too.
  - **An embedder can tell a node that a peer already holds a block** (Optimystic 1.18.0, `node.reportBlockHeld`). Sereus's join catch-up uses it (see Fewer messages).
  - **A machine no peer can dial directly no longer attempts hole punching** (Optimystic 1.18.0). A node whose addresses include none another machine can dial (a phone with no listen addresses, or only relay or loopback ones) is built without libp2p's `dcutr`, which cost two relay-only peers about nine relayed streams per strand join.
  - **Joining a strand fetches each missing block once, not twice** (Optimystic 1.17.0, gotchoices/Optimystic#39). A machine reading a block it did not hold asked each group member for it, then asked again to store it; it now stores the copy the first request brought back. Opening a collection also reads its header and log tail once each. A joiner's attach in `message-cost-accounting` went from 25 requests to the other member to 13 with this change alone (Sereus's own join backfill takes it to 2).
  - **A read checks all its blocks with each group member in one request** (Optimystic 1.17.0, gotchoices/Optimystic#43). The member sends a block's contents only when it holds a newer revision, and a machine that stored a commit as a group member counts its copy as checked, so a read of those blocks in the next 10 s asks no one.
  - **An idle phone stops pinging peers that run no FRET** (p2p-fret 1.2.1, gotchoices/Fret#3). FRET kept probing the relay, and another party's control node after a formation, and every failed probe held its maintenance loop at its fastest rate. An idle two-party strand now sends 6 FRET pings a minute, none failing, instead of 32, 12 of them failing.
  - **Retries on a slow link wait before re-sending** (Optimystic 1.16.0, gotchoices/sereus#48). A write retried through another coordinator, a read's retry round, and a block re-checked after a group member was silent now wait one declared link round trip first (3.5 s on Sereus's default), doubling each time, so a retry no longer queues behind the request it replaces.
  - **A slow ping echo no longer drops the connection at 10 s** (Optimystic 1.16.0). Each node now gives the pings it answers twice its own connection monitor's deadline, 60 s on Sereus's default, instead of a fixed 10 s that cut off the pinging side's 30 s.
  - **A machine joining on the Node file store receives the collection headers in its join backfill** (Optimystic 1.16.0, gotchoices/Optimystic#41). The file store's block listing skipped every id containing `/`, so the joiner fetched those blocks one at a time instead.
  - **A commit on the Node file store waits for the disk once per write group** (Optimystic 1.16.0, gotchoices/Optimystic#37), through a write-ahead log in the store's directory, instead of once per file.
  - **Optimystic tables accept catalog-only column changes** (Optimystic 1.16.0, gotchoices/sereus#46): `add column` of a nullable column with no default, `drop column` of a column in no key or index, `drop constraint` of a `check`, and tag changes that now survive a restart. In-place control store upgrades build on these and are not in this release.
  - A write that spans several collections (a table and its index or `unique` trees, or several tables) still costs about 4 requests per collection. Optimystic 1.17.0 carries the groundwork for one request per member, which does not take effect yet.

## Known limitations

- **After a long-lived group member leaves, reads of blocks this machine does not hold can report `cohort-unreachable` for up to 5 minutes** (p2p-fret 1.2.0). Before FRET marks a peer it has seen up for 10 minutes or more as gone, it waits one twelfth of the time it saw that peer up, at most 5 minutes.
