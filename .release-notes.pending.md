# Release notes — pending

- **A slow phone is no longer disconnected while it syncs** (gotchoices/sereus#13). libp2p pings every connection and closes any connection whose ping isn't answered within 5 s. A phone busy with pure-JavaScript encryption misses that ping. Its connection is closed, it reconnects, and reconnecting costs more encryption work, so a slow enough phone never finishes. Every node a Cadre node builds (the control node and each strand node) now defaults to a 30 s ping deadline, checked every 35 s, through the new `NetworkConfig.connectionMonitor` (default `DEFAULT_CONNECTION_MONITOR`). The interval has to be longer than the deadline. libp2p allows only one ping at a time per connection, so a second ping sent while the first is unanswered fails and closes the connection. With the stock 10 s interval, a 30 s deadline would effectively be 10 s. A dead peer is now dropped 30–65 s after it stops answering, instead of about 5–15 s. Supplying your own value replaces the default entirely: pass `{}` for libp2p's stock behaviour. If you widen the deadline, set `pingInterval` above it. The reference relay container (`ops/docker/libp2p-infra`) uses the same values and must be redeployed for its side to take effect.
- **Behaviour change: invalid strand ids are refused.** A strand's id becomes its storage name (a folder, file or database name). Ids from other nodes were used as-is, so a malformed or hostile id could write outside the storage folder. A strand id must now be 1–128 characters of `A–Z a–z 0–9 . _ -`, not `.` or `..`, and not start with `control-`. A node that meets any other id emits one `strand:error` with `InvalidStrandIdError` and doesn't start that strand. Ids that cadre-core generates always pass. Check ids your app creates itself with `isValidStrandScopeKey`.
- **Fixed: a failed join no longer hides a discovered strand until restart.** If `addStrand` failed for a strand the node had offered (`strand:discovered`), for example on a dropped or slow connection, nothing offered that strand again for the rest of the session. The node now retries it on later polls with backoff, reporting `strand:error` for each failure and `strand:started` when it succeeds. A strand stopped with `stopStrand` is still never offered again.
- **Requires `@optimystic/*` 1.4.0.** Besides the `connectionMonitor` option above, 1.4.0 cuts relay traffic. A received block copy is no longer pushed back to the peer it came from, and rebalancing no longer fetches blocks a node already holds. After another party's commit, a write fetches the log tail once instead of twice, so the joiner's `/repo` requests per insert over a relay fell from 3–6 to 2–3.
