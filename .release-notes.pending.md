# Release notes — pending

## Upgrading: recreate every party

**A party's control database from an earlier release cannot be carried into this one.** This release adds a table to the control database and changes a check constraint on an existing one, and stored control data cannot be migrated to a changed constraint. A node started over an earlier release's control store fails with `Module for table 'Revocation' does not support ALTER TABLE DROP CONSTRAINT`. Before running this release, delete the control store on **every** machine of the party and form the party again: strands, owner keys, peers and invitations recorded in it do not survive. Strand stores are separate, but a strand the new party does not publish or join again is not started.

The control store's name also changed, so a node pointed at old storage starts with an empty control database. For `cadre-cli` file storage, including nodes started by `cadre-host` (`<workdir>/storage`), the old store is the `control-<party id in base64url>` folder inside `storage.path`; delete it. For browser (IndexedDB) and phone (LevelDB, SQLite) stores, clear the app's storage.

**Why the name changed.** Windows and macOS ignore letter case in file and folder names. cadre-core names each store it asks the embedder's storage for with a **scope key**: the strand id for a strand, and a key derived from the party id for the control database. Until this release two keys could differ only in case, so two parties (for example party ids `aa@` and `aaZ`), or two strands whose ids differed only in case, shared one folder. Every scope key is now lowercase letters, digits, `.`, `_` and `-`; the control store is `control-<party id in lowercase hexadecimal>`.

**Strand ids containing uppercase letters are now refused** (`InvalidStrandIdError`), when publishing a strand and when starting one. No strand id minted by Sereus contains one.

**File-backed key stores and per-party record files whose names contain capital letters moved.** On Node, `FileKeyStore` and the per-party files in the node-state directory (`trusted-owners.<party id>.json`, `bootstrap-peers.…`, `enrolled-machines.…`, `strand-peers.…`) now spell each capital letter as an escape (`A` → `%41`). Names built from ids with no capital letters are unchanged, including the node identity key (`cadre%2Fidentity.key`) and every lowercase party id such as a UUID, so a machine keeps its peer id. The old files are ignored and can be deleted. Records of strands joined from another party are keyed by that party's base64url id, so such strands must be joined again after upgrading.

**Configuration is now checked strictly.** See *Configuration: typos are errors* below: a config file or environment variable that an earlier release quietly ignored may now stop start-up.

## Slow links: cadre now tells Optimystic how slow the link is

cadre-core, and so every program built on it, now requires `@optimystic/*` 1.8.0 or later.

The link round trip a node declares with `network.linkRoundTripMs` (3500 ms when not set) is now also handed to Optimystic on the control node and every strand node, and Optimystic sizes its own network time limits from it: how long one of its requests may take to connect and to be answered, its block pushes, and libp2p's limits on opening a connection. Before this, Optimystic kept limits sized for a local network. On a relayed link near the 3-second round trip sereus supports, its requests could not open a connection at all, and every read that asked another machine for a block gave up after 3 seconds, before the other machine could answer. Measured at that link, those reads now complete. A machine rejoining a strand over the store it kept became writable at once in 3 of 3 runs, and read the rows written while it was away after about 36 seconds, where it previously took up to three minutes. A machine joining a strand for the first time became writable after about 64 seconds, as before. The cost is paid against a machine that does not answer: at the default declaration one of Optimystic's requests now waits up to 21 seconds to connect where it waited 3, and 10.5 seconds for a reply where it waited 10. A control write against a connected machine that never answers failed after 42.2 seconds in our test, where it took 40.2.

libp2p's two connection limits (`connectionManager.dialTimeout` and `inboundUpgradeTimeout`) are now 17.5 s at the default declaration, up from 16 s, because Optimystic sizes them. `connectionManagerTimeouts()` is no longer exported from `@serfab/cadre-core`. A value of `network.linkRoundTripMs` above about 1.66 days is now refused when the node starts.

## Joined strands are shared across the party's machines

A strand one of your machines joins from another party is now recorded in your party's control database once an owner machine of the party is connected, not only on the machine that joined it. Your always-on machine keeps a copy of it, and your other devices are offered it (`strand:discovered`) and can open it. `forgetJoinedStrand` now leaves the strand for the whole party: every machine stops it, and on a machine that is not an owner it throws when the join is recorded party-wide (`stopStrand` still stops it on one machine). The closed strand's read secret is now stored in the party's control database, which every machine of the party holds, under the same accepted risk as the party's own strands' read secrets.

## App schemas: unrecognised items are now an error

An sApp schema is a list of declarative items: `table`, `index`, `unique index`, `view`, `materialized view`, `seed` and `assertion`. Until this release, an item the parser did not recognise, such as one written `create table Note (…)` or with a misspelled keyword, was silently skipped, so the app ran without that table. Now starting a strand with such a schema fails with an error saying so. If your schema uses `create table …`, write `table …` instead.

## Configuration: typos are errors

`cadre-cli`'s config file and `CADRE_*` environment variables, the Sereus SQL plugin's configuration, and `cadre-provider`'s config file are now validated when read. An unknown key, a misspelled `CADRE_*` name or a value of the wrong type stops start-up with an error naming the setting and where it came from, instead of being ignored or replaced by a default. `cadre start --seed` also fails at start-up when the seed does not decode or names a party other than the config's `controlNetwork.partyId`. A stray field in the provider's push-credential block, which was previously passed through to every tenant's node, is now reported by the provider.

## Always-on machines keep a copy of their party's strands

A `storage`-profile node (every `cadre-cli` node by default, and so every node `cadre-host` runs) now hosts a storage replica of each strand that its party's control database lists and its strand filter admits, even when no app on that machine registered the strand (`CadreNodeConfig.hostUnclaimedStrands`, on by default for `storage`). It stores and serves the strand's blocks without running the app's schema. With the party-wide joined strands above, this includes strands your devices joined from other parties. So once a phone's writes have reached the always-on machine, losing the phone loses nothing. If an app later registers the strand on that machine, the replica becomes a full instance in place, over the same storage, without re-syncing. Phones (`transaction` profile) keep announcing unclaimed strands without hosting them.

## Relayed connections

- **A relay run by one of your own machines no longer cuts connections off** (gotchoices/sereus#19). Every party-run relay applied circuit-relay-v2's default limit of 128 KiB or 2 minutes per relayed connection, which broke syncs partway through. Party-run relays now default to unlimited, like the dedicated relay, and `network.relayServerInit` passes circuit-relay-v2 server options through to the control node and strand nodes. The resolved limit is logged at start. `UNAUTHORIZED_RESERVATION_TTL_MS` is no longer exported.
- **Late joiners learn a strand's addresses at once** (#21). The strand-address refresh is now throttled per sibling instead of per strand, so a sibling that connects after a pass is asked on the next tick, and one that failed to answer is retried after about a minute. The peer book is merged into libp2p's peer store every tick.
- **A failed answer is no longer read as "no addresses"** (#22). The strand-address response carries a status, and a responder that could not read its data, or was at its concurrency cap, answers "unavailable". This is a wire change; both sides need this release.
- **Protocol handler registration is awaited.** A handler that fails to register now fails `start()`, where it could raise an unhandled rejection and end a Node process. Calling `initializeStrandSolicitation` twice, or `initializeSeedBootstrap` over an existing seed service, now throws a duplicate-handler error.
- **A relay no longer dials a sibling through itself** (#20). Addresses that route through this node are skipped; when only such addresses remain the dial fails with `SelfRelayOnlyError`, logged quietly.
- **Deadlines follow the declared link.** Wake, strand-address, seed-delivery and formation dials, the cohort read deadline, and a party-run relay's reservation window are now sized from `network.linkRoundTripMs` instead of fixed milliseconds, so declaring a slow link fixes them too.

## Joining and waking strands

- A join that the owner's approval service refuses no longer leaves an unused invitation stored behind it.
- A join to a hibernating strand wakes the strand instead of being refused with "unavailable, retry".
- Waking a hibernating strand is coalesced (a wake during a check-in no longer builds a second runtime), a failed wake can be retried, a failed probe no longer shuts down a runtime another wake owns, and a woken strand gets its hibernation timers back so it goes to sleep again.

## cadre-cli

- **`cadre enroll add <peerId>`** asks the running owner node for a seed for a new machine and prints it, for `cadre start --seed` on that machine. A CLI operator can now grow a cadre past one node.

## cadre-host

- **Revoking a grant shuts down the nodes lent under it.** `cadre-host grant revoke <token>` now terminates every live donated node of that grant; `--keep-nodes` leaves them running. `cadre-host grant terminate <donation id>` shuts down one donated node. The Nodes page's Stop, Start and Restart refuse donated nodes and name the terminate command, instead of stopping a node the supervisor would restart.
- **Donor-only installs** no longer show the Trust Circle, Connectivity and Strands pages they do not have, and cannot restart a personal node the owner switched off. A new **Grants** page issues, lists and revokes grant tokens.

## cadre-provider

- The provider remembers which ports its running containers hold across a restart, instead of handing them out again.
- The provider's configuration check no longer prints push and payment secrets.

## Reference apps

- The React Native and NativeScript apps remember the party and server settings between launches, so a solo phone no longer founds a new party on every relaunch.
- In the chat apps, a message whose send failed and was abandoned no longer causes the same text sent later to be silently dropped.
- The NativeScript chat no longer shows the previous conversation's messages after switching.
- On the NativeScript app, the storage wrapper now lists stored blocks, so a peer that joins a strand is sent the blocks it is missing (peer-join backfill had been silently off there).
