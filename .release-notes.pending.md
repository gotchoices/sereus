# Release notes — pending

## A join can wait for an offline inviter

`CadreNode.requestJoin(invitation, disclosure)` asks to join and keeps trying in the background, across restarts and from any owner machine of the party, until the join works, the invitation is used up or expires (at most 30 days), or the app calls `dismissPendingJoin(id)`. It tries once at once and returns the status after that attempt; `listPendingJoins()` and the `pendingJoin:changed` event report the rest (`pending`, `trying`, `waiting`, `joined`, `failed`). The request lives in a new owner-signed `PendingJoin` control table, so it works only on an enrolled owner machine; `formStrand` remains the one-shot join with no retries. `formStrand`'s two "approved, then a local step failed" errors are now the exported `FormationPostApprovalError`.

## Joining a strand tries every address in the invitation

A join now tries every address the invitation carries, until one connects, instead of only the first. An inviter with reservations on two relays is reachable while either relay is up. All the addresses share the one formation dial budget, so a relay that does not answer at all holds the attempt until libp2p's per-address dial timeout (libp2p 3.3 and later) or the whole formation dial budget runs out, whichever comes first, before the next address is tried. When every address fails, the error now names each address's own failure.

## A failed join says whether to try again

When an inviter turns a join down, `formStrand` now throws `FormationRejectedError` with a fixed `code` (for example `'token-spent'` for an expired or used-up invitation) and a `retryable` flag, so an app can branch on `error.code` instead of matching the message. A join that got no answer at all (no address reachable, a deadline passed) throws `FormationUnreachableError`, which is always retryable. An inviter that does not know a token yet now answers `'token-unknown'` (retryable) rather than the same answer as an expired one. The message text is unchanged.

## Every node answers join requests from the moment it starts

`CadreNode.start()` now installs the strand-formation responder on every node, checking each token against the party's own `FormationInvite`/`FormationUsage` rows, so an always-on machine (cadre-cli, cadre-host, a donated node) can answer for an inviter whose phone is offline. Embedders no longer wire it: drop any `initializeStrandSolicitation({ formationUsageRecorder: new ControlFormationUsageRecorder(...) })` call made after start. `initializeStrandSolicitation(options)` is now only for customizing the responder (an approver, a provisioner, a recorder, deadlines), and it replaces the one start installed instead of failing on a duplicate handler.

A responder installed lazily by `createOpenInvitation` or `formStrand`, or by `initializeStrandSolicitation` without a recorder, now checks tokens against the control database instead of accepting every token. Code that minted a token with `createOpenInvitation` and redeemed it without `publishFormationInvite` must now publish it, or pass its own `formationUsageRecorder`.

## An invitation names the party's other machines

`createOpenInvitation` now lists, after this machine's own addresses, up to three other machines of the party (up to four addresses each), taken from their signed address records, connected machines first. `formStrand` tries each machine in turn, one formation session per machine: an unreachable machine or a retryable refusal moves on to the next, a final refusal stops at once. So a join succeeds through an always-on machine while the inviting phone is offline. When every machine fails, `formStrand` throws the last retryable `FormationRejectedError` if any machine answered, otherwise one `FormationUnreachableError` naming each machine's failure. `dialFormationByMachine` is the new low-level export that does this; `dialFormation` still dials one machine. Whoever holds an invitation therefore now learns the peer ids and addresses of those other machines too.

`createOpenInvitation` now throws only when neither this machine nor any sibling has an address. The React Native reference app keeps its own stricter check (this phone must be reachable, since it runs the strand it invites to). A bootstrap entry that does not end in `/p2p/<peerId>` is now ignored by the joiner; hand-built invitations must name the machine in every address.
