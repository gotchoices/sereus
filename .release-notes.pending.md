# Release notes — pending

## Dependencies

- Every `@optimystic/*` dependency now requires ^1.17.0, which brings p2p-fret ^1.2.1, and `@quereus/quereus` requires ^4.20.3, which the Optimystic Quereus plugin now requires too.
  - **Joining a strand fetches each missing block once, not twice** (Optimystic 1.17.0, gotchoices/Optimystic#39). A machine reading a block it did not hold asked each group member for it, then asked again to store it; it now stores the copy the first request brought back. Opening a collection also reads its header and log tail once each. A joiner's attach in `message-cost-accounting` went from 25 requests to the other member to 13 with this change alone (Sereus's own join backfill takes it to 2).
  - **A read checks all its blocks with each group member in one request** (Optimystic 1.17.0, gotchoices/Optimystic#43). The member sends a block's contents only when it holds a newer revision, and a machine that stored a commit as a group member counts its copy as checked, so a read of those blocks in the next 10 s asks no one.
  - **An idle phone stops pinging peers that run no FRET** (p2p-fret 1.2.1, gotchoices/Fret#3). FRET kept probing the relay, and another party's control node after a formation, and every failed probe held its maintenance loop at its fastest rate. An idle two-party strand now sends 6 FRET pings a minute, none failing, instead of 32, 12 of them failing.
  - **Retries on a slow link wait before re-sending** (Optimystic 1.16.0, gotchoices/sereus#48). A write retried through another coordinator, a read's retry round, and a block re-checked after a group member was silent now wait one declared link round trip first (3.5 s on Sereus's default), doubling each time, so a retry no longer queues behind the request it replaces.
  - **A slow ping echo no longer drops the connection at 10 s** (Optimystic 1.16.0). Each node now gives the pings it answers twice its own connection monitor's deadline, 60 s on Sereus's default, instead of a fixed 10 s that cut off the pinging side's 30 s.
  - **A machine joining on the Node file store receives the collection headers in its join backfill** (Optimystic 1.16.0, gotchoices/Optimystic#41). The file store's block listing skipped every id containing `/`, so the joiner fetched those blocks one at a time instead.
  - **A commit on the Node file store waits for the disk once per write group** (Optimystic 1.16.0, gotchoices/Optimystic#37), through a write-ahead log in the store's directory, instead of once per file.
  - **Optimystic tables accept catalog-only column changes** (Optimystic 1.16.0, gotchoices/sereus#46): `add column` of a nullable column with no default, `drop column` of a column in no key or index, `drop constraint` of a `check`, and tag changes that now survive a restart. In-place control store upgrades build on these and are not in this release.
  - A write that spans several collections (a table and its index or `unique` trees, or several tables) still costs about 4 requests per collection. Optimystic 1.17.0 carries the groundwork for one request per member, which does not take effect yet.

## Known limitations

- **After a long-lived group member leaves, reads of blocks this machine does not hold can report `cohort-unreachable` for up to 5 minutes** (p2p-fret 1.2.0). Before FRET marks a peer it has seen up for 10 minutes or more as gone, it waits one twelfth of the time it saw that peer up, at most 5 minutes.
