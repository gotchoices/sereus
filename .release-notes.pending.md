# Release notes — pending

## The relay answers STUN; coturn and TURN are gone

The relay image (`ops/docker/libp2p-infra`) now answers STUN Binding requests on UDP 3478, so one relay both carries relayed traffic and lets peers find their public address before upgrading to a direct WebRTC connection. `STUN_ENABLED=false` turns it off and `STUN_PORT` moves it; the relay stack publishes it as `HOST_STUN_PORT`. Open UDP 3478 on the relay host when you redeploy. It answers over IPv4 only.

The `coturn` and `turn-credential-issuer` stacks, their quickstarts and `ops/test/check-turn-creds.mjs` are removed, and so is the `/ice-servers.json` manifest. A WebRTC upgrade that fails stays on the circuit relay. That fallback needs an uncapped relay (`RELAY_APPLY_DEFAULT_LIMIT` unset or `false`, the default): a capped relay marks its connections limited, and Optimystic's database protocols do not run over them. See `ops/docs/ice-servers.md`.

## cadre-core derives STUN servers from the relays

`resolveStunServers(relayAddrs, override?)` returns one `stun:<host>:3478` server per distinct relay host, or the comma-separated `override` URLs when it names any. A `/dnsaddr/<name>` relay gives `<name>`, which must then resolve to the relay. `relayStunUrl`, `RELAY_STUN_PORT` and the `StunServer` type are exported with it. With no relay and no override the list is empty, and WebRTC upgrades use LAN candidates only.

Removed with TURN: the `'webrtc-turn'` connection transport (and its `byTransport` count in health output), `ConnectionLike.turnRelayed`, `classifyConnectionPath` (use `classifyTransport`), and `peerKeySigner` / `PeerKeySigner`, whose only use was signing the manifest request.

## Reference apps take STUN from their relays

Both reference apps now use `resolveStunServers` on the relays they reserve on, so every build with a relay has STUN; before, a build without a manifest URL had none. `VITE_ICE_CONFIG_URL`, the web app's `ice-config-url` `localStorage` entry and `EXPO_PUBLIC_ICE_CONFIG_URL` are gone. `VITE_STUN_URLS` and `EXPO_PUBLIC_STUN_URLS` replace the derived list, for a relay whose STUN is published on another host or port.

## The relay advertises an address clients can dial

Set `PUBLIC_HOST` to the name clients reach the relay at, and it advertises each TCP and WebSocket listener on that host, instead of the loopback and Docker bridge addresses it bound. The ports default to the relay stack's published `HOST_PORT` / `HOST_WS_PORT`; `PUBLIC_TCP_PORT` / `PUBLIC_WS_PORT` override them for a router port-forward. `ANNOUNCE_ADDRS` still takes precedence and still replaces the whole advertised set. With neither set the relay logs a warning. `svc up` no longer builds `ANNOUNCE_ADDRS` itself, and `svc dns` uses the public ports.

## The relay runs libp2p 3

The relay image moves from libp2p 2.9 to the 3.x generation the clients use (`libp2p` ^3.3.8, `@libp2p/circuit-relay-v2` ^4.2.4, `@libp2p/websockets` ^10.1.12, `@multiformats/multiaddr` ^13), and declares `@types/node`, without which a clean install did not build. No behaviour change was observed.
