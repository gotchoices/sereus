# Release notes — pending

## @serfab/cadre-rn: native block hashing with native Noise crypto

Loading `@serfab/cadre-rn/noise-crypto` now replaces the boot polyfill's JavaScript `crypto.subtle.digest` with react-native-quick-crypto's native SHA-256/512. Optimystic hashes every block through that digest; in pure JavaScript it took 47% of a phone app's JS time. An app that passes native Noise crypto needs no change. The new `@serfab/cadre-rn/native-digest` (`installNativeDigest(createHash)`, `nativeDigestActive()`) does the same for an app that does not. It replaces only the kit's own tagged fallback, after a known-vector check, so real WebCrypto and an app's own digest are left alone.

## @serfab/cadre-rn: native Ed25519 from boot

The new `@serfab/cadre-rn/polyfills/native-crypto`, imported right after `@serfab/cadre-rn/polyfills`, fills `crypto.subtle`'s Ed25519 methods (`generateKey`, `importKey`, `exportKey`, `sign`, `verify`) from react-native-quick-crypto, and installs the native digest at the same time. libp2p then signs and verifies natively instead of in `@noble/curves`: 0.72 ms per verify on a Galaxy S7 against 169 ms. It must load before any libp2p import, because @libp2p/crypto probes for WebCrypto Ed25519 once, when it loads. The logic is `@serfab/cadre-rn/native-ed25519` (`installNativeEd25519(nativeSubtle)`, `nativeEd25519Active()`); it leaves a complete WebCrypto alone.
