# Release notes — pending

## Breaking

- **The control schema changed, so parties created with 1.14 or earlier must be recreated.** Each `CadrePeer` row now carries the machine's node profile (`Profile`: `transaction` for an app, `storage` for an always-on node) inside its signed record. An existing control store fails its warm start. Upgrade every machine of a party together.
- **`signPeerRecord`'s `fields` now require `profile`** (`NodeProfile | null`), and `peerRecordSignedPayload` takes it as a fifth argument. The profile is part of the signed digest, so a record signed without it does not verify. (`signPeerRecord` already took `partyId` as its first argument since 1.14.0.)
- **`dialPeerAddrs` takes the expected peer id** as its second argument: `dialPeerAddrs(dialer, peerId, addrs, budget, label)`. Every address is bound to that peer, so the handshake checks who answered.
- **Cadre invitations now start with `sereus-invite:1.`** and `decodeCadreInvitation` refuses text without it. Invitations minted by 1.14 do not decode; mint them again. A cadre-host invitation node recorded by 1.14 no longer decodes either; remove it and add it again.
- **`@serfab/cadre-rn/phone-node`:**
  - `LevelDBNative` requires `destroy` (pass `(name) => LevelDB.destroyDB(name)`), which the kit uses to delete a cadre's data from the phone.
  - `PhoneNodeStatus` has two new states, `joining` and `removed`, and `OwnerGenesisResult` has a new value, `member`. An app that switches over these exhaustively needs the new cases.
- **cadre-provider refuses to start with `docker.network` set to `host`, `none` or `container:<id>`.** Docker ignores port bindings in those modes, so the provider could not reach any container.
- **cadre-provider containers take four host ports each** from `docker.portRange` (a WebSocket port was added). Widen a range sized for three.
- **Every `@optimystic/*` dependency now requires ^1.13.0** (see "Dependencies").

## An app joins an existing cadre

A phone or browser app that started with a cadre of its own can now join the user's main cadre, bring its strands along and delete the cadre it left.

- **Join requests.** An app that wants to join shows a short join request (`sereus-join-request:1.…`, `encodeCadreJoinRequest` / `decodeCadreJoinRequest`) as text or a QR code. The managing app mints an invitation for that request's peer id and hands it back.
- **Invitations fit in a QR code.** An invitation names at most 6 addresses, ranked for a phone. `createCadreInvitation` returns `reach` (`anywhere`, `local-network` or `issuer-only`), judged on the machines other than the one that minted it, so an app can warn when nothing in the cadre could answer the invitation while the minting app is closed. `cadre enroll invite --json` includes it.
- **Redemption can wait.** `redeemCadreInvitation(invitation, { waitForMember: true, signal, onProgress })` retries every 5 s, doubling to 60 s, until a member answers, the invitation expires or the caller aborts. `redeemInPasses` is the underlying loop.
- **A joined device is an owner only if the cadre says so.** `CadreNode.wireOwnKeyIfOwner()` wires the device's key as an owner key only when the cadre holds it as a live `OwnerKey` row, and never inserts one, so a joining app never claims to have founded the cadre it joined.
- **Phone kit: `PhoneNode.joinCadre(invitation, options)`.** It switches the app's one node over to the invitation's cadre and waits for a member if none is reachable. If the join fails or is cancelled (`stop()` cancels it), the app goes back to the cadre it was running. The saved start records `origin` (`founded` or `joined`) and `formerPartyId`. `PhoneNode.identityPeerId()` returns the device's peer id before any cadre has started, so a new app can ask to join without founding one. Join progress adds `admitted` and `moving-strands`.
- **Strands move with the app.** The join exports what the left cadre held (its own strands and their keys, strands it joined, pending joins, open formation invitations and member addresses) and seats it in the joined cadre. A join that would need to move strands requires an invitation that grants owner; otherwise it is refused with `StrandsNeedOwnerJoinError`. A move cut short (for example, the app is killed) finishes on a later start; `pendingStrandMove()` and `finishStrandMove()` let the app show and retry it. cadre-core exports the pieces: `exportStrandBundle`, `adoptStrandBundle`, `readStrandHoldings`, `unheldBundleContent`.
- **Dissolving the cadre left behind.** `PhoneNode.dissolveFormerParty()` deletes the app's former one-node cadre from the phone, after checking against that cadre's own storage that the joined cadre holds everything it did and that no other machine belongs to it. It refuses with `StrandMovePendingError` or `FormerPartyNotEmptyError`. A deletion interrupted partway finishes at the next start.

## Removing a device or app from a cadre

- **`CadreNode.removeMachine(peerId, { revouch })`** removes a phone, app or always-on node in one transaction: its peer row, its owner key, its push token and the invitations it could come back through. Devices it had added can be kept by re-vouching them under the remover's key first. `listMachines()` lists the cadre's machines with their kind, and `planMachineRemoval(peerId)` previews a removal for a confirmation step. A refusal throws `MachineRemovalRefusedError`. The cadre's machines hang up their control connections to a removed machine.
- **Each machine publishes its kind** (app or always-on node) in its signed address record, so the list can tell a phone from a server.
- **A removed machine finds out, best-effort.** `CadreNode` emits `cadre:removed` and answers `removedFromCadre()` when it sees its own removal. It can only see it if the removal reaches it before the cadre cuts it off.
- **cadre-cli:** `cadre start` writes `removed.<party>.json` into the node-state directory, stops the node and keeps the process and its health server running. Later starts for that cadre do not start the node. `/status` reports `node.removed`, `/health` answers 503, and `cadre status` prints a `Removed:` line. The CLI deletes nothing; delete the marker file to let the node be admitted to the same cadre again.
- **cadre-host:** a node removed by an owner is stopped and its page says so, offering Remove to delete it from the machine.
- **Phone kit:** on removal the kit stops the node, deletes that cadre's data from the phone and reports status `removed`, with `formerPartyId` when the app had a cadre of its own to go back to.

## Between apps on one phone

- **Join by link instead of copy and paste.** `@serfab/cadre-rn/app-link` adds the link formats for a join request and its answer (`sereus-join-response:1.…`), `parseCadreLink`, the list of known Sereus apps (`KNOWN_SEREUS_APPS`, `installedSereusApps`) and `LinkRequestStore`, which accepts only an answer to a request this app sent (single use, matching nonce, 30 minutes). `CadreJoinRequest` carries an optional `reply` (scheme and nonce) for the answer.
- **Config plugin `appLinks`.** With `appLinks` set, the `@serfab/cadre-rn` Expo plugin registers the Android intent filter and `<queries>` entries and the iOS query schemes the links need. It takes effect in the next native build.
- **An app can recommend another app.** `AppRecommendationStore` (over `PhoneNode.recommendationSlot()`) records that the user already allowed an app to join, for one hour and one use. `storePageLink`, `recommendedByLink` and the install-referrer helpers name the recommending app, so the recommended app can join on first launch with no copy and paste. `SereusApp` gains optional `androidPackage` and `iosAppStoreId`.

## Reference apps

- **Phone (React Native), Settings:**
  - **Add a device or app:** paste or scan another app's request, or make an open invitation, choose whether it is also an owner, and hand over the invitation as text and a QR code. It warns when nothing in the cadre could answer while this app is closed. Outstanding invitations are listed and can be withdrawn.
  - **Join my existing cadre:** shows this app's request, takes the invitation back, and shows each step (joining, moving chats, removing the old cadre), with Cancel while it waits and Retry if moving stops partway. **Choose the app that holds your cadre** opens that app directly; the answer comes back by link.
  - **First launch** asks "Do you already use Sereus apps?" before founding a cadre. Yes goes straight to joining. An app opened because another app recommended it names that app and joins its cadre in one tap.
  - **Recommend an app:** allow another Sereus app to join up front and open its store page or the app itself.
  - **Devices and nodes:** every device, app and always-on node in the cadre, with Remove. A phone that was itself removed says so and offers to go back to its own cadre.
  - `APP_VARIANT=second` builds a second install, for trying these flows on one phone.
- **Browser (web), new Cadre page (`#/cadre`):** Add a device or app, Join an existing cadre (carrying what the tab's own cadre held, then removing it from the browser), and Devices and nodes with Remove. A tab that was removed deletes that cadre's data and offers to go back to its own cadre.

## cadre-cli: a node claimed by your phone in three commands

- **`cadre init`** sets up a folder for a node that waits to be claimed: identity, a one-time claim secret (`claim.secret`, mode 600) and a `cadre.yaml` with TCP and WebSocket listeners. `--public host[:port]` adds the address phones use away from home.
- **`cadre start`** reads the secret from the config's new `claim.secretFile` (env `CADRE_CLAIM_SECRET_FILE`), so no environment variable is needed. `CADRE_CLAIM_SECRET` still works; setting both is refused.
- **`cadre code`** prints the node code the phone scans (`sereus-join:1.…`), with `--qr`, `--png`/`--svg`, `--open` and `--link <url>`. It carries public names and the main LAN address only, so it skips Docker bridges and VPN interfaces a phone can't reach.
- **`cadre service`** prints a systemd unit (user, or `--system`) or launchd agent that runs the node at boot, and the commands to install it.
- **`cadre --version`** reports the real version instead of `0.7.1` (#35).

## Claim codes carry only addresses a phone can use

- **cadre-host and `cadre code` put only usable addresses in a node code:** public names (or the public IP when there is no name) and one LAN address. Docker bridges, VPN interfaces and TCP are left out. A phone tries each address in turn on its own timeout, so unusable addresses delayed a failing claim and made the QR code several times larger.
- **The admin can choose:** cadre-host's **Settings → Claim code addresses** (`host.config.json` `claimAddresses`: `lan` `auto`/`none`/an IP, or exact `addrs`; `auto` keeps no LAN address in public-IP mode), and `cadre code --lan <ip>`, `--no-lan` or `--addr <multiaddr>`.
- **cadre-core** exports the rule, `selectNodeClaimAddresses`, and a Node-only `@serfab/cadre-core/primary-lan-address`.

## cadre-host: VPS and home server, GUI first

- **Network mode.** cadre-host tells a machine behind a router (`lan`) from one that holds a public IP address (`public`, such as a VPS), detecting it automatically or by setting (**Connectivity → Network**, `cadre-host nat settings --network`).
  - On a public IP, nodes are reached at their own ports (`direct`) with no UPnP and no `nat forward`.
  - The status gives firewall advice (`sudo ufw allow …`) instead of router advice.
- **Installer.** The wizard no longer asks for values a flag already gave, and skips the UPnP question on a public IP. The unused "Configure DDNS now?" prompt is gone. Over SSH or on a headless machine, `install` and `cadre-host ui` print the exact `ssh -L` command to reach the UI.

## cadre-provider: a phone can use a rented node

- **Containers accept WebSocket connections** on a fourth published port, and the cadre-cli image, compose file and `env.example` carry the same `/ws` listener (`HOST_WS_PORT`). A phone has no TCP transport, so this is what lets it reach a rented node (part of #40).
- **`docker.publicHost`** (`PROVIDER_DOCKER_PUBLIC_HOST`) makes each container announce TCP and `/ws` addresses at the provider's public host, which `GET /containers/:id/peer` returns.
- **`bootstrapNodes` is optional** in `POST /containers` when `docker.publicHost` is set; without it the request is refused with 400.
- **`cadre-provider --version`** and its `/status` endpoint report the real version instead of `0.0.1` (#35).

## @serfab/cadre-rn: native Ed25519 from boot

The new `@serfab/cadre-rn/polyfills/native-crypto`, imported right after `@serfab/cadre-rn/polyfills`, fills `crypto.subtle`'s Ed25519 methods (`generateKey`, `importKey`, `exportKey`, `sign`, `verify`) from react-native-quick-crypto, and installs the native digest at the same time. libp2p then signs and verifies natively instead of in `@noble/curves`: 0.72 ms per verify on a Galaxy S7 against 169 ms. It must load before any libp2p import, because @libp2p/crypto checks for WebCrypto Ed25519 once, when it loads. The logic is `@serfab/cadre-rn/native-ed25519` (`installNativeEd25519(nativeSubtle)`, `nativeEd25519Active()`); it leaves a complete WebCrypto alone. The reference app imports it.

## @serfab/cadre-rn: Android release builds dial `/ws` nodes

Android release builds refused every plain `ws://` address, so a phone app could not reach or claim a node over WebSocket outside a debug build (#38). The kit now ships an Expo config plugin: add `"@serfab/cadre-rn"` to `app.json` `plugins` and prebuild, and it sets `android:usesCleartextTraffic="true"` on the app's manifest. That is safe because Noise encrypts and authenticates every connection; the kit's README has the details and the line to add by hand in a bare React Native app.

## Connection and sync fixes

- **Strand peers redial on the declared link budget (part of #44).** A running strand node connected to none of the strand's other members now redials them itself, giving each address the time a relayed dial needs on the declared link (21.5 s by default), with backoff up to 5 minutes. Two phones that restart on a slow relayed link reconnect, and a write saved before the restart reaches the other side.
- **A relay-only machine no longer waits about 18 s to open a strand (#34).** libp2p's automatic relay search could take the relay slots cadre fills itself and drop the request for a configured relay. It is now switched off wherever cadre manages the slots. Node embedders that build their own config pass `network.transports` or `network.defaultTransports` (cadre-cli uses the new Node-only `@serfab/cadre-core/node-default-transports`); without either, discovery stays on.
- **A dial no longer skips a peer's working address.** Trying a peer's addresses one by one could be captured by another dial of the same peer in flight, so a claim or invitation could fail although the node's working address was in the list. Each address is now dialed on its own (`dialAddr`), and an open connection to the peer is reused.
- **A joining strand keeps its connection while it waits.** When a joiner cannot build its copy of a strand on the first try, it keeps its node and connections and retries only the database build every 5 s.
- **A node added by a seed publishes its address record promptly.** It retries on every connected reconcile pass (every 15 s) until its first publish lands, instead of waiting up to 7.5 minutes for the heartbeat. A rented provider node or a machine added with `cadre enroll add` can be looked up much sooner.
- **A member stops waiting on an owner that went offline.** A stopped owner with no listen address, such as a phone, now leaves the members' cohort within about 5 s (FRET 1.0.2).
- **A storage replica that just joined no longer rejects other machines' writes while it is still copying data** (Optimystic 1.12.1).
- **A machine outside the cadre no longer receives the cadre's control-database writes.** A machine connected to a member could claim to serve the cadre's database and be picked to hold its control writes. Each node now tells Optimystic which machines are members (Optimystic 1.13.0's membership predicate), so only members are picked.

## Apps learn whether a change has reached another machine

After an app saves a change to a shared strand, Sereus now tells it whether another member already holds the change or only this device does, and tells it again when a change held only here reaches the others (Optimystic 1.13.0's commit durability, #26 upstream). An app can show "not yet delivered" instead of silently losing a change when the device stops. Both reference apps mark undelivered messages.

## Dependencies

- Every `@optimystic/*` dependency now requires ^1.13.0, which brings p2p-fret ^1.0.2. Optimystic 1.13.0: a write made with no other member connected is now owed to the members the node knows of and delivered when one connects (#44); reads of blocks a node already holds no longer wait on unreachable peers; requests in one write reuse an open stream, about halving relay round trips; commits report their durability.

## Known limitations

- **A joiner that writes alone and then stops for good can still lose that write (#44).** No mechanism can deliver a write from a machine that never comes back. An app now learns whether each write is held elsewhere (below), so it can tell the user.
- **FRET's maintenance pings still allow 2 s for a dial.** That is too short for a relayed dial on a slow link. Sereus's own redial (above) covers reconnection meanwhile; the FRET fix is pending upstream.
- **A removed machine keeps access to the cadre's strands.** Removal stops its control-database access only. It still holds the cadre's strand keys and the other strand members still serve it, so a removed (for example, stolen) phone can keep reading and writing shared strands until each strand is re-formed. What removal should do here is not decided yet.
- **The new phone flows have not been run on a device.** Joining an existing cadre, adding a device or app, Devices and nodes, joining by link between two apps on one phone, and recommending an app were tested headlessly only. The native Noise crypto and scan-to-claim flows are also still awaiting a device run.
- **Renting a provider node from an app (sign-up, token, create) is not built yet** (rest of #40).

## In 1.14.0 but missing from its notes (#39)

These shipped in 1.14.0, whose release notes listed only the Optimystic bump.

- **Breaking: the 1.14 control schema change required recreating parties.** Every signed control approval binds the party id (hence `signPeerRecord(partyId, …)`), and `PendingJoin` became `JoinRequest` / `JoinSuccess` / `JoinFailure`.
- **Nodes waiting to be claimed.** A node started with a one-time claim secret (`CADRE_CLAIM_SECRET`) belongs to nobody until a phone claims it with `CadreNode.claimNode` from the node's `sereus-join:` code.
- **Cadre invitations redeemable at any member while the owner is offline** (`cadre enroll invite`, `cadre start --invitation`). A member that has not yet received the invitation's row still admits the device: it records the invitation from what the device presents and sends the device its control data first, so the join succeeds on the first try. The owner-online invite path (`createInvite`, `acceptPhone`, the enrollment window and their admin routes) was removed.
- **Control-protocol guard.** A cadre machine accepts a connection from an unknown device provisionally and hangs it up after a short while unless it becomes a member. Every protocol declares whether non-members may use it, checked in one place.
- **Owners** can be added and removed through the node's API, and each machine's trusted-owner list follows those changes without a restart.
- **cadre-host was rebuilt around "Join a cadre" by QR or invitation.** Removed: the host's own cadre (founder role, owner node, Strands page), grants and node donation (including the phone-facing `/grants` API) and the trust circle (`/auth/*`, `invite`, `trust`). Added: router port mapping for every node, hand-forwarded ports, and per-node public addresses and reachability.
