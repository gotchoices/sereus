## Strand nodes can turn on change notifications

`CadreNodeConfig.strandReactivity: { enabled: boolean; strandIds?: string[] }` (the `strandReactivity` key in a cadre-cli config file) turns on Optimystic's change notifications for this node's strands. With `strandIds` absent or empty it covers every strand the node runs; listing ids covers exactly those. It is node-local, off by default, and never given to the control node. It is frozen when a strand's libp2p node is built, so a change takes effect at the next restart or hibernation wake.

A table opts in from the sApp schema: `with tags ("optimystic.network_watch" = true)`. On a node with the option, a `Database.watch` on that table wakes when another machine commits, including a machine outside the storage group of the table's log tail. Measured on three machines at `strandClusterSize: 2`: every registered watcher woke within about 100 ms of the commit. A tagged table on a node without the option keeps local wakes only, so an sApp can ship the tag unconditionally.

Enable it on every machine that serves the strand; a machine without it neither announces commits nor serves notifications. Every node built with it, a `'transaction'`-profile phone included, becomes a core notification host. A table watched before its first commit registers at the first 30 s renewal after that commit, and for up to 5 s after a machine registers a commit can miss it until the next 30 s tail read. Enabling also registers Optimystic's cohort-topic, reactivity and matchmaking protocols on the strand node, which the closed-strand revoked-peer stream gate does not cover. See `docs/strands.md` → "Change notifications (reactivity)".

## Optimystic 1.10.1

Every `@optimystic/*` dependency now requires ^1.10.1. 1.10.0 brings the change notifications above; 1.10.1 fixes registrations that arrive together (as on a new strand, where every machine registers on the same tick) locking later registrants out on a network smaller than 16 machines.

## @serfab/cadre-rn shares the phone-node code

Four subpaths move the reference RN app's node code into the kit (contributed by kjeib, PRs #29–#31):

- **`@serfab/cadre-rn/key-store`**: `SecureStoreKeyStore`, the identity key store over a secure store. The forwarded secure-store options are declared in the kit, so it has no Expo dependency; a bare React Native app passes an adapter over its own store.
- **`@serfab/cadre-rn/node-local`**: the durable, party-scoped `DurableSlot` backends for the node-local records. Record keys are unchanged.
- **`@serfab/cadre-rn/phone-node`**: `createPhoneNode(platform)` builds, starts, stops and rebuilds a phone's `CadreNode`: identity in the secure store, LevelDB storage per scope, bounded owner genesis, single-flight start, a stop that closes every database it opened, and a saved start for unattended starts. Native modules, transports, Noise crypto, storage names and config overrides are parameters, so the subpath imports nothing native. It also re-applies subscriptions across rebuilds and refuses a second live node over the same storage.
- **`@serfab/cadre-rn/lifecycle`**: the background runner, plus `phoneNodeLifecycle(phone)`, which wires it to a `PhoneNode` and cold-starts from the saved start only while `autoStart` is set. Pass react-native's `AppState` to it directly.

The kit gains dependencies on `@optimystic/db-p2p-storage-rn`, `@libp2p/circuit-relay-v2`, `@libp2p/websockets` and `uint8arrays`, and an optional peer dependency on `@serfab/cadre-core`. The reference RN app now uses all four subpaths; see `packages/cadre-rn/README.md`.
