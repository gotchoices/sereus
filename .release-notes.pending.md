# Release notes — pending

## Apps declare their schema version, and the author signs it

`SAppConfig.schemaVersion` is required: a positive whole number the app raises with every change to its `App` schema, separate from `version`, its release string. The author's signature now covers it, so a host cannot hand a signed schema a number its author never shipped. `signSchema` and `verifySchema` take `{ schema, version, schemaVersion }` in place of the separate schema and version arguments. Signatures from earlier releases no longer verify and must be minted again. A config whose `schemaVersion` is not a positive whole number is refused with `SchemaVerificationError` (`invalid schemaVersion`), whether or not the node requires signed schemas. A new strand's `Strand.Header` records the founding app's schema version in `sAppSchemaVersion`. Nothing refuses an older schema version yet; that comes next (docs/strands.md → "Until then: every member on the same schema version").
