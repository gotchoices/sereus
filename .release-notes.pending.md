# Release notes — pending

## Upgrading

- **A cadre that already forked on 1.19.x stays forked.** This release stops two machines restarted together from forking their `CadrePeer` block (see Fixes). It does not heal a block that forked before the upgrade: there, `CadrePeer` writes are still refused with `content-digest-mismatch`, and adding a machine still fails with `CoordinatorPartialCommitError`. Healing a forked control collection is Optimystic work that has not landed.

## Fixes

- **Two machines of a cadre started at the same moment no longer fork it** (gotchoices/sereus#53). Each used to publish its own address record about 1 s after start, before it had reconnected to the other, so both took the `CadrePeer` block to the same revision with different content. Every later `CadrePeer` write was then refused and the cadre could not add a machine. Writes nothing waits on now hold off while the machine is alone and its party has other authorized members, and go out once a sibling is reachable. Those are the address record's boot publish, its heartbeat and its address-change republish, and the pending-join runner's background attempts and their clean-up. A machine alone in a party with no other members still writes at once, since it has nothing to fork with. Writes a caller makes and awaits are unchanged.
  - **Seen from outside:** a machine restarted while its siblings are down publishes its fresh address only once one of them is back. `CadreNode.registerSelfUnlessCouldFork()` is the publish under the same rule. It resolves `'deferred'` instead of writing, and `cadre start --owner` now uses it for its startup publish. `CadreNode.registerSelf()` still writes at once.
- **Error text from a value that isn't an `Error` no longer reads `[object Object]`** (gotchoices/sereus#54). On React Native, a WebSocket failure rejects with an event object, so `relayStatus().error` could not say why a relay reservation kept retrying. Every place in cadre-core, cadre-cli, cadre-host, cadre-rn and the reference apps that turns a caught value into text now uses `describeThrown`.

- **A strand opens after an app schema change while its other member is offline** (gotchoices/sereus#55). The apply writes the strand's catalog, which needs the strand's members, so a two-member strand whose other member was offline failed `addStrand` with `PromiseShortfallError`, with offline mode on or off, even for a change that alters no row such as one column tag. The strand now comes up on the schema it already had, and the apply is retried when the strand node connects to a peer (and on a backoff up to every 5 minutes). `StrandDatabase.appSchemaState()` reads `'waiting-for-cohort'` meanwhile, and `strand:app-schema-applied` fires when it lands. See docs/strands.md → "An app schema upgrade waits for the queue or the cohort".
- **Phones start again on Optimystic 1.23.0.** Its React Native `LevelDBRawStorage` carries its own read cache and refuses a second one; `wrapStorageWithCache` (quereus-plugin-sereus) now passes such a storage through, and cadre-rn keeps one `LevelDBRawStorage` per scope.

## Changed

- **`strand:app-schema-deferred` carries `waitingFor`** (`'queue'` or `'cohort'`), and `transactionIds` is empty for `'cohort'`. It and `strand:app-schema-applied` are now emitted on every node, not only one configured with `strandOffline`.
- **`StrandAppSchemaState` gains `'waiting-for-cohort'`.** Code that switches over it needs the new case.
- **The app-schema listeners left `StrandOfflineListeners`** for their own `StrandAppSchemaListeners`, and `StartStrandConfig` takes them as `appSchema`. Only code that builds a `StrandInstanceManager` itself is affected; `CadreNode` events are unchanged apart from the above.
- **quereus-plugin-sereus:** the connection result gains `appSchemaWaitingFor` (`'queue'` or `'cohort'`).

## New

- **`describeThrown(value: unknown): string`**, exported from `@serfab/cadre-core`, describes any thrown value. It has no imports, so it runs on every platform.
  - An `Error` gives its `message`, unchanged.
  - An object gives its string `type`, `message` and `reason` joined, with ` (code X)` for a `code`, or else its JSON, cut to 500 characters.
  - Anything else gives `String()`.

## Dependencies

- Every `@optimystic/*` dependency now requires ^1.23.0 (Optimystic 1.21.0 through 1.23.0), which brings p2p-fret ^1.3.0, and `@quereus/quereus` requires ^4.23.0. What an embedder sees:
  - **FRET follows the declared link.** p2p-fret 1.3.0 derives its ring-maintenance deadlines from `NetworkConfig.linkRoundTripMs`, which cadre-core already states: at the default 3 500 ms a maintenance ping gets 7 s instead of 2 s. On a link slower than 2 s, FRET used to mark a connected strand member `dead`, and each side of a two-member strand then committed alone.
  - **A machine that forked while alone no longer replaces the group's version** of a block it changed. Block repair now asks it whether its history contains the group's version, and keeps the group's when it does not. The group's next write to that block can then fail with `SyncRevisionStalledError` until the forked machine writes or leaves: a stalled write instead of a lost one. It does not heal a fork; a cadre forked before the upgrade stays forked (see Upgrading).
  - **A write spanning several collections** (a table and its indexes) stops after two attempts that could not differ, with `CoordinatorRevisionStalledError`, instead of spending its whole retry budget.
  - **Offline mode:** an insert into a table with a `unique` column or an index no longer fails with `Path is invalid due to mutation of the tree` or `Missing block` while the offline queue commits earlier inserts into the same table (gotchoices/Optimystic#50).
  - **Phones:** reading stored data no longer runs the JavaScript text decoder (gotchoices/Optimystic#51), and a stream no longer rewrites libp2p's record of the other machine each time it opens; `db-p2p` lets that rewrite through once a minute per peer and protocol until the libp2p fix ships (gotchoices/Optimystic#40).
  - **With strand reactivity on** (`CadreNodeConfig.strandReactivity`): group status messages and change notifications are sent when something changed, plus a 30 s refresh; renewals to one machine share one request; and an idle watched table asks the other machines for a read only one check in ten, so a change nobody announced is noticed within 5 min on a core host and 200 s on an edge host (gotchoices/Optimystic#48, #49). A machine that stores a watched table's newest log block is woken by its own storage before the pushed notification arrives.
  - **SQL:** a partial index (`create index … where …`) holds only the rows its filter admits (gotchoices/Optimystic#42); entries older builds wrote for excluded rows stay until those rows are rewritten. Quereus 4.22.0 and 4.23.0 learn table sizes from the queries that run (cardinality feedback, on by default; `pragma cardinality_feedback = false` turns it off), so a statement's plan can change after the table has been read. `cid()` accepts the `dag-json` codec.
  - **Groundwork with no effect yet:** every write carries a lane (`serializable` unless a table is tagged `"optimystic.profile" = 'replay-permitted'`) and a hybrid logical clock timestamp; nothing orders or merges by either yet.
  - **Mixed versions:** no coordinated upgrade is needed. The new fields are optional and an older build ignores them. The client signature version is now `txsig:v3`, which matters only to a host that verifies client signatures itself; Sereus configures no `ClientSignatureVerifier`.
