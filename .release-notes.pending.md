# Release notes — pending

## Dependencies

- Every `@optimystic/*` dependency now requires ^1.15.0, which brings p2p-fret ^1.1.0.
  - **A failed cancel no longer leaves a write stuck** (Optimystic 1.14.0). When a member of a three-machine group answered a write's first step and then went silent, the write's cancel could fail too, and the writer refused every later write to the same blocks until it restarted. The cancel is now owed and re-sent until it lands, so the next write after the member returns commits. (In Sereus, found by `control-write-degraded-cohort-member`.)
  - **A one-collection write on a two-machine group costs the other machine 3 requests instead of 4** (Optimystic 1.14.0). That covers a two-machine strand's single-table writes. A write to an indexed table still costs 4 per collection.
  - **Two machines that lose a relayed connection reconnect on a slow link** (p2p-fret 1.1.0, Optimystic 1.15.0). FRET's maintenance redial used to allow 2 s for a dial, too short for a relayed dial on a slow link, so a phone that restarted could stay cut off from the other members of a strand. FRET now redials off its maintenance tick, and Optimystic gives it the node's own dial timeout (39 s on Sereus's declared link). Sereus's own strand redial stays as a second path.

## Changed

- **`connectionManager.dialTimeout` must be a positive, finite number.** Optimystic now refuses to build a node with 0 or a negative value, since FRET takes its dial budget from it. Sereus always sets it; this matters only to an embedder that passes its own libp2p options.

## Known limitations

- **A writer that exits before its owed cancel lands leaves its pending record on the other members.** Those members refuse writes to the same blocks until a sweep for such records exists upstream.
- **A removed machine keeps access to the cadre's strands.** Removal stops its control-database access only. What removal should do with strands is not decided yet.
