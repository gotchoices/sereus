# Release notes — pending

## Requires Optimystic 1.27.0 and Quereus 5.4.0

Every `@optimystic/*` range is now `^1.27.0` and every `@quereus/quereus` range `^5.4.0`. The Optimystic plugin's transaction engine id is now `quereus@5.4.0`, so a deployment that re-checks transactions must run the same Quereus version on every machine. Sereus does not configure re-checking itself.

**Fewer background checks between connected machines.** On a cohort of two or three machines that stay connected to each other, a read of unchanged data no longer asks the other machines whether anything is newer every 10 seconds. Every commit on such a cohort needs every member's agreement, so a machine that stayed connected cannot have missed one. The check runs again after any disconnect or reconnect, and at least every 5 minutes. Sereus keeps Optimystic's defaults for both intervals.

## What changes for an app's own SQL

These come from Quereus 5.1.0–5.4.0 and Optimystic 1.27.0 and reach a strand app's `App` schema and queries directly. Read both projects' notes for the full list.

- **Some queries that ran before now raise errors** (Quereus 5.4.0). A null or negative `limit` or `offset` is refused; omit the clause to mean "no limit". `sum`, `avg` and `total` refuse text, blob and date/time arguments, so a materialized view that sums an `any` column refuses an insert of such a value. A numeric `range` window offset over a non-numeric ordering key is refused.
- **Wrong results fixed** (Quereus 5.1.0–5.4.0): `where a = ? and b in (…)` over a two-column key, `nulls last` sorts served by an index, window `range` frames under `desc`, a generated column added by `alter table` after a later alter, and a recursive query selecting one column twice.
- **Faster plans on strand tables** (Optimystic 1.27.0): an `in (…)` list on a composite index or primary key seeks every key column, an ascending `order by` over a nullable text column walks the index, and `order by … limit n` is priced by its limit.
