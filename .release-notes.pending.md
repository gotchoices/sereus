# Release notes — pending

## Every machine upgrades together, on Optimystic 1.30.0 and Quereus 5.7.1

Every `@serfab/*` package now requires `@optimystic/*` ^1.30.0 and `@quereus/quereus` ^5.7.1. This release is about a node's disk: a node takes all of its storage as one value, measures what it stores against one figure its operator sets, and acts as it fills. Nothing stored by the previous release needs migrating.

- **Every machine of a party, and every machine of a strand, has to be on this release.** A coordinator on the previous release counts an out-of-space vote as neither an approval nor a rejection, so the writer gets a promise shortfall instead of being told the cohort is full. The same holds for a partner machine of a strand your party joined.
- **Set an allotment before you roll out, on any deployment whose backend reports no free space.** SQLite, LevelDB and memory report none, and a node that can measure neither an allotment nor free space cannot tell how full it is and does none of the behaviour below. Not a version-skew matter — it is a configuration this release starts reading. See [A platform that cannot measure free space](#a-platform-that-cannot-measure-free-space-must-declare-an-allotment).

## `CadreNodeConfig.storage` takes one asynchronous opener per scope

`storage.provider` is gone. In its place `storage.open(scope)`, an asynchronous function from a scope key to Optimystic's `NodeStorage` — all three of a scope's stores (blocks, the node-local key-value store, blob pieces) as one value. A platform calls its own storage package's one factory and hands back what it returns. See [A node's storage](https://github.com/gotchoices/sereus/blob/master/docs/cadre/node-storage.md).

- **The single-store-for-every-scope form is gone.** `storage.provider` accepted one `IRawStorage` shared by the control database and every strand; one value shared that way would put one party's control database in another's store. An embedder that wants sharing calls its platform factory over one location, which counts its holders.
- **`open` is asynchronous, so a platform's own factory can be called directly.** `lazyRawStorage` existed to defer an open behind a synchronous provider, and is deleted with it.
- **cadre-core still closes nothing it was handed.** Keep what the platform factory returned and close it once the node has stopped.

## `storage.quotaBytes` is now `storage.allotmentBytes`, and it is read

The old field was accepted and ignored. The new one reaches every node the machine runs. `CADRE_STORAGE_QUOTA` is now `CADRE_STORAGE_ALLOTMENT`, and a config naming the old key or the old variable is refused by name rather than defaulted.

- **The figure bounds one network's share of the machine, not the machine.** It reaches the control node and every strand node unchanged, not divided between them, so a machine running N strands can hold up to (N+1) times that figure before any one node reports itself full. It is not divided because a node's allotment is fixed when the node is constructed while the strand count changes as it runs. [The storage allotment](https://github.com/gotchoices/sereus/blob/master/docs/cadre/node-storage.md#the-storage-allotment) has the rest, including what reads the number.
- **Anything but a whole number above zero is refused.** cadre-cli refuses it at config load, naming the file or the environment variable it came from; a node built in code throws when it is constructed.
- **A hosted node's and a tenant's limit now does something.** cadre-host maps the management API's `resources.storageQuotaBytes` onto the child's `storage.allotmentBytes`, and cadre-provider emits `CADRE_STORAGE_ALLOTMENT` into the container. Both API field names are unchanged.

## A node acts as it fills

Each node measures what it stores against the smaller of its allotment and what its backend reports free. It shrinks its blob read cache as that fraction rises, and above `refuseAbove` (0.95) it refuses new data: a pushed replica, an announced blob, and a pend its cohort asks it to store.

- **A write whose cohort refused for space ends at once, with no retries.** An app tells that failure apart with `cohortOutOfSpaceOf`, exported from `@serfab/cadre-core` and `@serfab/quereus-plugin-sereus`, which names the full members. See [A write the cohort has no room for](https://github.com/gotchoices/sereus/blob/master/docs/strands/writes.md#a-write-the-cohort-has-no-room-for).
- **An entry already in an offline queue stays queued**, waiting for its cohort with the refusal as its last error, under the queue's usual backoff, rather than failing the way an unclassified error does.
- **Optimystic's three other responses to pressure stay inert on a Sereus node.** Ring move-in, ring move-out and the released-block sweep are all driven by its rebalance reaction, which every Sereus node turns off wherever it arms its own peer-join block catch-up instead — which is every node that serves blocks, was given storage, and did not have that catch-up turned off. So such a node under pressure shrinks its cache and refuses; it does not hand ranges to other machines.

## A platform that cannot measure free space must declare an allotment

Only the file store and a browser's IndexedDB report free space. LevelDB, SQLite and memory report none, so on those a node has a total only if an allotment is set — and a node with neither cannot tell how full it is, says so in one start-up warning, and acts on none of the behaviour above.

- **Both phone kits declare one.** `@serfab/cadre-rn` and the NativeScript reference platform pass `DEFAULT_DEVICE_STORAGE_ALLOTMENT_BYTES` (2 GiB), overridable per app — `PhoneNodePlatform.storageAllotmentBytes` on React Native.
- **The browser deliberately declares none**, because IndexedDB reports the origin's own estimate and a hand-set figure could only be the smaller of the two.

## `EdgeNodeStorage` changes shape

The storage seam an app implements for the edge node has three changes. Every platform in this repository is updated; an app with a platform of its own has to follow.

- **`nodeStorage(scope)` replaces `rawStorage(scope)`** and returns that scope's whole `NodeStorage`.
- **`offlineJournal(scope)` returns that scope's own key-value store**, rather than a second store over the same handle. Optimystic declares the journal's key prefix among the node's own namespaces so one store serves both, and two stores over one handle would not see each other's unflushed writes. The prefix did not change, so transactions an existing phone or tab was told were saved survive the upgrade.
- **`allotmentBytes` is new**, and is where a phone's figure comes from.

## A strand node that stores no blocks now gets storage too

A node running a strand as a [client](https://github.com/gotchoices/sereus/blob/master/docs/cadre/node.md#a-node-that-holds-no-strand-blocks) stores none of the strand's blocks, but it does keep its own clock high-water mark, its blob records, its owed-blob ledger, and blob pieces that may be its own host's only copy. So `storage.open` is now called for a client's strand scope, where before it was skipped.

- **On a phone that means a per-strand database where there was none**, and on a server a per-strand directory. What a client holds of the strand's blocks did not change: that store stays empty.

## Blob pieces and blob records now survive a restart on every platform

A `NodeStorage` has no part a platform can leave out, so every platform here now passes blob pieces and the node-local key-value store that holds blob records alongside its block store. Before, each fell back to memory on its own, and a restart — or, on a phone, a strand hibernating when the app went to the background — lost the bytes while the rows kept their references. This is the first of the three things [gotchoices/sereus#67](https://github.com/gotchoices/sereus/issues/67) asked for, and the one that stopped a blob surviving a hibernate and wake.

- **What is still missing before an app should declare a `blobref` column**: the `hold` choice that keeps a phone from storing other people's files eagerly, and an app-facing way to reach a strand node's blob service. Both are tracked in `feat-strand-blobs-persist`, and [docs/schema-guide.md](https://github.com/gotchoices/sereus/blob/master/docs/schema-guide.md) still says not to use the type yet.
- **A node whose disk is mostly block history can still fill up for good.** Optimystic cannot yet free old revisions of blocks a node is still responsible for, so such a node reaches its refusing stage and stays there until its allotment is raised; with Optimystic's ring shedding inert on such a node, peers do not take its ranges either.
- **A `network` connection made directly through `@serfab/quereus-plugin-sereus` over a client node still gets a memory-backed blob service**, because the storage is passed on the `local` transactor only. Unreachable while no schema declares a `blobref` column; a note sits at the site.

## NativeScript now has an offline journal

`CadreNode.setStrandOfflineMode` no longer refuses on NativeScript. The platform implements `offlineJournal(scope)` over the scope's own SQLite database, so a NativeScript app can queue writes while its strand has no reachable member, the way React Native and the browser already could.

- **A NativeScript strand now builds an offline queue object even in online mode**, which is what makes a commit's awaited machines and cohort reachability available there. Writes stay network-acknowledged until the app turns offline mode on.

## Nothing changed for a Quereus host's SQL

Quereus 5.7's three behaviour changes were each checked against the schemas in this repository, and none of them changes an outcome here. Said so a reader does not go looking.

- **The refusal of a write nested in a stored body applies to nothing**: no Sereus schema and no reference app schema declares a view, a materialized view, a maintained table or an assertion.
- **A write statement now opens its transaction before evaluating its expressions**, which only adds a guarantee for a function called in a write expression. Nothing here calls one there; the functions Sereus uses (`digest`, `verify`, `party_id`) are read in constraint checks.
- **A deferred cross-table CHECK now judges the row as it stands at commit.** The control schema is full of such checks, but the change only lets a transaction that wrote a row and then deleted or corrected it commit where it used to fail on the row's first version — nothing that committed before stops committing. The narrowing of child-side foreign-key checks to the columns an `update` assigns reaches nothing either: neither the control nor the strand schema declares a foreign key.
