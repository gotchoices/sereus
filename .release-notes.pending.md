# Release notes — pending

## Upgrading

- **A cadre that already forked on 1.19.x stays forked.** This release stops two machines restarted together from forking their `CadrePeer` block (see Fixes). It does not heal a block that forked before the upgrade: there, `CadrePeer` writes are still refused with `content-digest-mismatch`, and adding a machine still fails with `CoordinatorPartialCommitError`. Healing a forked control collection is Optimystic work that has not landed.

## Fixes

- **Two machines of a cadre started at the same moment no longer fork it** (gotchoices/sereus#53). Each used to publish its own address record about 1 s after start, before it had reconnected to the other, so both took the `CadrePeer` block to the same revision with different content. Every later `CadrePeer` write was then refused and the cadre could not add a machine. Writes nothing waits on now hold off while the machine is alone and its party has other authorized members, and go out once a sibling is reachable. Those are the address record's boot publish, its heartbeat and its address-change republish, and the pending-join runner's background attempts and their clean-up. A machine alone in a party with no other members still writes at once, since it has nothing to fork with. Writes a caller makes and awaits are unchanged.
  - **Seen from outside:** a machine restarted while its siblings are down publishes its fresh address only once one of them is back. `CadreNode.registerSelfUnlessCouldFork()` is the publish under the same rule. It resolves `'deferred'` instead of writing, and `cadre start --owner` now uses it for its startup publish. `CadreNode.registerSelf()` still writes at once.
- **Error text from a value that isn't an `Error` no longer reads `[object Object]`** (gotchoices/sereus#54). On React Native, a WebSocket failure rejects with an event object, so `relayStatus().error` could not say why a relay reservation kept retrying. Every place in cadre-core, cadre-cli, cadre-host, cadre-rn and the reference apps that turns a caught value into text now uses `describeThrown`.

## New

- **`describeThrown(value: unknown): string`**, exported from `@serfab/cadre-core`, describes any thrown value. It has no imports, so it runs on every platform.
  - An `Error` gives its `message`, unchanged.
  - An object gives its string `type`, `message` and `reason` joined, with ` (code X)` for a `code`, or else its JSON, cut to 500 characters.
  - Anything else gives `String()`.
